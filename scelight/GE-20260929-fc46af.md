## Symptom

When using `SelectionDeltaEvent` subgroup unitLinks to estimate how many
Hatcheries a Zerg player selected (by counting Larva unitLink=189 and
dividing by 3), the estimate is ~40% lower than ground truth. Drones
produced at 62% coverage instead of the expected 100%.

## Context

SC2 Zerg players select multiple Hatcheries and press a build key to train
one unit per Hatchery. The selection delta shows all Larva (unitLink=189)
from all selected Hatcheries, typically ~3 per Hatchery. Using
`ceil(larvaCount/3)` should give the Hatchery count.

The issue manifests during rapid-fire production — the player presses the
build key multiple times without reselecting. Each key press morphs one
Larva per Hatchery, consuming Larva from the game state. But no
`SelectionDeltaEvent` fires between CmdEvents to update the tracker.

## What was tried (didn't work)

- `ceil(larvaCount / 3)` — under-estimates because Larva are consumed
  between rapid CmdEvents without corresponding SelectionDeltaEvents
- `min(ceil(larvaCount/3), buildingCap)` — worse: under-estimates AND
  caps at a potentially stale building count
- Using non-Larva unitLinks (Hatchery=125, Lair=132) — only 84% of
  events have any Hatchery unitLink in the selection tracker

## Root cause

SelectionDeltaEvents update the tracker when the player explicitly
selects units. Between rapid-fire CmdEvents, Larva morph into units
(removing them from the game selection) but no SelectionDeltaEvent is
emitted. The tracker retains the stale Larva count from the last
explicit selection.

After 3 rapid build commands from 3 Hatcheries × 3 Larva (9 total),
the tracker still shows 9 Larva. But only 0 remain — 9 were consumed.
The next build command sees `ceil(9/3)=3` but 0 Larva are available.

## Fix

Use `productionBuildingCounts` (total Hatcheries/Nexus built, tracked from
detected BuildCommands) as the multiplication factor instead of deriving
from selection state. This over-counts for late-game tech units (~130%
Roach, ~172% Hydralisk) but maintains correct coverage for high-volume
units (Drone 103%, Zergling 107%).

```java
if (BUILDINGCAP_ABIL_LINKS.contains(abilLink)) {
    int capKey = (abilLink == ABIL_HATCHERY_QUEEN || abilLink == ABIL_LAIR_QUEEN)
        ? ABIL_LARVA : abilLink;
    repeatCount = state.productionBuildingCounts.getOrDefault(capKey, 1);
}
```

## Why this is non-obvious

The selection tracker correctly processes all SelectionDeltaEvent variants
(ZeroIndices, OneIndices, Mask, None+addSubgroups). The stale count only
manifests during rapid-fire production — a timing-dependent gap between
game state changes and replay event emissions. Unit tests with explicit
selection priming pass; the bug only surfaces at replay-processing scale.
