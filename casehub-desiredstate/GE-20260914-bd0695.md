### Symptom

Code like `if (adapted.equals(base)) return Optional.empty()` always returns false even when the two graphs contain identical nodes and dependencies. The recompiler appears to produce a new graph every cycle, triggering unnecessary `updateDesired()` calls and reconciliation cycles.

### Context

`DeploymentAdaptiveSituationRecompiler.recompile()` compiles from base goals each invocation and needs to detect when the adapted graph is structurally identical to the base — no adaptations applied. The check determines whether to return `Optional.empty()` (no change) or `CompilationResult.single(adapted)` (new graph).

### Root cause

`ImmutableDesiredStateGraph` inherits `Object.equals()` — identity comparison. Every call to `compiler.compile()` or `withNode()` / `withMutation()` produces a new object instance. Two graphs with identical nodes and dependencies are never `==` and never `.equals()`.

### Fix

Manual structural comparison of the two maps:

```java
private static boolean graphsEqual(DesiredStateGraph a, DesiredStateGraph b) {
    if (a == b) return true;
    if (a == null || b == null) return false;
    return a.nodes().equals(b.nodes()) && a.dependencies().equals(b.dependencies());
}
```

This works because `nodes()` returns `Map<NodeId, DesiredNode>` and `dependencies()` returns `Set<Dependency>` — both have proper `equals()` implementations. The graph wrapper is the only type missing it.

### Why this is non-obvious

`DesiredStateGraph` is a value-like type (immutable, carries data, no identity semantics). Java records and most immutable data types override `equals()`. The API returns `Map` and `Set` which have `equals()`. The natural assumption is that the container also has it. No compiler warning, no runtime error — just silently wrong comparison results causing unnecessary work.

### Alternatives considered

- Reference comparison (`==`) — only works if the same object is returned, which never happens after graph mutations
- Hash-based comparison — `hashCode()` also inherits from `Object`, same problem
- Comparing serialized forms — correct but expensive; structural map comparison is O(n) and sufficient
