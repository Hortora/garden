### Symptom
Quarkus app with `@McpServer("casehub")` on a CDI bean fails at startup:
```
java.lang.IllegalStateException: Invalid server name
  at io.quarkiverse.mcp.server.runtime.McpMessageHandler.validateServerConfigs
```

No other error context — just "Invalid server name."

### Context
When using `@McpServer("name")` to scope MCP tools to a named server (per boundary-rules.md: library modules use named servers, default server belongs to the application), the quarkus-mcp-server extension requires explicit configuration for the named server.

### What was tried (didn't work)
1. Adding `@McpServer("casehub")` annotation alone — startup failure
2. Checking the quarkus-mcp-server documentation — named server config not documented

### Root cause
`McpMessageHandler.validateServerConfigs()` checks that every `@McpServer` name used in annotations has a corresponding `quarkus.mcp.server.<name>.*` config block. Without this config, the server name is considered invalid and startup fails.

### Fix
Add a `META-INF/microprofile-config.properties` (or `application.properties`) with:
```properties
quarkus.mcp.server.casehub.server-info.name=casehub
```

The minimum required property is `server-info.name`. Other properties like `tools.page-size` and `http.root-path` are optional.

For library modules, use `META-INF/microprofile-config.properties` (not `application.properties`) so the config travels with the JAR.

### Why this is non-obvious
The unnamed/default MCP server works without any configuration. The error message "Invalid server name" doesn't suggest that configuration is missing — it reads like the name itself is malformed. The fix (adding a config property) is not discoverable from the error message or the `@McpServer` annotation javadoc.
