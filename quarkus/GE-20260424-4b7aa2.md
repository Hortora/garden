### Symptom
`ConfigValidationException: SRCFG00050: <property> does not map to any root` at Quarkus test startup. App starts fine when the properties are absent from `application.properties`.

### Context
`@ConfigMapping(prefix = "foo")` interface lives in a library JAR (not the main Quarkus app module). `quarkus.index-dependency.*` configured, Jandex plugin generates `META-INF/jandex.idx`. Properties with prefix `foo.*` exist in `application.properties`.

### What was tried (didn't work)
- Adding `quarkus.index-dependency.*` alone — CDI beans discovered, config validation still fails
- Adding Jandex Maven plugin to the library module — same result
- Both together — same result

### Root cause
SmallRye Config's strict validation fires during config source loading, BEFORE the library JAR's `@ConfigMapping` is registered as a config root. Properties with no registered root trigger SRCFG00050 immediately. The mapping IS registered eventually (Jandex + index-dependency do work for CDI bean discovery), but strict validation outruns registration.

### Solution 1 — Suppress unknown mapping validation (Recommended)
**Approach:** Disable SmallRye Config's strict validation for unmapped properties.
**Pros:** One line in application.properties, no code changes, handles all unmapped namespaces.
**Cons:** Suppresses validation globally — a genuine typo in a config mapping property won't be caught at startup.

```properties
smallrye.config.mapping.validate-unknown=false
```

Confirmed working on Quarkus 3.32.2. Note: the property is `smallrye.config.mapping.validate-unknown`, NOT `quarkus.config.mapping.validate-unknown` — the Quarkus-prefixed variant does not work.

### Solution 2 — Remove properties from application.properties
**Approach:** Remove the offending config properties until the integration is fully confirmed.
**Pros:** No global suppression — other config mapping typos are still caught.
**Cons:** Properties must be re-added later. `@ConfigMapping` CDI injection still works with empty/default values.

Alternatively: put properties under a profile excluded from tests (`%dev.foo.bar=x`).

## Variant — upstream JAR ships config for optional modules

When a dependency JAR bundles `META-INF/microprofile-config.properties` with properties for multiple `@ConfigMapping` namespaces (e.g. both `claude` and `langchain4j` adapters), but the consumer only depends on one adapter module, the other namespace's properties trigger SRCFG00050. Creating a stub `@ConfigMapping` interface in the application module does NOT fix it — application-module config mappings are not registered before SmallRye's validation runs (only JARs with Jandex indices are). Solution 1 (`smallrye.config.mapping.validate-unknown=false`) is the only fix short of adding the full dependency.

### Why this is non-obvious
Every other Quarkus CDI mechanism in library JARs (beans, producers, observers) works cleanly with `quarkus.index-dependency`. Config mapping looks identical but has a different timing dependency on strict validation. The error "does not map to any root" implies the mapping is missing entirely — not that it's registered too late.
