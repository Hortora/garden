# JpaCbrCaseMemoryStore requires default EntityManager — named datasource config fails silently

## Symptom

Quarkus CDI validation fails with `UnsatisfiedResolutionException: Unsatisfied dependency for type jakarta.persistence.EntityManager` when configuring a named datasource (`quarkus.datasource.cbr.*`) for `JpaCbrCaseMemoryStore`.

## Root cause

`JpaCbrCaseMemoryStore` injects `@Inject EntityManager em` — the default persistence unit, not a named one. Named datasource configuration (`quarkus.datasource.<name>.*` + `quarkus.hibernate-orm.<name>.*`) creates a named persistence unit that the default `@Inject EntityManager` cannot resolve.

## Fix

Use the default (unnamed) datasource configuration:

```properties
# Works
quarkus.datasource.db-kind=h2
quarkus.datasource.jdbc.url=jdbc:h2:file:~/.hortora/stats/cbr

# Fails — JpaCbrCaseMemoryStore injects default EntityManager
quarkus.datasource.cbr.db-kind=h2
quarkus.datasource.cbr.jdbc.url=jdbc:h2:file:~/.hortora/stats/cbr
```

If the application already has a default datasource for another purpose, this creates a conflict. The fix would require the JPA module to support `@PersistenceContext(unitName = "cbr")` or a CDI qualifier.

## Why this is non-obvious

The named datasource pattern is the documented Quarkus approach for multiple datasources. The error message points to EntityManager injection failure, not to the datasource naming mismatch. A developer would naturally expect the JPA module to work with a named datasource.
