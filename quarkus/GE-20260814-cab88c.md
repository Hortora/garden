### Context
When you need to discover CDI beans by a custom annotation at runtime in Quarkus — e.g., finding all beans annotated with `@McpDomain("engine")` — the standard Quarkus approach (Jandex via `@BuildStep`) requires a deployment extension. For simpler cases, a runtime-only approach is needed.

### What developers normally try
1. Jandex `IndexView` — but this is a build-time artifact in Quarkus, not available at runtime
2. Classpath scanning — heavy and unnecessary when CDI already knows all beans
3. CDI qualifier-based `Instance<T>` selection — but custom annotations aren't CDI qualifiers unless explicitly designed as such

### Technique
Use `Arc.container().beanManager().getBeans(Object.class, Any.Literal.INSTANCE)` to iterate all beans, then filter by annotation via reflection:

```java
@Observes StartupEvent event) {
    var beans = Arc.container().beanManager()
            .getBeans(Object.class, Any.Literal.INSTANCE);
    for (Bean<?> bean : beans) {
        MyAnnotation ann = bean.getBeanClass().getAnnotation(MyAnnotation.class);
        if (ann != null) {
            // Process this bean
        }
    }
}
```

To obtain the bean instance as a CDI proxy (with interceptors):
```java
Object proxy = CDI.current().select(bean.getBeanClass()).get();
```

### Why this is non-obvious
Quarkus documentation strongly pushes build-time processing for everything annotation-driven. The runtime BeanManager iteration pattern is valid CDI but rarely shown in Quarkus examples. Most developers either build a deployment extension (heavy) or give up on runtime discovery. The `Any.Literal.INSTANCE` qualifier is the key — without it, `getBeans(Object.class)` returns nothing useful.
