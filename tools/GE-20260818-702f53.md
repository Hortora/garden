### Symptom
After adding new classes to `quarkmind-core`, the downstream `quarkmind-chat-agent` module failed compilation with "cannot find symbol" errors for classes that existed in the source tree.

### Context
Multi-module Maven project. `quarkmind-chat-agent` depends on `quarkmind-core`. New classes were added to `quarkmind-core` and compiled locally, but `quarkmind-chat-agent` resolved `quarkmind-core` from `~/.m2/repository/` — which still contained the previously-installed jar without the new classes.

### Root cause
`mvn compile` compiles the module but does not update the local Maven repository (`~/.m2`). When building a downstream module with `-pl`, Maven resolves the upstream dependency from the local repo, not from the reactor. The stale jar is missing any classes added since the last `mvn install`.

### Fix
Re-run `mvn install -DskipTests` on the upstream module after adding classes, before compiling downstream modules.

```bash
# After adding classes to quarkmind-core:
mvn install -pl quarkmind-core -DskipTests -q

# Now downstream modules see the new classes:
mvn test -pl quarkmind-chat/quarkmind-chat-agent -Dtest=SomeTest -q
```

### Why this is non-obvious
The new classes exist on disk and compile fine in the upstream module. The error appears in the downstream module with no indication that the problem is a stale artifact — the "cannot find symbol" error looks like a missing dependency, not a versioning issue. Building from the root with `mvn compile` (full reactor) works fine, masking the problem when using `-pl` for faster iteration.
