### Symptom
`work-start` reports `META_STATE=active` with a stale issue number and branch name, even though the issue is closed and both repos are on `main`. Blocks starting new work.

### Context
Workspace repos use `.plan` files on branches to track work state. When a branch's work completes, `.plan` should be removed. If work-end doesn't clean it up, or if `git stash pop` restores a previously deleted `.plan`, the file persists as an untracked file on `main`.

### Root cause
`.plan` is not in `.gitignore` (it's tracked on branches). On `main`, it's untracked but present on the filesystem. `ctx.py` reads it and reports the stale state. `git checkout` between branches doesn't remove untracked files.

### Fix
Before branching, check for and remove stale `.plan` files on workspace `main`:
```bash
git -C $WORKSPACE status --short .plan
# If "?? .plan" → rm $WORKSPACE/.plan
```

### Why this is non-obvious
The file is invisible to `git status` unless you check for untracked files specifically. `git checkout main` doesn't touch it. The symptom (work-start refusing to start new work) points at the lifecycle state machine, not at a stale file on disk.
