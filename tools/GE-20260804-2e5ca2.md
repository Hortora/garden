### Symptom
Engine MCP server running (HTTP responding) but Claude Code's MCP client can't connect after a restart. `gardenReindex` tool unavailable.

### Context
After restarting both Qdrant and the engine, the hortora MCP server is live on HTTP but the Claude Code MCP client fails to reconnect. `WaitForMcpServers` returns `ready: false`. The SSE endpoint responds but the client-side connection is broken.

### Fix
Bypass the MCP tool and perform the reindex manually via Qdrant REST + cursor reset:

```bash
# 1. Delete the collection
curl -s -X DELETE http://localhost:6333/collections/hortora_garden

# 2. Reset the cursor
echo -n "" > ~/.hortora/cursors/garden.cursor

# 3. Restart the engine — it detects missing collection + empty cursor
#    and re-indexes all entries on startup
kill $(pgrep -f quarkus-run) && sleep 3 && launchctl list | grep hortora
```

The engine's `CollectionMigration.onStartup()` handles the rest — recreates the collection and triggers a full reconcile.

### Why this is non-obvious
The `gardenReindex` MCP tool wraps `collectionMigration.resetCorpus()` which does exactly these two operations. When the MCP client is broken, knowing the underlying operations lets you achieve the same result directly.
