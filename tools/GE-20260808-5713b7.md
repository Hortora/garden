### Symptom
`ide_open_project` reports "Project is open and ready" but all semantic tools (`ide_find_class`, `ide_search_text`, `ide_find_references`) return empty results — zero matches for classes that definitely exist.

### Context
Occurs when opening a Maven project directory that IntelliJ has never imported. `ide_open_project` opens the directory in an IntelliJ window and creates `.idea/` but does not link the Maven build model. Without the Maven link, IntelliJ sees the directory tree but has no module structure, no dependency resolution, and no class index.

### What was tried (didn't work)
- `ide_reload_project` — reports "Maven: skipped — build file found on disk but project is not linked"
- `ide_index_status` — reports `isDumbMode: false, isIndexing: false` (misleading — project appears indexed but has no content)
- `ide_open_workspace` with `modules` array — same result if the project was never Maven-imported

### Root cause
`ide_open_project` is equivalent to "File → Open" in IntelliJ — it opens the directory but does not perform Maven import. Maven project linking requires a separate step: `ide_import_modules`.

### Fix
After `ide_open_project`, call `ide_import_modules` with the project path:

```
ide_import_modules(paths=["/path/to/maven/project"], project_path="/path/to/maven/project")
```

Allow 10-15 seconds for Maven resolution before calling semantic tools. Verify with `ide_find_class` — if it returns results, the Maven model is linked.

### Why this is non-obvious
- `ide_open_project` returns success with "Project is open and ready" — no indication Maven is unlinked
- `ide_index_status` reports indexing complete — the empty index is technically "done indexing"
- The failure is silent: empty results, not an error. Easy to misattribute to wrong query or scope
