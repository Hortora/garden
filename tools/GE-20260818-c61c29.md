## topicSource adapter — bridging pages-push topic protocol to pages-data DataSource interface

### The technique

When the pages-push backend broadcasts events via `EventBroadcaster.broadcast(topic, payload)` (topic-oriented `listen` protocol) but the frontend needs a `DataSource` for the pages DSL's data binding model, create a `topicSource` adapter that:

1. Connects to `/ws/push` WebSocket
2. Sends `{op: "listen", topics: ["pattern:*"]}` to subscribe to topic patterns
3. Receives `{op: "event", topic: "matched:key", payload: {...}}` messages
4. Converts payloads to `DataSink.apply({ type: "snapshot", ... })` events

### Key design decisions

**Accumulation mode:** For panels showing aggregated state (e.g. positions table), accumulate rows in a Map keyed by a configurable field. Each event replaces the row with that key and emits a full snapshot. For single-event panels (e.g. routing decisions), disable accumulation and emit each event as a standalone snapshot.

**Reconnection:** Mirror the `websocket-source.ts` pattern — exponential backoff (1s → 30s cap), reconnect on abnormal close codes.

**composite() integration:** Use `composite(fetchSource(url), topicSource(topics))` — REST loads the initial state, then WebSocket takes over for live updates. The composite source handles the handoff: initial source emits a snapshot, composite disconnects it and connects the live source.

### Usage

```typescript
import { composite, fetchSource } from "@casehubio/pages-data";
import { topicSource } from "./topic-source";

const positionsDS = composite(
  fetchSource("/api/positions"),
  topicSource(["position:*"], { keyField: "instrument" }),
);

const routingDS = composite(
  fetchSource("/api/routing/decisions?limit=20"),
  topicSource(["routing:latest"], { accumulate: false }),
);
```

### Why non-obvious

The pages-data package provides `wsSource` which appears to be the right tool for WebSocket data binding. The discovery that `wsSource` uses an incompatible wire protocol (see GE-20260818-78bf96) and that a custom adapter is needed is the non-obvious part. The adapter itself is straightforward once you understand the protocol distinction.
