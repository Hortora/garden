### Symptom
Design review dimensions (coherence, structure, robustness) stall for 10-20 minutes
during round 1, producing no output. Progress log shows repeated "no output file yet —
agent may be reading/exploring" lines. Eventually hit soft timeout at 630s.

### Context
The `design-review` skill launches reviewer and implementor sessions via `claude -p`
(subprocess). These sessions attempt IntelliJ MCP operations (`ide_find_references`,
`ide_search_text`, `ide_index_status`) but the MCP connections from the parent session
are not inherited by the subprocess.

### Root cause
MCP server connections are session-scoped. `claude -p` starts a fresh process with no
MCP state. The reviewer agents see IntelliJ MCP tools listed (from CLAUDE.md or skill
instructions) and attempt to use them, but every call times out or returns "unable to
connect." Some agents retry repeatedly, consuming their entire time budget on failed
MCP calls.

### Fix
No fix available — this is a platform limitation. Workarounds:

1. **Reviewers should fall back to bash file reads** when MCP is unavailable. The
   robustness dimension did this successfully and completed 3 rounds.
2. **Kill stalled dimensions early.** If a dimension shows no output after 10 minutes,
   it's likely stuck in MCP retry loops. Kill it and rely on the surviving dimensions.
3. **Run fewer concurrent dimensions.** Three parallel `claude -p` sessions competing
   for the same IntelliJ instance causes additional instability.

### Why this is non-obvious
The reviewer agents are instructed to use IntelliJ MCP for code navigation (a correct
instruction for the parent session). They don't know they're running in a subprocess
without MCP access. The tools appear available but silently fail on every call. The
stall looks like "agent is thinking" rather than "agent is stuck on broken tooling."
