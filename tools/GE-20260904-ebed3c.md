### Symptom
`SherpaOnnxCreateOfflineTts` returns NULL when creating a Kokoro TTS engine, crashing the application. The sherpa-onnx log says: "You are using a multi-lingual Kokoro model (e.g., Kokoro >= v1.0). please pass --kokoro-lexicon or --kokoro-lang".

### Context
When upgrading from `kokoro-en-v0_19` to `kokoro-multi-lang-v1_0`, the TTS config struct gains a required `kokoro-lexicon` field. The model ships with lexicon files (`lexicon-us-en.txt`, `lexicon-gb-en.txt`, `lexicon-zh.txt`) in the model directory, but nothing in the API or docs indicates the field is mandatory.

### Root cause
Multi-lingual Kokoro models require explicit lexicon paths for phoneme lookup. Without them, the engine refuses to initialize. The error message only appears in stderr (sherpa-onnx C++ logging), not in any return value — the only signal is a NULL handle.

### Fix
Detect and set lexicon paths from the model directory:

```java
String lexicon = detectLexicon(modelDir);
if (lexicon != null) {
    seg.set(ValueLayout.ADDRESS, SherpaLayouts.KOKORO_LEXICON,
            arena.allocateFrom(lexicon));
}

private static String detectLexicon(Path modelDir) {
    var lexicons = new ArrayList<String>();
    for (String name : List.of("lexicon-us-en.txt", "lexicon-gb-en.txt", "lexicon-zh.txt")) {
        Path p = modelDir.resolve(name);
        if (Files.exists(p)) { lexicons.add(p.toString()); }
    }
    return lexicons.isEmpty() ? null : String.join(",", lexicons);
}
```

### Why this is non-obvious
The `kokoro-en-v0_19` model worked without lexicon. The upgrade to v1.0 silently adds a new required field. The error appears only in C++ stderr, and the only API signal is a NULL return — easy to misdiagnose as a model path issue.
