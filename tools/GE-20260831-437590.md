### Symptom / Context

You need to programmatically drop specific commits during a rebase — for
example, removing duplicate commits whose content already exists on the
target branch (identified by patch-id match). `git rebase --skip` only
works interactively after a conflict. There's no `--drop` flag.

### The technique

Write a Python (or shell) script that edits the rebase todo list, removing
`pick <sha>` lines for the commits you want to drop. Pass it via
`GIT_SEQUENCE_EDITOR`:

```python
import os, subprocess, tempfile

drop_shas = {"abc1234", "def5678"}  # short SHAs to drop
short_set = {sha[:7] for sha in drop_shas}

fd, script_path = tempfile.mkstemp(suffix=".py")
os.close(fd)
with open(script_path, "w") as f:
    f.write("import sys\n")
    f.write(f"drops = {short_set!r}\n")
    f.write("path = sys.argv[1]\n")
    f.write("with open(path) as fh: lines = fh.readlines()\n")
    f.write("kept = []\n")
    f.write("for line in lines:\n")
    f.write("    parts = line.split()\n")
    f.write("    if len(parts) >= 2 and parts[0] == 'pick':\n")
    f.write("        if any(parts[1].startswith(s) for s in drops):\n")
    f.write("            continue\n")
    f.write("    kept.append(line)\n")
    f.write("with open(path, 'w') as fh: fh.writelines(kept)\n")

env = dict(os.environ)
env["GIT_SEQUENCE_EDITOR"] = f"python3 {script_path}"
try:
    proc = subprocess.run(
        ["git", "-C", repo, "rebase", "-i", f"{remote}/{base}"],
        capture_output=True, text=True, env=env,
    )
finally:
    os.unlink(script_path)
```

### Why this is non-obvious

Most developers reach for `git rebase -i` manually or try to use
`--skip` in a loop (which only works after conflicts). The
`GIT_SEQUENCE_EDITOR` env var is documented but rarely used for
automation — it receives the todo file path as argv[1] and can
programmatically edit it before the rebase begins.
