### What
Add a `verify_fn` to each judgment step definition in a Python-driven state machine. When the LLM claims `step_done=X`, the state machine calls `verify_fn(workspace, produced)` before accepting the claim. If verification fails, the step_done is rejected with an error telling the LLM how to fix it.

### The technique
```python
@dataclass
class StepDef:
    name: str
    step_type: str  # "mechanical" or "judgment"
    verify_fn: Callable | None = None  # postcondition check

def _verify_produced_required(workspace, produced):
    if produced is None:
        return "retry with: step_done=<STEP> produced=N (use 0 if no findings)"
    return None

def _verify_forcing_function(workspace, produced):
    findings = read_findings(workspace / ".audit" / "findings.jsonl")
    open_findings = [f for f in findings if f.get("status") == "open"]
    if open_findings:
        return f"{len(open_findings)} open finding(s)"
    return None
```

In the step_done handler:
```python
step_def = next((s for s in STEPS if s.name == step_name), None)
if step_def and step_def.verify_fn:
    error = step_def.verify_fn(workspace, produced)
    if error:
        return {"ACTION": "error", "ERROR": "postcondition_failed",
                "STEP": step_name, "REASON": error}
```

### Why this is non-obvious
The natural approach for LLM agent orchestration is trust-based: the LLM says "done" and the orchestrator advances. This works for mechanical steps (Python verifies via script output) but fails for judgment steps (the LLM can claim completion without doing the work). The insight is that the same verification principle should apply uniformly — the distinction is what you verify (script exit code vs artifact existence), not whether you verify.

For null results (code review found 0 findings), require `produced=0` — an explicit claim of "I ran this and found nothing" rather than silence. This forces the LLM to acknowledge the step even when the result is empty.

### Alternatives considered
- Full artifact verification (check findings.jsonl for code-review entries with timestamps) — stronger but requires every step to produce a verifiable artifact, including sweep steps that may find nothing garden-worthy.
- No verification, rely on SKILL.md instructions — the status quo that failed repeatedly. The LLM skips steps, claims completion, and the orchestrator advances blindly.
