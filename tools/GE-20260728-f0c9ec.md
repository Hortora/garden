### Symptom
LLM skill routing misinterprets user intent when keywords overlap between skills. Example: user says "resume handover" on a feature branch → LLM matches "resume" and routes to `work-resume` (pause-stack restoration from main) instead of reading the handover file and continuing on the current branch.

### Context
Skill-based LLM systems often route to sub-skills based on keyword matching and context interpretation. When the routing decision depends entirely on mechanical state (which branch am I on? does a file exist? is a path pattern present?), the LLM adds no value — it only adds variance.

### What developers would normally do
Keep the routing logic in the skill's markdown instructions with inline bash checks. The LLM reads the instructions, runs the checks, interprets the results, and decides which skill to invoke. This works until the LLM misreads its own output or keyword-matches before checking state.

### Fix
Extract the state detection into a standalone Python script that outputs KEY=VALUE pairs:

```python
# work_router.py — one call, all state
def detect_state(current_branch, project_path, workspace_path):
    result = {
        "ROUTE": "start" if on_main else "resume_branch",
        "ON_MAIN": "yes" if on_main else "no",
        "IN_SLOT": "yes" if in_slot else "no",
        "IS_EPIC": "yes" if is_epic else "no",
        "STACK_DEPTH": str(stack_depth),
        "HAS_HANDOFF": "yes" if has_handoff else "no",
    }
    return result
```

The skill runs the script once, reads `ROUTE=`, and dispatches mechanically. No interpretation needed — the script is deterministic, testable, and fast.

### Why this is non-obvious
The instinct is to keep routing logic in the skill instructions where the LLM can "understand" it. But LLMs don't need to understand routing — they need to execute it. The insight is recognising which decisions are judgment (keep in the LLM) vs mechanical (extract to a script). Routing based on filesystem state is always mechanical.

### Alternatives considered
- **More detailed skill instructions:** Tried — the LLM still keyword-matched "resume" before checking branch state
- **Multiple skill entry points:** Would fragment the skill into many small skills, losing the unified `work` command

### Caveats
Only applies when the routing decision is fully determined by observable state. If routing requires interpreting user intent beyond state (e.g. "should I review or refactor this?"), the LLM is the right router.
