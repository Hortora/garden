### Symptom

A system uses topological sort (Kahn's algorithm) to order DAG node execution but runs everything sequentially. Independent nodes at the same depth wait unnecessarily.

### Context

Any execution system built on a dependency DAG — build tools, deployment orchestrators, desired-state reconcilers, CI pipeline schedulers. The standard implementation of Kahn's algorithm processes nodes level by level but flattens the result into a single `List<Node>`, discarding the layer boundaries.

### Root cause

Kahn's algorithm works by BFS: collect all nodes with in-degree 0 (layer 0), process them, decrement dependents' in-degrees, collect the next batch of zero-in-degree nodes (layer 1), repeat. The nodes in each BFS level have no cross-dependencies — they are inherently parallelizable.

Most implementations flatten the BFS levels into a single list because the primary goal is ordering correctness, not parallelism. The layer information is computed and then thrown away.

### Fix

Change the return type from `List<Node>` to `List<List<Node>>`. Instead of adding each node to a flat result list, collect all nodes at the current BFS level as one inner list before processing their dependents:

```java
// Before: flat list, layers discarded
List<Node> result = new ArrayList<>();
while (!queue.isEmpty()) {
    Node current = queue.poll();
    result.add(current);
    // ... update dependents
}

// After: preserve BFS levels as concurrent layers
List<List<Node>> layers = new ArrayList<>();
while (!queue.isEmpty()) {
    List<Node> layer = new ArrayList<>(queue);
    queue.clear();
    layers.add(layer);
    for (Node current : layer) {
        // ... update dependents, enqueue newly-zero nodes
    }
}
```

Each inner list is a set of nodes safe to execute concurrently. Execute layers sequentially, nodes within each layer in parallel (e.g. virtual threads with a latch per layer).

For reverse ordering (e.g. removal/teardown — leaves before roots), reverse the layer list.

### Why this is non-obvious

Developers typically think of topological sort as producing a single ordering. The connection between "BFS levels in Kahn's algorithm" and "concurrent execution groups" isn't made explicit in most algorithm textbooks or library implementations. The insight is that the data structure already encodes parallelism — you just need to stop throwing it away.

### Alternatives considered

- **Re-derive layers from the flat sorted list + dependency graph** — possible but wasteful: it duplicates the in-degree analysis that Kahn's algorithm already performed. The planner should be the single authority on execution ordering.
- **Per-node dependency latches** — submit all nodes at once, each awaiting its dependencies' completion signals. Maximally parallel but harder to reason about and debug. Layer-based execution is nearly as parallel and much more predictable.
