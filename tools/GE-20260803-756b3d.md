### Symptom

`Cannot find module '@casehubio/graph-core'` or similar resolution errors when building a workspace that uses `portal:` resolution to reference a package from a peer repo. The portal directory has source files but no `dist/` directory.

### Context

Yarn `portal:` resolution in `package.json` resolutions copies the package's source directory into `.casehub-packages/packages/<name>/`. If the peer repo uses TypeScript, the source `.ts` files are present but the compiled `.js`/`.d.ts` output in `dist/` is not — the peer repo must be built first.

### Root cause

`portal:` links to the source directory as-is. Unlike `link:`, it does not run the package's build scripts. The `dist/` directory is a build artifact that only exists after `tsc` runs in the source repo.

### Fix

Build the package in the source repo first, then copy the entire package (including `dist/`) into the portal location:

```bash
# Build in the source repo
yarn --cwd /path/to/source-repo workspace @pkg/name build

# Copy including dist
cp -r /path/to/source-repo/packages/name /consuming-repo/.casehub-packages/packages/name
```

Or if the source repo is already built, just copy the dist:
```bash
cp -r /source/packages/name/dist /consuming/.casehub-packages/packages/name/dist
```

### Why this is non-obvious

The portal resolution succeeds at install time — `yarn install` completes without errors. The failure only surfaces at build time when TypeScript tries to resolve the module's `.d.ts` files from `dist/`. The error message points at the consuming code, not the missing build output.

## Variant — syncing src/ without syncing dist/ leaves stale dist/index.js

When adding new modules to a package (e.g. `floating-frame-engine.ts`), syncing `src/` to the portal location updates the source files but leaves `dist/index.js` from a previous build. The `package.json` `main` field points to `dist/index.js`, so both esbuild (production) and vitest (tests) resolve from the stale dist — which doesn't re-export the new modules. The error is `X is not a function` at runtime, not a build-time resolution error, making it harder to diagnose. Fix: always sync both `src/` and `dist/` together, or rebuild after syncing.
