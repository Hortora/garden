### Context

LLM-based evaluation harnesses commonly use the same model to both generate responses (as the agent) and classify/judge those responses. This creates self-evaluation bias — the judge may recognize patterns from its own generation style rather than objectively evaluating the text.

### Technique

Use a different model for the judge than for the agent. In practice:

1. The `FunctionActivationJudge` accepts separate `agentModel` and `judgeModel` fields
2. A `setJudgeModel()` method allows overriding the judge after CDI injection
3. The test creates a second model instance directly when `judge-model` config is set

```java
// Agent model injected via CDI (default bean)
// Judge model created directly from config
if (!judgeModelName.isEmpty()) {
    var judgeModel = new VertexChatModel(projectId, region, judgeModelName, timeout);
    functionJudge.setJudgeModel(judgeModel);
}
```

### Validation

Ran 192 scenarios (8 profiles × 4 conditions × 6 scenarios each) in three configurations:

| Config | Framework Contribution | Baseline TAA |
|--------|----------------------|--------------|
| Haiku agent / Haiku judge | +0.10 | 0.63 |
| Haiku agent / Sonnet judge | +0.08 | 0.56 |
| Sonnet agent / Sonnet judge | +0.07 | 0.65 |

The framework contribution (+0.08) survived the stricter Sonnet judge — confirming the signal is real agent behaviour, not Haiku-as-judge inflating scores. Absolute scores dropped (0.56 vs 0.63 baseline) as expected — Sonnet is a more discriminating evaluator of Haiku's output.

### Why this is non-obvious

Most LLM eval frameworks use a single model for both roles without questioning it. The bias is invisible in single-model runs — scores look reasonable and internally consistent. Only when you swap the judge does the baseline shift reveal whether the measurement was of agent behaviour or judge self-recognition. The technique is simple to implement but the insight that self-evaluation bias affects classification (not just generation) is non-obvious.
