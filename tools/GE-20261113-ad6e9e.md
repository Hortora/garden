### Symptom

Cycle length distribution shows physically impossible short cycles (2-tick round trips from 6-unit distances) and high variance (σ=2.54) where the real system is nearly uniform (σ=0.58).

### Context

Tracking state transitions (GATHERING→RETURNING) for individual entities observed through an array-based API. The API reorders entities in the array between observation samples. The tracker uses array index as identity.

### What was tried (didn't work)

Built a direction-dependent collision model (head-on workers near-stop at 0.2× speed, same-direction pass transparently at 0.99×), tripled acceleration from 3.5 to 10.0, eliminated SC2-observed mining phase overheads (mining=22, deposit=7, approach=11 loops set to zero). Each change was internally coherent and moved σ toward the buggy target. Total effect: σ went from 0.34 (close to real 0.58) to 2.25 (4× too high).

### Root cause

Array index is not identity. When the observation system reorders entities between samples, index `[0]` at sample T is a different entity than index `[0]` at sample T+1. The tracker sees a transition from entity A's state to entity B's state and records a phantom cycle.

With N entities reshuffled into N slots each sample, phantom transitions outnumber real ones. Short phantoms dominate because each reshuffle has high probability of placing a RETURNING entity where a GATHERING entity was.

### Fix

Track by entity identity (tag, ID, handle), not array position.

```java
// Wrong — index-based
for (int w = 0; w < workers.size(); w++) {
    String act = workers.get(w).action().name();
    if (prevAction[w] != null && prevAction[w].equals("GATHERING")
        && act.equals("RETURNING")) {
        // phantom transition — different worker at same index
    }
    prevAction[w] = act;
}

// Right — tag-based
for (WorkerSnapshot w : workers) {
    String prev = prevAction.get(w.tag());
    if (prev != null && prev.equals("GATHERING")
        && w.action().name().equals("RETURNING")) {
        // real transition — same worker tracked by identity
    }
    prevAction.put(w.tag(), w.action().name());
}
```

### Why this is non-obvious

The buggy distribution has plausible statistical properties — right-skewed, long tail, stable across runs. Nothing about it screams "measurement error." The phantom transitions create a distribution consistent with a physical model (collision-driven variance), which leads to building compensating physics rather than auditing the measurement.

### Why this fix

The tell is domain knowledge: 2-tick cycles from 6-unit patches require teleportation. When a measurement implies physics that can't happen, check the measurement before adding the physics.

### The cascade pattern

A measurement bug that inflates variance drives compensating complexity: direction-dependent collision models, acceleration changes, overhead elimination. Each compensation is internally coherent. The simulation converges toward the buggy measurement. A week of physics corrections made the simulation worse — σ went from 0.34 (close to real 0.58) to 2.25 (4× too high).

### Alternatives considered

- Attributing the variance gap to mineral patch distance uniformity — investigated but ruled out when every SC2 worker achieved 2-tick cycles regardless of patch distance
- Randomising collision yielder selection per loop — reduced income 22% without improving distribution shape
- Increasing collision radius to create more collision events — added variance but in the wrong direction
