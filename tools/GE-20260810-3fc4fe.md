## The technique

When a state machine needs to record that an event occurred without changing state, add a self-transition: `(state, event) -> (state, [], [])`. The transition table validates the precondition (must be in the right state), the worklog records the event, but no effects fire and no state changes.

## Example

```python
# lifecycle.py — work_continue is observability-only
TRANSITION_TABLE = {
    ('active', 'work_continue'): ('active', [], []),
    # ...
}
```

The caller fires `transition(meta, 'work_continue')` then `commit_transition()`. The worklog gets a `work_continue` event with `from_state=active, to_state=active`. No effects execute. The branch stays active.

## Why this is non-obvious

The natural instinct is to skip the state machine entirely for no-op events — "if nothing changes, why fire a transition?" But this loses observability (the worklog doesn't know the user continued), and it bypasses precondition validation (the state machine can't reject `work_continue` from `paused` state if it never sees the event). The self-transition gets both for free from the existing infrastructure.

## When to use

- User-facing actions that should be logged but don't change state
- Events where precondition validation matters even though no state changes
- Any case where you'd otherwise write ad-hoc validation + logging outside the state machine
