### Symptom

Multiple entry points into a lifecycle system (work-start, work-end, work-pause, work-resume, session hooks, slot creation, epic setup) each independently re-derive system state from scattered filesystem signals. As entry points grow, gaps appear silently — context setup is skipped, closing gates are bypassed, lifecycle events go untracked.

### Context

CLI-based work lifecycle systems that track branch state via files (.meta, .pause-stack, .epic, .slot) and git branch position. Each entry point reads 5+ signals and applies its own if/elif detection logic. 6 of 11 entry points had gaps in a real system.

### What developers typically do

Add another if/elif branch to the detection logic in each entry point, or add a new signal file. This scales linearly in code but combinatorially in testing — each new signal multiplies the test matrix.

### Fix

Replace inference with an explicit `state:` field in the control file (e.g. `.meta`). A single Python module owns a data-driven transition table: `(current_state, event) → (new_state, effects)`. Entry points fire events; the state machine determines effects. No entry point decides what to do — the table decides.

```python
TRANSITION_TABLE = {
    ('idle', 'work'):         ('scaffolded', ['create_branch', 'write_meta'], []),
    ('scaffolded', 'auto'):   ('active',     ['garden_search', 'load_specs'], []),
    ('active', 'work_pause'): ('paused',     ['wip_commit'], ['switch_to_main']),
    # ... every valid transition is a row
}

def transition(meta_path, event):
    current = read_state(meta_path) or 'idle'
    if (current, event) not in TRANSITION_TABLE:
        raise InvalidTransition(current, event, INVALID_MESSAGES[(current, event)])
    new_state, effects, post_commit = TRANSITION_TABLE[(current, event)]
    return TransitionResult(current, new_state, event, effects, post_commit)
```

### Why this is non-obvious

Inference-based detection feels natural and works fine with 2-3 entry points. The failure mode is silent — a new entry point that doesn't check all signals produces no error, just skipped behaviour. The state machine makes every gap a test failure: parametrize all valid transitions, and any missing row is caught.

### Alternatives considered

- **Add validation to each entry point** — doesn't scale; each new entry point duplicates the validation
- **Central detection function** — better but still inference-based; the combinatorial testing problem remains
- **State machine** — the transition table IS the specification; testing is `(state, event) → expected_state`
