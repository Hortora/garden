### Symptom
After using `ide_insert_member` to add a method that references a type not yet imported (e.g. `NodeType`), the file compiles with `cannot find symbol` errors despite `reformat=true` being the default.

### Context
When inserting members into Java source files via the IntelliJ MCP `ide_insert_member` tool. The `reformat=true` default reformats whitespace and code style but does NOT trigger import optimization for types referenced in the inserted code.

### Root cause
`reformat=true` controls code formatting (indentation, line breaks) and import optimization for EXISTING imports. It does not analyze the inserted code for new type references that need imports added. The tool inserts the member text as-is — any types referenced must already be imported.

### Fix
After `ide_insert_member`, manually add the missing import using `ide_replace_text_in_file`:

```java
// Add missing import by appending after an existing import line
ide_replace_text_in_file(
    file: "path/to/File.java",
    searchText: "import io.casehub.desiredstate.api.NodeSpec;",
    replaceText: "import io.casehub.desiredstate.api.NodeSpec;\nimport io.casehub.desiredstate.api.NodeType;"
)
```

Alternatively, use `ide_reformat_code` with `optimizeImports=true` after insertion — but this only removes unused imports, it does NOT add missing ones. The manual approach is required.

### Why this is non-obvious
The `reformat=true` parameter name strongly implies full code cleanup including import management. The IntelliJ IDE's own "Reformat Code" action (Ctrl+Alt+L) with "Optimize imports" does NOT add missing imports either — it only removes unused ones. But in the IDE workflow, imports are auto-added by the editor as you type, so this gap is invisible. In the MCP workflow (no editor), the gap surfaces as compilation failures.

### Alternatives considered
- `ide_optimize_imports` — only removes unused imports, does not add missing ones
- `ide_reformat_code` with `optimizeImports=true` — same limitation
