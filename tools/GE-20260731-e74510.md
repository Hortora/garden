### Symptom
All `ide_create_file`, `ide_edit_member`, `ide_insert_member`, and `ide_replace_text_in_file` calls silently succeed but files appear in the main git working copy, not the worktree. The worktree's `git status` shows no changes.

### Context
Working in a git worktree (e.g. `/worktrees/53/clinical`) while IntelliJ has the main repo (`/clinical`) open. The session's CWD is the worktree, but `project_path` passed to IntelliJ MCP tools points to the main repo.

### What was tried
- Created 7 new Java files and edited 5 existing files via IntelliJ MCP tools
- All operations reported success
- Discovered the problem only when `git status` in the worktree showed only 2 files (those written via the Write tool, not IntelliJ MCP)

### Root cause
IntelliJ MCP tools operate on the project identified by `project_path`, which is the IntelliJ project root — not the shell's CWD. Git worktrees are separate filesystem trees that IntelliJ doesn't automatically associate with the same project.

### Fix
Call `ide_open_project` with the worktree's absolute path before any file operations:
```
ide_open_project(path="/path/to/worktrees/53/clinical", project_path="/path/to/clinical")
```
Then use the worktree path as `project_path` for all subsequent `ide_*` calls. Verify with `git status` in the worktree after the first file creation.

### Why this is non-obvious
The operations succeed silently — no error, no warning. The IntelliJ build even compiles clean (it sees the files in the main repo). The only signal is that the worktree's `git status` is empty. A developer would naturally assume CWD determines where files land, but IntelliJ MCP is project-scoped, not directory-scoped.
