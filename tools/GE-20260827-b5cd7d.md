### Symptom
After sync-main runs, fork main diverges from origin/main — 226+ files differ, feature branches are orphaned, build breaks. The fork has commits with new SHAs that are content-identical to commits already on origin with old SHAs.

### Context
Fork model: `upstream` = blessed repo, `origin` = personal fork. Local main has commits from prior work-end sessions that were merged to main and pushed to origin. Upstream advanced independently. sync-main fetches upstream and rebases local main onto upstream/main.

### Root cause
`git rebase upstream/main` replays ALL commits between upstream/main and local HEAD — including commits already pushed to origin. These get new SHAs. The subsequent `--force-with-lease` push overwrites origin's history. Feature branches based on the old SHAs now have a mismatched base — squash-merges silently miss changes because git sees them as "already applied" with different SHAs.

### Fix
Before rebasing, check whether origin has commits not on upstream:

```python
shared = rev_count(repo, f"upstream/{base}..origin/{base}")
if shared > 0:
    # Merge instead of rebase — preserves existing SHAs
    git merge upstream/main --no-edit
    git push origin main --no-verify
else:
    # Rebase safe — no shared commits to rewrite
    git rebase upstream/main
    git push origin main --force-with-lease --no-verify
```

The key check is `upstream/main..origin/main` (remote state after fetch), not `upstream/main..main` (local state which may include unpushed commits).

### Why this is non-obvious
The rebase is safe for unpushed commits — that's the normal case. The danger only emerges when local commits are already on origin but not yet on upstream: a state that occurs naturally in fork workflows where work lands on the fork first and upstream PRs are deferred. The `--force-with-lease` check doesn't catch this because origin/main was just fetched — the lease is current, so the overwrite succeeds silently.

### Alternatives considered
- Always merge, never rebase — rejected because it creates merge commits on every sync, making the fork history noisy for repos that are usually in sync.
- Push local-ahead commits before rebasing (`_check_ahead_and_push`) — tried first but creates a race: after pushing, `origin/main..main` is 0, but the rebase still replays the commits with new SHAs. The check must use remote refs (`upstream/main..origin/main`), not local state.
