## IntelliJ ide_optimize_imports silently skips newly created classes in unsynced worktrees

### Symptom

After creating a new Java class (e.g. `HandlerResult.java`) and calling `ide_optimize_imports` on files that reference it, the import is NOT added. The file compiles with the missing import error. No warning from the MCP tool — it reports success.

### Context

Working in a git worktree that was opened in IntelliJ via `ide_open_project`. New files created via `Write` or `ide_create_file` are not immediately visible to IntelliJ's index.

### Root cause

IntelliJ's virtual file system (VFS) hasn't synced the new file yet. `ide_optimize_imports` runs against the stale index where the new class doesn't exist, so it can't resolve the import — and silently skips it rather than erroring.

### Fix

Either call `ide_sync_files` with the directory containing the new file before running `ide_optimize_imports`:

```
ide_sync_files(paths: ["path/to/new/file/directory"])
```

Or manually add the import via `ide_replace_text_in_file` after the fact.

### Why this is non-obvious

`ide_optimize_imports` reports success — there's no indication it couldn't find the class. The failure is completely silent. You only discover it when the compiler reports the missing import.
