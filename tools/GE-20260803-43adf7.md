## Git pre-push hook failure produces identical error message to GitHub auth failure

**Stack:** git 2.x, GitHub

### Symptom

`git push` fails with:
```
error: failed to push some refs to 'https://github.com/Org/repo.git'
```

Diagnosed as GitHub authentication failure (expired token, wrong credentials). Multiple retry attempts with `pull --rebase` and cache clearing have no effect.

### Context

Any git repository with a pre-push hook (`.git/hooks/pre-push` or `.githooks/pre-push`). The hook runs before the push and returns non-zero to block it. Common in projects with squash-review enforcement, branch protection, or commit-message validation hooks.

### Root cause

Git's error message for hook rejection is identical to the message for remote rejection (auth failure, branch protection, etc.). The only difference is the hook's own output — which appears **above** the error line in the terminal and is easily missed, especially when:

- Grepping for "error" or "401" in the output
- Reading only the last few lines of output
- The hook produces a multi-line banner that scrolls past the visible area

Example hook output (easily missed):
```
╔══════════════════════════════════════════════════════════╗
║  Pre-push: 1 commit(s) about to push
╠══════════════════════════════════════════════════════════╣
║  Run /git-squash to review history before pushing,      ║
║  or use --no-verify to skip.                            ║
╚══════════════════════════════════════════════════════════╝

error: failed to push some refs to 'https://github.com/Org/repo.git'
```

The banner and the error line are both in stderr. An LLM agent reading `tail -3` of the output sees only the generic error.

### Fix

When `git push` fails, **read the full output** — not just the last line. Check for hook output (banners, messages, validation errors) above the `error: failed to push` line.

If the hook is the cause:
- Address what the hook is asking for (e.g. run squash review), OR
- Use `git push --no-verify` if the push doesn't need the hook's validation (e.g. a single integration commit, not squash-worthy)

### Why this is non-obvious

The error message `failed to push some refs` is universally associated with remote-side failures — auth, branch protection, force-push rejection. Git does not distinguish "hook blocked the push" from "remote rejected the push" in the error line. A developer (or LLM agent) who has seen this message 100 times in auth-failure contexts will pattern-match to auth without reading the hook output above.
