## Symptom

All vector analysis endpoints return empty results despite the Qdrant collection containing hundreds of entries. No error, no warning — just 0 points in the response.

## Context

Building domain-filtered vector queries against a Qdrant collection with named payload fields. The scroll API accepts a `filter` object with a `must` array of conditions.

## What was tried (didn't work)

Used the filter format `{"match": {"key": "domain", "value": "jvm"}}` — placing both `key` and `value` inside the `match` object. This format looks plausible from a quick read of the docs and returns HTTP 200 with an empty `points` array.

## Root cause

Qdrant's filter condition format requires `key` at the condition level, not inside `match`. The `match` object only contains `value`. The wrong nesting is silently accepted and returns 0 results — it doesn't fail validation.

## Fix

```json
// WRONG — silently returns 0 results
{"must": [{"match": {"key": "domain", "value": "jvm"}}]}

// CORRECT — key is a sibling of match, not inside it
{"must": [{"key": "domain", "match": {"value": "jvm"}}]}
```

## Why this is non-obvious

The wrong format is valid JSON, accepted by the API, and returns a well-formed response with `"points": []`. There is no error code, no warning, and no indication that the filter was ignored. You only discover the problem by noticing empty results against data you know exists.

### Alternatives considered

- Checking Qdrant logs for filter warnings — none emitted
- Using the Qdrant client library instead of raw REST — would have avoided the issue but added a dependency
