## Maven 3.9.x .mvn/maven.config mangles -s/--settings path

### Symptom

Maven fails with "The specified user settings file does not exist" — but the file
clearly exists at the given path. The error shows a mangled path with the project
basedir prepended and a literal space separator:

```
/Users/mdproctor/claude/casehub/slots/82/devtown/ /Users/mdproctor/claude/casehub/slots/82/slot-settings.xml
```

### Context

Occurs when `.mvn/maven.config` contains `-s <path>` or `--settings <path>` with
a space between the flag and value. Both absolute and relative paths fail.
Command-line `-s` works fine — the bug is specific to the config file parser.

### What was tried (didn't work)

- Absolute paths (`-s /full/path/to/settings.xml`)
- Relative paths (`-s ../slot-settings.xml`, `-s .mvn/slot-settings.xml`)
- Verifying file exists and permissions are correct
- Checking for invisible characters in the config file

### Root cause

Maven's `.mvn/maven.config` parser splits on whitespace. The `-s` flag and its
value become two separate tokens. The value token then passes through a path
resolver that prepends the project basedir using string concatenation with a
space separator instead of proper path joining.

### Fix

Use `--settings=path` (equals sign, no space) instead of `-s path`. The `=` form
keeps the flag and value as a single token, bypassing the broken resolver:

```properties
# .mvn/maven.config

# Broken — all of these fail:
-s /Users/mdproctor/settings.xml
-s .mvn/slot-settings.xml
--settings .mvn/slot-settings.xml

# Works:
--settings=.mvn/slot-settings.xml
```

Additionally, place the settings file inside the repo's `.mvn/` directory (copied
there during setup) so the path is short and relative. Don't reference files
outside the repo — even with the `=` fix, long external paths are fragile.

Note: `-D` property assignments are unaffected — only `-s`/`--settings` (and
potentially other path-valued flags like `-gs`/`--global-settings`,
`-t`/`--toolchains`) are broken by the whitespace parser.

### Why this is non-obvious

The error message says "file does not exist" — the natural response is to check
the path, permissions, and filesystem. The file genuinely exists. Nothing in
Maven's documentation warns that `-s` and `--settings=` behave differently in
config files vs command line. The basedir-with-space concatenation is an
implementation detail buried in Maven's argument processing that no error
message or log reveals.

### Why this fix

The `=` form is the only reliable workaround because it prevents the whitespace
tokenizer from splitting flag and value. Moving the settings file into `.mvn/`
is belt-and-suspenders — it works with any path form but eliminates the need
for absolute paths that make the mangled error even harder to diagnose.

### Alternatives considered

- **Quoting the path** (`-s "/path/to/settings.xml"`) — Maven's config parser
  doesn't honour shell-style quoting; quotes become part of the path string
- **Symlinks** — creating a symlink in the project root pointing to the real
  settings file works but adds fragile indirection
- **Environment variable** (`-s ${SETTINGS_PATH}`) — `.mvn/maven.config` does
  not expand environment variables
