### Symptom
After using `ide_edit_member` to replace a method, `git diff` shows every line in the method changed — even lines that were logically identical to the original.

### Context
Using the IntelliJ Index MCP plugin's `ide_edit_member` tool to replace a method body. The tool accepts the new method content as a string and replaces the entire declaration. Occurs regardless of whether `reformat: true` (default) or `reformat: false` is set.

### Root cause
`ide_edit_member` replaces the complete method declaration and then applies IntelliJ's code formatter to the changed range. The formatter uses IntelliJ's project-level code style settings, which may differ from the file's current formatting — for example, aligning dot-chain calls to the opening parenthesis instead of using standard 8-space indentation.

### Fix
When replacing a method where the body content hasn't changed (e.g. you were only trying to add/remove annotations), restore the original formatting after the edit:

```bash
git checkout -- path/to/File.java
```

When the method content DID change, accept the reformatted version or use `ide_replace_text_in_file` for surgical changes that preserve surrounding formatting.

### Why this is non-obvious
The tool description mentions auto-reformatting but doesn't warn that it reformats the ENTIRE replaced range, not just the new content. The `reformat` parameter suggests formatting is controllable, but the replacement mechanism itself introduces formatting changes regardless.
