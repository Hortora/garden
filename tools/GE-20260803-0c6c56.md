### Symptom
Calling `ide_change_signature` on a Java record to add a new component
(e.g. adding `Instant countdownEndsAt` to a 12-field record) returns
"No method found at line N, column M" regardless of cursor position —
including the record name, the opening parenthesis, and various column
offsets on the declaration line.

### Context
Java records have a canonical constructor implicitly defined by the
record declaration. The IntelliJ MCP `ide_change_signature` tool
expects to find a method/constructor PSI element at the cursor position.
Record components are not methods — the tool does not resolve the
canonical constructor from the record header.

### Root cause
`ide_change_signature` resolves the target via method PSI lookup. Java
record canonical constructors are synthesised by the compiler and do not
appear as explicit method declarations in the PSI tree at the record
header position. The tool cannot find a method element to modify.

### Fix
Use `ide_edit_member` with `member` set to the record class name to
replace the entire record declaration, then fix all caller sites:

1. `ide_edit_member(file, member=RecordName, content="public record RecordName(...new fields...) {}")`
2. `ide_build_project` to find all broken constructor calls
3. Fix each call site with `ide_replace_text_in_file`

Alternatively, use `ide_find_references` on the record class before
editing to enumerate all construction sites upfront.

### Why this is non-obvious
The tool accepts `line` and `column` parameters that point to the record
declaration — it looks like it should work. The error message ("No method
found at position") doesn't mention records or constructors, so you try
different column offsets before realising the tool fundamentally doesn't
support record component changes.
