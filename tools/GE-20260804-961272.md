## capture-pane without -e strips ANSI — replayed terminal display garbles

**ID:** GE-20260804-961272
**Stack:** tmux 3.x, xterm.js, WebSocket terminal

### Symptom

Terminal content captured via `tmux capture-pane -p` and replayed to xterm.js via WebSocket renders garbled: text centres instead of left-aligning, horizontal divider lines fragment across the width, and the cursor lands at the wrong position. The content is "there" but the layout is broken.

### Context

WebSocket terminal that captures tmux pane history on connect (to show prior content when reconnecting). The capture output is sent as the initial WebSocket text message before starting `pipe-pane` for live output.

### What was tried (didn't work)

- Increasing resize sleep time — doesn't affect capture output format
- Different capture-pane line counts (-S values) — same garbling regardless
- Matching xterm cols/rows to tmux pane size — necessary but not sufficient

### Root cause

Two issues compound:

1. **Missing `-e` flag:** `capture-pane -p` strips all ANSI escape sequences (colors, cursor movement, screen clearing). Without escapes, xterm.js can't position text correctly — everything renders sequentially from top-left. TUI apps like Claude Code use ANSI escapes extensively for layout.

2. **Missing cursor repositioning:** After replaying history, xterm.js's cursor is at the end of the replayed text, not at the tmux pane's actual cursor position. New input from `pipe-pane` arrives at the tmux cursor position but xterm renders it at its own cursor position — causing text to appear at the wrong row.

### Fix

```java
// 1. Capture with ANSI escapes preserved
String history = tmux.capturePane(sessionName, 100);  // uses -e flag
// capturePane: "tmux", "capture-pane", "-t", name, "-e", "-p", "-S", ...

// 2. Send history
connection.sendTextAndAwait(history);

// 3. Reposition cursor to match tmux pane cursor
String cursorInfo = tmux.displayMessage(sessionName, "#{cursor_y} #{cursor_x}");
String[] parts = cursorInfo.trim().split("\\s+");
int row = Integer.parseInt(parts[0]) + 1;  // tmux is 0-based, ANSI is 1-based
int col = Integer.parseInt(parts[1]) + 1;
connection.sendTextAndAwait("\033[" + row + ";" + col + "H");
```

Both fixes are required — `-e` alone still leaves the cursor wrong, and cursor positioning alone still garbles the text layout.

### Why this is non-obvious

`capture-pane -p` produces readable text output — it looks correct when printed to a terminal. The garbling only appears when the output is replayed to a different terminal emulator (xterm.js) that expects ANSI positioning. The `-e` flag is documented but its necessity for replay isn't — the docs describe it as "include escape sequences" without explaining that omitting it breaks replay to other terminal emulators.
