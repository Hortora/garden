### Symptom
Import resolution failures in a `git clone --shared` repo — yarn typecheck and
tests fail with "module not found" errors. No mention of the missing directory
in any error output.

### Context
A project uses yarn portal resolutions pointing to a gitignored directory
(e.g., `.casehub-packages/` containing 20 built packages from another repo).
The root `package.json` has entries like
`"@casehubio/graph-core": "portal:./.casehub-packages/packages/graph-core"`.
When `git clone --shared` creates an isolated workspace (e.g., for parallel
slot-based work), the gitignored directory is not cloned.

### What was tried (didn't work)
Running `yarn install`, `yarn typecheck`, `yarn test` — all fail with missing
module errors. The error messages point to import paths and module resolution,
not to a missing directory.

### Root cause
`git clone --shared` only copies tracked content. Gitignored directories —
regardless of whether they contain essential build dependencies — are silently
omitted. The clone appears complete (no warnings, no errors) but is missing
a directory the build system depends on.

### Fix
After cloning, detect gitignored-but-present directories in the source repo
and symlink them into the clone:

```python
for entry in sorted(source_repo.iterdir()):
    if not entry.is_dir() or entry.name == ".git":
        continue
    if entry.name in REGENERABLE_DIRS:  # node_modules, build, dist, target, etc.
        continue
    clone_entry = clone_dest / entry.name
    if clone_entry.exists():
        continue
    rc, _, _ = run(["git", "check-ignore", "-q", entry.name], cwd=source_repo)
    if rc == 0:  # gitignored
        clone_entry.symlink_to(str(entry.resolve()))
```

Skip regenerable directories (node_modules, build, dist, target, IDE artifacts)
— these should be recreated in the clone's own context.

### Why this is non-obvious
The error messages are about import resolution — you investigate package.json,
yarn configuration, or node_modules before suspecting a missing gitignored
directory. The directory name never appears in any error output. The clone
operation itself reports success with no warnings.
