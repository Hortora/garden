### Symptom

After calling `ide_replace_member` on a method, the Java file has a nested method declaration:

```java
void onCoachingCompleted(@Observes CoachingCompleted event) {
    void onCoachingCompleted (@Observes CoachingCompleted event){
        // ... actual body
    }}
```

Compilation fails with `illegal start of expression` at the inner method declaration.

### Context

Using the IntelliJ MCP plugin's `ide_replace_member` tool to update a method. The `content` parameter includes the full method declaration (modifiers, return type, name, parameters, body) — not just the body.

### What was tried (didn't work)

Called `ide_replace_member` with `content` containing the full method signature and body. Expected it to replace the entire method. Instead got a nested declaration.

### Root cause

`ide_replace_member` replaces only the **body** of a method (the code between `{` and `}`). The `content` parameter should contain only the body statements, not the method signature. When `content` includes the full declaration, it gets inserted inside the existing method's braces, creating a syntactically broken nested method.

### Fix

Use `ide_edit_member` instead of `ide_replace_member` when you need to replace the entire method declaration (signature + body). `ide_edit_member` replaces the complete declaration from the first modifier/annotation through the closing brace.

| Tool | What it replaces | Content parameter should be |
|------|-----------------|---------------------------|
| `ide_replace_member` | Method body only (between `{` and `}`) | Body statements without braces |
| `ide_edit_member` | Entire declaration | Full method with modifiers, signature, and body |

### Why this is non-obvious

The tool names suggest `replace_member` is the more complete operation ("replace the member") while `edit_member` sounds like a partial edit. The actual semantics are the opposite: `edit_member` replaces the whole thing, `replace_member` replaces only the body. The distinction is not documented in the tool description clearly enough to prevent the mistake on first use.
