### Context

When threading a new parameter through a deep private method chain (e.g., `rules()` → `publishByTarget()` → `publishWorkerSchedule()` → `scheduleWorker()`), manually editing each method signature and every call site is tedious and error-prone.

### Technique

Use `ide_change_signature` starting from the innermost method and working outward. Each call adds the parameter with a `defaultValue` of `"null"`, which IntelliJ inserts at all call sites automatically. Then replace the `null` literals with the actual value at each level.

```
# Start from the leaf method — callers get null injected
ide_change_signature(file, line, column, newParameters=[
    ...existing params with oldIndex...,
    {oldIndex: -1, name: "activationSnapshot", type: "JsonNode", defaultValue: "null"}
])
# Move up one level — same pattern
# After all signatures updated, replace null with the real argument at each call site
```

### Why this is non-obvious

The instinct is to edit from the top of the chain (where the data originates) and thread downward. But `ide_change_signature` only updates callers of the method being changed — not callees. Working leaf-to-root means each level's callers automatically get the default value inserted, and you only need to manually update the values after all signatures are in place.
