## Symptom

After calling `ide_replace_member` to write Java code containing HTML entity strings (e.g. `"&amp;"`, `"&lt;"`), the file contains decoded entities instead (`"&"`, `"<"`). The tool reports success. The code compiles but produces wrong output — `replace("&", "&")` is a no-op instead of `replace("&", "&amp;")`.

## Context

Writing an HTML escaping method like:

```java
return value.replace("&", "&amp;").replace("<", "&lt;");
```

Using `ide_replace_member` with this as the content parameter. The tool's content processing layer decodes HTML entities before writing to the file.

## What was tried (didn't work)

```
ide_replace_member(file, class, member, content='return value.replace("&", "&amp;")...')
```

Result in file: `return value.replace("&", "&")...` — entities decoded to literal characters.

## Root cause

The IntelliJ MCP plugin's content parameter processing appears to decode HTML entities before applying the replacement. The content is treated as markup rather than raw text.

## Fix

Use `ide_replace_text_in_file` instead of `ide_replace_member` when the content contains HTML entity strings. `ide_replace_text_in_file` performs plain text find-and-replace without entity processing:

```
ide_replace_text_in_file(file, searchText='old code', replaceText='return value.replace("&", "&amp;")...')
```

This preserves the entity strings as-is.

## Why this is non-obvious

The tool reports success and the file is modified — there's no error or warning. The entity decoding is invisible unless you inspect the file content after the write. The code still compiles (the replace calls are valid Java, just no-ops). The bug only manifests at runtime when the HTML escaping fails to escape.
