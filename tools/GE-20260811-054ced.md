### Symptom
`work next` repeatedly reports "no .plan" even though the file visibly exists at the slot root (e.g. `/slots/110/.plan`).

### Context
In multi-repo slot-based work, the `.plan` file may be created at the slot root directory. `plan_manager.detect()` is the canonical detection function called by `ctx.py` to find the plan.

### Root cause
`plan_manager.py:detect()` (line 607) hardcodes `workspace_path / "design" / ".plan"` as the only search path. It never checks `workspace_path / ".plan"`. Additionally, `ctx.py`'s search chain (workspace → ws_git_root → project dir → primary repo workspace) never checks the slot root directory (`project.parent`).

### Fix
Two changes needed:

1. `plan_manager.py:detect()` — check both paths:
```python
def detect(workspace_path):
    plan_path = workspace_path / "design" / ".plan"
    if not plan_path.exists():
        plan_path = workspace_path / ".plan"
    if not plan_path.exists():
        return None
```

2. `ctx.py` — add slot-root search after existing chain:
```python
if _plan_info is None and _is_slot_path(str(project)):
    _plan_info = _plan_detect(Path(project).parent)
```

Tracked as Hortora/soredium#221.

### Why this is non-obvious
The `.plan` file exists and is visible. The error message ("no .plan") gives no indication that the detection function only looks in one specific subdirectory. The slot-root path is a reasonable location that other slot infrastructure already uses.
