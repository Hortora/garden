### The technique
When a parser has a pre-extraction phase that converts domain-specific syntax before a general-purpose walker processes the AST, nested constructs (like concurrent branches) can bypass pre-extraction. The fix: make pre-extraction accept an optional second-phase resolver (the catalog), and when available, recursively resolve nested contents through the full pipeline.

### How it works
```typescript
function preExtract(rawSteps, catalog?) {
  // ... handle top-level signal/await ...
  
  if ('concurrent' in step && catalog) {
    // Recursive path: resolve branches through full pipeline
    for (const [name, branchSteps] of Object.entries(branches)) {
      const resolved = resolveStepArray(branchSteps, catalog);  // calls preExtract internally
      resolvedBranches.push({ kind: 'block', name, steps: resolved });
    }
    // Emit as pre-extracted (already resolved)
  }
  
  if ('concurrent' in step) {
    // Fallback: pass raw branches to walker (no pre-extraction)
  }
}
```

The catalog parameter gates the recursion: when the parser calls `preExtract` with a catalog, nested branches get full processing. When the Walker or other consumers call `preExtract` without a catalog, the old non-recursive path is used.

### Why this is non-obvious
The natural instinct is to modify the Walker to handle the domain-specific syntax directly (adding `await`/`signal` as step types). But this violates the separation between the parser's domain knowledge and the Walker's generic step resolution. The catalog-gated mutual recursion preserves the architecture while solving the nesting problem.

Termination is guaranteed because concurrent branch arrays are strict subsets of the parent step array — the recursion always operates on fewer steps.
