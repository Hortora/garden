## Symptom

Need to fetch only dense vectors from a Qdrant collection that has multiple vector types (dense, sparse, ColBERT, BM25), but the docs show `with_vector: true` (all vectors) or `with_vector: false` (none).

## Context

Collection has four named vector types. Fetching all vectors per point adds significant payload when you only need the 1024-dim dense vectors for similarity computation.

## Fix

Pass an array of named vector names instead of a boolean:

```json
{
  "limit": 100,
  "with_vector": ["dense"],
  "with_payload": {"include": ["title", "domain", "sourceDocumentId"]}
}
```

The response includes only the requested vector type under `point.vector.dense`, omitting sparse, ColBERT, and BM25 vectors entirely.

## Why this is non-obvious

The Qdrant REST API documentation primarily shows `with_vector: true|false`. The array-of-names syntax is not prominently documented but works and significantly reduces response payload size when a collection has multiple vector types.
