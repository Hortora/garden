## Claude CLI --max-budget-usd silently kills subprocesses mid-output

**Resolved in: design-review skill (soredium, 2026-08-21)** — `--max-budget-usd` removed from `build_claude_command()` in `setup.py`. Budgets are now advisory only — logged post-session, not enforced as a hard kill.

---

**ID:** GE-20260821-8383e6
**Stack:** Claude Code CLI, Python subprocess, design-review skill

### Symptom
Review agents (spawned by `design-review/review.py` as Claude CLI subprocesses) die with exit code 1 after ~300 seconds. The reported cost is $0.00. No output file is created despite the agent narrating "writing review findings" moments before death. The review script logs `Session failed (exit 1):` with nothing after the colon — no error message, no stack trace.

### Context
The `design-review` skill spawns Claude CLI instances via `subprocess.Popen` with `--max-budget-usd 5.0`. The agents spend their budget navigating platform SPIs via IntelliJ MCP (reading decompiled library classes). By the time they attempt to write their review output, the budget is exhausted.

### What was tried (didn't work)
1. Re-running with `--workspace` flag to resume — same failure pattern every time
2. Checking the script's timeout constants — `SESSION_TIMEOUT=600s`, `SESSION_HARD_TIMEOUT=1800s`, neither was reached
3. Looking for stderr output — the script only captures stderr for timeout kills (returncode < 0), not for budget kills (returncode 1)

### Root cause
`--max-budget-usd` is a hard enforcement gate on the Claude CLI. When the budget is exhausted, the CLI exits with code 1 — identical to any other error. The subprocess dies before it can write its output file. The review script sees exit code 1 but has no way to distinguish budget exhaustion from a genuine error because:

1. The exit code is the same (1) for budget exhaustion and other failures
2. stderr is only read after timeout kills (returncode < 0 check on line 1152-1161)
3. The $0.00 reported cost is because the cost tracking doesn't survive the crash

The script's own timeout system (600s soft / 1800s hard) never fires because the CLI's budget flag kills the process first at ~300s.

### Fix
Remove `--max-budget-usd` from `build_claude_command()` in `design-review/setup.py`. Both the fresh-session path (line 322) and the resume-session path (line 304) had the flag. Budgets should be advisory — logged after the session completes for cost visibility, never enforced as a hard subprocess kill.

Additionally, the script should capture stderr for ALL non-zero exit codes, not just timeout kills. This is a secondary bug that made diagnosis impossible.

### Why this is non-obvious
Exit code 1 with $0.00 cost and no stderr looks like a crash, an API error, or a permission problem — not budget exhaustion. The 300-second timing is coincidental enough to suggest context window limits or tool timeouts. Without knowing that `--max-budget-usd` is a hard kill (not advisory), the diagnosis points in the wrong direction entirely. Four consecutive failures across two separate runs were needed to establish the pattern.

### Alternatives considered
- Increasing the budget per session — masks the problem; agents with expensive exploration (IntelliJ MCP reads of decompiled classes) will always risk hitting any fixed budget
- Making budgets per-round instead of per-session — more complex, still a hard kill
- Advisory budgets with a warning at N% spent — the chosen approach; simplest, no subprocess death
