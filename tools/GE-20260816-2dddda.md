### Symptom
`python3 ~/.claude/skills/project/ctx.py` exits with `ERROR: Not in a git repository` when CWD is a slot root (e.g. `slots/122/`).

### Context
Slot roots contain cloned repos (`pages/`, `blocks/`, etc.) and metadata (`.slot`, `.plan`) but are not themselves git repositories. `topology.resolve()` runs `git rev-parse --show-toplevel` from CWD and raises `RuntimeError` when it fails.

### Root cause
`topology.resolve()` unconditionally requires CWD to be inside a git repo. Slot roots are plain directories containing git clones — they have no `.git` of their own.

### Fix
Run ctx.py from inside a sub-repo in the slot, not from the slot root:

```bash
cd /path/to/slots/122/pages && python3 ~/.claude/skills/project/ctx.py
```

The topology resolver then finds the pages git root, detects the `.slot` file in the parent, and correctly identifies `layout: slot`.

### Why this is non-obvious
The error message gives no indication that the fix is to change directories. The slot root *feels* like the right CWD since it contains `.slot` and `.plan`. The assumption that CWD must be inside a git repo is implicit in `topology.resolve()` — there's no guard or helpful error suggesting to use a sub-repo.
