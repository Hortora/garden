## lifecycle.py commit-transition expects evidence as single JSON argument

### Symptom
Calling `lifecycle.py commit-transition` with evidence keys as individual arguments (`pushed_repos=[a,b] pushed_shas={...}`) results in `MissingEvidence` — the evidence dict is `None` even though keys were provided.

### Context
The orchestrator needs to fire lifecycle transitions with evidence dicts. The CLI interface for `commit-transition` accepts `from_state=`, `new_state=`, `event=`, and `evidence=` as KEY=VALUE arguments.

### Root cause
`_parse_cli_args` collects all KEY=VALUE pairs into a flat dict. Individual evidence keys (e.g. `pushed_repos=project`) are parsed as top-level options, not as evidence sub-keys. The code expects evidence as a single pre-serialized JSON string: `evidence={"pushed_repos": ["project"]}`.

### Fix
Pass evidence as a single JSON-serialized argument:

```python
if evidence:
    cmd.append(f"evidence={json.dumps(evidence)}")
```

Not:
```python
for k, v in evidence.items():
    cmd.append(f"{k}={json.dumps(v)}")  # WRONG — parsed as top-level opts
```

### Why this is non-obvious
No documentation exists for the `commit-transition` CLI interface. The KEY=VALUE convention used throughout the soredium ecosystem suggests individual arguments would work. The error message (`MissingEvidence`) doesn't indicate the parsing issue — it looks like the evidence wasn't passed at all.
