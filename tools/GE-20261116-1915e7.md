# EMA compensation masking — switching to theoretically correct algorithm regresses accuracy when input noise was absorbed by the previous algorithm

## Symptom

You have a rate-computation algorithm (EMA) that produces ~15% MAPE. You discover the reference system uses a sliding window, not an EMA. You implement the sliding window (which is demonstrably the correct algorithm based on output quantization analysis) and MAPE increases to ~19%.

## Context

Occurs when:
1. The existing algorithm (EMA) was tuned against a system whose physics are imperfect — delivery events arrive at slightly wrong times
2. The EMA's alpha inadvertently absorbs the timing error as smoothing
3. You switch to the theoretically correct algorithm (sliding window, known from fingerprinting output quantization)
4. The correct algorithm has no smoothing — it exposes the raw timing errors

## What was tried

Implemented 240-loop sliding window (confirmed correct from SC2 rate quantization: `rate ≡ 27 mod 28`). Gas rate MAPE increased from 15.3% to 18.8%. Swept window sizes — same result. The window was correct; the physics weren't.

## Root cause

The EMA alpha (0.35 for gas) was calibrated via MAPE minimization against oracle replays while physics were imperfect. This calibration implicitly selected an alpha that compensated for delivery timing errors. The sliding window makes no such compensation — it applies the exact delivery count — so it exposes the full timing error.

The algorithm switch is correct in principle but premature. The prerequisite is that per-delivery timing in the simulation must match the reference system before the window can outperform the EMA.

## Fix

Do not switch algorithms until input quality justifies it:
1. First improve physics to match per-delivery timing
2. Then switch to the theoretically correct algorithm
3. The timing-corrected window will outperform the EMA

Keep the existing algorithm as the interim baseline. Document the switchover dependency explicitly.

## Why this is non-obvious

The window algorithm is provably correct (output quantization fingerprinting confirmed it). Every review would conclude "switch to the window." But the EMA's error reduction came not from being correct but from compensating for input noise. The improvement disappears when the compensating mechanism is removed before fixing the underlying input.

The diagnostic signal: if EMA alpha was calibrated by MAPE minimization (not from first principles), it may be absorbing noise, not modelling reality.

### Alternatives considered
- Tried sweeping window sizes around 240 loops — all performed worse than EMA
- Tried different EMA alphas — EMA at any alpha outperformed the window, confirming the issue was input quality not alpha choice
