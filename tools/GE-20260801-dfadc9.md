## iterdir() with is_dir skip silently drops files in subdirectories

**ID:** GE-20260801-dfadc9
**Stack:** Python pathlib, file scanning

**Symptom:** An artifact scanner reports 0 files found when files clearly exist. Promotion scripts run successfully but promote nothing. No error or warning.

**Root cause:** The scanner uses `Path.iterdir()` to list directory contents and `if f.is_dir(): continue` to skip directories. When files are organized in subdirectories (e.g., `specs/issue-273-slug/design.md`), the subdirectory is encountered, skipped, and its contents are never examined.

**Discovery:** 136 artifacts appeared lost across 13 attic slots. Investigation revealed the scanner (`workspace_artifacts.py`) only found top-level files. Specs in issue-specific subdirectories (`specs/issue-NNN-slug/`) were invisible. After fixing the scanner to recurse, only 5 were genuinely missing — 131 were false positives from the flat scan.

**Fix:** Replace flat iteration with recursive scanning:

```python
def _scan_dir(root, cat_dir, ext, exclude_names, exclude_dirs):
    entries = []
    for f in cat_dir.iterdir():
        if f.name in exclude_names:
            continue
        if f.is_dir():
            if f.name in exclude_dirs:
                continue
            entries.extend(_scan_dir(root, f, ext, exclude_names, exclude_dirs))
            continue
        if ext and f.suffix != ext:
            continue
        entries.append(str(f.relative_to(root)))
    return entries
```

**Why non-obvious:** The `is_dir(): continue` pattern is standard Python for "skip directories, process files." It reads as correct. The bug only manifests when the directory structure changes from flat to nested — which can happen gradually as a project grows. The scanner was correct when written; the data organization outgrew it.
