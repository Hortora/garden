### Symptom
`ide_move_file` reports success and creates the file at the destination, but the source file is NOT deleted from disk. The tool response says "Successfully moved" with `affectedFiles` listing both paths. Git sees the destination as a new file and the source as unchanged — leading to duplicate class compilation errors.

### Context
Moving Java files between sibling Maven modules that share the same Java package (split package pattern). Example: moving `TransitionPlanner.java` from `runtime/src/main/java/io/casehub/desiredstate/runtime/` to `runtime-core/src/main/java/io/casehub/desiredstate/runtime/`. The package declaration stays the same — only the Maven module changes.

Not every file exhibits this — in a batch of 25 moves, only 1 file was left as a copy. The behaviour is inconsistent, making it harder to detect.

### What was tried (didn't work)
Trusted the tool's "Successfully moved" response without verifying. The duplicate wasn't caught until the Maven build failed with duplicate class errors.

### Root cause / Fix
`ide_move_file` uses IntelliJ's VFS move semantics, which may not reliably delete the source file when moving between Maven modules in the same project. After any batch of `ide_move_file` operations across Maven modules:

1. List remaining files in the source directory to verify deletions
2. For any files that persist: `git rm <source-path>` to remove the tracked duplicate
3. Verify with `git ls-files` that only one copy is tracked

### Why this is non-obvious
The tool reports success. The `affectedFiles` array in the response includes both source and destination paths, which looks correct for a move operation. The duplicate only surfaces at compile time (duplicate class error) or when manually inspecting the source directory. In a batch of many moves, a single straggler is easy to miss.

### Alternatives considered
- Using bash `cp` + `git rm` instead of `ide_move_file` — blocked by intellij-first hook
- Using `git mv` — also blocked by the hook for Java files
- Always verifying source deletion after every `ide_move_file` — this is the recommended approach
