### Symptom
File content was created by a Claude Code session but never committed to git.
A subsequent session overwrote the file. The original content appears lost.

### Context
Claude Code stores full session transcripts as JSONL files under
`~/.claude/projects/-<path-encoded-project>/`. Each line is a JSON object
containing tool calls and their results. Write tool calls contain the full
`content` parameter — the exact bytes written to disk.

Subagent transcripts are stored in `<session-id>/subagents/agent-<id>.jsonl`.

### Fix
1. Find sessions that referenced the lost filename:
   ```bash
   grep -rl "filename-fragment" ~/.claude/projects/-<project-path>/ | grep -v "the-overwriting-session-id"
   ```

2. In the matching JSONL file, search for Write tool_use entries:
   ```bash
   grep "filename-fragment" <session>.jsonl | grep "Write"
   ```

3. Parse the JSON to extract the `content` field from the Write tool's
   `input` parameters. Also check for subsequent Edit tool calls that
   modified the file — the final state is the Write content plus all Edits
   applied in order.

4. Write the recovered content to the target file.

### Why this is non-obvious
The instinct when a file is overwritten is to check git history. But if
the original was never committed, git has nothing. The session transcript
is the only record — and its JSONL format with nested JSON tool calls
is not trivially searchable. The content is there but requires knowing
the storage structure and parsing the tool call format.
