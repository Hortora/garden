### Context

When migrating from a monorepo-style workspace (one git repo with
subdirectories per project) to per-project repos, you need to extract
each subdirectory's commit history and replay it into the new repo.

### Technique

`git format-patch --relative=<subdir>/` strips the subdirectory prefix
from patch paths, producing patches rooted at the repo root:

```bash
# Extract connectors-only changes from a family workspace
git -C work-casehub/ format-patch --relative=connectors/ \
    main..feature-branch -- connectors/

# Apply to the new per-project workspace clone
git -C wsp-casehub-connectors/ am *.patch
```

The `--relative=connectors/` flag means a file at
`connectors/specs/design.md` in the source becomes `specs/design.md`
in the patch — matching the new repo's root.

### Edge cases

- Cross-subdirectory commits (touching both `connectors/` and `pages/`)
  produce patches containing only the matching subdirectory's changes.
  Atomicity across repos is not preserved, but each repo gets its
  complete file-level changes.
- If no commits touch the subdirectory, no patches are generated —
  the fresh clone is already correct.
- Empty subdirectory-only commits (metadata changes, permission changes)
  may produce empty patches that `git am` skips.

### Why this is non-obvious

Most developers reaching for subdirectory extraction would use
`git filter-branch` or `git subtree split` — both heavyweight,
slow on large histories, and destructive. `format-patch --relative`
is lightweight, incremental (works on branch ranges), and
non-destructive (the source repo is unchanged).
