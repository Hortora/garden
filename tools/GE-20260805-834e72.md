### Context
When adding new capability to a layered system (e.g. server-side pagination in a data
pipeline), the question "which layer owns this?" often has two plausible answers. Abstract
reasoning about responsibilities ("a middleware wrapper encapsulates the concern") can
lead to solutions that add indirection without encapsulation.

### Technique
Trace the actual event flow through the code. Start from the user action (DOM event) and
follow each handler, function call, and data transformation to see which layer already
touches every integration point.

### Example
For server-side pagination in casehub-pages:
1. Table emits `pages-page` DOM event with `{ offset, count }`
2. `site.ts` handler receives it, updates `componentViewState`
3. Calls `pipeline.handleDataRequest()`
4. Pipeline's `pushData()` reads page state, calls `manager.lookup({ rowOffset, rowCount })`

The pipeline already: (a) handles page events, (b) tracks page state, (c) has template
URL resolution, (d) manages the DataSetManager cache. A middleware `DataSource` wrapper
would sit outside this event path — the pipeline would still need to detect server-paged
sources, route events to the wrapper, and manage its lifecycle. The wrapper adds a layer
but the pipeline does all the work.

### Fix
The "fix" is the decision method: trace the event flow, list which layer already owns
each integration point, and put the new logic where the points converge. If every
integration point already lives in one layer, adding a wrapper in a different layer
creates indirection without encapsulation.

### Why this is non-obvious
The abstract architecture argument for a middleware wrapper is compelling: "separation of
concerns," "single responsibility," "the source should manage its own pagination." These
are valid principles. But they optimize for the architecture diagram, not the actual code.
The event flow analysis reveals that the diagram's layers don't align with how events
actually propagate — and a solution that looks clean on the diagram creates special-casing
in the code.
