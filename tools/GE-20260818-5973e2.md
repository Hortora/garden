## Context

Trying to open a new Maven project in a git worktree or slot clone when IntelliJ already has multiple projects open. The typical scenario: a multi-slot development setup where each slot has its own clone of the repo.

## Symptom

`ide_open_workspace` with `modules: ["/path/to/slot/130/work"]`:

```
error: multiple_projects_open
message: Multiple projects are open. Please specify 'project_path' parameter
```

Adding `project_path: "/path/to/slot/130/work"`:

```
error: project_not_found
message: No open project matches the specified path: /path/to/slot/130/work
hint: Path exists but has no .idea directory — not an IntelliJ project.
```

Circular: `ide_open_workspace` needs `project_path` to disambiguate, but the project isn't open yet so no `project_path` matches.

## Fix

Use `ide_open_project` instead. It opens and indexes a single repo by filesystem path. Pass `project_path` pointing to any **already-open** project as the JSON-RPC context:

```
ide_open_project({
    "path": "/path/to/slot/130/work",
    "project_path": "/path/to/already/open/project"
})
```

Returns: `Project 'work' is open and ready.`

The opened project is then usable with all other `ide_*` tools by passing its path as `project_path`.

## Why this is non-obvious

`ide_open_workspace` is the documented way to open multi-module Maven projects. The failure mode when multiple projects are already open is not mentioned in any documentation. The solution (`ide_open_project` with an unrelated `project_path` for JSON-RPC context) is counterintuitive — the `project_path` parameter appears to be about the target project, not about selecting a communication context.
