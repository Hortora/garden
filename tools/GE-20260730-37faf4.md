### Symptom
`git checkout main` fails in a worktree with: `fatal: 'main' is already checked out at '/path/to/original'`. Any operation that needs to switch branches (handover commit, pause, work-end) crashes in worktree-based isolated environments.

### Context
`git worktree add` creates a checkout that shares refs with the original repo. Git enforces that no two worktrees can have the same branch checked out simultaneously. This is a safety feature to prevent divergent commits on the same branch, but it makes worktrees unsuitable for environments that need independent branch control.

### What was tried (didn't work)
- Writing to the original repo's main from within the worktree (requires knowing the original path, fragile)
- Skipping branch-switch operations in worktree context (creates behavioural forks in every downstream script)
- Using `git checkout --detach` before switching (loses branch tracking)

### Root cause
Worktrees share the ref database. The branch lock is per-ref-database, not per-worktree. There is no flag to disable it.

### Fix
Use `git clone --shared` instead of `git worktree add`:

```bash
git clone --shared --branch main /path/to/original /path/to/clone
git -C /path/to/clone checkout -b feature-branch
```

Properties:
- **Independent branch namespace** — `checkout main` works, no conflicts
- **Zero disk overhead** — `--shared` uses alternates (reads objects directly from the original's store)
- **Full history** — all commits, tags, branches from the original are available
- **Origin points to local original** — `push`/`pull` flow naturally between clone and original

For merge back: push from clone to original, then ff-merge in original:
```bash
git -C /path/to/clone push origin feature-branch --force-with-lease
git -C /path/to/original merge --ff-only feature-branch
```

### Why this is non-obvious
`git worktree` is the documented solution for parallel development. `git clone --shared` is documented as a disk-saving clone option, not as a worktree alternative. The connection between "I need independent branch control" and "use clone instead of worktree" requires understanding the shared-refs constraint that worktrees impose — which most developers don't encounter until it blocks them.
