### Symptom
An agent cognitive architecture presents internal state (satisfaction levels, confidence, drive intensities) to the LLM. Using the same format everywhere produces suboptimal behaviour in one mode or the other — raw numbers produce mechanical character dialogue; qualitative labels lose precision in analytical reasoning.

### Context
Building a needs pyramid for autonomous agent characters. Satisfaction per need tier is a float [0.0, 1.0]. Two consumers: (1) the observation pipeline, where the LLM embodies the character and should "feel" its needs; (2) the goal revision strategy, where the LLM analytically reorders goals based on urgency.

### Root cause
LLMs operate in different cognitive modes depending on prompt framing. Numeric values (`Safety: 0.35`) frame data as a metric to be optimised — the LLM reasons about it analytically. Qualitative labels (`"Your sense of safety feels neglected — recent events have left you uneasy"`) frame data as experiential state — the LLM incorporates it into character behaviour, producing richer dialogue and more natural decision-making.

The same underlying data (satisfaction=0.35) should be presented differently depending on which mode the consumer requires.

### Fix

**For LLM-as-reasoner** (goal prioritisation, confidence calibration, priority weighting): present raw numeric values. Precision matters — `0.73` lets the LLM calibrate differently from `0.95`. Fuzzy labels like "high" lose this distinction.

**For LLM-as-character** (observation pipelines, emotional states, inner monologue): present qualitative prose mapped from numeric bands. The label changes the LLM's behavioural mode from analytical to experiential.

```java
// Reasoning consumer — pass the number
"Need satisfaction levels: Safety=0.35, Social=0.72, Tasks=0.28"

// Embodiment consumer — pass the feeling
"Your sense of safety feels neglected — recent events have left you uneasy."
"Your social bonds feel well-met."
```

The mapping function (`bandLabel()`) is a simple threshold check — the engineering cost is trivial. The behavioural impact is significant.

### Why this is non-obvious
The default assumption is to pick one format and use it everywhere. Prior work dismissed fuzzy logic for LLM interactions because "LLMs understand probability numbers" — which is correct for reasoning but wrong for embodiment. The insight is that the same data has two valid presentations, and the choice depends on the consumer's cognitive mode, not the data's type.

### Alternatives considered
- **Numbers everywhere** — precise but produces mechanical character dialogue ("I note my safety metric is low")
- **Labels everywhere** — natural but loses precision for analytical tasks (the LLM can't distinguish between satisfaction 0.35 and 0.15 when both are "neglected")
- **Dual format ("neglected (0.35)")** — maximum information but breaks immersion for embodiment and adds noise for reasoning
