### Symptom
`mvn -f /path/to/module/pom.xml test` fails with:
```
ERROR: The specified user settings file does not exist: /path/to/module/.mvn/slot-settings.xml
```
The settings file exists at the repo root's `.mvn/slot-settings.xml`, not at the `-f` target.

### Context
The repo's `.mvn/maven.config` contains:
```
--settings=.mvn/slot-settings.xml
```
This relative path resolves from Maven's working directory (or the `-f` target location), not from the directory containing `.mvn/maven.config`.

### Root cause
Maven reads `.mvn/maven.config` from the project root (the directory containing the top-level `.mvn/`), but resolves relative paths in that file from the effective working directory — which changes when `-f` points to a different POM.

### Fix
Use an absolute path for `--settings` when invoking Maven from outside the repo root:
```bash
mvn test -f /path/to/module/pom.xml \
  --settings=/absolute/path/to/repo/.mvn/slot-settings.xml
```

Or invoke Maven from within the repo root so the relative path resolves correctly.

### Why this is non-obvious
The `.mvn/` directory convention suggests Maven treats it as a self-contained project configuration root. The relative path in `maven.config` looks like it should resolve relative to `.mvn/` (or the repo root where `.mvn/` lives), but Maven resolves it from the working directory instead.
