## Stateless re-entrant script inverts LLM orchestration control

### Symptom

LLMs reading multi-step SKILL.md instructions skip steps, forget steps,
or execute them out of order. 4/4 audited slot closures had failures
caused by LLM step-skipping. No amount of better instructions fixes this.

### Context

Any Claude Code skill with >10 sequential steps where the LLM reads the
full sequence and orchestrates execution. The failure rate compounds with
sequence length — more steps = more skips.

### Root cause

LLMs are unreliable orchestrators of long sequences. They prioritise
plausible-looking completion over mechanical correctness. The architecture
gives the LLM visibility of all steps, so it can "decide" to skip ones
that seem unnecessary.

### Fix

Invert control: a stateless re-entrant Python script owns the sequence.
Each invocation reads a progress file, runs mechanical steps silently,
yields one ACTION= line for the next judgment step, and exits. The LLM
calls it in a ~20-line loop.

```python
# Orchestrator pattern
def run_orchestrator(args):
    progress = read_progress(workspace)
    if is_stale(progress, meta_state):
        delete_progress(workspace)
        progress = {}

    # Walk steps — skip completed, run mechanical, yield at judgment
    if not done("review"):
        return {"ACTION": "review", "DIFF_RANGE": f"{base}..{branch}"}
    if not done("sweep_config"):
        return {"ACTION": "sweep_config", "ITEMS": defaults()}
    # ... mechanical steps run silently between yield points ...
    return {"ACTION": "complete", "SUMMARY": "Close complete."}
```

The SKILL.md becomes:
```
loop:
  output = run("python3 orchestrator.py ...")
  if ACTION=complete → done
  if ACTION=review → invoke code-review
  if ACTION=sweep_config → present toggle UI
  ... dispatch by action type ...
  go to loop
```

The LLM cannot skip steps because it never sees the step list. Python
decides what's next. Python validates outputs before continuing.

### Why this is non-obvious

The standard Claude Code pattern is LLM-as-orchestrator: the skill
describes what to do, the LLM does it. Claude Code Workflows offer
deterministic orchestration but spawn fresh agents per step, losing
conversation context. The re-entrant script pattern preserves context
(one continuous LLM conversation) while giving Python full control —
a middle ground that neither the standard model nor Workflows provide.

### Why this fix

The decisive advantage over Claude Code Workflows is conversation context
preservation. Work-end benefits from accumulated context: review findings
inform sweep, sweep informs squash analysis, user decisions carry forward.
A Workflow spawns a new agent per step, losing all of this. The re-entrant
script preserves it because the LLM maintains one continuous conversation,
calling the orchestrator repeatedly.
