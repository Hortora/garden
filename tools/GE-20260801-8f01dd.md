## shutil.move leaves ghost directories when a process has CWD anchored inside

**ID:** GE-20260801-8f01dd
**Stack:** Python shutil, OS filesystem, git worktrees

**Symptom:** After `shutil.move(src, dst)` or `shutil.rmtree(path)`, the source directory reappears empty. Repeated removal attempts fail — the directory keeps coming back.

**Root cause:** A running process (shell, IDE, Claude Code session) has its current working directory set to a path inside the directory being moved/removed. The OS recreates the directory structure to maintain the process's CWD reference, even after the directory's contents have been moved elsewhere.

**Discovery:** Slot 46 was archived but `/worktrees/46/engine/` persisted as an empty directory with only `.idea/` inside. `lsof +D` revealed a zsh shell (PID 45638) with CWD anchored there.

**Fix:** Before moving or removing a directory, check if the current process's CWD is inside it and escape:

```python
import os
from pathlib import Path

def escape_cwd(target_dir, escape_to):
    cwd = Path.cwd().resolve()
    target = target_dir.resolve()
    if cwd == target or target in cwd.parents:
        os.chdir(escape_to)
        return True
    return False
```

Call this before `shutil.move()` or `shutil.rmtree()`. This only handles the current process — external processes (other terminal tabs, IDE) must be closed manually.

**Why non-obvious:** The error is silent. `shutil.move()` succeeds, `shutil.rmtree()` succeeds (with `ignore_errors=True`), but the directory reappears. No exception, no error message. The ghost directory looks like a failed removal when it's actually a successful removal being undone by the OS.
