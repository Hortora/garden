### Symptom
After using `ide_replace_text_in_file` to insert Java code containing `\n` escape sequences in string literals, the compiler reports "unclosed string literal" errors at the replacement site.

### Context
Replacing a block of Java code that constructs strings with `sb.append("\nHard constraints: ")`. The `\n` in the replacement string is interpreted as a literal newline character, splitting the Java string literal across two lines.

### What was tried (didn't work)
1. Using `ide_replace_text_in_file` with `\n` in the replacement — produced literal newlines in source
2. Running the replacement again to fix just the corrupted lines — same issue recurred

### Root cause
`ide_replace_text_in_file` performs raw text substitution. The `\n` in the replacement string is interpreted by the transport layer as an actual newline character, not preserved as the two-character escape sequence `\n`. This is correct behaviour for a text replacement tool but surprising when editing source code that contains string escapes.

### Fix
Use `ide_replace_member` instead. It operates at method granularity — you provide the entire method body and the tool writes it structurally, preserving escape sequences in string literals. For non-method changes, `ide_edit_member` (which replaces an entire class member declaration) also preserves escapes correctly.

### Why this is non-obvious
The tool name suggests text-level replacement, which developers expect to be byte-exact. The corruption is silent — no error from the tool itself. The compiler error ("unclosed string literal") points at the wrong line and doesn't hint that the replacement tool caused it. A developer would typically re-read their replacement text looking for a typo rather than suspecting the tool interpreted an escape.

### Alternatives considered
- Escaping the backslash as `\\n` in the replacement — not tested; may work but doubles every backslash in the replacement text
- Using the `Edit` tool (Claude Code native) — works but bypasses IntelliJ's index, so references and imports are not updated
