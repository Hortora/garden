# A state file tracked in a repo is copied into every clone, so each clone silently has its own diverging copy

## Symptom

A tool keeps "the queue" for a piece of work in a tracked file. A work area made of several clones is believed to have one queue. Inspection finds one per clone, all different, each naming a different branch as current. Which one the tool uses depends on the directory it is run from.

## Context

A repository carries a tracked state file (`.queue`). Parallel work areas are built by cloning that repository, sometimes several repositories into one area. A separate copy of the file is also placed at the area root.

## Root cause

`git clone` copies tracked files. A state file that is tracked is therefore instantiated in every clone, with whatever content the base branch had at clone time: the whole backlog of the source repo, not the work of the new area. Each copy then evolves on its own branch. Nothing is wrong at any single step, so nothing reports it.

## Fix

Decide where the state lives by area, not by repository, and make one function answer it:

1. A work area made of clones keeps its state at the area root, outside every repository, and is marked as doing so.
2. A single repository worked on directly keeps it somewhere branch-independent (an orphan-branch worktree), not on the working branch.
3. Inherited copies inside clones are ignored, never deleted.

State that is local to an area is never synced between areas; syncing is what forces merge and reset logic.

## Why this is non-obvious

Tracking the file looks like the safe choice: it is versioned and backed up. The duplication appears only once clones are used for parallel work, and each clone looks correct in isolation. The symptom shows up far away, as tools disagreeing about what is active.

### Alternatives considered

- Syncing the copies through a central repository: needs push, pull and conflict resolution for data that has one owner.
- Stripping the file at clone time: loses it for repositories that legitimately track it, and leaves no rule for where the area's own copy goes.
