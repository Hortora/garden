# git commit with a pathspec reports 'nothing added to commit but untracked files present', not 'nothing to commit'

## Symptom

A script that writes a file and commits it treats "nothing to commit" as success. It works for weeks, then fails with a commit error on a write that changed nothing.

## Context

`git commit -m msg -- <file>` is run when `<file>` is unchanged. The directory contains some other untracked file.

## Root cause

Git has several wordings for an empty commit. With a clean tree it prints `nothing to commit, working tree clean`. With untracked files present it prints `nothing added to commit but untracked files present (use "git add" to track)`. The exit status is 1 in both cases. A check for the substring `nothing to commit` misses the second.

## Fix

Do not parse the message. Ask whether the path differs from what is committed:

```python
if commit.returncode != 0:
    unchanged = git(repo, "status", "--porcelain", "--", filename)
    if unchanged.returncode == 0 and not unchanged.stdout.strip():
        return          # the file is committed as written
    raise CommitFailed(commit.stdout + commit.stderr)
```

## Why this is non-obvious

The code is tested in a clean repository, where the familiar wording appears. The second wording needs an unrelated untracked file to be present, which only happens later, when something else starts using the same directory.

### Alternatives considered

- `git diff --cached --quiet -- <file>` before committing: also works; the status check after a failure keeps the common path to one command.
