### Symptom

Calling `ide_edit_member` with `member` set to the class name (e.g. `member: "ChannelMembershipService"`) and `content` containing only the new declaration line (e.g. `public class Foo implements Bar, Baz`) replaces the **entire class** — all fields, methods, inner classes, and the closing brace — with just the declaration text provided.

### Context

Using IntelliJ MCP tools for Java code editing. The tool documentation says it "Replaces the complete declaration from the first modifier/annotation through the closing brace" — which reads as "replaces the declaration header" but actually means "replaces everything from the first modifier to the final `}`", i.e. the entire class body.

### What was tried (didn't work)

```java
// Tried this to add "implements UnreadCountProvider" to the declaration:
ide_edit_member({
  file: "ChannelMembershipService.java",
  member: "ChannelMembershipService",
  content: "public class ChannelMembershipService implements MembershipManager, UnreadCountProvider"
})
// Result: entire class replaced with just that one line — all methods, fields, imports gone
```

### Root cause

`ide_edit_member` with `member` matching the class name treats the entire class (declaration + body) as the member being replaced. The `content` parameter must include the complete class with all its members, not just the modified declaration line.

### Fix

Use `ide_replace_text_in_file` for declaration-only changes — it does surgical text replacement without touching the rest of the file:

```java
ide_replace_text_in_file({
  searchText: "public class Foo implements Bar {",
  replaceText: "public class Foo implements Bar, Baz {"
})
```

Reserve `ide_edit_member` for replacing entire method/field bodies, not class declarations.

### Why this is non-obvious

The documentation phrase "from the first modifier/annotation through the closing brace" is ambiguous — "closing brace" could mean the declaration's opening brace or the class's closing brace. The actual behaviour is the latter, which is destructive when you only want to change the `implements` clause. The tool description even shows a class example but with `{ ... }` in the content — easy to miss that the `...` must be the actual class body.

### Alternatives considered

- `ide_refactor_rename` — only handles name changes, not interface additions
- Direct `Edit` tool — blocked by hook requiring IntelliJ tools for .java files
