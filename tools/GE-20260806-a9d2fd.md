### Symptom

Maven fails with "The specified user settings file does not exist" showing a
concatenated path like `/cwd/path/ /absolute/path/to/settings.xml` — two paths
joined with a space.

### Context

A `.mvn/maven.config` file in the project root contains:
```
-Dmaven.repo.local=/path/to/.m2
-s /path/to/slot-settings.xml
```

When `mvn` is invoked from a subdirectory (e.g. after `cd` into `sidecar/src/main/webui`
for yarn tests), Maven finds `.mvn/maven.config` by walking up, but misresolves the
`-s` argument path — prepending the current working directory to the absolute settings path.

### What was tried (didn't work)

- Using `-f pom.xml` to specify the POM location — Maven still reads `.mvn/maven.config`
  and misresolves the settings path
- Running from the project root with `cd /project && mvn` — works but requires cwd awareness

### Root cause

Maven's `.mvn/maven.config` parser resolves paths relative to the directory it finds
`.mvn/` in, but when the current working directory differs from the `.mvn/` parent,
the `-s` argument's absolute path gets concatenated with the cwd.

### Fix

Pass `-s` and `-Dmaven.repo.local` explicitly on the command line instead of relying
on `.mvn/maven.config`:

```bash
/opt/homebrew/bin/mvn -f /path/to/sidecar/pom.xml \
  -s /path/to/slot-settings.xml \
  -Dmaven.repo.local=/path/to/.m2 \
  test -Dtest=MyTest
```

Or ensure the working directory matches the `.mvn/` parent directory before invoking Maven.

### Why this is non-obvious

The error message shows a concatenated path with a space, which looks like a quoting
issue. The actual cause is Maven's `.mvn/maven.config` path resolution interacting with
cwd in unexpected ways. The `-s` value is an absolute path, so you'd expect it to be
used verbatim — it isn't.
