## Symptom

ML model accuracy degrades silently when spatial features (centroid position, distances, spread) are masked using the same continuous visibility scalar applied to count features.

## Context

In game AI (or any partial-observability domain), a "scouting visibility" scalar between 0.0 and 1.0 indicates how much of the opponent's state has been observed. Count features (unit counts, building counts, economic stats) degrade gracefully under continuous scaling: 3 marines × 0.3 visibility = 0.9 — a reasonable approximation of "partial information." The intuition is to apply this same mask to all features uniformly.

## Root cause

Count features and spatial features have fundamentally different scaling semantics. A centroid at map position (60, 40) scaled by 0.3 visibility becomes (18, 12) — a valid but meaningless position on the map, not the army's location. Distance features become fractional distances to nowhere. Spread (std dev of positions) becomes a fraction of the actual spread with no spatial meaning.

The model sees what looks like valid positional data but encodes noise — positions that correspond to no real game state. Training with this corruption teaches the model to partially ignore spatial features, reducing the benefit of having them.

## Fix

Use **binary visibility masking** for spatial and ratio features: full value (1.0) when any observation exists, zero (0.0) when no observation exists. Keep continuous masking for count/stat/upgrade features.

```python
# Opponent features split by type
COMP_END = 134  # count/stat/upgrade features
opp_comp = (opp_slice[:, :COMP_END] * continuous_mask[:, np.newaxis]).mean(axis=0)
opp_spatial = (opp_slice[:, COMP_END:] * binary_mask[:, np.newaxis]).mean(axis=0)
# where: binary_mask = (continuous_mask > 0).astype(np.float32)
```

In Java (inference), spatial features are computed from visible units only — binary visibility is inherent since only visible units contribute to the centroid.

### Why this is non-obvious

The intuition to "apply the same mask to all features" is strong — it feels consistent and principled. The failure mode is silent: the model trains, converges, and produces predictions. It just produces worse predictions than it could, and the cause is invisible in standard accuracy metrics unless you A/B test with binary masking.

### Alternatives considered

- **Separate spatial model with its own visibility handling** — adds architectural complexity and loses cross-dimensional interactions (the most valuable signal for strategy classification)
- **No masking at all (always full opponent data)** — unrealistic during training, causes distribution mismatch at inference when visibility is limited
