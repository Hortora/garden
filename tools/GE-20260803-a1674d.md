### Behaviour

`yaml.Document.deleteIn(path)` returns `undefined` and produces no error when the path does not exist in the document. There is no way to distinguish "key was deleted" from "key was already absent" without a separate `getIn()` check before calling `deleteIn()`.

### Context

When implementing property editing for a YAML-based editor, clearing an optional field calls `doc.deleteIn([...nodePath, fieldName])`. If the field was already absent in the YAML (never set by the user), `deleteIn()` silently succeeds. This is useful for idempotent "clear" operations but means you cannot detect whether a delete actually removed something.

### Discovery

Found during implementation of `applyPropertyEdit()` for the CaseHub diagram editor. The `yaml` npm package docs describe `deleteIn()` as "Remove the value at path" but do not document the behavior when the path doesn't exist. Discovered via testing — not documented in the API reference.

### Implication

Safe for fire-and-forget deletion of optional YAML properties. Not safe if you need to branch on "was the key present before deletion" — use `doc.getIn(path) !== undefined` first.
