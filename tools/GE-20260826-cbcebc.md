## Symptom

After using `ide_replace_text_in_file` with `\n` in the replacement text to insert a new line, the file contains a literal backslash-n (`\n`) instead of a newline character. This breaks JSON files (syntax error) and TypeScript files (compile error or unexpected single-line content).

## Context

The `replaceText` parameter of `ide_replace_text_in_file` interprets `\n` as a newline, `\t` as a tab, and `\\` as a literal backslash — per the tool's documentation. However, in practice the escapes appear to be applied inconsistently, and `\n` in the middle of a replacement string can be inserted literally.

## Fix

Do not rely on `\n` for multi-line replacements. Instead, use the tool for single-line replacements only. For multi-line insertions, use:

1. Multiple sequential single-line replacements
2. The `Edit` tool (which handles multi-line content natively)
3. The `Write` tool for full file rewrites

After any `ide_replace_text_in_file` call that includes `\n`, verify the result with `Read` to catch literal insertions.

## Why this is non-obvious

The tool documentation states that `\n` is interpreted as a newline. The literal insertion is silent — no error is reported. The breakage only surfaces when the file is parsed (JSON.parse fails, TypeScript compilation fails) or visually inspected.
