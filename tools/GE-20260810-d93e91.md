## Symptom

Regex with `re.DOTALL` and `.*?` (non-greedy) intended to match content between a markdown heading and its metadata field matches across multiple sections, capturing only the first heading's data and skipping subsequent ones.

## Context

Parsing design-review tracker files where each issue has a heading (`### R1-01: Title`) followed by metadata lines (`- **Status:** VERIFIED`). The goal was to extract all issue summaries with their statuses using `re.finditer`.

## What was tried (didn't work)

```python
for m in re.finditer(
    r"### (R\d+-\d+): (.+)\n.*?\*\*Status:\*\* (\w+)",
    content, re.DOTALL,
):
    # Expected: match each heading with its closest Status line
    # Actual: first match consumed content across multiple sections
```

With `re.DOTALL`, `.` matches newlines. Even though `.*?` is non-greedy, it can still cross section boundaries because there is no anchor preventing it from matching past the next `###` heading. The first match works; subsequent sections are consumed as part of the first match's `.*?` span or skipped entirely.

## Root cause

`re.DOTALL` makes `.` match `\n`, and `.*?` finds the *nearest* `**Status:**` — but "nearest" can be in a completely different section when the pattern between heading and status is ambiguous across sections. The regex engine has no concept of "stay within this section."

## Fix

Use line-by-line parsing instead of a single regex with DOTALL:

```python
def _extract_tracker_summaries(content: str, prefix: str) -> list[str]:
    findings: list[str] = []
    lines = content.split("\n")
    current_id: str | None = None
    current_title: str | None = None
    for line in lines:
        heading_match = re.match(r"### (R\d+-\d+): (.+)", line)
        if heading_match:
            current_id = heading_match.group(1)
            current_title = heading_match.group(2)
            continue
        if current_id and "**Status:**" in line:
            status_match = re.search(r"\*\*Status:\*\*\s*(\w+)", line)
            if status_match:
                findings.append(f"- {prefix}-{current_id}: {current_title} [{status_match.group(1)}]")
            current_id = None
            current_title = None
    return findings
```

### Why this is non-obvious

The intuition that `.*?` (non-greedy) will "stay close" is wrong when `re.DOTALL` is active. Developers expect non-greedy to find the nearest match within a logical section, but regex has no section concept — it operates on the raw character stream. The first match appears correct, masking the failure on subsequent sections.
