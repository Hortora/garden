## git commit --amend targets wrong branch when a script silently switches HEAD before the amend

**ID:** GE-20260818-77a06d
**Stack:** git (all versions)
**Symptom:** `git commit --amend` creates a modified commit on `main` instead of the feature branch. The only visible clue is `[main SHA]` in git's output prefix — easy to overlook when the commit message matches expectations.
**Context:** After a successful `git rebase` of a feature branch, a slot management script (merge-slot) runs internally and leaves HEAD on `main` as a side effect of its merge/push operations. A subsequent `git commit --amend` then amends main's HEAD instead of the feature branch's.

### What was tried (didn't work)
- Ran `git checkout local/main -- .gitignore` + `git commit --amend --no-edit` expecting to amend the feature branch — the amend went on `main` because merge-slot had silently switched HEAD
- The resulting commit graph showed two parallel commits with the same message on different branches, later merged together in a confusing merge commit

### Root cause
`git commit --amend` operates on HEAD, not on "the branch I was just working on." Any script that performs branch operations (`git checkout`, `git merge`) as part of its internal workflow leaves HEAD wherever it last pointed. There is no warning or error — git faithfully amends whatever HEAD points to.

### Fix
Always verify the current branch before running `git commit --amend`:

```bash
git branch --show-current
# Verify output matches expected branch before amending
git commit --amend --no-edit
```

After running any automation script that might switch branches, explicitly check out the expected branch:

```bash
git checkout issue-41-autonomous-agent-template
git commit --amend --no-edit
```

### Why this is non-obvious
The rebase completed successfully on the feature branch, and the amend was the immediate next command in the workflow. There's no reason to suspect HEAD has moved unless you know the intervening script's internals. Git's `[main SHA]` output prefix is the only clue, and it's easily missed when focused on the commit message content rather than the branch name.
