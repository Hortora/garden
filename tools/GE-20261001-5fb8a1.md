### Symptom
`ide_find_class`, `ide_find_file`, `ide_find_symbol`, and `ide_search_text` all return 0 results for a TypeScript project, even for strings that definitely exist in the codebase. No error is reported — just empty result sets.

### Context
Occurs with TypeScript monorepo projects (Yarn workspaces) opened in IntelliJ via `ide_open_project`. The project appears healthy: `ide_index_status` reports `isDumbMode: false, isIndexing: false`, and `ide_file_structure` successfully returns the AST structure of individual files when given explicit relative paths.

### What was tried (didn't work)
- `ide_find_file` with exact filename — 0 results
- `ide_find_class` with known class names — 0 results
- `ide_search_text` with strings known to exist — 0 results
- Specifying `project_path` explicitly — same empty results

### Root cause
The IntelliJ search index (used by Go to File, Go to Symbol, Find in Files) is populated separately from the PSI tree (used by file_structure). TypeScript projects may not have their search indices populated if the project's content roots aren't configured correctly, or if the TypeScript language service hasn't completed its background scan. The project "looks" indexed (isDumbMode=false) but the search-specific indices are empty.

### Fix
Use `ide_file_structure` with explicit relative paths for structure verification. For text search, fall back to `Read` tool + `grep` when `ide_search_text` returns empty results on a TypeScript project. Check `ide_file_structure` first to confirm the project is actually accessible before concluding the search index is broken.

### Why this is non-obvious
`ide_index_status` reports the project as fully indexed and ready. A developer would expect search to work once indexing reports complete. The split between PSI-level access (file_structure works) and search-index access (find/search don't) is not surfaced in any error or warning.
