## Scelight ID_UNIT_POSITIONS tracker event has no typed interface — flat Integer[] with delta-encoded triplets

### Context

When parsing SC2 `.SC2Replay` files via the Scelight library, tracker events are dispatched by `event.getId()` matching constants in `ITrackerEvents`. Most events have typed interfaces: `IBaseUnitEvent` for `UnitBorn`/`UnitInit`/`UnitDone`, `IPlayerStatsEvent` for `PlayerStats`, `IUpgradeEvent` for `Upgrade`.

### What is undocumented

The `UnitPositions` tracker event (`ITrackerEvents.ID_UNIT_POSITIONS = 8`) has **no typed interface**. The `Event` object is a plain `StructView` wrapping a `Map<String, Object>`. Fields must be accessed via raw `event.get()`:

- `event.get("firstUnitIndex")` → `Integer` — starting unit tag index for this batch
- `event.get("items")` → `Integer[]` — flat array of `(unitIndex_delta, x, y)` triplets

### Delta decoding

The `items` array contains groups of 3 integers per unit. The first element of each triplet is a **delta** from a running total, starting at `firstUnitIndex`:

```java
int runningIndex = firstIndex;
for (int i = 0; i + 2 < items.length; i += 3) {
    runningIndex += items[i];   // delta — accumulates
    int x = items[i + 1];
    int y = items[i + 2];
    // runningIndex is the unitTagIndex (no recycle counter)
}
```

**Coordinates** are in tracker scale — the same coordinate system as `UnitBornEvent.getXCoord()` / `getYCoord()`. No scaling needed when mixing with birth positions.

**Tag matching:** `UnitPositions` provides only `unitTagIndex` (no recycle counter). To match against units tracked from `UnitBorn` events (which use `"r-{index}-{recycle}"` tags), maintain a `Map<Integer, String>` from tagIndex to full tag string, populated on birth and cleaned on death.

### Why this is non-obvious

All other tracker events (`UnitBorn`, `UnitDied`, `UnitInit`, `UnitDone`, `PlayerStats`, `Upgrade`) have typed interfaces with named accessor methods (`getUnitTagIndex()`, `getXCoord()`, etc.). `UnitPositions` is the only event requiring raw `Map<String, Object>` access via `StructView.get()`. The `items` array type (`Integer[]`) and its delta-encoded triplet structure are not documented in Scelight source comments, Javadoc, the s2protocol specification, or any SC2 modding reference.

Without the diagnostic step of dumping `event.getStruct().keySet()` and inspecting array element types, the structure is undiscoverable from the API alone.
