## Symptom

Multi-line replacements via `ide_replace_text_in_file` produce files with literal `\n` characters instead of actual newlines. The file becomes a single long line with `\n` text scattered throughout.

## Context

When using `ide_replace_text_in_file` with `replaceText` containing `\n` escape sequences to represent newlines in multi-line code.

## Root cause

Despite the tool description stating "The escape sequences \n, \t, and \\ are interpreted as newline, tab, and a single literal backslash", the `\n` sequences in the `replaceText` parameter are treated as literal two-character strings (backslash + n), not as newline characters.

## Fix

Use actual newline characters in the `replaceText` parameter value — write the replacement text with real line breaks, not `\n` escape sequences.

```
// BAD — produces literal \n in the file
replaceText: "line one\nline two\nline three"

// GOOD — actual newlines in the parameter
replaceText: "line one
line two
line three"
```

## Why this is non-obvious

The tool description explicitly documents `\n` as interpreted escape sequences, which is the opposite of the actual behaviour. The file appears to save successfully (no error), making the corruption silent until you read the file back.
