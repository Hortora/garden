### Symptom
All artifact-scanning tests pass. Production spec promotion silently does nothing.
80 unpromoted specs found across 16 repos during a manual audit.

### Context
`close_artifacts.py:scan_artifacts()` scanned `workspace/specs/<branch>/` — a path
that never existed in any real workspace. Tests created `specs/<branch>/` directories
to match the code, so every test passed. The code was wrong from day one; the tests
locked in the wrong assumption.

### Root cause
Test fixtures were shaped to match the code's expectations, not production's reality.
Specs are flat at `workspace/specs/`, not nested under a branch subdirectory. Since
no test ever created a production-shaped fixture, the broken path was invisible.

### Fix
Build test fixtures that reproduce real directory layouts — derive them from actual
disk inspection, not from what the code currently does. Test against production-shaped
trees, not code-shaped trees.

```python
def build_single_repo_workspace(root: Path) -> Path:
    """Flat workspace (e.g. cc-praxis for soredium).
    Layout derived from actual disk: ls ~/claude/public/cc-praxis/
    """
    (root / "specs").mkdir()
    (root / "specs" / "2026-06-17-design.md").write_text("# Design\n")
    # ... realistic filenames, realistic structure
```

### Why this is non-obvious
When all tests pass, there's no signal that fixtures are wrong. The test suite
itself becomes a source of false confidence — "tests pass, so paths must be
correct." The only way to catch it is comparing fixtures against production
directory structure, which requires stepping outside the code entirely.

### Alternatives considered
- Snapshot-testing the filesystem: too brittle, breaks on unrelated changes
- Integration tests against real workspaces: couples tests to machine state,
  makes them non-portable
- Production-shaped fixtures (chosen): portable, explicit, documents the real
  layout in the test file itself
