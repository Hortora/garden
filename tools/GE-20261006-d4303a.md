## JQ uses 'or' keyword not '||' for logical OR — || is the pipe-alternative operator

**ID:** GE-20261006-d4303a
**Stack:** JQ (all versions), jackson-jq (Java)
**Symptom:** `ParseException: Encountered " "|" "| "" at line 1, column N` when using `||` in a JQ expression. The error points at the pipe character, not the logical operator.
**Context:** When writing JQ expressions in Java string literals (e.g. case completion conditions), or any JQ context where logical OR is needed.

### What was tried (didn't work)
- Read the error as a pipe parsing issue — wrong direction
- Tried escaping the `|` characters — still fails

### Root cause
JQ's logical OR is `or` (keyword), not `||`. In JQ, `|` is the pipe operator and `||` is parsed as two consecutive pipes, which is syntactically invalid. This catches developers coming from Java, JavaScript, Python, or C where `||` is the standard logical OR.

JQ logical operators: `and`, `or`, `not` (all lowercase keywords).

### Fix
```jq
# Wrong — ParseException
.status == "done" || .status == "failed"

# Right — use 'or' keyword with parenthesized operands
(.status == "done") or (.status == "failed")
```

In Java string literals:
```java
// Wrong
.completion(".cveStatus == \"resolved\" || .cveStatus == \"escalated\"")

// Right
.completion("(.cveStatus == \"resolved\") or (.cveStatus == \"escalated\")")
```

### Why this is non-obvious
Every mainstream language uses `||` for logical OR. JQ's choice of `or` keyword is correct for its functional style but trips up anyone who hasn't internalized JQ's operator vocabulary. The error message about `|` pipes further misdirects — you think it's a quoting or escaping issue, not an operator issue.
