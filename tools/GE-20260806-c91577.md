### The convention

When combining closure state across project and workspace repos, the
**worst state wins**. If the project branch is `CLOSED` but the workspace
branch is `OPEN`, the combined result is `OPEN`.

### Priority ordering

```python
_CLOSURE_PRIORITY = [
    ClosureState.CLOSED,           # index 0 — best
    ClosureState.MERGED_UNSTAMPED, # index 1
    ClosureState.OPEN,             # index 2
    ClosureState.STAMPED_UNMERGED, # index 3
    ClosureState.DELETED,          # index 4 — worst
]

# Worst state wins:
result = max(project_state, workspace_state,
             key=lambda s: _CLOSURE_PRIORITY.index(s))
```

### Why non-obvious

The natural instinct is to use `min()` — "take the minimum state." But
with this ordering where index 0 is the best state, `min()` returns the
*best* state (lowest index), which means "if either repo is CLOSED, report
CLOSED" — the opposite of what's needed.

`max()` returns the highest index = the worst state = the most conservative
answer. This was caught as a test failure during initial implementation.

### Alternative

The `DELETED` state is special-cased: if the workspace branch doesn't exist
(`DELETED`), the project state is returned directly rather than downgrading
to `DELETED`. This handles single-repo mode and branches that only exist
in the project repo.
