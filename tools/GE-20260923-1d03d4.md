### Symptom
After using `ide_replace_text_in_file` to replace type references (e.g. `ActorTrustScore` → `ActorTrustScoreBase`), class names and imports containing the search string as a substring get corrupted: `ActorTrustScoreRepository` → `ActorTrustScoreBaseRepository`, and previously-replaced text gets double-applied: `ActorTrustScoreBase` → `ActorTrustScoreBaseBase`.

### Context
Refactoring entity type references in a JPA SPI interface file. The intent was to change return types from the entity type to a new base POJO type. The file contained both the entity type name and identifiers that included the entity type name as a prefix (e.g. `ActorTrustScoreRepository`).

### What didn't work
- Single `ide_replace_text_in_file` call with `searchText: "ActorTrustScore"` and `replaceText: "ActorTrustScoreBase"` — replaces ALL occurrences including within longer identifiers
- Running the replacement twice (once for imports, once for type references) compounds the corruption

### Root cause
`ide_replace_text_in_file` does plain text replacement, not semantic/symbol-aware replacement. It has no word-boundary detection. Every occurrence of the search string is replaced, including when it appears as a substring of a longer identifier. The replacement text itself can then be matched on subsequent replacements if the same call matches it.

### Fix
Use `ide_refactor_rename` for symbol-level renames — it is semantically aware and only renames the targeted symbol, not substrings. For type reference changes in specific locations, use multiple targeted `ide_replace_text_in_file` calls with the FULL identifier as the search string:

```
# WRONG — matches substrings
ide_replace_text_in_file(searchText="ActorTrustScore", replaceText="ActorTrustScoreBase")

# RIGHT — full identifier, no substring matches
ide_replace_text_in_file(searchText="import io.example.ActorTrustScore;", replaceText="import io.example.ActorTrustScoreBase;")
ide_replace_text_in_file(searchText="Optional<ActorTrustScore>", replaceText="Optional<ActorTrustScoreBase>")
ide_replace_text_in_file(searchText="List<ActorTrustScore>", replaceText="List<ActorTrustScoreBase>")
```

### Why this is non-obvious
The tool name (`ide_replace_text_in_file`) suggests IDE-level intelligence, but it performs raw text substitution. A developer using IntelliJ's GUI "Replace" would see highlighted matches and catch substring hits before applying. The MCP tool applies all replacements silently. The double-application case (`Base` → `BaseBase`) is especially surprising because the replacement text itself becomes a match target within the same operation.
