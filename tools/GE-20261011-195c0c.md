### Symptom

Coverage gate reports 14% node field coverage despite data being present. All entities checked against all fields, but many fields only apply to specific entity types — PAD applies to persons, lifecycle to most types, goal_tier only to goals. A single concept node without PAD fails the entire PAD field check.

### Context

Knowledge graph with 276 nodes across 7 entity types (person, place, activity, goal, project, concept, organisation). Coverage checker required 100% of entities to have a field for it to count as "populated". With diverse types, many fields had 50-80% coverage which is correct but scored as 0%.

### Fix

Per-field threshold — a field counts as "populated" when ≥50% of applicable entities have it:

```python
field_threshold = 0.5
for field_def in fields:
    relevant = [n for n in nodes if _field_applies(field_def, n, stage)]
    present = sum(1 for n in relevant if _check_field(field_def, n))
    if present >= len(relevant) * field_threshold:
        populated_count += 1
```

Combined with **stage-aware filtering** — extraction-stage checks skip importer-only fields:

```python
def _field_applies(field_def, entity, stage=None):
    if stage:
        stages = field_def.get('stages', [])
        if stages and stage not in stages:
            return False
    # ... type_filter, event_filter checks
```

**Results:** Node coverage 14.3% → 77.8% with the same data. The data was always there; the checker was too strict.

### Why this is non-obvious

The 100%-per-field requirement seems correct in isolation — "every entity should have a name" is a reasonable check. But knowledge graphs are inherently heterogeneous. Applying uniform field requirements across entity types is like requiring every database row to have values in every column regardless of which table it's in. The fix is obvious once stated, but the symptom (low coverage despite good data) leads you to investigate the extraction prompts first, not the checker.
