### Symptom
After `git pull --rebase origin main`, Maven compilation fails with "cannot find symbol" for classes that exist in sibling module jars (e.g., `ExchangeProcessor` in `worker-api`). The classes are present in the host `~/.m2/repository` but not in the slot's local `.m2`.

### Context
Clone-based slots use `-Dmaven.repo.local=/path/to/slot/.m2` to isolate Maven state. The slot's `.m2` is populated at slot creation time. When the branch is rebased on `origin/main` which added new dependencies or new classes to existing SNAPSHOT jars, the slot's `.m2` still has the old jars.

### What was tried (didn't work)
- `mvn clean install` — fails because the stale dependency is needed to compile
- `-Dmaven.test.skip=true` — skips test compilation but doesn't fix main compilation when the new class is in a runtime dependency

### Root cause
The slot's `maven.config` sets `-Dmaven.repo.local=<slot>/.m2` with `slot-settings.xml` declaring the host `~/.m2/repository` as a fallback repo (`host-m2`). But Maven's SNAPSHOT metadata caching prevents it from checking the host repo — it sees the existing (stale) SNAPSHOT jar in the local repo and doesn't look further.

### Fix
Sync all casehub SNAPSHOT jars from the host `.m2` to the slot's `.m2`:

```python
# sync_m2.py — copy newer SNAPSHOT jars from host to slot
for jar in host_m2/io/casehub/**/*-SNAPSHOT.jar:
    if slot_m2 has same path but different size:
        copy host → slot
```

Or manually copy the specific stale jar:
```bash
cp ~/.m2/repository/io/casehub/<artifact>/<version>/*-SNAPSHOT.jar \
   <slot>/.m2/io/casehub/<artifact>/<version>/
```

### Why this is non-obvious
The error message ("cannot find symbol") points at the source code, not at dependency resolution. The class genuinely exists in the source and compiles fine in a non-slot context. The slot-specific `.m2` is an implementation detail that doesn't appear in error output.
