### Symptom
After `replace_all` on a short identifier, longer identifiers containing it as a prefix
have their prefix replaced, leaving a broken suffix.

Example: `replace_all` of `AclResourceType.CASE` → `"case"` also matches inside
`AclResourceType.CASE_DEFINITION`, producing `"case"_DEFINITION` — a syntax error.

### Context
Occurs when using Claude Code's Edit tool with `replace_all: true` on a string that
is a prefix of other strings in the same file.

### Root cause
`replace_all` performs literal string replacement on all occurrences. It does not
use word boundaries — any substring match is replaced.

### Fix
Replace the longest variant first:
1. `AclResourceType.CASE_DEFINITION` → `"case-definition"`
2. `AclResourceType.CASE` → `"case"`

Or use two separate Edit calls instead of `replace_all`.

### Why this is non-obvious
The tool name `replace_all` suggests "replace all occurrences of this exact string"
which is correct — but the mental model often forgets that the short string is a
substring of the longer one. The resulting code (`"case"_DEFINITION`) is syntactically
broken and the error message doesn't point back to the replacement.
