## Context

Proxying tmux terminal output to a browser via WebSocket for TUI applications like Claude Code (which uses Ink/React for terminals)

## What Was Tried

`capture-pane` for history replay on WebSocket connect, then `pipe-pane` for live output. The two formats (screen state vs output stream) conflict, corrupting cursor positioning.

## Fix

Skip `capture-pane` entirely. Start `pipe-pane` first, then force a full screen redraw via tmux resize cycle (shrink 1 column, wait 50ms, restore). This triggers SIGWINCH → the TUI app re-renders its entire screen cleanly through the pipe.

## Why Non-Obvious

`capture-pane` with `-e` flag (preserve ANSI) seems like it should work for history. The corruption only appears with TUI apps that do heavy cursor manipulation — simple shell prompts render fine with `capture-pane`.
