### Symptom
`gdown` fails with `FileURLRetrievalError: Cannot retrieve the public link of the file` for large publicly-shared files. The browser can download the file (after clicking "Download anyway") but programmatic tools cannot.

### Context
Google Drive shows a virus-scan warning page for files >100MB. `gdown` tries to parse this page but fails when rate-limited or when the file permissions don't allow direct programmatic access.

### Root cause
The virus-scan page is an HTML form that submits to `drive.usercontent.google.com/download` with hidden fields including `confirm=t`. `gdown` parses the HTML to find this URL but fails under rate limiting. The direct download URL with `confirm=t` appended bypasses the confirmation page entirely.

### Fix
```bash
# Pattern: add &confirm=t to skip the virus-scan confirmation
curl -L -o output.tar.gz \
  "https://drive.usercontent.google.com/download?id=FILE_ID&export=download&confirm=t"

# With resource key (some files require it — find in the sharing URL):
curl -L -o output.tar.gz \
  "https://drive.usercontent.google.com/download?id=FILE_ID&export=download&resourcekey=KEY&confirm=t"
```

Note: use `drive.usercontent.google.com` (not `drive.google.com/uc`).

### Why this is non-obvious
The `confirm=t` parameter is not documented in any Google API. The `gdown` FAQ suggests changing file permissions or using cookies, neither of which works for rate-limited public files. The working URL domain (`drive.usercontent.google.com`) differs from the standard sharing URL domain (`drive.google.com`).
