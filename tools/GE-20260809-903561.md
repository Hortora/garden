### Symptom

Users downloading from the `latest` GitHub Release get a mix of artifacts from two different builds — e.g. a snapshot from run A and models from run B. Checksum verification fails with mismatched hashes.

### Context

A common CI pattern for mutable releases: delete the existing `latest` release, then create a new one with the same tag and upload fresh artifacts. If two `workflow_dispatch` runs overlap:

1. Run A deletes `latest` and starts uploading artifacts
2. Run B deletes `latest` (now empty) and starts uploading its artifacts
3. Both runs upload to the same tag — artifacts from different builds are mixed

The window is small but real, especially with large artifact uploads (multi-GB snapshot files that take minutes to upload).

### Root cause

`gh release delete latest && gh release create latest` is not atomic. Between delete and the completion of all uploads, another run can interleave.

### Fix

Use immutable dated releases as the source of truth, then point `latest` at the complete release:

```bash
TAG="garden-$(date +%Y-%m-%d)"

# Create the dated release with all artifacts (immutable)
gh release create "$TAG" --title "Garden Snapshot $TAG" artifacts/*

# Point 'latest' at the complete dated release
gh release delete latest --yes 2>/dev/null || true
gh release create latest --title "Garden Snapshot (latest)" --latest artifacts/*
```

The key insight: `latest` is always created from a complete, already-uploaded artifact set. If two runs race, the worst case is that `latest` points to whichever dated release was created second — but it always points to a complete, consistent set of artifacts.

For stronger guarantees, use a lock mechanism (e.g. GitHub Actions concurrency groups):
```yaml
concurrency:
  group: snapshot-publish
  cancel-in-progress: false
```

### Why this is non-obvious

The delete-then-create pattern is the standard `gh` CLI approach and appears in many GitHub Actions examples. The race window is narrow enough that it works reliably for single-developer projects — it only manifests when multiple runs are triggered in quick succession, which happens during CI iteration or when automated triggers overlap with manual dispatches.
