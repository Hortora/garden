### Symptom

Production SQLite database accumulates thousands of entries from test runs. In the case that triggered this discovery: 2021 slot entries, 2540 work items, and 2477 repo records from pytest runs appeared in `~/.hortora/worklog.db`.

### Context

A worklog module has `connect(db_path=None)` that defaults to `~/.hortora/worklog.db`. Tests that exercise slot creation, lifecycle transitions, or any code that imports the module write to the real DB because nothing overrides the default path.

The pollution is silent — no test fails, no warning is emitted. The DB grows slowly across hundreds of test runs. The only symptom is stale/phantom entries in production queries (e.g. "116 active work items" when only 4 are real).

### Fix

Two changes, both required:

1. **Add env var support to `connect()`:**
```python
def connect(db_path: str | None = None) -> sqlite3.Connection:
    path = db_path or os.environ.get("HORTORA_WORKLOG_DB") or DEFAULT_DB
```

2. **Autouse pytest fixture in `conftest.py`:**
```python
@pytest.fixture(autouse=True)
def _isolate_worklog(tmp_path, monkeypatch):
    monkeypatch.setenv("HORTORA_WORKLOG_DB", str(tmp_path / "test_worklog.db"))
```

The autouse fixture means no test needs to opt in — isolation is automatic for every test in the suite.

### Why this is non-obvious

The pollution is invisible during normal development. Tests pass. The production DB works. The problem only surfaces when you query the DB and get 2000+ phantom entries. The fix is standard (env var + fixture), but the *discovery* that pollution exists requires inspecting the DB directly — nothing in the test output hints at it.
