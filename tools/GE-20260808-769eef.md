### Symptom
Garden-wide topic clustering across 1000+ vector entries requires an N×N pairwise
cosine distance matrix — ~1M+ comparisons. At this scale, client-side DBSCAN
with full vector fetch becomes impractical.

### Context
Content organised into domains (20–100 entries each). Goal: find cross-domain
topic overlaps and misclassified entries without computing the full global
distance matrix.

### Root cause
The naive approach fetches all vectors and runs DBSCAN globally. The O(n²) distance
matrix computation and the Qdrant scroll pagination (100 entries per page) make
this prohibitively slow for 1000+ entries.

### Fix
Two-stage approach:

**Stage 1 — Centroid clustering (cheap):**
Compute each domain's centroid vector (element-wise mean). Build a D×D pairwise
similarity matrix between domain centroids (typically <20×20). Identify domain
pairs with centroid similarity above a threshold (e.g. >0.7).

**Stage 2 — Targeted entry-level comparison:**
For high-similarity domain pairs only, fetch both domains' entry vectors and run
cross-domain entry-level comparison. Cap the number of pairs (e.g. top 20 by
centroid similarity) to bound computation.

```java
// Stage 1: domain centroids (cheap — one centroid per domain)
Map<String, float[]> centroids = new HashMap<>();
for (String domain : domains) {
    List<VectorEntry> entries = client.fetchEntriesWithVectors(domain);
    centroids.put(domain, computeCentroid(entries));
}

// D×D centroid similarity matrix
List<double[]> pairs = new ArrayList<>();
for (int i = 0; i < domainList.size(); i++) {
    for (int j = i + 1; j < domainList.size(); j++) {
        double sim = cosineSimilarity(centroids.get(domainList.get(i)),
                                       centroids.get(domainList.get(j)));
        if (sim > THRESHOLD) pairs.add(new double[]{i, j, sim});
    }
}
pairs.sort((a, b) -> Double.compare(b[2], a[2]));
if (pairs.size() > MAX_PAIRS) pairs = pairs.subList(0, MAX_PAIRS);

// Stage 2: entry-level only across high-similarity pairs
for (double[] pair : pairs) {
    findCrossEntries(domainA, entriesA, centroidA, domainB, entriesB, centroidB);
}
```

Per-domain DBSCAN (intra-domain topic discovery) runs independently — domains are
small enough for client-side O(n²). The garden-wide view aggregates per-domain
cluster results and adds the cross-domain overlap data from Stage 2.

### Why this is non-obvious
The instinct is to run one global clustering pass. The two-stage approach exploits
the domain structure as a natural partition — centroids compress each domain to
a single vector, making the global comparison tractable. Most developers would
either attempt the full N×N matrix or give up and use server-side approximate
nearest-neighbor search.
