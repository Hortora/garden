### Symptom

After creating a slot with repos from different org families, one repo has no `wksp` symlink. `ctx.py` reports `WORKSPACE_OK=no` and `SINGLE_REPO=yes`. The project skill triggers full workspace-init on every session — offering to create a workspace that already exists elsewhere.

### Context

Slot 5 contains trellis (hortora family, workspace at `~/claude/public/hortora/trellis/`) and pages (casehub family, workspace at `~/claude/public/casehub/pages/`). The slot manager clones the hortora workspace into `work/` for trellis, but never clones the casehub workspace for pages.

### Root cause

`resolve_workspace_source()` in `slot_manager.py` follows the `wksp` symlink in the source repo to find the workspace git repo root. For trellis, this resolves to `~/claude/public/hortora/` which gets cloned as `work/`. For pages, it should resolve to `~/claude/public/casehub/` — a different workspace git repo — and get cloned as `work-casehub/` (the collision-avoidance naming already exists in the code). Either the resolution fails for cross-org repos, or the workspace clone step doesn't trigger when the workspace repo differs from one already cloned.

### Fix

Manual fix:

1. Clone the second family's workspace: `git clone --shared --branch main ~/claude/public/casehub ~/slot/work-casehub`
2. Un-ignore the repo subdir: add `!/pages` to `work-casehub/.git/info/exclude`
3. Create the directory: `mkdir work-casehub/pages`
4. Create symlinks: `ln -s ../work-casehub/pages pages/wksp` and `ln -s ../pages work-casehub/pages/proj`
5. Exclude from git: add `wksp` and `proj` to `pages/.git/info/exclude`

Permanent fix: soredium#200 — `resolve_workspace_source()` should handle multiple workspace repos per slot.

### Why this is non-obvious

No error is raised. The slot creates successfully. The only symptom is the project skill repeatedly offering workspace-init — which looks like a setup issue, not a slot wiring bug. The cross-org case is uncommon (most slots contain repos from one family).
