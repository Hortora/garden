### Symptom
`slot_manager.py merge-slot <SLOT_PATH>` returns `ERROR=not_ready` after work-end has completed squash inside a slot. Six downstream failures cascade silently:

1. No `.landed` marker written (merge-slot never ran)
2. Archive blocked (`archive-slot` requires `.landed`)
3. Original repos never synced (two-hop push never executed)
4. Original workspace stale (workspace merge never ran)
5. Branch stamps missing (merge-slot stamps all repos)
6. `close_artifacts.py` push may fail (slot clone branch has no upstream)

### Context
When work-end runs inside a slot (`IN_SLOT=yes`), the SKILL.md says to call `merge-slot` in Phase C (Land). `merge-slot` was designed for standalone use (`work-slot merge` from the main repo after a slot session) and requires a `.phase-a-complete` marker file at the slot root as a readiness gate.

work-end's close sequence completes squash (Phase B) but never writes this marker. The marker was only created by the standalone two-phase workflow, not by work-end's integrated close path.

### Root cause
`merge_slot()` at line 977 of `slot_manager.py` checks:
```python
if not (slot_dir / ".phase-a-complete").exists():
    print(f"ERROR=not_ready slot={slot_num}")
    return 1
```

This is the ONLY readiness check. No other condition gates merge-slot. The marker file contains `branch=<name>` and `timestamp=<ISO-8601>`, consumed by `merge_slot()` (reads `branch=`) and `scan_ready()` (reads `timestamp=`).

### What was tried (didn't work)
- Running `merge-slot` directly after work-end's squash — returns `not_ready`
- Running `archive-slot` — blocked by missing `.landed` marker
- Running `archive-slot --force` — bypasses safety but original repos still stale

### Fix
Add `cmd_write_marker()` to `work_end_execute.py`:

```bash
python3 work-end/work_end_execute.py write-marker slot_path=<SLOT_PATH> branch=<BRANCH>
```

Called after Phase B (squash) completes, before Phase C (Land). Writes `.phase-a-complete` to the slot root with `branch=` and `timestamp=` fields. After this, `merge-slot` succeeds and handles the full landing pipeline.

### Why this is non-obvious
The error message `ERROR=not_ready` suggests the branch isn't ready — unfinished work, dirty tree, incomplete squash. The actual cause is a missing marker file that's an implementation detail of merge-slot's two-phase design. Nothing in the error output points to `.phase-a-complete` as the missing prerequisite. The cascade (6 failures from one missing file) compounds the debugging difficulty.

### Alternatives considered
- Adding slot-aware landing directly to `cmd_land()` in `work_end_execute.py` — rejected because it duplicates merge-slot's 287 lines of tested landing logic (rebase retry, SHA verification, .landed audit).
- Making merge-slot accept a `--skip-readiness-check` flag — reduces safety; the marker serves as a durable record that Phase A completed.
