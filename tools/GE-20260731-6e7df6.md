### Symptom
`ide_create_file` with path `planning/src/test/java/.../MyTest.java` in a workspace where the module root is already `planning/` creates the file at `planning/planning/src/test/java/.../MyTest.java`. IntelliJ compiles it (the doubled path is a valid source root in IntelliJ's view), but Maven never finds the class — `mvn test -Dtest=MyTest` fails with "no tests matching pattern" and zero compilation errors.

### Context
When `ide_open_workspace` opens a Maven project, the workspace root resolves to the project directory (e.g. `/path/to/engine`). In a multi-module project, each module (e.g. `planning/`) is a content root. `ide_create_file` interprets paths relative to the workspace root — so `planning/src/test/...` is correct. But if you mentally think "I'm working in the planning module" and pass a path relative to the module root, the module prefix gets doubled.

### Root cause
`ide_create_file` always resolves paths from the workspace root, not from any individual module's content root. There is no parameter to select a different resolution base. The doubled directory exists on disk and IntelliJ indexes it, so `ide_build_project` shows no errors — the problem only surfaces at Maven test execution time.

### Fix
Pass paths relative to the project root (workspace root), not module-relative paths. After creation, verify the file landed in the right place:

```bash
find /path/to/project -name "MyTest.java" -path "*/test/*"
```

If the path is doubled, move the file to the correct location and remove the spurious directory.

### Why this is non-obvious
IntelliJ reports zero compilation errors. The build succeeds. The only signal is Maven's "no tests matching pattern" message, which is also the error you get when surefire can't find the test class for any reason (wrong naming convention, wrong plugin config, etc.). Nothing points to the file being in the wrong directory.
