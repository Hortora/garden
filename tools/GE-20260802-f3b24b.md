### Symptom
Artifacts (specs, blogs, plans) silently skip during slot promotion. `PROMOTED=0` with no error. 79 patches over several weeks each fixed one variant, but promotion kept failing on the next slot.

### Context
A slot system creates isolated git clones for parallel development. Artifacts are scanned from the slot workspace but promoted to the original workspace. Three independent mechanisms produce the same silent-skip output.

### Root cause
Three separate bugs, all producing `PROMOTED=0` with skipped artifacts:

1. **`to_workspace_main`**: uses `git checkout branch -- path` on the original workspace, but the branch only exists in the slot clone. `git pull --rebase origin main` fetches main, not the feature branch. Every checkout silently fails.

2. **`to_project`**: reads artifacts from `workspace/path` where workspace is the original (on main). The file only exists on the slot workspace. `src.exists()` returns False, artifact skipped.

3. **`archive_plans`**: same branch-ref problem as #1. Plans not archived.

### Fix
`source-dir` parameter for `to_workspace_main` and `archive_plans` — filesystem copy from the scan source instead of `git checkout`. For `to_project`, pass `scan_source` instead of `workspace` as the read directory. Each fix is one parameter change; the root cause was architectural (scan/read separation not flowing through to promotion functions).

### Why this is non-obvious
Each bug produces identical output (`PROMOTED=0`, `SKIPPED_PATHS=...`). Fixing one reveals the next. Without tracing the full data flow across `close_artifacts.py` → `artifact_promote.py` with concrete paths for each mode (normal, single-repo, slot), the three bugs look like one recurring issue.

### Why this fix
The `source-dir` approach avoids the branch-ref problem entirely — no need to fetch the branch, no need for the repos to share refs. The filesystem already has the files; git is only needed for the write side.
