### What
When a Claude Code SKILL.md contains both abstract machinery (an orchestrator loop) and concrete handlers (detailed step-by-step instructions for specific actions), the LLM reads the full file upfront and latches onto the most concrete, actionable instruction. It skips the abstract control flow that sequences the concrete handlers.

### How it manifests
Observed repeatedly across multiple sessions and projects:

1. **Handover skill (700 lines):** LLM read the full SKILL.md, saw "write HANDOFF.md using this template" (concrete handler), and went straight to writing it — skipping the wrap orchestrator loop that runs forage, protocol, and write-content before the handover.

2. **Work-end skill (590 lines):** LLM read "invoke code-review on DIFF_RANGE" and ran code review, then jumped to marking the entire review step done — skipping branch-audit (4 dimensions), loose-ends sweep, and forcing function.

3. **Sweep config:** LLM read the sweep item descriptions, decided "these already ran" based on session context, and skipped the checklist presentation entirely — deselecting all items without asking the user.

### Why this happens
LLMs optimize for action. When presented with 700 lines of mixed abstract and concrete instructions, the concrete instruction ("write this file using this template") has higher activation than the abstract instruction ("call this script in a loop and follow its output"). The abstract loop is a control structure — it doesn't produce an immediate result. The concrete handler does.

This is not a bug in the LLM — it's a predictable consequence of how attention works over long instruction documents. The more concrete and actionable an instruction, the more likely the LLM will prioritize it.

### Mitigation
Extract concrete handlers to separate files loaded lazily. The SKILL.md has one instruction: "call the orchestrator and follow its output." Handler details live in `handlers/X.md` and are only read when the orchestrator yields that action.

Complementary: a PreToolUse hook blocks commits that would bypass the orchestrator, catching cases where the LLM still manages to shortcut.

### Why this is non-obvious
The intuitive skill design approach is "more detail = better execution." The opposite is true for control flow: more detail in the SKILL.md gives the LLM more targets to latch onto, increasing the probability of shortcutting. The SKILL.md should be minimal — the orchestrator provides the detail at the right time.
