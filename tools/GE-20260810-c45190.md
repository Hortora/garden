## Technique

Run design review dimensions (structure, coherence, robustness) sequentially instead of in parallel, passing each completed dimension's tracker as architectural context to the next. This produces richer findings because later dimensions build on earlier ones rather than operating independently.

## Evidence

First live ordered run on a real spec (soredium #198 — decision review + ordered dimensions design):

| Dimension | Issues found | Prior context |
|-----------|-------------|---------------|
| Structure | 12 | None (first) |
| Coherence | 22 | Structure's 12 issues |
| Robustness | 16 | Structure + Coherence (34 issues) |
| Cross-cutting | 7 | All three trackers |
| **Total** | **57** | |

Coherence found nearly 2x the issues of structure, directly informed by structure's boundary findings. The cascading context allowed coherence to ask "are requirements complete on both sides of this unclear boundary?" — a question it wouldn't have formulated independently.

## How it works

1. Structure runs first — establishes boundaries, decomposition, responsibilities
2. Structure's tracker.md is passed as `--arch-files` to coherence
3. `_generate_context_md()` in setup.py parses the tracker, extracts issue summaries with dimension prefixes (STR-R1-01, COH-R1-01), and injects them into context.md
4. The coherence reviewer sees "Structure review found: STR-R1-01: Unclear boundary..." and can probe completeness at those specific boundaries
5. Robustness receives both trackers and can construct failure scenarios at the intersection of structural and coherence gaps

## Trade-off

Wall-clock time is 2-3x parallel (sequential vs simultaneous). Use ordered mode when dimensional interactions are the primary risk (new module boundaries, unclear decomposition). Use parallel for clear boundaries or time-sensitive reviews.

### Why this is non-obvious

The intuition is that parallel dimensions + a cross-cutting pass should catch everything — the cross-cutting reviewer reads all trackers and finds contradictions. But cross-cutting only finds problems *between* completed findings. Ordered mode enables each dimension to *build on* prior findings, producing findings that neither dimension would have raised independently. The 22-vs-12 gap between coherence (with structure context) and structure (alone) demonstrates this.
