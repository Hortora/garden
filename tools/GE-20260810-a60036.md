### Symptom
Untracked symlinks appear in `git status` despite matching `.gitignore` patterns. For example, `.build/` in `.gitignore` does not ignore a `.build` symlink pointing to a directory.

### Context
Git clone operations with `--shared` or slot/worktree systems that create symlinks to asset directories in a source repo. The `.gitignore` patterns use trailing slashes (e.g. `.build/`, `.claude/`, `packages/`) which is the conventional way to ignore directories.

### Root cause
Git's trailing-slash pattern (e.g. `.build/`) explicitly matches only directories, not symlinks. A symlink is a different filesystem entity type even if it points to a directory. Git treats the symlink as a file, not as the directory it points to, so the pattern doesn't match.

### Fix
Remove the trailing slash from `.gitignore` patterns that need to match both directories and symlinks:

```gitignore
# Before — only matches directories
.build/
.claude/
packages/

# After — matches both directories and symlinks
.build
.claude
packages
```

The slash-free pattern matches any entry with that name regardless of type.

### Why this is non-obvious
The trailing-slash convention is widely recommended for directories in `.gitignore` and works correctly in normal repositories. The failure only surfaces when symlinks to directories are created — which is uncommon in typical git workflows but routine in worktree-based or slot-based development setups.
