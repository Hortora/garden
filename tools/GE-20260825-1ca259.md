## Evidence-based reconciliation checks mechanical steps only — judgment steps are not independently verifiable

### Context
A stateless re-entrant orchestrator tracks progress in a `.close-progress` file. On crash recovery, it needs to verify that steps marked "done" were actually completed — not just marked.

### The convention
Only check evidence for **mechanical steps** (subprocess calls that produce artifacts): file existence, git state, remote state. Never check evidence for **judgment steps** (LLM-executed work like review, forage, write-content).

### Why this convention exists
Judgment steps are LLM-executed. The orchestrator yields an ACTION, the LLM does the work, and marks the step done. There is no independently verifiable artifact that distinguishes "LLM did the review and found nothing" from "LLM was never asked to review." A review with zero findings produces no `findings.jsonl`. A forage sweep that finds nothing garden-worthy produces no entry files.

Reconciliation that checks judgment step evidence causes false resets during normal operation — the orchestrator resets `review=done` because no `findings.jsonl` exists, even though the review genuinely found nothing.

### Alternatives considered
- Check all steps including judgment: causes false resets during normal operation (observed in testing — 14 test failures from reconciliation resetting valid judgment progress)
- Only reconcile steps in phases behind the current lifecycle state: reduces false positives but still checks judgment steps unnecessarily
- Phase-gated + mechanical-only (adopted): combines both filters for maximum correctness
