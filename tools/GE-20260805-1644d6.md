### Symptom
`mvn compile -o` (offline mode) fails with `Cannot access central in offline mode and the artifact org.apache.maven.plugins:maven-surefire-plugin has not been downloaded before` — even though compilation would succeed online.

### Context
Slot clones have their own `.m2` via `-Dmaven.repo.local`. This `.m2` contains project dependencies (copied at slot creation) but may not contain all Maven plugins (surefire, compiler, install). Online mode re-downloads stale SNAPSHOT dependencies from GitHub Packages, overwriting locally-installed versions. Offline mode prevents that but also blocks plugin resolution.

### Fix
Use `-nsu` (no snapshot updates) instead of `-o`:

```bash
mvn clean compile -nsu
```

`-nsu` prevents SNAPSHOT metadata checks against remote repositories (blocking stale re-downloads) but still allows Maven to resolve plugins from Maven Central. It's the correct middle ground for slot builds where SNAPSHOTs are locally managed.

### Why this is non-obvious
The intuitive response to "Maven keeps downloading the wrong SNAPSHOT" is `-o` (go offline). But `-o` blocks ALL remote resolution including plugins, which fails in a fresh slot `.m2`. `-nsu` is a less common flag that specifically targets the SNAPSHOT update behaviour without affecting plugin resolution.
