## Comparative cognitive data needs perception-level translation — raw metrics are not self-contained data

### Context

When injecting cognitive state into LLM prompts, GE-20260914-e3cb03 established that structured profile data ("Pleasure: 0.94") outperforms behavioral directives ("let these feelings color your response"). The natural extension is to present all cognitive data as raw values — including comparative/relational data like PAD divergence scores, dimension deltas, and cosine similarities between agent perspectives.

### Technique

Raw values are self-contained only when the label is human-interpretable. Absolute values pass this test — "Pleasure: 0.94" needs no domain knowledge. Comparative values do not — "PAD divergence: 0.7" or "pleasure delta: -0.4" requires understanding the measurement framework, scale, and what constitutes significant.

Three abstraction levels exist for relational cognitive data:

| Level | Example | Problem |
|-------|---------|---------|
| Generic prose | "You sense tension with Peter" | Too vague — LLM has no signal about what kind of tension or which direction |
| Raw comparative metric | "PAD divergence: 0.7, pleasure delta: -0.4" | Leaks the mechanism — LLM must know PAD theory to interpret |
| Perception-level translation | "Peter seems to enjoy your interactions more than you do" | Self-contained, specific, actionable without domain knowledge |

The perception level is correct. Translate dimensional differences into character-perspective observations:

| Signal | Perception |
|--------|-----------|
| My pleasure low, theirs high | "Peter seems to enjoy your interactions more than you do" |
| My arousal high, theirs low | "You're on edge around Penelope, but she seems calm" |
| Trajectory DIVERGENT | "Your perceptions of Peter are moving apart" |
| Trajectory ALIGNED | "You and Peter are beginning to see eye to eye" |

The discriminator for whether translation is needed: **did the value come from a formula or comparison?** If yes, translate to a perception the character would notice. If it's a raw state with a human-readable label, present as-is.

### Why this is non-obvious

GE-20260914-e3cb03's principle — "data, not directives" — naturally leads developers to present ALL data as raw values. The distinction between self-contained and framework-dependent data is invisible when you're thinking in data-vs-directives terms. A developer who correctly applies "Pleasure: 0.94" (absolute, self-contained) will by extension write "divergence: 0.7" (comparative, not self-contained) — the same principle, applied consistently, produces the wrong output for the comparative case.

### Why this fix

The perception-level translation is correct because it preserves the data-over-directives principle while fixing the interpretability gap. "Peter seems to enjoy your interactions more than you do" is data (a perceived state), not a directive (what to do about it). The character briefing determines behavior — a schemer exploits the asymmetry, a peacemaker addresses it. The translation step maps framework-internal metrics to the same human-interpretable format that works for absolute values.

### Alternatives considered

- **Better-labeled raw metrics** — e.g. "perception mismatch with Peter: HIGH (0.7 on 0-1 scale)" — adds context but still requires the reader to interpret what "perception mismatch" means in behavioral terms
- **Templated prose directives** — "Because you and Peter see things differently, be cautious" — violates the data-over-directives principle from GE-20260914-e3cb03
- **No translation (dump raw PAD)** — consistent application of the original principle, but "divergence: 0.7" is not equivalent to "Pleasure: 0.94" in interpretability
