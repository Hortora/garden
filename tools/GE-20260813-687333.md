## Symptom

Archiving a slot silently fails to move Claude Code conversation directories. No error, no warning. The conversations stay at the old path — orphaned.

## Context

Claude Code stores per-project data in `~/.claude/projects/<encoded-path>/` where the path is the CWD encoded by replacing `/` with `-`. When a slot is archived, `relocate_claude_projects()` encodes the slot path to find matching project directories.

The function is called from `slot_manager.py` which receives `family_root` as a CLI argument. When invoked as `python3 slot_manager.py remove-slot . slot=101`, the family root is `.` (relative).

## What we tried (didn't work)

- Checked the matching logic — it was correct for absolute paths
- Checked the function was being called — it was
- Checked the project directory names — they existed

## Root cause

`str(Path(".") / "slots" / "101")` produces `"slots/101"`. Replacing `/` with `-` gives `"slots-101"`.

But Claude Code encoded the project directory name from the absolute CWD: `-Users-mdproctor-claude-casehub-slots-101-chat-app`.

`"slots-101"` never matches `-Users-mdproctor-claude-casehub-slots-101-chat-app"`. Zero matches. Zero moves. Zero errors.

## Fix

Call `.resolve()` before encoding:

```python
slot_path_encoded = str(slot_dir.resolve()).replace("/", "-")
```

This normalizes relative paths to absolute before encoding, ensuring the encoding matches regardless of how the path was passed.

## Why this is non-obvious

The encoding function itself is correct — it faithfully replaces `/` with `-`. The bug is invisible at the call site: `relocate_claude_projects(slot_dir, dest)` looks right. You have to trace through to realize that `slot_dir` can be relative (from CLI arg parsing) while the target project directory names are always absolute-encoded.

The function returned 0 (zero matches moved) but the caller didn't check the return value — it only printed `CLAUDE_PROJECTS_MOVED=N` if N > 0. Silent success.

### Alternatives considered

- Normalizing at the CLI arg parsing level — rejected because the fix belongs at the encoding boundary, not at every caller
- Adding a warning when zero matches are found — complementary but doesn't fix the root cause
