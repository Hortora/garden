### Context

Yield-based orchestrators exit after yielding an action, and the caller invokes them again after handling it. The orchestrator maintains state in a progress file. The caller (an LLM) can pass `skip_step` or `step_done` to advance past steps. Without enforcement, the caller can skip or complete steps it was never asked to handle.

### Technique

Write `last_yielded=<step_name>` to the progress file every time the orchestrator yields a judgment or user_input action. On the next call, validate that `skip_step` and `step_done` match `last_yielded`.

The critical design choice: **do not clear `last_yielded` after a skip or done**. Let the next yield overwrite it. This prevents cascading: after skipping step A, `last_yielded` still equals A. If the caller tries to skip step C before B is yielded, the mismatch is caught. Only when the orchestrator yields B does `last_yielded` update to B.

```python
# On yield:
update_progress(workspace, "last_yielded", step_name)
return {"ACTION": step_name, ...}

# On skip validation:
last = progress.get("last_yielded", "")
if last and step != last:
    return {"ERROR": "invalid_skip", "LAST_YIELDED": last}
# Don't clear last_yielded — next yield overwrites it
```

### Why this is non-obvious

The natural instinct is to clear `last_yielded` after the step is handled (skip or done) — "clean up after yourself." But clearing creates a window where `last_yielded` is empty, and the lenient path (empty = no validation) lets the next skip through. The technique inverts the cleanup assumption: staleness is safe (the next yield fixes it), premature clearing is dangerous.

### Alternatives considered

- **Track all yielded steps in a set** — validates against history, but grows unboundedly and doesn't capture ordering.
- **Sequence numbers** — assign monotonic IDs to yields, validate skip targets are the most recent. More complex with no benefit over a single `last_yielded` string.
- **Clear last_yielded and use a "never set" sentinel** — distinguishes "never yielded" from "just completed." Adds a state that needs its own validation logic.
