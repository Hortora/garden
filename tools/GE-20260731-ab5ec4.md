### Symptom

Maven build fails in a git worktree with `401 Unauthorized` from GitHub Packages for all CaseHub SNAPSHOT dependencies. The same build succeeds from the main repo checkout on the same machine with the same environment.

```
[ERROR] Failed to read artifact descriptor for io.casehub:casehub-eidos:jar:0.2-SNAPSHOT
[ERROR]   Caused by: Could not transfer artifact ... status code: 401, reason phrase: Unauthorized
```

### Context

A git worktree created by slot-based isolation tooling. The tooling creates `.mvn/maven.config` in the worktree root containing:

```
-Dmaven.repo.local=/path/to/worktrees/59/.m2
```

This points to a per-worktree Maven local repository that is empty — it has no locally-installed CaseHub SNAPSHOT artifacts. The main repo's builds use `~/.m2/repository` which has the SNAPSHOTs installed via `mvn install` from the monorepo.

### What was tried (didn't work)

1. Removing `_remote.repositories` and `*.lastUpdated` files from `~/.m2/repository` for CaseHub artifacts — no effect because the worktree uses a different local repo
2. Running with `-nsu` (no snapshot updates) — still fails because the artifacts don't exist in the worktree's local repo at all
3. Running with `-o` (offline) — fails because standard dependencies (assertj, byte-buddy) also haven't been downloaded

### Root cause

The `.mvn/maven.config` file sets `maven.repo.local` to an isolated per-worktree directory. This directory has never had `mvn install` run against it, so SNAPSHOT artifacts from sibling repos don't exist. Maven resolves the `<repository>` from `pom.xml` (GitHub Packages), attempts to download the SNAPSHOTs, and gets 401 because the `GITHUB_TOKEN` (a `gh auth` OAuth token) lacks `read:packages` scope. The 401 is a red herring — the real problem is the empty local repo.

### Fix

Remove or rename `.mvn/maven.config` in the worktree so Maven uses the shared `~/.m2/repository`:

```bash
rm /path/to/worktrees/59/examples/.mvn/maven.config
```

The file is typically `.gitignore`d, so removal is a local-only change.

### Why this is non-obvious

The 401 error from GitHub Packages dominates the error output and sends investigation toward token scopes, Maven settings.xml server config, and `_remote.repositories` resolver markers. The actual cause — a `.mvn/maven.config` file in the worktree root redirecting the local repo — is invisible unless you know to check for it. The main repo builds fine because it has no `.mvn/maven.config`.
