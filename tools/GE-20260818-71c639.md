## IntelliJ MCP ide_replace_text_in_file plain-text mode reports success on multi-line search but does not modify the file

**ID:** GE-20260818-71c639
**Stack:** IntelliJ MCP (intellij-index plugin)
**Symptom:** `ide_replace_text_in_file` returns `{"success": true, "replacements": 1, "affectedLines": [64]}` but `grep` on disk shows the original text unchanged. No error. No warning.
**Context:** When the `searchText` parameter contains embedded newlines (e.g., matching `<<<<<<< HEAD\n=======\n` as a multi-line block) with `regex: false` (default).

### What was tried (didn't work)
- Called `ide_replace_text_in_file` with plain-text multi-line searchText — tool reported 1 replacement at line 64, but file unchanged on disk
- Called `ide_sync_files` after the replacement — sync reported success, file still unchanged
- Called the same replacement a second time — again reported success, still no change

### Root cause
The plain-text matching mode does not correctly handle embedded newlines in the `searchText` parameter. The tool appears to match something in the IntelliJ Document model (reporting success) but the modification either targets an in-memory representation that doesn't map to the actual file content, or the match is spurious.

### Fix
Use `regex: true` with `\n` for newline matching:

```json
{
  "file": "path/to/file.java",
  "searchText": "<<<<<<< HEAD\\n=======\\n",
  "replaceText": "",
  "regex": true
}
```

Do NOT use plain-text mode when the search text spans multiple lines.

### Alternatives considered
- `ide_sync_files` after plain-text replacement — does not help; the replacement was never applied to the document
- Multiple retries of the same plain-text call — each reports success but none modify the file

### Why this is non-obvious
The tool returns a fully successful response — correct replacement count, correct affected line number. There is zero indication that the file was not modified. Even `ide_sync_files` reports success afterward. The only way to detect the failure is to independently verify the file content (e.g., `grep`).
