### Symptom
New type system builds cleanly and passes unit tests in isolation, but has structural bugs that only surface when wired into production code paths — by which point cross-references make the root cause hard to isolate.

### Context
When migrating from one type system to another (e.g. mutable Stage to immutable PlanItemDefinition.Compound), the new types are built alongside the old. They compile, they have tests, they look correct. The temptation is to wire them in immediately.

### What was tried (did not work)
Wiring the new compound types directly into PlanningStrategyLoopControl without a coherence audit. Would have hit the index conflation bug at runtime in integration tests — much harder to diagnose.

### Root cause / solution
Dispatch a design review subagent (Plan type, opus model) with a structured review brief covering:
1. **Naming consistency** — do names align across the type system?
2. **Structural coherence** — are indexes conflated? Are fields on the right type?
3. **Missing semantics** — does the new type cover everything the old type does?
4. **Undefined values** — are there enum values or fields with no consumers?

The subagent reads all related files and reports issues ranked by severity.

### Findings from one session
1. CRITICAL: childrenIndex mixed structural child IDs with binding name strings — evaluateCompletion() would throw IllegalArgumentException on compounds with scopedBindings
2. HIGH: DispatchMode.HYBRID — undefined enum value with no consumers, tests, or documentation
3. MEDIUM: dispatchMode() on PlanItemDefinition interface — meaningless on Primitive, adding noise to every construction site

All found before any production wiring, saving significant debugging time.

### Why this is non-obvious
The natural impulse is to wire new types immediately after building them — they compile and pass tests, so they must be correct. A review feels like overhead. But the wiring creates cross-references that make structural bugs harder to isolate. Catching them while the types are standalone is dramatically cheaper.
