## Separate skill sections create LLM bypass paths — merge mandatory gates into one section

**ID:** GE-20260801-e482fc
**Stack:** Claude Code skills, LLM instruction following

**Symptom:** A mandatory step in a skill is consistently skipped despite being marked "MANDATORY — do not skip." The LLM jumps from a preceding section directly to a later section, bypassing the mandatory gate.

**Root cause:** The skill had three consecutive sections:
1. `### User Review Gate` — "Please review... before we move to the implementation plan"
2. `### Review Depth Prompt (MANDATORY)` — the gate that should always run
3. `### Implementation` — "Invoke writing-plans"

The LLM read "implementation plan" in section 1's wording and jumped to section 3 ("Invoke writing-plans") after the user approved, skipping section 2 entirely. The standalone `### Implementation` section provided a direct bypass path — the LLM didn't need to pass through section 2 to reach it.

**Fix:** Merge the mandatory gate and the next step into a single section with no independent target to jump to:

```markdown
### Review Depth Prompt → writing-plans (MANDATORY gate)

**You MUST complete this step before invoking writing-plans. There is no
path from spec approval to writing-plans that bypasses this prompt.**

[... prompt flow ...]

**After review completes (or Skip):** invoke writing-plans.
```

No separate `### Implementation` section exists — writing-plans is only reachable as the final line of the gate section.

**Why non-obvious:** Bold text, capital letters, and "do not skip" instructions feel sufficient. But LLMs don't follow sections linearly — they pattern-match against section headings to find the next relevant action. A standalone section named "Implementation" with "Invoke writing-plans" is a stronger attractor than inline text saying "MANDATORY." The structural fix (one section, no bypass target) is more reliable than emphasis-based fixes.
