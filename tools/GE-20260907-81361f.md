## ide_edit_member with member=ClassName replaces entire class

### Symptom

Calling `ide_edit_member` with `member` set to the class name (e.g. `member: "CaseCompensationServiceImpl"`) replaces the **entire class declaration** — all fields, methods, inner classes — with only the content provided. A 400-line class is reduced to just the constructor code passed in the `content` parameter.

### Context

When editing a constructor that shares its name with the class (as Java constructors always do), passing `member=ClassName` to `ide_edit_member` matches the class declaration itself, not the constructor. The tool description says "Replace an entire member **or class declaration**" — the "or class declaration" clause activates when the member name matches the class name.

### Root cause

`ide_edit_member` resolves the target by name. When `member=ClassName` and `class=ClassName`, it matches the class declaration (the outermost named entity), not the constructor inside it. The tool treats the class as a "member" and replaces it entirely.

### Fix

Use `ide_replace_text_in_file` for constructor modifications instead of `ide_edit_member`. Target the specific text of the constructor signature and body:

```
ide_replace_text_in_file(
  searchText: "  @Inject\n  public ClassName(\n      ParamType1 p1) {\n    this.p1 = p1;\n  }",
  replaceText: "  @Inject\n  public ClassName(\n      ParamType1 p1,\n      ParamType2 p2) {\n    this.p1 = p1;\n    this.p2 = p2;\n  }"
)
```

Alternatively, use `ide_edit_member` with `parameterCount` to disambiguate the constructor from the class:
```
ide_edit_member(member: "ClassName", parameterCount: 6, content: "...")
```

If the damage has already occurred, recover immediately with `git restore <file>`.

### Why this is non-obvious

The tool name says "edit member" — constructors are members. A developer naturally passes the constructor name (which equals the class name in Java). The destructive class-level replacement is silent — no warning, no confirmation. The tool returns success even though it deleted hundreds of lines of code.

### Alternatives considered

- Using `ide_insert_member` to add a new constructor and `ide_refactor_safe_delete` for the old one — overly complex for a parameter addition
- Using `ide_replace_member` (body-only replacement) — correct for body changes but doesn't help with signature changes
