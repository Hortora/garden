### Context

Blizzard's SC2 API provides ~230K anonymized ladder replays per game version, but they're stripped of `replay.tracker.events` (unit births, deaths, player stats, upgrades). The sc2api.proto comment says `record_replay` is "useful for restoring tracker.events" — but making it work requires a specific setup.

### The technique

Play stripped replays through SC2 headless with `record_replay=True`, then save the re-recorded replay. The saved replay includes regenerated tracker events.

**Setup:**
1. Download SC2 Linux headless build matching the replay version from `blzdistsc2-a.akamaihd.net/Linux/SC2.<version>.zip` (password: `iagreetotheeula`)
2. Download ladder maps from `blzdistsc2-a.akamaihd.net/MapPacks/Ladder2019Season2.zip` (and Season3)
3. Extract SC2 + maps, `chmod +x` the SC2_x64 binary
4. Build a Docker amd64 image with PySC2, protobuf==3.20.3, mpyq
5. Mount SC2 install + replays into the container

**Restoration script (core loop):**

```python
import os, sys
os.environ["PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION"] = "python"
from absl import flags
flags.FLAGS(sys.argv[:1])

from pysc2 import run_configs
from s2clientprotocol import sc2api_pb2 as sc_pb

# PySC2 handles -dataVersion, version matching, temp dirs
version = "4.9.3"  # from replay.gamemetadata.json
rc = run_configs.get(version=version)

with rc.start(want_rgb=False) as controller:
    interface = sc_pb.InterfaceOptions(raw=True, score=True)
    req = sc_pb.RequestStartReplay(
        replay_data=replay_bytes,
        options=interface,
        observed_player_id=1,
        record_replay=True,  # KEY: enables tracker event recording
    )
    controller.start_replay(req)

    # Step through to game end
    while True:
        obs = controller.observe()
        if obs.player_result:
            break
        controller.step(2000)

    # Save — restored replay has tracker events
    saved_data = controller.save_replay()
```

**Result:** Original replay has 6 MPQ files (no tracker events). Saved replay has 14 MPQ files including `replay.tracker.events` (38-51KB of unit birth/death/stats data).

### Critical requirements

| Requirement | Detail |
|------------|--------|
| Exact build match | Replay build 75025 needs SC2 Base75025 — off by one build fails with "version not available" |
| PySC2 run_configs | Manual WebSocket connection fails with MissingReplay — PySC2 handles the stripped .backup format (see GE-20260927-c61fa5) |
| protobuf 3.20.3 | Newer protobuf versions throw descriptor compatibility errors with s2clientprotocol |
| Docker amd64 | SC2 Linux builds are x86_64 only; on ARM64 Macs, use `--platform linux/amd64` (QEMU emulation, ~10x slower) |
| `PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python` | Required for protobuf compatibility in Docker Python 3.10 |
| `absl flags.FLAGS(sys.argv[:1])` | PySC2 uses absl flags — must be parsed before importing run_configs |

### Performance

| Platform | Speed per replay | 230K replays (4 workers) |
|----------|-----------------|--------------------------|
| Native x86_64 Linux | ~3-5s | ~2 days |
| ARM64 Mac via QEMU | ~45s | ~40 days (impractical) |

### Why this is non-obvious

1. The sc2api.proto comment about `record_replay` doesn't mention the PySC2 requirement — it implies raw protobuf API calls should work
2. Manual WebSocket connections fail silently (MissingReplay error with no details)
3. AlphaStar trained on these replays but the restoration technique isn't documented in any DeepMind paper
4. The version matching must be exact to the build number (75025, not 75689) despite minor version compatibility expectations
5. The Blizzard API replay format (.backup files) is undocumented — you only discover it by inspecting the MPQ archive with mpyq
