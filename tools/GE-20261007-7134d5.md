### Symptom
Two pipeline phases circularly depend on each other's outputs — Phase A reads value X (written by Phase B) and Phase B reads value Y (written by Phase A). The system converges iteratively but first-cycle values use meaningless defaults, and one input may be silently double-counted in formulas.

### Context
Any ordered pipeline where phases read/write shared state (node properties, shared records, database rows). Common in consolidation schedulers, game loops, and cognitive architectures where affect, priority, and scoring phases interact.

### What was tried (didn't work)
- Reordering phases — fails when the dependency is genuinely bidirectional (A needs B's output and B needs A's output)
- Splitting Phase B into pre-A and post-A sub-phases — adds complexity and still requires the composite to be decomposed

### Root cause
Phase A reads a **composite** value that includes Phase B's output as a component. The circularity isn't intrinsic to the domain — it's caused by reading a derived aggregate where a primitive input is needed. Example: Phase A (emotion appraisal) reads `priority` to scale emotion intensity. Phase B (prioritization) reads PAD affect values to compute `priority`. But `priority = 0.3*urgency + 0.2*feasibility + 0.2*affectiveValence + 0.3*importance` — it includes affect, creating a feedback loop. Urgency appears in both the composite and the formula, causing double-counting.

### Fix
Replace the composite read with its **primitive inputs** that have no feedback component:

```java
// Before — circular: priority contains affect, affect depends on priority
double hopeIntensity = priority * feasibility * (1 - urgency * 0.5);

// After — no cycle: importance and drive-intensity have no affect component
double importance = doubleProperty(goal, "importance", 0.0);
double driveIntensity = doubleProperty(goal, "drive-intensity", 0.0);
double salience = Math.max(importance, Math.max(driveIntensity, 0.3));
double hopeIntensity = salience * feasibility * (1 - urgency * 0.5);
```

If the writing phase currently folds primitives into the composite, store them as separate properties so the reading phase can access them directly.

### Why this is non-obvious
The circular dependency is hidden in the **semantics** of the composite value. "Priority" appears to be a single concept, but it conflates two distinct things: intrinsic importance (stable, affect-free — how much you care) and operational ranking (dynamic, includes affect — what to work on next). The fix requires decomposing the concept, not reordering the phases or adding synchronization.

### Alternatives considered
- **Remove affect from the composite entirely** — breaks the cycle but loses a valid signal (affect should influence operational ranking, just not emotional scaling)
- **Split Phase B into two sub-phases** — works but adds pipeline complexity; decomposing the read is simpler and more targeted
- **Accept the iteration** — converges after 2-3 cycles for bounded values, but first-cycle defaults are meaningless and double-counting persists
