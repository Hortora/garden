## pkill -f with broad JVM patterns kills unintended Quarkus services

### Symptom

Running `pkill -f "quarkus:dev"` to restart one Quarkus sidecar also kills an unrelated Quarkus garden engine running as a launchd service. The garden engine takes several minutes to restart (ONNX model loading, Qdrant connection) and may crash on restart due to port conflicts with zombie processes from the kill.

### Context

Multiple Quarkus applications running on the same machine — a trellis sidecar in `quarkus:dev` mode and a garden engine launched via launchd. Both have `quarkus` in their JVM process arguments.

### Root cause

`pkill -f` matches against the full command line of all processes. Multiple Quarkus apps share similar invocation patterns (`java ... quarkus:dev`, `java ... -jar quarkus-app/...`), so a broad pattern like `"quarkus:dev"` or `"quarkus"` matches more processes than intended.

### Fix

Use more specific process matching:

```bash
# Match by the specific project/artifact, not by "quarkus"
pkill -f "trellis-sidecar"

# Or match by the Maven project path
pkill -f "-f sidecar/pom.xml"

# Or use the PID file / port to identify the target
lsof -i :8090 -t | xargs kill
```

For launchd-managed services, use `launchctl` instead:
```bash
launchctl kickstart -k gui/$(id -u)/io.hortora.engine
```

### Why this is non-obvious

`pkill -f "quarkus:dev"` looks specific enough — it targets the dev mode, not production. But in a multi-service dev environment, the pattern `quarkus:dev` can appear in the arguments of services started via Maven during development or in launchd-managed processes that were originally started via quarkus:dev and converted to jar execution. The kill is silent — no warning that multiple processes matched.
