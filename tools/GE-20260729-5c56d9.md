### Symptom
`yarn install` in GitHub Actions fails with "The lockfile would have been modified by this install, which is explicitly forbidden" — even after removing `--immutable` from the command.

### Context
Yarn 4 workspaces in CI (GitHub Actions). The `CI=true` environment variable is set automatically by GitHub Actions runners.

### What was tried (didn't work)
- Removed `--immutable` flag from `yarn install` command — same error
- The error message gives no indication that an environment variable controls this

### Root cause
Yarn 4 reads the `CI` environment variable and defaults `enableImmutableInstalls` to `true` when `CI=true`. This is independent of the `--immutable` CLI flag. The setting can also be in `.yarnrc.yml` but GitHub Actions triggers it implicitly via the `CI` env var.

### Fix
Set `YARN_ENABLE_IMMUTABLE_INSTALLS=false` in the CI step's environment:

```yaml
- name: Install dependencies
  run: yarn install
  env:
    YARN_ENABLE_IMMUTABLE_INSTALLS: false
```

### Why this is non-obvious
The CLI flag `--immutable` and the env var `YARN_ENABLE_IMMUTABLE_INSTALLS` control the same behaviour but are independent. Removing the flag doesn't disable the env-var-driven default. The error message doesn't mention the env var, and the `CI=true` trigger is not documented prominently.

### Alternatives considered
- Setting `enableImmutableInstalls: false` in `.yarnrc.yml` — works but modifies the upstream repo's config for all environments, not just CI
