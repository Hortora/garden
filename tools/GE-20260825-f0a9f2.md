### Problem

Opening an IntelliJ MCP workspace with 11 Maven modules (resolving to 86 content roots) causes `ide_replace_text_in_file`, `ide_replace_member`, `ide_sync_files`, and `ide_edit_member` to time out persistently. Read-only tools (`ide_find_references`, `ide_search_text`, `ide_find_class`) work reliably even with the large workspace.

### Symptom

Write-oriented MCP tools return timeout errors after ~120 seconds. No error message — just "The operation timed out." The IDE itself remains responsive. Restarting the MCP server does not help while the large workspace is open.

### Root cause

The IntelliJ Index MCP plugin's write operations appear to contend with the indexing load from 86 content roots. Read operations are served from the existing index cache; write operations trigger re-indexing or PSI tree updates that block on the indexer.

### Workaround

1. **For cross-repo reference analysis:** Open the large workspace briefly for read-only queries (`ide_find_references`, `ide_find_class`, `ide_search_text`), collect results, then close it.
2. **For editing:** Open a smaller workspace with only the repos being modified (2-4 modules work reliably).
3. **When write tools time out:** Fall back to `Edit` with `replace_all: true` for find-and-replace operations on disk.

### Why this is non-obvious

No documentation mentions a module count limit. The workspace opens successfully and reports all modules resolved. Read-only tools work fine, so the workspace appears healthy. The timeouts only manifest when attempting write operations, making it look like a per-tool bug rather than a systemic capacity issue.
