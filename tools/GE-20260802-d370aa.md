## Bash dirname resolves to symlink container, not target — use os.path.realpath for PYTHONPATH through symlinks

### Symptom

A Python script launched from a symlinked bash wrapper crashes with `ModuleNotFoundError` — the PYTHONPATH points to the symlink's parent directory, not the real script's parent. The crash is invisible because the subprocess uses `stderr=subprocess.DEVNULL`.

### Context

A hook script at `~/.hortora/tools/rag_shadow.sh` is a symlink to `/project/scripts/shadow/rag_shadow.sh`. The script computes PYTHONPATH for a Python subprocess:

```bash
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
export PYTHONPATH="${SCRIPT_DIR}/.."
```

`dirname "$0"` returns the symlink's directory (`~/.hortora/tools/`), not the target's. `cd && pwd` resolves to the same directory. PYTHONPATH becomes `~/.hortora/` which has no `shadow/` Python package.

### Root cause

Bash's `dirname` operates on the path string, not the filesystem. `$0` contains the path the script was invoked with — if that's a symlink, `dirname` returns the symlink's parent. `cd && pwd` resolves `.` and `..` but does not follow symlinks to the target.

### Fix

Use Python's `os.path.realpath` to resolve symlinks before computing PYTHONPATH:

```bash
SCRIPT_DIR="$(python3 -c "import os,sys; print(os.path.dirname(os.path.realpath(sys.argv[1])))" "$0")"
export PYTHONPATH="${SCRIPT_DIR}/.."
```

On macOS, `readlink -f` is not available natively (requires coreutils). Python's `os.path.realpath` is universally available and handles arbitrary symlink chains.

Also: never use `stderr=subprocess.DEVNULL` for subprocesses that can fail on import. Redirect stderr to a log file instead:

```python
stderr_log = open(LOG_DIR / "subprocess_stderr.log", "a")
subprocess.Popen([sys.executable, script], stderr=stderr_log, ...)
```

### Why this is non-obvious

`cd "$(dirname "$0")" && pwd` looks like it fully resolves the path — `cd` follows symlinks in the directory components and `pwd` returns the absolute path. The trap is that `$0` itself is a symlink, and `dirname` operates on the string before `cd` ever runs. The subprocess crash is invisible because stderr is devnulled — the script appears to do nothing, with no error.
