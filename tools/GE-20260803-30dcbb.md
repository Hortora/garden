### Symptom

`ide_create_file` with `project_path=/path/to/engine/common` and `file=common/src/main/java/...` creates the file at `common/common/src/main/java/...` — doubling the module directory.

### Context

When the IntelliJ MCP workspace includes a Maven multi-module project, `project_path` resolves to the submodule root (e.g., `/engine/common`). The `file` parameter is relative to that root. If the file path redundantly includes the module prefix (`common/src/main/...`), the MCP concatenates project_path + file, producing a doubled path.

### Root cause

`project_path` already resolves to the submodule directory. The `file` argument is concatenated onto it. Including the module name in both creates `<module>/<module>/src/...`.

### Fix

Use paths relative to the module root — `src/main/java/...` not `common/src/main/java/...` — when `project_path` already points to the submodule.

```
# Wrong — doubles the path
ide_create_file(project_path="/engine/common", file="common/src/main/java/Foo.java")
# Creates: /engine/common/common/src/main/java/Foo.java

# Right — relative to module root
ide_create_file(project_path="/engine/common", file="src/main/java/Foo.java")
# Creates: /engine/common/src/main/java/Foo.java
```

### Why this is non-obvious

The tool succeeds silently — no error is reported. The file is created, indexed, and compiles. The doubled path is only discovered when `git add` fails because the path doesn't match the expected location. In a workspace with many modules, the wrong directory tree can persist unnoticed.
