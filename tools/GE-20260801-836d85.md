## Post-push verification with git cat-file catches silent promotion failures

**ID:** GE-20260801-836d85
**Stack:** git, artifact promotion pipelines

**Context:** Artifact promotion scripts commit to a local branch, push to origin, and report success. But the push can silently fail (network error caught by bare except, push to wrong remote, slot clone pushing to local main instead of origin). The script reports `PUSHED=yes` or `PROMOTED=N` without verifying the files actually arrived.

**Technique:** After a successful push, fetch `origin/main` and verify each promoted file exists:

```python
def verify_push(cwd, promoted_paths):
    git("fetch", "origin", "main", cwd=cwd)
    missing = []
    for path in promoted_paths:
        try:
            git("cat-file", "-e", f"origin/main:{path}", cwd=cwd)
        except subprocess.CalledProcessError:
            missing.append(path)
    if missing:
        print(f"PUSH_VERIFIED=failed")
        print(f"PUSH_VERIFY_MISSING={','.join(missing)}")
    else:
        print(f"PUSH_VERIFIED=yes")
```

**Why this works:** `git cat-file -e` is O(1) — it checks object existence without reading content. The fetch is the only network call. Total overhead for 10 files: one fetch + 10 hash lookups, under 1 second.

**Why non-obvious:** Most push scripts check the push return code and stop. But `git push` can return 0 in scenarios where the data didn't reach the expected ref (force-push race, ref update hook rejection, or the script pushed to a different branch than expected). Verification after push is the only way to confirm delivery.
