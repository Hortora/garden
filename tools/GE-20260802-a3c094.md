### Symptom
A function that promotes artifacts via `git checkout branch -- path` can't work across independent git repos (clones with separate refs).

### Context
`to_workspace_main` normally checks out a file from a feature branch onto main in the same repo. In a slot system, the branch lives in a clone that shares objects but not refs with the original.

### Fix
Add an optional `source-dir` parameter. When present, copy from `source-dir/artifact` via `shutil.copy2` instead of `git checkout branch -- artifact`. The write side (`git add`, `git commit` on the destination repo) stays unchanged.

```python
if source_dir:
    src = Path(source_dir) / artifact
    dst = ws / artifact
    dst.parent.mkdir(parents=True, exist_ok=True)
    shutil.copy2(str(src), str(dst))
    git("add", artifact, cwd=workspace)
else:
    git("checkout", branch, "--", artifact, cwd=workspace)
    git("add", artifact, cwd=workspace)
```

### Why this is non-obvious
The natural instinct is to fetch the branch from the remote (`git fetch origin branch`) and use `origin/branch` as the ref. But this requires network access and adds complexity. The files already exist on the filesystem — the slot clone has them checked out. Filesystem copy is simpler, faster, and works offline.
