### Convention

Name workspace clones by their git remote URL stem (e.g.,
`wsp-casehub-connectors` from `wsp-casehub-connectors.git`)
instead of using a `work-` prefix (e.g., `work-casehub`).

### Why this convention

The `work-` prefix caused three problems:

1. **Collisions** — a project repo named `work` produces `work-work`
   when prefixed, breaking detection heuristics
2. **Fragile detection** — `is_project_repo()` must hardcode `work-*`
   exclusions, which break when workspaces are renamed
3. **Ambiguity** — `work-casehub/` could be a workspace for any project
   in the casehub family; `wsp-casehub-connectors/` is unambiguous

### Alternative considered

Using `work-<project>` (e.g., `work-connectors`) — still collides when
a project and its workspace share a base name, and the `work-` prefix
inherits the detection fragility.

### How to apply

Derive the name from the workspace repo's `origin` remote URL:

```python
remote_url = git_remote(workspace_repo, "origin")
name = Path(remote_url.rstrip("/")).stem  # strips .git extension
# "wsp-casehub-connectors.git" → "wsp-casehub-connectors"
```

Fallback when no remote: `wsp-<parent-dir-name>-<repo-name>`.
