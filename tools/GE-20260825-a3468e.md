# sync-local deploys skill files to all sessions before backing scripts reach main

## Symptom
After running `sync-local` on a feature branch, new Claude Code sessions invoking the skill get the updated SKILL.md but the Python scripts it references only exist on the feature branch. Sessions on main or other branches fail with script-not-found errors and no fallback instructions.

## Context
`sync-local` copies ALL files from a skill's source directory in the repo to `~/.claude/skills/<skill>/`. This includes both the SKILL.md (instructions) and .py scripts (implementation). The SKILL.md is loaded by Claude when the skill is invoked. If the SKILL.md references scripts by relative path and those scripts exist in the installed directory, it works from any repo. But if the SKILL.md was rewritten to reference an orchestrator that didn't exist in the previous version, sessions using the old codebase have no fallback.

## What was tried (didn't work)
Running `sync-local` twice during development to keep the installed skill current with branch changes. This deployed the new SKILL.md (dispatch loop referencing the orchestrator) to all sessions immediately.

## Root cause
`sync-local` has no concept of deployment gates — it copies the current working tree to the installed location unconditionally. There's no check for whether the source is on main, whether backing scripts exist, or whether the change is backwards-compatible with existing sessions.

## Fix
Restore the old SKILL.md to the installed location before merging:
```bash
git show <baseline-sha>:work-end/SKILL.md > ~/.claude/skills/work-end/SKILL.md
```
Then only run `sync-local` AFTER merging the branch to main, when all backing scripts are available from any checkout.

## Why this is non-obvious
`sync-local` is designed for rapid iteration during development. The expectation is that you sync, test, iterate. The failure mode only appears when multiple concurrent sessions exist — the developer's own session works fine because they're on the branch with the scripts. Other sessions (or future sessions after switching branches) silently break.

### Alternatives considered
- Adding a fallback section to the SKILL.md that preserves old instructions — works but doubles the file size and masks orchestrator failures during testing
- Only syncing SKILL.md without .py files — breaks the existing pattern where scripts need to be accessible from any repo
