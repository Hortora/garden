### Symptom
Orchestrator returns empty output — no `ACTION=` line, no error, exit code 0. The LLM sees nothing and the close sequence stalls silently. Only happens in slot mode with per-repo fan-out for judgment steps (protocol, update_claude_md).

### Context
In slot mode, judgment steps like `protocol` expand per-repo: `protocol:chat-app`, `protocol:blocks-ui`, `protocol:qhorus`. When all per-repo variants are done or skipped, the `_close_per_repo_judgment` callback returns `{}` (empty dict) to signal "all repos handled, nothing to yield."

### Root cause
Asymmetry in `orchestrator_engine.py` `run_loop` between mechanical and judgment per-repo handling:

```python
# Mechanical steps — CORRECT:
handled = per_repo_mechanical(step, ctx)
if handled is not None:
    if "ERROR" in handled:
        return handled
    continue  # ← advances to next step

# Judgment steps — BUG:
handled = per_repo_judgment(step, ctx)
if handled is not None:
    return handled  # ← returns empty dict to caller. Silent deadlock.
```

Empty dict is not `None`, so `return handled` fires. The caller prints `{}` as key=value output — which has no entries, so nothing prints.

### Fix
When `per_repo_judgment` returns empty dict (all repos done), mark the parent step done and `continue` — matching mechanical behavior:

```python
if per_repo_judgment:
    handled = per_repo_judgment(step, ctx)
    if handled is not None:
        if not handled:  # empty dict = all repos done
            update_close_progress(ctx.workspace, step.name, "done")
            ctx.steps_executed.append(step.name)
            continue
        return handled
```

### Why this is non-obvious
The asymmetry is invisible during non-slot operation — `per_repo_judgment` is only called when `in_slot=yes`. The empty dict vs None distinction is subtle: `{}` is truthy in a boolean context but empty when iterated. The mechanical path happened to use `continue` (correct) while the judgment path used `return` (incorrect) because judgment steps normally return an ACTION dict to yield to the LLM.

### Alternatives considered
- Making `per_repo_judgment` return `None` when all repos done — rejected because `None` means "not handled, fall through to regular yield" which would yield `ACTION=protocol` (wrong, all repos are done).
- Adding a sentinel value — rejected as unnecessary complexity when `continue` works.
