## @InjectMock @RestClient requires quarkus-junit-mockito dependency, not just mockito-core

**ID:** GE-20260802-c45513
**Stack:** Quarkus 3.x, Mockito

### Symptom

`@QuarkusTest` with `@InjectMock @RestClient` fails at test instantiation: `IllegalStateException: @io.quarkus.test.InjectMock declared on one or more fields of a @QuarkusTest but the quarkus-junit-mockito dependency is not present`.

### Root Cause

`quarkus-junit` provides the `@InjectMock` annotation but NOT the Mockito integration. The integration lives in `quarkus-junit-mockito`, which transitively pulls in `mockito-core` and registers the CDI test callbacks. Adding `mockito-core` alone provides the API but not the Quarkus CDI integration.

### Fix

Add `quarkus-junit-mockito` (not `mockito-core`) as a test dependency. It pulls in mockito-core transitively.

### Why This Is Non-Obvious

The `@InjectMock` annotation compiles fine with just `quarkus-junit` — the failure is runtime, not compile-time. Developers reach for `mockito-core` first without realising Quarkus needs its own bridge artifact.
