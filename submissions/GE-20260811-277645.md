## What it is

Textual's `App.suspend()` context manager temporarily exits the alternate screen, restores the terminal to normal mode, and yields control. When the context manager exits, Textual re-enters the alternate screen, redraws all widgets, and resumes event handling. This enables a TUI to hand terminal control to an external process (like `claude`, `vim`, or any interactive CLI), then resume seamlessly.

## How to use it

```python
# Inside a Textual App method:
async def launch_cli(self, cli_command: str, cwd: str):
    with self.suspend():
        import subprocess
        subprocess.run([cli_command], cwd=cwd)
    # Textual automatically resumes here — re-enters alternate screen,
    # redraws all widgets, restores event handling
    await self.refresh_state()  # Re-detect state after CLI session
```

The pattern is: suspend → run external process (blocks) → Textual auto-resumes on return.

## How it was discovered

Found by exploring Textual's API during design of a TUI that needs to hand off to LLM CLI sessions. The `suspend()` method exists in the Textual API but is not prominently featured in tutorials or the main documentation — most Textual examples assume the app owns the terminal for its entire lifetime.

## Why this matters

Without `suspend()`, a TUI that needs to launch external CLI processes would have to either embed a terminal emulator (complex) or exit and restart (loses state). `suspend()` provides clean handoff-and-resume semantics that Tamboui (Java TUI framework) does not yet offer natively — the Tamboui equivalent requires manual `leaveAlternateScreen()` / `disableRawMode()` and re-entry.
