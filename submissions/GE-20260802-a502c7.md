## InMemoryCaseRetriever cannot filter by sourceDocumentId — ChunkInput rejects it in metadata map

**ID:** GE-20260802-a502c7
**Stack:** casehub-neocortex-rag-testing, Quarkus 3.x

### Symptom

`PayloadFilter.in("sourceDocumentId", documentIds)` returns zero results when using `InMemoryCaseRetriever` in tests, even though the documents exist in `InMemoryEmbeddingIngestor`.

### Root Cause

`ChunkInput` constructor throws `IllegalArgumentException: metadata key 'sourceDocumentId' conflicts with ChunkInput field name` if you try to include `sourceDocumentId` in the metadata map. But `InMemoryCaseRetriever.matches()` filters against `metadata.get(field)` — it checks the metadata map, not the dedicated `ChunkInput.sourceDocumentId()` field. Since `sourceDocumentId` can never be in metadata, the filter always returns false.

In Qdrant (production), `sourceDocumentId` IS stored in the payload and filterable. The divergence is specific to the in-memory test implementation.

### Fix

For ID-based lookups in tests, don't use `PayloadFilter` on `sourceDocumentId`. Instead read from the filesystem directly (if the entry exists as a file), or use `InMemoryEmbeddingIngestor.getChunks(corpus)` and filter by `ChunkInput.sourceDocumentId()` manually.

### Why This Is Non-Obvious

The production path (Qdrant) works correctly — `sourceDocumentId` is a standard payload field. The failure is silent: `InMemoryCaseRetriever` returns an empty list, not an error.
