## GardenMcpTools.extractDocumentId() returns different formats for legacy vs new-format GE-IDs

**ID:** GE-20260802-aea7e3
**Stack:** Hortora engine, Qdrant

### Symptom

Entry lookup by GE-ID fails for legacy entries (GE-0031) but works for new-format entries (GE-20260618-c552c3). The mapping from GE-ID to Qdrant document ID produces inconsistent keys.

### Root Cause

`extractDocumentId()` has a regex check: `filename.matches("GE-\\d{8}-[0-9a-f]{6}")`. New-format IDs match and return the bare filename. Legacy IDs like `GE-0031` don't match the pattern, so the method returns the full domain-qualified path (`jvm/GE-0031`). The mapping has mixed key formats.

### Fix

When building a GE-ID lookup map, add entries for both the `extractDocumentId()` result AND the bare filename to handle both formats.

### Why This Is Non-Obvious

The method name implies a single canonical format. The format divergence is invisible unless you test with both legacy and new-format entries.
