# Quinoa dev WebSocket proxy intercepts backend WebSocket endpoints

## Symptom

WebSocket connections to a backend endpoint (e.g. `/ws/push`) fail with
"HTTP Authentication failed" or connect to the wrong server. Server logs
show `QuinoaDevWebSocketProxyHandler` routing to Vite's dev server port.

## Context

Quarkus dev mode with Quinoa enabled (`-Pui` profile). Any backend
WebSocket endpoint registered via `@WebSocket(path = "/ws/...")` from
`quarkus-websockets-next`. Quinoa's `package-manager` is set to `yarn`
or `npm` and Vite runs as the frontend dev server.

## What was tried (didn't work)

- Setting `quarkus.quinoa.ignored-path-prefixes=/ws/,/api/,/q/` — this
  only affects HTTP request routing, not WebSocket upgrade proxying.
- The `ignored-path-prefixes` config name implies protocol-agnostic
  path exclusion but the WebSocket proxy handler is separate.

## Root cause

`QuinoaDevWebSocketProxyHandler` intercepts ALL WebSocket upgrade
requests and proxies them to the Vite dev server for HMR support.
There is no config to exclude specific WebSocket paths from this proxy.
The `ignored-path-prefixes` config only applies to HTTP request routing
in `QuinoaDevProxyHandler`, not to `QuinoaDevWebSocketProxyHandler`.

## Fix

Run without the Quinoa profile for backend WebSocket testing:

1. Pre-build the frontend: `npm run build` (esbuild)
2. Serve from static resources (symlink or copy `dist/` to
   `META-INF/resources/`)
3. Start Quarkus without `-Pui`: `mvn quarkus:dev`

This bypasses Quinoa entirely — WebSocket upgrades reach the backend
endpoint directly.

### Why this is non-obvious

The config property `ignored-path-prefixes` strongly suggests it covers
all protocols for the given paths. The actual implementation splits HTTP
and WebSocket proxying into separate handlers with no shared exclusion
mechanism. Server logs show `QuinoaDevWebSocketProxyHandler Connected`
but don't indicate the original request path was meant for a backend
endpoint.
