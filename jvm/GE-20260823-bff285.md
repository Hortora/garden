### Symptom

Build extension validation tests using `QuarkusUnitTest` take seconds per test class due to full Quarkus container bootstrap — too slow for rapid TDD iteration on annotation scanning logic.

### Context

When developing a Quarkus deployment module (build extension), validation rules (e.g., "no dual pattern annotations", "all AgentRef params need role annotations") don't need the CDI container — they operate on the Jandex index. Testing with `QuarkusUnitTest` pays the full bootstrap cost unnecessarily.

### Fix

Use the Jandex `Indexer` API directly in JUnit 5 tests. Define fixture interfaces as inner classes of the test, index them from the classpath, and pass the `Index` to the scanner step:

```java
class PatternValidationTest {

    private Index indexClasses(Class<?>... classes) throws IOException {
        Indexer indexer = new Indexer();
        for (Class<?> clazz : classes) {
            String resourceName = "/" + clazz.getName().replace('.', '/') + ".class";
            try (InputStream stream = clazz.getResourceAsStream(resourceName)) {
                if (stream != null) indexer.index(stream);
            }
        }
        return indexer.complete();
    }

    // Fixture: valid debate pattern
    interface ValidDebate {
        @Debate(maxRounds = 5)
        String review(
                @Debater(role = "critic", systemPrompt = "Challenge") AgentRef critic,
                @Judge(systemPrompt = "Judge") AgentRef judge,
                String document);
    }

    @Test
    void accepts_valid_debate() throws IOException {
        Index index = indexClasses(ValidDebate.class);
        var descriptors = new PatternAnnotationStep().scan(index);
        assertThat(descriptors).hasSize(1);
        assertThat(descriptors.get(0).patternType()).isEqualTo(PatternType.DEBATE);
    }
}
```

Tests run in ~60ms vs seconds with `QuarkusUnitTest`. Inner interface fixtures compile with the test class — Jandex reads their bytecode from the classpath.

### Why this is non-obvious

Quarkus documentation emphasises `QuarkusUnitTest` and `@QuarkusTest` for extension testing. The Jandex `Indexer` API is low-level and not covered in the build extension guides. The technique of indexing test fixture inner classes from `getResourceAsStream()` is not documented anywhere.
