### Symptom

`@Any Instance<ChatModel>` in a main-scope `@ApplicationScoped` bean throws `IllegalStateException: ChatModel not configured` — even though a `@Produces` method in `src/test/java` creates the bean with a custom `@Qualifier`.

### Context

Quarkus ArC processes `src/main/java` and `src/test/java` as separate augmentation units. A `@Qualifier` annotation class defined in `src/test/java` is not on the classpath when ArC discovers beans from `src/main/java`. The main-scope bean's `@Any Instance<T>` injection point cannot see qualifier-annotated beans from the test scope.

### What was tried (didn't work)

1. Defined `@Judge` qualifier in `eval/src/test/java`
2. Added `@Judge @Produces ChatModel` in `VertexChatModelProducer` (test scope)
3. Injected `@Any Instance<ChatModel>` in `FunctionActivationJudge` (main scope)
4. Result: `Instance.isResolvable()` returns false — CDI cannot see the `@Judge`-qualified bean

### Root cause

ArC augmentation compiles bean metadata at build time per source set. The `@Judge` annotation class from test scope is not available when the main source set's bean metadata is compiled. The `@Any` qualifier should match all beans regardless of qualifiers, but the bean itself is not registered because its producer method references a qualifier class that doesn't exist in the main augmentation context.

### Fix

Bypass CDI qualifiers for cross-scope model wiring. Use a setter method on the main-scope bean and direct instantiation in the test:

```java
// Main scope — no qualifier dependency
public class FunctionActivationJudge {
    private ChatModel judgeModel;

    void setJudgeModel(final ChatModel judgeModel) {
        this.judgeModel = judgeModel;
    }
}

// Test scope — direct instantiation, no CDI
if (!judgeModelName.isEmpty()) {
    var judgeModel = new VertexChatModel(projectId, region, judgeModelName, timeout);
    functionJudge.setJudgeModel(judgeModel);
}
```

### Why this is non-obvious

The `@Any` qualifier is documented as matching all beans regardless of qualifiers. The failure mode is silent — no augmentation error, no warning. The bean simply doesn't exist from the main scope's perspective, so `Instance.isResolvable()` returns false. A developer would reasonably expect `@Any` to resolve beans from both source sets.
