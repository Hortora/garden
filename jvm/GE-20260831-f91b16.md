### Symptom
`java.io.FileNotFoundException: JAR entry not found in jar file` when using
`JarURLConnection` to list resources at a path like `META-INF/desiredstate/modules/`
inside a JAR. Works fine for `file:` protocol resources on the filesystem.

### Context
Classpath resource scanning using `ClassLoader.getResources(prefix)` returns URLs
for each location on the classpath. For JARs, the URL is
`jar:file:/path/to/foo.jar!/META-INF/desiredstate/modules/`. Opening a
`JarURLConnection` on this URL and calling `getJarFile()` fails if the JAR
doesn't contain a directory entry for that path.

Maven-built JARs don't always include directory entries. The `jar` tool and
`JarOutputStream` only create entries for files, not directories, unless
explicitly added.

### What was tried (didn't work)
Using `JarURLConnection` to open the JAR and list entries:
```java
JarURLConnection jarConn = (JarURLConnection) jarUrl.openConnection();
JarFile jarFile = jarConn.getJarFile(); // throws FileNotFoundException
```

### Root cause
`JarURLConnection` validates that the entry specified in the URL exists in the
JAR. When the URL points to a directory path (e.g. `META-INF/desiredstate/modules/`),
that directory entry must exist as a `JarEntry`. Maven's default JAR plugin
configuration doesn't create directory entries.

### Fix
Extract the JAR file path from the URL string and open `JarFile` directly.
Iterate all entries and filter by prefix:

```java
String urlStr = jarUrl.toString();
int bangIdx = urlStr.indexOf("!/");
String filePath = urlStr.substring("jar:file:".length(), bangIdx);
try (JarFile jarFile = new JarFile(filePath)) {
    Enumeration<JarEntry> entries = jarFile.entries();
    while (entries.hasMoreElements()) {
        JarEntry entry = entries.nextElement();
        if (entry.getName().startsWith(prefix) && !entry.isDirectory()
                && entry.getName().endsWith(".yaml")) {
            String fileName = entry.getName().substring(prefix.length());
            if (!fileName.contains("/")) {
                try (InputStream is = jarFile.getInputStream(entry)) {
                    // process the resource
                }
            }
        }
    }
}
```

### Why this is non-obvious
`JarURLConnection` is the standard JDK API for accessing JAR resources via URL.
The failure is silent until runtime when a dependent JAR happens to not include
directory entries. Tests with filesystem resources pass fine — the bug only
manifests with actual JAR dependencies.

### Alternatives considered
- Adding directory entries to JARs via Maven plugin configuration — fragile, requires
  all producing projects to configure it
- Using `ClassLoader.getResources()` with individual file paths — requires knowing
  file names in advance, defeating the purpose of discovery
