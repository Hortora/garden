## What's undocumented

`ToolSpecification.builder().parameters()` accepts `JsonObjectSchema`, not the parent interface `JsonSchemaElement`. The type hierarchy (`JsonObjectSchema implements JsonSchemaElement`) suggests either should work, but the builder field and method are typed to the concrete class.

Additionally, `JsonObjectSchema.Builder` uses:
- `addStringProperty(String name)` — adds a string parameter
- `addProperty(String name, JsonSchemaElement schema)` — adds a typed parameter
- `addIntegerProperty(String name)`, `addBooleanProperty(String name)`, etc.

There is no `properties(Map<String, JsonSchemaElement>)` method — properties must be added one at a time via the `add*` methods.

## How to discover this

The javadoc does not make the `JsonObjectSchema` requirement clear. Discoverable only via:

```bash
javap -p langchain4j-core-1.14.1.jar\!dev/langchain4j/agent/tool/ToolSpecification.class
javap -p langchain4j-core-1.14.1.jar\!dev/langchain4j/model/chat/request/json/JsonObjectSchema\$Builder.class
```

## Working example

```java
var spec = ToolSpecification.builder()
    .name("web-search")
    .description("Search the web")
    .parameters(
        JsonObjectSchema.builder()
            .addStringProperty("query")
            .addIntegerProperty("maxResults")
            .build())
    .build();
```

### Why this is non-obvious

The `JsonSchemaElement` interface is the common type across `JsonObjectSchema`, `JsonStringSchema`, `JsonArraySchema`, etc. A developer naturally expects the builder to accept the interface type, not a specific implementation. The compiler error ("incompatible types: JsonSchemaElement cannot be converted to JsonObjectSchema") appears to be a bug but is the intended API — tool parameters are always objects at the top level.
