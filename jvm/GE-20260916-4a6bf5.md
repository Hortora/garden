### Symptom

Need per-relationship trust (how much does observer A trust subject B?) but `TrustScoreComputer` computes per-actor trust (how trustworthy is actor X globally?).

### Context

The ledger's `TrustScoreComputer.compute(decisions, attestationsByEntryId, now)` takes all of an actor's decisions and all attestations on those decisions, producing a single global trust score. For cognitive agents with perspectival social awareness, each observer needs a different trust score for the same target.

### Fix

Filter the attestation map by `attestorId` before passing to the computer:

```java
Map<UUID, List<LedgerAttestation>> attestationMap = new HashMap<>();
for (LedgerEntry entry : entries) {
    List<LedgerAttestation> all = ledgerRepo.findAttestationsByEntryId(entry.id, tenantId);
    List<LedgerAttestation> filtered = all.stream()
        .filter(a -> observerId.equals(a.attestorId))
        .toList();
    if (!filtered.isEmpty()) {
        attestationMap.put(entry.id, filtered);
    }
}
TrustScoreComputer.ActorScore score = computer.compute(entries, attestationMap, now);
```

The computer processes only the filtered attestations — each observer's attestations produce a distinct Bayesian Beta posterior. With no attestations from a given observer, the prior returns 0.5 (maximum uncertainty).

### Why this is non-obvious

`TrustScoreComputer` is documented as a per-actor trust model. The per-relationship usage isn't in any docs or examples. The key insight is that the `attestationsByEntryId` parameter is the leverage point — same decisions, different attestation views, different scores. The computer doesn't care about the attestor identity; it just aggregates whatever attestations you give it.
