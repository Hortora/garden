### Symptom
After `CaseTrigger.fire()` completes, `CaseInstanceRepository.findAll(tenancyId)` returns empty.
No exception is thrown — the Jackson error is suppressed inside the engine's `CaseStartedEventHandler`.
In test output, the error appears only as a `Suppressed:` annotation on the test's own `AssertionError`.

### Context
`DefaultCaseTrigger.buildInputData()` automatically adds `context.detections()` (a `List<TimestampedDetection>`)
to the case input data. `TimestampedDetection` contains `Instant eventTime`. When the engine creates the
`CaseInstance`, `CaseStartedEventHandler.onCaseStarted()` calls `CaseContextImpl.asJsonNode()` which calls
`WritableLayerImpl.asJsonNode()`. This method uses an internal `ObjectMapper` without the `jackson-datatype-jsr310`
module, causing serialization failure on `Instant` fields.

### What was tried
- Verified case YAML definitions were correct (namespace, name, version all matched)
- Verified `DefaultCaseTrigger.fire()` returned a UUID (case creation appeared to succeed)
- Checked `findAll()` and `findByUuid()` with various tenant IDs
- Only after reading the suppressed exception in the surefire report was the root cause found

### Root cause
`WritableLayerImpl.asJsonNode()` (line 322) creates or uses an `ObjectMapper` that does not have
`JavaTimeModule` registered. When the case context contains raw `TimestampedDetection` objects
(added by `DefaultCaseTrigger`), serialization fails with `InvalidDefinitionException` for
`java.time.Instant`. The exception is caught and suppressed, but the case creation transaction
rolls back — the `CaseInstance` is never persisted.

### Fix
Register a `CaseInputContributor` CDI bean that converts the raw `TimestampedDetection` objects
to JSON-serializable `Map<String, Object>` representations before they enter case context:

```java
@ApplicationScoped
public class SocCaseInputContributor implements CaseInputContributor {
    @Override
    public Map<String, Object> contribute(CaseTriggerConfig config, SituationContext context) {
        Map<String, Object> data = new LinkedHashMap<>();
        // Override the raw detections with serializable maps
        data.put("detections", context.detections().stream().map(td -> {
            Map<String, Object> d = new LinkedHashMap<>();
            d.put("ganglionId", td.result().ganglionId());
            d.put("signal", td.result().signal().name());
            d.put("confidence", td.result().confidence());
            d.put("eventTime", td.eventTime().toString());
            d.put("evidence", td.result().evidence());
            return d;
        }).toList());
        return data;
    }
}
```

The contributor's `contribute()` runs after `DefaultCaseTrigger.buildInputData()` and its return
values are merged via `putAll()` — so putting the same `"detections"` key overrides the raw objects.

### Why this is non-obvious
The case creation *appears* to succeed — `CaseTrigger.fire()` returns a UUID. The serialization
failure happens downstream in the lifecycle event handler, which suppresses the exception. The
only way to discover this is to read the suppressed exception chain in the test report — the
standard test output shows only "Expecting actual not to be empty".

Related: GE-20260505-48085a (general static ObjectMapper + Instant pattern). This entry is
specific to the RAS→engine integration path and documents the `CaseInputContributor` workaround.

### Alternatives considered
- Adding `jackson-datatype-jsr310` to the engine's ObjectMapper — correct fix, but requires a
  platform change (engine repo)
- Not using `CaseInputContributor` and instead filtering detections before calling startCase —
  not possible because `DefaultCaseTrigger` adds detections internally
