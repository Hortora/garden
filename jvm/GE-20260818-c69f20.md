### Symptom

`schema.getExpressionLang() != null` is always `true` even when the YAML file doesn't declare `expressionLang`. Inference logic (`if null → use default`) never fires.

### Context

JSON schema declares `default: "jq"` on the `expressionLang` property. jsonschema2pojo generates the field as `private String expressionLang = "jq"`. The getter always returns `"jq"` — it's never null, even when the property is absent from the input YAML.

### Root cause

jsonschema2pojo honours JSON schema `default` by initializing the Java field with the default value. Jackson deserialization only calls the setter when the property IS present. Absent properties leave the default intact — the getter returns the default, not null.

### Fix

Check the raw JSON node for explicit presence instead of the generated getter:

```java
// Bad: always true due to field default
if (schema.getExpressionLang() != null) { ... }

// Good: distinguishes explicit from default
if (rawNode.has("expressionLang")) {
    expressionLang = schema.getExpressionLang();
} else {
    expressionLang = inferredDefault;
}
```

### Why this is non-obvious

The generated getter looks correct — it returns a String, and checking for null is the standard Java pattern. The default value is buried in the JSON schema definition, not visible in the generated Java class without reading the field initializer.
