## Symptom

`SchemaMapper.generate()` completes without error but produces no output files. No exception, no warning, no log message. The output directory is created but empty.

## Context

A JSON Schema file defines all its types under `$defs` (JSON Schema 2020-12 pattern) with no root-level `type: object` or `properties`:

```yaml
$schema: https://json-schema.org/draft/2020-12/schema
$defs:
  Person:
    type: object
    properties:
      name: { type: string }
  Address:
    type: object
    properties:
      street: { type: string }
```

This is a valid JSON Schema — `$defs` types are independently referenceable. But jsonschema2pojo treats the root as the generation entry point and traverses `$defs` types only when they're `$ref`-referenced from the root.

## Root cause

jsonschema2pojo generates from the root schema object outward. `$defs` types are generated as side effects of `$ref` resolution — when the root (or a descendant) references `#/$defs/Person`, the Person class is generated. If nothing references a `$defs` type from the root, it is never visited.

With no root-level properties at all, there's nothing to generate and nothing to trigger `$defs` traversal.

## Fix

Add a root-level type that references the `$defs` entries:

```yaml
$schema: https://json-schema.org/draft/2020-12/schema
$defs:
  Person:
    type: object
    properties:
      name: { type: string }
  Address:
    type: object
    properties:
      street: { type: string }
# Add root type that pulls in $defs via $ref
type: object
properties:
  people:
    type: array
    items:
      $ref: "#/$defs/Person"
```

Every `$defs` type that should be generated needs at least one `$ref` path from the root. Types only referenced by other `$defs` types (not reachable from root) are also silently skipped.

### Why this is non-obvious

The schema is valid JSON Schema — validators accept it, other tools (Cosium's annotation processor) handle standalone `$defs`. The silent-success behaviour gives no indication that anything is wrong. In a Maven build, the generate-sources phase succeeds and compilation only fails later with "class not found" errors that point away from the real cause.
