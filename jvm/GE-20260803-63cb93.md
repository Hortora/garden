### Symptom
Loading a YAML descriptor with an `AgentConstraint` that omits the `visibility` field causes `NullPointerException`:

```
java.lang.NullPointerException: constraint.visibility must not be null
  at io.casehub.eidos.api.AgentConstraint.<init>(AgentConstraint.java:16)
```

### Context
`AgentConstraint` requires 4 fields: `name`, `description`, `visibility`, `severity`. The YAML structure for constraints looks similar to goals, but goals have `visibility` as a meaningful distinction (PUBLIC vs PRIVATE). For constraints, `visibility` is less intuitive — "who can see this constraint" is not an obvious concept.

### Root cause
`AgentConstraint`'s compact constructor calls `Objects.requireNonNull` on `visibility`. Unlike other optional fields that default to null/empty, visibility has no default. Jackson deserializes the YAML into the config object with `visibility = null`, which then fails at construction.

### Fix
Always include `visibility` on every constraint in YAML descriptors:

```yaml
constraints:
  - name: non-verbal
    description: You do NOT speak in full sentences.
    visibility: PUBLIC
    severity: HARD
```

`PUBLIC` is the safe default for most constraints — it means other agents can query whether this character has this constraint.

### Why this is non-obvious
Other constraint fields (`severity`) are also required but produce a clear validation error message. `visibility` produces a raw NPE with no field-name context beyond `constraint.visibility`. The field feels optional because many constraint descriptions are self-evidently public, making the explicit declaration feel redundant.
