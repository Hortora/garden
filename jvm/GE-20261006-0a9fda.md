## Symptom

When using WordNet's lexicographer file names (`getLexFileName()`) to disambiguate word senses by domain — e.g., mapping "place" queries to `noun.location` — place-related terms like "restaurant", "eatery", "coffee shop", "café", and "hotel" silently return no matches. The normalizer falls through to passthrough, producing no synonym expansion.

No error is thrown. The lookup succeeds (the word exists in WordNet), but no synset matches the expected lexicographer file.

## Context

Using extJWNL 2.0.5 with WordNet 3.1 dictionary data (`extjwnl-data-wn31`). Building a term normalizer that maps domain hints to WordNet lexicographer files for sense disambiguation — e.g., domain "place" → `noun.location`, domain "thing" → `noun.artifact`.

## What was tried (didn't work)

Mapped the "place" domain to `noun.location` exclusively. All tests for place-related terms (restaurant, eatery, coffee shop, doll) failed — the normalizer returned passthrough for every term.

## Root cause

WordNet's `noun.location` category covers geographic features (rivers, mountains, cities) — not human-made establishments. Restaurants, shops, hotels, and other buildings/establishments are classified under `noun.artifact` (man-made objects). This is linguistically correct (a restaurant *is* an artifact) but operationally surprising when building a place-search normalizer.

Actual lexicographer file assignments:
- "restaurant", "eatery", "coffee shop", "café" → `noun.artifact`
- "doll" → `noun.artifact` (first sense), `noun.person` (slang)
- "bank" → `noun.object`, `noun.group`, `noun.possession`, `noun.artifact`, `noun.act`

## Fix

Map each domain to a **list** of lexicographer files, not a single file:

```java
private static final Map<String, List<String>> DOMAIN_TO_LEX_FILES = Map.of(
    KnowledgeDomain.PLACE, List.of("noun.artifact", "noun.location"),
    KnowledgeDomain.THING, List.of("noun.artifact", "noun.object"),
    KnowledgeDomain.ACTIVITY, List.of("noun.act")
);
```

Then match against any file in the list:
```java
for (Synset synset : indexWord.getSenses()) {
    if (lexFiles.contains(synset.getLexFileName())) {
        matchedSynset = synset;
        break;
    }
}
```

### Why this is non-obvious

A developer building a place-search normalizer would naturally map "place" → `noun.location`. The WordNet documentation describes lexicographer files but doesn't explain the mapping in terms a domain modeller would recognise. The only way to discover this is to inspect the actual `getLexFileName()` return values for the terms you care about — which requires writing a debug test to enumerate synsets.

### Alternatives considered

- **Single lexicographer file per domain** — the initial approach. Fails for places because `noun.location` doesn't contain establishments.
- **No lexicographer file filtering** — use the first synset regardless of category. Loses domain disambiguation entirely (e.g., "bank" would always resolve to its first sense regardless of context).
