## Symptom

`@QuarkusTest` fails at startup with:
```
IllegalArgumentException: Goal 'susar-complete' is not referenced in any completion expression.
Goals must drive case completion — use Milestone for non-terminal checkpoints.
```

All `@QuarkusTest` classes fail — the error fires during `DefaultCaseDefinitionRegistry.onStart()`.

## Context

YAML case definitions that define `goals` without a `completion` block referencing them. This worked before the engine SNAPSHOT update — unreferenced goals were silently ignored.

## What was tried (didn't work)

- Running individual test classes — all fail with the same startup error
- Checking if the test `application.properties` changed — no changes

## Root cause

An engine SNAPSHOT added `validateExpressions()` to `DefaultCaseDefinitionRegistry.registerCaseDefinitionBlocking()`. This method now requires every goal to be referenced in the case definition's `completion` expression. Previously, goals could exist independently as observable conditions without driving case completion.

## Fix

Add a `completion` block to every YAML case definition that has `goals`:

```yaml
spec:
  goals:
    - name: susar-complete
      kind: success
      condition: ".susarAssessmentComplete != null"

  completion:                     # ADD THIS
    success:                      # ADD THIS
      allOf: [susar-complete]     # ADD THIS — reference every goal

  bindings:
    - name: susar-assessment
      # ...
```

For cases with multiple goals, use `allOf` or `anyOf`:
```yaml
  completion:
    success:
      allOf: [goal-a, goal-b]
```

## Why this is non-obvious

The error message mentions "Milestone" as an alternative but doesn't explain the migration path. The change is silent — no deprecation warning in the prior SNAPSHOT, no engine changelog entry. YAML files that loaded successfully for months suddenly fail at startup after a routine SNAPSHOT bump.
