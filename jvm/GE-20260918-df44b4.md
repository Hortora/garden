## Symptom

After bumping Spring Boot from 3.x to 4.x, JPA test classes fail to compile:

```
package org.springframework.boot.test.autoconfigure.orm.jpa does not exist
package org.springframework.boot.autoconfigure.domain does not exist
cannot find symbol: class DataJpaTest
cannot find symbol: class EntityScan
```

## Context

Spring Boot 4 modularized its monolithic `spring-boot-autoconfigure` and `spring-boot-test-autoconfigure` JARs into smaller, focused modules. Classes that were in catch-all packages moved to domain-specific packages and modules.

## Root cause

Two changes compound:

1. **Package moves** (import changes):

| Annotation | Spring Boot 3 | Spring Boot 4 |
|---|---|---|
| `@DataJpaTest` | `org.springframework.boot.test.autoconfigure.orm.jpa` | `org.springframework.boot.data.jpa.test.autoconfigure` |
| `@EntityScan` | `org.springframework.boot.autoconfigure.domain` | `org.springframework.boot.persistence.autoconfigure` |

2. **New test dependency required** — `@DataJpaTest` is no longer in `spring-boot-starter-test`. You need an explicit dependency:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa-test</artifactId>
    <scope>test</scope>
</dependency>
```

## Fix

For each test file, update both imports:

```java
// Old (Boot 3)
import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;
import org.springframework.boot.autoconfigure.domain.EntityScan;

// New (Boot 4)
import org.springframework.boot.data.jpa.test.autoconfigure.DataJpaTest;
import org.springframework.boot.persistence.autoconfigure.EntityScan;
```

And add `spring-boot-starter-data-jpa-test` to each module's POM.

`@AutoConfigurationPackage` stays at `org.springframework.boot.autoconfigure` — it did not move.

## Why this is non-obvious

The compilation error says "package does not exist" — not "moved to X". Without the migration guide, you'd search for where `DataJpaTest` went, but the new package name (`org.springframework.boot.data.jpa.test.autoconfigure`) isn't guessable from the old one. The additional test dependency requirement is a second failure that appears after fixing the imports — two sequential fixes needed.
