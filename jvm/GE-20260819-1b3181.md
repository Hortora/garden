### Symptom
The pages-ui decision review referenced `masterDetail()` at `pages-ui/src/dsl/builders.ts:558` as the correct DSL function for composing a master-detail split layout. However, the compiled `builders.d.ts` in the installed `casehub-pages-npm` SNAPSHOT does not export `masterDetail`. The function is absent from the type definitions and cannot be imported.

### Context
During casehubio/iot#95 design review, the reviewer identified `masterDetail()` as the existing DSL mechanism that composes `split()` + `data-table` + `host-panel` with automatic selection wiring. The source file may contain this function, but the published SNAPSHOT either:
1. Has not been rebuilt since `masterDetail()` was added
2. Excludes it from the public API via an unexported internal module

### Workaround
Use the constituent DSL functions directly:

```typescript
split("horizontal",
  [
    panel("List", table({ ... })),
    hostPanel("blocks-work-item-detail", { endpoint: "/api" }),
  ],
  { ratio: [0.4, 0.6], minSizes: [320, 400] },
)
```

This loses the automatic selection wiring that `masterDetail()` would provide — table row selection must be manually connected to the detail panel via event topics.

### Why this is non-obvious
The function exists in the source repo and was identified by a code reviewer who read the actual source. But the installed package (consumed via Maven SNAPSHOT → `.casehub-packages` portal resolution) doesn't include it. A developer following the reviewer's advice to "use masterDetail()" would get a compilation error with no indication that the function exists in source but not in the published artifact.
