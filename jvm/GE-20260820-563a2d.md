### Symptom

Tests that use JAX-RS `SseEventSource` cannot connect to POST-based SSE endpoints (e.g. JSON-RPC dispatch with `Accept: text/event-stream`).

### Context

When refactoring REST-style GET SSE endpoints to POST-based JSON-RPC dispatch, existing `SseEventSource.target(webTarget).build()` tests fail — `SseEventSource` only supports GET requests. No JAX-RS API exists for POST-based SSE consumption.

### Fix

Use `java.net.http.HttpClient` with `BodyHandlers.ofLines()` for POST-based SSE:

```java
HttpClient httpClient = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(5)).build();
HttpRequest req = HttpRequest.newBuilder()
        .uri(URI.create(baseUri + "/endpoint"))
        .header("Content-Type", "application/json")
        .header("Accept", "text/event-stream")
        .POST(HttpRequest.BodyPublishers.ofString(jsonBody))
        .build();

// Async — for tests that dispatch messages while streaming
CopyOnWriteArrayList<String> events = new CopyOnWriteArrayList<>();
CountDownLatch latch = new CountDownLatch(1);
CompletableFuture<Void> streamFuture = httpClient.sendAsync(req,
        HttpResponse.BodyHandlers.ofLines())
        .thenAccept(resp -> resp.body().forEach(line -> {
            if (line.startsWith("data:") && line.contains("\"state\"")) {
                events.add(line.substring(5));
                latch.countDown();
            }
        }));

// ... dispatch messages on test thread, await latch ...
streamFuture.cancel(true); // cleanup

// Sync — for immediate-close tests (terminal state, error events)
String body = RestAssured.given()
        .contentType("application/json").accept("text/event-stream")
        .body(jsonBody).when().post("/endpoint")
        .then().statusCode(200).extract().body().asString();
```

### Why this is non-obvious

The JAX-RS SSE client API (`SseEventSource`) is the standard approach for SSE testing in Quarkus/JAX-RS projects. Its GET-only limitation is not documented — you discover it when switching to POST-based SSE. The `HttpClient` + `BodyHandlers.ofLines()` combination is not an obvious alternative for SSE consumption.
