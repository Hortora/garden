## QuarkusUnitTest only works in the deployment module

### Symptom

Test fails with: `No bean found for required type [TestClassName] and qualifiers [[]]`

The error occurs at CDI validation time. The test class itself is not registered as a CDI bean, so `@Inject` fields on the test class cannot be resolved.

### Context

When writing integration tests for a Quarkus extension in a separate module (e.g., an `examples/` module that consumes the extension), using `@RegisterExtension` with `QuarkusUnitTest` and `withApplicationRoot()` does not work. The test class needs to be a CDI bean for injection to work, but `QuarkusUnitTest` only auto-registers the test class when running inside the deployment module itself.

### Root cause

`QuarkusUnitTest` is designed for deployment module testing. It discovers build steps from the module's own classpath (`quarkus-build-steps.list`). When used in a different module, the test class is not part of the application root and is not registered as a CDI bean. Even adding `root.addClasses(TestClass.class)` to `withApplicationRoot()` does not reliably fix this.

### Fix

For extension integration tests outside the deployment module, use plain JUnit tests that instantiate the recorder directly:

```java
class ExampleTest {
    static GoalCompiler<Void> compiler;

    @BeforeAll
    static void setup() {
        GraphDescriptor descriptor = buildDescriptorFromAnnotations();
        DesiredStateGraphRecorder recorder = new DesiredStateGraphRecorder();
        compiler = recorder.createGoalCompiler(descriptor).getValue();
    }

    @Test
    void compilesToCorrectGraph() {
        var factory = new DefaultDesiredStateGraphFactory();
        var result = compiler.compile(null, factory);
        // assertions...
    }
}
```

This tests the full chain (annotations -> descriptor -> recorder -> graph) without CDI. The CDI integration is already proven by `QuarkusUnitTest` in the deployment module.

### Why this is non-obvious

The API accepts any module — there's no compile-time error or warning. The failure only appears at runtime with a CDI resolution error that doesn't mention the deployment module constraint. The natural assumption is that `QuarkusUnitTest` works anywhere the extension's runtime JAR is on the classpath.
