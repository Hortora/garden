### Symptom
You want api-module POJOs (zero JPA dependency) to define the persistent field set, with JPA entity subclasses in a runtime module adding only `@Entity`, `@Table`, `@NamedQuery`. But JPA requires `@MappedSuperclass` on the parent class for inherited fields to be persistent — and that annotation lives in `jakarta.persistence`, which the api module must not depend on.

### Context
Multi-layer architecture where the api module defines pure Java POJOs (SPIs, model types) with zero framework dependencies. JPA entities in a separate runtime module extend these POJOs. The api module must remain free of `jakarta.persistence` so it can be consumed by non-JPA backends (in-memory, event-sourced).

### What didn't work
- Adding `@MappedSuperclass` to the api POJO — introduces `jakarta.persistence` dependency in the api module
- Using `@AttributeOverride` on the entity subclass — only works for `@MappedSuperclass` or `@Embeddable` parents, not plain classes
- Redeclaring all fields in the entity with `@Column` annotations — field shadowing causes Hibernate to see the child's field but the parent's default value

### Root cause
JPA spec does not support persistent field inheritance from non-annotated superclasses. But Hibernate supports an escape hatch: `META-INF/orm.xml` can declare any class as `<mapped-superclass>` with full `<attributes>` mapping — column names, enum types, id designation — without the class itself having any JPA annotations.

### Fix
In the runtime module's `META-INF/orm.xml`, declare the api POJO as a mapped-superclass:

```xml
<mapped-superclass class="io.example.api.model.MyBase" access="FIELD">
    <attributes>
        <id name="id"/>
        <basic name="status">
            <column name="status_code" nullable="false"/>
            <enumerated>STRING</enumerated>
        </basic>
        <basic name="createdAt">
            <column name="created_at" nullable="false"/>
        </basic>
    </attributes>
</mapped-superclass>
```

The entity subclass becomes minimal — only class-level annotations:

```java
@Entity @Table(name = "my_table") @NamedQuery(...)
public class MyEntity extends MyBase {
    // No field declarations — all inherited from MyBase
}
```

### Why this is non-obvious
The standard answer to "how do I map inherited fields" is `@MappedSuperclass` — every JPA tutorial, every Stack Overflow answer. The orm.xml escape hatch is documented in the JPA spec but rarely used and almost never shown in the context of keeping a module JPA-free. A developer would typically conclude "you can't do this without a JPA dependency on the parent" and either accept the dependency or duplicate fields.

### Alternatives considered
- **Duplicate fields in entity**: works but violates DRY and risks field shadowing bugs
- **Make api module depend on jakarta.persistence-api (provided scope)**: technically possible but violates the zero-framework-dependency principle for api modules — non-JPA consumers still get JPA annotations on their classpath
