### Problem

Expression engine SPI has `evaluate(evaluator, context)` — no way to pass the POJO type needed for typed evaluation. The context type is known at definition-parse time but lost by evaluation time.

### Pattern

Create a specialized evaluator record that carries the context class alongside the expression:

```java
public record TypedMvelExpressionEvaluator(String expression, Class<?> contextClass)
    implements ExpressionEvaluator {
    @Override public String type() { return "mvel"; }
}
```

At parse time, wrap the registry to intercept `create()` and produce typed evaluators:

```java
class TypedMvelRegistry implements ExpressionEngineRegistry {
    ExpressionEvaluator create(String expression, String lang) {
        ExpressionEvaluator result = delegate.create(expression, lang);
        if ("mvel".equals(lang)) {
            return new TypedMvelExpressionEvaluator(expression, contextClass);
        }
        return result;
    }
}
```

At evaluation time, the engine checks `instanceof` and uses the typed path:

```java
if (evaluator instanceof TypedMvelExpressionEvaluator typed) {
    Object pojo = bridge.deserialise(workingJson, typed.contextClass());
    return platformEngine.compile(expr, typed.contextClass(), Boolean.class).eval(pojo);
}
// fallback: Map-based evaluation
```

### Why this works

- No SPI change — existing `evaluate(evaluator, context)` signature preserved
- All existing call sites get typed evaluators automatically via the registry wrapper
- The evaluator is a value type — serializable, cacheable, no CDI dependency
- Graceful degradation — untyped `MvelExpressionEvaluator` still works for top-level Map access

### Suitability

Works when: context type information is available at compile/parse time but not at evaluation time, and the SPI can't be changed to thread it.

Doesn't work when: the context type varies per evaluation (not per definition), or the evaluator must be serialized across JVMs (Class<?> reference lost).
