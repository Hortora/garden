### Symptom

After running k-core community detection and creating Summary nodes with edges to cluster members, the Summary node itself becomes part of subsequent k-core computations. When a cluster's original members disperse (nodes erased, edges removed), the Summary node's edges to remaining members keep the k-core alive — preventing cleanup of the stale summary.

### Context

Occurs when:
- A graph contains both factual nodes (entities) and derived nodes (summaries, aggregates, index entries)
- Derived nodes have edges to the entities they describe (e.g. `summarizes` edges)
- Community detection algorithms (k-core, modularity, label propagation) run on the full graph without filtering

### What was tried (didn't work)

**Run k-core on the full graph, then clean up stale summaries** — the stale summary detection checks whether the summary's `coreHash` matches any current k-core. But the summary's edges inflate its own core, producing a new k-core that includes the summary itself, generating a new hash that the summary never matches (since its `coreHash` was computed from the original factual members). The summary is never cleaned up.

### Root cause

k-core decomposition considers ALL nodes and ALL edges. A Summary node with N `summarizes` edges has degree N. If N ≥ k, the Summary node anchors a core that includes itself and its targets — even when the original cluster has dissolved. The derived node creates a self-sustaining community.

### Fix

Filter derived nodes from k-core results before processing:

```java
List<KCore> rawCores = MindMapAnalyzer.kCores(store, sgId, tenantId, k);
List<KCore> cores = rawCores.stream()
    .map(core -> {
        Set<String> filtered = core.nodeIds().stream()
            .filter(id -> !store.getNode(id, tenantId).traits().contains("Summary"))
            .collect(Collectors.toSet());
        return new KCore(filtered, core.density());
    })
    .filter(core -> !core.nodeIds().isEmpty())
    .toList();
```

Hash and process only the filtered (factual-only) node sets. Summary nodes are excluded from membership but their edges still participate in the graph structure for other nodes.

### Why this is non-obvious

The k-core algorithm is correct — it faithfully finds densely-connected subsets. The problem is semantic: derived nodes have structural properties (high degree from description edges) that make them look like core members, but they're not factual entities. The same issue applies to any graph analysis (centrality, density, PageRank) where synthetic nodes participate.
