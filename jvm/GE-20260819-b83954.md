## QhorusDashboardService CDI failure is pre-existing on main

### Symptom

`mvn test -pl quarkmind-sc2` fails with `UnsatisfiedResolutionException: Unsatisfied dependency for type io.casehub.qhorus.runtime.dashboard.QhorusDashboardService`. Running individual test classes (`-Dtest=ClassName`) works fine.

### Context

The failure occurs on main — it is NOT caused by any local changes. When surefire runs the full suite, Quarkus augmentation discovers `@QuarkusTest` classes and triggers CDI validation. The `QhorusDashboardService` bean is excluded via config but still referenced, causing the validation to fail.

### Root cause

`QhorusDashboardService` is excluded from the CDI context (`was excluded in config`) but something still declares an injection point for it. The exclusion happens at the CDI level, not at the classpath level — so the class is visible but the bean is not resolvable.

### Workaround

Run individual test classes with `mvn clean test -Dtest=ClassName` — this avoids triggering the full suite augmentation. Pure unit tests (non-`@QuarkusTest`) are never affected.

### Why this is non-obvious

When debugging a separate change (adding a field to `PatternAssessment`), this CDI error appears and is easily misattributed to the record change. Knowing it's pre-existing saves hours of false-trail debugging.
