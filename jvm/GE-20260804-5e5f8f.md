### Symptom
Implementing a test double for `CurrentPrincipal` with `actorId()`, `tenancyId()`, and `isCrossTenantAdmin()` compiles but fails at link time with "does not override abstract method groups()". Adding `groups()` then fails with "does not override abstract method roles()".

### Context
Writing unit tests for bridge modules that inject `CurrentPrincipal`. The interface is in `casehub-platform-api` (a compiled JAR — no source navigable in the IDE without decompilation).

### Fix
A complete test double requires all five abstract methods:

```java
tools.currentPrincipal = new CurrentPrincipal() {
    @Override public String tenancyId() { return "test-tenant"; }
    @Override public String actorId() { return "test-actor"; }
    @Override public boolean isCrossTenantAdmin() { return false; }
    @Override public java.util.Set<String> groups() { return java.util.Set.of(); }
    @Override public java.util.Set<String> roles() { return java.util.Set.of(); }
};
```

### Why this is non-obvious
The interface name `CurrentPrincipal` suggests identity — actor ID and tenant. The abstract methods `groups()` and `roles()` are authorization-related methods that aren't suggested by the name. Without IDE source navigation into the JAR, the only way to discover them is via compilation errors (one at a time, since the compiler reports one missing method per attempt).
