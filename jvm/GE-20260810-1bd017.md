## Maven reactor module gap causes invisible CI failure

### Symptom
CI compilation fails with `cannot find symbol` on methods that clearly exist in the source code. Local builds pass without issue. The error references a method in a module that compiles and installs locally.

### Context
A multi-module Maven project deploys SNAPSHOTs to GitHub Packages via CI. A module (`casehub-engine-queue`) existed as a directory with a valid `pom.xml` but was never added to the parent pom's `<modules>` list. It was deployed manually once and never again.

### What was tried (didn't work)
- Checking the method exists in the source — it does
- Checking the local `.m2` jar — method is present
- Rebuilding locally — passes every time

### Root cause
The module is not in the reactor, so CI's `mvn deploy` never publishes it. GitHub Packages serves a weeks-old SNAPSHOT. Local builds work because `mvn install` puts the current code into `~/.m2`. The disconnect between local `.m2` (current) and remote repository (stale) is invisible.

### Fix
1. Always verify new modules are added to the parent pom `<modules>` list
2. Detection: compare the timestamp in the local `.m2` jar with the GitHub Packages metadata timestamp — if the remote is significantly older, the module may not be in the reactor
3. Check CI deploy logs for the module name — if absent from the upload log, it's not in the reactor

```xml
<!-- Parent pom.xml — the module MUST be listed here -->
<modules>
    <module>api</module>
    <module>queue</module>  <!-- Was missing — module existed but wasn't deployed -->
    <module>rest</module>
</modules>
```

### Why this is non-obvious
Local `mvn install` populates `~/.m2` from the source tree regardless of reactor membership. The developer never sees a failure because Maven resolves the dependency from the local repository. Only CI — which pulls from the remote repository — sees the stale artifact. The error message (`cannot find symbol`) points at the consuming module, not the missing reactor entry.

### Alternatives considered
- Checking if the method was recently added (it was, but the real issue is the module not being deployed)
- Checking if CI was pulling the right version (it was — the latest SNAPSHOT, which happened to be months old)
