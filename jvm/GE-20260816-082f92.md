### Symptom
`MAPPER.convertValue(schemaBinding.getSignal(), Map.class)` returns `{}` even though the YAML has nested content under the `signal:` key.

### Context
JSON schema defines a property as `type: object` with `additionalProperties: true`. jsonschema2pojo generates a Java class for it, but the class has no `@JsonAnySetter` annotation and no map field to capture the additional properties. The class is effectively empty — no fields, no accessors beyond toString/equals/hashCode.

When Jackson deserializes YAML into this generated type, the additional properties are silently dropped (no error, no warning — `FAIL_ON_UNKNOWN_PROPERTIES` is typically disabled for schema classes). Converting the populated-but-empty generated object back to a `Map` via `convertValue` naturally returns `{}`.

### What was tried (didn't work)
- `MAPPER.convertValue(generatedType, Map.class)` — returns empty map
- Checking the generated class source — confirmed no `@JsonAnySetter`, no additional properties map

### Root cause
jsonschema2pojo does not generate `@JsonAnySetter`/`@JsonAnyGetter` for `additionalProperties: true` on named schema types. The generated class is a hollow shell that satisfies the Java type system but drops all dynamic content.

### Fix
Read the free-form field directly from the raw `JsonNode` (parsed from the YAML tree via `ObjectMapper.readTree()`) instead of going through the generated schema type:

```java
JsonNode signalNode = rawBindingNode != null ? rawBindingNode.get("signal") : null;
Map<String, Object> signalPayload = MAPPER.convertValue(signalNode, Map.class);
```

The raw `JsonNode` preserves all nested content regardless of the generated type's limitations.

### Why this is non-obvious
The failure is completely silent. The generated class compiles, Jackson deserializes without error, and `convertValue` returns a valid (but empty) map. No exception, no warning, no log. The only symptom is missing data downstream.
