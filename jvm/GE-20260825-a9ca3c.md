## Symptom

Clicking "run to" on a scenario step runs through the entire scenario without pausing at the target. The orchestrator sets `runToTarget` but `onStepResult` never matches it — the target is never reached according to the code, even though the step clearly executes.

## Context

Scenario steps in the YAML have two identity fields:

```yaml
- label: "Spotlight the intake form"   # display text (shown in outline)
  name: spotlight-form                  # internal ID (used for triggers)
```

The controller UI sends `runTo({ label: "Spotlight the intake form" })`. The orchestrator sets `runToTarget = "Spotlight the intake form"`.

When the step completes, the executor sends back `stepName: "spotlight-form"` (the `name` field, not the `label`). Serialization uses `step.name() != null ? step.name() : step.label()`.

## What was tried

Debugging the orchestrator's `onStepResult` — the comparison `runToTarget.equals(result.stepName())` always returned false because it compared `"Spotlight the intake form"` with `"spotlight-form"`.

## Root cause

`runTo` sets the target by `label` (from the UI). `onStepResult` matches by `stepName` (which serializes as `name`). When steps have both `name` and `label` with different values — which is the common case — the match always fails.

## Fix

Add a `resolveLabel()` method that maps `stepName` back to `label`:

```java
private String resolveLabel(String stepName) {
    if (allSteps == null) return stepName;
    for (var step : allSteps) {
        String name = step.name() != null ? step.name() : step.label();
        if (name.equals(stepName)) return step.label();
    }
    return stepName;
}
```

Then match against both:

```java
String stepLabel = resolveLabel(result.stepName());
if (runToTarget != null && (runToTarget.equals(result.stepName()) || runToTarget.equals(stepLabel))) {
```

### Why this is non-obvious

Steps that only have a `label` (no `name`) work fine — the serialization falls back to `label` and the match succeeds. The bug only appears when steps define both `name` and `label`, which is the recommended pattern for scenarios with trigger chains (triggers reference by `name`, UI displays by `label`).
