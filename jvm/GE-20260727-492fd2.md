### Symptom
SnakeYAML throws a parse error when a flow sequence contains a `${param}` placeholder:
```
while parsing a flow sequence
 in 'reader', line N, column M:
    ganglia: [${ganglionId}]
                 ^
expected ',' or ']', but got {
```

### Context
Occurs when building YAML-based templating with parameter placeholders like `${param}`.
Flow sequences (`[value1, value2]`) are valid YAML — but `${` inside a flow context
triggers YAML's flow mapping indicator (`{`), causing a parse error before your
application code ever sees the placeholder.

Scalar positions are unaffected: `ganglionId: ${param}` works because `${` outside
a flow context is treated as plain text.

### Root cause
YAML spec: inside a flow sequence `[...]`, the `{` character is a reserved flow
indicator that starts a flow mapping. SnakeYAML correctly rejects `${param}` inside
`[...]` because it sees `{` as mapping syntax, not as part of a string.

### Fix
Use block sequence form instead of flow sequences when values contain `${`:

```yaml
# Fails — flow sequence + ${ = parse error
chainMode:
  ganglia: [${ganglionId}]

# Works — block sequence, no flow context
chainMode:
  ganglia:
    - ${ganglionId}
```

### Why this is non-obvious
The error message points at `{` and says "expected ',' or ']'" — which makes it look
like a syntax error in your placeholder. The actual cause is a YAML spec rule about
flow indicators, not a problem with the placeholder itself. Developers familiar with
`${...}` from shell or Spring will not expect YAML to treat `{` specially only inside
`[...]` brackets.
