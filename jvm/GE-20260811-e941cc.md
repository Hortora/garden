### Symptom

Compile error when trying to pass an `AgentDisposition` to `DispositionAwareRouting` — types don't match despite both representing agent personality/disposition.

### Context

Two disposition types exist in the CaseHub platform:

1. **`AgentDisposition`** (in `casehub-eidos-api`, `io.casehub.eidos.api`) — uses Builder pattern with per-axis methods:
   ```java
   AgentDisposition.builder()
       .riskAppetite("aggressive")
       .ruleFollowing("moderate")
       .socialOrient("independent")
       .build();
   ```
   Internally stores `List<DispositionValue>` per axis. Attached to `AgentDescriptor`.

2. **`DispositionProfile`** (in `casehub-blocks`, `io.casehub.blocks.routing.agent`) — uses `Map<DispositionAxis, String>`:
   ```java
   new DispositionProfile(Map.of(
       DispositionAxis.RISK_APPETITE, "aggressive",
       DispositionAxis.RULE_FOLLOWING, "moderate"
   ));
   ```
   Used by `DispositionAwareRouting` for routing decisions.

### Root cause

The two types evolved independently in different modules. `AgentDescriptor` (eidos) carries `AgentDisposition` as the identity declaration. `DispositionAwareRouting` (blocks) operates on `DispositionProfile` as the routing signal. No built-in conversion exists between them.

### Fix

When building routing, extract values from `AgentDisposition` to construct a `DispositionProfile`:

```java
var disposition = descriptor.disposition();
var profile = new DispositionProfile(Map.of(
    DispositionAxis.RISK_APPETITE, disposition.primaryTerm(DispositionAxis.RISK_APPETITE),
    DispositionAxis.RULE_FOLLOWING, disposition.primaryTerm(DispositionAxis.RULE_FOLLOWING)
    // ... for each axis that has a value
));
```

Use `AgentDisposition.primaryTerm(axis)` to get the first `DispositionValue.term()` for each axis.

### Why this is non-obvious

Both types deal with "disposition" and use the same `DispositionAxis` enum. A developer seeing `DispositionAwareRouting` and `AgentDescriptor.disposition()` would naturally expect them to use the same type. The split between eidos (identity) and blocks (routing) is an internal module boundary that isn't visible from the API surface.
