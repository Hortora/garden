### Summary

`ReconciliationLoop` has no `status(key)` method. To check whether a loop is active for a given composite key, use `getDesired(key)` — returns `null` if no loop exists, or the current `DesiredStateGraph` if active.

### Context

When building REST endpoints that expose reconciliation state per cluster, the natural API call would be `reconciliationLoop.status(compositeKey)`. This method does not exist.

### What was tried

Searched for `status()` on `ReconciliationLoop` — not found. The public API includes: `start`, `stop`, `updateDesired`, `requestReconciliation`, `getDesired`, `compareAndSetDesired`, `setListener`.

### Root cause

The loop is event-driven — it doesn't maintain a separate status enum. Activity is determined by graph presence.

### Fix

```java
var desired = reconciliationLoop.getDesired(key);
boolean active = desired != null;
int nodeCount = active ? desired.nodes().size() : 0;
```

### Why this is non-obvious

The class has 15+ public methods. Without reading the source, you'd expect a `status()` or `isActive()` method to exist alongside `start()`/`stop()`.
