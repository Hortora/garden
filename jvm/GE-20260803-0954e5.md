### Symptom

`PlanItemStateChangedEvent` in `engine.common.spi.event` fails to compile with `cannot find symbol: class TaskStatus` when importing `TaskStatus` from `engine.common.internal.model`.

### Context

The engine uses a clear package boundary: `spi` packages are public API, `internal` packages are engine-private. CDI events in the SPI layer are observed by application modules (devtown, clinical, etc.). `TaskStatus` is an enum in the internal model package — not part of the public API.

### Fix

Use `String`-typed fields in the CDI event record, converting at publish and observe time:

```java
// Event record (SPI — no internal imports)
public record PlanItemStateChangedEvent(
    UUID caseId, String planItemId, String bindingName,
    String previousStatus, String newStatus, String tenancyId) {}

// Publisher (internal — has access to TaskStatus)
planItemStateChangedEvents.fireAsync(new PlanItemStateChangedEvent(
    caseId, planItemId, bindingName,
    item.getStatus().name(), TaskStatus.COMPLETED.name(), tenancyId));

// Observer (application — filters on String)
void onChanged(@ObservesAsync PlanItemStateChangedEvent event) {
    if (!"COMPLETED".equals(event.newStatus())) return;
    // handle completion
}
```

### Why this is non-obvious

The natural design puts the enum on the event for type safety. The compilation error only surfaces when the event is placed in the SPI package — during initial development in the same module, the internal import works fine. The fix trades compile-time type safety for correct package boundaries, which is the right trade in a multi-module platform where SPI stability matters more than internal convenience.
