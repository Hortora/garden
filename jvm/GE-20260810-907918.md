## Symptom

Adding `casehub-blocks` as a Maven dependency to a CaseHub app causes a build-time CDI failure:

```
AmbiguousResolutionException: Ambiguous dependencies for type
  io.casehub.api.spi.routing.AgentRoutingStrategy and qualifiers [@Default]
- injection target: parameter 'agentRoutingStrategy' of
  io.casehub.engine.internal.orchestration.DefaultWorkOrchestrator constructor
- available beans:
  - CbrAgentRoutingStrategy
  - ComposableAgentRoutingStrategy
  - LlmAgentRoutingStrategy
```

## Context

When blocks' Jandex index is configured (`quarkus.index-dependency.casehub-blocks`), Quarkus discovers `CbrAgentRoutingStrategy` and `LlmAgentRoutingStrategy` as `@ApplicationScoped` CDI beans. Both implement `AgentRoutingStrategy`. The engine's `DefaultWorkOrchestrator` injects a single `AgentRoutingStrategy` as the default — three beans now satisfy that injection point.

## What was tried (didn't work)

- Not indexing blocks — but then blocks' CDI beans (ChannelSummariser, etc.) aren't discovered either
- Looking for `@Alternative` or `@Priority` on blocks strategies — they have none

## Root cause

`LlmAgentRoutingStrategy` and `CbrAgentRoutingStrategy` implement both `AgentRoutingStrategy` (the engine's routing SPI) and `NamedStrategy` (the composable routing name-based resolution interface). They're designed to be resolved by name via `StrategyResolver` (e.g. `"llm"`, `"cbr"`), not injected as the default `AgentRoutingStrategy`. But CDI doesn't know this — all three beans are valid `@Default` candidates.

## Fix

Exclude the blocks routing strategies from CDI bean discovery via `application.properties`:

```properties
quarkus.arc.exclude-types=io.casehub.blocks.routing.agent.CbrAgentRoutingStrategy,io.casehub.blocks.routing.agent.LlmAgentRoutingStrategy
```

This leaves `ComposableAgentRoutingStrategy` as the sole default `AgentRoutingStrategy`. The blocks strategies remain available as `NamedStrategy` beans resolved by `StrategyResolver` at routing time — they don't need default CDI injection.

## Why this is non-obvious

The blocks consumer guide documents the Jandex indexing requirement but does not mention the routing strategy exclusion. The error only manifests when both blocks AND engine are on the classpath — blocks alone or engine alone work fine. The fix requires understanding that blocks routing strategies are `NamedStrategy` beans (resolved by name) not default injection candidates.

### Alternatives considered

- Adding `@Alternative` to blocks routing strategies — would fix the ambiguity but prevent `StrategyResolver` from discovering them
- Not using Jandex indexing for blocks — loses all blocks CDI beans, not just the routing strategies
- Using `@Priority` on `ComposableAgentRoutingStrategy` — engine-side fix, correct but requires engine change
