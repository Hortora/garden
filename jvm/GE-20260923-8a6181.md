### Symptom
Quarkus build fails at `ArcProcessor#generateResources` with:
```
DeploymentException: No template found for path [auditTrail]
  - available templates: [reports/audit-trail.html, reports/compliance-art12.html]
```

### Context
When injecting Qute templates via `@Inject Template <fieldName>`, Quarkus
resolves the template path from the field name. `@Inject Template auditTrail`
looks for a template at path `auditTrail` (or `auditTrail.html`). If the
template lives in a subdirectory (`templates/reports/audit-trail.html`) or
uses hyphens in the filename, the field name cannot match.

### Root cause
Qute's CDI injection resolves the template path using the Java field name as
a convention. Java identifiers cannot contain hyphens or path separators, so
field names like `auditTrail` cannot map to paths like `reports/audit-trail`.

### Fix
Use the `@Location` qualifier to specify the full template path:
```java
@Inject
@io.quarkus.qute.Location("reports/audit-trail")
Template auditTrail;
```
The `.html` extension is optional in the `@Location` value.

### Why this is non-obvious
The Qute docs show `@Inject Template` examples with simple names (`hello`,
`item`). Subdirectory layouts are common for organising templates by feature
(e.g. `reports/`, `emails/`), but the field-name convention silently fails
— you only discover the problem at build time via the deployment exception.
