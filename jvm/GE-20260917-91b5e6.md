### Context
Multi-repo Maven ecosystems where each repo is independently buildable. Need to detect circular repo entry — situations where repo A can't build without repo B's artifacts, and vice versa — without running Maven.

### Technique
Parse `pom.xml` files directly with Python's `xml.etree.ElementTree`. Key design decisions:

1. **Scan `<dependencies>` only, not `<dependencyManagement>`** — `dependencyManagement` sets versions but doesn't create build-time dependencies. Use XPath `{NS}dependencies/{NS}dependency` which only matches direct children of `<project>`, not nested inside `<dependencyManagement>`.

2. **Also scan profile dependencies** — `{NS}profiles/{NS}profile/{NS}dependencies/{NS}dependency` catches profile-activated cross-repo deps.

3. **Build artifact→repo mapping by scanning all module pom.xml files** — `rglob('pom.xml')` with exclusions for `target/`, `.git/`, `.claude/`, `src/`, `node_modules/`. Each module's `<artifactId>` is mapped to its owning repo.

4. **Filter to shared groupId** — only check `io.casehub` (or your org's groupId) dependencies. Third-party deps are irrelevant for repo-level cycles.

5. **DFS cycle detection on the repo graph** — standard visited/recursion-stack DFS. Deduplicate cycles by normalizing to frozenset of edge pairs.

6. **Report with evidence** — for each cycle edge, show the specific module and artifact creating it, with scope.

### Why this is non-obvious
The natural instinct is to use `mvn dependency:tree` for dependency analysis. But for repo-level cycle detection, direct pom.xml parsing is both sufficient and faster — you don't need transitive resolution because repo-level edges are determined by direct declarations. A dependency A→B→C creates repo edges A→repoB, B→repoC — both are visible from pom.xml without resolving B's tree.

Skipping `<dependencyManagement>` is the critical insight. Many multi-repo setups declare cross-repo artifacts in `<dependencyManagement>` for version pinning without creating actual dependencies. Including them produces false positives.
