## Symptom

A downstream module fails to compile with `cannot find symbol` errors for classes that should be available as transitive dependencies. The upstream module compiles and tests fine. The missing classes are deep transitives (e.g. `io.casehub.ledger.model.CaseLedgerEntry` from a 3rd-level transitive).

Maven logs show: `The POM for <artifact>:jar:0.2-SNAPSHOT is invalid, transitive dependencies (if any) will not be available: N problems were encountered`

## Context

Multi-module Maven project with SNAPSHOT versions. Module A declares dependencies without explicit `<version>` — they inherit from the parent `<dependencyManagement>`. Module B depends on Module A.

When Module A is compiled in a reactor build (`mvn compile -pl moduleA`), the parent's `<dependencyManagement>` resolves versions correctly. But when Module B resolves Module A from `~/.m2/repository/` (the installed POM), the POM is "invalid" if:

1. Module A was last `mvn install`ed before certain dependencies were added to the parent's `<dependencyManagement>`
2. Or the parent POM in `~/.m2` is stale

## What was tried (didn't work)

1. Checking if the dependency was excluded — it wasn't
2. Checking if the jar was in `~/.m2` — it was, with the correct classes
3. Running `mvn dependency:tree` on the downstream module — showed the upstream module but NO transitives, with the "POM is invalid" warning buried in output

## Root cause

Maven's dependency resolution has two modes:

- **Reactor build**: resolves sibling modules from the project model (in-memory). Parent `<dependencyManagement>` is always available. Works fine.
- **Installed POM resolution**: reads the POM from `~/.m2/repository/`. If the POM references `${property}` version variables that are defined in the parent, and the **installed parent POM is stale**, the version references are unresolvable. Maven declares the POM "invalid" and **silently drops all transitives**.

The symptom (missing deep transitive classes) is far from the root cause (stale parent POM version properties).

## Fix

Re-install the affected modules to refresh the POMs in `~/.m2`:

```bash
mvn install -DskipTests -pl core,casehub,testing
```

This writes fresh POMs with resolved version properties from the current parent `<dependencyManagement>`.

**Prevention**: Always run `mvn install` after adding new dependencies to the parent `<dependencyManagement>` — the reactor build will work without it, but downstream modules consuming the installed POM will silently lose transitives.

## Why this is non-obvious

1. The reactor build works perfectly — the problem only appears when resolving from `~/.m2`
2. The "POM is invalid" warning is printed as a `[WARNING]`, easily lost in Maven's verbose output
3. The symptom (missing classes from deep transitives) gives no indication that the problem is in the sibling module's POM, not the dependency itself
4. `dependency:tree` shows the upstream module present but silently omits its entire transitive tree — easy to miss unless you know what should be there
