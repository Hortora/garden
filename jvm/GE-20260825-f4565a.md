### Symptom

Calling `setMixIn()` on a `SimpleModule` subclass fails to compile — the method does not exist on `SimpleModule`.

### Context

When building a Jackson `Module` that needs to register mixins (e.g. `@JsonIgnoreProperties`, `@JsonProperty` name mappings) for types without polluting those types with annotations.

### Root cause

`SimpleModule` only provides `addSerializer`, `addDeserializer`, and related registration methods. Mixin registration is on `Module.SetupContext`, not on `SimpleModule` directly. The API surface makes it look like `setMixIn` should be a peer of `addDeserializer`, but it's a different registration mechanism.

### Fix

Override `setupModule` and use the `SetupContext`:

```java
public class MyModule extends SimpleModule {
    @Override
    public void setupModule(SetupContext context) {
        super.setupModule(context);
        context.setMixInAnnotations(TargetType.class, MixinType.class);
    }
}
```

### Why this is non-obvious

The `SimpleModule` API implies a fluent registration pattern where everything goes in the constructor. Mixins break this pattern — they require a callback-based registration via `setupModule`. The Jackson docs don't emphasize this distinction.
