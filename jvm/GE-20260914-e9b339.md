## Symptom

Quarkus augmentation fails with:

```
DeploymentException: It's not possible to automatically add a synthetic
no-args constructor to an unproxyable bean class. You need to manually
add a non-private no-args constructor to com.example.MyService
```

The class is produced by a `@Produces @ApplicationScoped` method in a CDI producer class. Adding `com.example.MyService` to `quarkus.arc.exclude-types` has no effect — the error persists.

## Context

Occurs when:
1. A CDI producer class has a `@Produces @ApplicationScoped` method
2. The produced type has only parameterized constructors (no no-args)
3. The produced type has `final` fields (preventing synthetic constructor generation)

`@ApplicationScoped` is a normal scope — Quarkus must create a client proxy, which requires a no-args constructor. `@Singleton` is a pseudo-scope that doesn't require proxying.

## What was tried (didn't work)

1. `quarkus.arc.exclude-types=com.example.MyService` — has no effect because `exclude-types` filters **class-level bean discovery**, not **producer method outputs**. The produced bean is registered by the producer, not by class scanning.
2. Making the no-args constructor `private` — Quarkus can't use private constructors for proxy generation.

## Root cause

`quarkus.arc.exclude-types` operates at the bean-class discovery phase. Producer methods register beans through a different mechanism — the produced type is never "discovered" as a bean class, so excluding it has no effect. The producer class itself must be excluded to prevent all its `@Produces` methods from firing.

## Fix

Change the producer method scope from `@ApplicationScoped` to `@Singleton`:

```java
// Before — fails if MyService has final fields and no no-args constructor
@Produces
@ApplicationScoped
public MyService myService(Config config) {
    return new MyService(config.value());
}

// After — @Singleton doesn't require proxying
@Produces
@jakarta.inject.Singleton
public MyService myService(Config config) {
    return new MyService(config.value());
}
```

If you don't control the producer (it's in a dependency jar), exclude the **producer class** instead of the produced type:

```properties
# Excludes ALL beans produced by this class
quarkus.arc.exclude-types=com.example.lib.MyServiceProducer
```

But this cascades — everything the producer creates disappears. If other beans depend on those produced types, they'll have unsatisfied dependencies.

### Why this fix

`@Singleton` and `@ApplicationScoped` are both "one instance per app" scopes, but `@ApplicationScoped` requires a client proxy (lazy initialization, circular dependency support) while `@Singleton` is eagerly created without a proxy. For produced beans with no special lifecycle needs, `@Singleton` is functionally equivalent and avoids the unproxyable constraint entirely.

## Why this is non-obvious

The error message says "add a non-private no-args constructor" — which is correct but misleading when you don't control the class (it's in a library jar). The natural next step is `exclude-types`, which silently does nothing because the bean isn't class-discovered. The connection between producer scope and proxy requirements isn't surfaced in the error.

### Alternatives considered

- Adding a no-args constructor to the produced type — not possible when the class is in a dependency jar
- `quarkus.arc.transform-unproxyable-classes=true` — Quarkus attempts this by default but fails when fields are `final`
- Excluding the produced type via `exclude-types` — doesn't work (root cause above)
