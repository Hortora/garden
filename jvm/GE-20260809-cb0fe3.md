## Maven slot .m2 repo isolation — mvn install to host repo does not reach slot engine

**Symptom:** `cannot find symbol` for a class that exists in the host `~/.m2/repository` JAR. The class was just added and `mvn install` completed successfully, but the consuming module in a slot still can't resolve it.

**Context:** casehub slots each have their own `.m2` at `/path/to/slot/.m2`. The slot's `slot-settings.xml` configures the host `~/.m2/repository` as a **remote** file:// repository (not the local repo). When you run `mvn install` from the source repo, it installs to the host `.m2`. But the slot engine's `localRepository` points to the slot `.m2` — a completely separate directory.

### What was tried (didn't work)

- `mvn install -DskipTests` from the source repo — installs to host `.m2` only
- `mvn test -o` (offline) in the slot — still resolves from slot `.m2`
- Removing remote metadata files (`maven-metadata-github.xml`) — doesn't help because the SNAPSHOT JAR itself is missing from the slot `.m2`
- `-nsu` flag — prevents checking remote updates but doesn't redirect the local repo

### Root cause

`mvn help:effective-settings` in the slot reveals `<localRepository>/path/to/slot/.m2</localRepository>`. The host `.m2` is configured as a remote repository via `file://` URL in `slot-settings.xml`, with `updatePolicy: always` for snapshots. Maven treats it as a remote — it downloads from it but does not treat it as the local install target.

### Fix

Install to the slot's `.m2` explicitly:

```bash
mvn -f /path/to/source/pom.xml install -DskipTests -q -Dmaven.repo.local=/path/to/slot/.m2
```

### Why this is non-obvious

`mvn install` normally puts artifacts where all local projects can find them. The slot system's separate `.m2` breaks this assumption — the host repo looks like "local" but is actually "remote" from the slot's perspective. The error message gives no hint about repository isolation.
