## Symptom

Adding a new `@McpDomain` class with `@PlatformQuery`/`@PlatformMutation` methods compiles and deploys without errors. The MCP tools register correctly. But all REST requests to the `basePath` return **404**. No error in logs, no deployment warning.

## Context

The `GraphQLResolverProcessor` annotation processor generates JAX-RS resource classes from `@McpDomain` beans at compile time. The generated class (e.g. `ClaudonyPoolsResource.java`) appears in `target/generated-sources/annotations/` and delegates to the `@ApplicationScoped` bean.

The processor is configured in `pom.xml` via `<annotationProcessorPaths>` and takes a compiler arg:

```xml
<compilerArgs>
  <arg>-AdomainFilter=claudony/sessions,claudony/mesh,claudony/cases,claudony/peers</arg>
</compilerArgs>
```

This **whitelist** controls which `@McpDomain` values get REST routes generated. Any domain not in the list is silently skipped — no warning, no error, no log.

## What was tried (didn't work)

1. Clean compile (`mvn clean compile`) — no change, still 404
2. Checking Quarkus deployment extensions — no `McpDomainProcessor` on classpath
3. Checking if the `@McpDomain` annotation had JAX-RS meta-annotations — it doesn't
4. Checking `casehub-platform-mcp-core` and `casehub-platform-endpoints-config` — these handle MCP tool registration, not REST route generation

## Root cause

The `GraphQLResolverProcessor` (in `casehub-platform-graphql-generator`) filters domains via the `-AdomainFilter` compiler arg. New `@McpDomain` classes are not included in the filter by default. The processor silently skips domains not in the filter — no generated JAX-RS resource class, no REST routes.

## Fix

Add the new domain to the `-AdomainFilter` compiler arg in the app module's `pom.xml`:

```xml
<arg>-AdomainFilter=claudony/sessions,claudony/mesh,claudony/cases,claudony/peers,claudony/pools</arg>
```

After adding, run `mvn clean compile` to trigger the annotation processor. Verify the generated resource exists:

```bash
ls target/generated-sources/annotations/io/casehub/claudony/server/rest/
# Should now include ClaudonyPoolsResource.java
```

## Why this is non-obvious

1. The `@McpDomain` annotation's javadoc says nothing about a filter
2. MCP tool registration works fine — the domain appears in MCP tool lists — only REST is missing
3. The filter is a compiler arg in `pom.xml`, not in any Java annotation or property file
4. No error or warning is produced when a domain is filtered out
5. The generated source file simply doesn't exist — there's nothing to debug

### Why this fix

The domainFilter exists to prevent the processor from generating REST resources for domains that aren't intended to be exposed (e.g. library domains consumed only via MCP). The fix is mechanical — add the domain to the list. The alternative (removing the filter entirely) would expose every `@McpDomain` class as REST, which may not be desired.

### Alternatives considered

- Checked for a Quarkus deployment extension (`@BuildStep`) that might process `@McpDomain` — none exists for REST generation
- Checked `casehub-platform-endpoints-config` — it loads YAML endpoint definitions, not annotation-based ones
- Considered whether the platform-mcp module's `DomainResourceRegistrar` generates REST — it registers MCP resources only
