### Symptom
Need to verify that a `@McpDomain` resolver is correctly wired for the platform MCP scanner (`GraphQLModelScanner`) and dispatcher (`ReflectiveOperationDispatcher`) — but `@QuarkusTest` requires the full CDI graph (EventBroadcaster, SessionSender, etc.) and takes ~10 seconds to boot.

### Context
The platform MCP uses `GraphQLModelScanner` (scans `@McpDomain` + `@GraphQLApi` beans for `@Query`/`@Mutation` methods) and `ReflectiveOperationDispatcher` (invokes resolver methods via `Method.invoke()` with Jackson param deserialization). Both use `Arc.container()` / `CDI.current()` — requiring a running CDI container.

### What was tried (didn't work)
- `@QuarkusTest` — works but requires wiring the entire CDI dependency graph (EventBroadcaster needs EventStore, TopicRegistry, SessionSender, JsonWriter). Heavy setup for what's essentially "are the annotations right?"

### Root cause
The scanner and dispatcher are mechanically simple — they scan annotations and invoke methods via reflection. The CDI dependency is for bean lookup, not for the scanning/dispatch logic itself.

### Fix
Replicate the scanner's logic in a test utility — scan the resolver class directly:

```java
private static List<OperationDescriptor> scanOperations(Class<?> resolverClass) {
    List<OperationDescriptor> ops = new ArrayList<>();
    for (Method method : resolverClass.getDeclaredMethods()) {
        if (Modifier.isStatic(method.getModifiers())) continue;
        Query query = method.getAnnotation(Query.class);
        Mutation mutation = method.getAnnotation(Mutation.class);
        if (query != null || mutation != null) {
            String name = query != null
                ? (query.value().isEmpty() ? method.getName() : query.value())
                : (mutation.value().isEmpty() ? method.getName() : mutation.value());
            var type = query != null
                ? OperationDescriptor.OperationType.QUERY
                : OperationDescriptor.OperationType.MUTATION;
            List<ParameterDescriptor> params = new ArrayList<>();
            for (Parameter p : method.getParameters()) {
                params.add(new ParameterDescriptor(p.getName(), p.getType().getSimpleName(), true));
            }
            ops.add(new OperationDescriptor(name, type, "", params,
                method.getReturnType().getSimpleName(), method, resolverClass));
        }
    }
    return ops;
}
```

Then dispatch via reflection — same as `ReflectiveOperationDispatcher`:

```java
Method method = op.method();
Parameter[] methodParams = method.getParameters();
Object[] args = new Object[methodParams.length];
ObjectMapper mapper = new ObjectMapper();
for (int i = 0; i < methodParams.length; i++) {
    Object rawValue = params.get(methodParams[i].getName());
    if (rawValue != null) {
        args[i] = mapper.convertValue(rawValue, methodParams[i].getType());
    }
}
Object result = method.invoke(resolverInstance, args);
```

Manual `@Inject` field injection via `setAccessible(true)` for the bridge dependency.

This proves: (1) annotations are discoverable, (2) operation names and parameter types are correct, (3) reflective dispatch works, (4) Jackson can deserialize nested types (e.g. `AriaTarget` within-scoping from `Map<String, Object>`).

### Why this is non-obvious
The natural instinct is `@QuarkusTest` — it's the standard approach for CDI beans. But the MCP dispatch chain is purely mechanical (annotations + reflection + Jackson) and doesn't need CDI for validation. The reflective test runs in <1 second vs ~10 seconds for Quarkus startup, and avoids the fragile CDI wiring that changes whenever the dependency graph evolves.
