## Problem

A service aggregates data from an external system that may be:
- **Absent** — the external system is not configured (graceful degradation)
- **Remote** — accessible via REST API (different JVM)
- **Co-located** — on the classpath with direct store access (same JVM)

Hardcoding one mode forces a deployment topology decision at compile time.

## Pattern

Define a query SPI that returns a caller-owned DTO. Three CDI implementations at different priority tiers activate based on what's available:

```
Tier 0: @DefaultBean       → EmptyXxxSource     (returns empty — always active as fallback)
Tier 1: @ApplicationScoped → RestXxxSource       (calls external REST API — active when URL configured)
Tier 2: @Alternative(1)    → EmbeddedXxxSource   (injects store directly — active when module on classpath)
```

The caller (aggregation service) owns all interpretation logic — urgency mapping, action construction, filtering. The SPI implementations only handle data retrieval and DTO mapping.

## Key design constraint

The SPI returns a **caller-owned DTO** (e.g. `WorkItemView`), not the external system's domain types. This keeps interpretation logic (urgency rules, action URLs) in one place — the aggregation service — rather than duplicated across each tier implementation.

## Structure

```java
// SPI interface
public interface WorkItemActionSource {
    List<WorkItemView> findActionableItems(String tenancyId);
}

// Tier 0 — always available
@DefaultBean @ApplicationScoped
public class EmptyWorkItemActionSource implements WorkItemActionSource {
    public List<WorkItemView> findActionableItems(String t) { return List.of(); }
}

// Tier 1 — REST client (active when URL configured)
@ApplicationScoped
public class RestWorkItemActionSource implements WorkItemActionSource {
    @Inject @RestClient WorkServiceClient client;
    @Inject @ConfigProperty(name = "work.url") Optional<String> baseUrl;
    // Maps REST response → WorkItemView
}

// Tier 2 — embedded (active when module on classpath)
@Alternative @Priority(1) @ApplicationScoped
public class EmbeddedWorkItemActionSource implements WorkItemActionSource {
    @Inject WorkItemStore store;
    // Maps JPA entity → WorkItemView
}

// Consumer — owns all interpretation
@ApplicationScoped
public class ActionAggregationService {
    @Inject WorkItemActionSource source;  // CDI selects highest-priority active tier
    // Urgency mapping, action construction, sorting — all here
}
```

## Why this works

- **CDI does the routing** — no if/else topology detection code
- **Graceful degradation** — Tier 0 means the consumer works even without the external system
- **Single source of truth for interpretation** — urgency rules tested once in the aggregation service
- **Topology-transparent consumers** — the aggregation service doesn't know or care which tier is active
