## APT code generators produce outputs for all indexed interfaces on classpath — need explicit domain filtering

**ID:** GE-20260914-3854b8
**Stack:** Jandex 3.x, javax.annotation.processing, Maven multi-module
**Symptom:** Generated REST/GraphQL endpoints appear for domains owned by other modules. The consuming module's `target/generated-sources/` contains classes for interfaces it doesn't implement, causing compilation errors or JAX-RS path conflicts at runtime.
**Context:** When a code-generating APT (like `graphql-generator`) is added to a module's `annotationProcessorPaths`, it reads Jandex indexes from ALL JARs on the processor classpath. If `platform-api` contains `@McpDomain` interfaces for multiple domains (e.g. `callbacks`, `delivery-channels`, `digest`), every consuming module generates endpoints for ALL of them — not just the ones it implements.

### What was tried (didn't work)
- Expected the APT to only generate for interfaces the module implements — it doesn't; the APT scans annotations, not implementation relationships
- Tried removing non-relevant dependencies from `annotationProcessorPaths` — not possible; the shared `platform-api` JAR contains all SPI interfaces in one Jandex index

### Root cause
`annotationProcessorPaths` includes the full dependency tree. `Jandex.CompositeIndex.create()` merges all discovered indexes into one flat view. The APT's annotation scan (`index.getAnnotations(MCP_DOMAIN)`) returns every `@McpDomain` interface across all indexes — it has no concept of "this module's interfaces" vs "other modules' interfaces."

### Fix
Add a processor option that limits generation to explicitly listed domains. The generator checks each domain against the allowed set and skips unlisted ones.

```java
// In the annotation processor
@SupportedOptions({"domainFilter", "generateGraphQL", "generateRest"})
public class GraphQLResolverProcessor extends AbstractProcessor {

    @Override
    public boolean process(...) {
        String domainFilter = processingEnv.getOptions().get("domainFilter");
        Set<String> allowedDomains = domainFilter != null
            ? Arrays.stream(domainFilter.split(","))
                    .map(String::trim)
                    .collect(Collectors.toSet())
            : null; // null = generate all (backward-compatible)

        for (var entry : domains.entrySet()) {
            if (allowedDomains != null && !allowedDomains.contains(entry.getKey())) {
                continue;
            }
            // generate...
        }
    }
}
```

```xml
<!-- In the consuming module's pom.xml -->
<compilerArgs>
    <arg>-AdomainFilter=callbacks</arg>
    <arg>-AgenerateGraphQL=false</arg>
</compilerArgs>
```

### Why this is non-obvious
Single-module projects never hit this — the problem only manifests when multiple modules share the same code-generating APT with a shared SPI dependency. The default behaviour (generate for everything) is correct for the single-module case and silently wrong for multi-module. The whitespace-in-comma-separated-values edge case (`-AdomainFilter=a, b` produces `" b"` with leading space) adds another subtle failure mode.
