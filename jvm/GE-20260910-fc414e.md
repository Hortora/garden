## Event<T> to Consumer<T> for framework-neutral core extraction

**ID:** GE-20260910-fc414e
**Stack:** CDI 4.0, Spring Boot 3.x, Java 21
**Labels:** `#dual-framework` `#core-extraction` `#event-decoupling`
**What it achieves:** Cleanly decouples business logic from CDI `Event<T>.fireAsync()` so the same POJO works in CDI, Spring, and plain unit tests with zero framework dependencies.
**Context:** When extracting framework-neutral POJO cores from CDI modules, classes that fire CDI events can't directly depend on `jakarta.enterprise.event.Event`. The core must be framework-independent while preserving event semantics.

### The technique
Replace `Event<T>` with `Consumer<T>` constructor parameter. The consumer is nullable — null means "no event system configured" (silent no-op). Framework modules wire it at construction time using method references.

**Core POJO (zero framework deps):**
```java
public class EngagementRecorder {
    private final DeliveryAttemptStore store;
    private final Consumer<EngagementRecorded> eventCallback;

    public EngagementRecorder(DeliveryAttemptStore store,
                              Consumer<EngagementRecorded> eventCallback) {
        this.store = store;
        this.eventCallback = eventCallback;
    }

    public void record(EngagementEvent event) {
        // ... business logic ...
        if (eventCallback != null) {
            eventCallback.accept(new EngagementRecorded(event));
        }
    }
}
```

**Quarkus producer:**
```java
@Produces @ApplicationScoped
public EngagementRecorder engagementRecorder(
        DeliveryAttemptStore store,
        Event<EngagementRecorded> cdiEvent) {
    return new EngagementRecorder(store, cdiEvent::fireAsync);
}
```

**Spring auto-configuration:**
```java
@Bean
public EngagementRecorder engagementRecorder(
        DeliveryAttemptStore store,
        ApplicationEventPublisher publisher) {
    return new EngagementRecorder(store, publisher::publishEvent);
}
```

**Unit test (no framework):**
```java
var events = new ArrayList<EngagementRecorded>();
var recorder = new EngagementRecorder(mockStore, events::add);
// ... assert events captured
```

### Alternatives considered
- Creating an `EventPublisher<T>` interface with CDI and Spring implementations — more ceremony, requires a new interface per event type or a generic one with framework-specific implementations. Consumer<T> achieves the same with zero new types.
- Using `ApplicationEvent` as a common base — ties the core to Spring's event model, defeating the purpose.

### Why this is non-obvious
The obvious approach is to define a framework-neutral event interface and implement it per framework. `Consumer<T>` eliminates that layer entirely — method references (`event::fireAsync`, `publisher::publishEvent`) bridge the gap at construction time. The null-guard pattern naturally handles the "no framework" case without a NoOp implementation class.

### When to use it
Any module extraction where CDI `Event.fire()` or `Event.fireAsync()` needs to become framework-neutral. Not suitable when events need return values, ordering guarantees, or transactional participation — those require a richer callback interface.
