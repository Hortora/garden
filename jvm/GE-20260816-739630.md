### Context
When a YAML schema defines a field as `type: object` with `additionalProperties: true`, jsonschema2pojo generates an empty class that drops all content (see GE-20260816-082f92). You need the raw content but the conversion method only receives the generated schema binding.

### Technique
Thread the raw `JsonNode` (from the initial `ObjectMapper.readTree()` call) alongside the generated schema object to the conversion method. Read free-form fields directly from the raw node:

```java
// At the top level — parse both representations
JsonNode rawNode = objectMapper.readTree(bytes);
SchemaType schema = objectMapper.readValue(bytes, SchemaType.class);

// Pass rawNode alongside schema to conversion methods
convertBinding(schemaBinding, rawBindingNode, capabilityMap, registry, expressionLang);

// Inside the conversion — read free-form field from raw node
JsonNode signalNode = rawBindingNode != null ? rawBindingNode.get("signal") : null;
Map<String, Object> payload = MAPPER.convertValue(signalNode, Map.class);
```

### Why this is non-obvious
The natural approach is to use the generated schema type for everything — it's the typed, validated representation. The idea of maintaining a parallel raw `JsonNode` tree just for free-form fields requires knowing that jsonschema2pojo's `additionalProperties` handling is broken. The technique was already used for `semanticData` in the same codebase but not documented as a general pattern.

### Alternatives considered
- Adding `@JsonAnySetter` to generated classes — requires post-processing the generated source, fragile across regeneration
- Using a custom Jackson deserializer — more code, same result
- Switching to raw `JsonNode` entirely — loses the type safety of the generated schema for structured fields
