### Symptom
Quarkus `@BuildStep` methods in deployment processors (e.g. `scanNodeTypes(IndexView)`)
are hard to unit test. Starting a full `@QuarkusTest` just to verify build-step logic
is slow and couples the test to the full extension lifecycle.

### Context
Deployment processors receive a `CombinedIndexBuildItem` with a Jandex `IndexView`.
The build step scans annotations, checks class hierarchies, and produces build items.
Testing this logic directly requires creating a Jandex index programmatically.

### Fix
Use Jandex's `Indexer` class to create a test index from specific classes:

```java
import org.jboss.jandex.Index;
import org.jboss.jandex.Indexer;

private static Index buildIndex(Class<?>... classes) throws IOException {
    Indexer indexer = new Indexer();
    for (Class<?> cls : classes) {
        indexer.indexClass(cls);
    }
    // Also index annotation and interface classes used in scanning
    indexer.indexClass(NodeTypeId.class);
    indexer.indexClass(NodeSpec.class);
    return indexer.complete();
}

@Test
void discoversAnnotatedClasses() throws IOException {
    Index index = buildIndex(MyAnnotatedClass.class);
    Map<String, String> result = MyProcessor.scanNodeTypes(index);
    assertThat(result).containsEntry("my-type", MyAnnotatedClass.class.getName());
}
```

The build-step method must be static or package-private (not private) for direct
invocation from tests.

### Why this is non-obvious
Quarkus documentation focuses on `@QuarkusTest` and `@QuarkusComponentTest` for
testing extensions. The ability to create a standalone Jandex index from specific
classes and pass it directly to build-step methods is not documented as a testing
pattern. Most extension developers write integration tests that boot the full
container, missing the faster unit-test option.

### Alternatives considered
- `@QuarkusTest` with synthetic test classes — works but slow (full container boot)
  and tests more than just the build-step logic
- Mocking `IndexView` with Mockito — brittle, must mock multiple Jandex internal
  methods. Real `Indexer` is simpler and tests actual annotation processing
