### Symptom

A keyword-based SEC (Stimulus Evaluation Check) pipeline for cognitive appraisal produces near-zero emotional responses across realistic agent scenarios. 14 out of 15 diverse scenarios trigger no emotions. 7 of 9 Frijda action tendencies never fire. The pipeline appears to work (no errors, plausible structure) but is functionally inert.

### Context

When building a cognitive appraisal system for LLM agents (CARMA architecture), the natural first implementation uses keyword matching: scan the observation text for positive/negative/agency/helplessness keywords to compute appraisal dimensions (relevance, conduciveness, controllability, norm adherence). This is cheap, deterministic, and testable.

The problem is invisible without measurement — each check produces a plausible-looking score for any single input, but across a corpus of realistic scenarios, the scores collapse to 1-2 distinct values per dimension.

### What was tried (didn't work)

Keyword-based SEC checks using `String.contains()` against hardcoded word lists:
- **RelevanceCheck**: drive trigger keyword matching — 12/15 scenarios score 0.0 because drive triggers ("research", "solve") don't appear in observation text
- **CopingCheck**: 7 agency + 7 helplessness keywords — defaults to 0.5 for 14/15 scenarios. "The server is down and I have no access" scores 0.5 (neutral) because "no access" isn't in the keyword list
- **ImplicationCheck**: 10 positive + 10 negative keywords — binary output (match or no match), 2 distinct values
- **NormativeCheck**: 7 violation + 7 conformity keywords — zero discrimination across all 15 scenarios

### Root cause

Keyword matching operates on surface tokens, not meaning. Controllability, conduciveness, and norm adherence are almost always implicit in natural language. "The door is locked and I don't have the key" implies low controllability from the *relationship* between "locked" and "don't have the key" — no single keyword captures this.

The fundamental mismatch: appraisal dimensions (Scherer's SECs) require understanding situational semantics, but keyword matching only sees lexical tokens.

### Fix

**Measure discrimination before building on appraisal checks.** Create a scenario corpus (15+ diverse situations) and run each SEC check across all scenarios. Compute distinct value counts per dimension. If a dimension produces <3 distinct values across 15 scenarios, the check is not discriminating.

For checks that fail the discrimination test, replace with LLM-backed implementations. The experiment showed an LLM-backed CopingCheck produces 13 distinct controllability values where the keyword version produces 2 — and correctly identifies implicit coping (locked door = 0.1 controllability, equipped and ready = 0.95).

**What to keep computational:** Habituation tracking (observation counting, novelty decay) is inherently mathematical and works well as pure computation. Drive relevance matching needs richer matching but the concept is sound.

**What needs LLM:** CopingCheck (controllability/adjustability are almost always implicit), NormativeCheck (norm violation is contextual), ImplicationCheck (goal conduciveness requires compositional understanding).

### Why this is non-obvious

Keyword matching is a reasonable first approach — it's cheap, deterministic, and works well for sentiment analysis. The assumption that it would transfer to appraisal dimensions is natural. The inertness is invisible without systematic measurement across a scenario corpus: any individual scenario produces a plausible-looking score. Only the aggregate reveals that most scores are the default value.

### Alternatives considered

- **Expanding keyword lists significantly** — more words help marginally but the fundamental problem is compositionality, not vocabulary size. "Deadline moved up" is negative from word *combination*, not any single word.
- **Hybrid escalation (keyword first, LLM on default)** — if 93% of inputs trigger the default, the keyword layer adds complexity without filtering any real traffic.
- **Embedding-based keyword expansion** — using cosine similarity instead of exact match could help but adds most of the cost of an LLM call without the contextual reasoning.
