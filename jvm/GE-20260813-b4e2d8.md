## pages-push PushProducers creates vanilla ObjectMapper — Instant serialization fails

### Symptom
`EventBroadcaster.broadcast(topic, event)` throws `InvalidDefinitionException: Java 8 date/time type java.time.Instant not supported by default` when the event object contains `Instant` fields (e.g. `Ticket.createdAt`).

### Context
Using `casehub-pages-push-runtime` CDI module in a Quarkus app. The `EventBroadcaster` is injected via CDI and used to broadcast domain events. The event record contains `java.time.Instant` fields. Quarkus's own Jackson ObjectMapper has JSR310 support, but `EventBroadcaster` uses a separate `JsonWriter` bean.

### What was tried (didn't work)
1. Assumed Quarkus's Jackson config would apply — it doesn't; `PushProducers` creates its own ObjectMapper
2. Adding `jackson-datatype-jsr310` to pom.xml — the dependency is already present (via `quarkus-rest-jackson`), but the `PushProducers` ObjectMapper doesn't register the module

### Root cause
`PushProducers.jsonWriter()` creates a `@DefaultBean` `JsonWriter` backed by `new ObjectMapper()` — a vanilla instance with no modules registered. This ObjectMapper is separate from Quarkus's configured one. Since `JsonWriter` is a `@DefaultBean`, it can be overridden by a non-default producer.

### Fix
Override the `JsonWriter` CDI bean with one that registers `JavaTimeModule`:

```java
@ApplicationScoped
public class AppJsonWriter {

    @Produces
    @ApplicationScoped
    JsonWriter jsonWriter() {
        var mapper = new ObjectMapper();
        mapper.registerModule(new JavaTimeModule());
        mapper.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
        return mapper::writeValueAsString;
    }
}
```

This overrides `PushProducers`' `@DefaultBean` because a non-default producer always takes precedence in CDI.

### Why this is non-obvious
Quarkus auto-configures Jackson with JSR310 support globally, so developers assume all Jackson serialization in the app will handle `Instant`. The `PushProducers` creates a completely separate ObjectMapper that bypasses Quarkus's configuration. The error only appears at runtime when `EventBroadcaster.broadcast()` is called with an object containing time fields — compilation and startup succeed.
