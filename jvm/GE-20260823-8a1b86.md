### Symptom

Compilation error in a Quarkus deployment module: `cannot find symbol` for `org.jboss.jandex.Indexer`, `AnnotationInstance`, `MethodInfo`, and other Jandex API classes — even though `quarkus-arc-deployment` is a compile dependency and transitively includes `io.smallrye:jandex-gizmo2`.

### Context

When writing a Quarkus build extension (deployment module) that uses the Jandex `Indexer` API directly (e.g., for a `PatternAnnotationStep` scanner), the `quarkus-arc-deployment` dependency brings in `jandex-gizmo2` — a merged artifact containing both Jandex and Gizmo 2. However, the plain Jandex API classes from `io.smallrye:jandex` are not exposed at compile scope through this path.

### Root cause

`quarkus-arc-deployment` depends on `io.smallrye:jandex-gizmo2` (compile scope), which bundles Jandex classes but does not make the standalone `io.smallrye:jandex` artifact available. Maven dependency mediation treats these as separate artifacts. Code importing `org.jboss.jandex.Indexer` needs the plain `jandex` artifact explicitly.

### Fix

Add an explicit compile-scope dependency on `io.smallrye:jandex` in the deployment pom:

```xml
<dependency>
    <groupId>io.smallrye</groupId>
    <artifactId>jandex</artifactId>
</dependency>
```

Version is managed by the Quarkus BOM — no explicit version needed.

### Why this is non-obvious

The `quarkus-arc-deployment` dependency tree shows `jandex-gizmo2:3.5.3:compile` — suggesting Jandex is available. The `org.jboss.jandex` package name is the same in both artifacts. A developer would reasonably expect the transitive dependency to suffice.
