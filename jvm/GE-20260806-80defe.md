### Symptom
`quarkus:dev` repeatedly fails with "Port 8080 seems to be in use by another process" even after killing the Maven parent process. `lsof -i:8080` shows a `java` process with `ppid=1` (reparented to init) running `quarkus-run.jar`.

### Context
Running `mvn quarkus:dev` from a non-interactive shell (backgrounded with `&`, `nohup`, or via a CI/automation tool). The Maven plugin spawns a child JVM (`quarkus-run.jar`) for the actual application. When the parent Maven process is killed (`kill -9`), the child JVM survives and gets reparented to init.

Multiple restart attempts create multiple orphaned child JVMs, all holding the port. The dev mode error page JVM also holds the port between internal restarts, causing cascading port conflicts.

### What was tried (didn't work)
- `kill -9 <maven-pid>` — kills Maven but child JVM survives
- `lsof -ti:8080 | xargs kill -9` — kills the visible orphan but another spawns during dev mode's internal restart cycle
- `pkill -f "quarkus:dev"` — misses the `quarkus-run.jar` child processes
- Running `mvn quarkus:dev` from a backgrounded bash process — the interactive dev mode prompt ("Press [space] to restart") prevents clean lifecycle management

### Root cause
`quarkus:dev` creates a two-level process tree: Maven plugin → dev mode JVM (`casehub-life-app-dev.jar`) → application JVM (`quarkus-run.jar`). When any ancestor is killed, the descendants are orphaned (not in the same process group in non-interactive shells). The dev mode JVM also binds port 8080 for its error page handler before the application starts, creating a race between the error page JVM and the application JVM.

### Fix
Nuclear cleanup before starting:
```bash
pkill -9 -f "quarkus-run.jar"
pkill -9 -f "quarkus:dev"
pkill -9 -f "casehub-life-app-dev.jar"  # the dev mode JVM
sleep 3
# Verify truly clean
pgrep -f "quarkus" || echo "CLEAN"
lsof -ti:8080 || echo "PORT_FREE"
```

For reliable demo/CI usage, prefer running the packaged jar directly instead of `quarkus:dev`:
```bash
java -Dquarkus.profile=demo -jar target/quarkus-app/quarkus-run.jar
```

This requires a `DemoIdentityProvider` to bypass `@RolesAllowed` (see GE-20260806-5c7fbf).

### Why this is non-obvious
Killing a parent process is normally expected to clean up child processes. The orphaned child JVM with `ppid=1` is invisible to typical cleanup commands that target the Maven process name. The cascading port conflicts from multiple orphans make the failure mode look like a port leak rather than a process management issue.
