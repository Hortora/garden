### Symptom
After using `ide_move_file` to move a type between Maven modules (e.g. `ScoredGrade` from `rag-crossencoder` to `rag-api`), `ide_optimize_imports` on consuming files silently fails to add the import for the moved type. Compilation fails with "cannot find symbol" on the moved type.

### Context
Multi-module Maven project. Type moved from a downstream module to an upstream module. `ide_move_file` correctly updates references in files within the same module, but consuming modules in other Maven artifacts still resolve against the old installed jar.

### Root cause
IntelliJ's import resolution uses the Maven local repository (`~/.m2/repository`) to resolve types in dependency jars. After `ide_move_file`, the source module's installed jar still contains the type at the old package — it hasn't been rebuilt. IntelliJ finds the type in the stale jar and doesn't add the new import.

### Fix
After any `ide_move_file` that crosses Maven module boundaries:
1. Run `mvn install -DskipTests` on the module the type moved INTO (to update the local repo jar)
2. Run `ide_sync_files` on consuming files
3. Only then run `ide_optimize_imports` — or manually add the import for the moved type

### Why this is non-obvious
`ide_move_file` reports success and shows all affected files updated. `ide_optimize_imports` also reports success. The failure is silent — you only discover it at Maven compile time, after potentially editing several more files.
