### Context

Calling Claude via Google Vertex AI from a Java/Quarkus application. The obvious approach is to add `langchain4j-vertex-ai-anthropic` or `quarkus-langchain4j-anthropic` as dependencies. But these extensions don't exist in the Quarkus ecosystem (as of 2026-08), and the core LangChain4j module requires additional Google Cloud dependencies.

### Technique

The Vertex AI rawPredict endpoint accepts the standard Anthropic Messages API body with two differences:

1. `anthropic_version` goes in the **request body** as `"vertex-2023-10-16"` (not a header)
2. Auth is a Google **Bearer token** from `gcloud auth print-access-token` (not `x-api-key`)

Endpoint format:
```
https://{REGION}-aiplatform.googleapis.com/v1/projects/{PROJECT_ID}/locations/{REGION}/publishers/anthropic/models/{MODEL_ID}:rawPredict
```

Implementation using only `java.net.http.HttpClient` — zero new dependencies:

```java
final class VertexChatModel implements ChatModel {
    private final String endpoint;
    private final HttpClient httpClient;

    VertexChatModel(String projectId, String region, String modelId, Duration timeout) {
        this.endpoint = String.format(
            "https://%s-aiplatform.googleapis.com/v1/projects/%s/locations/%s/publishers/anthropic/models/%s:rawPredict",
            region, projectId, region, modelId);
        this.httpClient = HttpClient.newBuilder().connectTimeout(timeout).build();
    }

    @Override
    public ChatResponse doChat(ChatRequest request) {
        String token = fetchAccessToken(); // gcloud auth print-access-token
        String body = buildRequestBody(request); // anthropic_version in body, system as top-level field
        HttpRequest req = HttpRequest.newBuilder()
            .uri(URI.create(endpoint))
            .header("Authorization", "Bearer " + token)
            .header("Content-Type", "application/json")
            .POST(HttpRequest.BodyPublishers.ofString(body))
            .build();
        HttpResponse<String> resp = httpClient.send(req, HttpResponse.BodyHandlers.ofString());
        // Parse content[].text from response
    }
}
```

The CDI producer reads `ANTHROPIC_VERTEX_PROJECT_ID` and `CLOUD_ML_REGION` from environment variables, activated by a build-time property (`casehub.eval.vertex.enabled=true`).

### Why this is non-obvious

A developer looking to integrate Claude via Vertex AI would search for a LangChain4j extension and find none in the Quarkus ecosystem. The `langchain4j-vertex-ai-anthropic` core library exists but brings Google Cloud dependencies. The rawPredict endpoint is documented in Google's docs but the two differences from the standard Anthropic API (body-level `anthropic_version`, Bearer token auth) are easy to miss. Using `java.net.http.HttpClient` directly is simpler and has zero dependency footprint.
