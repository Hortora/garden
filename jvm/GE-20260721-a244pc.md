When using `ide_edit_member` to change a method's return type (e.g., `RoutingResult` → `Uni<RoutingResult>`), the default `reformat=true` causes the IDE to reformat the entire method. If the IDE's cached interface definition still has the old signature, the reformat silently reverts the return type to match the cached interface — the body changes are kept but the signature is undone.

**Symptom:** Method body updated correctly but return type reverts to the pre-edit value. Maven compilation fails with "return type is not compatible" but IntelliJ IDE build may show it as clean (using the same stale cache).

**Root cause:** `reformat=true` triggers import optimization and code style enforcement, which includes checking the method signature against the declared interface. If the IDE hasn't reindexed the dependency jar containing the updated interface, it "fixes" the signature back to what it thinks is correct.

**Fix:** Use `ide_replace_text_in_file` for method signature changes — it performs literal text replacement without reformatting. Reserve `ide_edit_member` for body-only changes where the signature is unchanged.

**Alternative:** Call `ide_sync_files` or trigger a reindex before using `ide_edit_member` on signature changes, but this adds latency and may not be sufficient if the dependency jar itself hasn't been updated in the IDE's maven cache.
