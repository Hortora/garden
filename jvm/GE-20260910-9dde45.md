## Dual event dispatch for mixed Vert.x EventBus + CDI Event<T> codebases

### Context
When extracting framework-neutral cores from a Quarkus application that uses BOTH Vert.x EventBus (address-based publish/subscribe for internal orchestration) AND CDI Event<T> (type-based fireAsync for cross-module notifications), a single abstraction strategy fails.

### The technique
Use two different abstraction patterns matched to each mechanism's usage:

**Vert.x EventBus → EventDispatcher SPI**
```java
@FunctionalInterface
public interface EventDispatcher {
    void dispatch(Object event);
}
```
Core handlers get EventDispatcher via constructor. Handler chains (handler A publishes 3-6 different event types downstream) would need 3-6 Consumer<T> params each — impractical. One EventDispatcher param covers all.

**CDI Event<T> → Consumer<T> / Function<T, CompletionStage<Void>> callbacks**
```java
// Fire-and-forget
Consumer<WorkerDecisionEvent> onWorkerDecision;

// Completion-await (when handler needs to wait for all observers)
Function<CaseLifecycleEvent, CompletionStage<Void>> onLifecycleEvent;
```
CDI events are cross-module notifications with 1-2 event types per producer — Consumer<T> is natural (same as platform extraction pattern).

### Why this is non-obvious
Most extraction guides and hexagonal architecture references treat all events uniformly — "define an EventPublisher port." The engine uses Vert.x EventBus for internal state machine dispatch (35 handlers, 74 publish calls) and CDI events for cross-module notifications (27+ injection points). These serve different purposes and have different scale characteristics. Trying to use Consumer<T> for both creates constructor explosion (22+ params on complex handlers). Trying to use EventDispatcher for both conflates orchestration with notification.

### Alternatives considered
- Consumer<T> for everything — impractical at Vert.x scale (handlers publish 3-6 event types)
- EventDispatcher for everything — conflates two mechanisms; CDI events have completion-await semantics that don't map to void dispatch()
- Custom EventBus library — Google deprecated Guava EventBus; hexagonal consensus is simple port interfaces
