# @SubjectId requires UUID and triggers GOAP inference

Two issues when composing `@Audited` (ledger-annotations) with `@Case`/`@Worker` (engine-annotations) on the same interface.

## Symptom

### Issue 1 — UUID type required
Build fails with:
```
@SubjectId parameter on method 'io.casehub.examples.IncidentResponseCase.triage'
must be java.util.UUID — got java.lang.String
```

### Issue 2 — GOAP inference pollution
In `PlanningMode.GOAP` cases, a test asserting empty preconditions fails:
```
Expecting empty but was: {"uUID"=true}
```

## Context

When building cross-repo annotation examples that compose engine `@Case` with ledger `@Audited`, both issues surface during the first attempt.

## What was tried (didn't work)

- `@SubjectId String incidentId` — rejected by `LedgerAnnotationsProcessor#validateAnnotations`
- `@SubjectId UUID missionId` in GOAP mode — passes validation but UUID becomes a GOAP precondition with key `"uUID"`

## Root cause

### Issue 1
`LedgerAnnotationsProcessor` validates that `@SubjectId`-annotated parameters are `java.util.UUID`. The `@SubjectId` annotation definition itself has no type constraint visible — the requirement is in the build extension processor code.

### Issue 2
The GOAP type inferrer classifies parameters as dependencies unless they are primitive types, `String`, `Map<String, Object>`, or annotated with `@Param`. `UUID` is none of these, so it gets a precondition entry with key `"uUID"` (camelCase of `UUID.class.getSimpleName()`).

## Fix

Annotate `@SubjectId UUID` parameters with `@Param` to exclude them from GOAP inference:

```java
// EXPLICIT mode — @Param not needed, but harmless
TriageAssessment triage(@SubjectId UUID incidentId, @ActorId String analystId,
                        ScanResult scanResult);

// GOAP mode — @Param required to prevent "uUID" precondition
ConditionAssessment assessConditions(@Param("missionId") @SubjectId UUID missionId,
                                      @ActorId String coordinatorId,
                                      String lastKnownPosition, String terrain);
```

`@ActorId String` does not need `@Param` — `String` is already excluded from GOAP inference.

## Why this is non-obvious

The `@SubjectId` annotation is a plain `@Target(PARAMETER)` annotation with no type constraint in its definition. The UUID requirement is enforced only by the build extension processor — invisible until you hit the error. The GOAP interaction is doubly surprising: UUID feels like infrastructure, not a domain type, but the inferrer has no special case for it.

### Alternatives considered

- Adding UUID to the GOAP inferrer's excluded-type list — correct long-term fix but requires a change to `casehub-engine-common`'s `GoapKeyConvention`. Using `@Param` is the immediate workaround.
