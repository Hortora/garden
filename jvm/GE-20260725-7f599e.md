# Fusion strategy properties derive authority signal integration mode

### Symptom / Context

When adding a quality score (1-10, query-independent) to a hybrid retrieval system that supports multiple fusion strategies (RRF, CC, DBSF), the natural instinct is to add a `BoostMode { FUSION_LEG, RESCORE }` config so users can choose how quality integrates with retrieval signals. This creates a config matrix where most cells have only one correct answer.

### Root cause

Quality scores are **authority signals** (query-independent) not **relevance signals** (query-dependent). How they should integrate depends on the fusion algorithm's mathematical properties, not user preference:

| Fusion | Score model | Quality integration | Why |
|--------|-------------|-------------------|-----|
| CC | Score-aware (min-max normalized) | Fusion leg | Magnitude preserved in convex combination |
| RRF | Rank-based (1/k+rank) | Post-fusion rescore | Rank conversion loses magnitude — quality 9→10 gets same delta as 1→2 |
| DBSF | Score-aware, server-side | Post-fusion rescore | Can't inject non-vector legs server-side |

### Fix

Derive the integration mode from the already-selected fusion strategy. One `quality` weight (0.0 = disabled) controls whether boosting is active. The system does the right thing:

- CC → quality participates as a fusion leg in `convexCombination()`
- RRF/DBSF → decorator applies `score * (1 + normalizedQuality * weight)` post-fusion

No `BoostMode` enum. No separate strategy. The config matrix collapses to a lookup table the system resolves internally.

### Why this is non-obvious

Most developers treat "how to combine signals" as a user-facing configuration choice. The insight is that when the combination method is already chosen (the fusion strategy), the integration mode for new signals is determined — adding a second axis creates a matrix where most combinations are either the only correct choice or actively wrong. 4 of 6 cells in a 3×2 matrix had only one right answer — that's not a strategy, it's a lookup table.
