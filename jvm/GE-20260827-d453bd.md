### Symptom

After adding a module to `quarkus.index-dependency` in `application.properties`, all `@QuarkusTest` tests fail during Quarkus boot with:

```
graphql.schema.validation.InvalidSchemaException: invalid schema:
"Object" must define one or more fields.
```

The error message does not name the offending type — only the generic "Object" label appears.

### Context

When migrating MCP `@Tool` methods to `@GraphQLApi` + `@McpDomain` resolvers, return types from non-app modules (domain, review) need to be discoverable by SmallRye GraphQL. The obvious fix is adding the module to `quarkus.index-dependency`:

```properties
quarkus.index-dependency.devtown-domain.group-id=io.casehub
quarkus.index-dependency.devtown-domain.artifact-id=casehub-devtown-domain
```

This causes SmallRye to discover ALL types in the module — not just those reachable from `@GraphQLApi` method signatures.

### What was tried (didn't work)

1. Adding domain module to `quarkus.index-dependency` — fixed the immediate `type X not found in schema` error but introduced the `"Object" must define one or more fields` error from sealed interfaces
2. Adding both domain and review modules — review module also contained sealed interfaces, same failure
3. Using `%prod.` prefix to scope indexing — build-time property, doesn't help with test profile

### Root cause

Java sealed interfaces like:

```java
public sealed interface MergeOutcome {
    record Success(String mergeSha) implements MergeOutcome {}
    record Failure(String reason) implements MergeOutcome {}
}
```

have no instance fields or methods on the interface itself — only `permits` clauses and inner records. When SmallRye GraphQL discovers these via Jandex, it attempts to map them as GraphQL object types. An object type with zero fields violates the GraphQL spec, causing the schema validation error.

Multiple sealed interfaces in a single module (`MergeOutcome`, `RevertOutcome`, `BatchBranchOutcome`, `CoordinatedMergeResult`, `ReviewerOutcome`, `PrLifecycleEvent`) all trigger this — but the error message names none of them.

### Fix

Do not add modules containing sealed interfaces to `quarkus.index-dependency`. Instead, wrap external types in local records within the `@GraphQLApi` resolver class. See GE-20260827-50b67b for the technique.

### Why this is non-obvious

1. The error message (`"Object" must define one or more fields`) gives no clue which type is the problem — you must binary-search across all types in the indexed module
2. `quarkus.index-dependency` is documented for CDI bean discovery — its effect on SmallRye GraphQL type discovery is undocumented
3. Sealed interfaces seem like they should map to GraphQL union types (which don't require fields), not object types
4. The failure only manifests during `@QuarkusTest` boot, not during `mvn compile` — so you discover it late

### Why this fix

Wrapping in local records rather than fixing SmallRye's sealed interface handling because: (a) the sealed interfaces are in domain modules you may not control, (b) even if SmallRye fixed this, exposing internal domain types in the GraphQL schema is poor API design, (c) the wrapper pattern is already used by all other mutation methods in the resolver.

### Alternatives considered

- Adding `@org.eclipse.microprofile.graphql.Ignore` to sealed interface types — requires modifying the domain module and doesn't work on interfaces (only fields/methods)
- Adding `jandex-maven-plugin` to the domain module — same problem, SmallRye still discovers the sealed interfaces
- SmallRye GraphQL type exclusion config — no such config property exists as of Quarkus 3.32.2
