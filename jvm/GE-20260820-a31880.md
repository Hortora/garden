## Symptom

`jakarta.enterprise.inject.AmbiguousResolutionException` during `quarkus:build` (production augmentation) or `@QuarkusTest` startup:

```
Ambiguous dependencies for type io.casehub.platform.api.callback.CallbackRegistry and qualifiers [@Default]
  - available beans:
    - CLASS bean [...NoOpCallbackRegistry...] target=io.casehub.platform.callback.NoOpCallbackRegistry
    - CLASS bean [...NoOpCallbackRegistry...] target=io.casehub.soc.testing.NoOpCallbackRegistry
```

## Context

A platform module provides a `@DefaultBean @ApplicationScoped` implementation of an SPI (e.g., `NoOpCallbackRegistry`). A consuming application has its own `@ApplicationScoped` implementation of the same interface in `src/test/java/` — intended only for test use. Both beans are discovered by Quarkus.

## What was tried (didn't work)

Assuming test-scope beans are invisible during production augmentation. They are not — Quarkus scans Jandex indexes from both production and test classpaths during `quarkus:build`.

## Root cause

Quarkus augmentation (the `quarkus:build` Maven goal and `@QuarkusTest` startup) indexes test classes via Jandex alongside production classes. A test `@ApplicationScoped` bean and a runtime `@DefaultBean` both satisfy the same injection point, causing ambiguity. The `@DefaultBean` annotation only yields to `@Alternative` or `@Priority`-annotated beans — a plain `@ApplicationScoped` bean does not displace it cleanly; instead, both compete.

## Fix

Delete the test-scope duplicate. If the platform already provides a `@DefaultBean` implementation, test code does not need its own — the `@DefaultBean` serves both production and test contexts. If the test needs a different implementation, use `@Alternative @Priority(1)` in the test to properly displace the `@DefaultBean`.

## Why this is non-obvious

The mental model is that test sources are isolated from production augmentation. In most Java frameworks, test classes don't leak into production classpath analysis. Quarkus breaks this assumption because Jandex scanning covers both source trees during augmentation.
