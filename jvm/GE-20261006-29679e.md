## SmallRye GraphQL — List<?> wildcard resolves to Object type, causing InvalidSchemaException

**ID:** GE-20261006-29679e
**Stack:** Quarkus 3.39.x, SmallRye GraphQL
**Symptom:** App fails to boot with `InvalidSchemaException: invalid schema: "Object" must define one or more fields.` No indication of which Java type caused it.
**Context:** When any type in the GraphQL schema's object graph contains a `List<?>` field, or any field typed as `java.lang.Object`.

### What was tried (didn't work)
- Searched generated GraphQL resolver source files for `Object` — not found
- Checked all entity/DTO fields for `Map<String, Object>` — none in the API layer
- Checked return types of all resolver methods — all look typed

### Root cause
SmallRye GraphQL walks the full object graph of every type exposed by `@Query` and `@Mutation` methods. When it encounters `List<?>`, the wildcard resolves to `java.lang.Object`. GraphQL requires every type to define at least one field — `Object` has none. The error message says `"Object"` but doesn't name the class or field that caused it.

In this case: `public record CaseEventLog(UUID caseId, int eventCount, List<?> events) {}` — the `events` field used `List<?>` because the underlying engine API returns an untyped list.

### Fix
Replace `List<?>` with a concrete type. If the actual type is heterogeneous, use `List<String>` and serialize:

```java
// Before — causes "Object" schema error
public record CaseEventLog(UUID caseId, int eventCount, List<?> events) {}

// After — concrete type, GraphQL-safe
public record CaseEventLog(UUID caseId, int eventCount, List<String> events) {}

// Convert at call site
var eventLog = runtime.eventLog(caseId);
return new CaseEventLog(caseId, eventLog.size(),
    eventLog.stream().map(Object::toString).toList());
```

Empty records (zero fields) cause the same error for input types — remove or add a field.

### Why this is non-obvious
The error says `"Object" must define one or more fields` — this reads like a missing type definition, not a wildcard resolution problem. You search for `Object` in your code and find nothing. The actual cause is a `?` wildcard buried in a record used transitively by a resolver return type. Finding it requires tracing the full object graph of every exposed type.
