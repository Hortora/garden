### The convention

When extracting framework-neutral cores from Quarkus modules for dual Spring Boot/Quarkus support, name the modules:

- `module-core/` — pure Java POJOs, constructor injection, zero framework annotations
- `module/` — existing artifact name PRESERVED — CDI producers, event observers, @Scheduled wrappers
- `module-spring/` — new Spring Boot auto-configuration, @EventListener, @Scheduled wrappers

### Rationale

Preserving existing Quarkus artifact names means zero consumer disruption — every Quarkus consumer continues to depend on the same Maven coordinate. The `-core` suffix accurately describes the new module's role. The asymmetry (no `-quarkus` suffix) reflects the migration reality: Quarkus is the established framework being kept, Spring is the new addition.

### Alternatives

- `module/module-quarkus/module-spring` — symmetric naming but breaks every Quarkus consumer's pom.xml (must change from `module` to `module-quarkus`)
- `module/module-spring` (keep current names, add Spring only) — no core extraction, logic duplicated across framework modules
- `module-core/module-cdi/module-spring` — CDI suffix is more precise than bare name, but "CDI" is confusing for modules that also use JAX-RS, SmallRye, etc.
