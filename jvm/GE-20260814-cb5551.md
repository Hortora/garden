### Symptom
Attempting to call `result.isSuccess()` on a `WorkerResult` fails with "cannot find symbol." The API looks like it should have a convenience method for checking success/failure, but it doesn't.

### Context
`WorkerResult<R>` is a Java record with two accessors: `output()` (the result data) and `outcome()` (the status). The outcome is a sealed interface `WorkerOutcome` with variants: `Success`, `Failed`, `Declined`, `Expired`, `Completed`.

### Fix
Check the outcome type via `instanceof`:

```java
// Success check
assertThat(result.outcome()).isInstanceOf(WorkerOutcome.Success.class);

// Failure check
assertThat(result.outcome()).isInstanceOf(WorkerOutcome.Failed.class);

// Access output (requires cast for Map-typed results)
Map<String, Object> output = (Map<String, Object>) result.output();
assertThat(output).containsKey("someKey");
```

The existing `ComplianceRemediationCaseDescriptorTest` demonstrates this pattern throughout.

### Why this is non-obvious
The record declaration (`record WorkerResult<R>(R output, WorkerOutcome<R> outcome)`) doesn't reveal the sealed hierarchy or the correct assertion pattern. A developer naturally reaches for `isSuccess()` / `isFailed()` convenience methods that most result types provide. The actual API requires knowledge of the `WorkerOutcome` sealed hierarchy and `instanceof` pattern matching.
