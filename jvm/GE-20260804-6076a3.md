### Symptom
Setting `casehub.inference.models.bge-m3.max-sequence-length=768` in test `application.properties` causes `ConfigValidationException` requiring `model-path` and `tokenizer-path` — properties that should be optional in tests where in-memory stubs replace real models.

### Context
`@ConfigMapping` interfaces with `Map<String, ModelProperties>` structure. When any property in a map entry's group is set (e.g. `models.bge-m3.max-sequence-length`), SmallRye Config instantiates the entire `ModelProperties` group and validates all required fields. This is by design — config groups are all-or-nothing.

The problem compounds with `@LookupIfProperty(name = "...model-path", stringValue = ".+", match = REGEX)` — a CDI pattern that conditionally resolves beans based on config presence. You cannot have "config group populated for InMemoryEmbeddingIngestor but model-path absent for @LookupIfProperty" because:
1. Empty string (`""`) fails SmallRye validation (SRCFG00040)
2. Any non-empty value matches the `.+` regex, making the bean resolvable

### Root cause
SmallRye Config treats `@ConfigMapping` map entries as atomic groups. Setting one property in the group creates the entry and triggers validation of all required siblings. There is no way to partially populate a group.

### Fix
Provide full stub config globally in test properties (model-path, tokenizer-path, max-sequence-length all set to stub values). For tests that need "model absent" behaviour, convert from `@QuarkusTest` to plain unit tests that verify the `@LookupIfProperty` annotation contract via reflection rather than booting Quarkus with partial config.

```properties
# test/resources/application.properties
casehub.inference.models.bge-m3.model-path=stub
casehub.inference.models.bge-m3.tokenizer-path=stub
casehub.inference.models.bge-m3.max-sequence-length=768
```

```java
// Unit test verifying the guard annotation instead of booting Quarkus
@Test
void producerMethodHasLookupIfPropertyGuard() throws Exception {
    Method method = Arrays.stream(HybridSearchProducer.class.getDeclaredMethods())
            .filter(m -> m.getName().equals("multiModalEmbedder"))
            .findFirst().orElseThrow();
    LookupIfProperty ann = method.getAnnotation(LookupIfProperty.class);
    assertThat(ann.name()).isEqualTo("casehub.inference.models.bge-m3.model-path");
    assertThat(ann.stringValue()).isEqualTo(".+");
}
```

### Why this is non-obvious
The natural expectation is that setting `max-sequence-length` alone should work — it's a separate property from `model-path`. The all-or-nothing group validation is implicit in `@ConfigMapping` semantics and not surfaced in the error message (which just says "required property not found"). The `@LookupIfProperty` interaction makes the problem unsolvable within the `@QuarkusTest` framework — you must step outside it entirely.

### Alternatives considered
- Setting `model-path=""` — fails with SRCFG00040 (empty string treated as null)
- Excluding producer beans via `quarkus.arc.exclude-types` — causes cascading `UnsatisfiedResolutionException` on downstream beans
- Using `@QuarkusTestProfile` to override model-path — any non-empty value satisfies `.+` regex, defeating the "absent" test
