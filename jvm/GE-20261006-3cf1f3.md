## GraphQL generator classifies Map as simple type — REST @QueryParam Map causes JAX-RS param converter failure

**ID:** GE-20261006-3cf1f3
**Stack:** Quarkus 3.39.x, casehub-platform-graphql-generator
**Symptom:** Quarkus app fails to boot with `RuntimeException: Unable to create param converter for parameter java.util.Map<java.lang.String, java.lang.String>`. No indication of which REST endpoint is the source.
**Context:** When a `@McpDomain` API method has a `Map<String, String>` parameter and the platform GraphQL generator processes it with REST generation enabled.

### What was tried (didn't work)
- Searched for hand-written REST resources with Map params — none found
- Checked if the Map was a body param — the generator treats it as a query param
- Tried adding `@QueryParam` explicitly — same failure, JAX-RS can't convert Map

### Root cause
The platform `GraphQLResolverProcessor` has `COLLECTION_TYPES = Set.of("java.util.List", "java.util.Set", "java.util.Collection", "java.util.Map", "java.util.Optional")`. `isSimpleTypeJandex()` checks if a type is in `COLLECTION_TYPES` and if its type arguments are simple — `Map<String, String>` passes both checks. For mutations (POST), the REST generator only treats params as body when `!p.isSimpleType()`. Since Map is "simple", it emits `@QueryParam("body") Map<String, String>` instead of treating it as the request body. JAX-RS has no `ParamConverter` for `Map`.

### Fix
Replace `Map<String, String>` parameters in `@McpDomain` APIs with typed DTOs:

```java
// Before — causes param converter failure
public void upgradeService(@PathParam UUID id, Map<String, String> body) { ... }

// After — works correctly as REST body and GraphQL input
public record UpgradeServiceRequest(String newImage) {}
public void upgradeService(@PathParam UUID id, UpgradeServiceRequest request) { ... }
```

Platform fix (not yet applied): remove `"java.util.Map"` from `COLLECTION_TYPES` in `GraphQLResolverProcessor.java`.

### Why this fix
Typed DTOs are better API design regardless — Map params lose discoverability in GraphQL schemas and REST docs. The DTO fix is correct for ops; the platform fix prevents the same trap for other consumers.

### Why this is non-obvious
The error message gives no hint about `COLLECTION_TYPES` or the generator's type classification. The failure appears as a JAX-RS param converter issue, sending you to investigate JAX-RS extensions rather than the annotation processor's type system. The GraphQL resolver handles Map correctly (skips it via `usesHttpContext()` check) — only the REST side fails.
