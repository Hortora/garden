## PerceptionFilter uses content degradation not binary filtering

### Symptom

Test expects `filter()` to reduce section count when observer lacks required tags. Section count stays the same — the restricted section is still present but with different content.

### Context

`PerceptionFilter` implements `ObservationFilter` in the casehub-blocks world model observation pipeline. When an `AnnotatedSection` has `requiredTags` that the observer doesn't possess, the filter doesn't remove the section. Instead, it checks `resolutions()` for a lower-fidelity alternative (e.g. `ResolutionTier.REDUCED`) and substitutes that.

### Root cause

The visibility model is *fidelity-based*, not *binary*. An agent without the required tags still sees the section — just at reduced fidelity. Only when no resolution alternative exists does the section get removed entirely (returns `null`).

```java
// PerceptionFilter.resolve()
if (a.requiredTags().isEmpty() || observerTags.containsAll(a.requiredTags())) {
    return section;  // full access
}
if (!a.resolutions().isEmpty()) {
    // degrade to lower-fidelity alternative
    for (var tier : ResolutionTier.values()) {
        if (tier != ResolutionTier.FULL && a.resolutions().containsKey(tier)) {
            return a.resolutions().get(tier);
        }
    }
}
return null;  // no fallback — remove entirely
```

### Fix

When testing visibility gating with resolution alternatives, assert on *content* not *count*:

```java
// Wrong — count stays the same because fallback replaces the section
assertThat(withoutTrust.size()).isLessThan(withTrust.size());

// Right — content changes
assertThat(fullView).contains("Tesla's Private Diary");
assertThat(restrictedView).doesNotContain("Tesla's Private Diary");
assertThat(restrictedView).contains("deeper trust is needed");
```

### Why this is non-obvious

The method name `filter` and the interface name `ObservationFilter` strongly suggest include/exclude semantics. The actual behavior — resolution tier degradation with graceful fallback — is a richer model that a developer would only discover by reading the implementation. The `AnnotatedSection.resolutions()` field and the `ResolutionTier` enum are the mechanism, but nothing in the interface contract signals that filtering means fidelity adjustment.
