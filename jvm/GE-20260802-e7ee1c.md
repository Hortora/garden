## MockWebServer3 vs OkHttp3 MockWebServer — same name, incompatible APIs

### Symptom

`cannot find symbol: method shutdown()` and `readUtf8()` compilation errors when using MockWebServer in tests. The code looks correct — MockWebServer, MockResponse, standard patterns.

### Context

Two MockWebServer libraries coexist in the Maven ecosystem:
- `mockwebserver3.MockWebServer` (MockWebServer3 — newer, Builder API)
- `okhttp3.mockwebserver.MockWebServer` (OkHttp3 bundled — older, setter API)

### Root cause

The APIs are structurally different despite the same class names:

| Operation | `mockwebserver3` | `okhttp3.mockwebserver` |
|-----------|-----------------|------------------------|
| Create response | `new MockResponse.Builder().body("...").build()` | `new MockResponse().setBody("...")` |
| Status code | `.code(503).build()` | `.setResponseCode(503)` |
| Shutdown | `.close()` | `.shutdown()` |
| Read body | `request.getBody().utf8()` | `request.getBody().readUtf8()` |

### Fix

Check which dependency the project uses. In casehub-engine, the dependency is `com.squareup.okhttp3:mockwebserver` — use `okhttp3.mockwebserver.*` imports with setter-pattern API.

### Why this is non-obvious

The import auto-complete often suggests the wrong package. Both libraries exist on Maven Central. The class names are identical — only the package differs. The compilation errors point at method names, not imports, making it look like an API version issue rather than a wrong-library issue.

### Alternatives considered

- Using `mockwebserver3` consistently — rejected because the project already uses `okhttp3.mockwebserver` in the flow module tests, and consistency matters more than API preference.
