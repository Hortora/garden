## Context

A CDI `@Decorator` intercepts calls to an interface type. Not all callers should be intercepted — internal runtime code should bypass the decorator while external-facing entry points (REST resources) should go through it.

Example: a `FederationProxyService` decorator on `WorkItemOperations` should intercept REST resource calls (so operator actions on shadow WorkItems are proxied to the owner) but NOT intercept internal calls from `MultiInstanceGroupPolicy` or `ExpiryLifecycleService` (which operate on local WorkItems only).

## Fix

Deliberately split injection types to control which call paths the decorator intercepts:

```java
// Interface — extracted from WorkItemService
public interface WorkItemOperations {
    WorkItem claim(UUID id, String claimantId);
    WorkItem complete(UUID id, String actorId, String resolution, String outcome);
    // ... all public lifecycle + query methods
}

// Concrete class — implements the interface
@ApplicationScoped
public class WorkItemService implements WorkItemOperations {
    // full implementation
}

// Decorator — intercepts interface-typed injection only
@Decorator
@Priority(Interceptor.Priority.APPLICATION + 10)
public class FederationProxyService implements WorkItemOperations {
    @Delegate @Inject @Any WorkItemOperations delegate;
    // intercepts claim, complete, etc. on shadow WorkItems
}

// INTERCEPTED — REST resource injects the interface type
@Path("/workitems")
public class WorkItemResource {
    @Inject WorkItemOperations workItemService;  // ← decorator wraps this
}

// NOT INTERCEPTED — internal code injects the concrete class
@ApplicationScoped
public class MultiInstanceGroupPolicy {
    @Inject WorkItemService workItemService;  // ← direct, no decorator
}
```

CDI only wraps the interface-typed injection with the decorator. Concrete-class injection resolves to the bean directly, bypassing the decorator chain.

## Why this is non-obvious

Most CDI tutorials and examples show uniform injection — either always inject the interface or always inject the concrete class. The idea that you'd deliberately split injection types across callers to control decorator scope is a design pattern, not a documented CDI feature. CDI specifications describe decorator mechanics but don't document this as a strategy for selective interception.
