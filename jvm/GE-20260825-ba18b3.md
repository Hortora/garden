### Symptom
CBR `FeatureValue` supports only flat key-value maps (StringVal, NumberVal, BooleanVal, StringListVal). Storing a polymorphic `sealed interface` hierarchy (e.g. `NarrativeFragment` → `IndividualEpisode`, `GroupEpisode`, `DerivedTheme`) requires flattening nested, type-varying structures into a single string feature.

### Context
CaseHub blocks stores complex domain state in CBR for compositor-pattern orchestrators. Simple records (UserProfile, StrategyProfile) map fields directly to features. Polymorphic hierarchies need a different approach.

### Fix
Serialize the entire fragment list as a JSON string in a single `FeatureValue.string()` feature, using a `"type"` discriminator field for polymorphic dispatch on deserialization.

Serialization — pattern-match on the sealed hierarchy:
```java
switch (fragments.get(i)) {
    case IndividualEpisode e -> serializeEpisode(sb, e);
    case GroupEpisode g -> serializeGroupEpisode(sb, g);
    case DerivedTheme t -> serializeTheme(sb, t);
}
```

Each serializer writes `{"type":"episode", ...}`, `{"type":"group_episode", ...}`, or `{"type":"theme", ...}`.

Deserialization — depth-based object extraction (same pattern as `MentalModelSchema`), then type-discriminated dispatch:
```java
var type = extractField(obj, "type");
return switch (type) {
    case "episode" -> parseEpisode(obj);
    case "group_episode" -> parseGroupEpisode(obj);
    case "theme" -> parseTheme(obj);
    default -> null;
};
```

Nested collections (`List<String>`, `Set<String>`, `Map<String, String>`, `Map<DriveAxis, Double>`) use dedicated extract helpers that handle the JSON array/object syntax with escape-aware parsing.

### Why this is non-obvious
The natural instinct is to use Jackson or another JSON library, but the blocks module uses hand-rolled JSON serialization (no Jackson dependency in the serialization path) following the `MentalModelSchema` precedent. The depth-based brace-counting parser for object extraction, combined with type discriminators for polymorphic dispatch, is specific to this codebase's CBR integration pattern.
