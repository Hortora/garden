### Context
`GanglionDescriptor.ExpressionRules.Rule.when` requires an `ExpressionEvaluator`. The normal path is: declare an expression string (JQ, MVEL) → register with the expression engine → compile at runtime. For ganglia declared programmatically in a `SituationDefinitionProvider`, this compilation indirection is unnecessary.

### Technique
Use `LambdaExpression<Map, Boolean>` from `io.casehub.platform.api.expression` directly:

```java
new GanglionDescriptor.ExpressionRules.Rule(
    new LambdaExpression<>(ctx -> {
        Map<String, Object> data = (Map<String, Object>) ctx.get("data");
        if (data == null) return false;
        return "FAIL".equals(data.get("status"));
    }),
    DetectionSignal.DETECTED,
    0.9,
    null,  // no dynamic confidence
    Map.of()  // no evidence templates
)
```

`LambdaExpression` implements BOTH `ExpressionEvaluator` (the descriptor-level interface) AND `CompiledExpression` (the runtime-level interface). It has `type() = "lambda"`, which means no `ExpressionEngine` is looked up — the registry's `resolve("lambda")` returns empty, and the runtime uses the expression directly since it's already a `CompiledExpression`.

### Why this is non-obvious
The `ExpressionEvaluator` interface is a marker with only `type()`. The natural assumption is that you need to implement a full `ExpressionEngine` or use one of the string-based expression types (JQ, MVEL). `LambdaExpression`'s dual-interface trick — being both the descriptor AND the compiled form — is not documented. It's noted in the class javadoc as "intentionally outside the registry flow" but a developer looking at `GanglionDescriptor.ExpressionRules.Rule` would not discover it without separately finding `LambdaExpression` in the platform API.

### Alternatives considered
- Implementing `ExpressionEvaluator` directly with an anonymous class — works but requires casting at the runtime level since `ExpressionEvaluator` has no `eval()` method
- Using JQ string expressions — requires the JQ expression engine to be on the classpath and adds string-parsing overhead for what's a simple Java predicate
