### Symptom
YAML files with multi-document format (`---` separator between front matter
and content) parse without error, but only the first document is returned.
The second document is silently discarded.

### Context
Any Jackson YAML parsing via `ObjectMapper.readTree(yaml)` or
`objectMapper.readValue(yaml, Map.class)` with multi-document YAML input.
Common when adding front matter headers to YAML files (e.g. playbook
metadata before content).

### What was tried (didn't work)
- `ObjectMapper.readTree()` — returns only the first YAML document, no
  error or warning
- Expected behaviour: error on multi-doc input, or return all documents

### Root cause
Jackson's `readTree()` reads a single tree from the parser stream and
stops. The YAML parser positioned at the second document is simply
abandoned. No API contract violation — `readTree` is documented as
single-value — but the silent success with partial data is the trap.

### Fix
Use `ObjectMapper.readValues()` with an explicit parser to iterate all
documents:

```java
ObjectMapper mapper = new ObjectMapper(new YAMLFactory());
var parser = mapper.getFactory().createParser(yaml);
var it = mapper.readValues(parser, JsonNode.class);
List<JsonNode> documents = new ArrayList<>();
while (it.hasNext()) {
    documents.add(it.next());
}
// documents.size() == 1 for single-doc, 2+ for multi-doc
```

### Why this is non-obvious
`readTree()` succeeding without error gives no signal that data was lost.
A developer adding `---`-separated front matter to existing YAML files
will see their parser "work" while silently ignoring the content document.
The fix (`readValues`) is a rarely-documented API that most Jackson users
don't encounter.
