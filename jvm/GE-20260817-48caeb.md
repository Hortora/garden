### Symptom

When changing a Quarkus extension's `@BuildStep` from `@Record(ExecutionTime.STATIC_INIT)` to `@Record(ExecutionTime.RUNTIME_INIT)`, the build fails at `SyntheticBeansProcessor#initStatic` — not at your build step:

```
RuntimeException: Invalid proxy passed to recorder.
Parameter 0 of type class io.quarkus.runtime.RuntimeValue was created
in a runtime recorder method, while this recorder is for a static init
method.
  at io.quarkus.deployment.recording.BytecodeRecorderImpl$1.invoke(...)
  at io.quarkus.arc.deployment.SyntheticBeansProcessor.initStatic(...)
```

The stack trace points at Quarkus internals (`SyntheticBeansProcessor`, `BytecodeRecorderImpl`), not at your build step or recorder — making it look like a Quarkus bug rather than a configuration issue.

### Context

When a `@Record(RUNTIME_INIT)` recorder produces a `RuntimeValue<T>` and passes it to `SyntheticBeanBuildItem.runtimeValue()`, Quarkus still tries to configure the synthetic bean during `STATIC_INIT` unless you explicitly mark the bean as runtime-initialized.

### Root cause

`SyntheticBeanBuildItem` defaults to static initialization. The `runtimeValue()` call does not automatically infer the initialization phase from the `RuntimeValue` origin. The mismatch — `RuntimeValue` created at `RUNTIME_INIT`, bean configured at `STATIC_INIT` — triggers the "invalid proxy" check.

### Fix

Add `.setRuntimeInit()` to the `SyntheticBeanBuildItem` configuration:

```java
syntheticBeans.produce(
    SyntheticBeanBuildItem.configure(CaseDefinition.class)
        .scope(ApplicationScoped.class)
        .unremovable()
        .setRuntimeInit()          // ← required when RuntimeValue comes from RUNTIME_INIT
        .runtimeValue(runtimeValue)
        .done());
```

### Why this is non-obvious

The error message says "Parameter 0... was created in a runtime recorder method, while this recorder is for a static init method" — but "this recorder" refers to `SyntheticBeansProcessor`, not your code. The fix location (`setRuntimeInit()` on the `SyntheticBeanBuildItem` builder) is not mentioned in the error, and `setRuntimeInit()` is not prominently documented in the Quarkus extension guide. The `runtimeValue()` method name suggests it already handles runtime semantics.
