### Symptom
`<blocks-audit-trail-viewer>` entry expansion shows null content — the payload panel is empty even though ledger entries have metadata stored.

### Context
The `blocks-audit-trail-viewer` Lit component reads `entry.payload` from the JSON response. The `casehub-ledger-rest` module's `LedgerEntryResponse` record has the field named `metadata` (matching the underlying `LedgerEntry.metadata` JPA field). JSON serialization produces `"metadata": "..."` but the component reads `payload`.

### Root cause
Field name mismatch between the REST DTO and the UI component's TypeScript interface. The component's `LedgerEntry` type declares `payload: unknown | null`; the Java record declares `String metadata`. Since Jackson serializes by field name, the JSON has `metadata` and `payload` is `undefined` in JavaScript.

### Fix
Rename the DTO field in `LedgerEntryResponse.java`:

```java
// Before
public record LedgerEntryResponse(..., String metadata) {}

// After
public record LedgerEntryResponse(..., String payload) {}
```

The mapper still reads from `entry.metadata` — only the serialized JSON field name changes.

### Why this is non-obvious
Both `metadata` and `payload` are semantically reasonable names. The mismatch is invisible until you expand an entry in the UI and see null — no error, no warning. The component's conditional check `entry.payload === null` is false (it's `undefined`, not `null`), so `renderPropertyTree(undefined)` is called silently.
