### Symptom
`WorldBridge.perceive()` returned empty results on the first call despite accumulated messages existing in the history.

### Context
`ChatWorldBridge` initialized `lastCheck = Instant.now()` in its constructor. Test messages were created with `Instant.now()` as their `receivedAt` timestamp. The `perceive()` method filtered messages with `m.receivedAt().isAfter(lastCheck)`.

### Root cause
`Instant.isAfter()` is strict — it returns `false` when timestamps are equal. When the constructor and message creation happen within the same millisecond (common in tests), all messages have `receivedAt` equal to or before `lastCheck`, so the filter excludes everything.

### Fix
For gateway-accumulating message history (where messages only appear after bot startup), initialize `lastCheck = Instant.EPOCH`. This ensures the first `perceive()` returns all accumulated messages.

```java
// Wrong — races with message timestamps in tests and fast startup
private Instant lastCheck = Instant.now();

// Right — gateway messages only exist from startup, EPOCH catches everything
private Instant lastCheck = Instant.EPOCH;
```

### Why this is non-obvious
`Instant.now()` seems like the correct "start from now" initialization. The race is invisible in production (gateway messages arrive after constructor completes) but deterministic in tests where messages are pre-loaded. The strict `isAfter` semantics are easy to forget — `isAfter(x)` where x equals the value is false, not true.
