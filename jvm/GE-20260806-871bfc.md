### Symptom
Need to add session logging to a data relay (FifoRelay) without modifying the relay class or adding a dependency on the logger.

### Context
`FifoRelay` takes an `InputStream` and a `Consumer<String> sink`. The relay reads bytes and calls `sink.accept(text)`. Adding a session log tee requires the data to go to both the WebSocket and the log file.

### Technique
Compose the sink at the call site instead of modifying `FifoRelay`:

```java
new FifoRelay(
    new FileInputStream(fifoPath),
    text -> {
        connection.sendTextAndAwait(text);
        sessionLogger.append(sessionName, text);
    }
).relay();
```

The relay stays unchanged — no new constructor parameter, no logger dependency, no conditional logic. The tee is a composition concern handled by the consumer of the relay, not the relay itself.

### Why this is non-obvious
The natural instinct is to modify FifoRelay to accept a second consumer or an optional logger. That approach spreads the logging concern into the relay class and creates a dependency from the relay to the logger. Functional composition at the call site keeps both classes focused and independent.
