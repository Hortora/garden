## Symptom

`No message codec for type: io.example.MyEvent` thrown at runtime when `eventBus.publish(address, myRecordInstance)` is called. Unit tests pass because Mockito's mock `EventBus` accepts any argument type without codec validation.

## Context

Publishing a Java record (or any custom POJO) on the Vert.x event bus in a Quarkus application. The `@ConsumeEvent` handler on the receiving end expects the custom type as its parameter. The code compiles, unit tests with mock `EventBus` pass, but the first real invocation at runtime throws.

## What was tried (didn't work)

Registering a custom `MessageCodec<MyEvent, MyEvent>` — works but adds boilerplate per event type. For simple data-carrier records this is over-engineering.

## Root cause

Vert.x event bus requires a registered `MessageCodec` for every non-standard type. Quarkus auto-registers codecs for `String`, `JsonObject`, `Buffer`, and Java primitives. Custom records are not auto-registered. Mock `EventBus` implementations (Mockito) bypass codec resolution entirely, so the mismatch is invisible in unit tests.

## Fix

Serialize the record to `JsonObject` before publishing. Deserialize in the `@ConsumeEvent` handler.

```java
// Publisher — serialize to JsonObject
var json = new JsonObject(MAPPER.writeValueAsString(event));
eventBus.publish(EventBusAddresses.MY_EVENT, json);

// Consumer — receive JsonObject, deserialize
@ConsumeEvent(EventBusAddresses.MY_EVENT)
@RunOnVirtualThread
public void onMyEvent(JsonObject message) {
    JsonNode root = MAPPER.readTree(message.encode());
    // extract fields from root
}
```

### Why this is non-obvious

The natural expectation is that Java records — which are immutable value objects with well-defined serialization — would be handled by the framework. The Quarkus documentation covers `@ConsumeEvent` with typed parameters but does not mention the codec requirement for custom types. The mock `EventBus` in unit tests actively hides the problem because `publish(String, Object)` accepts any `Object`.

### Alternatives considered

- Custom `MessageCodec` per event type: works but verbose, one codec class per record
- Vert.x `EventBusCodecConfigurator`: Quarkus-specific, requires build-time registration, adds deployment complexity
