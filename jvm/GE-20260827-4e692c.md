## Symptom

Flyway migration with `CREATE INDEX idx_name ON subclass_table(parent_column, subclass_column)` fails:

```
Column "PARENT_COLUMN" not found; SQL statement:
CREATE INDEX idx_name ON subclass_table(parent_column, subclass_column) [42122-240]
```

The column exists on the entity and is queryable via JPQL, but the DDL fails.

## Context

When using JPA `@Inheritance(strategy = InheritanceType.JOINED)`, the parent class columns live on the parent table and the subclass columns live on the subclass table. A subclass entity like `MessageLedgerEntry extends JpaLedgerEntry` has `tenancyId` on `ledger_entry` (parent) and `toolName` on `message_ledger_entry` (subclass).

JPQL queries like `WHERE e.tenancyId = :tid AND e.toolName = :tn` work because the ORM joins both tables transparently. But DDL-level indexes cannot span tables — a `CREATE INDEX` on the subclass table can only reference columns physically present on that table.

## What was tried (didn't work)

```sql
-- Fails: tenancy_id is on ledger_entry, not message_ledger_entry
CREATE INDEX idx_mle_tenancy_toolname ON message_ledger_entry(tenancy_id, tool_name);
```

## Root cause

In JOINED inheritance, each table in the hierarchy contains only its own declared columns plus the discriminator/PK join column. The parent's columns are not duplicated on the child table. SQL indexes are per-table and cannot reference columns from other tables.

## Fix

Index only the columns that physically exist on the subclass table:

```sql
-- Correct: tool_name is on message_ledger_entry
CREATE INDEX idx_mle_toolname ON message_ledger_entry(tool_name);
```

The parent table's columns (like `tenancy_id`) can be indexed on the parent table separately. The ORM's join handles the cross-table filter at query time.

## Why this is non-obvious

JPQL treats the entity as a flat object — `e.tenancyId` and `e.toolName` are accessed identically regardless of which table they're physically on. The mental model from JPQL doesn't map to DDL. The error message ("Column not found") is clear but doesn't explain WHY the column is absent — you have to know about JOINED inheritance table splitting.
