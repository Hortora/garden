### Symptom
Compilation error when annotating a class with `@CustomStringScalar("JSON")`: "incompatible types: cannot be converted to java.lang.annotation.Annotation".

### Context
Registering a custom GraphQL scalar type (e.g. JSON for `Map<String, Object>`) with SmallRye GraphQL in Quarkus.

### Root cause
The SmallRye GraphQL API has three similarly-named constructs that are easy to confuse:
- `@CustomScalar("name")` — this is the **annotation** (goes on the class)
- `CustomStringScalar` — this is an **interface** to implement (provides `stringValueForSerialization()`)
- `CustomIntScalar`, `CustomFloatScalar` — also **interfaces**, not annotations

The correct pattern is to use both:
```java
@CustomScalar("JSON")
public class Json implements CustomStringScalar {
    public Json(String json) { /* deserialization */ }

    @Override
    public String stringValueForSerialization() { /* serialization */ }
}
```

SmallRye discovers the class via `@CustomScalar`, and uses the `CustomStringScalar` interface method for serialization. The `String` constructor is used for deserialization.

### Why this is non-obvious
The class names `CustomStringScalar`, `CustomIntScalar`, `CustomFloatScalar` read as annotations — the `Custom*` prefix and `Scalar` suffix match Java annotation naming conventions. The actual annotation `@CustomScalar` is generic (no type-specific variants). SmallRye docs don't clearly explain the relationship between the annotation and the interfaces.
