### Symptom
A hand-written `META-INF/spring/AutoConfiguration.imports` file in `src/main/resources/` is silently replaced by a generated version with fewer entries. The JAR contains only the generated entries.

### Context
A Maven plugin calls `project.addResource(resource)` to register a generated directory containing a `META-INF/spring/AutoConfiguration.imports` file. The same file also exists in `src/main/resources/` (hand-written, with additional entries). After the build, only the generated version appears in the JAR.

### What was tried (didn't work)
1. `project.addResource(resource)` — appends the resource directory to the end of the list; `maven-resources-plugin` processes directories in list order, with later entries overwriting earlier ones

### Root cause
`maven-resources-plugin` copies resources from each directory in the `<resources>` list sequentially. When two directories contain a file at the same path, the last directory processed wins (simple file overwrite). `project.addResource()` appends to the end of the list, so programmatically-added resources overwrite `src/main/resources/` entries.

### Fix
Insert at position 0 so generated resources are processed first, and hand-written `src/main/resources/` entries overwrite them:

```java
project.getResources().add(0, resource);  // not project.addResource(resource)
```

This ensures:
- Modules with ONLY generated resources: generated file ends up in JAR (no overwrite)
- Modules with BOTH hand-written and generated resources: hand-written file wins (overwrites generated)

### Why this is non-obvious
`addResource()` is the standard API — using `getResources().add(0, ...)` for positional insertion is not documented as a pattern. The overwrite behaviour produces no warning; the hand-written file simply disappears from the JAR. The symptom (Spring Boot not discovering auto-configs) is far removed from the cause (resource processing order).
