### Context
When debugging a Quarkus extension, build step output (System.out, Logger) may not appear in test output. You need to confirm whether a build step is actually being invoked.

### Technique
Use `QuarkusUnitTest.assertException()` with a deliberate `RuntimeException` in the build step. The assertException callback receives the exception — if your message appears, the step ran; if the test fails with "build was expected to fail", the step was never invoked.

```java
@RegisterExtension
static final QuarkusUnitTest test = new QuarkusUnitTest()
    .withApplicationRoot(root -> root.addClasses(TestCase.class))
    .assertException(t -> {
        System.err.println("=== TYPE: " + t.getClass().getName());
        System.err.println("=== MSG: " + t.getMessage());
    });
```

In the build step:
```java
@BuildStep
@Produce(ServiceStartBuildItem.class)
void diagnostic() {
    throw new RuntimeException("DIAGNOSTIC: step is running");
}
```

### Why this is non-obvious
The natural debugging approach — adding log statements or System.out.println to the build step — produces no output when the step isn't invoked. Without assertException, you can't distinguish "step ran but produced no visible output" from "step was never called." The technique uses the exception as a guaranteed-visible signal.
