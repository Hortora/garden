### Symptom

`@Inject` fields referencing `@ApplicationScoped` beans from a test-scoped dependency fail with `UnsatisfiedResolutionException` during Quarkus augmentation, even when `quarkus.index-dependency.<name>.group-id` and `quarkus.index-dependency.<name>.artifact-id` are correctly configured in `application.properties`.

The error blocks ALL `@QuarkusTest` classes — not just the ones using the injected types — because CDI validation runs at augmentation time across all discovered injection points.

### Context

Adding `casehub-eidos-eval` (test scope) to a Quarkus project. The JAR contains `@ApplicationScoped` beans (`MbtiAlignmentJudge`, `FunctionActivationJudge`) but ships without `META-INF/jandex.idx`. A test class injects these beans via `@Inject`. The `quarkus.index-dependency` config is present and syntactically correct.

### What was tried (didn't work)

1. `quarkus.index-dependency.eidos-eval.group-id=io.casehub` + `artifact-id=casehub-eidos-eval` — beans still not discovered
2. `mvn clean test` — stale augmentation cache ruled out; same failure after clean build
3. Verified the beans exist in the JAR (decompiled, confirmed `@ApplicationScoped` annotation)

### Root cause

`quarkus.index-dependency` tells Quarkus to generate a Jandex index for a dependency at augmentation time. However, for test-scoped dependencies, the augmentation appears to skip the indexing step — the beans in the JAR are never added to the CDI bean archive. The non-eval test suite (which excludes the test class via `@Tag`) passes because the injection point is never validated.

### Fix

Create a `@Produces` bridge in test sources that constructs the beans via their public `@Inject` constructors:

```java
@ApplicationScoped
public class EvalJudgeProducer {

    @Produces
    @ApplicationScoped
    MbtiAlignmentJudge mbtiAlignmentJudge(@Any Instance<ChatModel> models,
                                           ObjectMapper mapper) {
        return new MbtiAlignmentJudge(models, mapper);
    }

    @Produces
    @ApplicationScoped
    FunctionActivationJudge functionActivationJudge(@Any Instance<ChatModel> models,
                                                     ObjectMapper mapper) {
        return new FunctionActivationJudge(models, mapper);
    }
}
```

The producer class lives in `src/test/java` (indexed by Quarkus augmentation since it's part of the project). It calls the beans' public constructors directly, passing CDI-resolved dependencies (`Instance<ChatModel>`, `ObjectMapper`). The producer satisfies the injection points without requiring the upstream JAR to be indexed.

### Why this is non-obvious

`quarkus.index-dependency` is the documented mechanism for discovering beans from unindexed JARs. It works for compile/runtime-scoped dependencies. The silent failure for test-scoped dependencies — no error, no warning, just `UnsatisfiedResolutionException` pointing at the injection target rather than the indexing failure — makes it look like the beans don't exist rather than that they weren't scanned.

### Alternatives considered

- **Adding `META-INF/jandex.idx` to the upstream JAR** — requires changing the upstream module's build. Correct long-term fix but not always feasible.
- **Reflection to call package-private constructors** — fragile, breaks on module boundaries, and couples the test to internal API.
- **CDI synthetic bean extension** — overly complex for test wiring.
