# EMA convergence ceiling masks reinforcement count

## Symptom
Behavioral attractors in a CAPS (Cognitive-Affective Processing System) simulation
were stuck at the "emerging" band (≤0.4 strength) and could never reach
"deep-rooted" (>0.7), regardless of how many times the pattern was reinforced.

## Context
The strength update formula was:
```java
newStrength = currentStrength * 0.7 + settlerOutput * 0.3
```

With a typical settler output of ~0.6 (logistic activation), this EMA converges
to exactly 0.6 — the 100th reinforcement produces the same strength as the 1st.

## Root cause
An EMA with fixed weights converges to the input signal value regardless of
repetition count. The mathematical ceiling is `settlerOutput / (1 - retention)
* (1 - retention) = settlerOutput`. No amount of reinforcement changes this.

The formula treats every observation as equally informative — there is no
mechanism for cumulative evidence to push strength above the signal ceiling.

## Fix
Add a reinforcement bonus scaled by observation count:
```java
double reinforcementBoost = Math.min(boostCap,
    Math.log1p(sourceCount) / Math.log1p(reinforcementScale));
double boostedStrength = Math.min(1.0,
    settlerOutput * (1 + reinforcementBoost));
newStrength = currentStrength * retention + boostedStrength * (1 - retention);
```

The `log1p` scaling creates diminishing returns consistent with the power law
of practice (Newell & Rosenbloom, 1981) — early reinforcements contribute more.

After 10 reinforcements with a settler output of 0.6: strength reaches ~0.75
("deep-rooted"), up from the previous ceiling of 0.6.

## Why this is non-obvious
The EMA formula looks correct — it's the standard exponential moving average.
The bug is mathematical, not logical: convergence to the input value is a
property of the formula, not a defect in the code. You only notice it when
you ask "why doesn't strength grow with repetition?" and trace the algebra.

### Alternatives considered
- Cumulative average (mean of all observations): loses recency weighting
- Bayesian updating: more complex, requires prior specification
- Simple counter-based boost: doesn't have diminishing returns
