# Maven APT classloader isolates Jandex indexes from compile dependencies

## Symptom
An annotation processor that scans Jandex indexes silently skips a `@McpDomain`
interface after it moves to a dependency module. No compilation error — the APT
simply reports zero domains found. The interface compiles fine (it's on the
compile classpath), but the APT can't see its Jandex index.

## Context
A Jandex-based APT loads indexes via `getClass().getClassLoader().getResources("META-INF/jandex.idx")`.
This classloader is the **annotation processor classpath**, which is populated
exclusively from `<annotationProcessorPaths>` in `maven-compiler-plugin` config.
It does NOT include the module's compile dependencies.

## Root cause
Maven maintains two separate classpaths during compilation:
1. **Compilation classpath** — all `<dependency>` entries (compile, provided, system scope)
2. **Annotation processor classpath** — only `<annotationProcessorPaths>` entries

`getClass().getClassLoader()` in an APT returns classpath #2. When an annotated
type moves from the current compilation unit to a dependency JAR, the APT's Jandex
scan stops finding it — even though `javac` can resolve the type for compilation.

## Fix
Add the dependency module to `<annotationProcessorPaths>` alongside the APT itself:

```xml
<annotationProcessorPaths>
    <path>
        <groupId>io.casehub</groupId>
        <artifactId>casehub-platform-graphql-generator</artifactId>
        <version>${casehub-platform-api.version}</version>
    </path>
    <path>
        <groupId>io.casehub</groupId>
        <artifactId>casehub-neocortex-cognitive-observability-core</artifactId>
        <version>${project.version}</version>
    </path>
</annotationProcessorPaths>
```

## Why this is non-obvious
The type compiles without error — `javac` resolves it from the compile classpath.
The APT runs without error — it just finds fewer indexes. The only symptom is a
missing generated file, which may not be noticed until a dependent module fails
to compile or a drift-detection verify goal flags the gap.

### Alternatives considered
- Using `processingEnv.getFiler()` with `StandardLocation.CLASS_PATH` — would see
  compile dependencies but Jandex has no built-in API for this; would require
  custom resource enumeration via the Filer API.
