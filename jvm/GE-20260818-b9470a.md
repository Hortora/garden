### Symptom
Adding `casehub-qhorus-push` (a new module) to claudony's `app/pom.xml` without a `<version>` tag causes:
```
'dependencies.dependency.version' for io.casehub:casehub-qhorus-push:jar is missing
```
Other qhorus dependencies (`casehub-qhorus`, `casehub-qhorus-api`, `casehub-qhorus-testing`) resolve fine without explicit versions.

### Context
Existing qhorus modules are already listed in the consuming project's parent POM `<dependencyManagement>` section with `${casehub.version}`. A newly-created module isn't in that list yet. Maven's dependency management inheritance means the version must be declared somewhere in the parent chain.

### Root cause
Maven `<dependencyManagement>` is explicit — each artifact must be listed individually. There is no wildcard or group-level version management. When a new module is created in a multi-module project (e.g. `casehub-qhorus-push` added to qhorus), every consuming project's parent POM needs a new `<dependency>` entry in its `<dependencyManagement>` section.

### Fix
Add the new module to the consuming project's parent POM:
```xml
<!-- In claudony/pom.xml <dependencyManagement> -->
<dependency>
    <groupId>io.casehub</groupId>
    <artifactId>casehub-qhorus-push</artifactId>
    <version>${casehub.version}</version>
</dependency>
```
Then the app module can use the dependency without an explicit version.

### Why this is non-obvious
The error only occurs for NEW modules — existing qhorus dependencies work fine, creating a false impression that "qhorus dependencies don't need versions." The fix (adding to parent POM) is in a different file from where the dependency was added (app POM), so it's easy to overlook.
