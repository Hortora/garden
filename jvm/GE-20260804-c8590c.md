## casehub-engine SNAPSHOT CDI drift — 4 new internal beans inject excluded CaseDefinitionRegistry

**Stack:** casehub-engine 0.2-SNAPSHOT, Quarkus 3.32.2

### Symptom

`@QuarkusTest` fails with CDI `DeploymentException: Found N deployment problems` — unsatisfied dependency for `CaseDefinitionRegistry` and/or `ContextOutputApplier`. Appears after pulling a new engine SNAPSHOT without updating `%test.quarkus.arc.exclude-types`.

### Context

Claudony (and any repo embedding casehub-engine) excludes `DefaultCaseDefinitionRegistry` in test profiles because the full engine runtime isn't active. When the engine adds new internal beans that inject `CaseDefinitionRegistry`, those beans must also be excluded — otherwise CDI finds them, tries to satisfy their dependencies, and fails.

### Root Cause

Engine SNAPSHOT (circa 2026-08-04) added four internal beans that inject `CaseDefinitionRegistry`:

1. `io.casehub.engine.internal.routing.GoalFailureRecorder` — injects `CaseDefinitionRegistry` directly
2. `io.casehub.engine.internal.routing.AgentGoalCompletionMarker` — injects `CaseDefinitionRegistry` directly
3. `io.casehub.engine.internal.engine.handler.ContextOutputApplier` — injects `CaseDefinitionRegistry` directly
4. `io.casehub.engine.internal.engine.handler.ScopedWorkerOutputHandler` — injects `ContextOutputApplier`

The fourth bean creates a **second-order dependency chain**: excluding `ContextOutputApplier` without also excluding `ScopedWorkerOutputHandler` produces a *different* unsatisfied dependency error (for `ContextOutputApplier` itself, from `ScopedWorkerOutputHandler`'s injection point). Both must be excluded together.

### Fix

Add all four to `%test.quarkus.arc.exclude-types` in `src/test/resources/application.properties`:

```properties
%test.quarkus.arc.exclude-types=...,\
  io.casehub.engine.internal.routing.GoalFailureRecorder,\
  io.casehub.engine.internal.routing.AgentGoalCompletionMarker,\
  io.casehub.engine.internal.engine.handler.ContextOutputApplier,\
  io.casehub.engine.internal.engine.handler.ScopedWorkerOutputHandler
```

### Why this is non-obvious

The error message for `ScopedWorkerOutputHandler` says "unsatisfied dependency for type `ContextOutputApplier`" — which looks like `ContextOutputApplier` is the problem. But excluding `ContextOutputApplier` alone triggers the second-order error from `ScopedWorkerOutputHandler`. You must trace the full injection graph to find all beans in the chain.

### Alternatives considered

- Adding `CaseDefinitionRegistry` as a `@DefaultBean` in the test context: rejected because the registry requires case meta-model loading infrastructure that isn't available in embedding repos' test profiles.
