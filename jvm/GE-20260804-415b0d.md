## qhorus MessageReceivedEvent lives in api.gateway not api.message

### Symptom

Test compilation fails with `cannot find symbol: class MessageReceivedEvent` when importing `io.casehub.qhorus.api.message.MessageReceivedEvent`.

### Context

Writing a CDI observer or `MessageObserver` implementation that receives qhorus message events. The `io.casehub.qhorus.api.message` package contains `Message`, `MessageType`, and other message-related types — but not `MessageReceivedEvent`.

### Root cause

qhorus-api splits message-related types across two packages:

| Package | Contains | Role |
|---------|----------|------|
| `io.casehub.qhorus.api.message` | `Message`, `MessageType`, `ArtefactRef` | Stored records — what persists in the message store |
| `io.casehub.qhorus.api.gateway` | `MessageReceivedEvent`, `OutboundMessage`, `InboundHumanMessage`, `NormalisedMessage` | Transport events — what flows through the gateway and CDI |

`MessageReceivedEvent` is a transport event (fired by the gateway when a message is received), not a stored record. It lives in `gateway`, not `message`.

An additional naming trap: `MessageReceivedEvent` has `occurredAt()` but the `Message` record it wraps has `createdAt()`. Both refer to the same timestamp — the naming diverges because `occurredAt` is the event-time concept (when the event fired) while `createdAt` is the persistence concept (when the record was written).

### Fix

Use the correct import:

```java
// Wrong — compiles to nothing
import io.casehub.qhorus.api.message.MessageReceivedEvent;

// Correct
import io.casehub.qhorus.api.gateway.MessageReceivedEvent;
```

### Why this is non-obvious

The `message` package contains every other message-related type a developer needs (`Message`, `MessageType`). The natural assumption is that `MessageReceivedEvent` — which is semantically about messages — would be there too. The `gateway` package name suggests infrastructure plumbing, not domain events.
