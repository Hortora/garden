### Symptom
Testing push-based features requires intercepting `broadcast()` calls to verify topics and payloads. Creating a real `EventBroadcaster` requires four dependencies (`EventStore`, `TopicRegistry`, `SessionSender`, `JsonWriter`) — verbose setup even with minimal implementations.

### Context
`EventBroadcaster` is the central class for server→client push in CaseHub Pages. Tests for features built on top (e.g. `AriaCommandBridge`, scenario dispatch) need to verify that the correct topic and payload were broadcast without actually sending anything over WebSocket.

### Fix
`EventBroadcaster` is not final — subclass it with capturing overrides:

```java
var capturedTopic = new AtomicReference<String>();
EventBroadcaster broadcaster = new EventBroadcaster(
        new InMemoryEventStore(100),
        new TopicRegistry(),
        (connId, msg) -> {},   // no-op SessionSender
        obj -> "{}")           // no-op JsonWriter
{
    @Override
    public <T> long broadcast(String topic, T event) {
        capturedTopic.set(topic);
        return 1L;
    }
};
```

The constructor still requires real objects (can't pass nulls — `Objects.requireNonNull`), but they can be minimal: `InMemoryEventStore(100)` for the store, `new TopicRegistry()` for the registry, and lambdas for the functional interfaces.

The override captures the topic without involving the event store, topic registry, or session sender. Test assertions check `capturedTopic.get()`.

### Why this is non-obvious
The class looks like it should be final — it's a simple delegation class with no intended extension points. The natural testing approach is to use a mocking framework (Mockito). But subclassing gives type-safe interception without adding a test dependency, and the override is cleaner than `when(mock.broadcast(...)).thenReturn(...)` for the generic `<T>` method.
