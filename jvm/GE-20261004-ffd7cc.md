## Symptom

`UnknownEntityException` for entities that are on the classpath and have a Jandex index, after a library restructures entities from a flat package into subpackages.

Example: `io.casehub.qhorus.runtime.channel.ChannelEntity` is not found when the Hibernate config lists `io.casehub.qhorus.runtime`.

## Context

Occurs when:
- An upstream library moves JPA entities from `com.example.runtime` to subpackages like `com.example.runtime.channel`, `com.example.runtime.data`
- The consuming app has `quarkus.hibernate-orm.packages=com.example.runtime`
- The app expects subpackage entities to be included in the scan

## What was tried

- Verified the entity JAR has a Jandex index — entities are indexed
- Verified the entity class has `@Entity` annotation — correct
- Assumed `com.example.runtime` would include `com.example.runtime.channel` via prefix matching — it does not

## Root cause

Quarkus `quarkus.hibernate-orm.packages` (and `quarkus.hibernate-orm.<name>.packages`) uses exact package matching, not prefix matching. An entity in `com.example.runtime.channel` is NOT matched by listing `com.example.runtime`.

Each package containing JPA entities must be listed individually.

## Fix

List every subpackage explicitly:

```properties
quarkus.hibernate-orm.qhorus.packages=io.casehub.qhorus.runtime,\
  io.casehub.qhorus.runtime.channel,\
  io.casehub.qhorus.runtime.data,\
  io.casehub.qhorus.runtime.gateway,\
  io.casehub.qhorus.runtime.instance,\
  io.casehub.qhorus.runtime.message
```

## Why this is non-obvious

Most package-scanning mechanisms (Spring component scan, CDI bean discovery, Jandex indexing) use prefix matching — listing a parent package includes all children. Quarkus Hibernate ORM's `packages` config breaks this expectation with exact matching. No warning is emitted for entities in subpackages that are not scanned.
