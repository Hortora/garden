### Symptom
GraphQL schema validation fails at startup:
```
InvalidSchemaException: invalid schema:
"Object" must define one or more fields.
"ObjectInput" must define one or more fields.
```

### Context
Occurs when a `@Type` or `@Input` record has a field of type `Map<String, Object>`.
SmallRye GraphQL attempts to map `Object` as a GraphQL type and `Object` as an input
type — both are empty (no fields) which violates the GraphQL spec.

### Root cause
SmallRye GraphQL's type introspection treats `Map<String, Object>` as a complex type
with key type `String` and value type `Object`. `Object` has no public fields or
getters, so the generated GraphQL type `Object` is empty. The schema validator then
rejects it.

### Fix
Use a `Json` custom scalar instead of `Map<String, Object>`:

```java
// Before — fails schema validation
@Type("LedgerEntry")
public record LedgerEntryType(
        Map<String, Object> domainData) { }

// After — works
@Type("LedgerEntry")
public record LedgerEntryType(
        Json domainData) { }
```

Where `Json` is a `@CustomScalar("JSON")` type that wraps `Map<String, Object>`
and serializes via Jackson. When passing to service methods that expect
`Map<String, Object>`, unwrap with `.value()`.

### Why this is non-obvious
`Map<String, Object>` is the natural Java representation for arbitrary JSON.
It works fine in REST endpoints (Jackson handles it). The failure only occurs
in GraphQL because SmallRye introspects the value type — and `Object` produces
an empty schema type. The error message ("Object must define one or more fields")
doesn't hint at `Map<String, Object>` being the cause.
