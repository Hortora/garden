### Symptom
Events silently disappear when a `ContentSummariser` wrapper skips invocation (e.g. a concurrency guard that returns the previous result while a prior call is in-flight). No error logged — events are simply gone.

### Context
When composing a `SummarisationRunner` with a `ContentSummariser` wrapper that conditionally skips invocation (returning cached/previous result), events accumulated in the `EventAccumulator` are lost.

### Root cause
`SummarisationRunner.tickWithPolicy()` executes in this order:
1. `peekBuffer()` — check emission policy (non-destructive)
2. `accumulator.drain()` — **removes all events from the buffer**
3. Invoke the summariser with the drained batch

If the summariser wrapper decides to skip (returns previous result without processing), the drained events have already been removed from the accumulator. They cannot be re-buffered — the `EventAccumulator` has no `undrain()` or `putBack()` method.

### What was tried (didn't work)
Wrapping `ContentSummariser` to track in-flight status and skip when a previous call is pending:
```java
public class InFlightGuard<E, R> implements ContentSummariser<E, R> {
    public CompletionStage<R> summarise(List<E> items, R previous) {
        if (inflight != null && !inflight.toCompletableFuture().isDone())
            return CompletableFuture.completedFuture(previous); // LOSES items
        var stage = delegate.summarise(items, previous);
        inflight = stage;
        return stage;
    }
}
```
This returns the previous result but the `items` list (the drained batch) is discarded.

### Fix
Gate at the `EmissionPolicy` level instead of the `ContentSummariser` level. By suppressing emission, the drain never happens:

```java
public class InFlightGate<E, R> {
    private final ContentSummariser<E, R> delegate;
    private volatile CompletionStage<?> inflight;

    public ContentSummariser<E, R> summariser() {
        return (items, previous) -> {
            var stage = delegate.summarise(items, previous);
            inflight = stage;
            return stage;
        };
    }

    public <S> EmissionPolicy<E, S> gating(EmissionPolicy<E, S> policy) {
        return (buffer, state, now) -> {
            if (inflight != null && !inflight.toCompletableFuture().isDone())
                return false; // suppress emission — accumulator keeps events
            return policy.shouldEmit(buffer, state, now);
        };
    }
}
```

Wire into the runner:
```java
var gate = new InFlightGate<>(delegate);
var runner = SummarisationRunner.builder(gate.summariser().asSummariser(), bus, level)
    .emissionPolicy(gate.gating(windowPolicy))
    .build();
```

### Why this is non-obvious
The natural pattern for adding skip-logic to a processing pipeline is to wrap the processor. Every other aspect of `SummarisationRunner` composition (compaction, state management, output processing) works by wrapping or composing with the `Summariser`. The drain-before-invoke ordering is an internal implementation detail that makes the processor-wrapper approach silently destructive.
