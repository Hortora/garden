### Symptom
Quarkus extension build steps are listed in `META-INF/quarkus-build-steps.list` (generated by `quarkus-extension-processor`) but are never invoked. The Quarkus application starts normally, build steps from other extensions run, but your extension's steps are silently ignored.

### Context
Writing a Quarkus extension with the standard deployment/runtime module split. The deployment module has `quarkus-extension-processor` configured and generates `quarkus-build-steps.list`. The runtime module exists and is on the classpath. But the runtime module lacks `META-INF/quarkus-extension.properties`.

### What was tried (didn't work)
- Verified `quarkus-build-steps.list` exists with correct class names
- Added `quarkus-extension.yaml` to deployment module only
- Checked classloading — all classes loadable

### Root cause
Quarkus discovers extensions by scanning the classpath for `META-INF/quarkus-extension.properties` in runtime JARs. This file tells Quarkus which deployment artifact to load. Without it, the runtime JAR is treated as a regular dependency, not an extension — and its deployment module's build steps are never loaded.

### Fix
Create `src/main/resources/META-INF/quarkus-extension.properties` in the runtime module:

```properties
deployment-artifact=io.example\:my-extension-deployment
```

And optionally `META-INF/quarkus-extension.yaml`:

```yaml
name: my-extension
description: My Quarkus extension
metadata:
  status: preview
```

### Why this is non-obvious
The `quarkus-extension-processor` successfully generates `quarkus-build-steps.list` in the deployment JAR — everything appears configured correctly. The missing properties file in the runtime JAR is a separate requirement that is easy to overlook, and produces no error message when absent.
