### Symptom
`IllegalArgumentException: No enum constant com.example.UnitType.BUNKER` at CDI `@PostConstruct` init time. The exception names the missing enum value but gives no indication which YAML entry referenced it — in a 2000+ line YAML file with 58 top-level entries, each containing nested lists of enum references.

### Context
A YAML taxonomy file maps strategy archetypes to counter-unit recommendations. Each counter entry references unit types by enum name. The enum models mobile combat units but not buildings (Bunker, Spine Crawler, Photon Cannon). When authoring counter advice, buildings feel like natural counter units — "build a Bunker at the natural" — but `UnitType.valueOf("BUNKER")` throws because buildings aren't in the enum.

The parsing loop in `@PostConstruct init()` iterates all YAML entries and calls `UnitType.valueOf()` on each unit name. The first invalid reference fails the entire init with no context about which archetype or which counter section caused it.

### Root cause
The enum models a **subset** of the domain's entity types (mobile units only, not buildings). YAML data authoring naturally references the full domain. `Enum.valueOf()` provides no source-location context — the exception message is `"No enum constant <fully.qualified.EnumType>.<VALUE>"` with no reference to the YAML key, line number, or surrounding context.

### Fix
Wrap `valueOf()` calls with context-aware error handling that names the YAML entry being parsed:

```java
try {
    archetype = StrategyArchetype.valueOf(key);
} catch (IllegalArgumentException e) {
    throw new IllegalStateException(
        "YAML key '" + key + "' does not match any StrategyArchetype enum value");
}
```

For counter unit references specifically: use the nearest mobile unit equivalent (e.g. MARAUDER instead of BUNKER) when the domain entity is outside the enum's scope. Document which entities are excluded so future authors don't rediscover the gap.

### Why this is non-obvious
The YAML file is the authoring interface — authors think in domain terms ("counter with a Bunker"), not enum terms ("is BUNKER a valid UnitType value?"). The error surfaces at application startup (`@PostConstruct`), far from the authoring site, and the stack trace points to the parsing code, not the YAML content. In a large YAML file, binary-searching for the offending entry is the only diagnostic path.
