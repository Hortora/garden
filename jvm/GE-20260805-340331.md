## Symptom

Bean guarded by `@UnlessBuildProperty` (or `@IfBuildProperty`) with a required `@ConfigProperty` causes `DeploymentException` when the config property doesn't exist — even though the bean should never be instantiated.

```
Caused by: jakarta.enterprise.inject.spi.DeploymentException:
  io.quarkus.runtime.configuration.ConfigurationException:
  Failed to load config value of type class java.lang.String for: my.config.url

Suppressed: java.util.NoSuchElementException: SRCFG00014:
  The config property my.config.url is required but it could not be found
```

## Context

Happens when a CDI bean has conditional activation (`@UnlessBuildProperty`, `@IfBuildProperty`) AND injects a non-optional config property. Quarkus validates ALL `@ConfigProperty` injections at build time as part of `ConfigRecorder.validateConfigProperties()`, regardless of whether the bean is activated by its build property guard.

## Root Cause

Config property validation and bean activation are separate build steps in Quarkus. The validation step runs against ALL beans that have `@ConfigProperty` injections — it does not filter by bean activation status. The bean may be excluded from CDI resolution, but its config properties are still validated.

## Fix

Declare the config property as `Optional<String>` instead of `String`. Handle the empty case in the method body:

```java
@Inject
public MyBean(@ConfigProperty(name = "my.config.url") Optional<String> url) {
    this.url = url.orElse("");
}

@Override
public List<Result> doWork() {
    if (url.isEmpty()) return List.of();  // graceful degradation
    // ... use url
}
```

## Why this is non-obvious

The `@UnlessBuildProperty` annotation's documentation implies it controls whether the bean is activated at all — a developer would reasonably expect that if the bean isn't activated, its config properties wouldn't be validated. The error message points to the config property, not the bean activation guard, making it look like a config file issue rather than an annotation interaction issue.

### Alternatives considered

- `defaultValue = ""` on `@ConfigProperty` — doesn't work; Quarkus still validates the property exists before applying defaults in some code paths
- Setting the property to empty in test `application.properties` — works but activates the bean unconditionally
