### Symptom
`new TrustScoreSnapshot()` in a unit test fails with `TrustScoreSnapshot() has protected access`. The entity's public fields (`occurredAt`, `score`, `previousScore`) are accessible but the constructor is not.

### Context
JPA entities follow the Hibernate convention of a protected no-arg constructor — accessible to the persistence provider via reflection but not to application code. In integration tests (`@QuarkusTest`), entities are created by the persistence layer. In pure unit tests with Mockito mocks, you need to construct entities directly to set up test data.

### Fix
Use an anonymous subclass to access the protected constructor:

```java
private static TrustScoreSnapshot snapshot(Instant occurredAt, double score, double prev) {
    return new TrustScoreSnapshot() {{
        this.occurredAt = occurredAt;
        this.score = score;
        this.previousScore = prev;
    }};
}
```

The anonymous subclass is in the same package hierarchy, so it can access the protected constructor. The double-brace initialiser sets the public fields.

### Why this is non-obvious
The immediate instinct is to use Mockito (`mock(TrustScoreSnapshot.class)`) but JPA entities have public fields, not getters — Mockito can't stub field access. The other instinct is to use reflection (`Constructor.setAccessible(true)`) which works but is verbose. The anonymous subclass pattern is the shortest path.
