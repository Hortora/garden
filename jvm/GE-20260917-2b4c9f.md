### Symptom

All tests fail with `IllegalStateException` before any test method runs:

```
Caused by: java.lang.IllegalStateException:
  Unable to retrieve @EnableAutoConfiguration base packages
    at org.springframework.boot.autoconfigure.AutoConfigurationPackages.get(AutoConfigurationPackages.java:78)
```

### Context

When writing `@DataJpaTest` tests in a library module (e.g. a Spring Data JPA adapter module) that has no `@SpringBootApplication` class. The module only contains repository interfaces, store implementations, and auto-configuration — no application entry point.

### What was tried (didn't work)

- Adding `@EnableJpaRepositories` alone — still needs base packages for auto-configuration
- Adding a test-only `@SpringBootApplication` class — works but creates a confusing package-scanning anchor that may pick up unrelated beans

### Root cause

`@DataJpaTest` triggers `JpaRepositoriesAutoConfiguration` which calls `AutoConfigurationPackages.get()` to discover repository base packages. Without a `@SpringBootApplication` (which implicitly registers `@AutoConfigurationPackage`), the base packages are never registered and the lookup throws.

### Fix

Add three annotations to the test `@Configuration` class:

```java
@Configuration
@AutoConfigurationPackage
@EnableJpaRepositories(basePackageClasses = MyRepository.class)
@EntityScan(basePackageClasses = MyEntity.class)
static class TestConfig {
    // bean definitions
}
```

- `@AutoConfigurationPackage` registers the test config's package as the auto-configuration base
- `@EnableJpaRepositories` explicitly declares where to find repository interfaces
- `@EntityScan` explicitly declares where to find JPA entity classes

### Why this is non-obvious

Most Spring Boot testing documentation assumes a `@SpringBootApplication` class exists. Library modules that publish auto-configuration but have no main class fall outside this assumption. The error message ("Unable to retrieve base packages") doesn't suggest that the fix is adding `@AutoConfigurationPackage` — it sounds like a classpath issue rather than a missing annotation.
