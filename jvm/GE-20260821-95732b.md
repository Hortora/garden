### Symptom
A nested DagDriver (executing a contingency sub-plan inside a parent plan's node failure handler) has its own `volatile boolean cancelled` field. When the parent driver is cancelled, the nested driver continues to completion unaware — side-effecting tasks execute during a window that should be cancelled.

### Context
`DagDriver` is a single-use DAG executor. When a node fails and has a contingency sub-plan, a nested DagDriver executes the contingency inline. The parent and nested drivers need to share cancellation state.

### Technique
Replace the `volatile boolean cancelled` field with an `AtomicBoolean cancelSignal` shared via constructor injection:

```java
public class DagDriver<T, R> {
  private final AtomicBoolean cancelSignal;

  // Public constructor — creates its own signal
  public DagDriver(DagPlan<T> plan, DispatchMode mode, List<DagEventListener<T, R>> listeners) {
    this(plan, mode, listeners, new AtomicBoolean(false));
  }

  // Package-private — shares parent's signal
  DagDriver(DagPlan<T> plan, DispatchMode mode, List<DagEventListener<T, R>> listeners,
            AtomicBoolean cancelSignal) {
    this.cancelSignal = cancelSignal;
  }

  public void cancel() {
    cancelSignal.set(true);  // both parent and nested see this immediately
  }
}
```

The nested driver is constructed with the parent's `cancelSignal`:
```java
var contingencyDriver = new DagDriver<>(node.contingency(), mode, List.of(), cancelSignal);
```

### Why this is non-obvious
The straightforward approaches are either (a) tracking active child drivers and calling `cancel()` on each when the parent cancels (complex bookkeeping, race conditions on the active-children set), or (b) checking the parent's cancellation flag after the nested execution completes (misses the cancellation window — tasks execute during it). The `AtomicBoolean` constructor injection is simpler: zero bookkeeping, immediate propagation, and the package-private constructor keeps the sharing mechanism out of the public API.

### Alternatives considered
- **Tracking active child drivers** — requires a `ConcurrentHashMap<String, DagDriver>` or similar, with registration/deregistration on every contingency activation. Race condition between cancel() iterating the map and a new nested driver being added.
- **Post-execution cancel check** — only discards the result after the nested plan completes, allowing expensive side-effecting tasks to run during the cancellation window
- **Thread interruption** — doesn't compose well with virtual threads and `CompletableFuture.allOf().join()`, which catch `InterruptedException` internally
