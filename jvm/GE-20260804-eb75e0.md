### Symptom

Cannot compute merge keys, similarity scores, or feature-based grouping from `CbrCaseMemoryStore.scan()` results.

### Context

Building a batch compaction job that needs to group CBR cases by categorical feature values. `scan()` seemed like the right API for iterating all cases in a domain.

### Root cause

`CbrCaseSummary` (returned by `scan()`) contains only metadata:
```java
record CbrCaseSummary(String caseId, String entityId, String caseType,
                       String producerAgentId, Double trustScore, Instant storedAt)
```

No `features` field. No way to access the case's feature data from scan results alone.

### Fix

Use `retrieveSimilar()` with a broad query instead of `scan()`:

```java
var query = CbrQuery.of(tenantId, domain, Path.root(), caseType, Map.of(), 10000)
    .withMinSimilarity(0.0);
List<ScoredCbrCase<PlanCbrCase>> allCases = store.retrieveSimilar(query, PlanCbrCase.class);
```

An empty feature map with `minSimilarity(0.0)` returns all cases in the domain with their full feature data. Acceptable for weekly batch jobs on bounded case sets.

### Why this is non-obvious

`scan()` is the natural API for iterating all cases. Its paginated cursor interface suggests it's designed for bulk operations. But it returns summaries, not full cases — a deliberate design choice for memory efficiency that isn't documented in the interface javadoc.
