## PostgreSQL JSONB column rejects varchar binding from JPA AttributeConverter

**ID:** GE-20260812-10117e
**Stack:** Hibernate 6, PostgreSQL, JPA, Quarkus
**Symptom:** `PSQLException: column domain_data is of type jsonb but expression is of type character varying`. The JSON content is valid — the error is about how Hibernate binds the converter output to the JDBC parameter, not about the data itself.
**Context:** Occurs when a JPA entity uses `AttributeConverter<Map<String, Object>, String>` to serialize a Map to JSON, and the target column is defined as `JSONB` in the Flyway migration or DDL.

### What was tried (didn't work)
- Using `@Convert(converter = JsonMapConverter.class)` with a String-returning AttributeConverter — PostgreSQL rejects the binding
- Adding `?stringtype=unspecified` to the JDBC URL — works as a workaround but changes behavior for all string parameters globally

### Root cause
Hibernate's `AttributeConverter` with a `String` database column type uses `PreparedStatement.setString()` to bind the converted value. PostgreSQL's JDBC driver sends this as a `varchar` type to the server. PostgreSQL's type system is strict: `JSONB` columns require values bound via `PGobject` with type set to `jsonb`. The JDBC driver does not perform implicit `varchar -> jsonb` casting.

### Fix
Two options depending on requirements:

**Option A — Use TEXT column type (simplest):**
Change the Flyway migration to use `TEXT` instead of `JSONB`. The data is still valid JSON stored as text. AttributeConverter works correctly with TEXT columns.

```sql
-- V1__create_table.sql
CREATE TABLE my_entity (
    id UUID PRIMARY KEY,
    domain_data TEXT  -- not JSONB
);
```

**Option B — Use Hibernate's @JdbcTypeCode (keeps JSONB semantics):**
Replace AttributeConverter with Hibernate's native JSON type mapping. This preserves GIN indexing and containment query support.

```java
@JdbcTypeCode(SqlTypes.JSON)
@Column(columnDefinition = "jsonb")
private Map<String, Object> domainData;
```

### Alternatives considered
- `?stringtype=unspecified` JDBC URL parameter — works but is a global setting that can mask type errors elsewhere in the application
- Custom `UserType` implementing `PGobject` binding — correct but significantly more code than either option above

### Why this is non-obvious
The `AttributeConverter` API contract says: convert to `String`, Hibernate persists the `String`. This works on H2, MySQL, and other databases. PostgreSQL's strict type system breaks the contract silently — the error message points at the column type mismatch, not at the binding mechanism. A developer debugging this will try fixing the JSON content or the converter logic, when the actual problem is at the JDBC binding layer below the converter.
