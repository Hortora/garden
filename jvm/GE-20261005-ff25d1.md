### Symptom
Quarkus application fails at startup with:
```
io.smallrye.config.ConfigValidationException: Configuration validation failed:
SRCFG00050: casehub.knowledge.sqlite.path does not map to any root
```
despite the property being used correctly with `@ConfigProperty(name = "casehub.knowledge.sqlite.path")` on a CDI producer method.

### Context
Occurs when a `@ConfigMapping(prefix = "casehub.knowledge")` interface exists AND a `@ConfigProperty` injects a key under the same prefix. SmallRye Config validates that ALL keys under a mapped prefix belong to the mapping interface. Orphan keys are rejected.

### What was tried (didn't work)
- Using `@ConfigProperty` alongside `@ConfigMapping` on the same prefix — rejected at startup
- Overriding via `overrideConfigKey()` in QuarkusUnitTest — same validation error

### Root cause
SmallRye Config performs exhaustive validation of config keys against `@ConfigMapping` roots. When `casehub.knowledge` is declared as a `@ConfigMapping` prefix, every key under `casehub.knowledge.*` must map to a field in the interface hierarchy. `@ConfigProperty` keys under the same prefix are treated as unmapped and rejected.

### Fix
Move all config properties into the `@ConfigMapping` interface hierarchy. Replace `@ConfigProperty(name = "casehub.knowledge.sqlite.path")` with a nested interface:
```java
@ConfigMapping(prefix = "casehub.knowledge")
public interface KnowledgePipelineConfig {
    SqliteConfig sqlite();
    interface SqliteConfig {
        @WithDefault("knowledge-pipeline.db") String path();
    }
}
```
Then inject via `config.sqlite().path()` instead of `@ConfigProperty`.

### Why this is non-obvious
`@ConfigMapping` and `@ConfigProperty` are both legitimate config injection mechanisms in Quarkus. Nothing in the documentation warns that using both on the same prefix is invalid. The error message (`does not map to any root`) doesn't mention `@ConfigProperty` at all — it reads as if the property is misspelled rather than architecturally rejected.
