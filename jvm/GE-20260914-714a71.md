# Java APT without -parameters flag produces positional arg0/arg1 names in generated REST query parameters

## Symptom
APT-generated JAX-RS resources use `@QueryParam("arg0")`, `@QueryParam("arg1")`,
`@PathParam("arg0")` instead of meaningful names like `@QueryParam("subjectId")`,
`@QueryParam("tenancyId")`.

## Context
When an annotation processor generates REST resources from SPI interfaces, it reads
method parameter names from the compiled interface class files. Without the
`-parameters` javac flag, parameter names are not stored in the bytecode — the
compiler uses positional names (`arg0`, `arg1`, `arg2`).

## Root cause
By default, `javac` does not include method parameter names in `.class` files. The
`-parameters` flag enables this. When the APT processor reads the SPI interface via
`javax.lang.model`, parameter names are only available if:
1. The source is being compiled in the same compilation unit, OR
2. The class was compiled with `-parameters`

When the SPI interface is in a separate module (e.g. `api/` jar on the
`annotationProcessorPaths`), the APT sees the compiled class without parameter
names.

## Fix
Add `-parameters` to the Maven compiler configuration for the module containing
the SPI interfaces:

```xml
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-compiler-plugin</artifactId>
  <configuration>
    <parameters>true</parameters>
  </configuration>
</plugin>
```

This must be set on the **SPI interface module** (the one being read by the APT),
not on the module where the APT runs. The generated code in the consumer module
will then use the real parameter names.

### Why this is non-obvious
The developer sets up APT in the consumer module and assumes parameter names
propagate from the SPI interface. The compilation succeeds — the generated code
is syntactically correct with `arg0`/`arg1` names. The issue only surfaces when
inspecting the generated REST API (ugly query params) or when clients try to use
named parameters. There is no compilation warning.
