## quarkus.arc.exclude-types only excludes CLASS beans — producer methods on non-excluded beans still activate

**ID:** GE-20261006-56b2b7
**Stack:** Quarkus 3.39.x, Quarkus Arc CDI
**Symptom:** `AmbiguousResolutionException` persists after adding the ambiguous type to `quarkus.arc.exclude-types`. Two beans remain: a CLASS bean and a PRODUCER METHOD bean returning the same type.
**Context:** When a `@DefaultBean @Produces` method on a non-excluded declaring class creates a bean of the excluded type. Common with platform-level `DefaultBeans` classes that produce mock/no-op implementations.

### What was tried (didn't work)
- Added `MockGroupMembershipProvider` to `quarkus.arc.exclude-types` — ambiguity persists
- The CLASS bean (`NoOpGroupMembershipProvider`) was properly discovered; the PRODUCER METHOD bean (`DefaultBeans.mockGroupMembershipProvider()`) was NOT excluded

### Root cause
`quarkus.arc.exclude-types` removes types from Quarkus Arc's bean archive during discovery. This prevents a CLASS from being discovered as a bean. However, producer methods on NON-excluded declaring beans are unaffected — even if the producer's return type matches an excluded type. The producer method on `DefaultBeans` still creates a `MockGroupMembershipProvider` bean because `DefaultBeans` itself is not excluded.

### Fix
Exclude the OTHER bean (the CLASS bean) instead of the producer-method-produced bean:

```properties
# Wrong — excludes the CLASS but the producer method on DefaultBeans still creates it
quarkus.arc.exclude-types=io.casehub.platform.mock.MockGroupMembershipProvider

# Right — exclude the CLASS bean that competes with the producer
quarkus.arc.exclude-types=io.casehub.work.runtime.service.NoOpGroupMembershipProvider
```

The `@DefaultBean` producer will then be the sole provider — no ambiguity.

Alternative: exclude the entire declaring class (`DefaultBeans`) — but this removes all its producer methods, which may break other injections.

### Why this is non-obvious
The intuition is "exclude the type you don't want" — but `exclude-types` operates on bean discovery, not on the type system. Producer methods are discovered through their declaring class, not through their return type. The Quarkus documentation describes `exclude-types` as excluding "bean classes" but doesn't clarify that producer methods on non-excluded classes are unaffected.
