## Symptom

Kotlin code importing `com.intellij.platform.lsp.api.LspServerSupportProvider` or
`com.intellij.platform.lsp.api.ProjectWideLspServerDescriptor` fails to compile with
"Unresolved reference 'lsp'" when building against IntelliJ Community Edition (IC).

Adding `bundledModule("intellij.platform.lsp")` to Gradle dependencies produces
"Specified bundledModule 'intellij.platform.lsp' doesn't exist."

## Context

The IntelliJ Platform documentation describes `com.intellij.platform.lsp` as available
since 2023.2. The API exists and is documented, but the module is only bundled in
IntelliJ Ultimate and other paid JetBrains IDEs — not in Community Edition.

Searching all JARs in the IC distribution (`lib/` and `plugins/`) for `LspServer` finds
only `com.intellij.internal.sandbox.LSPServer` — an internal sandbox class, not the
public LSP API.

## What was tried (didn't work)

1. `bundledModule("intellij.platform.lsp")` — module doesn't exist in IC
2. `bundledPlugin("com.intellij.platform.lsp")` — not a plugin either
3. Searching all JARs with `unzip -l` for `LspServerSupportProvider` — not found

## Root cause

The `com.intellij.platform.lsp` module is shipped exclusively with IntelliJ Ultimate
(IU) and other paid products. IntelliJ Community (IC) does not include it. The
JetBrains documentation does not clearly indicate this edition restriction.

## Fix

Use **LSP4IJ** (Red Hat, plugin ID `com.redhat.devtools.lsp4ij`) instead of the
built-in LSP API. LSP4IJ works across all IntelliJ flavours including Community.

```kotlin
// build.gradle.kts
dependencies {
    intellijPlatform {
        intellijIdeaCommunity("2024.2")
        plugin("com.redhat.devtools.lsp4ij", "0.20.1")
    }
}
```

```xml
<!-- plugin.xml -->
<depends>com.redhat.devtools.lsp4ij</depends>
<extensions defaultExtensionNs="com.redhat.devtools.lsp4ij">
    <server id="my-server" name="My Server"
            factoryClass="com.example.MyLanguageServerFactory"/>
    <fileNamePatternMapping patterns="*.my.yaml"
                            serverId="my-server" languageId="yaml"/>
</extensions>
```

LSP4IJ provides `LanguageServerFactory` and `OSProcessStreamConnectionProvider`
as the equivalents of `LspServerSupportProvider` and `LspServerDescriptor`.

## Why this is non-obvious

The JetBrains documentation for `com.intellij.platform.lsp` does not prominently
indicate that the API is only available in Ultimate. A developer reasonably assumes
that a documented platform API works in Community, especially since Community
supports plugin development as a first-class use case.

### Alternatives considered

- **Extend yaml-language-server**: rejected because CaseHub YAML uses discriminated
  unions that yaml-language-server's JSON Schema oneOf handling flattens incorrectly.
- **LSP4J library directly**: lower-level, more code to write, less IntelliJ
  integration than LSP4IJ.
