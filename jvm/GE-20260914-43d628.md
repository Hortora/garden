## Symptom

Unit tests for a custom `NarrativeSignalStrategy` that mock `EventStreamBus<DecisionSignal>.publish()` and capture `DecisionSignal` arguments never see any invocations — `verify(signalBus).publish(any())` fails.

## Context

`AbstractNarrativeSignalStrategy.emit(DecisionSignal)` wraps the signal in a `LevelEvent<DecisionSignal>` before calling `signalBus.publish(LevelEvent)`. The mock expects `publish(DecisionSignal)` but the actual call is `publish(LevelEvent<DecisionSignal>)` — the type parameter mismatch means the mock never matches.

## Fix

Use a real `EventStreamBus<DecisionSignal>` with a subscriber that captures the payload:

```java
private EventStreamBus<DecisionSignal> signalBus;
private List<DecisionSignal> captured;

@BeforeEach
void setUp() {
    signalBus = new EventStreamBus<>();
    captured = new ArrayList<>();
    signalBus.subscribe(
        e -> true,
        (LevelEvent<DecisionSignal> event) -> captured.add(event.payload()));
    var pipeline = mock(DecisionNarrativePipeline.class);
    strategy = new MyNarrativeSignalStrategy(signalBus, pipeline);
}

@Test
void emitsStepOutcome() {
    strategy.onStepOutcome(someEvent());
    assertThat(captured).anyMatch(s -> s instanceof StepOutcome);
}
```

The subscriber unwraps `LevelEvent.payload()` to get the `DecisionSignal`, matching the types your assertions expect.

## Why this is non-obvious

The `emit()` method in `AbstractNarrativeSignalStrategy` is `protected` and its wrapping of signals in `LevelEvent` is an internal detail not visible from the subclass API. A developer writing tests sees `emit(DecisionSignal)` and naturally mocks `publish(DecisionSignal)`. The `LevelEvent` wrapping is only visible in the decompiled base class.

This pattern is used in `FsiNarrativeSignalStrategyTest` (fsitrading) — the reference implementation for narrative signal testing.
