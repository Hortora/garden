## @UnlessBuildProperty enableIfMissing defaults to false — bean excluded when property absent

### Symptom

A `@WebSocket` endpoint annotated with `@UnlessBuildProperty(name = "x", stringValue = "true")` is not discovered by Quarkus. CDI reports `UnsatisfiedResolutionException` when injecting, and `WebSocketProcessor.collectEndpoints()` skips it. No error mentions `enableIfMissing`.

### Context

Designing a zero-config default bean that should be active when no configuration is set, excluded only when the app explicitly opts out by setting a property.

### Root cause

`@UnlessBuildProperty` has `enableIfMissing` defaulting to `false`. When the property is completely absent from configuration (not set at all), the bean is **excluded** — the opposite of what the annotation name suggests. The name reads as "include this bean unless property X=Y" but the actual semantics with the default are "include this bean only when property X is set to something other than Y".

```java
// Bean is EXCLUDED when casehub.push.custom-endpoint is not set at all
@UnlessBuildProperty(name = "casehub.push.custom-endpoint", stringValue = "true")

// Bean is INCLUDED when property is absent — zero-config friendly
@UnlessBuildProperty(name = "casehub.push.custom-endpoint", stringValue = "true",
    enableIfMissing = true)
```

### Fix

Always set `enableIfMissing = true` when the intent is a zero-config default:

```java
@WebSocket(path = "/ws/push")
@UnlessBuildProperty(name = "casehub.push.custom-endpoint",
    stringValue = "true", enableIfMissing = true)
public class DefaultPushWebSocket { ... }
```

The same applies in reverse to `@IfBuildProperty` — its `enableIfMissing` also defaults to `false`, so a bean annotated `@IfBuildProperty(name = "x", stringValue = "true")` is excluded when the property is absent.

### Alternatives considered

- `@DefaultBean` — does not work for `@WebSocket` classes because endpoint scanning uses `beanStream().classBeans()` which sees both beans regardless of `@DefaultBean`, causing a path conflict
- Quarkus extension with custom build step — heavyweight for a single conditional endpoint

### Why this is non-obvious

The annotation name `@UnlessBuildProperty` strongly implies "enabled unless the property matches". A developer reading it would naturally expect that when the property is not configured at all, the bean is active. The `enableIfMissing` attribute is not mentioned in most Quarkus guides on conditional beans, and the default value contradicts the intuitive reading of the annotation name.
