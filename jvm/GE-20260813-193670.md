## quarkus-websockets-next package is io.quarkus.websockets.next (plural)

### Symptom
`import io.quarkus.websocket.next.WebSocketConnection` fails with "package io.quarkus.websocket.next does not exist" even though `quarkus-websockets-next` is correctly declared in pom.xml and `mvn dependency:resolve` confirms the JAR is available.

### Context
Adding `quarkus-websockets-next` dependency to a Quarkus project and importing its classes. The Maven artifact name is `quarkus-websockets-next` (plural), which is correct. The natural guess for the Java package is `io.quarkus.websocket.next` (singular) — following the common Java convention where package names use singular forms.

### What was tried (didn't work)
1. `import io.quarkus.websocket.next.WebSocketConnection` — compilation fails
2. Verified dependency resolution — JAR is present at 3.32.2
3. Clean rebuild — same error

### Root cause
The Java package name is `io.quarkus.websockets.next` (plural "websockets"), matching the Maven artifact name. This is unusual — most Java packages use singular forms (`java.util.concurrent`, `jakarta.enterprise.context`). The Quarkus WebSocket Next extension uses plural consistently across artifact and package names.

### Fix
Use the plural form in all imports:

```java
import io.quarkus.websockets.next.WebSocket;
import io.quarkus.websockets.next.WebSocketConnection;
import io.quarkus.websockets.next.OnOpen;
import io.quarkus.websockets.next.OnClose;
import io.quarkus.websockets.next.OnTextMessage;
import io.quarkus.websockets.next.UserData;
```

### Why this is non-obvious
The error message "package does not exist" gives no hint about the typo. The Maven artifact `quarkus-websockets-next` resolves correctly, so the developer looks at dependency scope, BOM version, and classpath — not at the import statement's spelling. The singular/plural difference is a single character (`s`) in a long package path.
