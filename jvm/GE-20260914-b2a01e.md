## SmallRye Config rejects empty-string @ConfigProperty defaultValue in CDI producer method parameters

### Symptom

`@QuarkusTest` fails at startup with:

```
jakarta.enterprise.inject.spi.DeploymentException:
  io.quarkus.runtime.configuration.ConfigurationException:
    Failed to load config value of type class java.lang.String for: my.api-key
```

The error names the config property but not the CDI producer method. Multiple properties may fail in the same deployment exception (suppressed exceptions list all failing properties).

### Context

A CDI producer method uses `@ConfigProperty(name = "...", defaultValue = "")` parameters for optional credentials (API keys, client secrets). The property exists in `application.properties` with an environment variable fallback that evaluates to empty string when the env var is not set:

```properties
my.api-key=${MY_API_KEY:}
```

The same pattern works correctly for field-injected `@ConfigProperty` on `@ApplicationScoped` beans. It fails only when used as a CDI producer method parameter.

### What was tried (didn't work)

- `@ConfigProperty(name = "my.api-key", defaultValue = "")` on the producer parameter — fails at deployment
- Setting the property to empty string in `application.properties` (`my.api-key=`) — same failure; the converter treats empty string as null regardless of source

### Root cause

SmallRye Config's `BuiltInConverter` for `String` considers empty string as null (error code `SRCFG00040`: "The config property ... is defined as the empty String which the following Converter considered to be null"). Quarkus's `ConfigRecorder.validateConfigProperties()` runs at deployment time, finds the property value is null (converter returned null for ""), and throws because the parameter type is `String` (not `Optional`).

The `defaultValue = ""` on the `@ConfigProperty` annotation is bypassed — the converter's null-coercion runs before the MicroProfile Config default-substitution logic can apply the default value.

### Fix

Use `Optional<String>` for the parameter type. SmallRye Config treats `Optional` parameters as truly optional — no deployment-time validation. Check `isEmpty()` or `get().isBlank()` in the producer body:

```java
// Before (fails at deployment):
@Produces @Singleton
public MyClient create(
        @ConfigProperty(name = "my.api-key", defaultValue = "") String apiKey) {
    if (apiKey.isBlank()) return MyClient.unconfigured();
    return new MyClient(apiKey);
}

// After (works):
@Produces @Singleton
public MyClient create(
        @ConfigProperty(name = "my.api-key") Optional<String> apiKey) {
    if (apiKey.isEmpty() || apiKey.get().isBlank()) return MyClient.unconfigured();
    return new MyClient(apiKey.get());
}
```

### Why this is non-obvious

`defaultValue = ""` is a valid MicroProfile Config annotation attribute. It works correctly on field injection (`@Inject @ConfigProperty(name = "...", defaultValue = "") String field`) — the empty default is applied and the field receives `""`. The failure manifests only in CDI producer method parameters during Quarkus deployment validation, making it appear as a config-source problem rather than a type-system problem. The error message points to the config property name, not the producer method — debugging requires tracing from the property name back to the producer that references it.

### Alternatives considered

- Adding the property with a non-empty sentinel default (e.g. `defaultValue = "NONE"`) — works but introduces a magic string that must be checked in every consumer
- Making the property non-optional and requiring it in all environments — breaks dev/test where credentials aren't available
