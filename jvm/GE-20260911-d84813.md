# AdaptiveSearchConfig constrains gapThreshold to [0,1] — breaks CE-score-based gap detection on migration

## Symptom

`IllegalArgumentException: gapThreshold must be in [0,1]` when constructing `AdaptiveSearchConfig` with a gap threshold designed for cross-encoder scores (e.g. `2.0`).

## Context

Cross-encoder reranking scores are not normalized to [0,1] — they range from roughly -10 to +20. Hand-rolled adaptive filters often use gap thresholds > 1.0 to detect meaningful score drops between CE-scored results. When migrating to the upstream `AdaptiveFilter` API, the `AdaptiveSearchConfig` constructor validates that `gapThreshold` is in [0,1], causing an immediate failure.

## Root cause

`AdaptiveSearchConfig` was designed for normalized relevance scores. The [0,1] constraint is a constructor validation, not a runtime check — it fails at filter construction time, not at filtering time.

## Fix

Clamp the gap threshold: `Math.min(gapThreshold, 1.0)` when constructing `AdaptiveSearchConfig`. A threshold of 0.5 works well for CE scores — the CE boundary detection (`withCeBoundary()`) handles the CE→non-CE transition as a hard cutoff, so the gap threshold only needs to detect within-CE-score drops.

```java
var options = AdaptiveFilterOptions.<SearchResult>of(
        new AdaptiveSearchConfig(scoreFloor, Math.min(gapThreshold, 1.0), minResults, 1.0),
        r -> boostedScore(r, boostWeight))
    .withCeBoundary(r -> r.crossEncoderScore() != null)
    .withClusterExtension(0.05);
```

## Why this is non-obvious

The old gap threshold value (2.0) worked fine for years with hand-rolled filtering. The upstream API's [0,1] constraint is undocumented in the record's javadoc — it's a constructor validation that only surfaces at runtime. The fix requires understanding that CE boundary detection is now a separate concern from gap thresholds.

### Alternatives considered

- Normalizing CE scores to [0,1] before filtering — rejected because normalization loses the absolute magnitude information that makes CE scores useful
- Passing the raw threshold and catching the exception — rejected because the constraint is a design decision, not a bug
