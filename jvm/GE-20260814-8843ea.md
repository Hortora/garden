### Symptom
Scanner silently skips all `@Subscription`-annotated methods. No compile error, no runtime warning. The annotation string matches nothing because the class doesn't exist at that package path.

### Context
String-based annotation checking (`hasAnnotation(method, "org.eclipse.microprofile.graphql.Subscription")`) compiles and runs without error — the string is just a string. But `@Subscription` is a SmallRye extension at `io.smallrye.graphql.api.Subscription`, not part of the MicroProfile GraphQL spec. `@Query`, `@Mutation`, and `@Description` ARE in the MP spec (`org.eclipse.microprofile.graphql.*`), which makes the inconsistency invisible.

### Root cause
MicroProfile GraphQL spec (as of 2.0) does not include subscriptions. SmallRye added `@Subscription` as a vendor extension in its own package. The natural assumption — that all GraphQL annotations live in the same package — is wrong for this one annotation.

### Fix
Use `io.smallrye.graphql.api.Subscription` — not `org.eclipse.microprofile.graphql.Subscription`.

```java
// Wrong — compiles fine, never matches
hasAnnotation(method, "org.eclipse.microprofile.graphql.Subscription")

// Correct
hasAnnotation(method, "io.smallrye.graphql.api.Subscription")
```

### Why this is non-obvious
`@Query`, `@Mutation`, `@Description`, `@Name`, `@GraphQLApi` are all in `org.eclipse.microprofile.graphql`. The natural assumption is `@Subscription` is too. String-based annotation checking hides the error completely — no compile-time check, no runtime ClassNotFoundException, just silent non-matching.
