### Symptom
Maven dependency resolution fails when using `quarkus-mcp-server-sse` as the artifactId. No artifact exists with that name in the 1.x release line.

### Context
Adding MCP server support to a Quarkus sidecar. Documentation examples and AI-generated plans frequently reference `quarkus-mcp-server-sse` as the artifact name, suggesting an SSE-specific transport module.

### Root cause
The artifact is `quarkus-mcp-server-http` — it provides both streamable HTTP (`/mcp`) and SSE (`/mcp/sse`) transports in a single dependency. There is no separate SSE-only artifact.

### Fix
```xml
<dependency>
    <groupId>io.quarkiverse.mcp</groupId>
    <artifactId>quarkus-mcp-server-http</artifactId>
    <version>1.11.1</version>
</dependency>
```

### Why this is non-obvious
The SSE transport is a prominent feature of MCP, so `quarkus-mcp-server-sse` is a natural guess. The actual artifact name (`-http`) doesn't suggest SSE support. The Quarkus startup log confirms both transports are active: `MCP HTTP transport endpoints [streamable: .../mcp, SSE: .../mcp/sse]`.
