### Symptom
Generated `@AutoConfiguration` classes compile and appear in the JAR, but Spring Boot never discovers them. No error, no warning. The `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` file written alongside the Java sources is silently absent from the JAR.

### Context
A Maven plugin (spring-generator) writes both `.java` files and a `META-INF/spring/AutoConfiguration.imports` file to `target/generated-sources/spring-generator/`. The plugin calls `project.addCompileSourceRoot(outputDirectory)` to register the output. Java sources compile correctly, but the imports file never reaches `target/classes/`.

### What was tried (didn't work)
1. Writing the imports file to the generated sources directory alongside the Java files — silently dropped
2. Assuming `addCompileSourceRoot` handles all files in the directory — it only handles `.java` files for compilation

### Root cause
`MavenProject.addCompileSourceRoot()` registers a directory for the Java compiler only. Non-Java files in that directory are not treated as resources and are not copied to `target/classes/` by `maven-resources-plugin`. The resources plugin only processes directories registered via `project.addResource()` or declared in `<resources>` in the POM.

### Fix
Add the generated directory as a Maven resource with a filter for `META-INF/**` only (to avoid packaging `.java` files as resources):

```java
protected void registerSourceRoot() {
    project.addCompileSourceRoot(getOutputDirectory().getAbsolutePath());
    Resource resource = new Resource();
    resource.setDirectory(getOutputDirectory().getAbsolutePath());
    resource.addInclude("META-INF/**");
    project.getResources().add(0, resource);  // position 0 — see GE-20260923-16782e
}
```

### Why this is non-obvious
The distinction between "compile source root" and "resource root" is not surfaced in Maven's error output. The generated Java classes compile and appear in the JAR, creating the illusion that the entire directory is being processed. The missing resource file causes a downstream failure (Spring Boot auto-config not discovered) with no connection to the Maven resource pipeline. In this case, 13 Spring modules were silently orphaned for months.

### Why this fix
`addResource` with `META-INF/**` include is the minimal change — it doesn't require `build-helper-maven-plugin` or POM-level configuration. The include filter prevents `.java` files from being packaged as resources.

### Alternatives considered
- `build-helper-maven-plugin:add-resource` goal — works but adds a plugin dependency for a one-line fix
- Writing the imports file directly to `target/classes/META-INF/spring/` — fragile, depends on lifecycle phase ordering
- Copying with `maven-resources-plugin` execution — verbose POM configuration for each consumer module
