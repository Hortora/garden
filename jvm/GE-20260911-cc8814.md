## Symptom

Gradle build fails immediately with the entire error message being just:

```
* What went wrong:
26.0.2
```

No "Caused by", no exception type, no file reference. Just a version number
as the complete error output. `--stacktrace` reveals the root cause, but
the default output is completely opaque.

## Context

Occurs when the Gradle daemon starts on JDK 26 and attempts to compile Kotlin
DSL scripts (settings.gradle.kts or build.gradle.kts). The Kotlin compiler
embedded in Gradle 8.x calls `JavaVersion.parse()` which doesn't recognise
version 26.

## What was tried (didn't work)

1. Setting `JAVA_HOME` to JDK 21 — but `/usr/libexec/java_home -v 21` returned
   JDK 26 because no JDK 21 was installed via the Apple Java framework
2. `--no-daemon` with `JAVA_HOME` — failed because JAVA_HOME resolved to the
   wrong path via jenv indirection
3. Multiple rebuilds with different flags — no useful diagnostic until `--stacktrace`

## Root cause

`org.jetbrains.kotlin.com.intellij.util.lang.JavaVersion.parse()` in the Kotlin
compiler does not handle version 26. It throws `IllegalArgumentException` with the
version string as the message. Gradle catches this and presents only the exception
message — which is just `26.0.2`.

The stacktrace reveals:
```
java.lang.IllegalArgumentException: 26.0.2
  at o.j.k.c.i.u.l.JavaVersion.parse(JavaVersion.java:307)
  at o.j.k.c.i.u.l.JavaVersion.current(JavaVersion.java:176)
  at o.j.k.c.j.modules.CoreJrtFileSystem...
```

## Fix

Run the Gradle daemon on JDK 21 (or any version the Kotlin compiler supports):

```bash
# Use the actual JDK path, not jenv or java_home indirection
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home \
  ./gradlew build
```

Key detail: `jenv prefix 21` may return a symlink path, and
`/usr/libexec/java_home -v 21` may return the wrong JDK if 21 isn't
installed in `/Library/Java/`. Use the actual filesystem path.

## Why this is non-obvious

The error message `26.0.2` contains zero diagnostic information. It looks like
a version number was accidentally printed, not like a build failure. Without
`--stacktrace`, there is no indication that the Kotlin compiler is the source
or that JDK version incompatibility is the cause. The fix (downgrade the daemon
JDK) is simple but unreachable without the stacktrace.
