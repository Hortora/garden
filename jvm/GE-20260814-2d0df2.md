## Symptom

`@QuarkusTest` augmentation fails with "Unsatisfied dependency" for a constructor parameter of a test inner class — even though that class is never used in the failing test. Error appears as `ClassSelector resolution failed` during JUnit test discovery.

## Context

A plain (non-`@QuarkusTest`) unit test has a `static` inner class extending a CDI bean (e.g. to access `protected`/package-private methods). The inner class has a constructor parameter that CDI cannot satisfy. A *different* `@QuarkusTest` in the same module triggers Quarkus augmentation, which scans all classes — including test source sets — and tries to register the inner class as a CDI bean.

```java
// MomentDetectionBattleTest.java — plain JUnit, NOT @QuarkusTest
class MomentDetectionBattleTest {
    static class TestMomentDetectionTask extends MomentDetectionTask {
        TestMomentDetectionTask(List<GameMoment> emitted) { // CDI can't inject this
            super(null);
        }
    }
}
```

This causes augmentation to fail for ALL `@QuarkusTest` tests in the module.

## Root Cause

Quarkus ArC augmentation scans the entire classpath — including test classes — during build-time bean discovery. A `static` inner class that extends a CDI-managed type is treated as a CDI bean candidate. If its constructor has parameters CDI can't resolve, augmentation fails.

## Fix

Add `@jakarta.enterprise.inject.Vetoed` to the test inner class. This tells CDI to skip it during bean discovery:

```java
@Vetoed
static class TestMomentDetectionTask extends MomentDetectionTask {
    TestMomentDetectionTask(List<GameMoment> emitted) {
        super(null);
    }
}
```

### Why this is non-obvious

The failing test class and the test inner class are unrelated — the inner class is in a plain JUnit test, but the failure surfaces in a completely different `@QuarkusTest`. The error message points to the `@QuarkusTest` that triggered augmentation, not the test file containing the problematic inner class. Requires reading the full CDI validation error (which lists the bean type hierarchy) to trace back to the offending class.

### Alternatives considered

- Making the inner class `private` — doesn't help; Quarkus ArC scans private classes too
- Moving the inner class to a non-CDI package — fragile; doesn't prevent discovery
- `@Unremovable` on the parent — wrong direction; makes the problem worse
