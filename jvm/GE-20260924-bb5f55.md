### Symptom
`org.hibernate.MappingException: Basic collection has element type 'X' which is not a known basic type (attribute is not annotated '@ElementCollection', '@OneToMany', or '@ManyToMany')` — but the `@OneToMany` annotation IS present on the field in the source code and compiled bytecode.

### Context
Extracting JPA entity classes from a Quarkus extension's runtime module to a shared `jpa-common` dependency JAR. Entity listeners (CDI beans in runtime) can't move to jpa-common (circular dependency), so they're registered via `<entity>` element in runtime's `META-INF/orm.xml`.

### What was tried (didn't work)
1. `IndexDependencyBuildItem` in deployment processor — entities indexed but still not mapped
2. `AdditionalJpaModelBuildItem` for each entity class — entities registered but same error
3. `quarkus.index-dependency` in application.properties — same result
4. `beans.xml` with `bean-discovery-mode="all"` in jpa-common — CDI warning, same error
5. Adding jpa-common as direct dependency of deployment module — same error
6. `metadata-complete="false"` on the `<entity>` element — same error

### Root cause
When an `<entity class="X">` element appears in orm.xml, Quarkus's build-time Hibernate ORM processor treats it as the authoritative metadata source for that entity — even with `metadata-complete="false"`. All annotation-based field mappings (`@OneToMany`, `@ManyToOne`, etc.) on that entity class are silently dropped. The entity listeners are registered, but the entity's field annotations are gone.

### Fix
Use `<persistence-unit-metadata>` with `<persistence-unit-defaults>` instead of `<entity>`:

```xml
<persistence-unit-metadata>
    <persistence-unit-defaults>
        <entity-listeners>
            <entity-listener class="com.example.MyTraceListener"/>
            <entity-listener class="com.example.MyEnforcementListener"/>
        </entity-listeners>
    </persistence-unit-defaults>
</persistence-unit-metadata>
```

This registers entity listeners as defaults for ALL entities in the persistence unit without overriding any entity's annotation metadata. The listeners must guard internally against non-target entity types.

### Why this is non-obvious
The error message points at a missing `@OneToMany` annotation — which IS present. The actual cause (`<entity>` overriding annotations) is in a different file (orm.xml) and the override is silent (no warning logged). `metadata-complete="false"` is supposed to prevent annotation override per the JPA spec, but Quarkus's build-time processing doesn't honor it.

### Alternatives considered
- Moving listener classes to jpa-common — rejected (circular dependency with runtime)
- Programmatic listener registration via Hibernate Integrator — more complex, non-standard
- `@EntityListeners` annotation on the entity class — requires entity to depend on listener classes (circular)
