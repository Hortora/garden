## Symptom

WebSocket tests using `CountDownLatch.await(5, SECONDS)` for READY events pass individually but flake when run as part of a full test suite. First test in the class times out; retries pass. Flake rate increases under CI load.

## Context

Tests that create a Vert.x `HttpServer` (WebSocket server) and `HttpClient` (WebSocket client) per `@BeforeEach` pay the full Vert.x/Netty/Jackson class-loading cost on the first test execution. This can push connection establishment past the latch timeout.

## What was tried (didn't work)

- Increasing latch timeouts from 5s to 10s — reduced flake rate but didn't eliminate it.
- Running tests individually — always passed (warmup cost amortized differently).

## Root cause

Vert.x pulls in Netty and Jackson, which have substantial class-loading overhead. The first `Vertx.vertx()` call in a JVM triggers this. Subsequent calls reuse cached classes and complete much faster.

## Fix

Add a `@BeforeAll` that pre-warms the Vert.x stack:

```java
@BeforeAll
static void warmUp() {
    Vertx vertx = Vertx.vertx();
    vertx.close().toCompletionStage().toCompletableFuture().join();
}
```

This forces class loading before the first test runs. The actual test instances then create their own Vert.x stacks quickly.

## Why this is non-obvious

The flake only manifests during full suite runs (cold JVM), not when running tests individually (IDE typically keeps the JVM warm). The error message ("latch timed out") points at the test logic, not at JVM startup overhead. The warmup idiom is not documented in Vert.x testing guides.
