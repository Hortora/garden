## The technique

Bridge CDI async events into per-entity SSE streams using SmallRye Mutiny's `BroadcastProcessor` — a hot stream that fans out to all subscribers. This avoids the `SseEventSink`/`Sse` JAX-RS API (which has request-scope injection issues in Quarkus REST) and matches the platform pattern used by `LocalWorkItemEventBroadcaster` in casehub-work.

### Pattern

**Broadcaster bean** — `@ApplicationScoped`, holds the processor, observes CDI events:

```java
@ApplicationScoped
public class CaseStreamBroadcaster {
    private final BroadcastProcessor<CaseStreamEvent> processor = BroadcastProcessor.create();

    void onPlanItemChanged(@ObservesAsync PlanItemStateChangedEvent event) {
        try {
            processor.onNext(CaseStreamEvent.planItem(event));
        } catch (BackPressureFailure ignored) {}
    }

    public Multi<CaseStreamEvent> stream(UUID caseId) {
        return processor.toHotStream().filter(e -> caseId.equals(e.caseId()));
    }
}
```

**REST endpoint** — thin delegation, Quarkus REST handles the SSE framing:

```java
@Path("/api/v1/cases/{caseId}/stream")
public class CaseStreamResource {
    @Inject CaseStreamBroadcaster broadcaster;

    @GET
    @Produces(MediaType.SERVER_SENT_EVENTS)
    @RestStreamElementType(MediaType.APPLICATION_JSON)
    public Multi<CaseStreamEvent> stream(@PathParam("caseId") UUID caseId) {
        return broadcaster.stream(caseId);
    }
}
```

**DTO with discriminator** — `@JsonIgnore` on the filter field, type discriminator in the payload:

```java
public record CaseStreamEvent(
    @JsonIgnore UUID caseId,
    String type,
    Map<String, String> data) {}
```

### Why this over SseEventSink

The JAX-RS `SseEventSink` + `@Context Sse` approach requires storing the `Sse` factory from request context for use in CDI observer methods that run outside request scope. In Quarkus REST (RESTEasy Reactive), `@Context` field injection returns a proxy that only works during a request — CDI observers calling `sse.newEvent()` would fail. The `BroadcastProcessor` + `Multi<T>` approach sidesteps this entirely.

### Why this is non-obvious

- The Quarkus REST SSE documentation focuses on `Multi<T>` return types but does not cover the CDI event bridging pattern
- The `SseEventSink` approach from the JAX-RS spec is prominently documented but silently fails in Quarkus REST when used from CDI observers
- `BroadcastProcessor` is a SmallRye Mutiny class not mentioned in Quarkus SSE docs — discovering it requires reading casehub-work's internal implementation
- `@ObservesAsync` vs `@Observes` are separate CDI dispatch paths — using the wrong one silently drops all events with no error
