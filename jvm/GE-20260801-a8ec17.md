### Symptom

`cannot find symbol` compile errors for classes from a JAR that IS in the local `.m2` repository and IS in `mvn dependency:tree`.

### Context

Adding `casehub-platform-agent-api` as an explicit dependency in `pom.xml` without `<scope>compile</scope>`. The parent POM's `dependencyManagement` declares the artifact with `runtime` scope. Maven resolves the effective scope as `runtime` — classes are available at runtime but invisible at compile time.

### What was tried (didn't work)

Adding the dependency without explicit scope (expecting Maven's default `compile` to apply). `mvn dependency:tree` shows the artifact with `:runtime` scope despite the explicit declaration.

### Root cause

Maven's dependency mediation gives `dependencyManagement` scope declarations priority over the default scope of a direct dependency. When the parent POM manages an artifact with `runtime` scope, a child `<dependency>` without `<scope>` inherits `runtime`, not `compile`.

### Fix

```xml
<dependency>
  <groupId>io.casehub</groupId>
  <artifactId>casehub-platform-agent-api</artifactId>
  <version>${version.io.casehub}</version>
  <scope>compile</scope>
</dependency>
```

### Why this is non-obvious

Maven's default scope is `compile`. Developers expect an explicit `<dependency>` to use `compile` scope unless stated otherwise. The `dependencyManagement` override is silent — no warning, no error, just `runtime` in the resolved tree.
