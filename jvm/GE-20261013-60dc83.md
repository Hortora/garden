### Symptom
Quarkus augmentation fails with:
`IllegalArgumentException: Property type java.util.Optional<java.util.Map<java.lang.String, java.lang.String>> cannot be optional`

### Context
Declaring `Optional<Map<String, String>>` in a `@ConfigMapping` interface — natural pattern when the map is genuinely optional (absent means "no metadata declared"). Other optional patterns work fine: `Optional<String>`, `Optional<List<String>>`, `OptionalInt`, `Optional<EnumType>`.

### Root cause
SmallRye Config's `@ConfigMapping` processor explicitly rejects `Optional` wrapping of `Map` types. The Map type has its own "absent" semantics (empty map), so SmallRye treats `Optional<Map>` as invalid rather than redundant.

### Fix
Use `Map<String, String>` directly — SmallRye returns an empty map when no keys are declared under that prefix:

```java
// ❌ Fails at augmentation
Optional<Map<String, String>> metadata();

// ✅ Works — empty map when absent
Map<String, String> metadata();
```

At the consumer boundary, check `metadata().isEmpty()` instead of `metadata().isPresent()`.

### Why this is non-obvious
`Optional<List<String>>` works. `Optional<String>` works. `Optional<EnumType>` works. The developer naturally expects `Optional<Map<>>` to follow the same pattern. The error only surfaces at Quarkus augmentation time (not at compile time), and the message names the full generic type signature which can be hard to parse in a stack trace.
