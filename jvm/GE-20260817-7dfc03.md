### Symptom

In a `@QuarkusTest` integration test, asserting on a root-level JSON array of strings
with `body("$.size()", greaterThan(0))` returns `Actual: null` — even though the
response is a valid JSON array with elements. The response has correct `Content-Type:
application/json` and a non-zero `content-length` (e.g. 12 bytes for `["thumbsup"]`).

The same `$.size()` GPath expression works correctly on root-level JSON arrays of objects.

### Context

Endpoint returns `Response.ok(List<String>)` from a JAX-RS resource with
`@Produces(MediaType.APPLICATION_JSON)`. The response body is a valid JSON array
of strings. Occurs specifically with root-level primitive arrays (strings, numbers).

### What was tried (didn't work)

- `body("$.size()", greaterThan(0))` — returns `null` instead of the array length
- `body("$.size()", greaterThanOrEqualTo(1))` — same `null` result
- Explicitly setting `.type(MediaType.APPLICATION_JSON)` on the Response builder — no effect

### Root cause

rest-assured uses Groovy's GPath for JSON path evaluation. The `$` symbol refers to
the root document. When the root is a JSON array of primitives (not objects), the
`.size()` method invocation does not resolve correctly — GPath treats primitive arrays
differently from object arrays at the root level.

### Fix

Use Hamcrest matchers that work directly on the root array instead of GPath `.size()`:

```java
// Instead of:
given().when().get("/api/endpoint")
    .then().statusCode(200)
    .body("$.size()", greaterThan(0));

// Use hasItem for specific content:
given().when().get("/api/endpoint")
    .then().statusCode(200)
    .body("$", hasItem("expected-value"));

// Or use hasSize for count:
given().when().get("/api/endpoint")
    .then().statusCode(200)
    .body("$", org.hamcrest.Matchers.hasSize(1));
```

### Why this is non-obvious

The `$.size()` pattern is widely used in rest-assured tests and works perfectly on
arrays of objects (which are far more common in REST API responses). The failure mode
is silent — no error, no exception, just a `null` return that looks like the endpoint
returned nothing. Debugging leads to checking serialization, content types, and response
bodies before discovering the GPath evaluation is the issue.
