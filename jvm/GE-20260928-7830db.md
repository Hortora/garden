# Raw PAD mood values don't influence LLM behavior — emotional labels required

### Symptom

An agent cognitive system uses the PAD (Pleasure-Arousal-Dominance) mood model to track emotional state. MoodPromptSection renders the state as raw numerical values in the observation layer:

```
Current emotional state:
- Pleasure: 0.60 (positive)
- Arousal: 0.20 (balanced)
- Dominance: 0.30 (balanced)
```

The LLM's behavior does not change when mood values change. An event-driven eval comparing before/after mood states showed a cognitive delta score of 1/5 (indistinguishable from random variation). The judge's verdict: "The AFTER response shows no trace of the event — both responses are nearly identical in tone."

Meanwhile, three other cognitive subsystems (beliefs, drives, persona switching) that communicate via natural language all scored 3-5/5.

### Context

The PAD model is a well-established dimensional model of emotion. The values are meaningful to researchers, but LLMs have no training data mapping "Pleasure: 0.60" to behavioral changes. The observation layer is the LLM's only window into cognitive state — if the rendering isn't actionable, the subsystem is dead.

### Root cause

The LLM needs behavioral signals, not measurements. "Pleasure: 0.60 (positive)" is a dashboard metric. The LLM doesn't know what to DO with it. Compare to beliefs ("Penelope is naive") or norms ("Never help Penelope directly") — these are semantic content the LLM reasons from.

### Fix

Translate PAD values to Russell's circumplex emotion labels plus behavioral coloring:

```java
// Map PAD to emotional label
if (p > 0.3 && a > 0.3) label = "excited and energized";
else if (p > 0.3 && a < -0.3) label = "content and serene";
// ... etc

// Map PAD axes to behavioral implications
if (p > 0.3) cues.add("more generous and open");
if (p < -0.3) cues.add("more guarded and short-tempered");
if (d > 0.3) cues.add("more assertive and commanding");
// ... etc

return "You're feeling " + label + ".\n"
     + "This colors your responses — you're " + String.join(", ", cues) + ".";
```

Renders as: "You're feeling pleased, with a sense of confidence. This colors your responses — you're more generous and open, more assertive and commanding."

After the fix, mood-elevation eval scored 3/5 (up from 1/5), with the judge noting: "explicit 'good mood' in thinking, more grandiose self-references, warmer tone toward Muttley."

### Why this is non-obvious

The PAD model is standard in affective computing. The rendering included human-readable labels ("positive", "balanced"). A developer would reasonably expect the LLM to interpret "Pleasure: 0.60 (positive)" as a behavioral signal. But LLMs respond to natural language narrative, not formatted measurements — the parenthetical labels are too weak to drive behavioral change.

### Why this fix

Russell's circumplex provides a well-validated mapping from PAD dimensions to discrete emotion labels that read as natural language. The behavioral coloring ("more generous and open") directly tells the LLM HOW the mood should manifest, bridging the gap between measurement and behavior.

### Alternatives considered

- Including the `cause` field from MoodState ("recent success") in the rendering — provides narrative context but doesn't address the core issue of unlabeled dimensions
- Keeping numerical values alongside labels — rejected because the numbers add noise without signal; the LLM doesn't need the precision
