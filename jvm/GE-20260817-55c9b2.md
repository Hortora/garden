## Context

Platform SPIs extend `NamedStrategy` (which has an `id()` method) and are resolved by `StrategyResolver` using config-selected IDs. When adding remote callback support, the callback routing must be transparent — no config changes required, existing strategy selection still works.

## Technique

Use a CDI `@Decorator` that wraps the SPI interface. The decorator intercepts every bean implementing the interface, but handles methods differently:

- **Metadata methods** (`id()`, `triggers()`) — always delegate to the wrapped bean. This ensures `StrategyResolver` indexes each bean under its correct ID.
- **Business methods** (`onBreach()`, `select()`) — check `CallbackRegistry` for remote registrations. If present, route to remote via `CallbackInvoker`. If absent or on failure, delegate to the wrapped bean.

```java
@Decorator
@Priority(Interceptor.Priority.APPLICATION + 100)
public class CallbackSlaBreachPolicyDecorator implements SlaBreachPolicy {

    @Inject @Delegate SlaBreachPolicy delegate;
    @Inject CallbackRegistry callbackRegistry;
    @Inject CallbackInvoker callbackInvoker;
    @Inject CurrentPrincipal currentPrincipal;

    @Override
    public String id() {
        return delegate.id();  // always delegate — metadata, not routable
    }

    @Override
    public BreachDecision onBreach(SlaBreachContext context) {
        List<CallbackRegistration> regs = callbackRegistry.findBySpi(SPI_NAME, currentPrincipal.tenancyId());
        if (regs.isEmpty()) return delegate.onBreach(context);

        try {
            BreachDecision result = callbackInvoker.invoke(regs.get(0), "onBreach", new Object[]{context}, BreachDecision.class);
            if (result != null) return result;
        } catch (Exception e) {
            LOG.warnf(e, "Remote policy failed — falling back to local");
        }
        return delegate.onBreach(context);
    }
}
```

## Why this is non-obvious

The natural CDI approach for callback routing would be `@ApplicationScoped` bean displacement or `@Alternative`. But with `NamedStrategy`, multiple strategy beans coexist and are selected by config — displacement would remove the local strategy entirely. A `@Decorator` wraps each strategy bean individually while preserving the `StrategyResolver` index, making callback routing orthogonal to strategy selection.

The key insight is that `Instance<T>` iteration in `StrategyResolver` returns decorator-wrapped beans, so `id()` calls during indexing go through the decorator. If the decorator didn't delegate `id()`, it would break strategy resolution.
