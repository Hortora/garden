### Symptom
Second `@QuarkusTest` method queries `CbrCaseMemoryStore.retrieveSimilar()` and finds cases stored by the first test method. Test fails with "Expecting empty but was: [ScoredCbrCase...]".

**Cross-class variant (2026-08-01):** A test class assuming an empty CBR case base ("cold start") fails when preceded by a different test class that wrote CBR cases. The contamination is invisible — the symptom is a triage decision change (SAR_WARRANTED → FALSE_POSITIVE) because the engine's CBR retrieval finds similar cases at case start, changing the investigation flow. The test times out waiting for a gate WorkItem that is never created.

### Context
`InMemoryCbrCaseMemoryStore` is `@ApplicationScoped` — one instance per Quarkus test application lifecycle. It persists across all test methods in all `@QuarkusTest` classes within the same test run. The store has no `clearAll()` or `reset()` method.

### What was tried (didn't work)
- `purge(CbrRetentionPolicy)` — requires `maxAgeDays >= 1` (won't clear cases stored seconds ago) and `maxCasesPerType >= 1` (keeps at least one case per type). Both constraints are validated in the constructor with `IllegalArgumentException`.
- `eraseEntity(entityId, tenantId)` — requires knowing the exact entity IDs from prior tests, which are randomly generated.

### Root cause
The `CbrRetentionPolicy` record validates that `maxAgeDays` and `maxCasesPerType` must both be positive when non-null. There is no API surface to clear all cases unconditionally.

### Solution 1 — Query-level filtering with withNotBefore
**Approach:** Capture `Instant.now()` before the operation under test, then filter query results to only cases stored after that timestamp.
**Pros:** No store mutation needed; works within a single test method.
**Cons:** Only filters retrieval results — the CBR data still exists in the store and can affect engine behaviour (e.g. triage decisions driven by CBR retrieval at case start).

```java
Instant before = Instant.now();
observer.onOutcome(event);  // stores a CBR case

CbrQuery query = CbrQuery.of(tenantId, domain, caseType, Map.of(), 10)
    .withNotBefore(before);
List<ScoredCbrCase<PlanCbrCase>> results = service.retrieveSimilar(query, PlanCbrCase.class);
assertThat(results).isEmpty();  // only sees cases stored after 'before'
```

### Solution 2 — Store-level purge with eraseByScope
**Approach:** Call `eraseByScope(Path.root(), tenantId)` at the start of any test that requires an empty case base.
**Pros:** Actually clears the store — no CBR data leaks into engine behaviour (triage, routing). Required for cross-class isolation where the engine retrieves CBR data autonomously.
**Cons:** Destructive — must be called before the test, not after (to avoid destroying data needed by ordered tests in the same class).

```java
@Test
@Order(1)
void coldStart_narrativeSeededFalse() {
    cbrStore.eraseByScope(Path.root(), TENANT);  // clear cross-class contamination
    // ... test that assumes empty case base
}
```

### Why this is non-obvious
The natural expectation is that an in-memory store would either auto-reset between test methods or provide a `clearAll()` method. The `purge()` method looks like it should work but its validation constraints silently prevent clearing fresh data. The cross-class contamination is especially deceptive: the symptom (Awaitility timeout on gate WorkItem) appears to be a Quartz scheduling issue, not a CBR data contamination issue. The triage decision change caused by stale CBR data is invisible without tracing the full investigation flow.
