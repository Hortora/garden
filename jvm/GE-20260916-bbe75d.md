### Symptom

Compilation error when filtering `MindMapNode.refs()` with `instanceof OverlayRef`:

```java
// FAILS — OverlayRef is not a subtype of NodeRef
String targetNodeId = overlay.refs().stream()
    .filter(r -> r instanceof OverlayRef)    // always false
    .map(r -> ((OverlayRef) r).targetNodeId()) // method doesn't exist
    .findFirst()
    .orElse(null);
```

### Context

When working with perspectival overlay nodes in the neocortex mindmap, you need to find which shared node an overlay references. The natural approach is to iterate `refs()` and look for `OverlayRef` instances.

### Root cause

`OverlayRef` is a static utility class with private constructor — it creates `NodeRef` instances via `OverlayRef.of(sharedNodeId)` but is not itself a `NodeRef` subtype. `MindMapNode.refs()` returns `Set<NodeRef>`, and the refs created by `OverlayRef.of()` are plain `NodeRef` records with `scheme = "overlay"`.

### Fix

Use the static extraction method instead:

```java
String targetNodeId = OverlayRef.sharedNodeId(overlay).orElse(null);
```

`OverlayRef.sharedNodeId(MindMapNode)` inspects the node's refs for the overlay scheme and extracts the target node ID. This is the intended API.

### Why this is non-obvious

The class name `OverlayRef` and the factory method `OverlayRef.of(sharedNodeId)` returning `NodeRef` strongly suggest `OverlayRef` is a specialised `NodeRef`. The actual relationship (utility creating plain `NodeRef` with a specific scheme) is only discoverable from the source.
