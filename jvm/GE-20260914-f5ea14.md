## Symptom

Quarkus startup fails with:

```
DeploymentException: ConfigurationException: Failed to load config value
of type class java.lang.String for: my.config.property
```

The property is defined in `application.properties` as `my.config.property=${MY_ENV_VAR:}` with an empty default after the colon.

## Context

Occurs when:
1. `application.properties` has a value using `${ENV_VAR:}` syntax (env var reference with empty default)
2. The env var is not set in the runtime environment
3. A CDI bean injects this property via `@ConfigProperty`

The MicroProfile Config spec says `${VAR:}` should resolve to an empty string when `VAR` is unset. Quarkus/SmallRye Config does not handle the empty default correctly — it treats the expression as unresolvable.

## What was tried (didn't work)

1. `${CROWDSTRIKE_CLIENT_ID:}` in application.properties with `@ConfigProperty(defaultValue = "")` on the injection point — the properties file expression fails before the `@ConfigProperty` default is evaluated.

## Root cause

SmallRye Config's expression resolver treats `${VAR:}` (empty after colon) as a malformed expression rather than "resolve to empty string." The `@ConfigProperty(defaultValue = "")` annotation default is only consulted when the property KEY is absent from all config sources — not when the VALUE fails expression resolution.

## Fix

Remove the env var expression from `application.properties` entirely. Rely on `@ConfigProperty(defaultValue = "")` for the default:

```java
// The @ConfigProperty default handles the missing-property case
@ConfigProperty(name = "my.config.property", defaultValue = "")
String myProperty;
```

In production, override via Quarkus's env var mapping (automatic: `MY_CONFIG_PROPERTY` env var maps to `my.config.property`):

```properties
# application.properties — just the non-secret defaults
my.config.api-base=https://api.example.com
# DO NOT add: my.config.client-id=${CLIENT_ID:}
```

```bash
# Production: set via environment
export MY_CONFIG_CLIENT_ID=actual-value
```

## Why this is non-obvious

The `${VAR:defaultValue}` syntax is standard MicroProfile Config and works correctly with non-empty defaults (`${VAR:fallback}`). The empty-default case (`${VAR:}`) looks syntactically valid and is specified in the MicroProfile Config spec — but Quarkus doesn't handle it. The error message says "Failed to load config value" which doesn't indicate an expression resolution problem.
