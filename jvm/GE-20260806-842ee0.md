## Wrap beans at @Produces site instead of CDI @Decorator to bypass Quarkus Arc lifecycle limitations

**ID:** GE-20260806-842ee0
**Stack:** Quarkus 3.36.x, quarkus-arc
**Labels:** `#quarkus` `#cdi` `#arc` `#producer-method` `#pattern`
**What it achieves:** Transparent bean wrapping with full initialization support, bypassing Quarkus Arc's lack of `@PostConstruct` on `@Decorator` beans.
**Context:** When a CDI `@Decorator` needs initialization (database connections, config resolution, conditional enablement), Arc's silent skipping of `@PostConstruct` on decorators is a blocker (see GE-20260806-93549d). This technique avoids the limitation entirely.

### The technique

Keep the wrapping logic as a plain class (not a CDI bean), and apply it in the `@Produces` method that creates the original bean. The producer method has full access to injected config and can conditionally wrap.

```java
// Plain wrapper class — NOT a CDI bean, no @Decorator
public class CachingMultiModalEmbedder implements MultiModalEmbedder {
    private final MultiModalEmbedder delegate;
    private final CacheConfig config;
    private final Map<String, EmbeddingResult> cache;

    public CachingMultiModalEmbedder(MultiModalEmbedder delegate, CacheConfig config) {
        this.delegate = delegate;
        this.config = config;
        this.cache = new ConcurrentHashMap<>();
        // Initialization happens here — in the constructor, not @PostConstruct
    }

    @Override
    public EmbeddingResult embed(String text) {
        return cache.computeIfAbsent(text, delegate::embed);
    }
}
```

```java
// Producer applies the wrapper conditionally
@ApplicationScoped
public class HybridSearchProducer {

    @Inject
    CacheConfig cacheConfig;

    @Produces
    @ApplicationScoped
    public MultiModalEmbedder multiModalEmbedder(
            @Inference("bge-m3") MultiModalEmbedder raw) {

        if (cacheConfig.enabled()) {
            return new CachingMultiModalEmbedder(raw, cacheConfig);
        }
        return raw;
    }
}
```

### Alternatives considered
- **CDI @Decorator with lazy init** — works but adds conditional checks to every decorated method call, clutters the decorator with boilerplate, and doesn't support conditional wrapping (the decorator is always active once discovered)
- **CDI @Decorator with @PostConstruct** — silently fails in Quarkus Arc (GE-20260806-93549d)
- **CDI Interceptor** — can have `@PostConstruct` but operates at method-level granularity, not interface-level wrapping; wrong abstraction for transparent delegation

### Why this is non-obvious
Most developers reaching for transparent bean wrapping in CDI would use `@Decorator` — it's the standard CDI pattern for exactly this use case. The idea of using a `@Produces` method to apply wrapping logic is unconventional because it conflates bean creation with decoration, which CDI was designed to separate. However, in Quarkus Arc where decorators have broken lifecycle support, the producer-site pattern is strictly superior: it supports initialization, conditional wrapping, and constructor injection without any Arc-specific workarounds.

### When to use it
- The wrapped bean is created via a `@Produces` method (or can be refactored to use one)
- The wrapper needs initialization (config, connections, conditional logic)
- Conditional wrapping is desired (enable/disable via config)
- The wrapper implements the same interface as the wrapped bean

Not suitable when:
- Multiple independent decorators need to compose on the same bean (producer-site wrapping doesn't compose as cleanly as decorator chains)
- The bean is auto-discovered by Arc without explicit production
