### Context
jmarkdoc requires the javadoc tool to resolve dependencies for full type information. When run standalone (not via maven-javadoc-plugin with classpath), dependency resolution fails and jmarkdoc falls back to "source-only mode" with a warning.

### Technique
The warning message ("javadoc analysis failed; retrying in source-only mode...") suggests degraded output. In practice, source-only mode produces high-quality markdown: full method signatures with generics, javadoc comment preservation, parameter documentation, and correct type relationships within the module.

Tested against casehub-engine-api (a non-trivial API module): 247 types documented with complete signatures, javadoc blocks, and parameter descriptions. Output is deterministic (byte-for-byte identical across runs) and suitable for RAG indexing.

```bash
# Standalone invocation — will fall back to source-only mode
java -jar jmarkdoc.jar src/main/java docs/guides/api/

# Output: "javadoc analysis failed; retrying in source-only mode..."
# Result: 247 well-formatted markdown files
```

For full dependency resolution (simple names instead of FQNs for external types), integrate via maven-javadoc-plugin with the project classpath. But source-only mode is often sufficient for documentation purposes.

### Why this is non-obvious
The warning message creates the impression that source-only output is a degraded fallback to be avoided. A developer would naturally spend time configuring the classpath before checking whether the fallback output is already adequate. In many cases, the simpler standalone invocation produces documentation good enough to ship.
