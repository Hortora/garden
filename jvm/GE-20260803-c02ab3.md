### Symptom
Adding `dominantFunction: Se` and `auxiliaryFunction: Fi` to the `disposition:` block in an Eidos YAML descriptor causes `UnrecognizedPropertyException` at startup:

```
Unrecognized field "dominantFunction" (class ...ClasspathYamlDescriptorRegistrar$DispositionConfig),
not marked as ignorable (8 known properties: "socialOrient", "mbtiType", "enneagramType",
"ruleFollowing", "delegation", "riskAppetite", "autonomy", "dispositionProfile", "conflictMode")
```

### Context
The `AgentDisposition` API (eidos#112) has `dominantFunction` and `auxiliaryFunction` fields. But the YAML registrar's inner `DispositionConfig` class does not include them — it only deserializes the 9 fields listed in the error message.

### Root cause
The dominant/auxiliary designation is auto-derived from the `dispositionProfile` weights (top-1 = dominant, top-2 = auxiliary). It is not a declared YAML field. The API fields exist for programmatic construction, not YAML declaration.

### Fix
Omit `dominantFunction` and `auxiliaryFunction` from YAML descriptors entirely. Declare the weighted `dispositionProfile` instead — the system derives dominant/auxiliary automatically:

```yaml
disposition:
  delegation: false
  dispositionProfile:
    - term: se
      weight: 0.45
    - term: fi
      weight: 0.20
    # ... remaining functions
```

For MBTI-typed characters, `mbtiType: ENTJ` auto-generates the profile including dominant/auxiliary derivation.

### Why this is non-obvious
The fields exist on the public `AgentDisposition` record. The error only surfaces at YAML parse time — there is no compile-time signal that the YAML registrar uses a different (narrower) schema than the API.
