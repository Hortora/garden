### Symptom

`UnfinishedStubbingException` thrown at a line that looks syntactically correct — `when(mock.method()).thenReturn(value)`. The error message points at a helper method call inside `thenReturn()`.

### Context

A test helper method internally creates a mock and stubs it with `when()`. The helper is called inside another `when().thenReturn()` chain:

```java
// Helper that internally stubs a mock
CaseInstance caseInstance(UUID id, String type, Map<String, Object> working) {
    CaseInstance instance = new CaseInstance();
    CaseContext ctx = mock(CaseContext.class);
    when(ctx.getOrDefault(eq("working"), any())).thenReturn(working);  // inner when()
    instance.setCaseContext(ctx);
    return instance;
}

// Test code — indirect nesting
when(caseCache.get(caseId)).thenReturn(caseInstance(caseId, "hvac", Map.of()));
//                                     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                                     This call opens an inner when() before
//                                     the outer thenReturn() completes
```

Mockito's framework state tracks the "current stubbing in progress." The outer `when(caseCache.get(caseId))` opens a stubbing context. Before `thenReturn()` can close it, `caseInstance()` opens a second stubbing context on a different mock. Mockito sees two overlapping `when()` calls and throws.

The nesting is indirect — the helper method hides the inner `when()`, making the root cause non-obvious. The stack trace points at the helper, not at the outer `when()`.

### Root cause

Mockito maintains global state for the "stubbing in progress." Nested `when()` calls — even on different mocks — corrupt this state. The indirection through a helper method makes the nesting invisible at the call site.

### Fix

Extract the helper call to a local variable before the outer `when()`:

```java
// Correct — helper runs outside the when() context
CaseInstance inst = caseInstance(caseId, "hvac", Map.of());
when(caseCache.get(caseId)).thenReturn(inst);
```

Alternative: use `doReturn().when()` inside the helper instead of `when().thenReturn()`. `doReturn` does not open a stubbing context during setup:

```java
CaseContext ctx = mock(CaseContext.class);
doReturn(working).when(ctx).getOrDefault(eq("working"), any());
```

### Why this is non-obvious

The test code at the call site looks correct — `when(x).thenReturn(y)` with a method call producing `y`. The error message points at the helper, not the nesting. Developers typically debug the helper's stubbing rather than recognising the outer `when()` as the problem. The issue only manifests when the helper is called inside `thenReturn()`, not when called standalone.
