### Symptom
`TrialSafetySignal.findByTrialAndType(trialId, signalType, tenantId)` returns `null` in integration tests despite seeding matching data. No error, no warning — the signal is simply never detected. `aggregateTrial()` completes successfully with 0 signals.

### Context
`TrialSafetyAggregationJob` runs on a Quartz scheduler thread — no request context, no `CurrentPrincipal`. It reads `tenantId` from `@ConfigProperty(name = "casehub.clinical.trial-safety.tenant-id", defaultValue = "default")` and uses that literal value in all Panache queries (`TrialSite.list("trialId = ?1 AND tenantId = ?2", trialId, tenantId)`).

Integration tests using `@QuarkusTest` seed data with `entity.tenantId = principal.tenancyId()`. If `FixedCurrentPrincipal.tenancyId()` returns anything other than `"default"` (the config property default), the query returns empty results.

### What was tried (didn't work)
- Seeding data with `principal.tenancyId()` — silent mismatch, query returns empty
- Debugging the aggregation job's detection logic — detection is correct, the data simply isn't found

### Root cause
Tenant identity comes from two unrelated sources: test entities use `FixedCurrentPrincipal.tenancyId()`, but the scheduled job uses a config property. These are not wired together. The mismatch is invisible because Panache queries with no matching rows return empty lists, not errors.

### Fix
Stamp `tenantId = "default"` explicitly on all entities in test `@BeforeEach` methods, matching the config property default:

```java
trial.tenantId = "default";  // matches casehub.clinical.trial-safety.tenant-id default
site.tenantId = "default";
enrollment.tenantId = "default";
ae.tenantId = "default";
```

Do NOT use `principal.tenancyId()` for entities that will be queried by the aggregation job.

### Why this is non-obvious
The tenant mismatch is completely silent. The job queries return empty results — no exception, no warning log. The developer's mental model ("I'm setting the tenant correctly via the principal") is correct for request-scoped code but wrong for scheduler-thread code that reads tenant from config.

### Alternatives considered
- Setting `casehub.clinical.trial-safety.tenant-id` in test properties to match `FixedCurrentPrincipal` — works but couples test config to the principal's implementation detail
- Using `principal.tenancyId()` and overriding the config property — same coupling problem
