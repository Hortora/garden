### Symptom
Web components embedded via `html()` in pages-ui DSL pages receive string attributes only. Complex properties (objects, arrays, function callbacks) set on the component in the HTML string are silently ignored — the component renders with default/empty state.

### Context
pages-ui DSL provides two mechanisms for hosting external web components:
- `html(content: string)` — renders via `renderHtml(el, props)` which does `el.innerHTML = props.content`
- `hostPanel(typeName: string, panelProps?: Record<string, unknown>)` — creates the element via `document.createElement(typeName)` and calls `configure(panelProps)` before `connectedCallback()`

When integrating blocks-ui Lit components (e.g. `<blocks-kpi-metric-row>`, `<blocks-work-item-detail>`) that need `MetricDefinition[]`, `WorkIdentity`, or `TabDefinition[]` with function callbacks, `html()` silently fails because innerHTML can only set string attributes.

### Root cause
`renderHtml` at `pages-runtime/src/content.ts:2` implements `el.innerHTML = props.content`. HTML attribute syntax can only express strings. Lit's property binding syntax (`.property=${value}`) is template literal syntax that requires Lit's `html` tagged template — it has no meaning inside an innerHTML string.

### Fix
Use `hostPanel()` instead of `html()` for any component that needs non-string properties:

```typescript
// Wrong — complex properties silently lost
html(`<blocks-kpi-metric-row endpoint="/api/kpi" columns="4"></blocks-kpi-metric-row>`)

// Right — configure() receives JS objects by reference
hostPanel("blocks-kpi-metric-row", {
  endpoint: "/api/kpi",
  columns: 4,
  density: "comfortable",
})
```

The hosted component must implement `ConfigurablePanel.configure(props)` (defined in `pages-component/model/hosting.ts`). Most blocks-ui components already do via `DataSourceMixin`.

### Why this is non-obvious
`html()` is the first DSL function developers reach for when embedding custom HTML. It works for static content, simple elements, and components that only need string attributes. The failure mode is silent — the component renders but with default state, and there's no error message indicating that properties weren't delivered. The `hostPanel()` alternative isn't discoverable from the `html()` API — you have to know the hosting model exists.
