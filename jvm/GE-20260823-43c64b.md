### Symptom
Quarkus fails to start with `ConfigValidationException`:
```
SRCFG00040: The config property %test.casehub.inference.models.strategy-vs-terran.tokenizer-path
is defined as the empty String ("") which the following Converter considered to be null:
io.smallrye.config.Converters$BuiltInConverter
```

### Context
A `@ConfigMapping` interface declares `String tokenizerPath()` as a required property. For ONNX tensor models that don't use a tokenizer, the natural approach is to set `tokenizer-path=` (empty string) to satisfy the config requirement while indicating "not needed". SmallRye Config's `BuiltInConverter` converts empty strings to null, which then fails the non-null validation for required properties.

### What was tried (didn't work)
- Setting `tokenizer-path=` (empty string) — rejected as null by BuiltInConverter
- Setting `tokenizer-path=NONE` — accepted by config but the code tries to load a tokenizer from path "NONE" and fails with IOException
- Removing the property entirely — fails with "required property not found"

### Root cause
SmallRye Config treats empty strings as null for `String` return types in `@ConfigMapping` interfaces. When the property is required (not `Optional<String>`), null violates the non-null constraint. There is no way to satisfy a required `String` property with "empty/not applicable" — the interface must be changed to `Optional<String>` or the config property must point to a valid value.

### Fix
Remove the config entries for models that don't need a tokenizer. Let the CDI `Instance<InferenceModel>` remain unsatisfied — check `isResolvable()` before accessing:

```java
// In the producer/consumer:
if (!modelInstance.isResolvable()) return; // ONNX tier unavailable
```

Tests that need the models construct them directly via `new ModelConfig(path)` (which accepts null for tokenizerPath) rather than relying on CDI injection.

### Why this is non-obvious
Empty string is the natural "not applicable" value for optional string properties. The conversion to null happens silently inside SmallRye's converter pipeline — the error message mentions `BuiltInConverter` but doesn't explain why empty string was rejected. The fix requires either changing the library's config interface or restructuring how the model is loaded.
