### Symptom

After refactoring a lifecycle manager to read state from CaseContext (in-memory) instead of EventLog (persisted), a Quartz SLA timeout job silently treats all milestones as PENDING — even ones that were ACTIVE before the JVM restart.

No error is thrown. The job reads null from CaseContext and falls through to the default (PENDING), skipping SLA violation detection.

### Context

Quartz with RAM store replays persisted job triggers after JVM restart. The `CaseInstance` loaded from the database at that point does not have `CaseContext` populated — CaseContext is an in-memory construct (`LinkedHashMap` in `InMemoryCaseContextStore`) that is populated during case startup, not from database state.

### Root cause

Two different execution contexts read the same state:
1. **Event-driven handlers** (Vert.x `@ConsumeEvent`) — always have a live `CaseInstance` with populated CaseContext
2. **Scheduled jobs** (Quartz `Job.execute()`) — load `CaseInstance` from repository, which may not have CaseContext populated after restart

Refactoring the state source from EventLog to CaseContext works for (1) but silently breaks (2).

### Fix

Maintain a two-tier state model:
- **CaseContext** — canonical for event-driven consumers (reactive handlers that always have a live CaseInstance)
- **EventLog** — canonical for scheduled jobs that may execute without CaseContext (Quartz jobs, recovery coordinators)

```java
// Event-driven handler — reads from CaseContext (O(1), always populated)
MilestoneLifecycleStatus status = readFromCaseContext(caseInstance, milestoneName);

// Quartz job — reads from EventLog (O(n), but works after restart)
MilestoneLifecycleStatus status = deriveFromEventLog(caseId, milestoneName, tenancyId);
```

### Why this is non-obvious

The refactoring appears safe because CaseContext is always populated when the lifecycle manager evaluates milestones on `CONTEXT_CHANGED` events. The Quartz job runs in a completely different execution context where this invariant doesn't hold — and the failure is silent (default to PENDING instead of throwing).
