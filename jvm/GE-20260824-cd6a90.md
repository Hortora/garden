### Symptom
Application crashes at startup with `IllegalArgumentException: timestampField 'minute' not found in innerFields` when registering a CBR schema with a `TimeSeries` field.

### Context
When defining a `FeatureField.timeSeries("timeline", "minute", dtwSpec, ...)` for CBR schema registration, the natural assumption is that the timestamp field name (`"minute"`) is metadata — it tells DTW which field to use for time alignment. The inner fields list would then contain only the value fields (e.g. `our_workers`, `our_minerals`).

### Root cause
The `TimeSeries` record constructor in neocortex `memory-api` validates that the named `timestampField` exists as one of the `innerFields`:

```java
var tsField = innerFields.stream()
    .filter(f -> f.name().equals(timestampField))
    .findFirst().orElse(null);
if (tsField == null) {
    throw new IllegalArgumentException(
        "timestampField '" + timestampField + "' not found in innerFields");
}
```

The timestamp field must be explicitly included in the inner fields list as a `FeatureField.numeric()`.

### Fix

Include the timestamp field in the `innerFields` list:

```java
// Wrong — crashes at startup
FeatureField.timeSeries("timeline", "minute",
    new SimilaritySpec.DtwSpec(new WarpingConstraint.SakoeChibaBand(3)),
    FeatureField.numeric("our_workers", 0, 80),
    FeatureField.numeric("our_minerals", 0, 5000),
    FeatureField.numeric("our_army_supply", 0, 200))

// Correct — minute is declared as an inner field
FeatureField.timeSeries("timeline", "minute",
    new SimilaritySpec.DtwSpec(new WarpingConstraint.SakoeChibaBand(3)),
    FeatureField.numeric("minute", 0, 30),          // ← must be here
    FeatureField.numeric("our_workers", 0, 80),
    FeatureField.numeric("our_minerals", 0, 5000),
    FeatureField.numeric("our_army_supply", 0, 200))
```

### Why this is non-obvious
The factory method signature `timeSeries(name, timestampField, spec, innerFields...)` suggests the timestamp field is a separate concern from the inner fields. The varargs parameter reads as "the value fields to compute DTW over" — not "all fields including the timestamp." The crash only manifests at `@Startup`/`@PostConstruct` when the schema is registered, not at compile time.
