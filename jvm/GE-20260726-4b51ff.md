### Symptom

Quarkus augmentation fails with 22 `AmbiguousResolutionException` errors for `CurrentPrincipal`:

```
Ambiguous dependencies for type io.casehub.platform.api.identity.CurrentPrincipal
  - available beans:
    - CLASS bean [...ChatAppCurrentPrincipal...]
    - CLASS bean [...QhorusInboundCurrentPrincipal...]
```

Build hangs at the CDI validation step (appears stuck for 10+ minutes with no output after the `BeanArchives` WARN line — the augmentation eventually fails or is killed).

### Context

The `capability-ownership.md` platform doc describes `QhorusInboundCurrentPrincipal` as `@DefaultBean @ApplicationScoped`. In the actual code, it is `@ApplicationScoped` only — NOT `@DefaultBean`. Any application providing a non-`@DefaultBean` `CurrentPrincipal` (e.g. bridging pages-auth JWT claims) creates an ambiguous CDI resolution.

### Root cause

`QhorusInboundCurrentPrincipal` at `io.casehub.qhorus.runtime.identity` is annotated `@ApplicationScoped` without `@DefaultBean`. It reads tenant from the `X-Tenancy-ID` HTTP header via `TenancyContextFilter`. Consumer applications that use JWT-based identity (pages-auth, platform-oidc) need their own `CurrentPrincipal` that reads from JWT claims — but CDI sees two non-default implementations and fails.

### Fix

Exclude `QhorusInboundCurrentPrincipal` in the consumer app's `application.properties`:

```properties
quarkus.arc.exclude-types=io.casehub.qhorus.runtime.identity.QhorusInboundCurrentPrincipal
```

Do NOT also exclude `TenancyContextFilter` — it is a `@Provider @PreMatching` JAX-RS filter. Excluding it from CDI causes a `NullPointerException` because RESTEasy Reactive still discovers and instantiates it via JAX-RS provider scanning, but its `@Inject` fields are null. The filter is harmless — it reads the `X-Tenancy-ID` header and stores it in `InboundTenancyContext`, which the consumer app's `CurrentPrincipal` simply ignores.

### Why this is non-obvious

The platform documentation (capability-ownership.md) explicitly says `@DefaultBean` — a developer reads the doc, provides a non-default implementation expecting CDI displacement, and gets an ambiguous resolution error. The build appears to hang (10+ minutes of no output) before eventually failing, making the root cause hard to diagnose.
