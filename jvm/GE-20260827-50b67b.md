### Symptom

A `@GraphQLApi` resolver method returns a type from another Maven module. SmallRye GraphQL fails at boot with `type X not found in schema` because the type's module isn't in the Jandex index. Adding the module to `quarkus.index-dependency` risks exposing problematic types (sealed interfaces, empty classes) — see GE-20260827-d453bd.

### Context

In a multi-module Quarkus project where `@GraphQLApi` resolvers live in the `app` module but return types from `domain` or `review` modules. SmallRye GraphQL resolves types by walking method signatures recursively — any type reachable from a return type or parameter must be in the Jandex index.

### Fix

Create local record types in the resolver class that mirror the external type's fields. Map from the domain type to the local type in the method body.

**Before** (fails — `PrPayload` not in index):

```java
@Query
public GovernanceQueryService.ReviewDetail reviewDetail(UUID caseId) {
    return governanceQuery.reviewDetail(caseId, tenant);
}
// ReviewDetail contains PrPayload from the review module
```

**After** (works — all types local to the app module):

```java
@Query
public ReviewDetailResult reviewDetail(UUID caseId) {
    var detail = governanceQuery.reviewDetail(caseId, tenant);
    var pr = detail.pr();
    return new ReviewDetailResult(
            detail.caseId(),
            new PrInfo(pr.repo(), pr.prNumber(), pr.headSha(),
                       pr.baseRef(), pr.linesChanged(), pr.contributor(),
                       pr.changedPaths()),
            detail.timeline(),
            detail.capabilities());
}

public record PrInfo(String repo, int prNumber, String headSha,
                     String baseRef, int linesChanged, String contributor,
                     List<String> changedPaths) {}

public record ReviewDetailResult(UUID caseId, PrInfo pr,
                                 List<EventEntry> timeline,
                                 List<CapabilityStatus> capabilities) {}
```

The same pattern applies to mutation return types:

```java
// Domain type IncidentFeedbackResult → local IncidentReport
public record IncidentReport(UUID caseId, int attestationsWritten,
                             List<FlaggedAgentEntry> flaggedAgents) {}
public record FlaggedAgentEntry(String agentId, String capabilityTag,
                                UUID attestationId) {}
```

### Why this is non-obvious

The natural instinct is to make the external type visible (via `quarkus.index-dependency` or `jandex-maven-plugin`) rather than duplicating fields in a wrapper. The wrapper feels like boilerplate — but it's actually better API design because:

1. It decouples the GraphQL/MCP schema from internal domain model evolution
2. It avoids exposing internal fields (like `contributorNumericId`) that aren't relevant to API consumers
3. It prevents sealed interface and empty-type issues from `quarkus.index-dependency` (GE-20260827-d453bd)
4. It follows the same pattern already used by all mutation methods (each returns a local record like `RetryResult`, `EnqueueResult`, etc.)
