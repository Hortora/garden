### Symptom
A `@Scheduled(every = "6h")` method fires immediately when the application starts, not after 6 hours.

### Context
Quarkus `@Scheduled` with an `every` interval fires the first invocation as soon as the scheduler is active — typically within seconds of the Quarkus banner appearing. This happens on a worker thread concurrent with the main startup sequence.

### Fix
Use the `delayed` parameter to defer the first invocation:

```java
@Scheduled(every = "${interval:6h}", delayed = "60s")
void periodicTask() { ... }
```

`delayed = "60s"` means the first invocation runs 60 seconds after Quarkus reports ready. Subsequent invocations follow the `every` interval normally.

### Why this is non-obvious
The annotation name `every = "6h"` strongly implies "run every 6 hours, starting 6 hours from now." The immediate-fire behaviour is not intuitive and the `delayed` parameter is easy to overlook in the Javadoc. Combined with concurrent startup, this creates a race condition window that only manifests under specific timing.
