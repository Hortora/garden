### Symptom
CDI cannot resolve `Instance<SimulationStrategy<I, O>>` because type erasure collapses all parameterisations to `SimulationStrategy`. Injecting the raw type or using qualifiers per type parameter combination doesn't scale.

### Context
When building a registry that maps string keys to generic SPI implementations — e.g. a `SimulationRuntime` that resolves `SimulationStrategy<I, O>` by qualified name, or a `CallbackRegistry` that resolves handlers by SPI name — CDI's type erasure makes `@Inject Instance<GenericSpi<I, O>>` unusable.

### Root cause
Java generics are erased at runtime. CDI bean resolution uses runtime types. `Instance<SimulationStrategy<String, String>>` and `Instance<SimulationStrategy<Object[], List<AgentEvent>>>` resolve to the same erased type and cannot be distinguished.

### Fix
Make the registry bean non-generic. Store implementations in a `ConcurrentHashMap<String, SimulationStrategy<?, ?>>` keyed by a string identifier (the "qualified name"). Callers request by string key and cast:

```java
@SuppressWarnings({"rawtypes", "unchecked"})
public class SimulationRuntime {
    private final SimulationCorpus corpus;  // raw type
    private final ConcurrentHashMap<String, SimulationStrategy<?, ?>> cache = new ConcurrentHashMap<>();

    public <I, O> Optional<SimulationStrategy<I, O>> strategyFor(String qualifiedName) {
        return config.strategyFor(qualifiedName)
            .map(name -> (SimulationStrategy<I, O>) cache.computeIfAbsent(
                qualifiedName, qn -> createStrategy(qn, name)));
    }
}
```

The type safety comes from the adapter layer — each SPI adapter registers its own `KeyExtractor<I>` and seeds its own `SimulationCorpus<I, O>` with the correct types. The registry is the unchecked bridge between the generic contracts and CDI's non-generic world.

### Why this is non-obvious
The natural instinct is to use CDI qualifiers (`@Named`, custom qualifier per type) or `Instance<>` with type parameters. Both fail at scale — qualifiers require a new annotation per type combination, and `Instance<>` with type parameters doesn't resolve correctly due to erasure. The raw-type registry with string-key resolution feels like a regression from type safety, but it's the correct pattern for CDI when the generic type parameter space is open-ended.

### Alternatives considered
- **CDI qualifiers per type combination** — doesn't scale; each new SPI needs a new qualifier annotation
- **`Instance<SimulationStrategy>` raw type** — resolves but loses all type information at the injection point
- **Producer methods per SPI** — requires a producer for every SPI being simulated; defeats the purpose of a generic framework

### Caveats
- The registry's thread safety depends on `ConcurrentHashMap.computeIfAbsent` — safe for the lazy-init pattern but callers must not mutate the returned strategy
- `@SuppressWarnings("unchecked")` is load-bearing — the unchecked cast is correct only if the adapter registered consistent types
