### Symptom

Compile error when constructing `FeatureValue` instances or pattern-matching on them using names inferred from the schema DSL.

### Context

`CbrFeatureSchema` registration uses `FeatureField.categorical()`, `FeatureField.categoricalList()`, and `FeatureField.numeric()`. The natural assumption is that runtime `FeatureValue` types follow the same naming: `FeatureValue.Categorical`, `FeatureValue.CategoricalList`, `FeatureValue.Numeric`.

### Root cause

`FeatureValue` is a sealed interface with inner records that use different names from the schema DSL:

| Schema DSL (`FeatureField`) | Runtime type (`FeatureValue`) | Factory method |
|---|---|---|
| `categorical(name)` | `StringVal` | `FeatureValue.string(value)` |
| `categoricalList(name)` | `StringListVal` | `FeatureValue.stringList(values)` |
| `numeric(name, min, max)` | `NumberVal` | `FeatureValue.number(value)` |

There is no `FeatureValue.Numeric`, `FeatureValue.Categorical`, or `FeatureValue.CategoricalList`. Pattern matching must use `FeatureValue.NumberVal n`, not `FeatureValue.Numeric n`.

### Fix

Use the correct runtime type names:
```java
if (fv instanceof FeatureValue.NumberVal n) { double val = n.value(); }
FeatureValue.string("PHASE_III");      // not FeatureValue.categorical(...)
FeatureValue.stringList(List.of("A")); // not FeatureValue.categoricalList(...)
FeatureValue.number(3.0);              // correct — but the type is NumberVal, not Numeric
```

### Why this is non-obvious

The schema DSL uses domain-appropriate names (categorical, numeric) while the runtime types use generic names (StringVal, NumberVal). No IDE autocompletion connects `FeatureField.categorical` to `FeatureValue.StringVal`.
