### Context

Querying `ActorTrustScore` from clinical code (default PU) when the entity lives in the qhorus PU. Direct Panache `find()` fails because `ActorTrustScore` is a regular JPA entity, not a Panache entity. Raw `EntityManager` injection requires specifying the `@PersistenceUnit("qhorus")` qualifier and building JPQL manually.

### Technique

Inject `ActorTrustScoreRepository` (casehub-ledger runtime) instead:

```java
@Inject ActorTrustScoreRepository trustScoreRepository;

double score = trustScoreRepository
    .findCapabilityDimension(actorId, "safety-monitoring", "safety-accuracy")
    .map(s -> s.trustScore)
    .orElse(0.5);
```

The repository is `@ApplicationScoped` with `@Alternative` wiring — the JPA implementation (`JpaActorTrustScoreRepository`) handles the correct persistence unit internally. The 3-arg method (`actorId, capabilityKey, dimensionKey`) maps to the named query `ActorTrustScore.findCapabilityDimensionByKeys`.

### Why this is non-obvious

The natural approach is to use `ActorTrustScore.find()` (Panache style) or inject an `EntityManager` with the qhorus PU qualifier. Neither works cleanly — `ActorTrustScore` doesn't extend `PanacheEntity`, and cross-PU `EntityManager` injection adds coupling to the persistence unit name. The repository abstracts all of this.
