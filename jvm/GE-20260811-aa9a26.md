### Symptom

Quarkus fails to start with `ConfigValidationException` listing 5 missing required properties:

```
java.util.NoSuchElementException: SRCFG00014: The config property casehub.cbr.retention.case-types is required but it could not be found in any config source
java.util.NoSuchElementException: SRCFG00014: The config property casehub.cbr.retention.domain is required but it could not be found in any config source
java.util.NoSuchElementException: SRCFG00014: The config property casehub.cbr.trust-retention.case-types is required but it could not be found in any config source
java.util.NoSuchElementException: SRCFG00014: The config property casehub.cbr.trust-retention.domain is required but it could not be found in any config source
java.util.NoSuchElementException: SRCFG00014: The config property casehub.memory.retention.domain is required but it could not be found in any config source
```

### Context

Triggered by adding `casehub-blocks` as a compile dependency. The blocks module transitively pulls in `casehub-neocortex-memory`, which declares these 5 properties as required via SmallRye Config mappings.

### Root cause

`casehub-neocortex-memory` uses `@ConfigMapping` with required properties. When the jar is on the classpath (via blocks transitive dependency), Quarkus's config validation runs at startup and fails if the properties are absent — even if no memory features are used.

### Fix

Add all 5 properties to `application.properties`:

```properties
casehub.memory.retention.domain=<your-app-domain>
casehub.cbr.retention.domain=<your-app-domain>
casehub.cbr.retention.case-types=<your-case-type>
casehub.cbr.trust-retention.domain=<your-app-domain>
casehub.cbr.trust-retention.case-types=<your-case-type>
```

Example for fsitrading:
```properties
casehub.memory.retention.domain=fsitrading
casehub.cbr.retention.domain=fsitrading
casehub.cbr.retention.case-types=strategy-evaluation
casehub.cbr.trust-retention.domain=fsitrading
casehub.cbr.trust-retention.case-types=strategy-evaluation
```

### Why this is non-obvious

The error messages reference `casehub.cbr.*` and `casehub.memory.*` — neither mentions blocks. A developer adding a blocks dependency has no reason to expect neocortex memory configuration requirements. The transitive chain (`blocks → neocortex-memory → config validation`) is invisible without dependency tree analysis.

### Why this fix

These properties configure the memory retention and CBR subsystems that blocks uses internally for agent memory and CBR-based routing. Even if the application doesn't use these features directly, the config mappings are validated at startup because they're `@ConfigMapping` required fields, not optional.

### Invalidation triggers

If casehub-neocortex-memory makes these properties optional (with defaults), this entry becomes obsolete.
