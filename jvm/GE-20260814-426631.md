### Symptom
`NullPointerException` when constructing `AdaptationContext` with null for case-specific fields:
```
java.lang.NullPointerException: definition
  at java.base/java.util.Objects.requireNonNull(Objects.java:246)
  at io.casehub.engine.plan.adaptation.AdaptationContext.<init>
```

### Context
When implementing `PlanRevisionStrategy` in an application without case infrastructure (no `CaseDefinition`, no `CaseInstance`, no `TaskStatus`), the natural approach is to pass `null` for unused fields. The constructor rejects this.

### Root cause
`AdaptationContext` is a Java record with `Objects.requireNonNull()` on multiple fields: `caseId` (UUID), `definition` (CaseDefinition), `latestStatus` (TaskStatus), `latestBindingName` (String), `compoundId` (String). Similarly, `PlanStepDescriptor.capabilityName` and `CompletedStep.capabilityName` reject null.

### Fix
Use placeholder values for all non-null required fields:

```java
var adaptCtx = new AdaptationContext(
    UUID.randomUUID(),                                    // caseId
    tenancyId,                                            // tenancyId
    "",                                                   // compoundId
    goalName,                                             // goalName
    completedSteps,                                       // completedSteps
    pendingSteps,                                         // pendingSteps
    List.of(),                                            // runningSteps
    null,                                                 // currentContext (JsonNode — nullable)
    new CaseDefinition("manor", "wacky-manor", "1.0"),    // definition
    TaskStatus.COMPLETED,                                 // latestStatus
    "",                                                   // latestBindingName
    plan.revisionGeneration()                             // adaptationGeneration
);
```

For `PlanStepDescriptor` and `CompletedStep`, use `""` for `capabilityName`.

### Why this is non-obvious
The SPI interface (`PlanRevisionStrategy.revise(RevisionContext)`) doesn't indicate which context fields are read vs ignored. A strategy that only uses `goalName`, `completedSteps`, and `pendingSteps` still crashes if `definition` is null — the validation runs in the constructor before any strategy code executes.

### Constraints
Applies when using the plan adaptation SPI without full case infrastructure. The placeholder values are never read by the manor's strategy implementation — they exist solely to satisfy the constructor.
