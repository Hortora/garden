## Symptom

`@QuarkusTest` startup fails with H2 DDL error:

```
Syntax error in SQL statement "create table lab_result (..., [*]value numeric(19,4) not null, ...)"; expected "identifier"
```

The `[*]` marker points at the column name but the error says "expected identifier" — not "reserved word". The column name `value` looks like a perfectly valid identifier.

## Context

Quarkus test environment using `quarkus.hibernate-orm.database.generation=drop-and-create` with H2 in PostgreSQL compatibility mode (`jdbc:h2:mem:test;MODE=PostgreSQL`). Entity has a field named `value` (or `type`, `key`, `status`, etc.) mapped to a column with the same name.

PostgreSQL accepts these column names unquoted. H2 in PostgreSQL mode does not — it still enforces its own reserved word list for DDL.

## What was tried (didn't work)

- Checked for typos in entity annotations
- Verified column types and nullability
- Compared with working entities (which had non-reserved column names)
- The error message gives no hint that it's a reserved word problem

## Root cause

`value` and `type` are SQL reserved words in H2. Hibernate's `drop-and-create` DDL generates unquoted column names. H2's parser rejects them with a generic syntax error, not a "reserved word" diagnostic.

## Fix

Use `@Column(name = "result_value")` to map the Java field to a non-reserved column name:

```java
@Column(name = "result_value", nullable = false, precision = 19, scale = 4)
public BigDecimal value;

@Column(name = "vital_type", nullable = false, length = 50)
public VitalType type;
```

Update Flyway migrations to match the renamed columns.

## Why this is non-obvious

The error message says "expected identifier" — which is what a column name IS. Nothing in the message mentions reserved words. A developer would typically look for syntax errors in the DDL, not question whether a common English word is reserved. PostgreSQL accepts these names unquoted, so the issue only manifests in H2 test environments.

### Alternatives considered

- Quoting column names with `@Column(name = "\"value\"")` — works but ugly and fragile across databases
- Switching test DB to PostgreSQL testcontainers — correct but slower test startup
- Renaming the Java field — breaks the domain model for a test infrastructure concern
