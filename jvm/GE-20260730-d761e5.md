### Symptom
CloudEvent fired via CDI `Event<CloudEvent>.fireAsync()` — no situation evaluation happens, no case
created, no error or exception. The RAS pipeline is completely silent.

### Context
`RasEngine.onCloudEvent(@ObservesAsync CloudEvent)` is the entry point for the RAS detection pipeline.
It reads `tenancyid` from the CloudEvent's extension attributes. If the extension is missing or null,
the engine logs a WARNING and skips all processing.

### Root cause
`RasEngine.extractTenancyId()` reads `event.getExtension("tenancyid")` — lowercase, no hyphens.
If null, the engine returns early with a `"CloudEvent without tenancyid extension — skipping"` log
line at WARNING level. In test scenarios with multiple CDI observers and log interleaving, this
warning is easy to miss.

### Fix
Always include the `tenancyid` extension when constructing test CloudEvents:

```java
CloudEvent event = CloudEventBuilder.v1()
    .withId(UUID.randomUUID().toString())
    .withSource(URI.create("test://siem"))
    .withType("soc.alert.siem.crowdstrike")
    .withExtension("tenancyid", "test-tenant")  // required by RasEngine
    .build();
```

Note: `tenancyid` is the extension attribute name — all lowercase, no hyphens, no camelCase.
CloudEvents spec requires extension names to be lowercase alphanumeric.

### Why this is non-obvious
The silent skip produces no exception, no test failure at the CDI level — the event is "handled"
(the observer completes without error). The only symptom is that downstream effects don't happen.
When debugging "case not created", the natural suspects are situation definitions, ganglion
registration, or trigger configuration — not a missing extension attribute on the event itself.
