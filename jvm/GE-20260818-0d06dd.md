### Symptom
A `@BuildStep` method annotated on a Quarkus extension processor compiles and the extension is loaded, but the method never executes. No error at compile time. At test time, the error is: "Build step 'X#methodName' does not produce any build item and thus will never get executed."

### Context
When writing a Quarkus build extension with a validation-only build step — a method that reads the Jandex index and emits warnings/errors but doesn't produce a new build item. Common when splitting annotation scanning (produces beans) from validation (only checks).

### What was tried (didn't work)
- `void validateTerms(CombinedIndexBuildItem index)` — compiles, never runs
- Adding `@BuildStep` annotation — present but insufficient

### Root cause
Quarkus's build step scheduler uses a dependency graph based on produced and consumed build items. A method that consumes build items (via parameters) but produces none (void return, no `BuildProducer<>` parameter, no `@Produce` annotation) has no dependents — nothing needs its output, so the scheduler never runs it.

### Fix
Three options:

1. **Fold into an existing build step** that already produces a build item — call the validation as a private method from within the producing step:
```java
@BuildStep
@Record(RUNTIME_INIT)
MyBuildItem processAnnotations(...) {
    // ... produce beans ...
    validateTerms(index);  // call as private method
    return new MyBuildItem(...);
}

private void validateTerms(CombinedIndexBuildItem index) {
    // validation logic
}
```

2. **Return a build item** from the validation step (even a marker):
```java
@BuildStep
ValidationCompleteBuildItem validateTerms(CombinedIndexBuildItem index) {
    // validation logic
    return new ValidationCompleteBuildItem();
}
```

3. **Use `@Produce` annotation**:
```java
@BuildStep
@Produce(ServiceStartBuildItem.class)
void validateTerms(CombinedIndexBuildItem index) {
    // validation logic
}
```

### Why this is non-obvious
The method compiles, the extension loads, and the `@BuildStep` annotation is present. Nothing indicates at compile time or extension discovery time that the step won't run. The error only surfaces at Quarkus test time (QuarkusUnitTest) — not during `mvn compile`. The mental model of "annotated methods are called" doesn't account for build step scheduling semantics.
