## Quarkus WebSocket UserData.TypedKey is final — anonymous subclass fails

### Symptom
`new UserData.TypedKey<>("connId") {}` fails with "cannot inherit from final io.quarkus.websockets.next.UserData.TypedKey".

### Context
Using `WebSocketConnection.userData()` to store per-connection state (e.g. a connection ID string). The `UserData` API requires `TypedKey<V>` instances for type-safe get/put. Some patterns for type tokens in Java use anonymous subclasses (`new TypeToken<T>() {}`), so the natural attempt is to use the same pattern.

### Root cause
`UserData.TypedKey` is declared `final` in Quarkus. This is intentional — the key's identity is based on the name string, not on the class. Anonymous subclasses would create a different class per instantiation site, which is unnecessary.

### Fix
Use the constructor directly without the anonymous subclass `{}`:

```java
// Fails — TypedKey is final
static final UserData.TypedKey<String> CONN_ID = new UserData.TypedKey<>("connId") {};

// Works
static final UserData.TypedKey<String> CONN_ID = new UserData.TypedKey<>("connId");
```

### Why this is non-obvious
The `{}` anonymous subclass pattern is common in Java for type tokens (Guava TypeToken, Jackson TypeReference, CDI TypeLiteral). Developers reaching for TypedKey assume the same pattern applies. The error message ("cannot inherit from final") is clear once you see it, but the instinct to use `{}` is strong enough that the first attempt will always fail.
