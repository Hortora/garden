# Quarkus @WrapBusinessError interceptor fires on all methods but only wraps exceptions for @Tool-annotated methods

## Symptom
After removing `@Tool` annotations from a CDI bean while keeping `@WrapBusinessError` on the class, tests asserting `ToolCallException` fail with the raw exception type (`IllegalArgumentException` or `IllegalStateException`). The stack trace shows `WrapBusinessErrorInterceptor.aroundInvoke()` IS called, but the exception passes through unwrapped.

## Context
Migrating `QhorusMcpTools` from `@Tool`-annotated methods to `@McpDomain` API interfaces. The class had `@WrapBusinessError({ IllegalArgumentException.class, IllegalStateException.class })` at the class level. After stripping all 52 `@Tool` annotations, 23 test files that asserted `ToolCallException` started failing.

## Root cause
`@WrapBusinessError` is a CDI interceptor binding — it activates on ALL public methods of the annotated class regardless of `@Tool` presence. However, the `WrapBusinessErrorInterceptor` implementation has an internal guard: it only wraps the listed exception types into `ToolCallException` when the invoked method is `@Tool`-annotated. Without `@Tool`, the interceptor fires (CDI binding is class-level) but the wrapping logic is skipped — exceptions propagate as-is.

## Fix
When removing `@Tool` annotations, also remove `@WrapBusinessError` from the class. Then update test assertions from `ToolCallException.class` to the actual exception type:

- `IllegalArgumentException` for validation failures (unknown channel, invalid type, malformed input)
- `IllegalStateException` for state violations (paused channel, ACL denied, rate limit exceeded, read-only instance)

Also remove any `ex.getCause()` chains in test assertions — without the wrapper, there's no cause to unwrap.

## Why this is non-obvious
The interceptor IS firing (visible in the stack trace), which suggests wrapping should happen. The conditional logic inside the interceptor is invisible from the CDI binding — you'd need to read the quarkus-mcp-server source to understand why exceptions pass through.
