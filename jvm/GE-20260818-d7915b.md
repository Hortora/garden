### Symptom
A Quarkus build extension compiles successfully. The `@BuildStep` method calls `SyntheticBeanBuildItem.configure(...).supplier(mySupplier).done()` where the supplier is a lambda capturing domain record instances (e.g. `AgentDisposition`, `List<AgentGoal>`). The build extension unit tests fail at augmentation time with an opaque error from `SyntheticBeansProcessor`.

### Context
When building Quarkus extensions that generate CDI beans from build-time annotation scanning. The extension extracts annotation values, constructs domain objects at build time, and captures them in a `Supplier<?>` lambda passed to `.supplier()`. The API signature accepts any `Supplier<?>` — no compile-time warning that the captured state must be bytecode-recordable.

### What was tried (didn't work)
- Passing the lambda directly: `() -> new MyRegistrar(complexDomainObject)` — compiles but fails at augmentation
- Capturing `List<Record>` in the lambda — same failure

### Root cause
Quarkus's `SyntheticBeanBuildItem.supplier()` records the supplier into Arc's generated bytecode. The captured state in the lambda must be bytecode-recordable (primitives, Strings, enums, and objects with no-arg constructor + public fields). Java records without explicit `Serializable` are NOT recordable. The augmentation fails when Quarkus attempts to generate the bean class, not at the point where `.supplier()` is called.

### Fix
Use a `@Recorder` class in the runtime module. The recorder method accepts only primitives/Strings/enums and constructs domain objects at runtime (not build time):

```java
// Runtime module — recorder
@Recorder
public class MyRecorder {
    public Supplier<MyBeanType> createBean(MyConfig config) {
        return () -> {
            // construct domain objects HERE at runtime, not at build time
            return new MyBeanType(config.field1, config.field2);
        };
    }
}

// MyConfig — must have no-arg constructor + public fields for recording
public class MyConfig {
    public String field1;
    public String field2;
    public MyConfig() {}
}

// Deployment module — build step
@BuildStep
@Record(RUNTIME_INIT)
void process(MyRecorder recorder, ...) {
    var config = new MyConfig();
    config.field1 = extractedValue;
    syntheticBeans.produce(SyntheticBeanBuildItem
        .configure(MyBeanType.class)
        .setRuntimeInit()
        .supplier(recorder.createBean(config))
        .done());
}
```

### Why this is non-obvious
The `.supplier(Supplier<?>)` API accepts any Supplier at compile time with no type constraint indicating recordability is required. The failure surfaces at augmentation — a phase most extension developers don't debug into. Related entries GE-20260614-efee3b (injection points) and GE-20260817-48caeb (setRuntimeInit requirement) cover other SyntheticBeanBuildItem traps in the same API surface.

### Alternatives considered
- `SyntheticBeanBuildItem.createWith(BeanCreator.class)` with a config map — works but limited to simple key-value pairs
- `SyntheticBeanBuildItem.runtimeValue(RuntimeValue<?>)` from a recorder — also valid, uses RuntimeValue wrapper instead of Supplier
