### Symptom
After widening a Java record field from `Map<String, String>` to `Map<String, Object>`,
YAML values like `monitoring_enabled: yes` silently change from `String "yes"` to
`Boolean true`. String interpolation that previously produced `"yes"` now produces `"true"`.

### Context
Happens when evolving a Jackson-deserialized YAML model to support typed values
(e.g. `batch_size: 500` as `Integer` instead of `String`). The type widening is
intentional — the boolean coercion is not.

### What was tried (didn't work)
Simply widening the record field type — assumed YAML parsing would remain stable
since the YAML content didn't change.

### Root cause
Jackson YAML uses target-type-driven type inference. With `Map<String, String>`,
the parser coerces all YAML values to strings — `yes` stays `"yes"`. With
`Map<String, Object>`, the parser applies YAML 1.1 type resolution where `yes`,
`no`, `on`, `off` are boolean literals. The trigger is the Java type change, not
any YAML configuration.

### Fix
Enable `PARSE_BOOLEAN_LIKE_WORDS_AS_STRINGS` (available since Jackson 2.15) on
the `YAMLFactory`:

```java
ObjectMapper yamlMapper = new ObjectMapper(YAMLFactory.builder()
        .enable(YAMLParser.Feature.PARSE_BOOLEAN_LIKE_WORDS_AS_STRINGS)
        .build());
```

This keeps `yes`/`no`/`on`/`off` as strings while preserving typed resolution
for integers, doubles, and YAML 1.2 booleans (`true`/`false`).

### Why this is non-obvious
The coercion is target-type-driven, not parser-config-driven. A developer
widening `Map<String, String>` to `Map<String, Object>` reasonably expects
this to be a safe, additive change. The silent value mutation (`"yes"` → `true`)
only surfaces when the resolved value is used in string interpolation or
condition evaluation downstream.

### Alternatives considered
- Keeping `Map<String, String>` and converting at the boundary — defeats the
  purpose of typed resolution (integers coerced back to strings)
- Post-processing the map to convert Booleans to strings — fragile, doesn't
  address the root cause
