### The technique

When testing a CDI bean that injects `MeterRegistry` but the test harness uses reflection-based injection (no CDI container), inject Micrometer's `SimpleMeterRegistry` — an in-memory registry that records all metrics synchronously. Assert on actual counter values and timer counts rather than verifying mock interactions.

```java
// Field
private SimpleMeterRegistry meterRegistry;

// In setUp()
meterRegistry = new SimpleMeterRegistry();
inject(agent, "registry", meterRegistry);

// Assertion helpers
private double counterValue(String name, String... tags) {
    io.micrometer.core.instrument.Counter counter = meterRegistry.find(name).tags(tags).counter();
    return counter != null ? counter.count() : 0.0;
}

private long timerCount(String name, String... tags) {
    io.micrometer.core.instrument.Timer timer = meterRegistry.find(name).tags(tags).timer();
    return timer != null ? timer.count() : 0;
}

// Usage
assertThat(counterValue("entries.processed", "outcome", "executed")).isEqualTo(1.0);
assertThat(timerCount("llm.call.duration", "outcome", "success")).isEqualTo(1);
```

### Why this is non-obvious

The natural instinct is to mock `MeterRegistry` and use `verify()` calls, but Micrometer's `MeterRegistry` interface has a complex API surface — `counter()` returns a `Counter`, which has `increment()`, and the registration path involves builders. Mocking this chain is fragile and tests the mock setup more than the metric recording. `SimpleMeterRegistry` sidesteps this entirely — it's a real registry that records real values, so assertions test that the correct metrics were recorded with the correct tags.
