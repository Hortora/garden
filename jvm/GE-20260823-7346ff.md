### Symptom
Upstream library moves a field from a record constructor to an interface method (e.g. `DesiredNode(NodeId, NodeType, NodeSpec, HumanGating)` becomes `DesiredNode(NodeId, NodeSpec, HumanGating)` with `NodeSpec.nodeType()` providing the type). Compilation fails across all modules simultaneously.

### Context
Multi-module Maven project where an API module defines sealed interfaces, and 4+ domain modules implement them. The record's accessor method (`node.type()`) still exists (derives from spec), so callers of the accessor are fine — only constructor call sites break.

### Fix
Fix top-down in dependency order:
1. Sealed interface — change return type (e.g. `String nodeType()` → `NodeType nodeType()`)
2. Each implementation — add/update `nodeType()` method returning the correct `NodeType`
3. API module tests — fix anonymous `NodeSpec` implementations to include `nodeType()`
4. Domain module production code — remove the dropped parameter from all constructor calls
5. Domain module tests — same constructor fix, plus fix `testSpec()` helpers

Use parallel agents for steps 4-5 across independent modules (deployment, compliance, infra, iot).

### Why this is non-obvious
The natural instinct is to grep-and-replace constructor calls first. But the API module must compile before any domain module can compile against it. Top-down ordering prevents wasted cycles from cascading compilation failures.
