### Symptom
Individual tests pass reliably. Full suite (322 tests) has 2-5 random failures per run — different tests each time. All failures are Awaitility `ConditionTimeoutException` waiting for case completion or gate WorkItem creation.

### Context
`casehub-engine-scheduler-quartz` uses Quartz for async worker execution. Each investigation dispatches 4-8 Quartz jobs. With 322 tests and default thread pool, jobs queue behind each other. Late-suite tests starve.

### Root cause
Quartz default thread pool is 10 threads. When multiple investigations from prior tests have undrained async jobs, the pool saturates. New investigations' jobs wait in the queue. The 15-30s Awaitility timeout expires before the job executes.

### Fix
```properties
# application.properties (test)
quarkus.quartz.thread-count=25
```

### Why this is non-obvious
The symptom — random Awaitility timeouts — looks like a race condition or flaky async behaviour. The tests pass individually (thread pool is sufficient for one investigation), making the failure appear ordering-dependent rather than resource-dependent. No error or warning is logged when the thread pool is exhausted — jobs silently queue.
