## SQLite in-memory databases create a new DB per getConnection() — tests see empty state

**Symptom:** Test assertions fail — tables not found, `PRAGMA user_version` returns 0 — despite `initialize()` succeeding without error. No exception thrown anywhere.

**Context:** Any test using `SQLiteDataSource` with `jdbc:sqlite::memory:` where one method creates tables via one `getConnection()` call and assertions verify via a separate `getConnection()` call.

### What was tried (didn't work)
- Assumed the in-memory database was shared across connections from the same `DataSource` — it is not
- Tried `jdbc:sqlite:file:test?mode=memory&cache=shared` — works on some platforms but has its own gotchas with concurrent access

### Root cause
`SQLiteDataSource` with `:memory:` URL creates a **new, empty, independent database** for every `getConnection()` call. This is SQLite's documented behaviour — each `:memory:` connection is a separate database — but JDBC developers expect a `DataSource` to return connections to the same database.

### Fix
Use temp file-based databases in tests:

```java
@TempDir Path tmpDir;

private SQLiteDataSource createDataSource() {
    var ds = new SQLiteDataSource();
    ds.setUrl("jdbc:sqlite:" + tmpDir.resolve("test.db"));
    return ds;
}
```

`@TempDir` handles cleanup. Each test gets an isolated file-backed database where all connections share the same state.

### Why this is non-obvious
The symptom — tables not found, pragmas returning defaults — looks like a schema migration bug, not a connection isolation issue. `initialize()` completes without error (it created the tables in its own ephemeral database), so the natural debugging path is to inspect the SQL, not the connection model. Nothing in the `SQLiteDataSource` API surface signals that `:memory:` connections are independent.
