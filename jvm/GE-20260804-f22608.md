### The convention

LLM worker factories belong in the package of the domain they serve, not in `plugin/advisory/`. A pattern classifier goes in `plugin/scouting/`; a coaching evaluator goes in `plugin/coaching/`. The `plugin/advisory/` package owns recommendation-producing advisors — not all LLM callers.

### Valid alternative

All LLM worker factories in `plugin/advisory/` (or a shared `plugin/llm/` package). This centralises LLM integration but obscures domain ownership — a reader looking at `plugin/scouting/` wouldn't know it has an LLM fallback path without checking `plugin/advisory/`.

### Rationale

Domain ownership determines package placement. The factory's purpose (classify enemy strategy) is a scouting concern. The fact that it calls an LLM is an implementation detail — the same way `DroolsScoutingTask` calls Drools without living in a `plugin/drools/` package. Consumers navigate by domain, not by technology.
