## Jackson ORDER_MAP_ENTRIES_BY_KEYS for deterministic JSON without JCS library

**ID:** GE-20260812-ba7ee4
**Stack:** Jackson 2.x, Java
**Labels:** `#jackson` `#json` `#deterministic` `#hash-chain` `#canonicalization`
**What it achieves:** Deterministic JSON serialization of `Map<String, Object>` for hash-chain computations (e.g. `canonicalBytes()`) without adding a JCS (RFC 8785) library dependency.
**Context:** When building hash chains or content-addressable stores, you need byte-identical JSON output for the same logical data. The obvious approach is to add a JCS library, but this introduces a dependency that may be unwelcome in API modules that must stay pure Java with minimal deps.

### The technique

Configure a dedicated `ObjectMapper` for canonical serialization:

```java
ObjectMapper canonicalMapper = new ObjectMapper()
    .configure(SerializationFeature.ORDER_MAP_ENTRIES_BY_KEYS, true)
    .configure(DeserializationFeature.USE_BIG_DECIMAL_FOR_FLOATS, true)
    .configure(DeserializationFeature.USE_LONG_FOR_INTS, true);

byte[] canonical = canonicalMapper.writeValueAsBytes(map);
```

Key properties:
- `ORDER_MAP_ENTRIES_BY_KEYS` recursively sorts all map keys in the output — not just top-level
- `USE_BIG_DECIMAL_FOR_FLOATS` ensures all decimals deserialize as `BigDecimal`, avoiding `float`/`double` precision drift
- `USE_LONG_FOR_INTS` ensures all integers deserialize as `Long`, avoiding `int`/`long` type instability

Together, these guarantee type-stable round-trips: the same logical data always produces the same bytes.

### Alternatives considered
- JCS (RFC 8785) library — full spec compliance including Unicode normalization and IEEE 754 number formatting, but adds a dependency to API modules
- TreeMap wrapper before serialization — only sorts top-level keys; nested maps remain unsorted
- Custom serializer — more code, same result as the built-in feature

### Why this is non-obvious
Most developers reaching for deterministic JSON will search for "JSON Canonicalization Scheme" or "RFC 8785" and find dedicated libraries. Jackson's `ORDER_MAP_ENTRIES_BY_KEYS` is documented as a serialization feature, but its recursive behavior and its sufficiency for hash-chain use cases is not widely known. The combination with `USE_BIG_DECIMAL_FOR_FLOATS` and `USE_LONG_FOR_INTS` to achieve type-stable round-trips is not documented as a pattern anywhere.

### When to use it
- Hash chains, content-addressable stores, or any context requiring reproducible JSON bytes
- API modules or libraries where adding a JCS dependency is undesirable
- When full RFC 8785 compliance is not required (no Unicode normalization edge cases, no IEEE 754 number formatting requirements)
