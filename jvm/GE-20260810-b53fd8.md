### Symptom
New `NamedStrategy` SPI implementations (e.g., `GoalFormationStrategy`, `GoalRevisionStrategy`) are `@ApplicationScoped` and correctly implement the SPI interface chain (`GoalFormationStrategy extends NamedStrategy`), but `StrategyResolver.resolve(GoalFormationStrategy.class, "llm")` throws "No strategy with id 'llm'". The failure happens inside a virtual thread where the exception is caught and logged at WARN — producing no visible output in test or production logs.

### Context
A strategy resolver uses per-type `@Any Instance<SpecificStrategy>` parameters for known SPI types, plus a catch-all `@Any Instance<NamedStrategy> allStrategies` to discover any strategies not explicitly listed. New SPI types added to `engine-api` are expected to be picked up automatically by the catch-all.

### What was tried (didn't work)
- Assumed `@Any Instance<NamedStrategy>` would discover all beans implementing any sub-interface of `NamedStrategy` — it doesn't in Quarkus ARC's build-time CDI
- Added `@Unremovable` to the implementation — no effect
- Checked `quarkus.index-dependency` for the API module — already indexed

### Root cause
Quarkus ARC performs build-time bean discovery and pruning. `@Any Instance<NamedStrategy>` discovers beans typed as `NamedStrategy` directly, but does not reliably discover beans whose only `NamedStrategy` relationship is through a sub-interface chain (e.g., `LlmGoalFormationStrategy implements GoalFormationStrategy extends NamedStrategy`). The bean is pruned or not indexed under the `NamedStrategy` type.

### Fix
Add an explicit `@Any Instance<NewStrategyType>` constructor parameter to the resolver for each new SPI type, and call `registerStrategies()` for it:

```java
@Inject
public EngineStrategyResolver(
    @Any Instance<AgentRoutingStrategy> agentStrategies,
    // ... existing explicit types ...
    @Any Instance<GoalFormationStrategy> goalFormationStrategies,  // NEW
    @Any Instance<GoalRevisionStrategy> goalRevisionStrategies,    // NEW
    @Any Instance<NamedStrategy> allStrategies) {                  // catch-all
  // ...
  registerStrategies(goalFormationStrategies);
  registerStrategies(goalRevisionStrategies);
  registerRemainingStrategies(allStrategies);  // catch-all last
}
```

### Why this is non-obvious
The catch-all `@Any Instance<NamedStrategy>` pattern works in standard CDI (Weld) but Quarkus ARC's build-time pruning changes the discovery semantics. The existing resolver had 10+ strategies working via explicit typed parameters, making the catch-all appear to work — it only fails for types added later that rely on it.

### Why this fix
The explicit typed parameter is the Quarkus-idiomatic way to ensure build-time discovery. The catch-all remains as a safety net for strategies from extension modules, but production SPI types must be listed explicitly.

### Alternatives considered
- `@Unremovable` on implementations — doesn't help because the issue is type-level discovery, not bean removal
- `quarkus.arc.unremovable-types` config — same limitation
- Moving to runtime CDI discovery — defeats Quarkus's build-time optimization model
