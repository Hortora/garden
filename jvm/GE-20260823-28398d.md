### Symptom

`NullPointerException` at `Objects.requireNonNull(routing)` when calling `SequenceBuilder.build()` — even though the builder was correctly constructed via `Patterns.sequence()`.

### Context

When building an `ExecutionModel` from `SequenceBuilder` programmatically (e.g., in a Quarkus recorder), calling `build()` without first calling `agents()` causes an NPE. This is surprising because all other pattern builders (Supervisor, Debate, Loop, Parallel, Voting, Conditional, HTN) set their `routing` and `termination` fields in their constructors.

### Root cause

`SequenceBuilder`'s constructor does NOT set `routing` or `termination` — these fields remain `null` after construction. They are only set inside the `agents(AgentRef...)` override, which creates `SequentialRouting` and a count-based termination condition using the agent array length. The other builders set defaults in their constructors.

### Fix

Always call `agents()` before `build()` on `SequenceBuilder`:

```java
var builder = Patterns.<Object>sequence();
builder.agents(agents);  // MUST come before build()
builder.task(beanName);
return builder.build();  // Safe — routing and termination now set
```

### Why this is non-obvious

Every other builder in the pattern API sets routing and termination in the constructor. The SequenceBuilder breaks this convention because its routing and termination depend on the agent count — a value not available at construction time. There's no compile-time signal that `agents()` is required before `build()`.
