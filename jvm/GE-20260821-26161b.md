## Quarkus recorder rejects Java records with non-canonical constructors

### Symptom

Build fails with: `Cannot serialise field 'fieldName' on object 'RecordType[...]' as the property is read only`

The error appears at Quarkus augmentation time when a `@Record(RUNTIME_INIT)` build step passes a Java record to a recorder method.

### Context

When building a Quarkus extension, descriptor records carry build-time metadata to the recorder for runtime initialization. Adding a convenience constructor (e.g., a shorter overload that delegates to the canonical constructor with a null default) breaks serialization.

### Root cause

Quarkus bytecode recording serializes recorder method parameters by generating bytecode that reconstructs the object at runtime. For Java records, it uses the canonical constructor (the one matching all record components). When a non-canonical constructor exists, the recording framework gets confused about which constructor to use and fails to match fields to constructor parameters.

### Fix

Only use the canonical constructor on records passed to `@Recorder` methods. If you need a convenience API, use a static factory method on the caller side instead of a secondary constructor on the record.

```java
// BAD: convenience constructor breaks recorder serialization
public record GraphDescriptor(String name, List<NodeDescriptor> nodes, GoalMethodDescriptor goalMethod) {
    public GraphDescriptor(String name, List<NodeDescriptor> nodes) {
        this(name, nodes, null);  // non-canonical constructor
    }
}

// GOOD: canonical constructor only
public record GraphDescriptor(String name, List<NodeDescriptor> nodes, GoalMethodDescriptor goalMethod) {}
// Callers pass null explicitly: new GraphDescriptor("x", nodes, null)
```

### Why this is non-obvious

Java records commonly use telescoping constructors for convenience. The compiler accepts them, tests pass when records are constructed directly, and the error only surfaces when the Quarkus build extension serializes the record for bytecode recording. The error message ("property is read only") doesn't mention constructors at all.
