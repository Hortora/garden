# composite() source replaces REST snapshot with empty WebSocket accumulator on first push

## Symptom

A data table or metric grid bound to `composite(fetchSource("/api/items"), topicSource(["items:*"]))` loads correctly from REST, then goes blank (shows only 1 row) when the first WebSocket push event arrives.

## Context

`composite()` in `@casehubio/pages-data` provides REST-initial + WebSocket-live data binding. The intended behavior is: REST loads the initial snapshot, then WebSocket events update it incrementally.

## Root cause

`composite()` performs a clean handoff: after the REST snapshot completes, it disconnects the REST source entirely and connects the WebSocket `topicSource` directly to the consumer's `DataSink`. The `topicSource` implementation maintains its own internal `rows` Map (accumulator) which starts empty. On the first push event, `topicSource` calls `sink.apply({ type: "snapshot", rows: [singleRow] })` — replacing the entire dataset with just that one row.

The REST data is gone. The WebSocket accumulator never received it.

## What was tried (didn't work)

Using `composite(fetchSource, topicSource)` for incident and work-item datasets in the Ops Centre — incidents loaded from REST then vanished on first push event.

## Fix

Use polled `fetchSource` with `refreshTime` instead of `composite()`:

```typescript
// Wrong — data loss on first push event
const incidents = composite(
  fetchSource("/api/incidents"),
  topicSource(["incident:*"], { keyField: "caseId" }),
);

// Correct — polling avoids the handoff bug
const incidents = fetchSource("/api/incidents");
// In dataset binding:
{ id: dataSetId("incidents"), source: incidents, refreshTime: "10s" }
```

Trade-off: polling introduces up to 10s staleness vs real-time push. Acceptable for dashboards; unacceptable for trading tick data.

## Why this is non-obvious

`composite()` is the documented pattern for REST+WebSocket binding. The data loss only manifests after the first push event — initial page load looks correct. In synthetic testing environments with infrequent events, the bug may never trigger.
