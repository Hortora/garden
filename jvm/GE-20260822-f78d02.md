## Symptom

`InvalidDefinitionException: Java 8 date/time type java.time.Duration not supported by default` when calling `MAPPER.valueToTree()` or `MAPPER.writeValueAsString()` on a record containing a `Duration` field. The stack trace points at `ObjectMapper.valueToTree` with the reference chain showing the record and field name, but the connection to `Duration` specifically requires reading the full exception message.

## Context

A record like `ToolCallRecord(String name, Map args, Map output, String sourceType, Duration duration)` is serialized via `MAPPER.valueToTree(listOfRecords)`. The `Duration` field is nested inside a `List` inside another record — the stack trace shows the nesting chain but the root cause (`Duration` not supported) is only in the exception message, not the stack trace method names.

## What was tried (didn't work)

Using `@JsonSerialize` annotations on the Duration field — works per-field but doesn't fix `valueToTree` calls on the containing structure.

## Root cause

Jackson's default `ObjectMapper` does not include the `jackson-datatype-jsr310` module. Java 8+ date/time types (`Duration`, `Instant`, `LocalDate`, etc.) are treated as unknown types. The module is typically on the classpath (Quarkus BOM includes it) but is not auto-registered on manually-created `ObjectMapper` instances.

## Fix

Register `JavaTimeModule` on any manually-created `ObjectMapper`:

```java
private static final ObjectMapper MAPPER =
    new ObjectMapper().registerModule(new com.fasterxml.jackson.datatype.jsr310.JavaTimeModule());
```

### Why this is non-obvious

The jar is on the classpath (included transitively by Quarkus). The CDI-managed `ObjectMapper` in Quarkus has the module registered automatically. But any `new ObjectMapper()` in application code does not — the auto-registration only applies to the CDI bean. The error appears at a nested serialization boundary, making it look like a structural problem rather than a missing module.
