## Symptom

`NoClassDefFoundError: com/google/crypto/tink/subtle/Ed25519Sign` at runtime when constructing `new Ed25519Signer(okp)` or `new Ed25519Verifier(okp.toPublicJWK())`. Also affects `OctetKeyPairGenerator.generate()` which uses Tink for key generation. Compiles without error.

## Context

Using nimbus-jose-jwt for JWS (RFC 7515) signing with Ed25519 (EdDSA). The library compiles against Nimbus without issue — the `Ed25519Signer` and `Ed25519Verifier` classes are present in the jar. The error surfaces only at runtime, inside a `<clinit>` static initializer block.

## What was tried (didn't work)

1. Adding `nimbus-jose-jwt` as the sole dependency — compiles, `NoClassDefFoundError` at runtime
2. Using `OctetKeyPairGenerator(Curve.Ed25519).generate()` — same Tink dependency for key generation
3. Constructing `OctetKeyPair` from JCA keys then passing to `Ed25519Signer` — still needs Tink for the signing operation itself

### Alternatives considered

- Adding `com.google.crypto.tink:tink` as a dependency — works, but pulls in protobuf and a large transitive tree (~15 MB) for a single crypto operation that Java already supports natively
- Using BouncyCastle as an alternative Ed25519 provider — unnecessary since Java 15+ has native support

## Root cause

Nimbus JOSE+JWT delegates all Ed25519 cryptographic operations (signing, verification, key generation) to Google Tink internally. Tink is declared as an `<optional>` Maven dependency in Nimbus's POM — meaning it is NOT pulled transitively into consumer projects. There is no compile-time signal that Tink is missing. The error only manifests at runtime when the JVM tries to load the `Ed25519Sign` class from the Tink package.

## Fix

Use JCA native `Signature.getInstance("Ed25519")` (available since Java 15) for the actual cryptographic operations. Use Nimbus only for JWS data structures and serialization:

```java
// Signing — JCA native, no Tink
Signature sig = Signature.getInstance("Ed25519");
sig.initSign(privateKey);
sig.update(canonicalPayload);
byte[] signatureBytes = sig.sign();

// JWS header — Nimbus data structures only
JWSHeader header = new JWSHeader.Builder(JWSAlgorithm.EdDSA)
        .type(new JOSEObjectType("agentcard+jws"))
        .keyID(keyId)
        .build();

// Verification — JCA native, no Tink
Signature verifier = Signature.getInstance("Ed25519");
verifier.initVerify(publicKey);
verifier.update(canonicalPayload);
boolean valid = verifier.verify(signatureBytes);

// JWK serialization — Nimbus data structures only (no crypto)
OctetKeyPair jwk = new OctetKeyPair.Builder(Curve.Ed25519, Base64URL.encode(rawPubBytes))
        .keyID(kid).keyUse(KeyUse.SIGNATURE).build();
JWKSet jwkSet = new JWKSet(jwk);
```

This eliminates the Tink dependency entirely while keeping Nimbus for its JWS/JWK type system.

## Why this is non-obvious

Nimbus's Maven POM lists Tink as `<optional>true</optional>`. The compile succeeds because the Nimbus classes themselves are present — they just delegate to Tink internally. No documentation page or README warns that Ed25519 operations require Tink at runtime. The error message (`NoClassDefFoundError` in a `<clinit>`) points to Tink internals, not to Nimbus configuration. A developer would reasonably expect that adding `nimbus-jose-jwt` is sufficient for Ed25519 support.
