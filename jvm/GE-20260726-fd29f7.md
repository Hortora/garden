### Symptom

Maven enforcer `DependencyConvergenceError` when declaring explicit versions of
`google-api-client` and `google-auth-library-oauth2-http` alongside a
`google-api-services-*` artifact:

```
Dependency convergence error for com.google.api-client:google-api-client:jar:2.4.0
  +-myproject
    +-com.google.api-client:google-api-client:jar:2.4.0:compile
  and
  +-myproject
    +-com.google.apis:google-api-services-calendar:jar:v3-rev20250404-2.0.0:compile
      +-com.google.api-client:google-api-client:jar:2.7.2:compile
```

### Context

Adding Google Calendar (or any Google API service) to a Maven project. Natural
instinct is to declare all three dependencies with versions from documentation
or examples (e.g. jgccli). The enforcer rejects the build because the service
artifact (`google-api-services-calendar`) transitively pulls specific compatible
versions of `google-api-client` and `google-auth-library-oauth2-http`.

### What was tried (didn't work)

1. Declaring all three with versions from jgccli's pom.xml — versions were stale
   relative to the calendar service artifact's transitive tree.
2. Aligning `google-auth-library-oauth2-http` to `1.23.0` (the transitive version) —
   fixed that dep but exposed a second convergence error on `google-api-client` itself.

### Root cause

`google-api-services-*` artifacts manage their own transitive dependency tree.
Each service artifact version is built against a specific `google-api-client`
version which in turn pulls a specific `google-auth-library` version. Declaring
explicit versions of these transitive deps creates two dependency paths with
different versions — the enforcer correctly rejects this.

### Fix

Only declare the service-specific artifact. Let it pull compatible versions
of `google-api-client` and `google-auth-library-oauth2-http` transitively:

```xml
<dependency>
  <groupId>com.google.apis</groupId>
  <artifactId>google-api-services-calendar</artifactId>
  <version>v3-rev20250404-2.0.0</version>
</dependency>
<!-- Do NOT declare google-api-client or google-auth-library explicitly -->
```

Classes from `google-api-client` (`GoogleNetHttpTransport`, `GsonFactory`) and
`google-auth-library` (`UserCredentials`, `HttpCredentialsAdapter`) are available
on the classpath via the transitive pull — no explicit dependency needed.

### Why this is non-obvious

Documentation and example projects (including jgccli) list all three dependencies
with explicit versions. The natural approach is to copy those declarations. The
versions in examples lag behind the service artifact's transitive tree, so
copying them always triggers convergence errors with recent service artifact
versions.
