### What exists

qhorus-api has a complete Space model that is not documented in any consumer guide:

- **`Space`** — record: `UUID id`, `String name`, `String description`, `UUID parentSpaceId` (supports nested hierarchy), `String tenancyId`, `Instant createdAt`
- **`SpaceStore`** — interface: `put`, `find`, `findByName`, `listByParent`, `listRoots`, `hasChildren`, `delete`, `findByIds`
- **`SpaceService`** — create with nesting depth limits, rename, move with cycle detection, channel assignment
- **`Channel.spaceId`** — links channels to spaces
- **`ChannelQuery.bySpaceId()`** / **`topLevel()`** — query channels by space or root-level
- **`ChannelDetail.spaceId`** / **`spaceName`** — included in dashboard aggregation responses
- **`SpaceCreateRequest`** — supports `name`, `description`, `parentSpaceId`

### How to discover it

The Space model was built as part of qhorus#328 (epic: conversation model enrichments). It's findable via:
- `io.casehub.qhorus.api.channel.Space` — the record
- `io.casehub.qhorus.api.store.SpaceStore` — the SPI
- `io.casehub.qhorus.runtime.channel.SpaceService` — the service

### Why this is non-obvious

No consumer guide (chat-app, claudony, or parent) documents the Space model. Issue #7 (space-based channel hierarchy) references it as a dependency but doesn't link to the actual classes. Without grep-for-Space in qhorus-api, a developer would assume spaces need to be built from scratch — which is what happened during initial design brainstorming for casehubio/chat-app#33 before a first-principles review prompted the search.
