### Symptom

After updating to a new casehub-engine SNAPSHOT, Quarkus `@QuarkusTest` and production builds fail with:

```
AmbiguousResolutionException: Ambiguous dependencies for type
io.casehub.api.spi.routing.AgentRoutingStrategy and qualifiers [@Default]
```

Two competing beans:
- `ComposableAgentRoutingStrategy` — the existing composable strategy (used by AML for trust-weighted routing)
- `LeastLoadedAgentStrategy` — new bean added in the SNAPSHOT

### Context

The engine SNAPSHOT added `LeastLoadedAgentStrategy` as a `@Default @ApplicationScoped` bean implementing `AgentRoutingStrategy`. This competes with `ComposableAgentRoutingStrategy` which is also `@Default`. No release note or migration guide accompanied the change.

### Fix

Exclude `LeastLoadedAgentStrategy` from both `application.properties` files (main and test):

```properties
quarkus.arc.exclude-types=...,\
  io.casehub.engine.internal.routing.LeastLoadedAgentStrategy
```

AML uses `ComposableAgentRoutingStrategy` which composes with trust-weighted routing via `AmlTrustRoutingPolicyProvider`. The least-loaded strategy is not needed.

### Why this is non-obvious

No changelog, deprecation notice, or migration guide for this SNAPSHOT change. The error message names the interface (`AgentRoutingStrategy`) but doesn't immediately indicate which new bean caused the ambiguity — you need to read the "available beans" list to spot the new entry.
