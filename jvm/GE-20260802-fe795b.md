## BM25 keyword dilution — separate keywords from NL query via RetrievalQuery(text, expandedText)

### What it achieves

Prevents specific keyword matches from being drowned by generic NL query terms in BM25 scoring, without affecting dense/sparse retrieval quality.

### Context

A hybrid search pipeline uses RRF fusion across dense (BGE-M3), sparse (learned lexical), and BM25 (Qdrant Document vectors). When the caller provides specific technical keywords alongside a natural language query, concatenating them into a single string dilutes the keywords — BM25 treats all tokens equally, so 1 keyword among 15+ NL terms gets a small fraction of the score.

Real example: searching for `"Quarkus CDI augmentation failure engine SPI migration reactive to blocking"` with keyword `CasehubEnabledProfile`. The entry containing `CasehubEnabledProfile` was absent from results because the 10+ NL tokens dominated BM25 scoring.

### The technique

Use `RetrievalQuery(text, expandedText)` to separate the BM25 query from the dense/sparse query:

```java
RetrievalQuery retrievalQuery;
if (keywords != null && !keywords.isBlank()) {
    // text = keywords → BM25 focuses on exact keyword matching
    // expandedText = NL query + keywords → dense/sparse get full semantic context
    retrievalQuery = new RetrievalQuery(keywords, query + " " + keywords);
} else {
    retrievalQuery = RetrievalQuery.of(query);
}
```

`HybridCaseRetriever` uses `query.text()` for BM25 and `query.searchText()` (which returns `expandedText` when set) for dense/sparse embeddings. This separation is built into the API but not used by default.

### Why this is non-obvious

The natural approach — concatenating keywords into the NL query — works for dense/sparse (more context helps) but hurts BM25 (dilution). The `RetrievalQuery` API has `text()` vs `searchText()` but their distinct roles (BM25 vs embedding) are not documented. The fix requires understanding that BM25 scores are token-frequency-based while dense scores are vector-similarity-based — the same input optimization doesn't apply to both.

### Alternatives considered

- Per-token weighting in BM25 — not available in Qdrant
- BM25F (multi-field BM25) — Qdrant GitHub issue #7541 closed without implementation
- Dynamic RRF weight boosting when keywords present — correct but requires neocortex-rag change (filed as neocortex#190)
