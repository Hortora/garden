### Symptom

FLAG_HUMAN messages posted to the Qhorus channel during an autonomous debate session
are silently ignored by the running orchestrator. The debate continues despite human
intervention.

### Context

`ConversationOrchestrator.converse(triggeringMessage)` processes an internal
`ArrayDeque<MessageView>` queue. Messages enter the queue only when the orchestrator
itself generates agent responses via `responseBuilder.build()` — the queue is seeded
with the triggering message, then each agent response is added. Messages posted to the
Qhorus channel via `messageService.dispatch()` trigger `ChannelBackend.post()` through
gateway fan-out, but they never enter the orchestrator's internal queue.

### Root cause

The orchestrator is a closed loop: seed → process → invoke agent → build response →
dispatch → enqueue response → repeat. External messages (human FLAG_HUMAN, manual
raise_point) go through `messageService.dispatch()` → `ChannelGateway.fanOut()` →
`ChannelBackend.post()` — a completely separate path that the orchestrator doesn't
observe.

### Fix

External interruption requires calling `orchestrator.terminate()`, which sets a
volatile boolean checked on each loop iteration. In DraftHouse, this is wired in
`DebateChannelBackend.post()`:

```java
// FLAG_HUMAN from external source → terminate running orchestrator
if ("FLAG_HUMAN".equals(meta.get("entryType"))
        && session.orchestrator() != null) {
    session.orchestrator().terminate();
    return;
}
```

Similarly, `endDebate()` calls `terminate()` before removing the session.

### Why this is non-obvious

The orchestrator accepts a `Consumer<MessageView> responseDispatcher` that calls
`messageService.dispatch()` — this makes it look like the orchestrator participates
in the channel message flow bidirectionally. In reality, the dispatcher is output-only:
responses go out to the channel, but nothing comes back in. The orchestrator's
`converse()` loop is self-contained.
