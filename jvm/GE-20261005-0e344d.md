### Symptom
`QuarkusUnitTest` fails at startup with `UnsatisfiedResolutionException` for beans in dependency jars — even when those beans are NOT in the `withApplicationRoot` archive:
```
UnsatisfiedResolutionException: Unsatisfied dependency for type CaseMemoryStore
  - injection target: parameter 'memoryStore' of ConsolidationScheduler constructor
```
The `ConsolidationScheduler` class is in a transitive dependency, not in the test's application root.

### Context
A library module (`knowledge-pipeline`) depends on `mindmap-intelligence` which transitively pulls in `mindmap` (CDI wiring). Both modules have Jandex indexes generated by `jandex-maven-plugin`. The `QuarkusUnitTest` uses `withApplicationRoot` to scope the test to knowledge-pipeline classes only.

### What was tried (didn't work)
- `withApplicationRoot(jar -> jar.addPackage(...))` — only controls which classes are in the "application" archive; dependency jars with Jandex are still scanned
- Adding the test class to the application root (`addClass(TestClass.class)`) — necessary for test injection, but doesn't prevent dependency scanning

### Root cause
`withApplicationRoot` controls the synthetic application JAR contents, but Quarkus Arc also discovers beans from dependency JARs that contain a Jandex index (`META-INF/jandex.idx`). Any dependency built with `jandex-maven-plugin` becomes a bean archive. Beans in those JARs are discovered and their injection points are validated — even if they're never used by the test.

### Fix
Use `quarkus.arc.exclude-types` to suppress discovery of beans from transitive dependencies:
```java
@RegisterExtension
static final QuarkusUnitTest unitTest = new QuarkusUnitTest()
    .withApplicationRoot(jar -> jar
        .addClass(MyTest.class)
        .addPackage(MyService.class.getPackage()))
    .overrideConfigKey("quarkus.arc.exclude-types",
        "io.casehub.neocortex.mindmap.intelligence.**,"
        + "io.casehub.neocortex.mindmap.cdi.**,"
        + "io.casehub.neocortex.mindmap.core.**");
```
Pattern syntax: `**` matches any sub-package. Comma-separated for multiple patterns.

### Why this is non-obvious
`withApplicationRoot` reads as "only scan these classes" — the API name suggests scoping. In practice, it only controls the application archive; dependency discovery runs independently via Jandex. The error points to a class the test doesn't reference and didn't include, making the cause hard to trace.
