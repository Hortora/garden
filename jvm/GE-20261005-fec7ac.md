### Symptom
Two SQLite databases (pipeline and research) silently use the same database file at runtime, causing data corruption. No error at startup — the application starts normally.

### Context
A `@ConfigMapping` interface reuses the same nested interface type for two different config groups:
```java
@ConfigMapping(prefix = "casehub.knowledge")
public interface Config {
    SqliteConfig sqlite();              // casehub.knowledge.sqlite.path
    ResearchConfig research();
    interface SqliteConfig {
        @WithDefault("knowledge-pipeline.db") String path();
    }
    interface ResearchConfig {
        SqliteConfig sqlite();          // casehub.knowledge.research.sqlite.path
    }
}
```
Both `sqlite().path()` and `research().sqlite().path()` default to `"knowledge-pipeline.db"` because `@WithDefault` is on the interface method, not the usage site.

### What was tried (didn't work)
- Reusing `SqliteConfig` for both groups — appeared to work but both databases use the same file
- Adding `@WithDefault` on the `ResearchConfig.sqlite()` method — not supported (defaults are on leaf methods)

### Root cause
SmallRye Config resolves `@WithDefault` from the declaring interface's method, not from the calling context. When `SqliteConfig.path()` has `@WithDefault("knowledge-pipeline.db")`, ALL config paths that resolve through `SqliteConfig` get that default — regardless of their property prefix.

### Fix
Create separate interface types with distinct defaults:
```java
interface SqliteConfig {
    @WithDefault("knowledge-pipeline.db") String path();
}
interface ResearchSqliteConfig {
    @WithDefault("knowledge-research.db") String path();
}
interface ResearchConfig {
    ResearchSqliteConfig sqlite();  // now defaults correctly
}
```

### Why this is non-obvious
The interface reuse pattern looks like standard DRY refactoring — both config groups need a `path()` method with the same type signature. SmallRye doesn't warn about shared defaults across usage sites. The collision is silent: no startup error, no log warning, just two databases writing to the same file.

### Why this fix
Separate interfaces are verbose but unambiguous. Each leaf method carries its own default. The alternative — a single interface with no default and `@WithDefault` at the usage site — is not supported by SmallRye's `@ConfigMapping` model.

### Alternatives considered
- Single `SqliteConfig` interface with no `@WithDefault`, requiring explicit config in `application.properties` — works but removes the convenience of sensible defaults
- `@WithName` annotation to alias the property path — doesn't affect defaults, only property name mapping
