### Symptom

Dispatching a COMMAND message returns a successful `DispatchResult` (message stored, messageId assigned), but no `Commitment` is created. `CommitmentReader.findByChannel(channelId)` returns an empty list.

### Context

Consumer code dispatches a COMMAND message via `ConsumerMessaging.dispatch()` without setting `correlationId` on the `MessageDispatch` builder:

```java
var dispatch = MessageDispatch.builder()
        .channelId(channelUuid)
        .sender(sender)
        .type(MessageType.COMMAND)
        .content("Investigate case-456")
        .target("agent-b")
        .build();  // correlationId is null
var result = messaging.dispatch(dispatch);
// result.messageId() is valid — message stored
// But no commitment created
```

### Root cause

`MessageService.dispatch()` line ~325 checks `dispatch.correlationId() != null` before creating a commitment. If `correlationId` is null, the commitment creation branch is skipped entirely. The `MessageDispatch.builder().build()` validation does NOT require `correlationId` for COMMAND messages — only DONE/DECLINE/FAILURE/HANDOFF/RESPONSE require it.

### Fix

Set `correlationId` explicitly when dispatching COMMAND messages:

```java
String correlationId = UUID.randomUUID().toString();
var dispatch = MessageDispatch.builder()
        .channelId(channelUuid)
        .sender(sender)
        .type(MessageType.COMMAND)
        .content("Investigate case-456")
        .correlationId(correlationId)
        .target("agent-b")
        .build();
```

The correlationId links the COMMAND to its commitment and to all subsequent reply messages (STATUS, RESPONSE, DONE, DECLINE) that reference the same correlationId.

### Why this is non-obvious

COMMAND is the speech-act type that creates obligations. The natural expectation is that dispatching a COMMAND automatically creates a commitment. The dispatch succeeds with a valid `DispatchResult` — there is no error, warning, or advisory indicating that the commitment was skipped. The builder validation enforces `correlationId` for terminal types (DONE, DECLINE) but not for COMMAND, which is the originating type.
