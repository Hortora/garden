### Symptom
Test assertion `assertThat(desc.get().defaultValue()).isEqualTo("P7D")` fails with actual value `"PT168H"`.

### Context
Any code that serializes `java.time.Duration` via `toString()` after constructing with `Duration.ofDays(N)`. Common in preference systems, config serialization, and REST API responses.

### Root cause
`Duration` is internally stored in seconds. `ofDays(7)` converts to `604800` seconds. `toString()` normalizes to the largest unit it supports — **hours** — producing `PT168H`, not `P7D`. Duration does not support calendar days; `ofDays()` is a convenience that multiplies by 86400.

### Fix
Write assertions and comparisons against the hours-normalized form:

```java
// Wrong — Duration doesn't emit day units
assertThat(serialized).isEqualTo("P7D");

// Correct — Duration normalizes days to hours
assertThat(serialized).isEqualTo("PT168H");
```

For human-readable display, use `Period` (calendar days) or format manually.

### Why this is non-obvious
`Duration.ofDays()` accepts days as input, suggesting days are a first-class unit. The normalization to hours in `toString()` is documented in the javadoc but contradicts the intuition set by the factory method name.
