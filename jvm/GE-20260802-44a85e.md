## Symptom

`mvn install` fails with `401 Unauthorized` for casehub SNAPSHOT dependencies (`casehub-qhorus-api`, `casehub-eidos-api`, etc.) even after purging `_remote.repositories`, `.lastUpdated`, `resolver-status.properties`, and `maven-metadata-github.xml` files from `~/.m2/repository/io/casehub/`.

## Context

GitHub Packages requires a PAT (`ghp_`) with `read:packages` scope. The `GITHUB_TOKEN` environment variable was set to a `gho_` OAuth token (from `gh auth`), which doesn't have `read:packages`. Maven tried to resolve SNAPSHOT metadata from GitHub Packages, got 401, and cached the failure.

## What was tried (didn't work)

1. Deleting `_remote.repositories` files — Maven re-creates them on the next build from the install metadata
2. Deleting `.lastUpdated` files — Maven still caches the 401 in a new `.lastUpdated` on the next resolution attempt
3. Using `-nsu` (no snapshot updates) — Maven still checks the initial resolution when metadata has expired
4. Using `-o` (offline mode) — fails because non-casehub dependencies (e.g. Quarkus 3.32.2) weren't cached yet

## Root cause

Maven's SNAPSHOT resolution is a two-phase process: (1) check remote metadata, (2) resolve the artifact. The 401 failure is cached at phase 1 — and the cache key includes the repository ID (`github`). Purging `_remote.repositories` removes the provenance marker but Maven's internal `maven-metadata-github.xml` cache (or its absence) still triggers a fresh remote check on the next build. The fresh check hits the same 401 and immediately re-caches the failure.

## Fix

Build the upstream repos from local source to install fresh SNAPSHOT artifacts. This bypasses the remote resolution entirely — `mvn install` writes to `~/.m2/repository` with local provenance, and subsequent builds resolve from the local install:

```bash
mvn -f /path/to/platform/pom.xml install -DskipTests -q -nsu
mvn -f /path/to/worker/pom.xml install -DskipTests -q -nsu
mvn -f /path/to/qhorus/pom.xml install -DskipTests -q -nsu
mvn -f /path/to/eidos/pom.xml install -DskipTests -q -nsu
# Then: purge .lastUpdated files and rebuild the consuming project
find ~/.m2/repository/io/casehub -name "*.lastUpdated" -delete
mvn -f /path/to/engine/pom.xml install -DskipTests -nsu
```

The `-nsu` flag prevents Maven from checking remote SNAPSHOT metadata during the consuming build.

## Why this is non-obvious

The natural instinct when seeing "cached failure" is to purge the cache files. This works for most Maven caching issues — but SNAPSHOT resolution failures are cached at a different layer that survives file deletion. The symptoms look like a stale cache when the actual problem is the remote check re-triggering on every build. Building from source is the only reliable bypass when the remote is inaccessible.
