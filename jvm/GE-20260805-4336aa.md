## Symptom

`CbrCaseMemoryStore.retrieveSimilar()` returns an empty list even though a case was just stored via `storeIdempotent()` in the same transaction.

## Context

When writing an integration test for a CBR listener that stores cases with a specific scope path (e.g. `Path.of(trialId, siteId, patientId)`), querying with `Path.root()` and `withMinSimilarity(0.0)` returns nothing — despite the case being successfully stored moments earlier.

## What was tried (didn't work)

- `CbrQuery.of(tenantId, domain, Path.root(), caseType, Map.of(), 100).withMinSimilarity(0.0)` — returns empty
- Using `store.retrieveSimilar()` directly vs `cbrService.retrieveSimilar()` — both return empty with `Path.root()`
- Adding `@Transactional` to the test method — no effect (in-memory store doesn't participate in JTA)

## Root cause

`InMemoryCbrCaseMemoryStore` performs scope-path filtering during retrieval. Cases stored with a specific scope path (e.g. `trial-1/site-1/patient-1`) are only returned when the query path matches or is an ancestor/descendant of the stored path. `Path.root()` does not match specific paths in this implementation.

## Fix

Use the **exact scope path** that was used during storage in the retrieval query:

```java
// Store with specific scope
cbrService.storeIdempotent(cbrCase, "clinical-ae", entityId, domain, tenantId, caseId,
    Path.of(trialId.toString(), siteId.toString(), patientId));

// Query with SAME scope — not Path.root()
CbrQuery query = CbrQuery.of(tenantId, domain,
    Path.of(trialId.toString(), siteId.toString(), patientId),
    "clinical-ae", Map.of(), 100);
List<ScoredCbrCase<PlanCbrCase>> results = cbrService.retrieveSimilar(query, PlanCbrCase.class);
```

The existing `ClinicalCaseOutcomeObserverIntegrationTest` demonstrates the correct pattern — it uses the specific scope path in its query.

## Why this is non-obvious

`Path.root()` reads as "search everywhere" and `withMinSimilarity(0.0)` reads as "match everything." The combination feels like a universal query. The in-memory store's scope filtering is not documented — discovered by comparing a working integration test against the failing one.
