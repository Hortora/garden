### Symptom
`UnrecognizedPropertyException` at runtime when deserializing YAML to a Java record.
Error lists the known properties, revealing the field name mismatch.

### Context
Multi-module project where sibling SPI modules define similar domain records
independently. Commerce module has `ProductReview(... long timestampMs)`.
Location module has `Review(... long timeMillis)`. Both represent epoch
milliseconds but use different field names.

When writing YAML seed files, the field name from one record was used for
the other — compiles fine (YAML is untyped), fails at runtime.

### What was tried (didn't work)
Assumed all timestamp fields across sibling modules used the same name.
Wrote YAML with `timestampMs` for location Review — Jackson rejected it.

### Root cause
Java records expose component names as Jackson property names. Two records
representing the same concept in different modules can have different
component names. Jackson performs strict matching by default — no fuzzy
fallback.

### Fix
Always read the target record's field names before writing YAML:
```bash
# Check record components via IDE or grep
grep "record Review" location-spi/src/main/java/.../Review.java
```
The error message itself is clear — `not marked as ignorable (4 known
properties: ...)` — but the wasted build cycle is the real cost.

### Why this is non-obvious
The field names look semantically identical (`timestampMs` vs `timeMillis`)
and both are `long`. A developer copying YAML patterns from a sibling module
would reasonably assume the same field name. The compiler can't catch it
because YAML is untyped — the failure is deferred to runtime deserialization.
