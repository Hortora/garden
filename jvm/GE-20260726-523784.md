### Symptom / context
When building MCP tools with `quarkus-mcp-server-core`, command parameters
(e.g. `{"temperature": 22.0, "unit": "CELSIUS"}`) need to reach the tool
method. The natural approach is declaring `@ToolArg String parameters` and
parsing the JSON string manually with `ObjectMapper.readValue()`.

This forces double-encoding: the LLM must produce a JSON string containing
escaped JSON inside the already-JSON MCP tool call payload — e.g.
`"parameters": "{\"temperature\": 22.0}"` instead of
`"parameters": {"temperature": 22.0}`.

### What most developers would do
Declare the parameter as `String`, add `ObjectMapper.readValue()` parsing
with a try/catch for `JsonProcessingException`, and return a "Failed:
Invalid JSON" error message on parse failure.

### The technique
Declare the parameter as `@ToolArg Map<String, Object>`:

```java
@Tool(name = "my_tool")
public String myTool(
        @ToolArg(required = false) final Map<String, Object> parameters) {
    // parameters is already deserialized — no manual parsing needed
    Map<String, Object> params = parameters != null ? parameters : Map.of();
}
```

The MCP JSON schema becomes `"type": "object"` and the LLM produces a
native JSON object. No double-encoding, no manual parsing, no error path.

### Root cause / mechanism
`FeatureManagerBase.handleParam()` in `quarkus-mcp-server-core` handles
non-primitive argument types via `ObjectMapper.convertValue()`. When the
MCP protocol delivers a JSON object for a `Map`-typed parameter, Jackson
converts it directly to `Map<String, Object>`.

### Why this is non-obvious
The `@ToolArg` javadoc lists supported primitive wrappers (`String`,
`Integer`, `Boolean`, etc.) but does not mention `Map` or complex types.
The Map support is an implementation detail of `FeatureManagerBase`, not
a documented feature.

### Alternatives considered
- `String` + manual `ObjectMapper.readValue()`: works but forces
  double-encoding and adds boilerplate error handling
- Custom record type: possible but overkill for dynamic key-value
  parameters where the schema varies per command
