### Symptom
After rebuilding an upstream dependency that ships JPA entities, tests that directly instantiate entities with `new TrustScoreSnapshot()` fail with:

```
TrustScoreSnapshot() has protected access in io.casehub.ledger.runtime.model.TrustScoreSnapshot
```

The entity class hasn't changed in the consumer — the visibility change was in the upstream module.

### Context
JPA entities should have protected no-arg constructors (JPA spec recommendation). When an upstream module enforces this, all downstream consumers that directly instantiate entities in tests break — even though production code (which uses JPA to create instances) is unaffected.

### Fix
Use an anonymous subclass — Java allows subclass constructors to call protected parent constructors:

```java
private static TrustScoreSnapshot snapshot(double score, double prev, Instant at) {
    var s = new TrustScoreSnapshot() {};  // anonymous subclass
    s.score = score;
    s.previousScore = prev;
    s.occurredAt = at;
    return s;
}
```

The `{}` creates an anonymous subclass whose implicit constructor calls `super()` — legal because subclasses can access protected members.

### Why this is non-obvious
The error reads as "this constructor doesn't exist" — the instinct is to look for a factory method or builder. The anonymous subclass trick is a Java language feature that most developers don't associate with constructor visibility.
