## Mockito nested when() via helper method inside thenReturn() triggers UnfinishedStubbingException

### Symptom

`UnfinishedStubbingException` thrown from inside a mock helper method that was working fine in other tests. Stack trace points at the helper, not at the actual nesting site.

### Context

A test helper method (e.g. `mockMessage()`) creates and stubs a mock object. When this helper is called as an argument inside another `when().thenReturn()` call, the inner stubbing starts before the outer stubbing completes.

### Root cause

Java evaluates method arguments before calling the method. In this code:

```java
when(messageStore.scan(any(MessageQuery.class)))
    .thenReturn(List.of(mockMessage()));  // mockMessage() evaluates FIRST
```

Execution order:
1. `when(messageStore.scan(any()))` — starts outer stubbing (not yet completed)
2. Evaluating the arg to `thenReturn()`: `List.of(mockMessage())`
3. Inside `mockMessage()`: `when(m.id()).thenReturn(1L)` — starts inner stubbing
4. Mockito detects the outer stubbing was never completed → `UnfinishedStubbingException`

The stack trace points to `mockMessage()` line N, which is misleading — the bug is at the call site, not in the helper.

### Fix

Pre-compute the mock before the outer `when()`:

```java
// Wrong — nested stubbing
when(messageStore.scan(any(MessageQuery.class)))
    .thenReturn(List.of(mockMessage()));

// Correct — helper runs outside when()
List<Message> messages = List.of(mockMessage());
when(messageStore.scan(any(MessageQuery.class))).thenReturn(messages);
```

### Why this is non-obvious

The helper works perfectly when called outside of a `when()` context — other tests in the same file use it without issue. The nesting only fails when the helper is called as an argument to `thenReturn()`, `thenAnswer()`, or similar stubbing methods. Java's argument evaluation order is well-known, but its interaction with Mockito's thread-local stubbing state is not intuitive. The stack trace compounds the confusion by pointing at the helper, not the nesting.
