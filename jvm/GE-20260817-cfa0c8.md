### Symptom
A `@BuildStep` method is listed in `META-INF/quarkus-build-steps.list` and compiles without error, but is never invoked during augmentation. No error, no warning — the step is silently skipped.

### Context
Writing a Quarkus extension with a validation-only build step that consumes `CombinedIndexBuildItem` and throws on constraint violations but produces nothing:

```java
@BuildStep
void validate(CombinedIndexBuildItem index) {
    // validation logic — throws RuntimeException on errors
}
```

### What was tried (didn't work)
- Adding `BuildProducer<ReflectiveClassBuildItem>` parameter without calling `.produce()` — still skipped
- Logging and System.err.println — no output, confirming the method never executes
- Adding `quarkus-extension.yaml` and `quarkus-extension.properties` metadata files — no effect

### Root cause
Quarkus schedules build steps based on a dependency graph of build items. A step that produces no build items has no dependents and is never scheduled. This is by design (dead-code elimination for the build graph), but the lack of any warning makes it a debugging trap.

### Fix
Annotate with `@Produce(ServiceStartBuildItem.class)` to force execution:

```java
@BuildStep
@Produce(ServiceStartBuildItem.class)
void validate(CombinedIndexBuildItem index) {
    // now actually runs
}
```

`ServiceStartBuildItem` is always consumed by the Quarkus startup chain, so producing it guarantees the step is scheduled.

### Why this is non-obvious
The method compiles, the extension processor generates `quarkus-build-steps.list` correctly, Quarkus augmentation runs, and other build steps in the same class execute. Nothing suggests the method was skipped — you only discover it by adding a deliberate exception and observing that it doesn't fire.
