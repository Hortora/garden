### Symptom
Adding `@Observes` CDI observer methods directly on a `@QuarkusTest` test class causes engine settlement to timeout at 5 seconds per game tick. The same tick completes in under 200ms when the observer is removed. Test output shows:

```
Engine signal+settle failed at frame 1: Settlement timed out after PT5S
```

A test with 10 game ticks takes 50+ seconds instead of less than 1 second.

### Context
The CaseHub engine's `signalAndAwaitSync()` fires CDI events from virtual threads during its settle cycle. The test class:

```java
@QuarkusTest
class WorkbenchPipelineIT {
    @Inject AgentOrchestrator orchestrator;

    // This observer causes the timeout:
    void onPattern(@Observes PatternAssessmentPublished event) {
        firedEvents.add("pattern:" + event.assessments().size());
    }
}
```

The observer method is syntactically valid — `@QuarkusTest` instances are CDI beans managed by Arc. No compilation or startup errors occur.

### What was tried (didn't work)
1. Using `static` event list (`CopyOnWriteArrayList`) — still timed out
2. Removing `SimulatedGame.reset()` — no effect
3. Adding `ScenarioRunner.run("spawn-enemy-attack")` for richer game state — still timed out

### Root cause
CDI events fired from virtual threads inside the engine's settle cycle interact badly with observer methods on `@Dependent`-scoped test beans (the default scope for `@QuarkusTest` instances). The exact mechanism is unclear — likely scope resolution or thread-context propagation overhead in Arc — but the effect is consistent and reproducible: every tick blocks for the full timeout duration.

The same test without the `@Observes` method completes ticks in ~193ms.

### Fix
Move `@Observes` methods to a dedicated `@ApplicationScoped` CDI bean and inject that bean into the test:

```java
@ApplicationScoped
public class WorkbenchEventCollector {
    private final List<String> events = new CopyOnWriteArrayList<>();

    void onPattern(@Observes PatternAssessmentPublished e) {
        events.add("pattern:" + e.assessments().size());
    }

    public List<String> events() { return List.copyOf(events); }
    public void clear() { events.clear(); }
}
```

```java
@QuarkusTest
class WorkbenchPipelineIT {
    @Inject WorkbenchEventCollector collector;
    // ... use collector.events() in assertions
}
```

### Why this is non-obvious
`@QuarkusTest` instances ARE CDI beans — Arc manages their lifecycle and processes `@Inject`. So `@Observes` on them is natural and expected to work. The timeout manifests as a performance issue, not a CDI error. Nothing in the stack trace, error message, or Quarkus documentation suggests the observer is the cause. The connection between "I added an @Observes method" and "the engine times out at exactly 5s per tick" requires eliminating all other variables.
