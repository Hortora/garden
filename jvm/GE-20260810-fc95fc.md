### Symptom
`NullPointerException: Cannot invoke "ObjectMapper.readTree(byte[])" because "objectMapper" is null` when calling `new MyYamlCaseHub().getDefinition()` in a plain JUnit test.

### Context
`YamlCaseHub` uses `@Inject @YamlMapper ObjectMapper`, `@Inject ExpressionEngineRegistry`, and `@Inject WorkerFunctionProviderRegistry`. Outside a CDI container, all three are null.

### What was tried
Instantiating `YamlCaseHub` directly in a `@Test` method — NPE on first call to `getDefinition()`.

### Root cause
The `@Inject` fields are only populated in a CDI context (`@QuarkusTest`). Plain JUnit tests have no CDI container.

### Fix
Call `CaseDefinitionYamlMapper.load()` directly with manual stubs:
```java
ObjectMapper yamlMapper = new ObjectMapper(new YAMLFactory());
ExpressionEngineRegistry registry = new JqOnlyRegistry(); // stub
WorkerFunctionProviderRegistry providerRegistry = node -> WorkerFunction.NONE;

try (InputStream is = Thread.currentThread().getContextClassLoader()
    .getResourceAsStream("casehub/my-case.yaml")) {
    CaseDefinition def = CaseDefinitionYamlMapper.load(is, yamlMapper, registry, providerRegistry);
}
```
The `ExpressionEngineRegistry` stub needs all abstract methods implemented — check `javap` for the full interface (methods include `transform`, `extractString`, `assertLanguageSupported`).

### Why this is non-obvious
The CLAUDE.md says "Fallback to JQ-only parsing outside CDI" — suggesting it should work. The fallback exists in the code path but the ObjectMapper injection happens before the fallback can engage.
