# JSpecify @Nullable fails on fully-qualified type references

## Symptom
Compilation error when using `@Nullable` with a fully-qualified type name:
```
type annotation @org.jspecify.annotations.Nullable is not expected here
  (to annotate a qualified type, write io.casehub.pkg.@Nullable Type)
```

## Context
JSpecify's `@Nullable` is a TYPE_USE annotation (JSR 308). When applied to a
fully-qualified type reference, javac requires the annotation to appear
immediately before the simple name, not before the package prefix.

## Root cause
Java language spec (JLS §9.7.4): type-use annotations on a qualified type
must appear directly before the simple type name component, not before the
full package path. `@Nullable io.pkg.Type` is syntactically invalid;
`io.pkg.@Nullable Type` is correct but unusual.

## Fix
Two options:

### Solution 1 — Import and use short name (Recommended)
```java
import io.casehub.neocortex.mindmap.MindMapStore;
private final @Nullable MindMapStore mindMapStore;
```
**Pros:** Reads naturally, standard Java style
**Cons:** Adds import line

### Solution 2 — Split annotation placement
```java
private final io.casehub.neocortex.mindmap.@Nullable MindMapStore mindMapStore;
```
**Pros:** No import needed
**Cons:** Unusual syntax, confuses readers

## Why this is non-obvious
The error message suggests the split placement syntax, but most developers
have never seen `pkg.@Annotation Type` and assume it's a javac bug. The
natural instinct is `@Nullable io.pkg.Type` — which works with
javax.annotation.Nullable (a declaration annotation) but fails with
JSpecify (a type-use annotation).
