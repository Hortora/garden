### Symptom
`CompletableFuture.supplyAsync(() -> ...)` throws `ThreadContextProvider: JtaContextProvider not a subtype` in Quarkus test contexts. The supplier runs but fails when MicroProfile context propagation tries to load SPI providers.

### Context
Attempting to run blocking work off the main thread for timeout enforcement in a `@QuarkusTest` integration test. The `CompletableFuture.supplyAsync()` no-arg overload delegates to `ForkJoinPool.commonPool()`.

### What was tried (didn't work)
1. `CompletableFuture.supplyAsync(() -> driver.execute(...).await().indefinitely())` — throws `JtaContextProvider not a subtype` because ForkJoinPool threads have a different classloader than the Quarkus application classloader.

### Root cause
The `ForkJoinPool.commonPool()` is created at JVM startup with the system classloader. Quarkus uses a custom classloader for application classes and SPI discovery. When MicroProfile context propagation runs on a ForkJoinPool thread, `ServiceLoader` finds `JtaContextProvider` via the system classloader but can't verify it's a subtype of `ThreadContextProvider` loaded by the Quarkus classloader — different classloaders, different Class objects.

### Fix
Use `Executors.newVirtualThreadPerTaskExecutor()` instead — virtual threads inherit the creating thread's context classloader:

```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    var future = executor.submit(() -> blockingWork());
    return future.get(timeout, TimeUnit.MILLISECONDS);
}
```

Or pass a Quarkus-managed executor explicitly:
```java
CompletableFuture.supplyAsync(() -> blockingWork(), managedExecutor);
```

### Why this is non-obvious
`CompletableFuture.supplyAsync()` is the standard Java API for async computation. Nothing in the API warns about classloader incompatibility. The error message (`JtaContextProvider not a subtype`) gives no hint that this is a classloader issue — it looks like a missing dependency.

### Alternatives considered
- Quarkus `ManagedExecutor` — works but requires CDI injection, not available in all contexts
- Setting thread context classloader manually on ForkJoinPool threads — hacky and fragile
