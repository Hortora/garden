### Symptom
Running `mvn test -pl my-module -Dtest=MyTest -am` fails with:
> No tests matching pattern "MyTest" were executed!

The error comes from an **upstream dependency module** (e.g. `fusion-api`), not from `my-module`. The target module's test never runs.

### Context
Multi-module Maven project. Using `-pl my-module -am` to build `my-module` plus its transitive dependencies. Adding `-Dtest=MyTest` to run a specific test in `my-module`.

### Root Cause
`-Dtest=MyTest` is a system property applied to every module in the Maven reactor, not just the target `-pl` module. When `-am` includes upstream modules in the reactor, Surefire runs in each one and enforces the test filter. Upstream modules don't have `MyTest`, so Surefire fails on the first one it reaches.

### Fix
Add `-Dsurefire.failIfNoSpecifiedTests=false` to let upstream modules pass without matching tests:

```bash
mvn test -pl my-module -Dtest=MyTest -am -Dsurefire.failIfNoSpecifiedTests=false
```

### Why This Is Non-Obvious
The error message names the upstream module and says "No tests matching pattern" — which reads like a test discovery problem in the wrong module, not a scoping issue with the `-Dtest` property. The natural debugging path is to check test naming, classpath, or module structure rather than adding a property to suppress the filter in non-target modules.
