# Spring Boot 4 moves HealthIndicator, Health, Status to spring-boot-health module

### Symptom

Compilation fails with "cannot find symbol: variable Health" and "does not override or implement a method from a supertype" for HealthIndicator implementations after upgrading to Spring Boot 4.

### Context

Spring Boot 4 reorganized the health infrastructure. The actuator module was split — health types moved to a dedicated `spring-boot-health` module with new package names.

### Root cause

Three relocations:
- `org.springframework.boot.actuate.health.HealthIndicator` → `org.springframework.boot.health.contributor.HealthIndicator`
- `org.springframework.boot.actuate.health.Health` → `org.springframework.boot.health.contributor.Health`
- `org.springframework.boot.actuate.health.Status` → `org.springframework.boot.health.contributor.Status`

The containing artifact changed from `spring-boot-actuator` to `spring-boot-health`.

### Fix

Update imports and POM dependency:

```java
// Before (Spring Boot 3.x)
import org.springframework.boot.actuate.health.Health;
import org.springframework.boot.actuate.health.HealthIndicator;
import org.springframework.boot.actuate.health.Status;

// After (Spring Boot 4.x)
import org.springframework.boot.health.contributor.Health;
import org.springframework.boot.health.contributor.HealthIndicator;
import org.springframework.boot.health.contributor.Status;
```

```xml
<!-- POM: add spring-boot-health (or use spring-boot-starter-actuator which pulls it) -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-health</artifactId>
</dependency>
```

`InfoContributor` stayed at `org.springframework.boot.actuate.info.InfoContributor` — not relocated.

`@ConditionalOnClass(HealthIndicator.class)` still works as a classpath guard — the class exists in the new package.

### Why this is non-obvious

The error messages don't mention the package relocation — they report "cannot find symbol" which looks like a missing dependency, not a wrong import. The old `spring-boot-actuator` JAR still exists but no longer contains health types. IDE auto-import suggestions may point to the old package if the old JAR is still on classpath from a transitive dependency.

### Why this fix

The Spring Boot team split actuator into focused modules. Health got its own first-class module (`spring-boot-health`) reflecting its importance beyond just the actuator endpoint. This is a permanent reorganization, not a deprecation cycle.

### Alternatives considered

- Adding `--add-opens` to expose the old package — wrong approach, the classes genuinely moved
- Keeping `spring-boot-actuator` dependency — still needed for `InfoContributor`, but health types require `spring-boot-health`
