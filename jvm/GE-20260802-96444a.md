## Nested domain directories in garden cause duplicate Qdrant points with different sourceDocumentId paths

### Symptom

`gardenSearch` returns the same entry twice with different scores and different `id` fields: `jvm/GE-20260517-e78ae8.md` and `jvm/jvm/GE-20260517-e78ae8.md`. The content is identical.

### Context

A forage or manual operation placed an entry file at `~/.hortora/garden/jvm/jvm/GE-20260517-e78ae8.md` instead of `~/.hortora/garden/jvm/GE-20260517-e78ae8.md`. The filesystem watcher detected both paths and indexed both as separate Qdrant points with different `sourceDocumentId` values.

### Root cause

`FlatChangeSource` scans recursively — it finds files in nested subdirectories. The `sourceDocumentId` is the relative path from the garden root. When a file exists at both `jvm/GE-xxx.md` and `jvm/jvm/GE-xxx.md`, the watcher creates two separate Qdrant points. There is no path normalization or dedup check.

### Fix

1. **Prevent:** Validate the target path before writing — ensure no nested domain directories exist:
   ```bash
   # Check for nested dirs before writing
   ls ~/.hortora/garden/jvm/jvm/ 2>/dev/null && echo "WARNING: nested domain dir exists"
   ```

2. **Detect:** Run a dedup scan using cosine similarity — self-matches (score > 0.99) with different sourceDocumentId paths are the signature:
   ```python
   # Qdrant nearest-neighbor query with score_threshold=0.99
   # Self-matches with different sourceDocumentId = path duplication
   ```

3. **Fix:** Move files from nested dirs to parent, remove duplicate, run reconcile:
   ```bash
   git -C ~/.hortora/garden mv jvm/jvm/GE-xxx.md jvm/GE-xxx.md
   # Engine filesystem watcher handles the rest
   ```

### Why this is non-obvious

The duplicate is invisible in normal usage — search results show different `id` fields (with and without the nested path) but identical content. The 0.999 cosine similarity is only detectable via a corpus-wide nearest-neighbor scan. No error or warning is produced during ingestion.
