### Context
`DefaultCaseTrigger.buildInputData()` automatically adds several fields to case input data:
`situationId`, `correlationKey`, `tenancyId`, and `detections` (the raw `List<TimestampedDetection>`
from the `SituationContext`). After building the base data, it calls each registered
`CaseInputContributor.contribute()` and merges results via `data.putAll(contributor.contribute(...))`.

### Technique
Because `putAll` overwrites existing keys, a `CaseInputContributor` can override any
auto-added field — including `detections`. This enables applications to:

1. **Transform raw RAS objects** into JSON-serializable representations (critical for
   avoiding engine ObjectMapper serialization failures — see GE-20260730-41c406)
2. **Extract domain-specific context** from detection results (e.g. alert severity,
   source, rule from ganglion evidence maps) and add it as structured case context
3. **Remove unwanted fields** by putting the same key with a transformed value

```java
@ApplicationScoped
public class SocCaseInputContributor implements CaseInputContributor {
    @Override
    public Map<String, Object> contribute(CaseTriggerConfig config, SituationContext context) {
        Map<String, Object> data = new LinkedHashMap<>();
        // Extract alert from first detection's evidence
        if (!context.detections().isEmpty()) {
            var first = context.detections().getFirst();
            data.put("alert", Map.of(
                "eventType", first.result().evidence().get("eventType"),
                "severity", first.result().signal().name(),
                "confidence", first.result().confidence()));
        }
        // Override raw detections with serializable form
        data.put("detections", context.detections().stream()
            .map(td -> Map.of(
                "ganglionId", td.result().ganglionId(),
                "signal", td.result().signal().name(),
                "confidence", td.result().confidence(),
                "eventTime", td.eventTime().toString()))
            .toList());
        return data;
    }
}
```

### Why this is non-obvious
The `CaseInputContributor` SPI is documented for *adding* data, but the `putAll` merge
semantics make it equally useful for *overriding* auto-added fields. Without this knowledge,
the natural approach would be to try to intercept `DefaultCaseTrigger` or subclass it —
both of which are harder and less portable.
