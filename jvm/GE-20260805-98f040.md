### The technique

When an `@Alternative` CDI bean needs to fall back to the default implementation on failure (e.g., LLM service falls back to deterministic adapter on timeout), the default must be `@ApplicationScoped` — **not** `@DefaultBean`.

```java
// ✅ CORRECT — default stays in CDI when alternative is active
@ApplicationScoped
public class TemplateSarNarrativeService implements SarNarrativeService {
    // deterministic adapter — always available
}

@Alternative @Priority(1) @ApplicationScoped
public class EidosSarNarrativeService implements SarNarrativeService {

    private final TemplateSarNarrativeService fallback;

    @Inject
    public EidosSarNarrativeService(TemplateSarNarrativeService fallback, ...) {
        this.fallback = fallback;  // injected by concrete type — works
    }

    NarrativeResult callLlm(NarrativeContext ctx) { /* LLM call */ }

    NarrativeResult draftDeterministic(NarrativeContext ctx) {
        return fallback.draft(ctx);  // fallback on failure
    }
}
```

```java
// ❌ WRONG — @DefaultBean is REMOVED from CDI when @Alternative activates
@DefaultBean @ApplicationScoped
public class TemplateSarNarrativeService implements SarNarrativeService { ... }

// EidosSarNarrativeService @Inject TemplateSarNarrativeService → UnsatisfiedResolutionException
// The @DefaultBean bean is gone — CDI does not provide it when an @Alternative for the same type is active
```

### Why this is non-obvious

The mental model of `@DefaultBean` is "use this unless something better exists" — which sounds exactly like a fallback. But `@DefaultBean` in Quarkus Arc means "this bean is removed from the CDI container when any non-default bean for this type exists." It is a displacement mechanism, not a priority mechanism.

When the `@Alternative` activates, CDI resolves `SarNarrativeService` to the alternative (correct) but the `@DefaultBean` implementation is no longer a bean at all — injection by concrete type fails with `UnsatisfiedResolutionException`.

The `@ApplicationScoped` (non-default) bean stays in CDI regardless of whether the `@Alternative` is active. CDI resolves the interface to the alternative, but the concrete type is still injectable — enabling the composition pattern.

### When to use which

| Pattern | CDI annotations | Use case |
|---------|----------------|----------|
| **Layer displacement** | `@DefaultBean` + `@ApplicationScoped` (no `@Alternative`) | Progressive replacement: Layer 1 stub displaced by Layer 3 real implementation. No composition — the displaced bean is not needed. |
| **Optional runtime variant** | `@ApplicationScoped` + `@Alternative @Priority(1)` | Composition with fallback: the alternative wraps the default and delegates on failure. Both beans must coexist in CDI. |

### Caveats

- The concrete-type injection creates intentional coupling — the `@Alternative` knows about the specific default implementation. This is acceptable for the fallback pattern (the alternative is architecturally above the default) but would be wrong for peer implementations.
- Activation requires explicit `quarkus.arc.selected-alternatives` configuration — the `@Alternative` does not auto-activate on classpath presence.
