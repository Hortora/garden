### Symptom
`index.getAnnotations(DotName)` returns empty even though classes annotated with the target annotation are in the Jandex index. Error message: "Index did not contain annotation definition: io.example.MyAnnotation".

### Context
Writing a Quarkus build extension where annotations are defined in a runtime module and annotated classes are in the application. The runtime module JAR does not have a Jandex index (`jandex-maven-plugin` not configured).

### What was tried (didn't work)
- Verified annotated classes ARE in the index via `withApplicationRoot().addClasses()`
- Checked DotName construction (`DotName.createSimple(String)` vs `DotName.createSimple(Class)`) — both produce the same result
- Added `quarkus-extension.properties` and `quarkus-extension.yaml` — no effect on annotation discovery

### Root cause
Jandex's `getAnnotations()` requires the annotation type definition itself to be present in the index. If the annotation class is in a JAR without a Jandex index, the index has no definition for that annotation type and cannot find instances of it — even when annotated classes are indexed.

### Fix
Add `jandex-maven-plugin` to the module that contains the annotation definitions:

```xml
<plugin>
    <groupId>io.smallrye</groupId>
    <artifactId>jandex-maven-plugin</artifactId>
    <executions>
        <execution>
            <id>make-index</id>
            <goals><goal>jandex</goal></goals>
        </execution>
    </executions>
</plugin>
```

### Why this is non-obvious
The intuition is that indexing the *annotated* class is sufficient — annotations are metadata ON the class. But Jandex stores annotation definitions separately and requires them to be indexed independently. The error message ("Index did not contain annotation definition") is clear once you see it, but it only appears for some Jandex API calls, not all.
