### Context
When using `CbrCaseMemoryStore.retrieveSimilar()` with a `TimeSeries` field, DTW is computed internally by `CbrSimilarityScorer` to produce the per-feature similarity score. The low-level `DtwSimilarity.compute()` returns a `DtwResult(score, List<AlignmentPair> alignment)` containing the full warping path — which step in the query maps to which step in the case.

### What is undocumented
`ScoredCbrCase` — the return type of `retrieveSimilar()` — only exposes:
- `score` (overall weighted similarity, `double`)
- `featureSimilarities` (`Map<String, Double>` — per-feature similarity scores)

The DTW alignment path (`List<AlignmentPair>`) is computed but discarded by the high-level retrieval API. There is no way to obtain alignment data from `ScoredCbrCase`.

### Workaround
Re-run `DtwSimilarity.compute()` directly on the retrieved cases' timeline features. This is a static method — no instance or CDI needed:

```java
// After retrieval
List<ScoredCbrCase<SC2GameCbrCase>> results = cbrStore.retrieveSimilar(query, SC2GameCbrCase.class);

// For each result, re-run DTW to get the alignment path
for (var scored : results) {
    var caseTimeline = ((FeatureValue.StructListVal) scored.cbrCase().features().get("timeline")).items();
    
    DtwResult dtwResult = DtwSimilarity.compute(
            queryObservations, caseTimeline, timeSeriesSchemaField,
            new WarpingConstraint.SakoeChibaBand(3), Double.MAX_VALUE);
    
    // dtwResult.alignment() is the warping path
    List<AlignmentPair> alignment = dtwResult.alignment();
    int alignmentPoint = alignment.get(alignment.size() - 1).caseIndex();
    // Use alignmentPoint to look ahead in the past game's timeline
}
```

### Performance impact
The re-run is only needed on top-K results (typically 5), not all candidates. At 5 × O(n×m×w) with n≈8, m≈30, w=3, this adds ~3600 operations — negligible compared to the initial retrieval across all stored cases.

### Why this is non-obvious
The `DtwSimilarity.compute()` method and `DtwResult` record are public API — they exist and work. But the typical consumer path (`registerSchema` → `store` → `retrieveSimilar`) never surfaces the alignment data. A developer following the standard CBR lifecycle would not discover that direct `DtwSimilarity.compute()` invocation is needed for alignment-dependent use cases like temporal prediction.
