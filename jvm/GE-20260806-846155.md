### Symptom
Maven builds fail with `The specified user settings file does not exist:` followed by the project basedir, a space, and the settings path — regardless of whether the path is absolute or relative:

```
The specified user settings file does not exist: /Users/dev/project/ /Users/dev/slot/settings.xml
The specified user settings file does not exist: /Users/dev/project/ .mvn/slot-settings.xml
```

### Context
Any Maven 3.9.x project that uses `-s <path>` in `.mvn/maven.config` to point to a custom settings file. Common in slot-based workflows where each slot has its own settings with repository fallbacks.

### What was tried (didn't work)
- Absolute paths (`-s /absolute/path/to/settings.xml`) — basedir prepended
- Relative paths (`-s .mvn/slot-settings.xml`) — basedir prepended
- Moving the settings file into the project directory — same issue

### Root cause
Maven's `.mvn/maven.config` parser splits on whitespace. The `-s` flag and its value become two tokens. The value token passes through a path resolver that prepends basedir using string concatenation with a space separator instead of proper path joining.

### Fix
Use `--settings=path` (equals sign, no space) instead of `-s path`:

```
# Broken — all of these fail:
-s /absolute/path/to/settings.xml
-s .mvn/slot-settings.xml

# Works — equals sign keeps flag+value as one token:
--settings=.mvn/slot-settings.xml
```

Place the settings file inside `.mvn/` and reference it with a short relative path.

### Why this is non-obvious
The error message looks like the path is wrong, not that Maven's parser is broken. The natural response is to fix the path — but no path works with the space-separated form. The `=` workaround is not documented in Maven's `.mvn/maven.config` documentation.
