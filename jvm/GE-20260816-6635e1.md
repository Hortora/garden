## Context

The blocks agentic framework has two execution backends: `reactive()` (orchestrated push) and `choreographed(EventSource...)` (event-driven). When running a Debate pattern over qhorus channels, three concerns must be bridged: (1) channel messages must update a `ConversationProjection`, (2) the projected state must be accessible for `ConvergenceTermination`, and (3) new messages must wake the `ChoreographedDriver` for the next iteration.

## Technique

`ChannelObserver<S>` (in `blocks.agentic.channel`, added in blocks#97) implements all three interfaces in a single type:

- **`MessageObserver`** (qhorus) — `onMessage()` applies the projection to update state via `AtomicReference`
- **`EventSource`** (blocks) — `subscribe(Consumer<DriverEvent>)` emits `DriverEvent.signal("message")` on each new message, waking the `ChoreographedDriver`
- **State holder** — `currentState()` returns the latest projected state for termination checks

Additional API:
- `terminateWhen(Predicate<S>)` — convenience factory for `TerminationCondition` from a predicate
- `asTermination(Function<S, TerminationDecision>)` — full-control factory
- `Builder` — `ChannelObserver.builder(projection).channel("name1").channel("name2").build()` for multi-channel observation
- `TerminationCondition.or()` / `.and()` — priority-aware composition (Escalate > Failed > Complete > Continue)

## Why this is non-obvious

Without `ChannelObserver`, you'd build three separate components: a `MessageObserver` that applies the projection, a custom `EventSource` that wraps the observer's notification, and a state holder with thread-safe access. The three would need to be wired together manually — and every app using channel-based patterns would rebuild the same bridge. `ChannelObserver` makes the composition declarative.
