### Symptom
WorkItem created from a YAML binding with `scopeExpression` has `scope = null`. The dynamic scope expression evaluates correctly (visible in `HumanTaskScheduleEvent.resolvedScope()`) but never reaches the WorkItem.

### Context
Using `scopeExpression` in the analyst-review YAML binding to encode priority tier in the scope path for SLA breach policy routing.

### Root cause
`HumanTaskScheduleHandler.createInline()` used `target.scope()` (the static field from HumanTaskTarget) instead of `event.resolvedScope()` (the engine-evaluated expression result). Same issue for `resolvedTitle`.

```java
// Before fix:
.scope(target.scope())      // null when scopeExpression is used

// After fix (work#340):
.scope(resolvedScope != null ? resolvedScope : target.scope())
```

### Fix
Fixed in casehubio/work#340. Update `casehub-work-engine-adapter` to a snapshot dated 2026-08-06 or later.

### Why this is non-obvious
The engine correctly evaluates `scopeExpression` and carries the result in `HumanTaskScheduleEvent.resolvedScope()`. The handler just doesn't use it — a plumbing gap, not an evaluation failure. `expiresInExpression` works through a different path (`event.expiresAtDeadline()`), so dynamic expressions appear to work in general.
