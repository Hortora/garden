### Context
When creating a `SituationRegistration` for use with `SituationDefinitionRegistry.register()` or `SituationDefinitionProvider.registrations()`, the `correlationKeyExtractor` parameter can be null.

### What happens
The compact constructor in `SituationRegistration` defaults `null` to `DefaultCorrelationKeyExtractor.INSTANCE`:
```java
public SituationRegistration {
    Objects.requireNonNull(definition, "definition");
    if (correlationKeyExtractor == null) {
        correlationKeyExtractor = DefaultCorrelationKeyExtractor.INSTANCE;
    }
}
```

There are also convenience constructors:
- `new SituationRegistration(definition, null)` — 2-arg
- `new SituationRegistration(definition)` — 1-arg

### Evidence
The existing `DesiredStateSituationDefinitionProvider` passes `null` for the extractor on 2 of 3 registrations (repeated-failure and persistent-drift situations). Only zone-degradation uses a custom `DesiredStateCorrelationKeyExtractor`.

### Why this is non-obvious
No javadoc documents this default behaviour. The record has 4 fields (`definition`, `correlationKeyExtractor`, `eventFilter`, `compiledDynamicData`), and a developer might assume all are required. The null-defaulting behaviour is only discoverable by reading the compact constructor source.
