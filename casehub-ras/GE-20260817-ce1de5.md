### Context
When writing `GanglionDescriptor.ExpressionRules` for RAS, the `Rule.when` field is an `ExpressionEvaluator` that receives a context map. The structure of this map determines what conditions your rules can evaluate.

### What happens
`CloudEventExpressionContext.build(CloudEvent event)` (runtime-internal class) produces a `Map<String, Object>` with exactly these keys:

| Key | Type | Source |
|-----|------|--------|
| `type` | String | `event.getType()` |
| `source` | String | `event.getSource().toString()` |
| `subject` | String | `event.getSubject()` |
| `id` | String | `event.getId()` |
| `time` | String | `event.getTime().toString()` |
| `tenancyid` | String | `event.getExtension("tenancyid")` |
| `data` | Map<String, Object> | JSON-parsed `event.getData()` — empty map if null, non-JSON, or parse failure |

The `data` key contains the parsed JSON payload as a nested map. Rule conditions access nested data via `((Map) ctx.get("data")).get("fieldName")`.

### Evidence
Found by reading `ExpressionRulesGanglion.detect()` → `CloudEventExpressionContext.build(event)` in `casehub-ras-runtime`. The class is package-private, not documented in the RAS API guide or contributor guide. The `ExpressionRulesGanglionTest` uses `CompiledExpression<Map, Boolean>` lambdas that return `true`/`false` without inspecting the map — so the test doesn't demonstrate the map structure.

### Why this is non-obvious
The RAS API declares `ExpressionEvaluator` as a marker interface with no type parameter for the context. The fact that it receives a `Map<String, Object>` with specific keys is only discoverable by reading the runtime source. A developer writing ExpressionRules ganglia would not know what keys are available without tracing through `ExpressionRulesGanglion.detect()`.
