### Symptom
After opening a slot clone (e.g. `slots/138/pages`) via `ide_open_project`, both it and the main clone (`casehub/pages`) appear in IntelliJ's project list as "pages". All `ide_*` calls without an explicit `project_path` parameter, or with the wrong path, silently operate on the main clone's checkout (on `main`) rather than the slot (on the feature branch). Edits succeed but modify the wrong files.

### Context
Slots are full git clones of a repo at a different path, typically on a feature branch. When both the main repo and a slot are open in IntelliJ, they share the same project name. `ide_open_project` returns success even when the project was already registered under a different path.

### What was tried (didn't work)
- Calling `ide_open_project` with the slot path — returned "Project 'pages' is open and ready" but this was the existing main checkout, not the slot
- Using IntelliJ tools without `project_path` — defaulted to the main clone

### Root cause
IntelliJ's MCP plugin disambiguates projects by path, not name. When multiple projects share a name, the `project_path` parameter is mandatory on every `ide_*` call. The `ide_open_project` success message doesn't indicate which path was actually used.

### Fix
Always pass `project_path` with the full slot path to every `ide_*` call:
```
ide_replace_text_in_file({
  file: "src/scenario/types.ts",
  project_path: "/Users/dev/slots/138/pages",  // slot path, not main
  searchText: "...",
  replaceText: "..."
})
```

Verify the slot is registered by checking `ide_open_workspace` or `ide_open_project` error output — the available projects list shows paths, confirming which "pages" is which.

### Why this is non-obvious
The `ide_open_project` call returns a generic success message that doesn't reveal which physical project was resolved. The natural assumption is that opening a project by path targets that specific path, but IntelliJ may match an existing project by name instead. The failure mode is silent — edits succeed on the wrong checkout with no warning.
