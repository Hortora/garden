### Symptom

After using `ide_replace_member` to rewrite a large method body (~30 lines), a critical call at the end of the method (`economyTracker.tickUpdate(...)`) was silently removed. The tool reported success: `"Replaced body of method 'tick'"`. No warning about content loss. The regression was only caught during code review.

### Context

Occurs when replacing the body of a method that has more content than the replacement string includes. The tool replaces the entire body between `{` and `}` with exactly what you provide — it does not merge or diff. If the original method has lines you didn't copy into the replacement (because you were focused on the section you were modifying), those lines are permanently deleted.

Particularly dangerous with large methods where you're modifying the top half but the bottom half has important calls you didn't read into your replacement content.

### Root cause

`ide_replace_member` is a wholesale replacement, not a patch. It replaces the full method body with the provided content. There is no diff, no merge, and no warning when the replacement is shorter than the original. The success message is identical whether you preserved all original content or dropped half of it.

### Fix

Before calling `ide_replace_member` on a method body, read the full method first and include ALL original lines in the replacement content — not just the section you're modifying. Alternatively, use `ide_replace_text_in_file` for surgical insertions within a method body (find a unique anchor string and replace it with the anchor plus your new code).

For additions to a method (inserting new code blocks), prefer `ide_replace_text_in_file` with a unique anchor over `ide_replace_member` — the anchor approach only touches the targeted location and cannot accidentally drop other content.

### Why this is non-obvious

The tool name suggests "replace member" — which could mean "replace part of a member" or "replace the entire member body." The documentation says "replaces the code between { and }" but the implications for large methods aren't immediately apparent. The success response gives no indication that content was lost, making it feel safe when it isn't. A developer would expect either a diff-based merge or at least a warning when the replacement is significantly shorter than the original.

### Alternatives considered

- Using `Edit` tool with `old_string`/`new_string` for surgical changes — blocked by the `intellij-first-edit.sh` hook in projects that enforce IntelliJ MCP usage
- Using `ide_insert_member` — only works for adding new members, not modifying existing method bodies
