### Symptom

After using `ide_edit_member` to replace a field declaration, the project fails to compile with `';' expected` on the line after the field.

### Context

Occurs when replacing a static field initializer via `ide_edit_member` with `member` set to the field name. The tool replaces the field value but can strip the trailing `;` delimiter, producing syntactically invalid Java.

Example: replacing `TERMINAL_STATES = Set.of("completed", "failed", "cancelled")` produced `Set.of("completed", "failed", "canceled")` without the semicolon.

### Root cause

`ide_edit_member` treats fields differently from methods — method bodies have natural `{}` delimiters, but field initialisers end with `;` which the tool sometimes drops during replacement.

### Fix

Always run `mvn compile` or `ide_build_project` immediately after any `ide_edit_member` call that targets a field. If the semicolon is missing, use `ide_replace_text_in_file` to add it back.

### Why this is non-obvious

The edit appears to succeed — the tool returns `success: true` and the field value is correct. The missing semicolon is only discovered at compile time, and the error points to the *next* line, not the edited field.
