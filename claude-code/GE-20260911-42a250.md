## Context

In a multi-repo slot, each project repo has a `wksp` symlink pointing to a workspace clone (e.g. `wksp -> ../wsp-casehub-neocortex`). The workspace contains specs, plans, blog posts, and other markdown files that reference Java type names as text (e.g. `PlanCbrCase` mentioned in design specs).

When `ide_refactor_rename` is called to rename a widely-referenced Java record (106+ references), IntelliJ processes text occurrences in ALL project-visible files — including markdown files accessible via the symlink.

## Symptom

`ide_refactor_rename` fails with: "Rename was not applied — the platform aborted the refactoring (read-only files or unresolved conflicts)." No diagnostics errors reported. `ide_diagnostics` shows zero problems. All files in the project tree are writable (`find -not -writable` returns nothing). The rename silently does nothing.

## What was tried

1. `ide_sync_files` → still fails
2. Remove wksp symlink → still fails (IntelliJ caches the project VFS)
3. `ide_refactor_rename` with `relatedRenamingStrategy: "none"` → still fails
4. `ide_move_file` as workaround → creates a nested DIRECTORY instead of renaming
5. `ide_refactor_rename` with `targetType: "file"` → still fails

## Root cause

Two compounding issues:

1. **Symlinked markdown files:** IntelliJ's rename refactoring includes a "search for text occurrences" phase that processes non-Java files. When markdown files in symlinked directories reference the type being renamed, IntelliJ may abort if it encounters issues processing those files (permissions, encoding, or file system semantics of symlink targets).

2. **Maven not linked:** After adding new modules to the parent pom.xml, `ide_reload_project` reported "Maven: skipped — build file found on disk but project is not linked." Without Maven linkage, IntelliJ cannot resolve the full dependency graph, causing the rename to fail even after removing the symlink. This is the same root cause as GE-20260816-6eb6ff but with a different trigger (adding modules, not opening a workspace).

## Fix

Three steps, all required:

1. **Remove the symlink** before renaming:
   ```bash
   rm <repo>/wksp
   ```

2. **Ensure Maven is linked** — the symlink removal alone is insufficient if Maven became unlinked:
   ```
   ide_open_project(path=<repo>, autoLink=true)
   ```

3. **Perform the rename**, then **restore the symlink**:
   ```
   ide_refactor_rename(file=<file>, targetType="symbol", line=N, column=N, newName="NewName")
   ```
   ```bash
   ln -s ../wsp-<family>-<repo> <repo>/wksp
   ```

### Why this fix

The symlink removal prevents IntelliJ from seeing the markdown files during the rename's text-occurrence phase. The Maven re-link ensures the dependency graph is complete so IntelliJ can resolve all type references across modules. Both must be done — either alone is insufficient.

## Why this is non-obvious

The error message says "read-only files" but no files are read-only. The actual cause is a combination of symlinked directory traversal and Maven unlinking, neither of which is mentioned in the error. The same error message appears for both causes, making diagnosis harder. A developer would naturally try `ide_sync_files` or check file permissions — neither helps.

### Alternatives considered

- **`ide_move_file` with newName** — creates a nested directory (destination treated as directory path, not file rename)
- **Bash-based rename** — bypasses IntelliJ reference updates entirely; blocked by project hooks that enforce IntelliJ usage
- **`ide_replace_text_in_file` across all files** — mechanical but loses semantic rename safety (wouldn't rename the file or update imports)
