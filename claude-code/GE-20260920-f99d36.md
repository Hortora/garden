# IntelliJ MCP ide_refactor_rename blocks on invisible preview dialog for text replacements in non-code files

## Symptom
`ide_refactor_rename` returns "Rename was not applied — the platform aborted the refactoring (read-only files or unresolved conflicts)" for renames that touch many files including markdown docs. The identical error as the symlink issue, but different root cause. Dry run shows `canApply: true`, 0 conflicts.

## Context
Renaming a widely-used type (e.g. an interface with 700+ usages across Java and markdown files). IntelliJ finds text references to the symbol name in markdown files and shows a "Preview" dialog in the GUI for the user to confirm non-code replacements. The MCP plugin cannot interact with GUI dialogs, so it reports the refactoring as aborted.

## What was tried (didn't work)
- `relatedRenamingStrategy: "none"` — still triggers preview for non-code text matches
- Restarting IntelliJ — dialog reappears on next rename attempt
- Multiple rename attempts — previews stack up in IntelliJ, compounding the problem

## Root cause
IntelliJ's rename refactoring shows a preview dialog when it detects text-based (non-code) replacements in comments, strings, or non-code files. This is a safety feature in the GUI. The MCP plugin's headless rename cannot dismiss this dialog, so the refactoring blocks until a human clicks "Refactor" in the IntelliJ window.

## Fix
The user must watch the IntelliJ GUI window and click "Refactor" on the preview dialog when it appears. Coordinate with the MCP client:

1. Fire the rename via MCP
2. Watch IntelliJ GUI for the preview dialog
3. Click "Refactor" to proceed
4. The MCP tool may still report failure (it timed out waiting), but check the filesystem — the rename likely completed

Small renames (< ~30 affected files, no markdown references) typically proceed without a preview dialog.

## Why this is non-obvious
The error message is identical to the symlink failure ("read-only files or unresolved conflicts"), making it impossible to distinguish the two failure modes from the MCP response alone. The dialog is invisible to the MCP client — there is no API to detect or dismiss it. Repeated rename attempts cause previews to stack, making IntelliJ appear "stuck in a loop."
