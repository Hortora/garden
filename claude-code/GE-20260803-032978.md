### Symptom

Agents dispatched with `isolation: "worktree"` fail or produce inferior results when instructed to use IntelliJ MCP tools (`ide_find_references`, `ide_search_text`, etc.). The tools either error or return no results because the worktree path is not recognized as an open project.

### Context

The Agent tool's `isolation: "worktree"` creates a fresh git worktree at `.claude/worktrees/agent-<id>/`. This gives each agent an isolated copy of the repo — no file conflicts. But IntelliJ only knows about projects explicitly opened in the IDE. The worktree directory is not an IntelliJ project and has no `.idea/` directory.

### What was tried (didn't work)

Dispatching agents with instructions to use IntelliJ MCP for code navigation. The agents couldn't resolve symbols or find references because their working directory (`/project/.claude/worktrees/agent-xxx/`) isn't an open IntelliJ project.

### Root cause

IntelliJ MCP tools require `project_path` to point to an open project in the IDE. Git worktrees created by the Agent tool are ephemeral directories that IntelliJ has never seen. Even `ide_open_project` would need `.idea/` configuration or a build file (pom.xml/build.gradle) — the worktree has the build file but opening it adds latency and IDE resource consumption per agent.

### Fix

When dispatching agents with worktree isolation, explicitly instruct them to use Read/Edit/Bash tools instead of IntelliJ MCP. Include this in the agent prompt:

> "Do NOT use IntelliJ MCP tools — they won't work in a worktree. Use Read/Edit/Bash tools."

For S-scale mechanical work (renames, find-and-replace, new file creation), text tools are sufficient. For work requiring semantic code intelligence, consider sequential execution in the main project instead of parallel worktree dispatch.

### Why this is non-obvious

Agents inherit MCP server connections from the parent session, so the tools appear available. The failure is silent — the agent tries IntelliJ tools, gets errors or empty results, and falls back to guessing rather than using text tools. The prompt must preemptively block IntelliJ usage.
