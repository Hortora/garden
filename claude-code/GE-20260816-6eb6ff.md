## Context

Multiple Claude sessions share one IntelliJ instance. When session B opens a large workspace (e.g. `ide_open_workspace` with 50+ modules), session A's previously-open project may lose its Maven model linkage — IntelliJ unloads the Maven project to accommodate the new workspace.

## Symptom

`ide_find_class` with `scope: project_and_libraries` returns zero results for types that are Maven dependencies (e.g. `ChannelObserver` from `casehub-blocks`). Project source files still visible — only dependency jars are missing. `ide_reload_project` reports: "Maven: skipped — build file found on disk but project is not linked in IntelliJ."

## Root cause

IntelliJ's project model and Maven model are independent. `ide_open_project` reopens the project directory and restores the `.idea` project structure, but does NOT automatically re-link the Maven build model. The Maven model was unloaded when the other session's workspace displaced it, and reopening the project doesn't trigger a Maven re-import.

## Fix

Manually click "Link" in the IntelliJ Maven tool window to re-import the Maven model. Alternatively, `ide_import_modules` reports "already imported as a module" (because the project directory IS the module) but doesn't fix the Maven linkage.

**Workaround for automated sessions:** Use `javap` or `python3 zipfile` to decompile classes directly from the `.m2/repository` jar files. This bypasses IntelliJ entirely but loses semantic navigation.

## Why this is non-obvious

`ide_open_project` succeeds and reports "Project is open and ready." `ide_index_status` shows `isDumbMode: false, isIndexing: false` — everything appears healthy. The only symptom is that dependency types are invisible in `project_and_libraries` scope, which looks like a search query problem rather than a Maven linkage problem.
