### Symptom
Multi-line text replacement via `ide_replace_text_in_file` produces a single line with literal `\n` characters instead of newlines. No error is reported — the file is silently mangled.

### Context
When using `ide_replace_text_in_file` to replace a block of code with multi-line content, `\n` escape sequences in the `replaceText` parameter are interpreted as two literal characters (backslash + n), not as newline characters.

### Root cause
The tool's `replaceText` parameter documentation says "The escape sequences \\n, \\t, and \\\\ are interpreted as newline, tab, and a single literal backslash" — but in practice, `\n` is treated as literal backslash-n when embedded in a longer replacement string. The tool works for single-line find-and-replace but cannot produce multi-line output.

### Fix
Use `Edit` with `replace_all: true` for multi-line replacements. Reserve `ide_replace_text_in_file` for single-line substitutions only (renaming tokens, updating imports, changing literals).

### Why this is non-obvious
The tool's own documentation claims `\n` is interpreted as a newline. The failure is completely silent — no error, no warning, just code that doesn't parse.
