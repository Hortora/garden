# IntelliJ MCP ide_refactor_rename silently fails when project contains symlinks to other git repos

## Symptom
`ide_refactor_rename` returns "Rename was not applied — the platform aborted the refactoring (read-only files or unresolved conflicts)" even though `dryRun: true` reports `canApply: true` with 0 conflicts.

## Context
Project directory contains a symlink (e.g. `wksp -> ../workspace-repo`) pointing to a directory in a separate git repository. The rename target has many usages (764+) including text references in markdown files. IntelliJ follows the symlink during refactoring, finds files in the symlinked directory, and tries to modify them as part of text-based reference updates.

## What was tried (didn't work)
- `relatedRenamingStrategy: "none"` — still fails
- Position-based targeting instead of qualified-name — still fails
- Restarting IntelliJ — still fails (stale VCS mapping persists)
- Fixing `.idea/vcs.xml` to remove stale VCS directory mapping — still fails until IDE restart AND symlink removal
- `ide_open_project` with `excludeDirectories` — causes "Write access is allowed inside write-action only" threading error that corrupts refactoring system

## Root cause
IntelliJ traverses symlinks when searching for text references in non-code files (markdown, etc.). Files reached through the symlink are in a different git repository context, making them effectively read-only from IntelliJ's write-action perspective. The refactoring system aborts when it encounters any file it cannot write to.

Additionally, `excludeDirectories` in `ide_open_project` triggers a write-action threading error that corrupts IntelliJ's internal state, making ALL large refactorings fail even after the symlink is removed.

## Fix
Remove the symlink from the project directory before running renames. If the project was opened with `excludeDirectories`, close and reopen without it (or delete `.idea` and reopen via `ide_open_workspace`).

```bash
# Remove symlink before rename
rm /path/to/project/wksp

# Also clean stale VCS mappings if present
# Edit .idea/vcs.xml to remove <mapping directory="$PROJECT_DIR$/wksp" vcs="Git" />

# Reopen project
ide_open_workspace with modules=["/path/to/project"]

# Restore symlink after renames complete
ln -s ../workspace-repo /path/to/project/wksp
```

## Why this is non-obvious
The dry run reports `canApply: true` with 0 conflicts — the pre-validation passes. The error message says "read-only files or unresolved conflicts" without identifying which files or what conflicts. The symlink appears to be excluded via `excludeDirectories`, but that parameter itself causes a separate threading error. Multiple independent failure modes compound: symlink traversal + VCS mapping + excludeDirectories threading = three interacting bugs that mask each other.

### Alternatives considered
- Using `excludeDirectories` on `ide_open_project` — this triggers the "Write access" threading error, making things worse
- Editing `.idea/vcs.xml` alone — insufficient; the symlink must also be physically removed
- Smaller renames (< ~50 usages) work even with the symlink present — only large renames that touch many markdown files trigger the preview dialog path that follows symlinks
