### Symptom
`ide_search_text` for a method call pattern (e.g. `ApplicationEntity.findById`) returns
far fewer results than actually exist. In the observed case: 1 match returned vs 12
actual call sites confirmed by `mvn compile` errors.

### Context
Occurs when the target method does not exist on the class — for example, calling
`findById()` on a plain JPA entity that hasn't been converted to Panache yet. The
calling code compiles against a method that doesn't exist, making the references
unresolvable in IntelliJ's index.

### What was tried (didn't work)
Trusted the `ide_search_text` result of 1 match and initially underestimated the
scope of the fix. The actual compilation revealed 12 errors across 6 files — the
issue description's "9+ locations" was closer to reality than the search result.

### Root cause
IntelliJ's indexing of method call references depends on symbol resolution. When
`ApplicationEntity` is a plain JPA entity without `findById()`, calls to
`ApplicationEntity.findById()` in other files are unresolvable references. The IDE
cannot classify them as method calls to that specific class, so they may not appear
in text search results that rely on the semantic index.

### Fix
When searching for references to a method/symbol that may not exist yet (pre-fix
scenario), cross-verify with `mvn compile` or `mvn test-compile` to get the true
error count. The compiler finds all call sites regardless of resolution state.

```bash
# Don't trust this alone when the target method doesn't exist:
# ide_search_text query="ApplicationEntity.findById"  →  1 result

# Cross-verify with compilation:
mvn --batch-mode -o compile -pl app 2>&1 | grep "cannot find symbol" | wc -l
# → 12 errors — the real scope
```

### Why this is non-obvious
`ide_search_text` is a text search, not a semantic search — you'd expect it to find
all literal occurrences of the string regardless of whether the symbol resolves. The
gap is that IntelliJ's text search may still use index acceleration that filters based
on resolution state, producing results that look complete but aren't.
