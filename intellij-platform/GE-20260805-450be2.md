### Symptom
Replacing `table` with `dataTable` also converted `sortable` to `sordataTable` across four files. The corruption was silent — the tool reported successful replacements with no warning.

### Context
During a pages-ui API rename (`table` → `dataTable`), `ide_replace_text_in_file` with plain text mode (default, `regex: false`) matched `table` as a substring inside `sortable`. The tool has no `wholeWord` parameter — it always does substring matching in plain text mode.

### What was tried (didn't work)
- Plain text replacement with `searchText: "table"` — corrupts all identifiers containing "table"

### Root cause
`ide_replace_text_in_file` performs substring matching in plain text mode. Unlike `ide_search_text` (which has a `wholeWord` parameter), `ide_replace_text_in_file` has no equivalent. Every occurrence of the search string within any larger token is replaced.

### Fix
Always verify results after `ide_replace_text_in_file`. For short common strings, use regex mode with word boundaries:

```
ide_replace_text_in_file({
  file: "path/to/file.ts",
  searchText: "\\btable\\b",
  replaceText: "dataTable",
  regex: true
})
```

Alternatively, include enough surrounding context in the search text to make the match unique (e.g. `"{ table," ` instead of `"table"`).

### Why this is non-obvious
The tool description says "Find and replace text" which implies exact token matching. The `ide_search_text` tool has a `wholeWord` parameter, creating an expectation that `ide_replace_text_in_file` has the same — but it does not. The corruption is silent: the tool reports the correct total replacement count (which is higher than expected) but gives no warning that unintended matches were included.

### Alternatives considered
- Using multiple targeted replacements with full line context — works but tedious for bulk renames
- Using `ide_refactor_rename` — only works for symbol renames, not arbitrary text like DSL function names
