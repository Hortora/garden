### Symptom

After using `ide_replace_text_in_file` to insert Java generics like `Map.<String, Object>of()`, the code silently fails compilation with `<identifier> expected` errors. The tool reports success with the correct replacement count.

### Context

When using `ide_replace_text_in_file` to replace text containing angle brackets (`<`, `>`), the tool HTML-encodes them in the output. `Map.<String, Object>of()` becomes `Map.&lt;String, Object&gt;of()` in the file. The tool reports successful replacement, but the file contains HTML entities instead of actual angle brackets.

### What was tried (didn't work)

Passed `Map.<String, Object>of()` as the `replaceText` parameter. Tool reported 1 replacement made. Compilation failed with cryptic `<identifier> expected` errors pointing to the HTML entities.

### Root cause

The `ide_replace_text_in_file` MCP tool processes the `replaceText` parameter through an XML/HTML encoding layer, converting `<` to `&lt;` and `>` to `&gt;`. This is likely a serialization issue in the JSON-RPC parameter handling for the IntelliJ MCP plugin.

### Fix

Avoid angle brackets in replacement text entirely. Two workarounds:

1. **Drop the type hint** — use `Map.of()` instead of `Map.<String, Object>of()`. Java type inference handles it in most argument positions.

2. **Use a different tool** — `ide_edit_member` or `ide_replace_member` for structural edits, or `Edit` (if the hook allows it) for non-structural text changes.

### Why this is non-obvious

The tool reports success — correct replacement count, no errors. The HTML encoding is invisible unless you re-read the file. The compilation error (`<identifier> expected`) doesn't mention HTML entities, making the root cause hard to trace.

### Alternatives considered

- Using `Edit` tool directly — blocked by the `intellij-first-edit.sh` hook in projects that enforce IntelliJ-first editing
- Using `ide_edit_member` — correct for structural member replacement but heavier than find-and-replace for simple text substitution
