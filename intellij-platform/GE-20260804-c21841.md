### Symptom

Using `ide_edit_member` with `member = className` on a Java record to add a
field to the record declaration wipes the entire record body — all inner
records, factory methods, and other members are deleted. Only the updated
declaration survives.

### Context

When adding a field to a Java record like `ManorWebSocketEvent` (14 fields,
8 factory methods, 2 inner records), `ide_edit_member` with `member =
ManorWebSocketEvent` and the new declaration as `content` replaces the class
"entirely" — the tool's own response says "Replaced class 'ManorWebSocketEvent'
entirely". The body is not preserved.

### Root cause

`ide_edit_member` with `member = className` treats the content as a complete
class replacement, not a declaration-only update. The tool does not distinguish
between "replace the declaration header" and "replace the entire class".

### Fix

Use `ide_replace_text_in_file` for targeted changes to record declarations —
match the specific text being changed (e.g. the last field + closing paren)
and replace with the new text. This preserves all other record content.

For adding a field to a record constructor:
```java
// Match the last field line
ide_replace_text_in_file(searchText="String reason) {", replaceText="String reason,\n        Double newField) {")
```

Then update factory methods individually with `ide_replace_text_in_file`.

### Why this is non-obvious

The `ide_edit_member` docs say `member = className` is for "class/record/interface
declaration" changes. The natural expectation is that it updates the declaration
while preserving the body — like editing a method signature preserves the method
body. Instead, it replaces the entire class.
