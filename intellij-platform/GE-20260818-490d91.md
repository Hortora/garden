### Symptom
`ide_open_project` succeeds — reports "Project 'X' is open and ready." `ide_index_status` shows `isDumbMode: false`, `isIndexing: false`. But ALL `ide_find_file` queries return zero results — even wildcard `*` and `package.json`. The project appears open and indexed but has no content.

### Context
Opening a TypeScript (or any) project that has a root `.iml` file but no `.idea/modules.xml`. The `.idea` directory may have been auto-created by `ide_open_project` (containing `vcs.xml`, `workspace.xml`) but without module registration. Common with slot-based clones where `.idea/` is gitignored and the project has never been opened in IntelliJ before.

### What was tried (didn't work)
- `ide_sync_files` (full project sync) — no effect, index remains empty
- Closing and reopening without creating `modules.xml` — same empty result
- `ide_find_file` with various queries and scopes — all return zero

### Root cause
IntelliJ needs `.idea/modules.xml` to link the `.iml` module file to the project. Without it, the project opens as a shell with no content roots — the index has nothing to scan. `ide_open_project`'s trust-marking creates a minimal `.idea` configuration (vcs.xml, workspace.xml) but does NOT generate `modules.xml`. The `.iml` file at the project root defines the content roots but is orphaned without the module link.

### Fix
Create two files, then close and reopen the project:

**`.idea/modules.xml`:**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<project version="4">
  <component name="ProjectModuleManager">
    <modules>
      <module fileurl="file://$PROJECT_DIR$/project-name.iml"
              filepath="$PROJECT_DIR$/project-name.iml" />
    </modules>
  </component>
</project>
```

**`.idea/misc.xml`** (optional but recommended — sets project SDK):
```xml
<?xml version="1.0" encoding="UTF-8"?>
<project version="4">
  <component name="ExternalStorageConfigurationManager" enabled="true" />
  <component name="ProjectRootManager" version="2" languageLevel="JDK_26"
             project-jdk-name="homebrew-21" project-jdk-type="JavaSDK" />
</project>
```

Then:
```
ide_close_project(project_path)
ide_open_project(path, project_path=<other-open-project>)
```

The index populates on reopen — `ide_find_file` returns results immediately.

### Why this is non-obvious
Distinct from GE-20260629-0a3cb4 (TypeScript language support limitation where specific tools like `ide_file_structure` don't support TS). This is a module registration issue — the index is completely empty for ALL file types, not just TypeScript. The misleading signals are: (1) `ide_open_project` reports success, (2) `ide_index_status` shows indexing complete and not in dumb mode — both suggest everything is working when the project has zero content roots.
