## Symptom

After using `ide_insert_member` or `ide_replace_member` to modify a file, running `git add <file>` and `git commit` results in a commit that does not contain the IDE-written changes. The file reads correctly via `Read` or `cat`, but `git diff --staged` shows the old content. The changes appear as unstaged modifications after the commit.

## Context

IntelliJ MCP tools (`ide_insert_member`, `ide_replace_member`, `ide_edit_member`) modify files through IntelliJ's Document API, which may buffer writes to disk. When `git add` runs before the buffer is flushed, git stages the on-disk version (stale) rather than the in-memory version (current).

## Root cause

IntelliJ's Document API does not guarantee synchronous disk flush on tool completion. The MCP tool returns success when the in-memory document is modified, but the physical file may not yet be written. A subsequent `git add` reads the stale on-disk content.

## What was tried (didn't work)

1. Running `git add <directory>/` immediately after IDE tool calls — staged stale content
2. Reading the file with `Read` tool (confirmed content was correct) then running `git add` — still staged stale content because `Read` may use in-memory cache while git reads the filesystem

## Fix

Call `ide_sync_files` after IDE tool modifications and before any `git add`:

```
ide_sync_files()    // flushes all in-memory documents to disk
git add <files>
git commit -m "..."
```

Alternatively, add a brief delay or verify with `git diff` before committing to confirm the expected changes are staged.

## Why this is non-obvious

The IDE tools report success, the file content reads correctly via the Read tool, and `git status` shows the file as modified. Everything appears correct until the commit is inspected and found to be missing the changes. The failure is silent — no error at any step.
