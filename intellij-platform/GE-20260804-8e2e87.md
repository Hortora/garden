### Symptom

`ide_find_class`, `ide_find_file`, and `ide_find_symbol` return zero results for ALL queries — including `pom.xml`. `ide_project_status` shows the project as `open: true, mode: background`. `ide_index_status` reports `isDumbMode: false, isIndexing: false`. Everything looks healthy.

### Context

Occurs when a project was opened by the lifecycle manager (auto-open on `project_path`) but the Maven build model was never linked. The project directory is registered as an IntelliJ project, but no content roots or source roots exist — the index is empty.

### What was tried (didn't work)

- `ide_sync_files` — synced the entire project, but the index remained empty because there were no source roots to sync.
- `ide_set_project_mode` to `active` — switched mode but didn't trigger Maven linking.
- `ide_reload_project` — revealed the root cause: "Maven: skipped — build file found on disk but project is not linked in IntelliJ."

### Root cause

The Index MCP plugin's auto-open mechanism registers the project directory but does not automatically link the Maven build model. Without Maven linking, IntelliJ has no source roots, so the Java index is empty. All semantic search tools return zero results without error.

### Fix

Call `ide_import_modules` with the project path before any semantic search:

```java
ide_import_modules({"paths": ["/path/to/project"], "project_path": "/path/to/project"})
```

This links the Maven project, triggers dependency resolution, and populates the source roots. After this, `ide_find_class` and all other search tools work normally.

### Why this is non-obvious

The project appears healthy — `ide_project_status` shows it open and in background mode, `ide_index_status` shows no indexing in progress. There is no error message indicating the Maven project isn't linked. The zero-result responses look identical to "no matches found" rather than "index is empty." The diagnosis requires knowing to try `ide_reload_project` which reveals the "not linked" message, or to check source root count (which no MCP tool exposes directly).

### Alternatives considered

- Closing and reopening the project via `ide_close_project` + `ide_open_project` — would work but is slower and loses window position. `ide_import_modules` is the targeted fix.
