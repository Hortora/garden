### Symptom

`ide_create_file` with an absolute `file` path reports success but creates the file at a doubled path. For example:

```
project_path: /Users/dev/project
file: /Users/dev/project/src/main/java/com/example/MyClass.java
```

Creates the file at:
```
/Users/dev/project/Users/dev/project/src/main/java/com/example/MyClass.java
```

The tool reports `{"success": true}` with no warning. The file exists on disk at the wrong location and is invisible to Maven compilation — the class simply doesn't appear in the build output.

### Context

The `file` parameter is documented as "Path to the new file relative to project root. REQUIRED." but no validation rejects absolute paths. The tool silently concatenates `project_path + file`, producing a deeply nested wrong directory.

### What was tried (didn't work)

Passed the full absolute path assuming the tool would handle it. The file appeared to create successfully — the error was only discovered when Maven compilation failed with "cannot find symbol."

### Root cause

`ide_create_file` always treats the `file` parameter as relative to `project_path`. When an absolute path is passed, it becomes a path segment under the project root — `/project` + `/Users/dev/project/src/...` → `/project/Users/dev/project/src/...`.

### Fix

Always use relative paths with `ide_create_file`:

```
// Wrong — doubles the path:
file: /Users/dev/project/src/main/java/com/example/MyClass.java

// Correct — relative to project_path:
file: src/main/java/com/example/MyClass.java
```

After encountering this, check for and remove the wrongly-placed directory tree:
```bash
rm -rf /project-root/Users/
```

### Why this is non-obvious

The tool accepts absolute paths without error and reports success. The doubled directory structure is created silently. The failure only surfaces later during compilation — and the error message ("cannot find symbol") gives no hint that the file exists at a wrong path.
