### Symptom
Java compilation fails with "cannot find symbol" for classes whose import
statements were added via `ide_replace_text_in_file` moments earlier.

### Context
When using `ide_replace_text_in_file` to insert Java import statements into
a file that does not yet contain code referencing those classes, IntelliJ's
auto-reformat/optimize-imports runs as a side effect and removes the
"unused" imports silently. The tool reports success ("Replaced 1 occurrence")
but the imports are gone when the next compilation runs.

### Root cause
`ide_replace_text_in_file` triggers IntelliJ's post-edit pipeline which
includes import optimization. Imports with no referencing code in the file
body are classified as unused and removed — even though they were just added
intentionally for code that will be inserted in a subsequent tool call.

### Fix
Add imports AFTER inserting the code that references them, not before. Use
`ide_insert_member` or `ide_replace_text_in_file` to add the method/field
first, then add the import statements in a second operation. By then the
references exist and optimize-imports leaves them alone.

### Why this is non-obvious
`ide_replace_text_in_file` is a text replacement tool — you wouldn't expect
it to have semantic side effects like removing content it didn't touch. The
success message ("Replaced 1 occurrence") confirms the replacement happened,
giving no indication the imports were subsequently removed.
