### Symptom
Calling `ide_replace_member` to replace a method body results in the NEW method being inserted INSIDE the old method body, creating a nested method declaration that fails to compile:

```java
public boolean tryTransition(TaskStatus from, TaskStatus to) {
    public boolean tryTransition (TaskStatus from, TaskStatus to){
        if (from.isTerminal()) {return false;}
        return status.compareAndSet(from, to);
    }
}
```

The error is `illegal start of expression` — a nested method declaration in Java.

### Context
Happens consistently when using `ide_replace_member` on methods in the `casehub-engine-planning` module. The tool appears to insert the replacement content as the method body rather than replacing the entire method declaration.

### What was tried (didn't work)
- Calling `ide_replace_member` with the full method signature in the content — still inserts inside
- Calling `ide_replace_member` multiple times — same result each time

### Root cause
`ide_replace_member` replaces the method BODY (between `{` and `}`), not the entire method declaration. When the replacement content includes the method signature, it gets nested inside the existing declaration.

### Fix
Use `ide_edit_member` instead — it replaces the ENTIRE member declaration (modifiers, return type, name, parameters, and body). The content parameter should include the complete method signature:

```
ide_edit_member(file, class, member, content="public boolean tryTransition(...) { ... }")
```

`ide_edit_member` consistently produces the correct result where `ide_replace_member` duplicates.

### Why this is non-obvious
The tool names suggest symmetry — `replace` sounds like it should replace the whole thing. The actual distinction (body-only vs entire declaration) is not documented in the tool description. The resulting error (`illegal start of expression`) doesn't point toward the tool choice as the cause.
