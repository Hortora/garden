### Symptom

`ide_edit_member` or `ide_insert_member` times out (300s default), and the tool
reports an abort. The file appears unchanged — but it is not. The edit was
partially applied: content up to the edit point reflects the new code, but
everything after the edit point is deleted. Methods, fields, and closing braces
below the insertion are gone.

### Context

Happens when the MCP server is slow to respond (GC pause, background indexing,
large file). The tool call times out client-side, but the server-side write has
already started. The partial write is flushed to the VFS before the timeout
fires.

### What was tried (didn't work)

- Retrying the same edit — makes it worse (edits a now-truncated file)
- Using `ide_sync_files` to refresh — syncs the corrupted state, not the original
- Reading the file to check — shows truncated content, confirming the corruption

### Root cause

The MCP client aborts the tool call after the timeout, but the IntelliJ plugin's
Document API write has already executed (or is mid-execution). There is no
rollback mechanism — the write is not atomic.

### Fix

1. **Detect:** After any timeout on `ide_edit_member` or `ide_insert_member`, immediately read the file — if it's shorter than expected or missing methods, it's truncated.
2. **Recover:** `git checkout HEAD -- <file>` to restore from the last commit.
3. **Retry differently:** Use `ide_replace_text_in_file` with small, targeted search/replace patterns instead. This tool completes faster and has a smaller blast radius on timeout.

### Why this is non-obvious

The timeout error message says the operation was "aborted" — implying it didn't
happen. In reality, the write completed (or partially completed) and the abort
only affects the response delivery. The file is silently corrupted with no error
in the file content or git status.

### Alternatives considered

- Writing to `/tmp/` and copying — blocked by hooks that enforce IntelliJ-first editing
- Using `ide_edit_member` with very small edits — reduces but doesn't eliminate the risk
- Checking file length after every edit — too noisy for normal workflow
