## Symptom

After calling `ide_replace_member` on a method, Spotless or checkstyle reports a syntax error (`';' expected` or `illegal start of expression`) at the method declaration line. The file compiles in IntelliJ but fails Maven's formatter validation.

## Context

Using `ide_replace_member` to replace a method body (e.g. slimming down a class during extraction refactoring). The tool is called with the full method signature and body as content.

## What was tried (didn't work)

- Using `ide_replace_member` with correct method content — produces the error
- Reformatting with `ide_reformat_code` after — doesn't fix the structural duplication

## Root cause

`ide_replace_member` sometimes inserts the provided content as the method body rather than replacing the entire method declaration. This creates a nested duplicate: the original method signature wraps the new content (which also contains the method signature), producing:

```java
public Uni<Void> schedule(ScheduledJobRequest request) {
    public Uni<Void> schedule (ScheduledJobRequest request){
        // actual body here
    }
}
```

The outer method has no body of its own — just the inner duplicate. IntelliJ's PSI parser may tolerate this, but javac and Spotless reject it.

## Fix

Use `ide_edit_member` instead of `ide_replace_member` when replacing an entire method declaration (signature + body). `ide_edit_member` replaces the complete declaration from modifier through closing brace, avoiding the nesting issue:

```
ide_edit_member(file, class, member, content)  // replaces entire declaration — safe
ide_replace_member(file, class, member, content)  // replaces body only — may nest
```

If you must use `ide_replace_member`, always read the file back (`ide_read_file`) after the call and check for duplicate method signatures before proceeding.

## Why this is non-obvious

The tool returns `success: true` and the message says "Replaced body of method 'X'" — no indication that the content was wrapped. The file looks correct in IntelliJ (PSI tolerance). The error only surfaces when Maven runs Spotless or checkstyle, and the error message (`';' expected`) points at the duplicate signature line — not at the nesting structure.
