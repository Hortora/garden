### Symptom
Calling `ide_edit_member` with `member` set to the same name as the `class` parameter replaces the entire class body — not the constructor. The file is left with only the replacement content (e.g. a single constructor), all other fields, methods, and inner classes are destroyed.

### Context
When trying to replace a constructor of `ManorGoalEvaluator` (class name = `ManorGoalEvaluator`):
```json
{
  "class": "ManorGoalEvaluator",
  "member": "ManorGoalEvaluator",
  "content": "public ManorGoalEvaluator(...) { ... }"
}
```

The tool treats `member == class` as "replace the class declaration itself" rather than "replace the constructor."

### Root cause
`ide_edit_member` resolves the member to edit. When the member name matches the class name, it resolves to the class declaration rather than a constructor. The replacement content then overwrites the entire class body.

### Fix
For constructor modifications, use `ide_replace_text_in_file` with the constructor text as `searchText`:

```json
{
  "file": "src/main/java/.../MyClass.java",
  "searchText": "    public MyClass(Type1 a, Type2 b) {\n        ...\n    }",
  "replaceText": "    public MyClass(Type1 a, Type2 b, Type3 c) {\n        ...\n    }"
}
```

Or use `ide_insert_member` to add a new constructor overload rather than replacing the existing one.

### Why this is non-obvious
The tool reports success: `"Replaced class 'ManorGoalEvaluator' entirely"` — which sounds like it replaced a member within the class, not the class itself. The word "entirely" is the only hint. Recovery requires `git checkout -- <file>`.

### Alternatives considered
- Using `anchorParameterCount` to disambiguate — but the ambiguity is between member and class, not between overloaded members
