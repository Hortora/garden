## ide_replace_member on large method bodies hangs IntelliJ EDT

**Symptom:** `ide_replace_member` call on a `build()` method (~50 lines, with validation, field assignments, and conditional logic) causes IntelliJ to become unresponsive. After 90+ seconds: `IDE UI thread has been unresponsive for 90s — tool calls requiring the IDE are unavailable. Consider restarting the IDE.`

**Context:** Using IntelliJ MCP to replace the full body of `Binding.Builder.build()` in a Quarkus project. The replacement content was a complete rewrite of the method body (~40 lines of validation + field wiring). The method contained `instanceof` checks, conditional throws, and chained setter calls.

### What was tried (didn't work)

- Waiting for recovery — EDT stayed hung past 100s
- `ide_restart` — also failed because EDT was unresponsive
- Had to close and reopen IntelliJ manually

### Root cause

`ide_replace_member` operates on the PSI tree — it parses the new content, replaces the PSI subtree, and reformats. For large method bodies with complex expressions (especially those involving generic types, instanceof patterns, and string concatenation in throw statements), the PSI replacement + reformat operation can exceed the EDT timeout.

### Fix

Use `ide_replace_text_in_file` with a precise search/replace instead:

```
// Instead of replacing the entire build() method body:
ide_replace_text_in_file({
  file: "path/to/File.java",
  searchText: "      b.setPermissionIntent(this.permissionIntent);\n      return b;",
  replaceText: "      b.setPermissionIntent(this.permissionIntent);\n      b.setNewField(this.newField);\n      return b;"
})
```

This performs a string-level replacement without full PSI tree reconstruction — much faster and EDT-safe.

### Why this is non-obvious

`ide_replace_member` works fine for small-to-medium method bodies. The EDT hang only manifests with larger bodies, and the threshold is not documented. The error message suggests restarting the IDE rather than using a different tool.
