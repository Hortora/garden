### Symptom
`JdbcSQLSyntaxErrorException: Syntax error in SQL statement "CREATE TABLE ... id INT [*]AUTO_INCREMENT PRIMARY KEY"` — expected `GENERATED, ON UPDATE, SEQUENCE` etc.

### Context
H2 database with `jdbc:h2:mem:test;MODE=PostgreSQL` connection string. Creating tables with `INT AUTO_INCREMENT PRIMARY KEY` — standard H2 syntax that works without `MODE=PostgreSQL`.

### What was tried
Standard H2 DDL with `AUTO_INCREMENT` — parse error at the `AUTO_INCREMENT` keyword.

### Root cause
In PostgreSQL compatibility mode, H2 follows PostgreSQL syntax for identity columns. PostgreSQL uses `GENERATED BY DEFAULT AS IDENTITY`, not MySQL-style `AUTO_INCREMENT`.

### Fix
```sql
CREATE TABLE my_table (
    id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(255) NOT NULL
)
```

### Why this is non-obvious
`AUTO_INCREMENT` is the most common H2 tutorial syntax and works in default mode. Switching to `MODE=PostgreSQL` (common in Quarkus test setups) silently changes the DDL grammar without a clear migration guide.
