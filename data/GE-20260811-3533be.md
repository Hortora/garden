### Symptom
Test setup that creates a SQLite database, sets `PRAGMA journal_mode=WAL`, creates tables, and inserts seed data throws: `[SQLITE_BUSY] The database file is locked (cannot commit transaction - SQL statements in progress)`.

### Context
JUnit test `@BeforeEach` method using `SQLiteDataSource` with a temp file database. The connection is in autocommit mode (default). The sequence is: `PRAGMA journal_mode=WAL` → `PRAGMA foreign_keys=ON` → `CREATE TABLE` statements → `INSERT` statements.

### What was tried (didn't work)
Running all statements on a single connection with autocommit=true. The WAL pragma returns a result set that is not consumed, holding an implicit statement open. Subsequent DDL triggers autocommit attempts that conflict with the open statement.

### Root cause
`PRAGMA journal_mode=WAL` returns a result set (the new journal mode). In autocommit mode, sqlite-jdbc tries to commit after each statement. The unconsumed result set from the PRAGMA holds an internal lock that conflicts with the autocommit on subsequent DDL statements.

### Fix
Use explicit transaction control:

```java
try (var conn = ds.getConnection()) {
    conn.setAutoCommit(false);
    createSchema(conn);   // DDL
    seedData(conn);       // DML
    conn.commit();
}
```

Or separate the PRAGMA into its own connection that is closed before schema creation.

### Why this is non-obvious
The BUSY error message ("cannot commit transaction - SQL statements in progress") suggests a concurrent access problem, but this occurs on a single connection in a single-threaded test. The actual cause — an unconsumed PRAGMA result set holding a lock — is not intuitive from the error message.
