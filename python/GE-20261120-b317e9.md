# An environment dict built at module import bypasses per-test monkeypatch.setenv, so subprocess tests hit real resources

## Symptom

The suite isolates a production resource by pointing an environment variable at a temp path in an autouse fixture:

```python
@pytest.fixture(autouse=True)
def _isolate_db(tmp_path, monkeypatch):
    monkeypatch.setenv("APP_DB", str(tmp_path / "test.db"))
```

Rows with pytest temp paths still appear in the real database.

## Context

One test module defines, at import:

```python
GIT_ENV = {**os.environ, "GIT_AUTHOR_NAME": "Test", ...}
```

and runs its subprocesses with `env=GIT_ENV`.

## Root cause

Modules are imported during collection, before any fixture runs. `GIT_ENV` is a snapshot of `os.environ` taken then, without `APP_DB`. The fixture later changes `os.environ`, but subprocesses started with `env=GIT_ENV` get the snapshot, so the code under test falls back to its default: the real resource. Wider-scoped fixtures that run before the function-scoped one have the same hole.

## Fix

Set a session-wide default at the top of `conftest.py`, which is imported before test modules. The per-test fixture can still override it:

```python
# conftest.py, module level
SESSION_DB = str(Path(tempfile.mkdtemp(prefix="app-test-db-")) / "db.sqlite")
os.environ["APP_DB"] = SESSION_DB
```

Pin it with a test that inspects the snapshot the module really uses:

```python
def test_env_copied_at_import_is_isolated():
    from tests import test_promotion
    assert test_promotion.GIT_ENV["APP_DB"] != app.DEFAULT_DB
```

## Why this is non-obvious

The autouse fixture demonstrably works for every in-process test and for subprocesses that inherit the environment. Only the modules that pass an explicit `env=` built at import escape, and nothing fails: the tests pass while writing to production.

### Alternatives considered

- A test that sets the variable itself and checks the real database is untouched: it cannot fail, because it supplies the isolation it claims to verify.
- Refusing to write when the path looks like a pytest temp directory: hides the leak instead of closing it.
