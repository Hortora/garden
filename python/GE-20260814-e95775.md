### Context

A lifecycle state machine defines transitions with named effects
(e.g. `create_branch`, `wip_commit`, `push_stack`). The protocol
executor looks up each effect name in a dispatch table and calls it.
Testing the protocol requires verifying effect ordering, state
commitment, and transient-state auto-fire — without needing real git
repos or script functions.

### Technique

Make the dispatch table an injectable parameter with a production
default:

```python
def run_transition(event, ctx, dispatch=None):
    if dispatch is None:
        dispatch = EFFECT_DISPATCH  # production table
    result = lifecycle.transition(ctx.meta_path, event)
    for effect_name in result.effects:
        dispatch[effect_name](ctx)
    lifecycle.commit_transition(ctx.meta_path, result)
```

Tests build a mock dispatch dynamically from the transition table:

```python
from unittest.mock import MagicMock

def _mock_dispatch():
    all_effects = set()
    for (_, effects, post_effects) in TRANSITION_TABLE.values():
        all_effects.update(effects)
        all_effects.update(post_effects)
    return {name: MagicMock(name=name) for name in all_effects}
```

Protocol tests then verify ordering, call counts, and state without
any I/O — running in <0.1s.

### Why this is non-obvious

The natural instinct is to mock individual script imports or use
`unittest.mock.patch` on each function. The dispatch-table-as-parameter
approach is simpler, faster, and cleanly separates "does the protocol
work?" from "does each script work?" Two concerns, two test suites.
