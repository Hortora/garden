### Symptom
MSC GlobalFeatureVector `.npz` files contain scipy CSC sparse matrices with ~1121 features per timestep, but no documentation describes the layout. Directory names like `Terran_vs_Zerg/Zerg/` suggest Zerg player data but actually contain Terran player data.

### Context
The MSC dataset (36k SC2 replays) stores pre-extracted game state as sparse matrices. The `game_state.py` in the MSC repo defines `to_vector()` which concatenates feature blocks, but the actual `.npz` files include 15 additional features not in `to_vector()`.

### Root cause
The feature vector layout is: `[reward(1), action(1), score_cumulative(13), scalars(12), alerts(N), upgrades(N), research(N), friendly_units(N*6), enemy_units(M*6)]`. The extra 15 features (reward + action + 13 score fields) precede the 12 normalized scalars that `to_vector()` documents.

The directory naming follows the MSC parsing code's `race` variable which is the player's actual race, but the stat file used for encoding determines which unit types can appear. The Zerg stat has 119 unit types (all races) while Terran (56) and Protoss (41) stats only encode their own race's units. This causes:
- `TvZ/Zerg/` files: uses Zerg stat → can encode Terran units → shows Terran player data
- `TvZ/Terran/` files: uses Terran stat → cannot encode Zerg units → enemy section always empty
- Cross-race matchups via non-Zerg stats lose all enemy unit data silently

### Fix
Compute offsets empirically: `units_offset = 15 + 12 + len(stat['alert']) + len(stat['upgrades']) + len(stat['research_id'])`. Each unit type occupies 6 features: `[total_num, finished_num, building_num, max_progress, min_progress, avg_progress]`, all normalized by `stat['max_unit_num']`. Only the Zerg-stat directories (TvZ/Zerg, PvZ/Zerg, ZvZ/Zerg) plus same-race mirrors (TvT/Terran, PvP/Protoss) produce usable unit data.

### Why this is non-obvious
The MSC paper describes the dataset but not the binary format. The `game_state.py` code in the repo produces a DIFFERENT layout than what's in the downloaded files (missing 15 features). The directory naming convention is inverted from what a reader would assume. Only empirical probing of actual data values reveals the true structure.

### Why this fix
Empirical reverse-engineering was the only viable path — the code doesn't match the data, and no schema documentation exists. The offset formula generalizes across all matchup configurations.
