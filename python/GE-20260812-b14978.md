### Symptom
Testing Textual widgets requires `async with app.run_test()` which is slow (~0.5s per test) and requires mocking the full app context. Simple assertions about widget state and rendering shouldn't need this overhead.

### Context
Building a TUI with multiple widgets (header, action panel, content area, footer). Each widget has state (selected index, action list, mode) and rendering logic. Need fast feedback during TDD.

### Fix
Two-tier testing pattern:

**Tier 1 — Unit tests (no Textual infrastructure):**
Store state as plain instance variables instead of `reactive` properties. Expose a `_build_display() -> str` method that returns the rendered text.

```python
class ActionPanel(Widget):
    _actions: list[str] = []
    _selected_index: int = 0
    _enabled: bool = True

    def _build_display(self) -> str:
        lines = ["Actions", ""]
        for i, action in enumerate(self._actions):
            cursor = "▸ " if i == self._selected_index else "  "
            lines.append(f"{cursor}{action}")
        return "\n".join(lines)

    def render(self) -> str:
        return self._build_display()

    def move_down(self) -> None:
        if self._enabled and self._selected_index < len(self._actions) - 1:
            self._selected_index += 1
```

Unit tests instantiate the widget directly and call `_build_display()` or `move_down()`:
```python
def test_move_down():
    panel = ActionPanel()
    panel._actions = ["start", "status"]
    panel._selected_index = 0
    panel.move_down()
    assert panel._selected_index == 1
```

**Tier 2 — Integration tests (full Textual test framework):**
Use `async with app.run_test() as pilot` with mocked backend functions to verify keyboard navigation, view composition, and event routing.

### Why this is non-obvious
The Textual docs and examples use `reactive` properties extensively. These properties require a mounted widget to function (they trigger watchers and refresh calls). The natural approach — `reactive` for everything — forces every test through the full app test harness. The `_build_display()` pattern gives you 0.01s unit tests alongside 0.5s integration tests.
