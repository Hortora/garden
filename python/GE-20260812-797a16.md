### Symptom
`TypeError: SorediumApp._dispatch_action() takes 2 positional arguments but 4 were given` — appears only when a key is pressed, not at class definition or app startup.

### Context
Defining a method named `_dispatch_action` on a `textual.app.App` subclass. The app starts fine, mounts widgets, renders correctly. The error only surfaces when a key binding fires.

### Root cause
Textual's `App` class has an internal method `_dispatch_action(self, target, action_name, params)` used by the key binding system. Defining your own `_dispatch_action(self, action)` silently overrides it. When Textual calls `self._dispatch_action(action_target, action_name, params)`, it hits your method with the wrong signature.

### Fix
Use a different method name — e.g. `_handle_action`. Avoid `_dispatch_*` and `_check_*` prefixes on Textual App subclasses; Textual has many internal methods with these prefixes that are not part of the public API.

### Why this is non-obvious
No warning at definition time. The app starts and renders correctly. Python doesn't warn about overriding methods with different signatures. The error message points to the call site inside Textual internals, not to the conflicting method definition.

### Alternatives considered
- Prefixing with `__` (name mangling) — works but makes subclassing harder
- Using a standalone function instead of a method — breaks the App pattern
