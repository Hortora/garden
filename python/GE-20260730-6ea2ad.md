### Symptom
`torch.onnx.export()` fails with `ModuleNotFoundError: No module named 'onnxscript'` despite torch and onnx being installed.

### Context
When exporting a PyTorch model to ONNX in a clean venv with `torch>=2.0.0` and `onnx>=1.15.0` installed. PyTorch 2.13 switched to the dynamo-based ONNX exporter internally, which depends on `onnxscript` — but `onnxscript` is not listed in torch's `install_requires`.

### Root cause
PyTorch's new ONNX export path (`torch.onnx._internal.exporter`) imports `onnxscript` at the top of `_core.py`. This is a hard import, not a lazy one. The package is not declared as a dependency of torch.

### Fix
Add `onnxscript>=0.1.0` to your requirements.txt alongside torch and onnx:

```
torch>=2.0.0
onnx>=1.15.0
onnxscript>=0.1.0
```

### Why this is non-obvious
The error appears at export time, not at import time. `import torch` succeeds, `import torch.onnx` succeeds — the failure only surfaces inside `torch.onnx.export()` when the internal exporter path resolves. The missing dependency is not mentioned in PyTorch's ONNX export documentation.
