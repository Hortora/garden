### Symptom
Path resolution silently falls through to a default/fallback path when a symlink exists but its target doesn't. No error, no warning — the symlink is treated as if it doesn't exist at all.

### Context
`Path.exists()` follows the symlink and checks if the TARGET exists. A symlink to `/workspace/engine` where `/workspace/` exists but `/workspace/engine/` doesn't returns `False` from `.exists()` even though `.is_symlink()` returns `True`. Code that uses `if path.exists()` as the gate silently skips the symlink entirely.

### What was tried (didn't work)
Using `Path.exists()` as the sole check for symlink presence. This works when targets exist but silently breaks when targets are partial paths (pointing to a subdirectory of a git repo that doesn't exist).

### Root cause
POSIX semantics: `stat()` (which `.exists()` uses) follows symlinks and checks the final target. `lstat()` (which `.is_symlink()` uses) checks the symlink itself. These are different operations with different answers for broken symlinks.

### Fix
Check `is_symlink()` first to detect the symlink exists, then resolve the target separately:

```python
if symlink.exists():
    return str(symlink.resolve())  # target exists — normal path
if symlink.is_symlink():
    # Symlink exists but target doesn't — walk up to find nearest git root
    raw_target = Path(os.readlink(symlink))
    if not raw_target.is_absolute():
        raw_target = (symlink.parent / raw_target).resolve()
    candidate = raw_target
    while candidate != candidate.parent:
        if candidate.is_dir() and (candidate / ".git").exists():
            return str(candidate)
        candidate = candidate.parent
```

### Why this is non-obvious
`.exists()` reads as "does this path exist?" — the natural assumption is that a symlink at that path means yes. The distinction between "the symlink exists" and "the symlink's target exists" is invisible in most code until it breaks.

### Why this fix
Walking up from the broken target to find the nearest git root handles the common case where a symlink points to a subdirectory of a repo that doesn't exist — the repo itself is the intended target.

### Alternatives considered
- Always requiring exact symlink targets — too fragile, breaks when workspace layouts change
- Removing broken symlinks and falling back — loses the information that a workspace was configured
