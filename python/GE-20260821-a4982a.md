### The technique
Before merging multi-source training data, check each source for systematically zeroed feature blocks using `np.abs(block).sum(axis=per_sample_dims) == 0`. This reveals asymmetric feature coverage across sources that z-score normalization will hide.

### Context
Three SC2 replay data sources merged for strategy classification: SC2EGSet had both player and opponent features, MSC had player features only (opponent block all-zeros), Spawning Tool had opponent features only (player block all-zeros — a bug). Without this check, the merged dataset appeared normal after normalization.

### What developers would normally do
Merge sources, normalize, train, evaluate. If accuracy is low, investigate architecture or hyperparameters. Feature coverage asymmetry across sources is invisible after normalization because z-score maps zero-blocks to centered values near 0 (using the cross-source mean/std).

### The fix
```python
from evaluation.strategy_classifier.sc2egset_extractor import N_FEATURES_PER_PLAYER as N

for source in ["sc2egset", "spawningtool", "msc"]:
    d = np.load(f"data/{source}/vs_terran/train.npz")
    t = d["temporal"]  # (samples, windows, features) — BEFORE normalization
    n_samples = len(t)
    player_pop = int((np.abs(t[:, :, :N]).sum(axis=(1, 2)) > 0).sum())
    opp_pop = int((np.abs(t[:, :, N:2*N]).sum(axis=(1, 2)) > 0).sum())
    print(f"{source}: {n_samples} samples "
          f"(player: {player_pop}/{n_samples}, opponent: {opp_pop}/{n_samples})")
```

Output that revealed the Spawning Tool bug:
```
sc2egset:     3458 samples (player: 3458/3458, opponent: 3022/3458)
spawningtool: 2252 samples (player: 0/2252,    opponent: 1970/2252)  ← BUG
msc:          2772 samples (player: 2772/2772, opponent: 0/2772)
```

### Why this is non-obvious
After z-score normalization (`(x - mean) / std`), zero-blocks map to `(-mean / std)` — non-zero values that look like real features. The asymmetry is completely invisible in the normalized data. The check MUST happen on raw pre-normalization data. Additionally, the results should drive explicit availability flags (`has_player`, `has_opponent`) included as model inputs, so gating mechanisms can learn to handle missing modalities.
