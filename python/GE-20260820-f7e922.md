### Symptom
Training a CNN classifier on multi-source data produces NaN loss or collapses to majority-class prediction (99%+ accuracy on one class, 0% on all others). Individual sources train fine; only the combined dataset fails.

### Context
Mixing training data from sources with different feature completeness — e.g., Source A has full features, Source B has zeros for half the feature dimensions (partial observations from a different data collection method).

### Root cause
BatchNorm1d computes running mean and variance across the batch dimension. When a batch contains a mix of zero-feature samples (where an entire feature block is zeros) and full-feature samples, the running statistics are pulled toward zero. This distorts normalization for non-zero samples, producing either NaN (division by near-zero variance) or uniform outputs that erase class-discriminative information.

### Fix

**Option 1 — Replace BatchNorm with LayerNorm:**
```python
# LayerNorm normalizes per-sample across features, not per-batch
self.norm1 = nn.LayerNorm(channels)  # instead of nn.BatchNorm1d(channels)
```

**Option 2 — Separate feature branches before concatenation:**
Process each feature block through its own BatchNorm before concatenating, so zero blocks don't contaminate non-zero block statistics.

**Option 3 — Random modality dropout (complementary):**
During training, randomly zero out feature blocks (p=0.2) even for full-feature samples and append binary availability flags. This teaches the model to handle missing features, but does NOT fix the BatchNorm corruption itself — combine with Option 1 or 2.

### Why this is non-obvious
BatchNorm is standard in CNN architectures and works perfectly with homogeneous data. The failure only manifests when mixing heterogeneous sources — a scenario that doesn't arise during single-source development and testing. The NaN/collapse symptom points toward learning rate or data quality issues, not normalization layer statistics.
