### Symptom

Code that constructs `Path(url.strip())` from a remote URL and checks `is_dir()` silently treats empty URLs as valid directories — operations redirect to the current working directory instead of failing.

### Context

When parsing git remote URLs or any external string that might be empty, `Path("")` does not raise an error. Instead it behaves identically to `Path(".")` — it resolves to the CWD. Any subsequent `is_dir()`, `exists()`, or `resolve()` call succeeds, making the empty input invisible to validation logic.

### Root cause

Python's `pathlib.Path("")` is equivalent to `Path(".")`. The empty string is a valid POSIX path that refers to the current directory. `Path("").resolve()` returns the absolute CWD. `Path("").is_dir()` returns `True`.

### Fix

Always guard `Path()` construction from external strings with an emptiness check:

```python
# Wrong — empty url silently becomes CWD
if rc == 0:
    origin_path = Path(url.strip())
    if origin_path.is_dir():
        return origin_path.resolve()

# Right — reject empty strings before constructing Path
if rc == 0 and url.strip():
    origin_path = Path(url.strip())
    if origin_path.is_dir():
        return origin_path.resolve()
```

### Why this is non-obvious

Developers expect `Path("")` to be invalid or to raise an error. The POSIX semantics where empty string equals current directory are not intuitive, and `pathlib` does not warn or document this prominently. The failure mode is silent redirection to CWD, which can pass validation checks and produce correct-looking but wrong results.
