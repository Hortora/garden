### Symptom
Model trains with phantom output classes (zero training samples, max focal loss weight). Per-class evaluation shows wrong class names mapped to wrong accuracy numbers. Overall accuracy drops because model capacity is wasted on dead output neurons.

### Context
Multi-class classifier with a consolidation step that merges rare classes into parent classes (e.g., AIR_SUPERIORITY → MACRO_ECONOMY). The consolidation happens in the normalize/merge pipeline and remaps labels to contiguous indices. The training pipeline reads the original class list from a config file, unaware of the consolidation.

### What was tried (didn't work)
Training with the original 8-class config when data only had 5 effective classes after consolidation. Model created 3 phantom output neurons with max focal loss weight (weight 5.0) and zero samples. Accuracy dropped from expected ~55% to 48%.

### Root cause
Two pipeline stages disagree on the class list. The normalize step consolidates rare classes and remaps labels to contiguous indices (0-4), but the training step reads `archetypes_for_matchup()` from the original config which returns 8 classes. Labels 5-7 never appear in training data but get maximum class weight in focal loss.

### Fix
Save the post-consolidation class list as metadata alongside the normalized data:
```python
# In normalize.py — after consolidation
with open(matchup_dir / "classes.json", "w") as f:
    json.dump(final_archetypes, f)

# In run_pipeline.py — read actual classes
classes_path = matchup_dir / "classes.json"
if classes_path.exists():
    with open(classes_path) as f:
        archetypes = json.load(f)
else:
    archetypes = archetypes_for_matchup(matchup)
num_classes = len(archetypes)
```
Also compact labels to remove zero-sample classes (e.g., PROXY with 0 samples) by remapping present labels to contiguous indices.

### Why this is non-obvious
The pipeline stages are in separate files and the mismatch is silent — the model trains without errors, just with degraded accuracy. The class weights computation masks the problem by capping zero-count class weights at 5.0 (via `np.maximum(counts, 1.0)`). The evaluation prints wrong class names but correct accuracy numbers, making it hard to notice.
