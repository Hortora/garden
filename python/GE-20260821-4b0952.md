### The technique
When a classifier's overall accuracy plateaus despite architecture changes, compute the full confusion matrix and identify the top 3 confusion pairs by absolute count before any further tuning. The dominant confusion pair tells you whether the problem is architecture, features, or labels.

### Context
Strategy classifier stuck at 53% on vs_terran. Five architecture changes were tried (dual encoder, attention, hierarchical heads, label smoothing, feature projection) — none moved accuracy more than ±2pp. The confusion matrix immediately showed MECH_PUSH↔BIO_TIMING accounted for 20.9% of all test errors, pointing directly to a missing feature (upgrade timing), not an architecture gap.

### What developers would normally do
When accuracy plateaus, try hyperparameter sweeps, learning rate schedules, architecture changes, or more data. These are expensive and don't address data-level bottlenecks.

### The fix
```python
from collections import Counter
preds = logits.argmax(dim=-1)
confusion_pairs = Counter()
for pred, true in zip(preds.tolist(), labels.tolist()):
    if pred != true:
        confusion_pairs[(archetypes[true], archetypes[pred])] += 1

for (true, pred), count in confusion_pairs.most_common(5):
    pct = count / len(labels) * 100
    print(f"  {true} → {pred}: {count} ({pct:.1f}% of total)")
```

The dominant pair tells you:
- **Same group confused** (e.g., MECH_PUSH↔BIO_TIMING) → missing discriminative feature, not architecture
- **Unrelated classes confused** → label noise or data quality issue
- **One class absorbs others** (attractor) → class imbalance or labelling rule priority bug

### Why this is non-obvious
Architecture changes feel productive — each one is a week of work with measurable (if small) changes. The confusion matrix takes 10 lines of code and 10 seconds to compute, but is often skipped because "we already know per-class accuracy." Per-class accuracy shows WHICH classes are bad; the confusion matrix shows WHERE the errors go, which is the actionable diagnostic.
