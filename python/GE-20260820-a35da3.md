### The technique
When a classifier is trained on data from multiple sources with different feature availability, evaluate accuracy PER SOURCE in addition to the overall confusion matrix. This reveals whether accuracy problems are architectural (model can't learn), data-quality driven (one source has bad labels), or feature-availability driven (one source lacks the discriminative features).

### Context
Strategy classifier trained on 3 sources: SC2EGSet (both feature blocks), SpawningTool (opponent only), MSC (player only). Overall accuracy 51.4% on vs_terran. Confusion matrix showed MECH_PUSH and BANSHEE_HARASS heavily confused with BIO_TIMING, but didn't explain WHY.

### What developers would normally do
Look at the confusion matrix and per-class accuracy, then adjust architecture or hyperparameters. This misses the fact that one data source might be responsible for most errors.

### The fix
After training, evaluate the model separately on each source's test data:

```python
for source in ["sc2egset", "spawningtool", "msc"]:
    source_samples = load_and_normalize(source, matchup)
    _, acc, logits, labels = evaluate(model, DataLoader(source_samples))
    print(f"{source}: {acc:.1%}")
    for i, name in enumerate(archetypes):
        mask = labels == i
        if mask.sum() > 0:
            print(f"  {name}: {(preds[mask] == i).float().mean():.1%}")
```

In this case, the breakdown revealed:
- SC2EGSet (both modalities): 54.3%
- SpawningTool (opponent only): 58.2% — opponent features are the primary signal
- MSC (player only): **42.3%** — player features are an indirect proxy

MSC contributed 33% of test samples at 42.3%, dragging overall accuracy. MECH_PUSH was 67.6% on SpawningTool (direct signal) but 10.1% on MSC (indirect proxy). This shifted the entire improvement strategy from architecture tuning to modality-aware training.

### Why this is non-obvious
The overall confusion matrix shows what's confused but not why. Per-class accuracy shows which classes struggle but not which data source causes the struggle. Per-source breakdown is the diagnostic that connects feature availability to classification performance — without it, you waste time on architectural changes when the problem is data heterogeneity.
