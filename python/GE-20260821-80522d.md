### Symptom
Model accuracy drops to near-random (1.6% on 5 classes) with pathological temperature calibration (-14.7). Training loss decreases normally — no NaN, no divergence, no error signal. Only visible on test evaluation.

### Context
Merging 3 data sources for a strategy classifier: SC2EGSet (41% of data, both feature blocks populated), Spawning Tool (27%, both populated), MSC (32%, opponent feature block all-zeros). After re-ingesting MSC without a cap, MSC grew to 90% of combined data. The model silently collapsed.

### Root cause
When one source dominates at 90% and has an entire feature block zeroed out, the model optimizes for the majority case: ignore the opponent feature block entirely. The dual-encoder architecture's gating mechanism learns to shut down the opponent encoder because 90% of training signal says "opponent features are noise." The 10% of samples with real opponent features can't overcome this.

Temperature calibration going negative (-14.7) is the smoking gun — it means the model's logits have reversed polarity, producing confidently wrong predictions.

### Fix
Cap each source to balanced proportions before merging:
```python
ingest_msc(max_replays_per_source=700)  # ~3k samples, matching other sources
```

Pre-merge checks:
```python
for source in sources:
    d = np.load(f"data/{source}/train.npz")
    n = len(d["labels"])
    player_pop = (np.abs(d["temporal"][:, :, :N_PLAYER]).sum(axis=(1,2)) > 0).sum()
    opp_pop = (np.abs(d["temporal"][:, :, N_PLAYER:2*N_PLAYER]).sum(axis=(1,2)) > 0).sum()
    print(f"{source}: {n} samples, player: {player_pop}/{n}, opponent: {opp_pop}/{n}")
```

### Why this is non-obvious
Training loss decreases normally — the model IS learning, just learning the wrong thing (ignoring a feature block). Standard training metrics (loss curve, validation accuracy during training) don't flag the problem. The pathological temperature is the only external signal, and it's easy to attribute to overfitting rather than data composition.
