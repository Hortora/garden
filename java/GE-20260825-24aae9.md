### Symptom
`when(mock.id()).thenReturn("expected")` on a mocked concrete class returns `null` instead of
the stubbed value. The mock setup compiles and runs without error — the stub is silently ignored.

### Context
`PlanItem` is a concrete class implementing `TaskDescriptor` interface. `id()` is declared in
`TaskDescriptor` and overridden in `PlanItem` (returns a private field). When `PlanItem` is
mocked via `mock(PlanItem.class)`, calling `id()` returns null instead of the stubbed value.

### What was tried (didn't work)
- `when(planItem.id()).thenReturn(PLAN_ITEM_ID)` — standard Mockito stub, silently returned null
- Verified the stub was set before the method call — still null

### Root cause
Mockito's inline mock maker may fail to intercept `@Override` methods on concrete classes where
the method is inherited from an interface, particularly when the concrete class uses
`AtomicReference` fields. The exact trigger is unclear — it may be related to the class
structure or JVM version.

### Fix
Use a real instance instead of a mock. Create the object via its factory method and transition
it to the desired state:

```java
PlanItem item = PlanItem.create(BINDING_NAME, null, 0);
item.tryMarkDispatching();
// item.id() now returns a real UUID-based ID
```

### Why this is non-obvious
The mock setup follows standard Mockito patterns and produces no errors. The stub appears to
be correctly configured. The failure mode is silent — `null` is returned with no warning.
