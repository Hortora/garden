### Behaviour
`doc.textBetween(start, end)` returns text with `\n` characters inserted at boundaries between inline nodes within a paragraph. These `\n` characters do NOT correspond to visual line breaks or `<br>` elements in the rendered DOM.

### Example
A paragraph rendered as:
> The new component model uses a *shared bridge interface* (`EditableText`) that enables programmatic editing across different editor engines.

Returns from `textBetween`:
```
"The new component model uses a shared bridge interface (EditableText)\nthat enables programmatic editing across different editor engines."
```

The `\n` after "EditableText)" is a node boundary separator — the emphasis and code marks create separate text nodes. There is no `<br>` tag in the DOM, and the text renders as one continuous paragraph.

### Impact
Code that splits `textBetween` output on `\n` to find "lines" gets wrong results — it finds node boundaries instead of visual line breaks. This breaks line-level operations like `highlightLine` when they try to scope to one line by splitting on `\n`.

### Why this matters
`textBetween` is the primary API for extracting text content from a ProseMirror document. Its default separator behaviour is not prominently documented, and the `\n` characters it inserts are easily confused with actual line breaks — especially in markdown-first editors where `\n` has structural meaning.
