## Shadow-aware CSS injection with per-root WeakMap ref-counting

### Symptom

Web component library injects CSS via `document.head.appendChild(style)`.
Components render correctly in light DOM but appear completely unstyled
(blank rectangles, invisible edges, unstyled controls) when hosted inside
a LitElement shadow root.

### Context

Any web component library that injects shared CSS (isolation resets,
theme overrides, control styles) into `document.head` will break when
consumed inside another component's shadow root. The shadow boundary
blocks `document.head` styles from reaching the component. This commonly
manifests when a library component is wrapped by an application-level
LitElement that uses shadow DOM by default.

### Root cause

`document.head` styles cannot cross shadow DOM boundaries. The library
assumes all consumers render in light DOM or at the document level.

### Fix

Accept an optional `host` element in the injection function. Use
`host.getRootNode()` to detect the nearest shadow boundary:

```typescript
interface StyleEntry {
  count: number;
  style: HTMLStyleElement;
}

const styleRoots = new WeakMap<Document | ShadowRoot, StyleEntry>();

function getStyleRoot(host?: HTMLElement): Document | ShadowRoot {
  if (host) {
    const root = host.getRootNode();
    if (root instanceof ShadowRoot) return root;
  }
  return document;
}

export function injectStyles(host?: HTMLElement): HTMLStyleElement {
  const root = getStyleRoot(host);
  const target = root instanceof ShadowRoot ? root : document.head;
  const entry = styleRoots.get(root);

  if (entry) {
    entry.count++;
    entry.style.textContent = getCSS();
    return entry.style;
  }

  const style = document.createElement('style');
  style.textContent = getCSS();
  target.appendChild(style);
  styleRoots.set(root, { count: 1, style });
  return style;
}

export function releaseStyles(host?: HTMLElement): void {
  const root = getStyleRoot(host);
  const entry = styleRoots.get(root);
  if (!entry) return;
  entry.count--;
  if (entry.count === 0) {
    entry.style.remove();
    styleRoots.delete(root);
  }
}
```

Key properties:
- **Per-root ref-counting** via `WeakMap` — multiple components in the
  same shadow root share one style element; components in different
  shadow roots get independent copies
- **Backward compatible** — callers that don't pass `host` get the
  existing `document.head` behaviour
- **No memory leaks** — `WeakMap` allows garbage collection when shadow
  roots are detached

### Why this is non-obvious

The naive fix is to inject styles into both `document.head` and the shadow
root. This duplicates memory and creates confusing ownership semantics
during cleanup. The per-root `WeakMap` approach handles arbitrary nesting
depth, multiple independent shadow roots, and cleanup — all without
global mutable state.

### Alternatives considered

- **Duplicate injection** (both document.head and shadow root) — wastes
  memory, confusing cleanup semantics
- **Constructable Stylesheets** (`adoptedStyleSheets`) — cleaner API but
  not universally supported and requires different CSS generation pipeline
- **CSS `@layer`** — does not cross shadow boundaries either; tested and
  rejected (see GE-20260802-01)
