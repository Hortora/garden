### Symptom

`json-schema-to-typescript` generates a TypeScript interface where the index signature type conflicts with a named property type. TypeScript error TS2411: `Property 'doneWhen' of type 'string' is not assignable to 'string' index type 'GoalExpression'`.

### Context

A JSON Schema type (e.g. `CaseCompletion`) has both a named property (`doneWhen: string`) and `additionalProperties: { $ref: "#/$defs/GoalExpression" }`. The generated TypeScript has:

```typescript
export interface CaseCompletion {
  doneWhen?: string;
  [k: string]: GoalExpression | undefined;  // ← conflicts with doneWhen
}
```

The index signature requires ALL properties (including `doneWhen`) to be `GoalExpression | undefined`, but `doneWhen` is `string`.

### Root cause

`json-schema-to-typescript` generates the index signature directly from `additionalProperties` without considering that named properties of other types exist on the same interface. Under `exactOptionalPropertyTypes: true`, TypeScript enforces strict index signature compatibility.

### Fix

Post-process the generated output in the generator script to widen the index signature:

```typescript
const fixed = ts.replace(
  /(\s+\[k: string\]: GoalExpression \| undefined;)/,
  '  [k: string]: GoalExpression | string | undefined;',
);
```

This makes the index signature accept both the `GoalExpression` additional properties and the `string` named property.

### Why this is non-obvious

The JSON Schema itself is valid — `additionalProperties` with `$ref` alongside named properties is a standard pattern. The conflict only surfaces when the generated TypeScript is compiled under strict settings. The error message (TS2411) points at the named property, not the index signature, making it unclear which side to fix.
