### Symptom
Edit a TypeScript component in `src/main/webui/src/`, save, refresh browser — old JavaScript is still served. The change is invisible until the server is manually restarted.

### Context
Quarkus dev mode with Quinoa for frontend bundling (esbuild via yarn). Backend Java changes hot-reload correctly. Frontend TypeScript changes do not trigger a Quinoa rebuild.

### Root cause
Quinoa runs `yarn run build` during the initial Quarkus build phase. In dev mode, Quarkus watches Java source changes but does not watch the webui directory for TypeScript changes. The compiled frontend bundle in `target/quinoa/build/` is stale.

Clearing `target/quinoa/` alone is insufficient — Quarkus caches the built resources in `target/classes/META-INF/resources/`.

### Fix
Kill the dev server, clean both caches, and restart:
```bash
# Kill the running server
lsof -ti :8091 | xargs kill
# Clear both caches
rm -rf target/quinoa target/classes/META-INF/resources
# Restart — forces full Quinoa rebuild
mvn quarkus:dev -Dquarkus.http.port=8091
```

For frequent frontend iteration, consider running esbuild in watch mode separately.

### Why this is non-obvious
Quarkus dev mode's "live reload" implies all source changes are picked up automatically. The Java side works this way. The frontend side appears to work (no errors) but silently serves stale bundles — there's no warning that TypeScript changes aren't being watched.
