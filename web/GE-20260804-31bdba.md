### Symptom
Test suite reports "2 passed, 4 failed" — partial pass suggests a code bug, not a missing dependency. The 4 failing suites all error with `Failed to resolve import "@xyflow/react"` but the 2 passing suites work fine because they don't import the missing package.

### Context
`@xyflow/react` was added to `package.json` dependencies but `yarn install` was never re-run. The lockfile had the resolution but `node_modules` did not have the package. Test suites that import `@xyflow/react` (directly or transitively) fail at import resolution. Suites that don't import it pass normally.

### What was tried (didn't work)
- Investigating the failing test code for bugs — code was correct
- Checking the import paths — all correct
- Looking at package.json — dependency was declared

### Root cause
Adding a dependency to `package.json` does not install it. `yarn install` must be run explicitly. The lockfile (`yarn.lock`) is updated by `yarn add` but not by manual edits to `package.json`. When edited manually, only `yarn install` resolves the new entry to `node_modules`.

### Fix
Run `yarn install` after any manual edit to `package.json` dependencies:
```bash
yarn install
```

### Why this is non-obvious
The partial pass/fail pattern (2/6 suites pass) strongly suggests a code bug, not a missing dependency. A total failure (0/6) would immediately point to infrastructure. The misleading signal wastes time investigating the wrong cause. The dependency IS in package.json and yarn.lock — only `node_modules` is stale.
