## Symptom

Need to make CodeMirror 6 editor properties (language, readonly, line numbers, tab size, label, extensions) dynamically changeable via Lit `@property()` decorators, but CodeMirror's `EditorState` is immutable — you can't just set a property and have it take effect.

## Context

A LitElement web component wrapping CodeMirror 6 where consumers set properties declaratively (`<pages-code-editor language="json" readonly>`) and expect them to take effect at runtime, including after the editor is already created.

## Fix

Use one `Compartment` per reconfigurable property. Each Compartment wraps the extension it controls, and `_syncProperties()` in Lit's `updated()` lifecycle dispatches reconfiguration effects:

```typescript
import { Compartment, type Extension } from '@codemirror/state';
import { EditorView } from '@codemirror/view';

class PagesCodeEditor extends LitElement {
  @property({ type: String }) language: 'yaml' | 'json' = 'yaml';
  @property({ type: Boolean, reflect: true }) readonly = false;

  private _editorView: EditorView | null = null;
  private _suppressUpdate = false;

  // One Compartment per reconfigurable property
  private _languageCompartment = new Compartment();
  private _readonlyCompartment = new Compartment();

  // Initial state uses compartments
  private createEditorState() {
    return EditorState.create({
      doc: this.value,
      extensions: [
        this._languageCompartment.of(yaml()),
        this._readonlyCompartment.of(EditorState.readOnly.of(false)),
        EditorView.updateListener.of((update) => {
          if (update.docChanged) {
            this._suppressUpdate = true;  // prevent update loop
            this.value = update.state.doc.toString();
            this._suppressUpdate = false;
            this.dispatchEvent(new Event('input', { bubbles: true, composed: true }));
          }
        }),
      ],
    });
  }

  // Lit updated() dispatches reconfiguration
  override updated(changed: PropertyValues) {
    if (this._editorView && !this._suppressUpdate) {
      this._syncProperties(changed);
    }
  }

  private _syncProperties(changed: PropertyValues) {
    if (!this._editorView) return;

    if (changed.has('language')) {
      this._editorView.dispatch({
        effects: this._languageCompartment.reconfigure(
          this.language === 'json' ? json() : yaml()
        ),
      });
    }

    if (changed.has('readonly')) {
      this._editorView.dispatch({
        effects: this._readonlyCompartment.reconfigure(
          EditorState.readOnly.of(this.readonly)
        ),
      });
    }
  }
}
```

**Critical detail — the `_suppressUpdate` flag:** When CodeMirror's `updateListener` fires on user edits, it sets `this.value` which triggers Lit's `updated()`. Without the flag, `_syncProperties` would dispatch a redundant `value` change back to CodeMirror, creating an infinite loop. The flag breaks the cycle:

```
User types → CM6 updateListener → sets this.value (suppressUpdate=true)
  → Lit updated() fires → _syncProperties skips (suppressUpdate=true)
  → suppressUpdate=false
```

**Lifecycle — re-insertion after DOM removal:** `disconnectedCallback` destroys the EditorView, but `firstUpdated` only fires once. Use a `_pendingCreate` flag:

```typescript
override connectedCallback() {
  super.connectedCallback();
  if (!this._editorView) this._pendingCreate = true;
}

override updated(changed: PropertyValues) {
  if (this._pendingCreate && !this._editorView) {
    this._createEditor();
  }
  // ...
}

override disconnectedCallback() {
  this._editorView?.destroy();
  this._editorView = null;
  super.disconnectedCallback();
}
```

## Why this is non-obvious

CodeMirror 6's documentation describes Compartments for dynamic reconfiguration, but the Lit integration pattern — where Compartments map 1:1 to `@property()` decorators and reconfiguration happens in `updated()` — is not documented anywhere. The `_suppressUpdate` flag to prevent update loops between CM6's updateListener and Lit's reactive property system is a subtle requirement that only surfaces when you try to make `value` bidirectional. The re-insertion lifecycle pattern (`_pendingCreate`) catches a Lit-specific trap where `firstUpdated` doesn't fire on re-insertion.

### Alternatives considered

- Destroying and recreating EditorState on every property change — works but loses cursor position, undo history, and selection
- Using `EditorView.dispatch()` with raw state effects — verbose and error-prone without the Compartment abstraction
- Using Lit's `willUpdate()` instead of `updated()` — CM6 view isn't ready yet in `willUpdate`, effects can't be dispatched
