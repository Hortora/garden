# pages page() nested children need interactive container for navigation

## Symptom

Two child `page()` components inside a parent `page()` — only one renders. `LiveSite.navigate()` has no effect. `buildPageIndex` maps both children to the same path.

## Context

Creating a multi-page site with `casehub-pages-ui` DSL — e.g. a Trading Desk page and an Ops Centre page in one application.

## Root cause

`page()` places all its children in `slots: { content: children }`. When two child pages are direct children, both map to the `"content"` path segment in `buildPageIndex`. The second overwrites the first. `walkNavigate` only searches `INTERACTIVE_TYPES` containers for navigation slot matching — plain content slots are not interactive.

No `site()` builder exists. The `Site` interface and `LiveSite` are runtime types, not DSL builders.

## Fix

Wrap child pages in an interactive container — `tabs()`, `sidebar()`, `pills()`, etc.:

```typescript
import { page, tabs } from "@casehubio/pages-ui";

const site = page("My App",
  tabs(
    ["Page One", page("Page One", dockWorkbench({...}), { datasets: [...] })],
    ["Page Two", page("Page Two", dockWorkbench({...}), { datasets: [...] })],
  ),
);

loadSite(container, site);
```

`tabs()` creates distinct named slots that `buildPageIndex` can resolve. `LiveSite.navigate(path)` then switches between them correctly.

**Choosing the container:** `tabs()` for 2-3 pages (lightweight horizontal bar). `sidebar()` for more pages. When using `dockWorkbench()` inside pages, prefer `tabs()` — a site-level `sidebar()` visually competes with dock bars.

## Why this is non-obvious

The `page()` API accepts variadic children with no type constraint — placing two child `page()` components compiles and builds without error. The failure is silent: one page just never renders. No documentation describes the `INTERACTIVE_TYPES` requirement or the path segment collision.
