### Symptom
Building a flyout popover inside a Lit web component required manual JS for
show/hide, click-outside dismiss, focus management, z-index stacking, and
positioning relative to a trigger element.

### Context
Any Lit (or vanilla) web component that needs a popover, dropdown, or flyout
menu. The component renders both the trigger and popover content inside the
same shadow root.

### What was tried (didn't work)
Manual approach: `position: absolute` with a `_popoverOpen` state property,
`document.addEventListener('click', ...)` for click-outside, manual `aria-expanded`
management, and z-index coordination. This is fragile in shadow DOM because
`composedPath()` doesn't cross shadow boundaries in jsdom tests
(see GE-20260713-9e6bf5).

### Fix
Use `popover="auto"` on a `<div>` inside the shadow root and `popovertarget`
on the trigger button. Both elements must be in the same shadow root (same
tree scope) for the ID-based `popovertarget` resolution to work. CSS Anchor
Positioning handles placement:

```css
button[part="trigger"] { anchor-name: --my-trigger; }
[popover] {
  position: fixed;
  position-anchor: --my-trigger;
  position-area: block-end span-inline-end;
  position-try-fallbacks: flip-block;
  margin-block-start: 4px;
}
```

Critical for multiple instances: add `anchor-scope: all` on the component's
`:host` — without it, all instances resolve to the last DOM element's anchor
name.

The browser provides for free: light-dismiss, Escape-to-close, auto
`aria-expanded` on the invoker, top-layer rendering (no z-index), and
tab-order repositioning.

### Why this is non-obvious
The `popovertarget` attribute uses ID-based resolution, and IDs are scoped
to shadow roots. The whatwg spec (issue #9109) discusses cross-shadow-boundary
limitations, which leads developers to assume `popovertarget` won't work in
shadow DOM at all. It does — within the same shadow root. The `anchor-scope`
gotcha for multiple instances is documented in the CSS spec but not in any
Lit or web component guide.

### Caveats
- Safari 18.2-18.3 supports `anchor()` but not `@position-try` — base
  positioning works, viewport flipping doesn't on those versions
- jsdom doesn't implement `showPopover()`/`hidePopover()` — mock them in
  tests if testing open/close behaviour
- `popover="hint"` (hover tooltips) is Chrome-only as of mid-2026
