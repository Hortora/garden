### Symptom
Calling `bridge.setContent("# Heading\n\n**bold**")` or `bridge.insertText("> blockquote")` renders the raw markdown syntax as literal text in the WYSIWYG editor — `# Heading` appears as plain text, not as a rendered heading. Bold markers `**` are visible instead of rendering as bold.

### Context
The `MarkdownEditorBridge` extends `EditableTextBridge` and wraps a Milkdown/ProseMirror editor. The `EditableText` interface defines `setContent(text)` and `insertText(text)` for programmatic editing.

### Root cause
The initial implementation used ProseMirror's `tr.insertText()` which inserts raw text into the document without parsing it through the markdown parser. ProseMirror treats the input as literal characters, not markdown to be rendered.

### Fix
Pass the Milkdown parser to the bridge constructor and use it in `setContent`/`insertText`:

```typescript
constructor(view, serializer, parser?) { ... }

setContent(text: string): void {
  if (this.parser) {
    const doc = this.parser(text);
    if (doc) {
      const { tr } = this.view.state;
      this.view.dispatch(tr.replaceWith(0, this.view.state.doc.content.size, doc.content));
      return;
    }
  }
  // fallback to raw insert
  this.view.dispatch(tr.insertText(text, 0, this.view.state.doc.nodeSize - 2));
}
```

The parser is obtained from Milkdown's `parserCtx` in the component's `firstUpdated()`.

### Why this is non-obvious
`insertText` is the standard ProseMirror API for adding text. The name suggests it handles text correctly. But in a markdown-first editor like Milkdown, "text" means "markdown source" to the user and "literal characters" to ProseMirror. The bridge must translate between these two interpretations.
