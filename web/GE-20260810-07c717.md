### Symptom

Compiler error: `Property 'key' is optional in type '{ position: ...; size: ...; key?: string; ... }' but required in type 'FrameLayout'`.

Nothing in the code declares `key` as optional. The interface has `readonly key: string` — clearly required.

### Context

Spreading a `readonly` interface and overriding some fields:

```typescript
interface FrameLayout {
  readonly key: string;
  readonly order: number;
  readonly position: { x: number; y: number };
  readonly size: { width: number; height: number };
  // ... more readonly fields
}

function sideBySide(frames: FrameLayout[]): FrameLayout[] {
  return frames.map((f, i) => ({
    ...f,
    position: { x: i * 400, y: 0 },
    size: { width: 400, height: 800 },
  }));
  // TS2322: Property 'key' is optional in type ... but required in type 'FrameLayout'
}
```

### Root cause

TypeScript's spread type inference for `readonly` interfaces produces a type where non-overridden properties become optional. The spread `{ ...f, position, size }` infers the result type with `key?: string` rather than `key: string` because the `readonly` modifier interacts poorly with the spread homomorphic mapped type.

### Fix

Use an explicit construction helper that names all fields:

```typescript
function withLayout(
  f: FrameLayout,
  pos: { x: number; y: number },
  sz: { width: number; height: number },
): FrameLayout {
  return {
    key: f.key, order: f.order, zIndex: f.zIndex,
    pinned: f.pinned, hidden: f.hidden, tabs: f.tabs,
    activeTabKey: f.activeTabKey, position: pos, size: sz,
  };
}

// Now this compiles:
function sideBySide(frames: FrameLayout[]): FrameLayout[] {
  return frames.map((f, i) =>
    withLayout(f, { x: i * 400, y: 0 }, { width: 400, height: 800 })
  );
}
```

### Why this is non-obvious

The error message says "optional" but nothing is declared optional. The actual cause — `readonly` modifier interaction with spread inference — is not documented and doesn't appear in the TypeScript FAQ. The fix (explicit construction helper) feels verbose but is the only reliable approach.

### Alternatives considered

- Non-null assertion on the result (`as FrameLayout`) — masks real type errors
- Removing `readonly` from the interface — loses immutability guarantees for all consumers
- Using `Omit` + intersection — verbose and fragile when interface changes
