### Symptom
Click a point on a canvas to show a crosshair and open a detail panel. The crosshair appears offset from the click position — shifted left on the first click, correct on subsequent clicks.

### Context
A Lit component with a flex layout: canvas container (flex: 1) + optional detail panel (fixed 320px). Clicking selects an entry, sets `@state()` which triggers Lit re-render adding the panel. The canvas container shrinks by 320px.

### Root cause
The click handler captures mouse coordinates relative to the pre-panel canvas rect. Then `selectedEntry` state change triggers Lit re-render (panel appears, canvas shrinks). The stored pixel coordinates are now relative to the old wider canvas, but the crosshair draws on the new narrower canvas.

Storing fractional coordinates (`clickFracX = (mx - pad) / gridWidth`) helps but still drifts because the fraction was computed from the old grid width.

### Fix
Use HTML overlay divs instead of canvas-drawn crosshairs. Store the click position as a CSS percentage of the container at click time, render as absolutely-positioned divs:

```typescript
this.crosshairPctX = (mx / rect.width) * 100;
this.crosshairPctY = (my / rect.height) * 100;
```

```html
<div class="crosshair-v" style="left:${this.crosshairPctX}%"></div>
<div class="crosshair-h" style="top:${this.crosshairPctY}%"></div>
```

CSS percentage positioning is immune to container resize — the browser reflows the overlay position automatically.

### Why this is non-obvious
The natural approach is drawing crosshairs on the canvas (same context as the data visualization). But canvas coordinates are fragile when the container resizes between click capture and draw. HTML overlays with CSS percentages delegate the coordinate math to the browser's layout engine.
