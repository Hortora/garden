### Symptom
Floating panels render a placeholder ("No content") with zero console errors.
The `createComponent` callback fires but `options.params` is undefined — the
content factory never receives the tab configuration passed via `addPanel()`.

### Context
When using `DockviewComponent` with `addPanel({ params: { tabConfig, frameKey } })`,
the expectation is that `createComponent(options)` receives those params in
`options.params`. This matches intuition from React component patterns where
props are available at construction time.

### What was tried (didn't work)
Reading `options.params?.tabConfig` inside `createComponent` — always undefined.
No error thrown, no warning logged. The fallback path produces a visible placeholder
but gives no diagnostic signal about why params are missing.

### Root cause
Dockview v7's `createComponent` callback receives only `{ id, name }` — the
component identifier, not the panel configuration. User-provided params from
`addPanel()` are delivered later via the `init(params)` lifecycle method, where
`params.params` holds the user-provided object.

This is undocumented in the dockview-core README. The only way to discover it
is by reading the dockview source or stepping through the panel creation flow.

### Fix
Defer content creation from `createComponent` to the `init()` lifecycle method:

```typescript
createComponent: () => {
  const wrapper = document.createElement("div");
  let storedResult: ContentFactoryResult | undefined;
  return {
    element: wrapper,
    init(params: any) {
      const tabConfig = params?.params?.tabConfig as FrameTabConfig | undefined;
      if (!tabConfig || !factory) {
        wrapper.textContent = "No content";
        return;
      }
      const result = factory(tabConfig);
      storedResult = result;
      wrapper.appendChild(result.element);
    },
    dispose() {
      storedResult?.dispose?.();
    },
  };
},
```

### Why this is non-obvious
The API name `createComponent` strongly implies it receives everything needed
to construct the component. The silent failure mode (no error, just a blank panel)
makes debugging harder — there's no signal that params are being delivered via a
different lifecycle method.

### Why this fix
Reading params in `init()` instead of the constructor aligns with Dockview's
internal lifecycle. The wrapper element is created eagerly (Dockview needs it
immediately) while content is populated lazily when params arrive.

### Alternatives considered
- Storing params on a side channel during `addPanel` and reading them by panel ID in `createComponent` — fragile, races with Dockview's internal panel lifecycle
- Monkey-patching `DockviewComponent.addPanel` to inject params into the constructor options — breaks on version updates
