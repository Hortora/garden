### Symptom
In a recursive container model (containers nested inside containers), drag-and-drop events from an inner container must be handled by the nearest parent — not by grandparent or higher ancestors. Without scoping, every ancestor handler responds to every drag event, causing duplicate transfers.

### Context
A workspace has nested free-layout containers. Each container has a DnD handler listening for tab drag events. When a tab drag starts in an inner container, the event must reach exactly one handler — the immediate parent free-layout — and stop there.

### Fix
Use two DOM events with `bubbles: true` and call `stopPropagation()` in the first handler that catches each:

**`pages-tab-drag-start`** — fired by the Container when a tab drag gesture begins. The nearest free-layout DnD handler catches it and calls `stopPropagation()`:

```typescript
function onDragStart(e: Event): void {
  const evt = e as CustomEvent<{ tabKey: string; ghost: HTMLElement; sourceContainer: Container }>;
  evt.stopPropagation(); // scope to THIS free-layout level
  // ... set up pointermove/pointerup tracking
}
hostElement.addEventListener("pages-tab-drag-start", onDragStart);
```

**`pages-tab-escaped`** — fired when the pointer exits the current handler's host bounds, signalling the parent level to take over:

```typescript
if (isOutsideHost(moveEvt.clientX, moveEvt.clientY)) {
  cleanup();
  hostElement.dispatchEvent(new CustomEvent("pages-tab-escaped", {
    bubbles: true,
    detail: { tabKey, ghost, sourceContainer },
  }));
}
```

The parent free-layout catches `pages-tab-escaped`, calls `stopPropagation()`, and enters its own drag mode.

### Why this is non-obvious
The common approach for nested DnD is a central coordinator that tracks all containers. The DOM event + stopPropagation pattern eliminates the coordinator entirely — each level handles its own events independently, and scoping emerges from the DOM tree structure. The escape event creates a handoff chain that naturally follows the nesting depth.
