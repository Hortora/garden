## Symptom

TypeScript error when passing a `Record<string, ComponentType<NodeProps>>` to React Flow's `nodeTypes` prop:

```
error TS2769: No overload matches this call.
  Type 'Record<string, ComponentType<NodeProps>>' is not assignable to type 'NodeTypes'.
    Type 'ComponentType<NodeProps>' is not assignable to type 'ComponentType<unknown>'.
```

## Context

Building a plugin registry for React Flow v12 custom nodes. The registry stores `ComponentType<NodeProps>` and the getter returns `Record<string, ComponentType<NodeProps>>`. Passing this to `<ReactFlow nodeTypes={...} />` fails with a deep type incompatibility.

## Root cause

React Flow v12 defines `NodeTypes` in `@xyflow/react/dist/esm/types/general.d.ts` as:

```typescript
export type NodeTypes = Record<string, ComponentType<NodeProps & {
  data: any;
  type: any;
}>>;
```

The `& { data: any; type: any }` widening makes `NodeTypes[string]` a **different type** from `ComponentType<NodeProps>`. TypeScript's contravariant parameter checking means `ComponentType<NodeProps>` (stricter props) is not assignable to `ComponentType<NodeProps & { data: any }>` (wider props) — the `getDerivedStateFromProps` and `constructor` signatures become incompatible.

## Fix

Use `NodeTypes` from `@xyflow/react` directly instead of constructing your own `Record<string, ComponentType<NodeProps>>`:

```typescript
import type { NodeTypes } from '@xyflow/react';

type NodeComponent = NodeTypes[string];

interface NodeTypeDescriptor {
  readonly type: string;
  readonly component: NodeComponent;  // not ComponentType<NodeProps>
}

function getNodeTypes(): NodeTypes {
  const result: NodeTypes = {};
  for (const [type, desc] of registry) {
    result[type] = desc.component;
  }
  return result;
}
```

For test stubs, cast through `unknown`:
```typescript
const StubNode = (() => null) as unknown as NodeTypes[string];
```

## Why this is non-obvious

The type error message is deeply nested (references `getDerivedStateFromProps`, `ComponentClass`, `Readonly<unknown>`) and doesn't point to the `{ data: any; type: any }` widening as the root cause. A developer seeing `ComponentType<NodeProps>` would naturally expect it to be compatible with React Flow's node type system — `NodeProps` IS the React Flow node props type. The widening with `any` is an internal typing detail not visible in the public API docs.
