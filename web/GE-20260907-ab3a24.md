### Symptom
ReactFlow's built-in BezierEdge renders near-straight lines between nodes with same-side handles (e.g. both `Position.Left`). The bezier control points use the horizontal distance between source and target for the offset — zero for vertically aligned nodes.

### Context
Hub-spoke graph layouts where bidirectional edges (A→B and B→A) use same-side handles to avoid overlap. The return edge gets `left→left` which is geometrically shortest but renders as a straight vertical line with no visible curvature.

### What didn't work
- `getBezierPath` with custom `sourceControlX/Y` parameters — silently ignored, not part of the API
- Increasing `curvature` parameter — only affects different-side handles, same-side still computes zero offset for aligned nodes
- SmartBezierEdge — uses pathfinding that ignores handle direction entirely, drawing the shortest path

### Root cause
ReactFlow's bezier path computation for same-direction handles calculates control point offset from the inter-node distance along the handle axis. For vertically aligned nodes with `Position.Left` handles, the horizontal distance is zero, so the offset is zero — producing a straight line.

### Fix
Custom edge component that constructs the SVG cubic bezier path directly with a proportional minimum departure:

```typescript
function DirectionalBezierEdge(props: EdgeProps) {
  const { sourceX, sourceY, sourcePosition, targetX, targetY, targetPosition } = props;
  const dist = Math.sqrt((sourceX - targetX) ** 2 + (sourceY - targetY) ** 2);
  const offset = Math.min(60, dist * 0.4);
  const signX = (pos: Position) => pos === Position.Left ? -1 : pos === Position.Right ? 1 : 0;
  const signY = (pos: Position) => pos === Position.Top ? -1 : pos === Position.Bottom ? 1 : 0;
  const scx = sourceX + signX(sourcePosition) * offset;
  const scy = sourceY + signY(sourcePosition) * offset;
  const tcx = targetX + signX(targetPosition) * offset;
  const tcy = targetY + signY(targetPosition) * offset;
  const path = `M${sourceX},${sourceY} C${scx},${scy} ${tcx},${tcy} ${targetX},${targetY}`;
  return <g><path d={path} fill="none" className="react-flow__edge-path" style={props.style}
    markerEnd={props.markerEnd} markerStart={props.markerStart} /></g>;
}
```

Key: `min(60, dist * 0.4)` scales with edge length — short edges get small departures (no squiggly lines), long edges get up to 60px for visible curvature.

### Why this is non-obvious
The natural assumption is that ReactFlow's BezierEdge handles same-side positions correctly. The zero-offset behaviour is a mathematical consequence of the control point formula, not a documented limitation. The `getBezierPath` API accepts undocumented-looking parameters that seem like they'd solve it but are silently ignored.
