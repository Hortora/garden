### Symptom
Canvas element in a Lit component renders blank despite data being loaded. `drawNetwork()` calls `getContext('2d')` and draws shapes, but nothing appears on screen.

### Context
Occurs when a `<canvas>` is conditionally rendered inside a Lit template — e.g., an empty state message shows when `nodes.length === 0`, then switches to `<canvas>` when data loads. The `updated()` lifecycle fires after Lit commits the DOM change, but the canvas may not be paintable yet.

### Root cause
Lit's `updated()` fires synchronously after the DOM mutation, before the browser has completed layout and paint. Setting `canvas.width` (which clears the canvas) and drawing in the same microtask means the draw commands execute before the canvas has its final dimensions from CSS layout.

### Fix
Use `requestAnimationFrame` inside `updated()` to defer drawing until after the browser's next paint cycle. Also add a dirty flag to prevent redundant redraws:

```typescript
private drawn = false;

updated() {
  if (this.nodes.length > 0 && !this.drawn) {
    this.drawn = true;
    requestAnimationFrame(() => this.drawCanvas());
  }
}
```

### Why this is non-obvious
`updateComplete.then()` is the standard Lit recommendation for post-render work, but it resolves after Lit's update cycle, not after the browser's paint. For DOM elements that need layout (like canvas with CSS `width: 100%`), the paint hasn't happened yet. `requestAnimationFrame` is the browser-level solution.
