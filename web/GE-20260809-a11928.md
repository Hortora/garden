## D3 force simulation as layout companion for Lit Web Components

### The technique
D3 and Lit occupy different layers of the same component without interfering:

- **Lit owns the component lifecycle**: properties, state, conditional rendering (loading/error/empty/data states), shadow DOM, CSS
- **D3 owns the SVG internals**: force simulation, node/edge rendering, zoom/pan/drag behaviors, tick-driven position updates

The boundary is a `<g class="container">` element inside Lit's SVG. Lit renders the SVG structure; D3 populates and animates the container's children.

### How it works

```typescript
// Lit renders the SVG shell
override render() {
  return html`
    <svg role="img" aria-label=${ariaLabel}>
      <defs></defs>
      <g class="container"></g>  <!-- D3 takes over here -->
    </svg>`;
}

// D3 populates the container after Lit's render
private _buildGraph(): void {
  const container = this.shadowRoot.querySelector('.container');
  // D3 creates nodes, edges, sets up simulation
  renderGraph(container, nodes, links, options);
  this._sim = createSimulation(nodes, links, width, height);
  this._sim.on('tick', () => {
    // D3 updates SVG attributes directly — no Lit re-render
    select(container).selectAll('.nodes g')
      .attr('transform', d => `translate(${d.x},${d.y})`);
  });
}
```

### Why this works well
- No framework conflict: D3's `select().attr()` mutates DOM directly, bypassing Lit's rendering pipeline. Lit doesn't observe changes inside the container `<g>` because they're not reactive properties.
- Clean lifecycle: `disconnectedCallback` stops the simulation and clears the SVG. Data changes stop the old simulation, clear, and rebuild.
- Render callbacks bridge the gap: consumer-provided `renderNode` functions return raw `SVGElement` instances (not Lit templates), which D3 appends to node groups.

### Why this is non-obvious
The natural instinct with Lit is to render everything via `html` tagged templates. But D3's force simulation updates positions on every tick (potentially 60fps during convergence), and running those updates through Lit's reactive system would be wasteful — Lit would diff and patch the template on every frame. D3's direct DOM manipulation is both simpler and more efficient for this specific use case.

The key insight is that Lit and D3 can coexist in the same component if they own different parts of the DOM tree. Lit owns the component boundary; D3 owns the visualization internals.
