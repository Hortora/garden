# Vite alias + cross-repo node_modules causes duplicate Lit custom element registration

## Symptom

```
NotSupportedError: Failed to execute 'define' on 'CustomElementRegistry':
the name "pages-theme-picker" has already been used with this registry
```

Page renders blank. Only one error in console but the entire import
chain breaks because the failing module's top-level code throws.

## Context

Project A's Vite/esbuild config aliases `@scope/pkg-b` to sibling
repo B's source directory. Repo B has its own `node_modules/@scope/`
with symlinks to B's local package directory (e.g. `.casehub-packages`).
Project A also has `@scope/pkg-c` in its own packages or node_modules.

Both `@scope/pkg-c` copies contain the same Lit component with
`@customElement('my-element')`.

## What was tried (didn't work)

- `resolve.dedupe: ['lit', '@lit/reactive-element']` in Vite config —
  deduplicates Lit core but not the component packages that re-register
  custom elements.
- Aliasing individual packages to `dist/` — causes "double dist" when
  pre-compiled imports already include `dist/` in the path.

## Root cause

Vite resolves `@scope/pkg-c` from two different physical paths:

1. **Via Project A's aliases/node_modules** → Project A's copy
2. **Via Repo B's node_modules symlink** → Repo B's copy

Both modules execute, both call `customElements.define('my-element')`.
The second call throws `NotSupportedError`.

`resolve.dedupe` handles npm version deduplication within a single
`node_modules` tree but does not resolve cross-repo symlink paths to
a canonical location.

## Fix

Use an esbuild/Vite resolve plugin that intercepts all `@scope/*`
imports and resolves them through a single canonical directory:

```js
const casehubResolvePlugin = {
  name: "casehub-resolve",
  setup(b) {
    b.onResolve({ filter: /^@scope\// }, (args) => {
      const match = args.path.match(/^@scope\/([^/]+)(?:\/(.+))?$/);
      if (!match) return null;
      const [, pkg, subpath] = match;
      const pkgDir = resolve(CANONICAL_PKGS, pkg);
      if (!subpath) {
        const idx = resolve(pkgDir, "dist", "index.js");
        if (existsSync(idx)) return { path: idx };
      }
      // ... resolve subpath through dist/
    });
  },
};
```

For `dist/` vs non-`dist/` subpath conflicts (compiled imports include
`dist/`, source imports don't), use two aliases per package:
1. `@scope/pkg/dist` → `pkg/dist` (identity — prevents double-dist)
2. `@scope/pkg` → `pkg/dist` (maps bare imports)

### Why this is non-obvious

The duplicate is invisible in the import graph — you can't see it in
`vite --debug` or build output. It only manifests at runtime when
`customElements.define()` is called a second time. The error message
gives no indication of which two physical paths are in conflict.
