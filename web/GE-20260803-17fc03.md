### Symptom
esbuild fails with `Could not resolve "@casehubio/channel-activity"` even though the package directory exists at `.casehub-packages/packages/channel-activity/`.

The esbuild error message suggests marking the path as external — this is misleading. The real issue is a package name mismatch.

### Context
casehub-packages are consumed via Yarn Berry `portal:` resolutions in `package.json`. The resolution maps an npm package name to a local directory path. When adding a new casehub package dependency, the natural assumption is that the import path matches the directory name.

### What was tried
1. `import { renderMarkdown } from '@casehubio/channel-activity'` — fails with "Could not resolve"
2. Adding `"@casehubio/channel-activity": "portal:./.casehub-packages/packages/channel-activity"` to resolutions — still fails because the package's own `package.json` declares a different name

### Root cause
The directory is `channel-activity/` but the package's `package.json` declares `"name": "@casehubio/blocks-ui-channel-activity"`. Yarn Berry portal resolutions require the import path to match the `name` field in the target package's `package.json`, not the directory name.

The naming convention is inconsistent across casehub-packages:
- Some use `@casehubio/blocks-ui-*` prefix: `blocks-ui-channel-activity`, `blocks-ui-core`, `blocks-ui-kpi-metric-row`
- Others use bare `@casehubio/*`: `pages-runtime`, `pages-ui`, `pages-component`

### Fix
Always check the `name` field in `<package-dir>/package.json` before adding a portal resolution or import statement:

```bash
cat .casehub-packages/packages/<dir>/package.json | python3 -c 'import sys,json; print(json.load(sys.stdin)["name"])'
```

Use the returned name (not the directory name) in both `dependencies` and `resolutions`.

Alternative: if only one function is needed from a large package (e.g. `renderMarkdown` from `channel-activity` which pulls in `dompurify` and `emoji-picker-element`), use the underlying dependency directly (e.g. `marked`) to avoid the transitive dependency overhead.

### Why this is non-obvious
Directory names are the primary navigation mechanism when browsing `.casehub-packages/packages/`. The assumption that directory name = import path holds for most JavaScript ecosystems. The inconsistent prefix convention (`blocks-ui-*` vs bare) means you can't predict the pattern — you must check each package individually.
