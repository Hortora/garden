## Yarn `resolutions` field in package.json is silently ignored by npm

### Symptom
Dependency version overrides declared in `resolutions` have no effect. npm installs whatever the dependency tree resolves to, ignoring the override. No warning, no error — completely silent.

### Context
A project migrated from Yarn to npm (or was developed with both). The `package.json` has a `resolutions` field with `portal:` or version overrides. A `package-lock.json` also exists. npm uses the lockfile but completely ignores `resolutions`.

### Root cause
`resolutions` is a Yarn-only field. npm's equivalent is `overrides`. The two have different semantics:

- Yarn `resolutions`: `"@scope/pkg": "portal:./.local/pkg"` — direct replacement
- npm `overrides`: `"@scope/pkg": "$@scope/pkg"` — `$` prefix means "use the version from my direct dependencies"

npm does not warn when `resolutions` is present — it treats it as an unknown field and silently skips it.

### Fix
Replace `resolutions` with `overrides` in `package.json`:

```json
{
  "overrides": {
    "@scope/pkg-a": "$@scope/pkg-a",
    "@scope/pkg-b": "$@scope/pkg-b"
  }
}
```

The `$pkgname` syntax tells npm to use the version declared in direct `dependencies` for all transitive occurrences. For packages not in direct deps, use explicit version or path.

### Why this is non-obvious
There is no warning. A developer seeing `resolutions` in `package.json` alongside `package-lock.json` would reasonably assume npm supports it (or at least warns). The silent ignore means version overrides appear to be "working" until a transitive dependency conflict surfaces at runtime.
