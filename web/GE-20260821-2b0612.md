## Symptom

After editing source files in a Yarn `portal:` dependency (e.g.
`.casehub-packages/packages/graph-renderer/`), `yarn build` succeeds
but the running Vite dev server continues serving the old version.
Console logs added to the source never appear.

## Context

Yarn `portal:` dependencies point to local directories. Vite's dependency
pre-bundler resolves portal paths at startup and caches the result in
`node_modules/.vite/`. Subsequent changes to the portal source directory
do not invalidate this cache — Vite treats pre-bundled deps as stable.

This differs from `link:` or workspace dependencies where Vite may detect
changes. Portal deps are resolved once and frozen.

## Root cause

Vite's pre-bundle optimizer (`esbuild`) runs at startup, resolves portal
paths to their concrete source, bundles the result into `node_modules/.vite/deps/`,
and never re-checks. The `optimizeDeps` watcher does not include portal
source directories in its watch list.

## Fix

Delete the pre-bundle cache and restart the dev server:

```bash
rm -rf <project>/examples/node_modules/.vite
# restart vite
```

Alternatively, add the portal source directory to `optimizeDeps.exclude`
in `vite.config.ts` to prevent pre-bundling entirely (at the cost of
slower dev server startup).

## Why this is non-obvious

The build (`yarn build`) uses the source directly and works correctly.
Only the dev server serves stale content — the developer sees correct
build output but wrong browser behaviour, which looks like a component
rendering bug rather than a caching issue.
