## Symptom

When multiple panels share the same dock slot (e.g., Navigator and Files both in the left-side zone), closing one panel hides ALL panels in that slot. Only reopening the dock zone brings them back.

## Stack

- TypeScript / React
- casehub-pages tool-window docking system
- `restoreFromUrl()` dock state restoration function

## Context

Tool-window docking infrastructure allows multiple panels to occupy the same zone. When a user closes a panel and the dock state is saved to a URL, reopening the page should restore only that single panel as closed — other panels in the shared slot should remain visible.

## Root Cause

`restoreFromUrl()` used `panelEl.closest("[data-slot]")` to locate the slot container and then applied `display: none` to hide "closed" panels. Because `closest()` matches the first ancestor with the `[data-slot]` attribute, all children of that slot were hidden as a side effect — not just the specific panel element.

## Fix

Remove slot-hiding logic from `restoreFromUrl()` entirely. Dock visibility is already managed by the `dock-toggle` event handler, which correctly applies visibility state to individual panel elements without touching the slot container. The slot itself should remain visible; only the panel's display state changes.

```typescript
// Remove this block from restoreFromUrl():
// const slotEl = panelEl.closest("[data-slot]");
// if (dockState[panelId] === "closed") {
//   slotEl.style.display = "none"; // ❌ WRONG: hides entire slot
// }
```

## Why This is Non-Obvious

`closest()` is used correctly for finding the slot context, but applying `display: none` to the slot ancestor (rather than the panel element itself) is a scope mismatch. The dock-toggle handler already owns panel visibility — applying state at the slot level creates a duplicate responsibility with inconsistent semantics.

## Constraints

Applies only when: multiple panels share a single dock slot. Single-panel slots are unaffected.

## Alternatives Considered

- Filtering the slot's children to hide only the specific panel (still wrong — would require tracking which panels are in the slot and hiding others)
- Adding a "hidden" class to the panel instead of using `display: none` (correct approach, but must coordinate with dock-toggle to avoid conflicts)

## Invalidation Triggers

Revisit if dock-toggle event handler is removed or refactored to no longer manage individual panel visibility.
