### Symptom

```
Transform failed with 1 error:
[TSCONFIG_ERROR] Failed to load tsconfig for '../package/src/index.ts': Tsconfig not found
```

Vitest test suite fails to start. The error points at a file resolved through a Vite alias.

### Context

Vitest config aliases `@scope/pkg` to a sibling package's `src/` directory in a monorepo-style `.casehub-packages` structure. The vitest config provides `esbuild.tsconfigRaw` with `experimentalDecorators` and `useDefineForClassFields` settings. This worked fine when Vite used the esbuild transform.

### What was tried (didn't work)

- Adding `tsconfigRaw` to the vitest esbuild config — ignored because oxc took precedence
- Aliasing to `src/` with the assumption that the package's own `tsconfig.json` would be found — it wasn't, because the alias resolves the import to a path outside the consuming project's tsconfig tree

### Root cause

Vite's oxc transform (`vite:oxc`) resolves tsconfig by walking up the filesystem from the source file being transformed. When a Vite alias points `@scope/pkg` → `../../packages/pkg/src`, oxc looks for `tsconfig.json` starting from that `src/` directory and walking up. If the sibling package doesn't have a `tsconfig.json` in its ancestor chain (or has one that's not reachable from the alias target), the transform fails.

The esbuild transform accepted inline `tsconfigRaw` in the vitest config, which masked the problem entirely — no filesystem tsconfig lookup was needed.

The vitest config even warns: "Both esbuild and oxc options were set. oxc options will be used and esbuild options will be ignored."

### Fix

Alias transitive dependencies to `dist/` (pre-compiled JS + `.d.ts` types) instead of `src/`:

```typescript
// vitest.config.ts
alias: [
  // Direct dep — shares tsconfig tree, src/ is fine
  { find: '@scope/blocks-ui-core', replacement: path.resolve(__dirname, '../../packages/blocks-ui-core/src') },
  // Transitive deps — use dist/ to avoid tsconfig resolution
  { find: '@scope/pages-primitives', replacement: path.resolve(__dirname, '../../packages/pages-primitives/dist') },
  { find: '@scope/pages-ui-tokens', replacement: path.resolve(__dirname, '../../packages/pages-ui-tokens/dist') },
]
```

The `dist/` directory contains pre-compiled `.js` files that don't need TypeScript transformation, so oxc never looks for a tsconfig.

### Why this is non-obvious

The esbuild-to-oxc migration in Vite is largely transparent — most projects don't notice the switch. The `tsconfigRaw` inline config that worked with esbuild silently stops working with oxc, and the error message ("Tsconfig not found") doesn't hint that the fix is to change the alias target from `src/` to `dist/`. The natural instinct is to add a `tsconfig.json` to the target package, not to avoid the transform entirely.
