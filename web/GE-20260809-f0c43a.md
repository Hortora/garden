### Symptom
Unit tests against a mock DockviewComponent pass consistently. Every fix deployed to the real app fails. The mock tests give false confidence — they test the code's logic against a fantasy Dockview that doesn't exhibit the real bugs.

### Context
happy-dom provides DOM APIs (`ResizeObserver`, `MutationObserver`, `DragEvent`, `getBoundingClientRect`) but has no CSS layout engine. `getBoundingClientRect()` always returns `{x:0, y:0, width:0, height:0}` regardless of CSS styles. Dockview depends on real element dimensions for: overlay positioning, drag calculations, drop zone detection, container clamping, and floating group layout.

A mock `DockviewComponent` class that reimplements `addPanel`, `removePanel`, `addFloatingGroup` with simple array operations passes every test but doesn't reproduce: CSS anchoring switches, position clamping to container dimensions, smooth-reorder event behaviour, or overlay lifecycle during page teardown.

### Root cause
happy-dom is a DOM API implementation, not a browser rendering engine. It can create elements, fire events, and track the DOM tree, but it cannot compute layout — elements have no dimensions, no position, no CSS cascade.

### Fix
Use Playwright e2e tests for all behaviour that depends on Dockview, DOM layout, or DnD. Keep happy-dom unit tests only for pure logic (math functions, serialization, command dispatch, z-order calculations).

```typescript
// playwright.config.ts — test against the real running app
export default defineConfig({
  testDir: './e2e',
  use: { baseURL: 'http://localhost:8080' },
});

// e2e test — real Dockview, real browser
test('frame position persists across refresh', async ({ page }) => {
  // ... create frame, drag, reload, verify position
});
```

### Why this is non-obvious
happy-dom advertises `ResizeObserver` and `getBoundingClientRect` support — the APIs exist and are callable. The zero return values only matter when the code under test uses them for logic (clamping, positioning). Mock tests pass because the mock skips the code that reads dimensions. The false confidence compounds over time — each "fix" passes tests and fails in production, leading to days of wasted debugging.
