### Symptom
Palette items set with `?draggable=${true}` in a Lit template are not
draggable. The `draggable` property on the DOM element reads `false`.

### Context
Lit's `?` prefix is a boolean attribute directive — it adds/removes the
attribute based on the expression's truthiness. For boolean attributes
like `disabled`, `hidden`, `checked`, presence alone means true.

### Root cause
`draggable` is NOT a boolean attribute — it's an **enumerated attribute**
with three valid values: `"true"`, `"false"`, `"auto"`. When Lit's `?`
adds the attribute, it sets `draggable=""` — an empty string that the
browser interprets as `false`.

### Fix
Use a regular attribute binding with an explicit string value:
```html
draggable=${condition ? 'true' : nothing}
```

Or use the property binding:
```html
.draggable=${condition}
```

Do NOT use:
```html
?draggable=${condition}  // sets draggable="" which is false
```

### Why this is non-obvious
Developers who use `?disabled`, `?hidden`, `?readonly` expect `?draggable`
to work the same way. The HTML spec distinguishes boolean attributes (where
presence = true) from enumerated attributes (where the value matters), but
this distinction is rarely encountered in practice. `draggable` is one of
the few attributes that looks boolean but isn't.
