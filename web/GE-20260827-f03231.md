### Symptom
React Flow's default connection UX requires users to precisely locate and drag from small circular handles at node edges. For auto-layout diagram editors where handle positions don't matter (ELK, dagre), users expect to drag from anywhere on a node to start a connection — and drop anywhere on a target node to complete it.

### Context
Applicable to any React Flow diagram editor using automatic layout where precise handle positioning is irrelevant. The technique works with `connectionRadius={0}` for exact element-based hit detection rather than proximity matching.

### Fix
Create two invisible full-node handles per node type: a **source** handle at `z-index: 2` (on top, initiates connections) and a **target** handle at `z-index: 1` (underneath, receives connections). Both cover 100% of the node's width and height. Hide the default handle dots with CSS.

```tsx
// In the stencil wrapper component:
<Handle
  type="source"
  position={Position.Bottom}
  id={`${type}-source`}
  className="stencil-source-handle"
  style={{
    position: 'absolute', top: 0, left: 0,
    width: '100%', height: '100%',
    zIndex: 2, opacity: 0, border: 'none', background: 'transparent',
    borderRadius: 'inherit', cursor: 'crosshair',
  }}
/>
<Handle
  type="target"
  position={Position.Top}
  id={`${type}-target`}
  style={{
    position: 'absolute', top: 0, left: 0,
    width: '100%', height: '100%',
    zIndex: 1, opacity: 0, border: 'none', background: 'transparent',
    borderRadius: 'inherit',
  }}
/>
```

```css
/* Hide default handle appearance */
.react-flow__handle {
  opacity: 0; width: 1px; height: 1px;
  border: none; background: transparent;
  pointer-events: all;
}

/* Source handle initiates drag */
.stencil-source-handle {
  cursor: crosshair;
  pointer-events: all;
}

/* Disable source handles during connection to allow target handles to receive drops */
.graph-connecting .stencil-source-handle {
  pointer-events: none !important;
  cursor: default;
}
```

During a connection drag, toggle a `.graph-connecting` class on the parent container. This disables `pointer-events` on source handles so that target handles (z-index 1) can receive the drop. Combine with `document.elementsFromPoint()` in `onConnectEnd` for reliable hit detection (see GE-20260827-ed8606).

### Why this is non-obvious
React Flow's handle system is designed around small, precisely-positioned connection points. The documentation doesn't suggest using invisible full-node handles. The z-index layering trick — source on top for drag initiation, target underneath revealed by disabling source pointer-events during drag — requires understanding the interaction between CSS pointer-events, z-index stacking, and React Flow's connection state machine. Without the `.graph-connecting` toggle, the source handle blocks the target handle permanently.

### Alternatives considered
- Using `connectionRadius` with large values — rejected because radius-based matching creates false positives and doesn't respect node boundaries
- Custom drag handlers outside React Flow's connection system — rejected because it bypasses `isValidConnection`, edge type inference, and the built-in connection state machine
- Visible handles at cardinal positions — rejected because auto-layout renders handle positions meaningless, and visible handles add visual clutter
