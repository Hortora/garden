## Technique

Use headless Playwright scripts with `getBoundingClientRect()` measurements to verify layout correctness without manual visual inspection. This approach is more reliable and faster than iterative visual checks during development.

## Pattern

```typescript
import { test, expect } from '@playwright/test';

test('dock layout fills viewport and panels anchor correctly', async ({ page }) => {
  await page.goto('/dashboard');
  
  // Get viewport dimensions
  const viewport = page.viewportSize()!;
  
  // Measure dock root and left panel
  const dockRoot = await page.locator('[data-dock-root]').boundingBox();
  const leftPanel = await page.locator('[data-dock-zone="left-top"]').boundingBox();
  
  // Assertions for layout correctness
  expect(dockRoot!.width).toBe(viewport.width);    // Fills viewport width
  expect(dockRoot!.height).toBe(viewport.height);  // Fills viewport height
  expect(dockRoot!.x).toBe(0);                     // Anchored to top-left
  expect(dockRoot!.y).toBe(0);
  
  // Verify panel positioning within zone
  expect(leftPanel!.x).toBeGreaterThan(0);         // Has some left inset
  expect(leftPanel!.y).toBe(dockRoot!.y);          // Aligned to zone top
  
  // Measure gaps between adjacent panels
  const topPanel = await page.locator('[data-panel="top"]').boundingBox();
  const middlePanel = await page.locator('[data-panel="middle"]').boundingBox();
  const gap = middlePanel!.y - (topPanel!.y + topPanel!.height);
  
  expect(gap).toBe(0); // No gaps between panels (or expect(gap).toBe(8) for intentional spacing)
  
  // Screenshot for visual confirmation
  await page.screenshot({ path: 'layout.png' });
});
```

## Why This Technique

**Advantages:**
- **Automation:** Runs every commit without human eye-strain
- **Precision:** Pixels don't lie — measurements are exact
- **Repeatability:** Same test, same assertions, every time
- **CI/CD friendly:** No screenshots to diff manually
- **Regression detection:** Catches accidental layout shifts immediately

**When to use:**
- Layout structure that must stay stable across releases
- Flex/grid arrangements where gaps matter
- Panel positioning that affects usability (e.g., buttons must be visible at all viewport sizes)

**When not to use:**
- Color/shadow/opacity changes (use visual regression testing instead)
- Subtle animation timing (use performance assertions)

## Measurement Strategy

1. **Anchor point assertions** — verify root element aligns to viewport corners
2. **Sibling gap measurements** — ensure adjacent elements don't overlap or have unintended spacing
3. **Stretch assertions** — check that flex/grid children fill allocated space (`height ≈ parent.height`)
4. **Positioned element checks** — verify absolutely-positioned or grid-placed elements land in expected regions

## Integration with TDD

- **Before implementation:** Write the layout spec as a Playwright test with expected measurements
- **During development:** Run tests frequently to validate layout changes (faster than manual checking)
- **After refactoring:** Regression suite catches accidental layout drifts

## Caveats

- `getBoundingClientRect()` returns viewport-relative coordinates, not document-relative (account for scrolling)
- Measurements depend on viewport size — test at multiple breakpoints if needed
- Timing: ensure elements are rendered before measuring (`await page.waitForLoadState('networkidle')`)
