### Symptom

`buildFlatGraph()` throws:

```
Error: Unable to find task to transition to 'done' from 'checkCondition'
```

The error message suggests a graph-construction bug — it reads as though the SDK can't find a node named 'done' in the graph. The stack trace points to `getNextTask` in `graph-builder.ts`.

### Context

SWF YAML with a `switch` task whose cases use `then:` flow directives:

```yaml
- checkCondition:
    switch:
      - caseA:
          when: "${ .output.status == 'ok' }"
          then: done        # ← this is the problem
      - default:
          then: raiseError
```

### Root cause

The `then:` field in SWF switch cases accepts only:
- `continue` — proceed to the next task in the `do:` array
- `exit` — exit the current scope (try block, for loop)
- `end` — terminate the workflow
- An **exact task name** that exists in the same `do:` array

`done` is not a valid flow directive and there's no task named `done` in the workflow. The SDK validates this during graph construction, but the error message doesn't indicate it's a flow-directive validation issue.

### Fix

Use valid SWF flow directives:

```yaml
- checkCondition:
    switch:
      - caseA:
          when: "${ .output.status == 'ok' }"
          then: continue    # proceed to next step
      - default:
          then: raiseError  # jump to named task
```

### Why this is non-obvious

The error message "Unable to find task to transition to 'done'" reads as a graph-builder internal failure, not as a YAML validation error. A developer's first instinct is to debug the graph construction, not to check whether 'done' is a valid flow directive. The SWF spec documents `then:` values but doesn't prominently warn that arbitrary strings are validated against the task list.

### Why this fix

Using the spec-defined flow directives (`continue`, `exit`, `end`) or exact task names ensures the graph builder can resolve all transitions. The fix is in the YAML source, not in the SDK call.
