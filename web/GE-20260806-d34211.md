### Symptom
`tsc` emits dozens of TS4094 errors: `Property 'X' of exported anonymous class type may not be private or protected.` Every protected state property, abstract method, and inherited Lit lifecycle method triggers the error. The mixin works at runtime but won't compile in a `composite` project.

### Context
A Lit mixin function returns an anonymous class extending the base:

```typescript
export function MyMixin<T extends Constructor<LitElement>>(Base: T) {
  abstract class MixedIn extends Base {
    @state() protected _foo = '';
    protected abstract _bar(): void;
    // ...
  }
  return MixedIn as unknown as Constructor<InstanceType<typeof MixedIn>> & T;
}
```

This pattern works fine with `composite: false`. With `composite: true` (required for TypeScript project references in monorepos), the compiler needs to emit `.d.ts` files — and it cannot represent private/protected members of anonymous classes in declarations.

### What was tried (didn't work)
- Casting the return type as `Constructor<InstanceType<typeof MixedIn>> & T` — still exported anonymous class
- Making the class non-abstract — same error, plus loses the abstract method contract
- Using `skipLibCheck` — only skips `.d.ts` from dependencies, not the project's own output

### Root cause
TypeScript's declaration emitter cannot represent access modifiers (private/protected) on anonymous class types. With `composite: true`, every exported symbol must produce a valid `.d.ts` entry. The anonymous class from the mixin function is exported via the return type, triggering TS4094 for every non-public member — including inherited Lit lifecycle methods like `render`, `willUpdate`, `performUpdate`.

### Fix
Use the standard Lit mixin declaration pattern: a `declare class` interface for the public surface, plus a function overload:

```typescript
// 1. Declare the public interface (no private/protected)
export declare class MyMixinInterface {
  foo: string;           // public props only
  bar(): void;           // public methods only
  get isDirty(): boolean;
}

// 2. Overload signature returns the interface type
export function MyMixin<T extends Constructor<LitElement>>(
  Base: T
): Constructor<MyMixinInterface> & T;

// 3. Implementation (real class with protected/abstract)
export function MyMixin<T extends Constructor<LitElement>>(Base: T) {
  abstract class MixedIn extends Base {
    @state() protected _foo = '';
    protected abstract _bar(): void;
    // ...
  }
  return MixedIn as unknown as Constructor<MyMixinInterface> & T;
}
```

The `declare class` is never instantiated — it exists only for the `.d.ts` output. Protected/abstract methods are omitted from the interface since they're implementation details.

**Trade-off:** Subclasses using `override` on mixin methods that aren't in the interface will get TS4114 (`must have override modifier`) for methods IN the interface but not for methods OUTSIDE it. Remove `override` from methods not in the interface.

### Why this is non-obvious
The standard Lit mixin examples work without `composite` mode. Most TypeScript mixin tutorials use `composite: false`. The error only surfaces when the monorepo uses project references — which is the recommended setup for multi-package repos. The fix requires knowing three separate TypeScript features (declare class, function overloads, constructor type casting) and understanding why they compose to solve the problem.
