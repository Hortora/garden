### Symptom
`Cannot read properties of undefined (reading 'withScope')` when running a step with a `signal:` decorator through the step runner. The deploy step succeeds, but the signal decorator crashes.

### Context
`createStepRunner` in `casehub-entry.ts` constructs the evaluation context as `{ scope } as never` — a type-cast escape hatch that silences the compiler but provides only `scope`. The `Context` interface requires 5 fields: `scope`, `services`, `resolver`, `params`, `stepName`.

The `signal` decorator in `DecoratorChain` accesses `context.resolver.withScope('signal', ...)` to scope signal payload variables. With `resolver` being `undefined`, this crashes.

### Root cause
The `as never` cast hides the incomplete context from the type checker. Any decorator that accesses a context field beyond `scope` crashes at runtime. The `signal` decorator is the first one hit because it's the only commonly-used decorator that accesses `resolver`.

### Fix
Construct a complete context with all required fields:
```typescript
const services = new MapServiceRegistry();
const resolver = new VariableResolver();
// in the loop:
const ctx = { scope, services, resolver, params: {}, stepName: step.name ?? `step-${i}` };
const result = await evaluator.evaluate(step, ctx);
```

### Why this is non-obvious
The `as never` cast means the compiler gives no warning. The error message ("cannot read 'withScope' of undefined") points to the decorator chain internals, not to the context construction. You have to trace from the decorator chain back through the evaluator to the createStepRunner factory to find the incomplete context.
