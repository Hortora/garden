## casehub-pages YAML desugarer drops unknown component props silently

### Stack
casehub-pages TypeScript monorepo — `packages/pages-ui/src/parser/component-desugar.ts`

### Symptom
A new `compositor: true` property added to the `FloatingWorkspaceProps` interface was ignored at runtime. The YAML parsed correctly, the TypeScript compiled, but the prop never reached the activation code.

### Context
The `floating-workspace` component type has a dedicated desugaring block in `component-desugar.ts` (line ~173) that explicitly maps known fields: `centre`, `frames`, `organisers`. Any field not explicitly mapped is silently dropped — no error, no warning, no passthrough.

### What was tried (didn't work)
1. Added `compositor?: boolean` to `FloatingWorkspaceProps` — compiled fine
2. Added `compositor: true` to the YAML — parsed fine
3. Checked activation code — `props.compositor` was always `undefined`
4. Eventually traced through the YAML parser to discover the desugarer

### Root cause
The `component-desugar.ts` desugaring block for `floating-workspace` calls `floatingWorkspace({centre, frames, organisers})` with only the three known fields. The `compositor` field from the raw YAML is never extracted or passed through.

### Fix
Adding a new prop requires updating **three** places:
1. `FloatingWorkspaceProps` interface in `component-props.ts`
2. `FloatingWorkspaceConfig` interface in `types.ts`
3. The desugarer block in `component-desugar.ts` — extract the field from `raw` and pass it to `floatingWorkspace()`

```typescript
// component-desugar.ts — add alongside the organisers extraction
const compositorFlag = (raw as Record<string, unknown>).compositor;
return floatingWorkspace({
  centre,
  ...(frames ? { frames } : {}),
  ...(organisers !== undefined ? { organisers: organisers as boolean } : {}),
  ...(compositorFlag !== undefined ? { compositor: compositorFlag as boolean } : {}),
});
```

And in the builder (`builders.ts`):
```typescript
const props: FloatingWorkspaceProps = {
  centre: config.centre,
  ...(config.frames ? { frames: config.frames } : {}),
  organisers: config.organisers ?? true,
  ...(config.compositor ? { compositor: true } : {}),
};
```

### Why this is non-obvious
The failure is completely silent. TypeScript compiles, YAML parses, no runtime error. The prop just doesn't arrive. The desugarer is an intermediate step that most developers wouldn't know to check — the mental model is "YAML fields become component props" but the desugarer is an explicit whitelist, not a passthrough.

### Alternatives considered
- Making the desugarer a generic passthrough for unknown fields — rejected because it would bypass type safety and allow arbitrary props to reach components
