### Symptom
Clicking a table row fires the `row-activate` event and the component tracks `selectedKeys` correctly, but the table shows no visual row highlighting. No error, no warning.

### Context
Any component using `pages-table` with `.selectedKeys` but without `selection="single"` or `selection="multi"`.

### Root cause
`pages-table` defaults `selection` to `'none'`. The `_isRowSelected()` method gates on `this.selection !== 'none'` before checking `selectedKeys`. The property is accepted and stored but never consulted during rendering.

### Fix
Add `selection="single"` (or `"multi"`) alongside `.selectedKeys`:
```html
<pages-table
  .selectedKeys=${this._selectedKeys}
  selection="single"
  @row-activate=${this._handleRowActivate}
></pages-table>
```

### Why this is non-obvious
The `selectedKeys` property is a reactive Lit property that accepts any array without complaint. A developer reasonably expects that setting it is sufficient for visual highlighting. The `selection` attribute is documented as controlling "selection mode" but reads as optional configuration, not as a hard gate on whether `selectedKeys` has any effect.
