## Symptom

LSP4IJ plugin delivers completions correctly, but IntelliJ's built-in language plugin (e.g. YAML) also contributes items (like `{}`, `[]`) that clutter the completion popup.

## Context

When building an IntelliJ plugin that uses LSP4IJ for language server protocol support, the host language plugin's completions appear alongside LSP completions. For CaseHub YAML files, IntelliJ's YAML plugin adds generic structural items (`{}` for empty mapping, `[]` for empty sequence) that are noise alongside schema-driven LSP completions.

## What was tried (didn't work)

1. **CompletionContributor with `runRemainingContributors`** — blocks LSP4IJ's async completion channel. LSP4IJ sends `textDocument/completion` to the server asynchronously; `runRemainingContributors` runs synchronously and blocks the thread, preventing the async response from resolving.

2. **CompletionContributor with `stopHere()`** — kills ALL contributors including LSP4IJ's own `CompletionContributor`. No completions appear at all.

3. **Custom language/file type (dialect of YAML)** — broke LSP4IJ's completion pathway entirely. LSP4IJ's document tracking depends on the file being associated with a known language.

## Root cause

LSP4IJ's completion mechanism is asynchronous and participates in IntelliJ's `CompletionContributor` chain. Any synchronous interception (runRemainingContributors, stopHere) either blocks the async channel or kills it. There is no LSP4IJ API for exclusive completion mode (unlike formatting, which has `isExistingFormatterOverrideable`).

## Fix

Use `CompletionWeigher` — it only affects sort order, runs AFTER all contributors have finished adding items, and cannot block or interfere with any contributor's pipeline.

```kotlin
class CaseHubYamlCompletionWeigher : CompletionWeigher() {
    override fun weigh(element: LookupElement, location: CompletionLocation): Comparable<*> {
        val file = location.completionParameters.originalFile.virtualFile ?: return 0
        val name = file.name
        if (!name.endsWith(".page.yaml") && !name.endsWith(".dash.yaml")) return 0
        val s = element.lookupString
        if (s == "{}" || s == "[]") return -1
        return 0
    }
}
```

Register in `plugin.xml`:
```xml
<extensions defaultExtensionNs="com.intellij">
    <weigher key="completion"
             implementationClass="io.casehub.intellij.completion.CaseHubYamlCompletionWeigher"
             id="casehubYamlWeigher"/>
</extensions>
```

Items with weight -1 sort below items with weight 0. LSP items (weight 0) appear first; YAML structural items (`{}`, `[]`) sink to the bottom.

### Why this is non-obvious

The natural approach for filtering completions in IntelliJ is `CompletionContributor` — it's the documented API for adding/modifying completion results. But LSP4IJ's async completion model makes all `CompletionContributor` interception approaches fail. `CompletionWeigher` is a different extension point that operates post-collection and is invisible to the contributor pipeline.

### Alternatives considered

- **LSP4IJ feature request** for `isExistingCompletionOverrideable` (analogous to the formatting API) — the right long-term fix but doesn't exist yet
- **CompletionConfidence** — can prevent auto-popup but changes UX (requires explicit Ctrl+Space)
- **LookupManagerListener** — post-hoc filtering at the lookup level, but more complex and fragile
