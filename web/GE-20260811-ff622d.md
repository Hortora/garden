### Symptom
`group.element.querySelector(".dv-floating-titlebar")` returns `null` when trying to inject chrome (close button, pin button, etc.) into a Dockview floating group's titlebar. Chrome injection silently fails — no error, no buttons rendered.

### Context
When Dockview renders a floating group, the DOM hierarchy is:
```
.dv-resize-container
  ├── .dv-floating-titlebar    ← NOT inside .dv-groupview
  └── .dv-groupview            ← group.element points here
```

The titlebar is a **sibling** of the group view inside the resize container, not a child. Code that searches for `.dv-floating-titlebar` from `group.element` will always miss it.

### What was tried (didn't work)
- `group.element.querySelector(".dv-floating-titlebar")` — returns null
- `group.header?.element?.closest?.(".dv-groupview")` then querySelector — same result, stays within the groupview subtree

### Root cause
Dockview's floating overlay host places the titlebar and the group view as sibling children of `.dv-resize-container`. The `group.element` property returns the `.dv-groupview` element, which does not contain the titlebar.

### Fix
Search from the resize container (common ancestor) instead of the group element:

```typescript
const groupEl = group.element ?? group.header?.element?.closest?.(".dv-groupview");
if (!groupEl) return;
const resizeContainer = groupEl.closest(".dv-resize-container") ?? groupEl;
const titlebar = resizeContainer.querySelector(".dv-floating-titlebar");
```

This pattern applies to all operations that need the titlebar: chrome injection, pin state updates, drag lock handlers, and double-click listeners.

### Why this is non-obvious
The Dockview TypeScript API exposes `group.element` as the entry point for DOM access. The assumption that the titlebar is a descendant of the group element is natural — most component libraries nest related elements. The silent failure (querySelector returns null, no error thrown) makes this particularly hard to diagnose.

### Alternatives considered
- Using `group.header?.element` — also doesn't reach the floating titlebar, which is separate from the tab header
- Querying from `document` — works but loses scoping to the specific floating group
