## Symptom

`vite build` fails with `Rollup failed to resolve import "js-yaml"` (then `"marked"`, then `"echarts/core"`) after importing `loadSite` from `@casehubio/pages-runtime`.

## Context

life-ui consumes `@casehubio/*` packages via Vite aliases pointing at `.casehub-packages/packages/` (extracted from a Maven WebJar SNAPSHOT). These aliases resolve at bundle time — npm never sees the `@casehubio` scope. When `loadSite` is imported, Vite follows the module graph into `site.ts` → `content.ts` (marked) → `site.ts` (js-yaml) → `pages-ui` (zod) → `pages-viz` (echarts). Each of these is a real npm package that must be in `node_modules/`.

## What was tried (didn't work)

1. `npm install js-yaml` — fails because npm tries to resolve ALL `@casehubio/*` dependencies first (they're `"*"` in package.json) and gets 404 from the npm registry.
2. `npm install --legacy-peer-deps` — same failure.

## Root cause

`loadSite` is the entry point for the Pages runtime, and `site.ts` imports the entire module surface including YAML parsing (js-yaml), markdown rendering (marked), and chart rendering (via pages-viz → echarts). There is no tree-shaking boundary — importing `loadSite` pulls everything.

## Fix

Manually install each transitive dep via `npm pack` + `tar extract`:

```bash
npm pack js-yaml@4.1.0 --pack-destination /tmp
mkdir -p life-ui/node_modules/js-yaml
tar xzf /tmp/js-yaml-4.1.0.tgz -C life-ui/node_modules/js-yaml --strip-components=1

# Repeat for marked, zod, and echarts (+ echarts transitive deps)
```

This bypasses npm's dependency resolution entirely.

## Why this is non-obvious

The Vite alias pattern works perfectly for `@casehubio` packages — imports resolve at bundle time without npm. The surprise is that `@casehubio/pages-runtime` has third-party transitive dependencies that ARE real npm packages and must be installed separately. The error message (`failed to resolve import "js-yaml"`) doesn't indicate this is a transitive dependency — it looks like a missing direct dependency.
