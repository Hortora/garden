### Symptom
A pages `dataTable` bound to a `restSource` shows "No data" even though the REST endpoint returns a valid response with data. No console errors — the component renders its empty state silently.

### Context
CaseHub engine-rest endpoints (`/api/v1/cases`, `/api/v1/case-definitions`) return paginated responses:
```json
{"items": [...], "page": 1, "size": 20, "totalElements": 6, "totalPages": 1}
```

The pages data pipeline receives this wrapper object rather than the array.

### Root cause
`restSource` fetches the JSON response and passes it directly into the data pipeline. The pipeline expects an array of records. When it receives an object (`{items: [...]}`) instead, it treats it as a single record with keys `items`, `page`, `size` — the `groupBy` lookup finds no matching columns and produces zero rows.

### Fix
Pass `dataPath: "items"` in the `restSource` options to extract the array from the wrapper:

```typescript
rest("cases", "/api/v1/cases", { dataPath: "items", refreshTime: "10second" })
```

This tells the data pipeline to unwrap the response before processing.

### Why this is non-obvious
The dataTable renders correctly with its "No data" empty state — there's no error, no console warning. The REST endpoint returns 200 with valid data. The mismatch between "endpoint has data" and "table shows nothing" points toward a data binding issue, but the actual cause is the response wrapper format — easy to miss when the endpoint works fine in curl.
