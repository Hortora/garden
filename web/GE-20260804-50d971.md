## Symptom

A pages-data-table with `mode=paginated` and 1 row takes 820px, pushing content below it out of viewport

## Context

When using pages-data-table in a flex column layout with multiple tables stacked vertically

## Root Cause

The table's host element has height constraints that apply regardless of display mode. In paginated mode all rows are in DOM so the table should size to content, but it fills the parent instead.

## Fix

Wrap the table in a div with max-height calculated from row count: `max-height: ${rows * rowHeight + headerHeight}px`. Also: the column settings pill feature (`ColumnSettings.pill`) internally replaces all `columnRenderers` — custom renderers and pills cannot coexist.

## Why Non-Obvious

Paginated mode renders all rows without virtualization, so you'd expect it to size to content like a normal table. The height expansion is CSS-internal to the component. The pill/renderer conflict is undocumented — it silently replaces your renderers.
