## Lit @property/@state decorators fail in Vitest unless both esbuild tsconfigRaw AND tsconfig.json set experimentalDecorators

### Symptom
Importing a Lit component with `@property()` or `@state()` decorators in a Vitest test fails with:
```
Error: Unsupported decorator location: field
```
The error points at a CSS line inside `static styles`, not at the actual decorator — misleading the developer away from the real cause.

### Context
A monorepo where other Lit components test fine (their package has the correct config) but a newly-added package with Lit components fails. The package has `vitest.config.ts` with `environment: 'jsdom'` but no decorator configuration.

### What was tried (didn't work)
Adding only the `esbuild.tsconfigRaw` block to `vitest.config.ts` — this alone is insufficient if the package's `tsconfig.json` doesn't also declare `experimentalDecorators: true` and `useDefineForClassFields: false`.

### Root cause
Vitest uses esbuild for TypeScript transformation. Lit's decorators require the legacy TypeScript decorator mode (`experimentalDecorators: true`) plus `useDefineForClassFields: false` (so class fields use `[[Set]]` semantics, not `[[Define]]`, which Lit's reactive system requires). Both must be set in **two places**:

1. `vitest.config.ts` → `esbuild.tsconfigRaw.compilerOptions` (controls the esbuild transform at runtime)
2. `tsconfig.json` → `compilerOptions` (controls IDE type checking and `tsc --build`)

### Fix

In `vitest.config.ts`:
```typescript
export default defineConfig({
  esbuild: {
    target: 'es2022',
    tsconfigRaw: {
      compilerOptions: {
        experimentalDecorators: true,
        useDefineForClassFields: false,
      },
    },
  },
  test: { environment: 'jsdom' },
});
```

In `tsconfig.json`:
```json
{
  "compilerOptions": {
    "experimentalDecorators": true,
    "useDefineForClassFields": false
  }
}
```

### Why this is non-obvious
The error message points at a CSS line inside `static styles`, not at the decorator itself. A developer naturally investigates CSS template issues rather than decorator configuration. The fix requires knowing that Vitest's esbuild transform and TypeScript's compiler have independent decorator settings that must agree — this is not documented in Vitest's Lit integration guides.
