### Symptom

Setting `avatarSpeakingEyeContact: 1.0` in TalkingHead options does not make the avatar consistently look at the camera while speaking. The avatar still glances away after several seconds.

### Context

TalkingHead's `avatarSpeakingEyeContact` parameter appears to control how much the avatar looks at the camera during speech. The documentation suggests values from 0 to 1, implying 1.0 means "always look at camera."

### What actually happens

`avatarSpeakingEyeContact` is used as a **probability weight** (`p:` field) in TalkingHead's internal animation template system. The speaking eye template has:

```javascript
speaking: { alt: [
    {
        p: () => this.opt.avatarSpeakingEyeContact,  // probability of this branch
        dt: [0, [3000,10000,1,2], [2000,5000]],      // timing: start immediately, then after 3-10s allow drift
        vs: { eyeContact: [1, null], ... }            // start with contact, then null (can look away)
    },
    { ... }  // alternative branch: look away
]}
```

Even at `p: 1.0`, the `eyeContact: [1, null]` array means the animation starts with eye contact but transitions to `null` after the first timing phase (3-10s), which allows the eye rotation parameters to take over and move gaze away from camera.

### Fix

Call `lookAtCamera(duration)` explicitly when speech begins:

```javascript
_handleAudioWithHead(header, audioBuf) {
    if (header.turnSeq === this._activeTurnSeq) {
        this._enterFloorState(FloorState.SPEAKING);
        if (this._head && !this._speakingEyeLock) {
            this._speakingEyeLock = true;
            this._head.lookAtCamera(200);
        }
    }
    // ... rest of audio handling
}
```

Reset `_speakingEyeLock` in `_resetTurnState()` so it re-triggers on the next turn.

### Why this is non-obvious

The parameter name and 0-1 range strongly suggest a linear control ("0 = never look, 1 = always look"). The actual behavior — a probability weight feeding a multi-phase animation template with independent timing — is only discoverable by reading TalkingHead's internal animation state machine source code (~line 390-420).
