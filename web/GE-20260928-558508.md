### Symptom
A child web component (e.g. terminal) renders blank after navigation, despite the
parent correctly fetching its configuration data. Works on first load, fails
intermittently on subsequent navigations.

### Context
A Lit component calls two parallel async fetches on property change:
- `_loadRepo()` — sets `_loading = true` immediately, which conditionally removes
  the child element from the template (loading spinner shown instead)
- `_loadTerminal()` — fetches data and sets a `_terminalName` state property

The `updated()` lifecycle method configures the child element when `_terminalName`
changes, using `updateComplete.then(() => querySelector('#child'))`.

### Root cause
When `_loadTerminal()` resolves before `_loadRepo()`:
1. `_terminalName` changes → `updated()` fires
2. `updateComplete.then()` runs → `querySelector` returns **null** (loading spinner
   still showing, child element not in DOM)
3. Configure is skipped; the guard variable (`_lastConfigured`) is NOT updated
4. `_loadRepo()` completes → `_loading = false` → child element appears in DOM
5. `updated()` fires for `_loading` change, but NOT for `_terminalName` (unchanged)
6. No code path triggers configure → child element renders blank

A secondary variant: if the guard variable retains a value from a previous visit
(e.g. navigating A → empty → A), the guard blocks configure even though the DOM
element is brand new.

### Why this is non-obvious
The race is invisible in normal testing because fetch timing varies. The
`updateComplete.then()` pattern is the documented Lit approach for post-render
DOM access, but it only guarantees the current render is complete — it doesn't
account for the element being absent due to a separate async state.

### Fix
Two changes:
1. **Reset the guard on navigation** — clear `_lastConfigured` when the parent
   property changes, ensuring fresh elements always get configured
2. **Add a loading-complete trigger** — check for pending configuration when
   `_loading` transitions to false, not just when the config property changes

```typescript
override updated(changed: Map<PropertyKey, unknown>) {
  if (changed.has('parentProp') && this.parentProp) {
    this._lastConfigured = '';  // reset guard
    this._loadParent();
    this._loadChild();
  }
  if (this._needsConfigure(changed)) {
    this._configureChild();
  }
}

private _needsConfigure(changed: Map<PropertyKey, unknown>): boolean {
  if (!this._childName || this._childName === this._lastConfigured) return false;
  if (changed.has('_childName')) return true;
  if (changed.has('_loading') && !this._loading) return true;
  return false;
}
```

### Alternatives considered
- Using `MutationObserver` to detect when the child element appears — overly complex
  for what is fundamentally a state coordination problem
- Sequencing the fetches (await loadRepo then loadTerminal) — eliminates the race
  but doubles the perceived latency
