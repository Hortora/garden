## Convention

life-ui uses the Pages DSL (`dockWorkbench`, `hostPanel`, `loadSite`) for layout composition rather than building custom Lit layout components. Pages components ARE Lit components underneath — the DSL is a declarative way to compose them with state persistence, deferred rendering, and split resizing built in.

## Rationale

Pages already provides the layout primitives (split, dockBar, hostPanel, LayoutStore, DetachController) as Lit elements. Building a custom `<dock-layout>` Lit component would duplicate split handling, state persistence, and panel toggling that Pages has already implemented and tested. The `dockWorkbench()` builder generates the exact tree structure needed — calling `loadSite(container, workbench, { layoutStore })` renders it with all features working.

## Alternative

Build custom Lit Web Components (`<dock-layout>`, `<dock-panel>`) with CSS grid, custom resize handlers, and localStorage persistence. This gives full control but duplicates ~500 lines of Pages layout infrastructure and loses deferred rendering, detach-to-window, and the exclusive dock bar behaviour.

## When to use

Any CaseHub application (life, AML, clinical, DevTown) that needs a workbench layout should use the Pages DSL, not custom layout components. Custom Lit components are appropriate for domain-specific content panels (e.g. `<morning-briefing>`, `<family-summary>`) — but not for layout composition.
