## xterm.js renders invisible inside Lit shadow DOM — CSS isolation hides viewport

**ID:** GE-20260804-f4e13a
**Stack:** xterm.js 5-6.x, Lit 3.x, shadow DOM

### Symptom

xterm.js terminal renders as a tiny white rectangle (default 80x24) or is completely invisible when hosted inside a Lit web component. The terminal container has correct dimensions (verified via getBoundingClientRect) but the xterm viewport has height 0. The terminal is "there" — cols/rows are computed correctly — but nothing is visible.

### Context

Hosting an xterm.js terminal inside a Lit component that uses shadow DOM (the default). The xterm.css stylesheet is loaded globally via `<link>` in the HTML page or bundled by esbuild. The terminal container div is inside the Lit component's shadow root.

### What was tried (didn't work)

- Setting `.terminal-container { position: absolute; inset: 0; }` — doesn't fix the viewport
- Calling `fitAddon.fit()` manually — computes correct cols/rows but viewport stays at height 0
- Adding `ResizeObserver` — fires correctly but fit() still doesn't render
- Embedding full xterm.css via `unsafeCSS()` in Lit styles — works but is heavy (218 lines)

### Root cause

CSS loaded globally (`<link>` in HTML or bundled CSS) cannot pierce shadow DOM boundaries. xterm.js's `.xterm-viewport` requires `position: absolute; right: 0; left: 0; top: 0; bottom: 0;` from xterm.css to render. Without these styles, the viewport collapses to height 0 and the terminal is invisible. The `.xterm-screen` and canvas elements exist at the right size, but the viewport overlay that shows the content has no positioning.

### Fix

**Option A — inject xterm.css into the shadow root via `<link>`:**

```typescript
override connectedCallback() {
  super.connectedCallback();
  const link = document.createElement('link');
  link.rel = 'stylesheet';
  link.href = 'https://cdn.jsdelivr.net/npm/@xterm/xterm@6.0.0/css/xterm.min.css';
  this.renderRoot.prepend(link);
}
```

**Option B — use a light-DOM terminal component:**

Use a component like PagesTerminal that extends bare `HTMLElement` (no shadow DOM). When placed inside a Lit shadow root, its children are part of the parent's shadow tree, and CSS rules in the parent's `static styles` can reach them via descendant selectors.

### Why this is non-obvious

The terminal "exists" — `fitAddon.fit()` computes correct dimensions, `terminal.cols` and `terminal.rows` are right, the container element has the correct bounding rect. The failure is entirely visual: the viewport overlay has height 0 because it's missing CSS positioning. Nothing errors. The symptom (tiny white box or invisible terminal) points toward xterm configuration, WebGL issues, or container sizing — not CSS isolation.
