### Symptom
After calling `page.setViewportSize()` in Playwright, native browser `<select>` dropdown popups appear inches to the right of where you click on macOS Retina displays. The page content renders correctly but native OS controls are mispositioned.

### Context
Playwright's `setViewportSize()` internally calls Chrome's `Emulation.setDeviceMetricsOverride`, which overrides `deviceScaleFactor` to 1. On a Retina Mac (native DPR 2), this means Chrome renders at 1x but macOS positions native popups at 2x coordinates — creating a 2x offset.

### What was tried (didn't work)
- `Emulation.clearDeviceMetricsOverride` via CDP — Playwright re-applies the override on every navigation/reload
- Setting `deviceScaleFactor: 0` (auto-detect) via CDP — Playwright overwrites it
- Setting `deviceScaleFactor: 2` via CDP — fixes DPR but breaks viewport dimensions, hiding controls
- Page reload — Playwright re-applies cached override

### Root cause
Playwright internally caches the viewport override and re-applies `setDeviceMetricsOverride` after every CDP clear or page navigation. Once `setViewportSize` is called, the DPR override is permanent for that page.

### Fix
Create a new page in the same context — new pages don't inherit the cached device metrics override:

```javascript
const context = page.context();
const newPage = await context.newPage();
await newPage.goto('http://localhost:8090');
await page.close();
// newPage has native DPR (2 on Retina)
```

### Why this is non-obvious
The documentation doesn't mention that `setViewportSize` affects DPR, or that the override is sticky and survives CDP `clearDeviceMetricsOverride`. The symptom (dropdown appears far from click) doesn't obviously point to a DPR issue — you'd naturally suspect CSS positioning.
