## Symptom

YAML property values starting with capital letters silently disappear when a companion `.ts` script is executed in the CaseHub Pages gallery. The YAML parses with an error (`bad indentation of a mapping entry`) but the missing values produce no warning or error in the strip phase.

## Context

The gallery executes companion `.ts` files via a `stripTs()` function that uses regex to remove TypeScript syntax before passing the code to `new Function()`. When YAML content is embedded as a JavaScript string literal (using `\n\` line continuation), the regex operates on the entire source text — including string contents.

## What was tried (didn't work)

1. Embedded YAML content directly in the companion `.ts` file using string literal continuation (`\n\`)
2. The YAML appeared correct in the source file
3. At runtime, values like `Revenue`, `Orders`, `Customers`, `Month` were silently removed
4. No error from stripTs — the stripping happened silently
5. The YAML parser then reported `bad indentation` because `text: Revenue` became just `text` (no value)

## Root cause

The `stripTs()` function includes this regex for removing TypeScript type annotations:

```javascript
.replace(/:\s*(?:readonly\s+)?(?:[A-Z]\w*(?:<[^>]*>)?(?:\[\])?(?:\s*\|\s*\w+(?:<[^>]*>)?)*)/g, '')
```

This matches `: CapitalizedWord` globally — including inside string literals. So `text: Revenue` inside a YAML string gets `Revenue` stripped because the regex sees `: Revenue` as a type annotation (capital R matches `[A-Z]`).

Affected patterns:
- `text: Revenue` → `text` (value gone)
- `source: Month` → `source` (value gone)
- `text: Customers` → `text` (value gone)
- `title: Monthly Sales` → `title` (` Monthly` starts with space + capital M, matches)

## Fix

Do not embed structured text with capitalized values in companion `.ts` files. Instead:

**Option 1 — Hidden DOM elements:** Embed the content in a hidden `<pre>` element in the `.dash.yaml` file, then read it from the DOM:

```html
<!-- In the .dash.yaml content: block -->
<pre id="sample-data" style="display:none">
  text: Revenue
  value: "$48,200"
</pre>
```

```javascript
// In the companion .ts file — stripTs never touches this
var data = (document.getElementById('sample-data') || {}).textContent || '';
```

**Option 2 — Fetch from a separate file:** Store the content in a separate `.yaml` file (in `fixtures/` to avoid the sample generator picking it up) and fetch it:

```javascript
fetch('fixtures/my-content.yaml')
  .then(function(r) { return r.text(); })
  .then(function(text) { (editor as any).value = text; });
```

## Why this is non-obvious

The failure is completely silent. The regex operates on the entire source text with no awareness of string literal boundaries. The values vanish without any error or warning — the only symptom is a downstream YAML parse error with a misleading message about indentation. Debugging requires understanding that `stripTs()` applies TypeScript-stripping regexes to ALL text in the file, not just TypeScript code.

### Alternatives considered

- Quoting all capitalized values in the YAML (`"Revenue"` instead of `Revenue`) — prevents the regex match but fragile and not all YAML contexts use quotes
- Rewriting stripTs to be string-literal-aware — correct fix but high complexity for a gallery utility function
