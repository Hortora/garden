### Symptom
A Lit web component renders content (zone containers, panel holders) that a parent framework
needs to query via `querySelector`. The parent framework uses
`target.querySelector('[data-component-id="inbox"]')` to find elements for event handling,
data pipeline wiring, and state management. Shadow DOM makes these elements invisible to the
parent.

### Context
Building a layout engine component (`<pages-dock-workbench>`) in Lit that renders dock bars,
resize handles, and zone containers. A parent runtime framework fills those containers with
content and later needs to query them by attribute selectors. The component is consumed in
two contexts: (1) inside the parent runtime, where querySelector access is essential, and
(2) inside another Lit component's Shadow DOM (builder-shell), where the consumer provides
its own isolation.

### What was tried (didn't work)
- Shadow DOM with slots: slotted content stays in light DOM (queryable), but the layout chrome
  (dock bars, resize handles) is in shadow DOM. Deferred rendering coordination between the Lit
  component and the parent framework becomes complex — the component must signal when to render
  into slot containers, and the parent must locate the right container.
- Shadow DOM with `composed: true` events: events cross the boundary, but querySelector does not.
  The parent framework's event handlers and state management rely on querySelector to find
  elements by `data-component-id`, which cannot pierce shadow roots.

### Root cause
Shadow DOM's encapsulation is designed to hide component internals from external queries. This
is the right default for UI widgets but the wrong choice for **layout engine** components —
components that render structural containers which a parent framework fills and queries. The
parent needs the same querySelector access it would have without the component boundary.

### Fix
Override `createRenderRoot()` to return `this`, disabling Shadow DOM. The component renders
into its own host element (light DOM). All content is in the main DOM tree, queryable by any
ancestor. Lit's reactive properties, lifecycle hooks, and declarative templates work identically.

```typescript
class MyLayoutComponent extends LitElement {
  createRenderRoot() { return this; }

  // @property, @state, render() all work normally
  // No static styles — use CSS injection instead:

  connectedCallback() {
    super.connectedCallback();
    const root = this.getRootNode() as Document | ShadowRoot;
    if (!root.querySelector('style[data-my-component]')) {
      const style = document.createElement('style');
      style.setAttribute('data-my-component', '');
      style.textContent = `my-component { display: flex; ... }`;
      if (root === document) {
        document.head.appendChild(style);
      } else {
        (root as ShadowRoot).prepend(style);
      }
    }
  }
}
```

Key details:
- **CSS injection replaces `static styles`**: Light DOM has no scoped style support.
  Inject a `<style>` element into the containing root (document or enclosing shadow root)
  with a `data-` attribute for dedup checking.
- **Style selectors use tag name prefix**: `my-component .dock-bar { ... }` scopes styles
  to instances of the component without Shadow DOM encapsulation.
- **Consumer-provided isolation**: If the consumer wraps the light DOM component inside its
  own Shadow DOM (e.g., a builder shell), style isolation comes from the consumer, not the
  layout component.

### Why this is non-obvious
Lit documentation and examples default to Shadow DOM. Developers assume Shadow DOM is
required for Lit components. The `createRenderRoot` escape hatch is documented but the
**judgment of when to use it** — specifically for layout/container components consumed by
non-Lit parent frameworks that rely on querySelector — is not. Most Lit tutorials and
examples show Shadow DOM as the only path, and the CSS injection pattern needed to replace
`static styles` is not covered in standard Lit guidance.

### Alternatives considered
- Shadow DOM + slots — content stays in light DOM (queryable) but deferred rendering
  coordination is complex; the component must signal the parent when to render into
  slot containers, adding a new async protocol
- Shadow DOM + `composed: true` events — events cross the boundary but querySelector
  does not; the parent's state management breaks
- No web component at all — just functions that build DOM. Works but loses Lit's reactive
  properties, lifecycle, and declarative templates
