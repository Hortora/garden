### Symptom

Gesture and mood cues attached to segments with visemes are silently dropped. The avatar speaks with lip sync but never performs gestures (nod, shrug, etc.) or mood transitions during speech, even though the server sends cue data.

### Context

In the audio handler, viseme data and gesture/mood cues are both gated by a `firstChunk` flag tracked via `_turnCuesAttached` set. The intent is: attach visemes and cues only on the first audio chunk per segment.

### Root cause

```javascript
// Viseme attachment block
if (!this._turnCuesAttached.has(key) && seg && seg.visemes && seg.visemes.length > 0) {
    this._turnCuesAttached.add(key);  // ← marks key as attached
    r.words = [...]; r.visemes = [...];
}
// Cue attachment — AFTER viseme block
const firstChunk = !this._turnCuesAttached.has(key);  // ← always false!
```

`firstChunk` is captured **after** `_turnCuesAttached.add(key)` runs in the viseme block above. So for any segment with visemes, `firstChunk` is always `false`, and the cue loop `for (const cue of (firstChunk ? (seg?.cues || []) : []))` iterates over an empty array.

### Fix

Capture `firstChunk` **before** the viseme attachment block:

```javascript
const firstChunk = !this._turnCuesAttached.has(key);
if (firstChunk && seg && seg.visemes && seg.visemes.length > 0) {
    this._turnCuesAttached.add(key);
    r.words = [...]; r.visemes = [...];
}
// Now firstChunk correctly reflects whether this is the first chunk
```

### Why this is non-obvious

The viseme attachment works correctly — lip sync functions. The silent failure only affects gestures and moods, which are secondary and harder to notice. The bug is a subtle ordering dependency between two blocks that share the same tracking set.
