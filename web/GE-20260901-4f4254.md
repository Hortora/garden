## pages-dock-toggle event — undocumented CustomEvent for dock panel activation

### Context
Building a `dockWorkbench` application where the centre panel needs to switch content based on which left dock panel is active. The Pages DSL provides `dockWorkbench()`, `dockBar()`, and `hostPanel()` builders, but no documented API for programmatically detecting dock panel activation.

### Symptom
No API exists on `LiveSite` or any exported type to listen for dock panel open/close events. The `dockWorkbench()` builder returns a `Component` tree — it does not expose an event interface.

### Root cause
Dock panel activation is handled internally by `pages-runtime/src/activation.ts`. When a dock bar button is clicked, the activation code dispatches a `pages-dock-toggle` CustomEvent with `{ bubbles: true, composed: true }` from the dock bar button element (line ~147 in `activation.ts`).

### Fix
Listen for `pages-dock-toggle` on `document` (the event bubbles and crosses shadow DOM boundaries via `composed: true`):

```typescript
document.addEventListener('pages-dock-toggle', (e: Event) => {
  const { panelId, visible } = (e as CustomEvent<{
    panelId: string;
    visible: boolean;
  }>).detail;

  // panelId matches the hostPanel typeName (e.g. 'aml-investigation-nav')
  // visible is true when the panel is being shown, false when hidden
  if (visible && panelId === 'my-panel') {
    // panel is now active
  }
});
```

The `panelId` corresponds to the `typeName` passed to `hostPanel()` in the `dockWorkbench` configuration. The centre panel is a sibling of the dock bar in the component tree — not an ancestor — so the listener must be on `document`, not on the component itself.

### Why this is non-obvious
The `dockWorkbench()` API is purely declarative — `storageKey`, `centre`, `left`, `right`, `bottom`. Nothing in the config or return type suggests an event mechanism. The event name `pages-dock-toggle` appears only in `activation.ts` source code. The payload shape (`{ panelId, visible }`) is not exported as a type.
