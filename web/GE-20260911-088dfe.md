## Context

A ts-morph code generator walks TypeScript types and emits Zod schema code. When types are mutually recursive (e.g. HTN task/method), the generator detects cycles via a `visited` set and emits `z.lazy(() => schemaName)` at the cycle-breaking point. But the referenced `schemaName` variable doesn't exist in the generated output — the type was inlined at its first occurrence, not extracted as a named declaration.

## Technique

Use a `lazyRefs` accumulator map alongside the `visited` set:

```typescript
const lazyRefs = new Map<string, Type>();

// In the cycle detection branch:
if (symbolId && visited.has(symbolId)) {
  lazyRefs.set(symbolName, type);  // record for later declaration
  return `z.lazy(() => ${getSchemaVarName(symbolName)})`;
}
```

After the main schema generation completes, emit top-level declarations for all accumulated lazy references:

```typescript
let prelude = '';
for (const [name, lazyType] of lazyRefs) {
  const lazyVisited = new Set<string>();
  const innerZod = typeToZod(lazyType, 0, lazyVisited);
  prelude += `const ${getSchemaVarName(name)}: z.ZodType<unknown> = z.lazy(() => ${innerZod});\n\n`;
}
return `${header}\n${prelude}export const ${exportName} = ${mainZodCode};\n`;
```

This produces output like:

```typescript
const htnTaskYamlSchema: z.ZodType<unknown> = z.lazy(() => z.object({
  name: z.string(),
  methods: z.array(z.object({
    tasks: z.array(z.lazy(() => htnTaskYamlSchema)),
  })).optional(),
}));

export const htnDocumentSchema = z.object({
  spec: z.object({
    decomposition: z.object({
      root: z.object({
        // ... uses z.lazy(() => htnTaskYamlSchema) where cycle occurs
      }),
    }),
  }),
});
```

## Why this is non-obvious

The natural approach — emitting `z.lazy()` at the cycle point — produces a reference to a variable that doesn't exist. A developer might try to solve this with a two-pass approach (first pass to identify cycles, second to generate), but the accumulator pattern is simpler: let the first pass naturally discover cycles as side effects, then emit the declarations as a prelude. The key insight is that the type stored in the Map can be re-walked with a fresh `visited` set to produce its full inline definition.

### Alternatives considered

- **Two-pass generation** — first pass identifies all recursive types, second pass generates with pre-declared variables. More complex, harder to maintain, and unnecessary since the single-pass accumulator captures the same information.
- **Inline z.lazy() without named variables** — doesn't work for mutual recursion because both types need to reference each other by name.
