## Symptom

When a TypeScript project is cloned into a Claude Code slot without a pre-existing `.idea` directory, IntelliJ MCP symbol search tools return zero results:
- `ide_find_symbol()` returns empty
- `ide_search_text()` returns empty
- `ide_find_file()` returns empty

However, file reading and diagnostics still work:
- `ide_read_file()` returns content
- `ide_diagnostics()` reports errors
- `ide_file_structure()` returns the file tree

## Stack

- IntelliJ IDEA (via MCP)
- TypeScript / JavaScript
- Claude Code slot projects

## Context

Claude Code slot containers (`/Users/mdproctor/claude/casehub/slots/NN/`) are ephemeral. Opening a TS project from a slot without first running IntelliJ to initialize `.idea` causes the IDE index to be empty for search operations, even though the IDE is reading the files.

## Root Cause

IntelliJ's Qdrant-based symbol index requires an initialized IDE project state. When a project is opened for the first time without `.idea`, the IDE creates indexes in memory but may not persist or fully seed them to the MCP layer before search queries arrive. Reading files works because that operation doesn't depend on the symbol index — it reads the filesystem directly.

## Fix

**Workaround — use filesystem scanning for discovery, IntelliJ for reading:**

For symbol discovery in slot TS projects, fall back to filesystem-based tools. Do not attempt `ide_find_symbol()` or `ide_search_text()` on slot-cloned projects without `.idea`.

For reading and understanding code (`ide_read_file()`, `ide_diagnostics()`), use IntelliJ MCP — it works reliably even in slot projects.

**To prevent:** If working with a TS project that will be accessed via MCP, initialize the `.idea` directory before opening in Claude Code. Run IntelliJ's `File > Invalidate Caches > Invalidate and Restart` once to seed the cache.

## Why This is Non-Obvious

The partial functionality (read works, search fails) suggests a permissions or environment issue rather than an initialization problem. The IDE appears operational — it reads files and reports errors. The index appears to exist somewhere (since diagnostics work), just not available for symbol search.

## Constraints

Applies to: TypeScript/JavaScript projects in slot containers opened without pre-existing `.idea` directory. Non-slot projects and projects with `.idea` present are unaffected.

## Alternatives Considered

- Running `ide_reload_project()` after opening (does not always reseed the symbol index)
- Pre-creating a minimal `.idea/modules.xml` (not sufficient; requires full project state)

## Invalidation Triggers

Revisit if IntelliJ MCP adds project initialization hooks or slot-aware cache management.
