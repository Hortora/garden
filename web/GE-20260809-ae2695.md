## Symptom

Setting CSS properties via `el.style.setProperty("gridTemplateRows", "1fr")` silently creates a custom CSS property `--gridTemplateRows` instead of setting the standard `grid-template-rows` property. The layout does not change.

## Stack

- TypeScript / React
- DOM `HTMLElement.style.setProperty()` API
- CSS Grid and Flexbox layout

## Context

Grid and flex layout builders dynamically set CSS properties using JavaScript code. Code uses camelCase names (matching the JavaScript property naming convention), which works fine for direct assignment (`el.style.gridTemplateRows = "1fr"`), but fails silently with `setProperty()`.

## Root Cause

The DOM `setProperty()` method interprets its first argument as a literal CSS property name. JavaScript's camelCase-to-hyphenated conversion happens automatically for direct property assignment (e.g., `el.style.gridTemplateRows`), but `setProperty()` does not perform this conversion — it passes the string literally. `gridTemplateRows` becomes a custom property `--gridTemplateRows` (valid CSS, but not what was intended).

## Fix

Always use hyphenated CSS property names with `setProperty()`:

```typescript
// ❌ Wrong — creates custom property --gridTemplateRows
el.style.setProperty("gridTemplateRows", "1fr");

// ✅ Correct — sets actual grid-template-rows property
el.style.setProperty("grid-template-rows", "1fr");
```

For a reusable helper, convert camelCase to hyphenated:

```typescript
function setCSSProperty(el: HTMLElement, prop: string, value: string) {
  const hyphenated = prop.replace(/([A-Z])/g, "-$1").toLowerCase();
  el.style.setProperty(hyphenated, value);
}

setCSSProperty(el, "gridTemplateRows", "1fr"); // ✅ Works
```

## Why This is Non-Obvious

The JavaScript property access pattern (camelCase) and the `setProperty()` method signature both accept strings, making them appear interchangeable. The automatic camelCase→hyphenated conversion only happens for direct property assignment, not for the `setProperty()` method. The silent failure (custom property is valid CSS) masks the mistake completely.

## Why This Fix

Using hyphenated names directly is explicit and prevents cognitive switching between naming conventions. A helper function makes the fix reusable without template duplication.

## Constraints

Applies to all CSS property setting via `setProperty()`. Direct property assignment (`el.style.prop = value`) works with camelCase and needs no change.

## Alternatives Considered

- Always use direct assignment (`el.style.gridTemplateRows`) instead of `setProperty()` (simpler, but less flexible when property names are dynamic)
- Build a property-mapping dictionary at init time (more overhead, same correctness)

## Invalidation Triggers

None expected — the CSS property name format is stable across all browsers.
