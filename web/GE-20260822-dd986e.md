## PagesElement render gate blocks standalone usage — data property does not bypass

### Symptom
A component extending `PagesEventTimeline` (which extends `PagesElement`) shows the loading skeleton forever when `data` is set directly without setting `props` and having `dataSet` pushed by a host. The component appears to accept data but never renders content.

### Context
When evaluating inheritance from `PagesEventTimeline` for standalone components that self-fetch data (e.g. `BlocksTimeline` with `DataSourceMixin`), the `data` property on `PagesEventTimeline` appears to offer a bypass — set data directly, skip the host-pushed `DataSourceController` pipeline.

### Root cause
`PagesElement.render()` gates content display on three conditions:
```typescript
const showContent = !!this.props && !this.controller.loading && !!this.controller.dataSet;
```
The `data` property is only consumed inside `renderContent()`, which `render()` only calls when `showContent` is true. Without `props` being set and `dataSet` being pushed by the pages runtime host, `renderContent()` never fires — regardless of whether `data` is set.

### Fix
Use composition instead of inheritance. Extract render functions as pure standalone functions (nodes + callbacks → HTML) and import them from both `PagesEventTimeline` (host-pushed data model) and standalone components (self-fetch data model). Each component orchestrates rendering with its own data lifecycle.

### Why this is non-obvious
The `data` property declaration (`@property({ attribute: false }) data?: unknown`) and the code inside `renderContent()` that reads it (`const raw = this.data ?? this._dataSetToNodes(dataset)`) strongly suggest `data` bypasses the `DataSourceController` pipeline. The gate is in `PagesElement.render()` — one level up in the inheritance chain — where `showContent` never becomes true without `props` and `dataSet`.

### Alternatives considered
- Override `render()` in the subclass to bypass the gate — works but requires ~125 lines of bridge code, negating the value of inheritance
- Add a `standalone` mode to `PagesElement` — changes the base class contract for all subclasses
- Require consumers to fetch externally and pass `data` alongside dummy `props`/`dataSet` — works but breaks the existing consumer API
