### Symptom

First test in a `describe` block passes but subsequent tests fail with `undefined` for stencil lookups. `getStencil('type')` returns `undefined` even though `registerStencils()` was called in `beforeEach`.

### Context

Stencil registration functions (e.g. `registerCaseStencils()`, `registerOrgStencils()`) use a module-level `let registered = false` guard to prevent double-registration (which throws "Stencil type already registered"). Tests call `clearRegistry()` in `beforeEach` to reset state between tests, then call the registration function again.

### What was tried (didn't work)

Calling `clearRegistry()` then `registerOrgStencils()` in `beforeEach`. First test passes because `registered` is `false`. All subsequent tests fail because `registered` is still `true` from the first test — the function returns immediately without registering anything into the now-empty registry.

### Root cause

`clearRegistry()` clears the stencil `Map` and edge `Map` in `graph-renderer`, and calls `clearGrammarRegistry()` in `graph-core`. But the module-level `let registered = false` in the registration function file is ES module state — it persists across test invocations within the same vitest process. After the first call sets it to `true`, subsequent calls return immediately even though the registry is empty.

The two state stores (registry Maps and boolean flag) are decoupled — `clearRegistry()` resets one but has no access to the other.

### Fix

Check the registry itself instead of a separate boolean:

```typescript
// Before (broken in tests):
let registered = false;
export function registerOrgStencils(): void {
  if (registered) return;
  registered = true;
  registerStencil({ type: 'org-unit', ... });
  // ...
}

// After (works in tests):
export function registerOrgStencils(): void {
  if (getStencil('org-unit')) return;
  registerStencil({ type: 'org-unit', ... });
  // ...
}
```

This way `clearRegistry()` genuinely resets the guard because the stencil entry is gone from the Map.

### Why this is non-obvious

The `let registered = false` guard pattern is used across multiple stencil packages (`graph-stencil-case` uses it too). It works correctly at runtime (single registration per page load) but fails in tests because `clearRegistry()` and the guard are decoupled. The failure is silent in the first test — only test 2+ fails, making it look like a test ordering issue rather than a state leak. The error message (`expected undefined to be defined`) points at the assertion, not at the registration guard.
