### Symptom

Frame titlebars render but are empty — no close dot, no pin button. The elements exist in the DOM (`.dv-floating-titlebar`) but have zero children.

### Context

The DockviewBackend's `injectFrameChrome` runs inside `renderFrame()` immediately after `dockview.addPanel()`. It queries `group.element` for the titlebar. If the Dockview DOM hasn't fully rendered yet, `group.element` or the titlebar query returns null, and the function silently returns without injecting any buttons.

The same problem recurs after hide/show: `engine.showFrame()` re-renders the floating group via the backend, creating a fresh DOM with empty titlebars.

### Root cause

No retry mechanism. The function checks `group.element → querySelector('.dv-floating-titlebar')`, and if either is null, exits silently. Dockview creates the floating group asynchronously — the DOM element exists but the titlebar may not be attached yet.

### Fix

In the host component, add `_ensureFrameChrome()` that scans for empty titlebars and injects buttons. Call it after a double-`requestAnimationFrame` delay from both `createFrame` and `showFrame`:

```typescript
requestAnimationFrame(() => requestAnimationFrame(() => this._ensureFrameChrome()));
```

The method scans all `.dv-floating-titlebar` elements, skips any that already have a `.frame-close-dot`, and injects buttons into empty ones. It maps each titlebar back to its frame key via the Dockview floating group's panel params.

### Why this is non-obvious

No error is thrown. The titlebars render — they're just empty. The backend's `injectFrameChrome` appears to run (it's called from `renderFrame`), but its early return is silent. The timing dependency on Dockview's async DOM creation isn't documented.
