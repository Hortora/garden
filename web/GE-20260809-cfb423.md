## Convention

The dock system uses a deliberate naming convention for zone IDs that differs between side columns and the bottom bar:

**Side columns (left / right):** `{side}-{position}` format
- `left-top` — top zone within the left column
- `left-bottom` — second zone within the left column (not the bottom bar!)
- `right-top` — top zone within the right column
- `right-bottom` — second zone within the right column

**Bottom bar (full-width horizontal):** `{position}-{side}` format
- `bottom-left` — left side of the bottom bar
- `bottom-right` — right side of the bottom bar

The word-order reversal is intentional: side columns are named for their vertical structure (which side, then which position in that side), while the bottom bar is named for its horizontal structure (position in the bar, then which side).

## Rationale

This convention optimizes for the most common cognitive model in each context:

- **In side columns:** "I have three zones in the left column" → naturally think "{left}-{position}"
- **In bottom bar:** "I have zones distributed across the bottom" → naturally think "{position}-{bottom}"

The reversal minimizes the number of times a developer consciously maps between layout concept and zone ID. It is a trade-off: uniform naming (e.g., all `{side}-{position}`) would be simpler, but less aligned with how developers think about these regions.

## Valid Alternatives

Other projects use equally valid naming schemes:

- **Uniform format:** `{side}-{ordinal}` (e.g., `left-1`, `left-2`, `bottom-left`) — more consistent but less semantic
- **Abbreviated:** `{side}{position}` (e.g., `lt`, `lb`, `br`) — compact but cryptic
- **Positional:** `{x}-{y}` (e.g., `left-middle`, `bottom-center`) — evocative but less precise for zones

## When to Apply This Convention

Use this naming convention for dock systems where:
1. Side columns can have multiple stacked zones
2. A distinct bottom bar exists with left/right subdivisions
3. Developers need to conceptually separate "zones within a side" from "sides of a bar"

For simpler layouts (e.g., single zone per side, no bottom bar), simpler naming works fine.

## Caveats

- The reversal is a source of confusion — expect developers to mix up `left-bottom` and `bottom-left` initially
- Documentation should prominently clarify the convention (see GE-20260809-aee002 for gotcha and example)
- Automated tooling (linters, type checkers) can help catch zone ID mismatches early
