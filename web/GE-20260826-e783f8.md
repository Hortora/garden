### Symptom
A layout strategy (tabbed, accordion, etc.) needs to fire a DOM event carrying a reference to its parent Container, but the strategy is created independently — it has no reference to its parent.

### Context
In a recursive container model where Container creates a LayoutStrategy via a factory function, the strategy receives callbacks but no back-reference to its Container. When the strategy detects a user gesture (e.g. tab drag start), a DOM event must fire with `sourceContainer` in the detail so ancestor handlers can identify the source.

### What was tried
Attempting to fire the event from within the strategy itself fails because the strategy has no `Container` reference to include in the event detail.

### Root cause
The strategy is intentionally decoupled from its parent Container. The event must be dispatched from the Container's callback wrapper, which has access to both the callback arguments and the Container instance (`group`).

### Fix
Intercept the strategy's callback in the Container's `wrappedCallbacks()` function and dispatch the DOM event from there:

```typescript
function wrappedCallbacks(): LayoutCallbacks {
  return {
    onTabDragStart: (key, ghost) => {
      config.callbacks?.onTabDragStart?.(key, ghost);
      organiserContainer?.dispatchEvent(new CustomEvent("pages-tab-drag-start", {
        bubbles: true,
        detail: { tabKey: key, ghost, sourceContainer: group },
      }));
    },
  };
}
```

The forward reference to `group` (a `const` defined later in the same function scope) works because the callback closure is only *called* during user interaction — well after `group` is fully initialized. JavaScript const declarations are hoisted but the temporal dead zone only matters at declaration time, not at closure invocation time.

### Why this is non-obvious
The instinct is to fire the event from where the gesture is detected (inside the strategy). The correct dispatch point is the Container's callback layer — one abstraction level up from where the gesture occurs. The forward-reference timing is safe but looks wrong at first glance.
