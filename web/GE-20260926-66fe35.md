### Symptom

A REST endpoint returns records with nested object fields (e.g. a
polymorphic `BridgeMessage` payload). The data loads into a `pages-table`
via `pages-event-trail`. Column values display correctly for scalar
fields, but `getRowDetail` receives `TypedRow` where the nested payload
field contains the string `"[object Object]"` instead of the original object.

### Context

`pages-data`'s `fromRows()` function converts raw entries to `TypedDataSet`.
Each cell value is mapped to a `CellValue` — one of TEXT, NUMBER, DATE,
LABEL, or NULL. Values that don't match these types are converted via
`String()`, which produces `"[object Object]"` for any object or array.

### Root cause

The `CellValue` type system is deliberately scalar — it supports table
display, sorting, and filtering. Complex objects don't fit the model
and are silently converted to their string representation.

### Fix

Maintain a `WeakMap<TypedRow, unknown>` that maps each row to its
corresponding raw entry. Build the map during filter application
using index correspondence — the i-th row in the TypedDataSet
corresponds to the i-th entry in the filtered raw array.

Pass the raw entry to consumers via a wrapper function:

```typescript
@state() private _rawEntryByRow = new WeakMap<TypedRow, unknown>();

// In _applyFilters(), after building filteredDataSet:
for (let i = 0; i < filteredDataSet.rows.length; i++) {
  const row = filteredDataSet.rows[i];
  if (row) this._rawEntryByRow.set(row, filtered[i]);
}

// Wrap getRowDetail to inject the raw entry:
const wrapped = (row: TypedRow) =>
  this.getRowDetail!(row, this._rawEntryByRow.get(row));
```

### Why this is non-obvious

The conversion is silent — no warning, no error. Scalar fields work
perfectly, so the issue only surfaces when a detail renderer tries
to access a nested field. The `TypedRow` API has no method to retrieve
the original value, making the data loss invisible until render time.
