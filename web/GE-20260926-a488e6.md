### Context

When a `pages-data` pipeline converts raw entries to `TypedDataSet` via
`fromRows()`, complex objects in the entries are destroyed by `CellValue`
conversion (see GE-20260926-66fe35). Detail renderers that need access
to polymorphic payloads, nested objects, or type-discriminated unions
cannot retrieve them from `TypedRow`.

### Technique

Use a `WeakMap<TypedRow, unknown>` as a side channel that preserves
the mapping between TypedRow objects and their corresponding raw entries.
The map is rebuilt each time the data pipeline re-filters, using index
correspondence.

```typescript
@state() private _rawEntryByRow = new WeakMap<TypedRow, unknown>();

// After filtering and building filteredDataSet:
this._rawEntryByRow = new WeakMap();
for (let i = 0; i < filteredDataSet.rows.length; i++) {
  const row = filteredDataSet.rows[i];
  if (row) this._rawEntryByRow.set(row, filtered[i]);
}
```

The `getRowDetail` callback signature gains an optional second parameter:

```typescript
getRowDetail?: (row: TypedRow, rawEntry?: unknown) => TemplateResult | undefined;
```

A wrapper function injects the raw entry before passing to `pages-table`:

```typescript
const wrappedDetail = this.getRowDetail
  ? (row: TypedRow) => this.getRowDetail!(row, this._rawEntryByRow.get(row))
  : undefined;
```

### Why this is non-obvious

The natural approach is to use `TypedRow` for everything — it's the
pipeline's output type and what `pages-table` passes to callbacks.
The WeakMap bypass is necessary only because `CellValue` is deliberately
scalar. Using WeakMap (not Map) ensures rows that leave the dataset
through re-filtering are garbage collected — no memory leak. The
second parameter is optional and non-breaking for existing consumers.
