### Symptom
Type error when assigning `{ parentId: parentId ?? undefined }` to a type with `parentId?: string`:
```
Type 'string | undefined' is not assignable to type 'string'.
```

### Context
Building a `GraphNode` object from React Flow's `NodeProps` where `parentId` may be `undefined`. The target interface declares `parentId?: string` (optional, but when present must be `string`).

### Root cause
With `exactOptionalPropertyTypes: true`, TypeScript distinguishes between "property absent" and "property present with value `undefined`". The expression `parentId ?? undefined` always includes the key — it is present with value `undefined`, which violates `parentId?: string`.

### Fix
Use conditional spread to omit the key entirely when the value is undefined:
```typescript
const graphNode: GraphNode = {
  id,
  type: type ?? '',
  ...(parentId ? { parentId } : {}),
  properties: data as Readonly<Record<string, unknown>>,
};
```

### Why this is non-obvious
The `?? undefined` fallback pattern is idiomatic JavaScript for "use the value or default to undefined". Under `exactOptionalPropertyTypes`, this silently creates a type violation that has no runtime effect — the resulting object behaves identically. The fix (conditional spread) is noisier but type-correct.
