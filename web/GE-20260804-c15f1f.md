### Symptom
CSS `:host([mode="scroll"])` selector has no effect on a Lit web component even though
the `mode` property is set to `"scroll"` at runtime.

### Context
Lit `@property({ type: String })` creates a reactive property that **accepts** values
from an HTML attribute but does NOT **reflect** property changes back to the attribute.
Many frameworks (React, Angular) auto-sync properties and attributes. Lit does not.

### Root cause
Lit's `reflect` option defaults to `false`. When `reflect` is false, setting
`this.mode = 'scroll'` updates the internal property but the DOM attribute stays absent.
CSS attribute selectors like `:host([mode="scroll"])` match on DOM attributes, not
JavaScript properties — so the selector never matches.

### Fix

```typescript
@property({ type: String, reflect: true }) mode: DisplayMode = 'auto';
```

Now property changes write back to the DOM attribute, and CSS attribute selectors work.

### Why this is non-obvious
Many developers expect String-typed properties to auto-reflect — the pattern works in
other frameworks. Lit's default is intentional (performance: fewer DOM writes) but the
silent failure makes it hard to diagnose. The CSS selector doesn't error or warn; it
simply never matches.
