## exactOptionalPropertyTypes blocks undefined assignment to optional fields — use delete

### Stack
TypeScript 5 with `exactOptionalPropertyTypes: true` in tsconfig

### Symptom
`TS2412: Type 'undefined' is not assignable to type 'CompositorState' with 'exactOptionalPropertyTypes: true'. Consider adding 'undefined' to the type of the target.`

### Context
When clearing an optional property after consuming its value (e.g. `wsRef.compositorStash = undefined` after restore), TypeScript rejects the assignment because `exactOptionalPropertyTypes` distinguishes between "property is absent" and "property is present with value undefined".

### Root cause
With `exactOptionalPropertyTypes`, `field?: T` means the field can be absent but cannot be explicitly set to `undefined`. The type is `T` when present, not `T | undefined`. Assigning `undefined` violates the type.

### Fix
Use `delete` instead of assigning `undefined`:

```typescript
// Bad — TS2412
wsRef.compositorStash = undefined;

// Good
delete wsRef.compositorStash;
```

### Why this is non-obvious
Most TypeScript developers treat `field?: T` as equivalent to `field: T | undefined`. The `exactOptionalPropertyTypes` flag breaks that mental model. The error message suggests adding `undefined` to the type union, but that defeats the purpose of the flag — `delete` preserves the intent.
