### Symptom
`ReferenceError: ResizeObserver is not defined` thrown from `connectedCallback` when
a Lit component that creates a `ResizeObserver` is appended to the DOM in a vitest test.
The error names the missing constructor but gives no guidance on why it's absent or how
to provide it.

### Context
jsdom does not implement the `ResizeObserver` API (nor `IntersectionObserver`). Lit
components that observe element dimensions — common for responsive layouts, canvas
sizing, or panel resizing — fail immediately when mounted in vitest's jsdom environment.

### Root cause
jsdom implements a subset of browser APIs. `ResizeObserver` is not part of that subset.
The `ReferenceError` fires at the point of `new ResizeObserver(...)` — typically in
`connectedCallback` — which means the component cannot be tested by mounting it to the DOM.

### Fix
Stub `ResizeObserver` as a no-op class in `beforeAll`:

```typescript
beforeAll(() => {
  if (typeof globalThis.ResizeObserver === 'undefined') {
    (globalThis as any).ResizeObserver = class {
      observe() {}
      unobserve() {}
      disconnect() {}
    };
  }
});
```

For components with heavy imperative DOM (e.g. `createRenderRoot` with innerHTML), even
the stub may not be enough — jsdom's DOM manipulation can cause `NotFoundError` during
cleanup. In that case, test the class API without mounting:

```typescript
it('exports expected API', async () => {
  const { MyComponent } = await import('./my-component.js');
  const proto = MyComponent.prototype;
  expect(typeof proto.configure).toBe('function');
});
```

### Why this is non-obvious
The error message (`ReferenceError: ResizeObserver is not defined`) is clear about *what*
is missing but not *why*. A developer unfamiliar with jsdom's API surface might assume
the import is wrong or the test setup is misconfigured, rather than recognising that
jsdom simply doesn't implement this browser API.

### Alternatives considered
- **happy-dom** — provides ResizeObserver natively, but has other compatibility gaps with Lit's rendering model
- **@playwright/test** — full browser environment, but much heavier for unit tests
- **vitest browser mode** — runs in real browser, avoids all jsdom gaps, but slower and requires browser binary
