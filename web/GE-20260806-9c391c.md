### Symptom
`TypeError: Cannot read properties of undefined (reading 'find')` when test code calls `this._dockview.panels.find(...)`.

### Context
Testing a Lit component that wraps `DockviewComponent`. happy-dom doesn't support `ResizeObserver`, so Dockview can't fully initialize. A mock class replaces `DockviewComponent` with basic `addPanel`/`removeGroup`/`dispose`/`onDidLayoutChange` methods. Code that accesses properties not in the mock crashes silently.

### Root cause
The mock only implements the methods the initial implementation needed. As features grow (e.g. closing individual tabs via `panels.find(p => p.id === name).api.close()`), the mock falls behind. No TypeScript error because the component uses `any` typing for the Dockview instance.

### Fix
Use optional chaining for any Dockview API property access that might not exist in tests:

```typescript
// Bad — crashes in test mock
if (this._dockview) {
  const panel = this._dockview.panels.find(p => p.id === name);
}

// Good — safe against incomplete mock
if (this._dockview?.panels) {
  const panel = this._dockview.panels.find(p => p.id === name);
}
```

The mock provides: `constructor`, `dispose()`, `onDidLayoutChange()`, `addPanel()`, `removeGroup()`. Everything else (`panels`, `groups`, `api`, `activePanel`, etc.) is undefined.

### Why this is non-obvious
The code works correctly at runtime with the real `DockviewComponent`. The crash only appears in tests. Since the mock uses a class (not an interface), TypeScript doesn't flag missing properties — they're just `undefined` at runtime.
