## Symptom

esbuild error during Vite dev server startup:

```
Cannot read file: /project/node_modules/reactjsx-runtime
```

Note `reactjsx-runtime` — the `/` between `react` and `jsx-runtime` is missing.

## Context

Vite config uses regex aliases to deduplicate React across a monorepo:

```typescript
{ find: /^react\//, replacement: resolve(__dirname, '../node_modules/react/') },
```

The intent is to redirect `react/jsx-runtime` to `../node_modules/react/jsx-runtime`.

## Root cause

`path.resolve()` normalises paths and **strips trailing slashes**. So `resolve(__dirname, '../node_modules/react/')` returns `.../node_modules/react` (no trailing `/`).

When Vite's regex alias matches `react/` in `react/jsx-runtime`, it replaces the matched portion with the resolved path (no trailing `/`). The remainder `jsx-runtime` is appended directly, producing `reactjsx-runtime`.

## Fix

Use a capture group instead of relying on the trailing slash:

```typescript
{ find: /^react\/(.*)/, replacement: resolve(__dirname, '../node_modules/react') + '/$1' },
{ find: /^react-dom\/(.*)/, replacement: resolve(__dirname, '../node_modules/react-dom') + '/$1' },
```

The `+ '/$1'` is appended as a string literal after `resolve()`, so the slash is preserved.

### Alternatives considered

- Using `path.join` instead of `path.resolve` — also strips trailing slashes.
- Hardcoding absolute paths without `resolve` — fragile, breaks when project moves.

## Why this is non-obvious

The error message (`Cannot read file: reactjsx-runtime`) gives no indication that the problem is a missing `/`. The path looks like a typo or a completely wrong module name. The connection between `path.resolve()` stripping a trailing slash and the module resolution failure is invisible without stepping through the alias replacement logic.
