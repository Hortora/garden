## Symptom

Panels rendered into dock slots do not stretch to fill available height, even when their parent is a flex-column with `flex: 1`. The slot container remains at its intrinsic content height, leaving empty space below.

## Stack

- TypeScript / React
- CSS Flexbox layout
- `renderNode()` slot renderer
- casehub-pages tool-window system

## Context

Dock zones are flex-column containers that should stretch to fill the available vertical space. When panels are rendered into `[data-slot]` containers within these zones, the panels should expand to fill their allocated flex space.

## Root Cause

`renderNode()` creates plain `<div>` elements for slot containers with no CSS styling. Plain divs are not flex items by default and don't participate in flex layout. The slot remains at its intrinsic height (content height), breaking the flex chain from the zone down to the panel's content.

## Fix

Set explicit flex styling on slot containers when the parent is a flex-column:

```typescript
function renderNode(slot: SlotNode): HTMLElement {
  const container = document.createElement("div");
  container.setAttribute("data-slot", slot.id);
  
  // Add flex styling to participate in flex layout
  container.style.display = "flex";
  container.style.flexDirection = "column";
  container.style.flex = "1";
  container.style.minHeight = "0"; // Critical: allows flex shrinking
  
  // Render children...
  return container;
}
```

The `min-height: 0` is critical — flex containers need an explicit min-height to allow shrinking below content height.

## Why This is Non-Obvious

Flex layout requires explicit styling at each level of the hierarchy. A plain `<div>` looks like it should participate in layout but doesn't. Setting `flex: 1` on the parent is not enough; the intermediate container must also declare itself as a flex item and flex container.

## Why This Fix

The slot container must be both a flex item (within its parent zone) and a flex container (for its own children). This is the only way to maintain the flex height chain and allow content to expand/shrink with available space.

## Constraints

Applies when: slot containers have a flex-column parent. Slot containers with static or grid parents may require different styling.

## Alternatives Considered

- Setting `height: 100%` on the slot (breaks flex semantics; doesn't respond to sibling sizes)
- Letting the parent explicitly size the slot in CSS (requires coupling parent to slot count and layout)

## Invalidation Triggers

Revisit if `renderNode()` refactored to use a different base element type (e.g., custom web component).
