### Symptom
Gallery companion `.ts` scripts silently fail at runtime — buttons don't attach listeners, variables are undefined. No build error, no console error about TypeScript syntax — the script just doesn't execute.

### Context
The Pages examples gallery compiles companion `.ts` files at runtime using `new Function(stripTs(code))`. The `stripTs` function uses regex to remove TypeScript syntax before `eval`-ing the result as JavaScript.

### Root cause
The `stripTs` regex `:\s*(?:readonly\s+)?(?:[A-Z]\w*...)` matches `: UpperCamelCase` patterns as TypeScript type annotations and strips them. This inadvertently strips:

1. **Uppercase constant names in object properties**: `{ value: SAMPLE_CONTENT }` becomes `{ value }` (shorthand property), causing `ReferenceError: value is not defined`
2. **Lowercase type annotations**: `: any`, `: number`, `: string` are NOT matched (regex requires uppercase first letter), causing `SyntaxError: Unexpected token ':'`

### What was tried (didn't work)
- Adding TypeScript type annotations to companion `.ts` files (natural for TS) — silently broken at runtime
- Using `var activeSession: any = null` — survives compilation but fails at `eval`

### Fix
Write companion `.ts` scripts in a style that survives `stripTs`:
- Use `camelCase` variable names, never `UPPER_CASE` constants
- Never use lowercase type annotations (`: any`, `: number`) — only `as Type` casts survive (stripped by a separate regex)
- Never use `catch (e: any)` — use `catch (e)` instead

### Why this is non-obvious
The stripTs regex is designed to remove TypeScript syntax, but its UpperCamelCase heuristic has false positives on JavaScript identifiers. The failure is silent — no error about TypeScript, just a missing variable at runtime.
