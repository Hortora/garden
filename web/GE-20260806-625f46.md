### Symptom

Need to add hover behaviour (mouseenter/mouseleave with delay timer) to
Dockview tab elements for a flyout tooltip, but Dockview renders tabs
internally — no direct access to tab DOM elements.

### Context

Dockview v7 uses floating groups with title bars and tab strips. The tab
elements are created inside Dockview's DOM structure. Common approaches
(MutationObserver, event delegation with mouseover) are fragile and break
when Dockview restructures its DOM.

### What was tried (didn't work)

- MutationObserver on `.dv-tabs-container` — works but brittle, requires
  cleanup, and misses tabs created during rapid group changes
- Event delegation with `mouseover` on the Dockview container — `mouseenter`
  doesn't bubble, `mouseover` fires on child elements requiring manual
  enter/leave tracking

### Root cause

Dockview provides `createTabComponent` in `DockviewFrameworkOptions` — a
factory that returns an `ITabRenderer` for each panel's tab. This is the
intended extension point but is not prominently documented.

### Fix

Pass `createTabComponent` in the `DockviewComponent` constructor options:

```typescript
this._dockview = new DockviewComponent(container, {
  createTabComponent: (options) => {
    const tabEl = document.createElement('div');
    tabEl.className = 'custom-tab';
    let hoverTimer: ReturnType<typeof setTimeout> | null = null;

    tabEl.addEventListener('mouseenter', () => {
      hoverTimer = setTimeout(() => {
        this._showFlyout(options.id, tabEl);
      }, 300);
    });
    tabEl.addEventListener('mouseleave', () => {
      if (hoverTimer) { clearTimeout(hoverTimer); hoverTimer = null; }
      this._hideFlyout();
    });

    return {
      element: tabEl,
      init(params) { tabEl.textContent = params.title ?? options.id; },
      update(event) { if (event.params?.title) tabEl.textContent = event.params.title; },
      dispose() { if (hoverTimer) clearTimeout(hoverTimer); },
    };
  },
  createComponent: (options) => { /* panel content renderer */ },
});
```

The `ITabRenderer` interface requires `element` (HTMLElement) and `init(TabPartInitParameters)`.
Optional: `update`, `dispose`, `layout`, `toJSON`, `focus`. Dockview handles
click-to-select and drag-to-rearrange — the custom tab only needs to render
the label and handle hover.

`options.id` is the panel's unique ID (the terminal name in this case).
`params.title` is the panel's display title.

### Why this is non-obvious

Most developers would reach for DOM observation or event delegation because
`createTabComponent` is buried in `DockviewFrameworkOptions` alongside
`createComponent` and `createRightHeaderActionComponent`. The Dockview docs
emphasise the React/Vue wrappers which have different APIs. The vanilla TS
factory approach using `ITabRenderer` is the correct extension point for
non-framework usage.
