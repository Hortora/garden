## z.intersection() over .merge() for widened ZodType composition

### Symptom

Composing two Zod schemas via `.merge()` fails at compile time with a TypeScript error — `.merge()` is not a method on `z.ZodType`.

### Context

A schema registry interface declares `documentSchema: z.ZodType` (the widened base type) to accept any Zod schema shape. When composing a language-layer schema with a format-specific schema, `.merge()` is the natural Zod API for combining object schemas.

```typescript
interface FormatRegistration {
  documentSchema: z.ZodType;  // widened — accepts ZodObject, ZodUnion, etc.
}
```

### What was tried (didn't work)

```typescript
// Fails: Property 'merge' does not exist on type 'ZodType'
documentSchema: yamlCoreSchema.merge(dashboardSchema),
```

`ZodObject.merge()` requires a `ZodObject` argument. When `dashboardSchema` is exported as `z.ZodType` (common for registry interfaces that need to accept unions, intersections, etc.), `.merge()` is not available on the widened type.

### Root cause

Zod's `.merge()` is defined only on `ZodObject`, not on the base `ZodType`. Schema registries commonly widen to `z.ZodType` for flexibility (to accept discriminated unions, lazy schemas, etc.). This makes `.merge()` unavailable even though both schemas are structurally objects.

### Fix

Use `z.intersection()` which works with any `ZodType`:

```typescript
documentSchema: z.intersection(yamlCoreSchema, dashboardSchema),
```

The schema-navigation engine must handle `ZodIntersection` — walking both the left and right sides when resolving paths. In a well-built schema walker, this is already supported:

```typescript
} else if (tn === 'ZodIntersection') {
  const def = current._def as { left: z.ZodType; right: z.ZodType };
  const left = navigateSchema(def.left, [key], siblings);
  if (left) { current = left; continue; }
  const right = navigateSchema(def.right, [key], siblings);
  if (right) { current = right; continue; }
  return null;
}
```

### Why this is non-obvious

`.merge()` is the documented, ergonomic API for combining Zod objects. The failure only surfaces when schemas are exported through a widened interface (`z.ZodType`), which is common in registry patterns but not in typical application code. The fix — `z.intersection()` — is less commonly shown in Zod examples but is the correct abstraction for composing schemas of unknown shape.
