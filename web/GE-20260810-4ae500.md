### Symptom
A `position:absolute;inset:0` overlay renders at the height of its sibling
content (e.g. 85px for a short markdown paragraph) instead of filling the
full available flex space (e.g. 493px in a dock-workbench centre).

### Context
Parent chain: flex container → flex child (implicit height) → absolute overlay.
The flex child's height is determined by content, not by available space,
because it lacks `height:100%` or `flex:1`. The absolute overlay resolves
`inset:0` against the flex child's actual height, not the available space.

### Root cause
CSS absolute positioning resolves against the containing block's dimensions.
If the containing block (the `position:relative` parent) hasn't been given
explicit sizing within the flex layout, it collapses to content height.

### Fix
Make the parent stretch to fill available flex space before the overlay resolves:

```typescript
el.style.position = "relative";
el.style.height = "100%";
el.style.display = "flex";
el.style.flexDirection = "column";
el.style.minHeight = "0";

// Centre content fills remaining space
centreContainer.style.flex = "1";
centreContainer.style.minHeight = "0";
```

### Why this is non-obvious
`position:absolute;inset:0` reads as "fill the parent" and works when the
parent has explicit dimensions. In a flex layout where the parent's height
is implicit, it silently collapses. The visual result (content renders but
is cramped) doesn't immediately suggest a CSS containment issue — it looks
like a content overflow problem.
