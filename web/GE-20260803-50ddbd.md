### Context

React Flow custom nodes must be React components. A Lit-based project (like CaseHub blocks-ui) wants to author node visuals as lit-html templates so they stay framework-agnostic and reusable in palette/panel contexts outside React Flow.

### Technique

Create a ~20 LOC React wrapper that bridges any lit-html render function into a React Flow-compatible node component:

```tsx
import React, { useRef, useEffect } from 'react';
import { render as litRender, type TemplateResult } from 'lit-html';

type StencilRenderFn = (data: Record<string, unknown>) => TemplateResult;

function createReactNodeType(
  renderFn: StencilRenderFn,
): React.FC<{ data: Record<string, unknown> }> {
  return function LitNodeWrapper({ data }) {
    const containerRef = useRef<HTMLDivElement>(null);
    useEffect(() => {
      if (containerRef.current) {
        litRender(renderFn(data), containerRef.current);
      }
    }, [data]);
    return <div ref={containerRef} />;
  };
}
```

Register stencils by wrapping their render functions:
```typescript
registerNodeType({
  type: 'binding',
  component: createReactNodeType(renderBinding),
});
```

Stencil authors write pure lit-html templates. They never import React. The bridge handles mounting, updating, and unmounting. The stencil templates use inline styles and CSS custom properties for styling (required because they render in light DOM inside the React Flow canvas).

### Why this is non-obvious

The natural approach is to write React components directly for React Flow nodes. The bridge adds a layer — but it keeps the stencil definitions usable outside React Flow (in Lit palette components, property panel previews, and future non-React renderers like @xyflow/lit). Most developers wouldn't think to render lit-html templates inside React components via `useRef` + `litRender`.
