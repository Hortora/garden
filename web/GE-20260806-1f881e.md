### Symptom
Subscribing to `SSEManager` with `eventNames: ['WORK_ITEM_CREATED']` receives no events, even though the backend is sending events with `type: "WORK_ITEM_CREATED"` in the JSON payload.

### Context
Backend sends standard unnamed SSE events where the event type is in the JSON body:
```
data: {"type":"WORK_ITEM_CREATED","data":{"workItemId":"..."},"timestamp":"..."}\n\n
```

Frontend subscribes with `SSEManager.subscribe(url, handler, { eventNames: ['WORK_ITEM_CREATED'] })`.

### Root cause
`SSEManager` has two event dispatch paths:

1. **Unnamed events** (`onmessage` handler) — catches all events without an SSE `event:` field. Parses JSON, extracts `type` from payload, queues with `sourceName: null`.

2. **Named events** (`addEventListener(name, ...)`) — catches SSE events with an explicit `event: name` field. Queues with `sourceName: name`.

In `_flushBatch`, the dispatch logic is:
- If `sourceName === null` (unnamed): only call handlers that have **no** `eventNames` (or empty list)
- If `sourceName` matches a name: only call handlers whose `eventNames` **includes** that name

So `eventNames` filters on the SSE protocol-level event name (the `event:` field in the SSE stream), NOT on the JSON payload's `type` field. The `type` extracted from JSON is set on `SSEEvent.type` for the handler to read, but it doesn't participate in the dispatch routing.

### Fix
Subscribe without `eventNames` and filter by `event.type` in the handler callback:

```typescript
const handler: SSEHandler = (event: SSEEvent) => {
  const sseEvent = event.data as { type: string };
  if (sseEvent.type !== 'WORK_ITEM_CREATED') return;
  // handle event
};

manager.subscribe('/events/stream', handler);  // no eventNames
```

For reuse, wrap in a controller that accepts type filters:

```typescript
export class LifeEventController {
  private readonly _types: Set<string>;

  constructor(types: string[]) {
    this._types = new Set(types);
  }

  private _handler = (event: SSEEvent) => {
    const sseEvent = event.data as { type: string };
    if (!this._types.has(sseEvent.type)) return;
    // process event
  };
}
```

### Why this is non-obvious
`SSEManager.subscribe()` accepts `eventNames` in its options, and the `onmessage` handler does extract `type` from JSON and set it on `SSEEvent.type`. The natural assumption is that `eventNames` filters on this extracted type. The actual behaviour — filtering on the SSE protocol's `event:` field, which is a completely different concept — is only discoverable by reading the `_flushBatch` source code.
