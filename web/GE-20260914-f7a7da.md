### Symptom

Accessing nested properties from a YAML document via a facade that uses
`YAMLMap.get(key)` returns opaque YAML node objects (YAMLMap, YAMLSeq)
instead of plain JS objects. Code like `props['lookup']['uuid']` silently
returns `undefined` because bracket access doesn't work on YAMLMap.

### Context

When building a typed facade over the `yaml` library's `Document` object
(e.g. `getProperties(): Record<string, unknown>`), scalar values (strings,
numbers, booleans) are auto-converted by `Map.get(key)`. But nested maps
and sequences are returned as their YAML node types.

### What was tried (didn't work)

Treating the return value of `Map.get(key)` as a plain JS object and
accessing nested keys with bracket notation. No error is thrown — the
access just returns `undefined`.

### Root cause

The `yaml` library's `Map.get(key)` (without the `keepScalar` second
argument) converts Scalar nodes to their JS values, but returns
Collection nodes (YAMLMap, YAMLSeq) as-is. This is by design — the
library preserves the AST structure for collections to enable
format-preserving mutations.

### Fix

Guard nested property access with a `.toJSON()` check:

```typescript
const raw = props['lookup'];
const lookup = typeof (raw as any).toJSON === 'function'
  ? (raw as any).toJSON()
  : raw as Record<string, unknown>;
const uuid = lookup?.['uuid']; // now works
```

Or convert the entire properties record recursively using `doc.toJS()` on
the properties node — but this loses the CST reference needed for
format-preserving edits.

### Why this is non-obvious

The `yaml` library docs describe `get(key)` as returning "the value" —
which reads as "the JS value". The asymmetry between scalars (auto-converted)
and collections (returned as nodes) is not called out, and no error
signals the problem — bracket access on a YAMLMap simply returns undefined.
