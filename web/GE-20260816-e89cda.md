### Symptom

Two Lit-based app shells (~800 lines each) independently compose the same set of web components, each duplicating data state management, WebSocket connection lifecycle, REST call orchestration, and event routing. Extracting to a single monolithic controller creates a god object that changes for any reason.

### Context

Multiple applications consuming the same component library (e.g. blocks-ui channel-activity) where the components need the same data shape but the host layout differs significantly (responsive dock workbench vs terminal-centric layout). The apps can't share a composition element because layout is the divergence point.

### Fix

Decompose shared logic into composable Lit reactive controllers with an explicit dependency chain:

```typescript
// Dependency chain: PushController ← ChannelStateController ← feature controllers
this._push = new PushController(this, config);
this._channels = new ChannelStateController(this, this._push);
this._messaging = new MessagingController(this, this._push, this._channels, config);
this._members = new MembershipController(this, this._push, this._channels);
this._reactions = new ReactionController(this, this._push, this._channels);
this._commitments = new CommitmentController(this, this._push, this._channels);
```

Each controller:
- Implements `ReactiveController` (Lit native pattern)
- Takes the host element + upstream controllers as constructor params
- Registers dataset handlers with PushController for its data
- Exposes typed state properties that trigger host re-renders
- Handles its own subset of `ChannelEventTopics`

Host elements drop from ~800 to ~200 lines — pure layout + controller binding.

### Why this is non-obvious

The natural instinct is either a single thick controller (simpler API but god object) or a composition element with slots (rigid layout). The composable controller pattern is less obvious because:
- Lit's ReactiveController docs show simple single-controller examples, not multi-controller dependency chains
- Cross-controller state sharing (e.g. `selectedChannelId` from ChannelStateController used by all others) requires explicit constructor injection — there's no built-in mechanism
- The pattern only pays off when multiple host elements consume the controllers differently; for a single host it's over-engineering
