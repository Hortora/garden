### Symptom
`containerizeEntry` creates a tabbed child container with an `onCollapse` callback, but the callback never fires — the child container can drop to a single entry and nothing happens. Auto-flatten is silently broken for tabbed and accordion containers; only split containers auto-collapse.

### Context
A strategy-pattern factory (`buildOrganiser`) creates different layout strategies (tabbed, accordion, split, free). The `onCollapse` callback was defined on a strategy-specific extension interface (`SplitCallbacks extends LayoutCallbacks`) and only spread into callbacks for split strategies. Tabbed and accordion strategies received the base `LayoutCallbacks` which didn't include `onCollapse`.

### Root cause
Selective callback routing in the factory function:

```typescript
function buildOrganiser(type, callbacks, onCollapse) {
  switch (type) {
    case "tabbed":
      return createTabbedStrategy(callbacks);        // ← no onCollapse
    case "splith":
      return createSplitStrategy("horizontal",
        { ...callbacks, onCollapse });                // ← onCollapse only here
  }
}
```

The factory had a separate parameter for `onCollapse` and only merged it into callbacks for split strategies. Other strategies received it nowhere — their `removeEntry` couldn't check for it because the callback type didn't include it.

### Fix
Move `onCollapse` from the strategy-specific extension to the universal callback interface:

```typescript
// Before: only SplitCallbacks had onCollapse
interface SplitCallbacks extends LayoutCallbacks {
  onCollapse?: (remaining: Entry) => void;
}

// After: LayoutCallbacks has it — all strategies receive it
interface LayoutCallbacks {
  onCollapse?: (remaining: Entry) => void;
  // ... other callbacks
}
```

Then each strategy that should auto-collapse checks in `removeEntry`:
```typescript
if (currentEntries.length === 1 && callbacks?.onCollapse) {
  callbacks.onCollapse(currentEntries[0]!);
  return;
}
```

### Why this is non-obvious
The factory function compiles and runs without error. The `onCollapse` callback is wired by the caller (`containerizeEntry`). The tabbed strategy creates correctly. The only signal is that closing tabs in a nested container doesn't flatten — a behaviour absence, not an error. Unless you read both the factory function AND the callback type hierarchy AND the strategy's `removeEntry`, the routing gap is invisible.
