## Symptom

Implementation plan assumes `<work-item-inbox>` has a `compact` or `density` property for dock panel use. It does not — the component always renders a full tabbed table with filter bars, batch claim/cancel buttons, queue pills, and summary bar.

## Context

When building a dock layout (IntelliJ-style collapsible panels), the natural assumption is to wrap `<work-item-inbox>` in compact mode for a sidebar inbox. An audit of all 44 blocks-ui packages found that only 6 components have any compact/density property — `work-item-inbox` is not one of them.

## Fix

Use `<list-pane>` instead. Configure with minimal columns (title, status, age), small `pageSize` (5), and a `selectionTopic`. Feed it work-item data from the same `/pending-actions` endpoint.

```html
<list-pane
  .columnConfig=${[
    { key: 'title', label: 'Task' },
    { key: 'status', label: 'Status' },
    { key: 'createdAt', label: 'Age' }
  ]}
  pageSize="5"
  selectionTopic="inbox-dock"
  emptyMessage="Inbox clear"
></list-pane>
```

## Why this is non-obvious

The component name "work-item-inbox" strongly implies it's THE inbox component for work items in any context. The assumption that it supports density variants is natural — especially since `kpi-metric-row`, `trust-score-panel`, and `sla-indicator` all do. The fix (using `list-pane` instead) requires knowing that `list-pane` exists and is a generic table wrapper.
