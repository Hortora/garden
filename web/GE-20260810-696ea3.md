### Symptom
A new ECharts chart type (e.g. `heatmap-chart`) renders as a `data-table` instead of a chart. No errors in console.

### Context
casehub-pages has three separate type registries that must all include new chart types:

1. `displayer-desugar.ts` `TYPE_MAP` — maps uppercase type strings to canonical names (line ~8). Missing here → type defaults to `"data-table"` (line 104)
2. `component-desugar.ts` `DATA_COMPONENT_TYPES` — gates which types route through displayer desugar (line ~22). Missing here → type becomes `"unknown"`
3. `activation.ts` `DATA_COMPONENT_TYPES` — gates which types get runtime element creation (line ~50). Missing here → no element created

### Fix
When adding a new chart type, update all three registries:

```typescript
// 1. displayer-desugar.ts TYPE_MAP
"HEATMAP-CHART": "heatmap-chart",

// 2. component-desugar.ts DATA_COMPONENT_TYPES
"heatmap-chart",

// 3. activation.ts DATA_COMPONENT_TYPES
"heatmap-chart",
```

Plus the usual pages-viz registrations: custom-elements.ts, index.ts, displayer-types.ts, type-guards.ts, model/index.ts.

### Why this is non-obvious
Each registry fails silently with a different fallback: one produces `data-table`, another produces `unknown`, and the third simply doesn't create the element. The component appears to render (as a table) rather than throwing an error, so the misconfiguration looks like a data binding issue rather than a missing type registration.
