### Context
Interactive canvas visualizations (heatmaps, scatter plots) that need click indicators — crosshairs, selection highlights, hover markers. The canvas sits in a flex container that resizes when side panels open/close.

### Technique
Instead of drawing interaction markers on the canvas (which requires redrawing after every resize and suffers from coordinate drift), use absolutely-positioned HTML `<div>` elements overlaying the canvas:

```css
.crosshair-h, .crosshair-v { position: absolute; pointer-events: none; z-index: 5; }
.crosshair-h { left: 0; right: 0; height: 2px; background: #7cb3f5; }
.crosshair-v { top: 0; bottom: 0; width: 2px; background: #7cb3f5; }
```

Store click position as a percentage of the container at click time:
```typescript
this.crosshairPctX = (mx / rect.width) * 100;
// Render: <div class="crosshair-v" style="left:${pctX}%"></div>
```

The browser's layout engine handles coordinate recalculation on resize automatically. `pointer-events: none` ensures the overlays don't block canvas mouse events.

### Why this is non-obvious
Canvas-based drawing is the natural choice for visual markers on a canvas visualization — same rendering context, same coordinate system. But canvas coordinates are fragile when the container resizes (flex panels, responsive layouts). HTML overlays with CSS percentage positioning delegate the hard part (coordinate recalculation on resize) to the browser.
