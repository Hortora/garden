### Symptom

Dockview floating groups render but the container height blows up to 16,777,216 pixels. Frames exist in the DOM but are invisible — they're positioned at correct coordinates inside an absurdly tall container.

### Context

The `createDockviewBackend()` from pages-runtime injects Dockview's CSS into `document.head` via a `<style>` element. When the host component (workspace-view) uses shadow DOM (Lit's default), styles in `document.head` don't reach the shadow root. Dockview's structural CSS — which constrains container overflow — never applies.

### Root cause

Shadow DOM style isolation. The backend's CSS injection targets `document.head`, but the Dockview container lives inside a shadow root. Without the structural CSS, the internal `.dv-grid-view` and `.dv-view-container` elements have no overflow constraints and expand to fill their content's natural height.

### Fix

Re-add Dockview CSS to the component's shadow root styles, independent of the backend's injection:

```typescript
import dockviewCSS from 'dockview-core/dist/styles/dockview.css?raw';

static override styles = [
  unsafeCSS(dockviewCSS),
  unsafeCSS(xtermCSS),
  css`...`,
];
```

Also add `overflow: hidden; position: relative;` to the Dockview container element to prevent the height explosion even if some CSS rules are missing.

### Why this is non-obvious

The backend's CSS injection is intentional — it works for non-shadow-DOM hosts. No error is thrown. The 16M pixel height looks like a Dockview bug, not a CSS scoping issue. The frames are in the DOM at correct positions — they just can't be seen.
