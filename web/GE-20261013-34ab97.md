### Symptom
Clicking "Run" on scenario samples does nothing — no error in console, no execution, no state change. The UI remains at "idle" with 0% progress.

### Context
The runtime renamed `parseScenario()` to `parsePlaybook()` but 4 sample TypeScript files still called the old name via `window.casehubPages.parseScenario`. Since the property lookup returns `undefined` and the code guards with `if (!parseScenario || !createScheduler) return;`, execution silently exits without any error message.

### Root cause
Property access on a JS object for a missing key returns `undefined`, not an error. The guard clause treats `undefined` as "not available" rather than "renamed" — same exit path as "bundle not loaded yet."

### Fix
Rename all call sites from `parseScenario` to `parsePlaybook`. The guard clause pattern is fine — the issue is purely that the old name was left behind after the rename.

### Why this is non-obvious
The failure mode is completely silent. No console error, no exception, no warning. The sample loads, displays YAML, shows buttons — everything looks correct. Only clicking Run reveals nothing happens, and even then there's no error to diagnose. You have to inspect the bundle's exported symbols to discover the rename.
