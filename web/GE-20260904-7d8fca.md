## Lit composite component value propagation must use a dirty flag — render() runs on any reactive property change

**ID:** GE-20260904-7d8fca
**Stack:** Lit 3.x, LitElement, Shadow DOM
**What it achieves:** Prevents parent-set values from overwriting user edits when a Lit component re-renders for unrelated reasons (e.g., `editable` toggle, `collapsible` state change).

### Context

A composite form component (e.g., an object-group fieldset) receives a structured value from its parent via a `value` setter and must distribute sub-values to child input elements. The naive approach — distributing values during `render()` — causes silent data loss.

### The problem

Lit calls `render()` whenever any reactive property (`@property`, `@state`) changes. If the render method distributes `this.value` to children unconditionally, any re-render triggered by a non-value change (toggling `editable`, collapsing a section, parent re-render) overwrites whatever the user typed.

```typescript
// BAD — runs on every render cycle, overwrites user input
override render(): TemplateResult {
  if (this.value && typeof this.value === "object") {
    const obj = this.value as Record<string, unknown>;
    for (const [field, child] of this._children) {
      (child as any).value = obj[field];  // silently kills user edits
    }
  }
  return html`...`;
}
```

### Fix

Use a dirty flag set by the value setter, cleared after distribution:

```typescript
private _valuePending = false;

protected propagateValue(v: unknown): void {
  this._valuePending = true;
  this.requestUpdate();
}

override render(): TemplateResult {
  // ... create/update children ...

  if (this._valuePending && this.value && typeof this.value === "object") {
    this._valuePending = false;
    const obj = this.value as Record<string, unknown>;
    for (const [field, child] of this._children) {
      const fieldValue = obj[field];
      if (fieldValue === undefined) continue;
      (child as any).value = fieldValue;
    }
  }
  return html`...`;
}
```

Distribution only happens when `value` was explicitly set — not on unrelated re-renders.

### Why this is non-obvious

The pattern appears correct because `this.value` doesn't change between renders — so distributing it again seems idempotent. But child inputs hold mutable state (user-typed text) that isn't reflected back into `this.value`. The overwrite is silent — no error, no event, no visual glitch (the old value just reappears instantly).

### Alternatives considered

- **`updated()` lifecycle with `changedProperties.has('value')`** — Works for `@property` but not for values set via a custom setter that doesn't use Lit's property system. The mixin pattern (`FormValueMixin`) uses a plain setter, not `@property`.
- **Lit `willUpdate()`** — Same limitation as `updated()` for non-reactive properties.
- **Never distribute in render, only in setter** — Doesn't work when children don't exist yet at setter time (element created but not rendered). The render method is the first point where children are guaranteed to exist.
