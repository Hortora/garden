## Symptom

A Lit-based web component bundle fails at runtime with:

```
Error: Unsupported decorator location: field
    at standardProperty (@lit/reactive-element)
    at <static_initializer>
```

The error appears during UMD module initialization, causing the entire bundle to fail silently — no custom elements register, no exports are available.

## Context

TypeScript 5.0+ defaults to TC39 Stage 3 decorators when `experimentalDecorators` is not set. Lit's `@property()` and `@state()` decorators from `@lit/reactive-element` use the legacy `experimentalDecorators` runtime.

When webpack's ts-loader compiles Lit source files without `experimentalDecorators: true`, TypeScript emits Stage 3 decorator metadata. Lit's `standardProperty` function receives this metadata and throws because it doesn't understand the Stage 3 decorator `location` value.

This only surfaces when webpack compiles Lit from **source** (e.g. monorepo packages without a pre-built dist). Pre-built packages ship transpiled JS and are unaffected.

## What was tried (didn't work)

- Checked the Lit changelog for breaking changes — no mention
- Searched for the error message — few results, none helpful
- Assumed a Lit version mismatch — versions were correct

## Root cause

The shared `tsconfig.json` (via `@casehubio/pages-tsconfig`) targets ES2022 with `verbatimModuleSyntax` but does not set `experimentalDecorators: true`. TypeScript 5.0+ interprets this as "use Stage 3 decorators." Lit requires the legacy decorator runtime.

## Fix

Add both settings to the ts-loader `compilerOptions` in the webpack config:

```javascript
// webpack.config.js — ts-loader rule override
compilerOptions: {
  experimentalDecorators: true,
  useDefineForClassFields: false,
}
```

`useDefineForClassFields: false` is required alongside `experimentalDecorators` — without it, TypeScript uses `Object.defineProperty` for class fields, which breaks Lit's reactive property system that relies on setter interception.

## Why this is non-obvious

1. The error message says "Unsupported decorator location: field" — no mention of TypeScript, experimentalDecorators, or Stage 3 vs legacy
2. The failure is in `@lit/reactive-element` internals, suggesting a Lit bug rather than a config issue
3. The UMD bundle fails during initialization, so no useful stack trace reaches the consumer
4. Only manifests when compiling from source via webpack — pre-built dists mask the issue
