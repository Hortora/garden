### Symptom

`TypeError: Cannot redefine property: ownerDocument` when calling
`document.adoptNode(element)` to move an element back to its original
document after a previous `adoptNode` moved it to a different document.

### Context

Testing cross-document DOM manipulation in happy-dom (Vitest's default
DOM environment). The forward direction works — adopting from doc A to
doc B succeeds and the element renders in the new document. But adopting
back from doc B to doc A throws.

### Root cause

happy-dom's `adoptNode` implementation sets `ownerDocument` on the
element using `Object.defineProperty` with `configurable: false`. The
first adoption succeeds because the property doesn't exist yet. The
second adoption fails because the property is already defined and
non-configurable — `Object.defineProperty` cannot redefine it.

Real browsers implement `adoptNode` as an internal DOM operation that
directly mutates the node's owner document without going through
`Object.defineProperty`, so round-trips work correctly.

### Fix

Use the **same document** for both the main window and child window in
tests. This makes `adoptNode` a no-op (element already belongs to this
document), allowing tests to verify controller state management,
placeholder logic, and event relay without triggering the cross-document
mechanics that happy-dom cannot handle.

```typescript
function makeFakeWindow() {
  // Same document avoids happy-dom's ownerDocument redefinition bug.
  // Real browsers handle cross-document round-trips correctly.
  return {
    document,  // ← same document, not createHTMLDocument()
    close: vi.fn(),
    focus: vi.fn(),
    closed: false,
    addEventListener: vi.fn(),
    removeEventListener: vi.fn(),
  };
}
```

Full cross-document round-trip testing requires a real browser
environment (Playwright).

### Why this is non-obvious

The forward direction works perfectly — the element adopts, renders, and
responds to property changes in the new document. Nothing suggests the
reverse will fail. The error message (`Cannot redefine property`) points
at a JavaScript property descriptor constraint, not at a DOM limitation,
so the initial instinct is to look for a code bug rather than a test
environment limitation.
