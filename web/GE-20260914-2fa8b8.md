### Symptom

`Document.setIn(['parent', 'child', 'grandchild'], value)` throws
"Expected YAML collection at child" when `parent.child` doesn't already
exist as a Map node. The error message doesn't suggest the fix.

### Context

When building compound mutations on a YAML CST (e.g. creating a new named
tab entry with a components array inside), the natural approach is to call
`setIn` with the full path. This works when all intermediate nodes already
exist, but fails when any intermediate segment needs to be created as a
new Map or Seq.

### What was tried (didn't work)

1. `doc.setIn(['tabs', 'Tab 2', 'components'], [])` — throws because
   'Tab 2' doesn't exist yet as a map entry
2. `doc.setIn(['tabs', 'Tab 2'], { components: [] })` followed by
   `doc.setIn(['tabs', 'Tab 2', 'components'], [])` — the first call
   creates a scalar, not a map, so the second call still fails

### Root cause

`Document.setIn()` uses `Collection.setIn()` internally, which traverses
existing nodes but does not create intermediate collection nodes. It can
only create the leaf value. When a path segment resolves to a non-existent
or non-collection node, it throws.

### Fix

Build the structure from the inside out using `createNode()` and
`Map.set()`:

```typescript
const doc = this._doc;
const mapNode = doc.getIn(mapPath) as YAMLMap;

// Create the entire entry structure as a single node
const newEntry = doc.createNode({ components: [] });

// Set it on the parent map using Map.set (not setIn)
mapNode.set(doc.createNode('Tab 2'), newEntry);
```

`createNode()` recursively converts plain JS objects into proper YAML
nodes (YAMLMap, YAMLSeq, Scalar), so the resulting structure is valid
for all subsequent `getIn`/`setIn` operations.

### Why this is non-obvious

`setIn` works perfectly for updating existing paths and creating leaf
values — the failure only surfaces when building new nested structures.
The error message ("Expected YAML collection") points to the wrong level
of the path, and the fix (using `createNode` + `Map.set`) requires
understanding the difference between the Document API (`setIn`) and the
Collection API (`set`).
