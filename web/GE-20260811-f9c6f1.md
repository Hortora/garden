### Symptom
Adding `@property({ type: String }) nodeType = '';` to a LitElement class produces:
- `TS1238: Unable to resolve signature of class decorator when called as an expression`
- `Argument of type 'typeof MyComponent' is not assignable to parameter of type 'CustomElementClass'`
- `The types of 'prototype.nodeType' are incompatible between these types. Type 'string' is not assignable to type 'number'.`

### Context
Any LitElement subclass declaring a reactive property named `nodeType`. The name is intuitive for "what type of node is selected" in graph/diagram editors.

### Root cause
`Node.nodeType` is a readonly `number` property on the DOM `Node` interface (returns 1 for ELEMENT_NODE, 3 for TEXT_NODE, etc.). LitElement extends HTMLElement which extends Node. Declaring `nodeType` as a `string` property shadows the inherited DOM property with an incompatible type, breaking the `CustomElementClass` constraint that Lit's `@customElement` decorator requires.

### Fix
Rename the property to avoid the collision. Use `selectedType`, `elementKind`, or any name not in the `Node` interface.

### Why this is non-obvious
The error message says "Unable to resolve signature of class decorator" — pointing at the `@customElement` decorator, not the property. The `nodeType` incompatibility is buried in nested type error details. Developers debug the decorator configuration or Lit version compatibility before realising a property name is the issue.

### Alternatives considered
- Using `override` modifier — doesn't help because the type (`string` vs `number`) is incompatible, not just missing an override annotation
- Using `@litProp({ attribute: 'node-type' })` — changes the HTML attribute name but doesn't fix the TypeScript interface conflict
