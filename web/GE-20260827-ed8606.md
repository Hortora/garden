### Symptom
When implementing custom connection-drop handling in React Flow v12 via `onConnectEnd`, `event.target` always resolves to the React Flow pane overlay (`<div class="react-flow__pane">`) — never to the actual node the cursor is over. Connections dropped over valid target nodes are treated as drops on empty space.

### Context
Occurs when using `onConnectEnd` to implement custom connection logic (e.g., showing a node picker on empty-space drops, or creating edges programmatically). The pane overlay sits above nodes in the z-order and intercepts all pointer events during connection drag.

### What was tried (didn't work)
- Using `event.target` and traversing up with `.closest('.react-flow__node')` — always null because event.target is the pane
- Using `connectionRadius` to let React Flow handle proximity matching — too imprecise for UX that requires exact element overlap
- Checking `event.target.dataset.id` — undefined because the pane has no node id

### Root cause
React Flow renders the connection line and pane as overlay layers above the node layer. During a connection drag, the pane overlay captures all pointer events. When `onConnectEnd` fires, `event.target` is always this overlay element, regardless of what visual element appears under the cursor.

### Fix
Use `document.elementsFromPoint(clientX, clientY)` to see through the overlay stack and find the actual node element. Additionally, set `pointer-events: none !important` on the connection line SVG and edge interaction overlays during the connection drag so they don't block the hit test.

```typescript
// In onConnectEnd handler:
const pos = event instanceof MouseEvent
  ? { x: event.clientX, y: event.clientY }
  : { x: event.changedTouches[0]?.clientX ?? 0, y: event.changedTouches[0]?.clientY ?? 0 };

let targetNodeId: string | undefined;
for (const hitEl of document.elementsFromPoint(pos.x, pos.y)) {
  const nodeEl = hitEl.closest('.react-flow__node') as HTMLElement | null;
  if (nodeEl?.dataset['id']) {
    targetNodeId = nodeEl.dataset['id'];
    break;
  }
}
```

```css
/* Applied during connection drag via a parent class toggle */
.graph-connecting .react-flow__connectionline,
.graph-connecting .react-flow__connection,
.graph-connecting .react-flow__edges,
.graph-connecting .react-flow__edge-interaction {
  pointer-events: none !important;
}
```

### Why this is non-obvious
The natural assumption is that `event.target` in `onConnectEnd` would reference the element under the cursor, as it does in standard DOM events. React Flow's overlay architecture means the event target is always the pane, which is invisible and sits above everything. The need to also disable pointer-events on the connection line SVG and edge overlays is a second layer of surprise — even `elementsFromPoint()` returns these overlay elements before the actual nodes without the CSS fix.

### Alternatives considered
- Using `connectionRadius` for proximity-based matching — rejected because it creates false matches and doesn't support exact element-overlap UX
- Using a custom `isValidConnection` callback alone — doesn't help because `onConnectEnd` still doesn't know which node was under the cursor
