## Context

The `blocks-approval-gate` component name implies a binary yes/no approval workflow. The component's default outcomes are `[{key: "approve", variant: "success"}, {key: "reject", variant: "danger"}]`.

## What is undocumented

The `outcomes` property accepts any `OutcomeDefinition[]`:

```typescript
interface OutcomeDefinition {
  key: string;
  label: string;
  variant: "success" | "danger" | "neutral";
}
```

You can pass 4+ arbitrary outcomes — e.g., for a triage decision:

```typescript
gateElement.outcomes = [
  { key: "CONFIRM", label: "Confirm Severity", variant: "success" },
  { key: "DOWNGRADE", label: "Downgrade", variant: "neutral" },
  { key: "ESCALATE", label: "Escalate", variant: "neutral" },
  { key: "FALSE_POSITIVE", label: "False Positive", variant: "danger" },
];
```

The component renders a button per outcome with the correct styling, prompt text, evidence slot, and confirmation dialog. The `gate.decided` event carries the selected outcome key.

## Why this is non-obvious

The component name "approval-gate" and the default outcomes strongly suggest binary approval semantics. The flexible API is only discoverable by reading the TypeScript source — the `@property({ attribute: false }) outcomes: OutcomeDefinition[] = DEFAULT_OUTCOMES` declaration is the only hint.
