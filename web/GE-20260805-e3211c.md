# pages-runtime hostPanel resolves custom elements via registerPanel — import AND register before loadSite

### Context
Building a dock workbench layout using `dockWorkbench()` from `@casehubio/pages-ui/dist/dsl/builders.js`. Each dock panel references content via `hostPanel('panel-type-name')`. The rendered panels show "Unknown panel type: ..." warnings instead of content.

### Technique
`hostPanel(typeName)` creates a `{ type: "host-panel", props: { typeName } }` component descriptor. At render time, `activation.js` resolves it:

1. Calls `lookupPanel(typeName)` from `panel-registry.js`
2. If not found → shows "Unknown panel type" warning and returns
3. If found → calls `document.createElement(tagName)` to create the custom element
4. If the element has a `configure(panelProps)` method → calls it with panel props

Two things must happen BEFORE `loadSite()` renders the component tree:

```typescript
// 1. Import component files so customElements.define() runs
import './panels/centre-content.js';
import './panels/inbox-dock.js';

// 2. Register panel type → tag name mapping
import { registerPanel } from '@casehubio/pages-runtime';
registerPanel('life-centre-content', 'life-centre-content');
registerPanel('life-inbox-dock', 'life-inbox-dock');
```

Both steps are required — importing without registering leaves the panel unknown to the registry; registering without importing leaves the custom element undefined.

### Why this is non-obvious
The `hostPanel()` API is purely declarative — it gives no indication that a separate imperative registration step is needed. The error message "Unknown panel type" doesn't mention `registerPanel`. The resolution chain (hostPanel → lookupPanel → createElement) spans three separate modules (builders.js, panel-registry.js, activation.js).
