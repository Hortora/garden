## Symptom

Need to use a React-based library (e.g. React Flow for graph editing) inside a Lit 3.x Web Component application, without introducing React as an app-wide framework.

## Context

The host application is entirely Lit Web Components. A specific component needs React Flow's graph editing capabilities. React Flow relies on document-level event handlers, portal-based controls, and CSS-in-JS injection — all incompatible with Shadow DOM.

## Fix

### The bridge component (~50 lines)

```typescript
import { LitElement, html } from 'lit';
import { customElement, property } from 'lit/decorators.js';
import * as React from 'react';
import * as ReactDOM from 'react-dom/client';

@customElement('react-bridge')
class ReactBridge extends LitElement {
  private root?: ReactDOM.Root;

  // Skip Shadow DOM — React needs light DOM
  override createRenderRoot() { return this; }

  override connectedCallback() {
    super.connectedCallback();
    const container = document.createElement('div');
    this.appendChild(container);
    this.root = ReactDOM.createRoot(container);
    this.renderReact();
  }

  override disconnectedCallback() {
    this.root?.unmount();
    super.disconnectedCallback();
  }

  override updated() {
    this.renderReact();
  }

  private renderReact() {
    this.root?.render(React.createElement(MyReactComponent, { ...this.reactProps }));
  }
}
```

### CSS isolation (required when Shadow DOM is disabled)

Three mechanisms, each with a distinct role:

**1. `all: initial` on the container — blocks inheritance**

```css
.react-bridge-root {
  all: initial;
  display: block;
  position: relative;
  width: 100%;
  height: 100%;
}
```

Resets all inherited properties (including custom properties) from the host. The container requires a parent with explicit height.

**2. Scoped `all: revert` on children — blocks host element-specific resets**

```css
.react-bridge-root * {
  all: revert;
}
```

Specificity 0,1,0 beats the host's `* { box-sizing }` (0,0,0) and element resets like `button { appearance: none }` (0,0,1). Reverts host author styles to browser defaults. Library CSS (loaded after, with class selectors) overrides via source order.

**3. Theme token re-injection — re-declares design tokens**

If the host uses a theme injection API (e.g. `applyTheme(name, container)`), call it on the container element. The injected `<style>` inside the container appears later in document order than the head stylesheet's `all: initial`, so the token declarations win. No manual token list needed.

If no theme API: explicitly re-declare each design token on the container.

**Use source order, NOT `@layer`, for internal CSS cascade control:**

```
1. isolation.css        — container reset, children revert
2. Library CSS           — React library's own styles
3. Plugin-contributed   — custom component styles
```

~~**CSS `@layer`** prevents host globals from affecting React internals~~ **CORRECTED:** `@layer` does NOT isolate from unlayered host CSS. In the CSS cascade, unlayered CSS has *higher* priority than layered CSS. Putting library CSS in `@layer` makes it *weaker* than the host — the opposite of isolation. See GE-20260802-953404.

### Key points

1. **Skip Shadow DOM** on the bridge component only — sibling Lit components keep their shadow roots
2. **`all: initial`** resets inherited styles but also kills CSS custom properties — re-declare via theme injection API (preferred) or manual list
3. **`all: revert` on children** beats host universal selectors; library CSS overrides via source order
4. **Do NOT use `@layer`** for isolation from unlayered host CSS — it makes you weaker (see GE-20260802-953404)
5. **Lifecycle**: mount in `connectedCallback`, unmount in `disconnectedCallback`, re-render in `updated()`; guard `updated()` with `if (!this.root) return` (fires before `connectedCallback` if properties are set early)
6. **Props**: pass Lit `@property` values as React props; React callbacks emit CustomEvents with `composed: true`
7. **Bundle cost**: ~45KB gzipped for React + ReactDOM — acceptable for a single specialized component

## Why this is non-obvious

The most-cited concern (Shadow DOM event retargeting breaking React) disappears entirely when you skip Shadow DOM on the bridge component. Most guides focus on solving the Shadow DOM problem; the simpler answer is avoiding it. The three-mechanism CSS isolation approach (`all: initial` + scoped `all: revert` + theme re-injection) is less well-known than Shadow DOM but more practical for this use case. The common recommendation to use `@layer` for CSS isolation is actively harmful when the host CSS is unlayered.
