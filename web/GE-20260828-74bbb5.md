### Symptom
Layout persistence doesn't work despite correct backend endpoint. Requests go to `/api/layouts/workbench` without the required `?root=` query parameter.

### Context
Using `createRestLayoutStore()` from `@casehubio/pages-runtime` to persist layout state. The backend requires a `root` query parameter to scope layouts to a workspace. The consumer expects to pass extra query params alongside the key.

### Root cause
`createRestLayoutStore(baseUrl, tokenFn)` constructs URLs as `${baseUrl}/api/layouts/${encodeURIComponent(key)}` — no mechanism to inject query parameters. The API accepts only `baseUrl` and `tokenFn`. No `params` option exists.

### Fix
Implement the `LayoutStore` interface directly instead of using `createRestLayoutStore`:

```typescript
import type { LayoutStore } from '@casehubio/pages-runtime';

function createLayoutStore(workspaceRoot: string): LayoutStore {
  const rootParam = `root=${encodeURIComponent(workspaceRoot)}`;
  return {
    async load(key) {
      const resp = await fetch(`/api/layouts/${key}?${rootParam}`);
      return resp.ok ? resp.json() : null;
    },
    async save(key, state) {
      await fetch(`/api/layouts/${key}?${rootParam}`, {
        method: 'PUT',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(state),
      });
    },
    async delete(key) {
      await fetch(`/api/layouts/${key}?${rootParam}`, { method: 'DELETE' });
    },
  };
}
```

### Why this is non-obvious
The `createRestLayoutStore` function appears to be the standard way to persist layouts. Its TypeScript signature (`baseUrl: string, tokenFn: () => string | null`) gives no hint that query parameters are unsupported. The limitation is only visible by reading the implementation source — the function is 100 lines of fetch calls with hardcoded URL construction.

### Alternatives considered
- Embedding query params in `baseUrl` (e.g. `http://localhost:8080?root=...`) — breaks because the key path segment is appended after the query string
- Wrapping `createRestLayoutStore` — the returned object has no hook points for URL modification

### Invalidation triggers
Revisit if pages-runtime adds a `params` or `urlBuilder` option to `createRestLayoutStore`.
