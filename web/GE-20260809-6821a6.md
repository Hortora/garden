### Symptom
After enabling `tabAnimation: 'smooth'`, dragging a tab within its own frame (reordering) unexpectedly detaches it into a new floating frame. The tab appears to reorder visually (FLIP animation), but on mouse release a new frame is created.

### Context
Dockview's smooth tab reorder is handled by the `Tabs` class using FLIP animations and `_animState` tracking. This is a separate code path from the main drop handler (`handleDropEvent` → `onMove` → `moveGroupOrPanel`). The main drop handler fires `onDidDrop` on the `DockviewComponent`. The smooth reorder path does NOT fire `onDidDrop`.

### What was tried (didn't work)
- Checking `_dragDidDrop` flag in the `dragend` handler — `_dragDidDrop` is only set from the `onDidDrop` callback, which smooth reorder never fires. Every smooth reorder looks like "tab dropped outside all targets."
- Using `onWillShowOverlay` to distinguish reorder from drop-out — the overlay system is separate from smooth reorder.

### Root cause
Two parallel drag systems in Dockview:
1. **Main DnD** (`handleDropEvent` → `onDidDrop`): fires for cross-group drops, content-area drops
2. **Smooth reorder** (`Tabs._animState` → FLIP animation): fires for within-group tab reorder

Only #1 fires `onDidDrop`. Code that uses `onDidDrop` to distinguish "tab was handled by Dockview" from "tab dropped outside" misclassifies all smooth reorders as "dropped outside."

### Fix
Check the mouse position against frame bounds on `dragend` instead of relying on `_dragDidDrop`. Only create a new frame if the mouse is actually outside all frames.

```typescript
this.shadowRoot!.addEventListener('dragend', (e: DragEvent) => {
    if (!panelId || this._dragDidDrop) return;

    const cx = e.clientX;
    const cy = e.clientY;
    const insideFrame = [...this._frameGroups.values()].some(group => {
        const container = group.element?.closest('.dv-resize-container');
        if (!container) return false;
        const rect = container.getBoundingClientRect();
        return cx >= rect.left && cx <= rect.right && cy >= rect.top && cy <= rect.bottom;
    });
    if (insideFrame) return; // Smooth reorder handled it — don't detach

    // Mouse outside all frames — create new frame
    setTimeout(() => { /* ... */ }, 50);
});
```

### Why this is non-obvious
`onDidDrop` sounds like "a drop happened anywhere in Dockview." In reality it means "a drop was handled by the main DnD system." Smooth reorder is a separate system that doesn't participate in the drop event chain. The visual feedback (tabs shifting smoothly) makes it look like the reorder worked — the new-frame creation only happens on mouse release, making the cause-effect relationship hard to trace.
