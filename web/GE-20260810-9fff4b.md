## Convention

When a set of filter buttons behaves as radio buttons (one active at a time), clicking the already-active button should deselect it and return to the unfiltered state ("All"), rather than being a no-op.

```typescript
private setFilter(f: string) {
  this.activeFilter = (f !== 'all' && this.activeFilter === f) ? 'all' : f;
  this.emit();
}
```

## Alternative

The standard radio-button convention: clicking an already-selected radio does nothing. The user must explicitly click "All" to clear the filter.

## Rationale

With signal-driven filters (Stale, Duplicates, Outliers, Low Health), clicking "Low Health" to see 1,206 entries then wanting to go back is a common flow. If the user doesn't notice the "All" button, they're stuck — especially when the filter zone has hover-expand secondary filters that make the "All" button scroll out of view. Toggle-off provides an escape hatch at the point where the user already is (the active button), without requiring them to find a separate reset control.

The Sparge UI uses the same pattern for its `.fb` filter buttons — clicking an active filter deselects it.
