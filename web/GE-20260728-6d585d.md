### Symptom
`TypeError: U.createTreeWalker is not a function` when dynamically importing
an esbuild-produced Lit component bundle in Node.js.

### Context
Validating that an esbuild bundle is loadable ESM — a build-time sanity check
in a CI assembly script, not a test environment with jsdom.

### What was tried (didn't work)
Minimal browser stubs: `globalThis.HTMLElement`, `globalThis.customElements`,
`globalThis.document = { createElement: () => ({...}) }`. Lit still crashes
because its template compilation runs at module evaluation time and touches
deeper DOM APIs.

### Root cause
Lit's template engine calls `document.createTreeWalker()` during module init
(not at render time) to set up its template walker. The minified bundle
inlines this as a top-level call. Additional APIs accessed at init:
`document.createComment`, `CSSStyleSheet.replaceSync`, `MutationObserver`.

### Fix

```js
const noop = () => {};
class FakeElement {
  constructor() { this.childNodes = []; this.style = {}; }
  setAttribute() {}
  removeAttribute() {}
  append() {}
  replaceWith() {}
  get content() { return this; }
  get firstChild() { return new FakeElement(); }
}
globalThis.HTMLElement = class {};
globalThis.customElements = { get: () => undefined, define: () => {} };
globalThis.CSSStyleSheet = class { replaceSync() {} };
globalThis.document = {
  createElement: () => new FakeElement(),
  createComment: () => new FakeElement(),
  createTreeWalker: () => ({ nextNode: () => null, currentNode: null }),
  adoptedStyleSheets: [],
  head: { prepend: noop },
};
globalThis.window = globalThis;
globalThis.MutationObserver = class { observe() {} disconnect() {} };
await import(bundlePath);
```

### Why this is non-obvious
The error message references a minified variable (`U.createTreeWalker`),
making it unclear this is `document`. Lit's module-init-time DOM access
is an implementation detail not documented in Lit's API — most developers
expect DOM access only at render/connect time.
