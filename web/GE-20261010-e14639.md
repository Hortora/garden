### Symptom
Highlighting a visual line causes the text to reflow — the highlighted text wraps to a second line even though it fit on one line before the highlight was applied.

### Context
`Decoration.inline(from, to, { style: 'border: 2px solid red' })` wraps the text range in `<span style="border: 2px solid red">`. The border adds pixel width (2px left + 2px right = 4px total) to each span created by the decoration.

### Root cause
CSS `border` participates in the box model for inline elements. Each decorated span becomes slightly wider than its text content. When the text was near the wrap boundary, the extra border pixels push it past the line edge, causing reflow. The act of highlighting creates the very problem it tries to visualize.

### Fix
Use `outline` instead of `border` in the CSS output. Outlines are painted outside the element's box and do not affect layout.

```typescript
// WRONG — border adds width, causes reflow
if (opts.border) parts.push(`border: ${opts.border}`);

// RIGHT — outline looks identical but doesn't affect layout
if (opts.border) parts.push(`outline: ${opts.border}`);
```

### Why this is non-obvious
`border` and `outline` look identical visually for rectangular inline elements. The layout difference (border affects box model, outline doesn't) is a CSS fundamental but easy to overlook when composing dynamic inline styles. ProseMirror's documentation for Decoration.inline doesn't warn about layout-affecting CSS properties.
