### Context
Implementing resizable panels in a Lit web component workbench with shadow DOM. CSS `resize` is unsuitable (see GE-20260916-9b0559). Custom drag handles with PointerEvent provide full-edge dragging, event callbacks for persistence, no overflow constraints, and consistent shadow DOM behavior.

### Technique
A thin `<div>` (4px) rendered between panels acts as the drag handle. Three PointerEvent listeners handle the full lifecycle:

```typescript
private _onDragStart(panel: 'nav' | 'member', e: PointerEvent) {
  const target = e.currentTarget as HTMLElement;
  target.setPointerCapture(e.pointerId);
  const startX = e.clientX;
  const startWidth = panel === 'nav' ? this._navWidth : this._memberWidth;
  const minW = 180;
  const maxW = panel === 'nav' ? 360 : 300;

  const onMove = (me: PointerEvent) => {
    const delta = panel === 'nav' ? me.clientX - startX : startX - me.clientX;
    const newWidth = Math.max(minW, Math.min(maxW, startWidth + delta));
    if (panel === 'nav') this._navWidth = newWidth;
    else this._memberWidth = newWidth;
  };

  const onUp = () => {
    target.removeEventListener('pointermove', onMove);
    target.removeEventListener('pointerup', onUp);
    // persist width to layout store here
  };

  target.addEventListener('pointermove', onMove);
  target.addEventListener('pointerup', onUp);
}
```

Template integration:
```typescript
// Between left panels and main
${leftPanels.length > 0 ? html`
  <div class="drag-handle"
    @pointerdown=${(e: PointerEvent) => this._onDragStart('nav', e)}
    @dblclick=${() => { this._navWidth = 240; /* reset + persist */ }}>
  </div>` : nothing}
```

CSS:
```css
.drag-handle {
  width: 4px;
  cursor: col-resize;
  background: transparent;
  flex-shrink: 0;
  transition: background 0.15s;
}
.drag-handle:hover { background: var(--pages-accent-7, #818cf8); }
.drag-handle:active { background: var(--pages-accent-9, #007bff); }
```

### Key insights

1. **`setPointerCapture`** eliminates the need for global `document.addEventListener('pointermove/pointerup')`. Events continue firing on the capture target even when the pointer leaves the element during drag.

2. **Delta direction inversion** — for right-side panels, the delta is `startX - me.clientX` (inverted) because dragging left should increase the panel width.

3. **Double-click to reset** — add `@dblclick` on the drag handle to restore default widths. A small usability win that's easy to miss.

4. **Persist on pointerup, not pointermove** — updating layout store on every move event floods localStorage. Persist once when the drag ends.

### Why this is non-obvious
Developers typically reach for CSS `resize` first (the "native" approach) or heavy resize libraries (split.js, allotment). The key insight is that `setPointerCapture` + three event listeners is the entire implementation — ~30 lines, no dependencies, works in shadow DOM, and handles edge cases (mouse leaving the element during drag) that global-listener approaches struggle with.
