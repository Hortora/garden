## Symptom

CSS styles inside a `@layer` are overridden by unlayered host page CSS (e.g. `* { box-sizing: border-box }`, `button { appearance: none }`). The layer was expected to provide isolation — instead it makes the layered CSS *weaker* than the host.

## Context

Common when embedding a third-party library (React Flow, ECharts, etc.) inside a light-DOM container and attempting to isolate it from host page globals. Blog posts and framework docs recommend `@layer` for CSS scoping, which suggests it can prevent host styles from leaking in.

## Root cause

The CSS cascade resolves priority in this order for normal (non-`!important`) declarations:

1. Unlayered author styles (highest priority)
2. Layered author styles (later layers > earlier layers)

This means **all unlayered CSS beats all layered CSS**, regardless of specificity or source order. If the host page's CSS is unlayered (which is the common case — most existing CSS doesn't use `@layer`), putting your CSS in a layer makes it *subordinate* to the host, not isolated from it.

The host's `* { box-sizing: border-box }` (unlayered, specificity 0,0,0) beats `.my-container .my-element { box-sizing: content-box }` (layered, specificity 0,2,0). Specificity is only compared *within* the same cascade origin and layer — cross-layer, the unlayered declaration always wins.

## What was tried (didn't work)

A design spec proposed `@layer diagram.reactflow` to "prevent host globals from affecting internals." Analysis during implementation proved this backwards — layered CSS is weaker, not stronger, than unlayered host CSS.

## Fix

For light-DOM CSS isolation from unlayered host CSS, use three mechanisms instead of `@layer`:

1. **`all: initial` on the container** — resets all inherited properties (including custom properties) from the host
2. **Scoped `all: revert` on children** (`.container * { all: revert; }`) — specificity 0,1,0 beats the host's `*` (0,0,0) and element resets like `button` (0,0,1), reverting host author styles to browser defaults
3. **Theme/token re-injection** — re-declare design tokens on the container after `all: initial` kills them (e.g. via a theme injection API)

Use **source order** (import ordering) for internal CSS cascade control between your own stylesheets. This achieves the same priority ordering as `@layer` without the unlayered-beats-layered pitfall.

`@layer` is still useful for organizing CSS *within* a project where all CSS is layered. It does NOT help when you need to isolate from external unlayered CSS.

## Why this is non-obvious

`@layer` is widely recommended for CSS isolation and scoping. The MDN documentation does state that unlayered styles take precedence, but this is buried in the cascade algorithm details. The mental model developers form — "layers provide isolation" — is correct only when ALL CSS is layered. In the common case (embedding inside a host page with legacy unlayered CSS), `@layer` has the opposite effect.

### Alternatives considered

- `@layer` with `!important` — would flip the priority (layered `!important` beats unlayered `!important` when the layer is declared first). Rejected: `!important` is a maintenance nightmare and breaks the cascade for everything inside the layer.
- Shadow DOM — provides genuine style isolation but incompatible with libraries that need document-level event handlers, portals, or CSS-in-JS injection (e.g. React Flow).
- iframe — full isolation but heavy, no shared theme tokens, no event propagation.
