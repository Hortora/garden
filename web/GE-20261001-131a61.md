### Symptom
`Failed to resolve import "@casehubio/pkg/dist/sample-data.js"` even though the alias `{ find: '@casehubio/pkg', replacement: resolve(__dirname, '../components/pkg/src') }` is configured in `vite.config.ts`.

### Context
Occurs in Vite dev server with monorepo workspace aliases. The alias resolves bare imports (`import '@casehubio/pkg'`) correctly but fails on subpath imports (`import '@casehubio/pkg/dist/file.js'` or `import '@casehubio/pkg/src/file.js'`).

### What was tried (didn't work)
- Changing `/dist/` to `/src/` in the import path — still fails
- Vite's `resolve.alias` with exact string match — only matches the bare package name

### Root cause
Vite's `resolve.alias` with a string `find` value performs an exact prefix match on the bare module specifier. `@casehubio/pkg` matches `@casehubio/pkg` but NOT `@casehubio/pkg/dist/...`. To match subpath imports, use a regex pattern: `{ find: /^@casehubio\/pkg\/(.*)/, replacement: resolve(__dirname, '../components/pkg/src/$1') }`.

### Fix
For showcase/example pages that need to import from sibling packages, use relative paths instead of aliased subpath imports:

```typescript
// Won't work with bare alias
import { sampleData } from '@casehubio/blocks-ui-evolution-workbench/src/sample-data.js';

// Works — relative path bypasses alias resolution
import { sampleData } from '../../../components/evolution-workbench/src/sample-data.js';
```

Alternatively, add a regex alias for each package that needs subpath resolution.

### Why this is non-obvious
The bare import (`import '@casehubio/pkg'`) resolves correctly, so the alias appears to be working. The failure only surfaces when adding a subpath, and the error message doesn't mention the alias — it just says the import can't be resolved, suggesting the file doesn't exist.
