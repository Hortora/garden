## Symptom

ReactFlow's built-in `fitView` always centres content in the canvas.
There is no alignment option (top-left, bottom-right, etc.). When nodes
resize asynchronously after initial measurement (e.g. thumbnails loading
inside Web Components), `fitView` calculates zoom from stale dimensions
and clips content.

## Context

ReactFlow renders inside a Web Component (LitElement) shadow DOM.
`document.querySelector('.react-flow')` cannot reach the canvas element
for manual viewport dimension calculation. `useNodesInitialized()` fires
before async content (like embedded SVG thumbnails) finishes expanding,
so a single fitView call at that point uses wrong bounding boxes.

Timer-based delays (`setTimeout(doFit, 300)`) are fragile — they guess
at timing rather than reacting to actual state.

## Fix

Subscribe to ReactFlow's internal store for the aggregate bounding box
of measured nodes. Re-fit whenever the bounding box changes:

```tsx
const viewportSizeSelector = (s: { width: number; height: number }) =>
  ({ width: s.width, height: s.height });

function computeBounds(nodes: Node[]): string {
  let minX = Infinity, minY = Infinity, maxX = -Infinity, maxY = -Infinity;
  for (const node of nodes) {
    const w = node.measured?.width ?? node.width ?? 150;
    const h = node.measured?.height ?? node.height ?? 40;
    minX = Math.min(minX, node.position.x);
    minY = Math.min(minY, node.position.y);
    maxX = Math.max(maxX, node.position.x + w);
    maxY = Math.max(maxY, node.position.y + h);
  }
  return `${Math.round(minX)},${Math.round(minY)},${Math.round(maxX)},${Math.round(maxY)}`;
}

const boundsSelector = (s: { nodeLookup: Map<string, Node> }) => {
  const nodes = Array.from(s.nodeLookup.values());
  return nodes.length > 0 ? computeBounds(nodes) : '';
};

function FitTopLeft({ nodes, onFitRef }) {
  const { setViewport, getNodes } = useReactFlow();
  const { width: vw, height: vh } = useStore(viewportSizeSelector);
  const bounds = useStore(boundsSelector);
  const lastFittedBounds = useRef('');

  const doFit = useCallback(() => {
    const measured = getNodes();
    if (!measured.length || !vw || !vh) return;
    // ... compute bounding box, zoom, setViewport
    lastFittedBounds.current = bounds;
  }, [getNodes, setViewport, vw, vh, bounds]);

  useEffect(() => {
    if (!bounds || bounds === lastFittedBounds.current) return;
    doFit();
  }, [bounds, doFit]);

  return null;  // renders nothing — pure side-effect component
}
```

Place `<FitTopLeft>` inside the `<ReactFlow>` tree (not outside it —
`useReactFlow()` requires the ReactFlow context provider as ancestor).

Also hide the default fit button and add a custom one that calls
`doFit()` via a ref:

```tsx
<Controls showFitView={false}>
  <ControlButton onClick={() => fitRef.current?.()} title="Fit to view">
    {/* fit icon SVG */}
  </ControlButton>
</Controls>
```

## Why this is non-obvious

Three separate non-obvious aspects compound:

1. `useStore(boundsSelector)` with `nodeLookup` — the store shape is
   internal API, not documented for this use case
2. Shadow DOM blocks `document.querySelector` — viewport dimensions
   must come from the store, not DOM measurement
3. String-serialised bounds as the change detector — avoids object
   reference instability that would cause infinite re-render loops

The obvious approach (`fitView` prop + `useNodesInitialized`) fails
silently when nodes resize after initialisation. The next obvious
approach (timer delay) is fragile. The reactive subscription is the
only approach that is both correct and deterministic.

### Alternatives considered

- `fitView` prop with `fitViewOptions` — no alignment control, centres content
- `useNodesInitialized` + single fit — fires before async resize completes
- `setTimeout(doFit, 300)` — fragile, breaks on slow renders, code smell
- `ResizeObserver` on canvas container — can't reach inside shadow DOM
