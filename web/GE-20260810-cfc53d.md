### Symptom
The AML workbench UI spec assumed a standalone `dataset()` function that could create datasets at runtime for parameterised drill-down (e.g. click case → create `dataset("case-detail", { url: /api/investigations/${caseId} })`). No such function exists.

### Context
casehub-pages uses a component-tree model where datasets are declared as page-level options at definition time. `loadSite()` calls `buildDataSetScope()` which walks the component tree and creates a static `DataSetScope` (a `Map<string, Map<DataSetId, DataSetEntry>>`). The `LiveSite` interface returned by `loadSite()` exposes only `navigate()`, `setTheme()`, `dispose()`, and `layout` — no dataset mutation methods.

### Root cause
The pages DSL is designed for declarative, YAML-like site definitions where datasets are scoped to pages in the component tree. `extendDataSetScope()` exists for lazy page resolution (adding new pages to the tree), not for application-code-driven dataset creation. The architecture assumes data shapes are known at site definition time.

### Fix
For applications needing dynamic, event-driven data loading (click item → fetch item-specific data), use **blocks-ui components** with direct REST endpoint attributes instead of the pages DSL:

```typescript
// blocks-ui pattern — endpoint is an attribute, data loads on selection events
html`
  <blocks-split-workbench selection-topic="case">
    <blocks-list-pane slot="list"
      selection-topic="case"
      endpoint="/api/investigations">
    </blocks-list-pane>
    <blocks-detail-pane slot="detail"
      selection-topic="case"
      .tabs=${investigationTabs}>
    </blocks-detail-pane>
  </blocks-split-workbench>
`;
```

blocks-ui components handle parameterised data loading natively via `selection-topic` event-driven data flow. No need for the composite endpoint fallback described in the spec.

### Why this is non-obvious
The spec examples show `dataset("name", { url: "..." })` calls that look like a runtime API. The pages codebase exports `buildDataSetScope` and `resolveDataSetDef` from `pages-runtime`, which suggests a dataset management layer. But neither is mutable after initialization. You only discover this by reading the `LiveSite` interface and `dataset-scope.ts` source — there's no documentation stating the limitation.
