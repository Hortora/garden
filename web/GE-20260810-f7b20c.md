### Symptom
An ECharts treemap with hierarchical data shows a single large rectangle (the root) instead of nested children. In dark mode, this appears as a white square with no sub-divisions.

### Context
When building treemap data from flat rows with a parent column, parent nodes naturally get `value: 0` from the dataset (since their "size" is the sum of children, not an independent value). ECharts treemap uses the explicit `value` for sizing — it does NOT auto-sum from children when `value` is present.

### Root cause
`{ name: "Company", value: 0, children: [...] }` tells ECharts the node has size 0. The children have values but the parent's explicit 0 takes precedence over any auto-sum behaviour. The treemap renders the parent as a 0-area rectangle, making children invisible.

### Fix
After building the tree, delete `value` from branch nodes so ECharts auto-sums from children:

```typescript
const clearBranchValues = (nodes: TreeNode[]): void => {
  for (const n of nodes) {
    if (n.children && n.children.length > 0) {
      delete (n as Partial<TreeNode>).value;
      clearBranchValues(n.children);
    }
  }
};
clearBranchValues(roots);
```

### Why this is non-obvious
The ECharts treemap documentation implies auto-sum happens for parent nodes. In practice, an explicit `value` field — even 0 — suppresses auto-sum. The fix is to omit `value` entirely on branch nodes, not set it to the sum of children.
