## Context

A curation workbench needs to display entries with metadata (from one endpoint), health scores (from another), and boolean flags like isDuplicate/isOutlier (from a third). Each data source has different availability — health scores require analyses to have run, flags depend on cached analysis results, but basic entry metadata is always available.

## Technique

Load three independent REST endpoints in parallel via `Promise.all`, then join client-side by a shared key (Qdrant UUID):

```typescript
const [entriesRes, healthRes, flagsRes] = await Promise.all([
  fetch('/api/entries'),
  fetch('/api/analysis/health'),
  fetch('/api/analysis/flags'),
]);

let entries = entriesRes.ok ? await entriesRes.json() : [];
const healthMap = new Map();
if (healthRes.ok) {
  const data = await healthRes.json();
  for (const he of data.health.entries) healthMap.set(he.entryId, he);
}
const flagsMap = new Map();
if (flagsRes.ok) {
  const flags = (await flagsRes.json()).flags;
  for (const [id, f] of Object.entries(flags)) flagsMap.set(id, f);
}

// Join — missing data defaults to null/false
this.entries = entries.map(e => ({
  ...e,
  compositeScore: healthMap.get(e.id)?.compositeScore ?? null,
  isDuplicate: flagsMap.get(e.id)?.isDuplicate ?? false,
  // ... other merged fields
}));
```

Each endpoint degrades independently: no health data → scores show "—", no flags → signal filter counts show 0, no entries → empty list. The UI is useful at every level of data availability.

## Why this is non-obvious

The natural instinct is a single composite endpoint (`GET /api/workbench`) that returns everything pre-joined. That approach couples the API to the view, requires the backend to handle partial availability internally, and makes the endpoint slow (blocked by the slowest data source). The three-way client join keeps APIs orthogonal, enables parallel loading (wall-clock time = slowest endpoint, not sum), and makes graceful degradation trivial — each `if (res.ok)` branch handles its own failure case.

Filter counts computed from the joined dataset update instantly on domain/type scope changes — no server round-trips for filter state.
