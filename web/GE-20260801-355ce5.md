## Symptom

After applying `style="all: initial"` on a container to isolate it from inherited host styles, CSS custom properties (`--pages-*` design tokens) are no longer available inside the container. Components inside the reset container that reference `var(--pages-primary)` get the initial value (empty/transparent).

## Context

Common when embedding a third-party library (e.g. React Flow) inside a design-token-based UI. You want to reset inherited styles (font, box-sizing, margins) without losing your design tokens. `all: initial` seems like the right tool — reset everything, then your library's CSS takes over.

## Root cause

Per the CSS spec, `all: initial` resets ALL properties including custom properties (`--*`). Custom properties are not exempt from the `all` shorthand. This is correct per spec but counter-intuitive — custom properties feel like "user-defined variables" that should be separate from presentation properties.

`all: revert` has the same issue — it reverts custom properties to their initial value (empty).

## Fix

After `all: initial`, explicitly re-declare every design token the container needs:

```css
.isolated-container {
  all: initial;
  
  /* Must explicitly re-declare — all:initial killed these */
  --pages-color-primary: var(--pages-color-primary-from-parent, #0066cc);
  --pages-spacing-md: var(--pages-spacing-md-from-parent, 8px);
  --pages-font-body: var(--pages-font-body-from-parent, system-ui);
  /* ... every token the container's children need */
}
```

The token list must be maintained as the design system evolves. This is a maintenance burden — each new token requires updating the re-declaration list.

**Alternative approach:** Instead of `all: initial`, use targeted resets for the specific properties you need to neutralize:

```css
.isolated-container {
  font: initial;
  color: initial;
  box-sizing: content-box;
  /* Reset only what leaks — custom properties survive */
}
```

This preserves custom properties but is less thorough — new host styles may leak through properties you didn't reset.

## Why this is non-obvious

`all: initial` is widely recommended for CSS isolation. The MDN documentation mentions that it applies to all properties but doesn't prominently flag the custom property implication. Most developers discover this only when their design tokens stop working after applying the reset.

The related garden entry GE-20260706-9335b9 covers Shadow DOM custom property override behaviour — this entry covers the `all:initial` reset case which occurs specifically when Shadow DOM is *disabled* and `all:initial` is used as a CSS isolation substitute.
