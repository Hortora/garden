### Symptom
Hub-spoke graph layouts with bidirectional edges (A→B DELEGATES_TO and B→A REPORTS_TO) produce overlapping edge paths. The handle optimizer assigns mirror handles (top→bottom forward, bottom→top return) which render as the same visual path in opposite directions.

### Context
Org chart federation pattern: orchestrator at center, specialists around it. Each pair has forward (delegation) and return (reporting) edges. With 4 handle positions per node (top/bottom/left/right), the shortest-distance optimizer assigns both edges the same path.

### What didn't work
- Cross-type congestion (penalizing source+target on same side) — prevents exact mirror but both edges still take nearly-parallel paths
- Same-type congestion (penalizing multiple sources on same side) — spreads outgoing edges but doesn't separate inverse pairs
- Global handle optimizer with higher direction penalty — the optimizer's global search overrides local preferences

### Root cause
The handle optimizer treats each edge independently by distance, with congestion as a weak coupling. For inverse pairs, the shortest-distance handles are mirrors of each other — both paths are geometrically equivalent.

### Fix
Compute per-edge handle preference from the angle between source and target centers. For the second edge in an inverse pair, rotate the preferred direction by 90 degrees clockwise:

```typescript
const angle = Math.atan2(tgtCy - srcCy, tgtCx - srcCx);
const reverseKey = `${edge.target}:${edge.source}`;
const rot = assignedPairs.has(reverseKey) ? Math.PI / 2 : 0;
const srcSide = angleToSide(angle + rot);
const tgtSide = angleToSide(angle + Math.PI + rot);
```

This creates a pinwheel pattern: forward edges use the nearest side, return edges use the clockwise-adjacent side. Each side of the hub has at most one incoming and one outgoing edge from adjacent spokes.

### Why this is non-obvious
The standard approach (yFiles, GoJS) uses ELK's `portConstraints: FIXED_ORDER` which only works for the layered algorithm. For radial/stress/force layouts, no standard port assignment exists. The clockwise rotation trick comes from graph visualization literature but isn't implemented in any common open-source library.
