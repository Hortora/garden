## Symptom

CodeMirror 6 editor renders content and accepts input inside a LitElement shadow root, but no cursor (caret) is visible. The editor has focus (outline visible), text can be typed, but the blinking cursor line never appears. No error in the console.

## Context

A LitElement web component wrapping CodeMirror 6's `EditorView`, mounted inside the component's shadow root. The editor uses `contenteditable` for input. Without `drawSelection()`, CodeMirror relies on the browser's native caret rendering.

## What was tried (didn't work)

1. Checked cursor CSS — `.cm-cursor` element existed with correct `borderLeftColor` and `borderLeftWidth`
2. Verified the cursor element was positioned correctly (`position: absolute`, correct bounding rect)
3. Assumed the cursor was being caught mid-blink during screenshots — set `cursorBlinkRate: 0` to disable blinking
4. Even with blinking disabled, the native browser caret was not reliably visible inside shadow DOM

## Root cause

CodeMirror 6 has two cursor rendering modes:
1. **Native browser caret** (default) — uses the browser's built-in `contenteditable` cursor
2. **Custom cursor** via `drawSelection()` extension — renders CM6's own `.cm-cursor` element

The native browser caret does not render reliably inside shadow DOM `contenteditable` elements. The browser's caret rendering engine appears to have issues with the shadow boundary — the caret exists but is not painted.

## Fix

Add `drawSelection()` to the CodeMirror extensions:

```typescript
import { EditorView, drawSelection } from '@codemirror/view';

const view = new EditorView({
  state: EditorState.create({
    extensions: [
      drawSelection(),  // renders CM6's own cursor element
      // ... other extensions
    ],
  }),
  parent: shadowRoot.querySelector('.cm-host'),
});
```

Also widen the cursor for better visibility:

```typescript
EditorView.theme({
  '.cm-cursor, .cm-dropCursor': {
    borderLeftColor: 'var(--your-cursor-color)',
    borderLeftWidth: '2px',
  },
});
```

## Why this is non-obvious

The editor works perfectly — content renders, typing works, selection works, everything except the cursor is visible. There is no error, no warning, and no indication that `drawSelection()` is needed. The native browser caret is the expected default for `contenteditable`, and it works fine outside of shadow DOM. The connection between "cursor not visible" and "need to add an extension" is not documented in CodeMirror's shadow DOM guidance.

### Alternatives considered

- Setting `caret-color` CSS property — has no effect because the native caret isn't being painted at all, not just colored wrong
- Using `contenteditable="plaintext-only"` — doesn't affect caret rendering
