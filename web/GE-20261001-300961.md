## Symptom

A catalog action invoked with scalar shorthand (e.g., `navigate: "/dashboard"`) resolves as a `PluginStep` with `params: {}` — the scalar value is silently dropped. No error, no warning. The action's `execute()` receives an empty params map.

## Context

The Walker's `resolveOne()` method in `packages/yaml-core/src/step/walker.ts` resolves unrecognised keys by looking them up in the catalog. When found, it creates a `PluginStep` with the key's value as params. The value coercion logic:

```typescript
const params = (typeof actionValue === 'object' && actionValue !== null && !Array.isArray(actionValue))
  ? actionValue as Record<string, unknown>
  : {};  // ← scalar values become empty object
```

This silently succeeds — the step resolves, the action is found in the catalog, but params are empty.

## What was tried (didn't work)

Defining a catalog action like `navigate` that expects `{ value: "/dashboard" }` — the action receives `{}` and silently does nothing or throws a confusing "missing required param" error far from the parsing layer.

## Root cause

The Walker was designed for object-valued action params (e.g., `click: { role: button, name: A }`). Scalar values were an unconsidered case — the fallback `{}` was written as a safety default, not as a deliberate "drop the value" decision.

## Fix

Wrap non-object values as `{ value: actionValue }` instead of dropping them:

```typescript
const params = (typeof actionValue === 'object' && actionValue !== null && !Array.isArray(actionValue))
  ? actionValue as Record<string, unknown>
  : { value: actionValue };
```

Actions that accept shorthand forms declare `value` as an input in their Definition.

## Why this is non-obvious

The Walker resolves the step successfully — no error at parse time. The failure appears at execute time as a missing-param error in the action's implementation, far from the coercion in `resolveOne()`. A developer adding a new catalog action with scalar shorthand would debug the action's execute method, not the Walker's param extraction.

### Alternatives considered

- Throwing an error for non-object values — rejected because scalar shorthand (`navigate: "/path"`) is a legitimate and ergonomic YAML pattern
- Array wrapping — rejected because arrays have distinct semantics from scalars
