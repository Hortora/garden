### What it does
The `LiveSite` interface returned by `loadSite()` has `navigate(path: string)` — this walks the component tree using slot names as path segments. For `tabs()` components, the slot names ARE the tab labels passed to the `tabs()` builder.

### How to use it
```typescript
// Switch to the Cases tab
site.navigate("Cases");

// Switch to a nested sub-tab (System → Definitions)
site.navigate("System/Definitions");
```

For selecting an entity within a tab after navigation, use `emitPagesEvent` from `@casehubio/pages-component`. Note the required `target: EventTarget` first argument:

```typescript
import { emitPagesEvent } from "@casehubio/pages-component";

// Navigate to tab, then select an entity
site.navigate("Cases");
setTimeout(() => {
  emitPagesEvent(appContainer, "case:selected", { id: "abc-123" });
}, 100);
```

The `setTimeout` allows the tab's components to mount before receiving the selection event.

### Why it's undocumented
There is no `selectTab()`, `switchTab()`, or `setActiveTab()` method on `LiveSite`. The `navigate()` method's connection to tab labels is only apparent from reading the source (`walkNavigate` in `navigation.ts` which uses `findInteractiveWithSlot` to match path segments to slot names). The `LiveSite` interface in the `.d.ts` just shows `navigate(path: string): void` with no documentation of what constitutes a valid path.

Similarly, `emitPagesEvent` is exported from `@casehubio/pages-component` but its `target` parameter requirement (it dispatches a CustomEvent on the target, not globally) is only clear from the implementation in `pages-data/src/events.ts`.
