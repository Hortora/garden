### Symptom
Lit template content inside a React Flow custom node re-creates the entire DOM subtree on every React re-render, even when only one property changed. Performance degrades with complex templates.

### Context
Bridging lit-html into React using `useRef` + `useEffect` + `render(template, container)`. The natural pattern puts both render and cleanup in one effect.

### What was tried (didn't work)
Single `useEffect` with cleanup:
```tsx
useEffect(() => {
  render(template, containerRef.current!);
  return () => { render(nothing, containerRef.current!); };
}, [id, type, data]);
```

### Root cause
React runs the previous effect's cleanup function *before* re-running the effect on dependency change. `render(nothing, container)` clears lit-html's tracked DOM parts. The subsequent `render(template, container)` finds no tracked parts and creates everything from scratch — destroying lit-html's efficient diff-patch capability.

### Fix
Split into two separate effects:
```tsx
// Render effect — fires on mount and data changes
// lit-html render() diffs against tracked parts
useEffect(() => {
  render(template, containerRef.current!);
}, [id, type, data]);

// Cleanup effect — fires only on unmount
useEffect(() => {
  return () => { render(nothing, containerRef.current!); };
}, []);
```

### Why this is non-obvious
React's useEffect cleanup semantics are well-documented, but their interaction with lit-html's tracked-parts model is not. A developer familiar with both frameworks would naturally combine render and cleanup in one effect (the standard React pattern). The bug is invisible until you profile — the DOM looks identical, just rebuilt instead of patched.

### Alternatives considered
- Using `useLayoutEffect` instead — same problem, cleanup still runs on dependency change
- Skipping cleanup entirely — causes memory leaks, lit-html parts accumulate
- Using a ref flag to skip cleanup on updates — fragile, doesn't handle React strict mode double-invocation
