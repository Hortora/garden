## Symptom

Calling `document.createElement('a')` with `download` and `href` attributes, then `.click()`, produces no download. No error in console. The click event fires but the browser ignores it.

## Context

Exporting a rendered diagram (React Flow viewport) to SVG or PNG using `html-to-image`. The library returns a data URL. The standard pattern for triggering a browser download is to create an anchor element, set its `download` and `href` attributes, and call `.click()`.

Two independent failure modes compound:

1. **Detached anchor** — most browsers require the `<a>` element to be in the DOM for `.click()` to trigger a download. A detached element (never appended to `document.body`) fires the click event but the browser's download manager ignores it.

2. **Data URL size limit** — for large exports (>500KB), some browsers silently truncate or refuse data URLs as `href` values on download anchors. The download either produces a corrupted file or doesn't start at all.

## What was tried (didn't work)

```javascript
const link = document.createElement('a');
link.download = 'diagram.png';
link.href = dataUrl;  // data:image/png;base64,...
link.click();          // silent no-op in most browsers
```

## Root cause

1. Browser download manager requires the anchor to participate in the document's navigation context — detached nodes don't.
2. Data URLs encode the entire payload in the URL string, which hits browser-internal size limits for navigation/download URLs.

## Fix

Convert the data URL to a Blob URL and attach the anchor to the DOM:

```javascript
const response = await fetch(dataUrl);
const blob = await response.blob();
const blobUrl = URL.createObjectURL(blob);

const link = document.createElement('a');
link.download = filename;
link.href = blobUrl;
link.style.display = 'none';
document.body.appendChild(link);
link.click();
document.body.removeChild(link);
URL.revokeObjectURL(blobUrl);
```

Key details:
- `fetch(dataUrl)` converts the data URL to a Blob without network I/O
- `URL.createObjectURL()` creates a short `blob:` URL that the browser handles natively
- The anchor must be in the DOM before `.click()` and removed after
- `URL.revokeObjectURL()` prevents memory leaks from retained blob references

## Why this is non-obvious

The detached anchor pattern appears in many tutorials and Stack Overflow answers. It works in some browsers under some conditions (small files, specific browser versions), making the failure intermittent and hard to diagnose. The React Flow official download example uses the detached pattern, which propagates the issue to anyone following their docs. The data URL size issue is entirely silent — no error, no warning, just no download.

### Alternatives considered

- **`window.open(dataUrl)`** — opens in a new tab rather than downloading; user has to right-click → Save As
- **`navigator.msSaveBlob()`** — IE/Edge legacy API, not available in modern browsers
- **FileSaver.js** — adds a dependency for something achievable in 8 lines
