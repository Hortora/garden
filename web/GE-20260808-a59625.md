### Symptom
Dashboard renders as three equal-width columns. Left and right dock panels (~33% width each) are mostly white space. Centre content is cramped despite being the primary view.

### Context
Using `dockWorkbench(config)` from `@casehubio/pages-ui/dist/dsl/builders.js` with left and right dock panels. `DockPanelConfig` accepts `minSize` but no `defaultSize` or `initialSize`. On a 1920px screen, each column gets ~640px — far too wide for narrow dock content (inbox list, family summary).

### What was tried (didn't work)
Setting `minSize: 200` and `minSize: 240` on dock panels — these set floors but not initial sizes. The `DockWorkbenchConfig` type has no sizing options beyond per-panel `minSize`.

### Root cause
`dockWorkbench()` internally calls `split("horizontal", [leftZone, centreArea, rightZone], { minSizes })` with no initial size ratios. The `split()` component defaults to equal distribution across children.

This is undocumented — the `DockWorkbenchConfig` TypeScript interface shows only `storageKey`, `centre`, `left`, `right`, `bottom`. No sizing control is exposed. The equal-split behaviour is only visible by reading the compiled `builders.js` source (lines 376–389).

### Fix
Replace `dockWorkbench()` with a CSS grid layout:

```typescript
// CSS grid with fixed-width side panels, centre fills remaining space
static override styles = css`
  .layout {
    display: grid;
    height: 100%;
    grid-template-columns: auto 1fr auto;
    gap: 1px;
  }
  .dock-bar { width: 32px; }
  .dock-panel { width: 280px; }
`;
```

Build the dock bar (vertical tab labels) and panel toggling manually with Lit `@state()`. This gives full control over sizing and matches IntelliJ-style dock behaviour — narrow side panels with centre filling remaining space.

### Why this is non-obvious
The API surface (TypeScript types, JSDoc) gives no indication of the equal-split default. A developer configuring `minSize: 200` reasonably expects narrow dock panels, not 33%-width columns. The `split()` function is an internal implementation detail of `dockWorkbench()` — not documented in the DSL API. The design spec (§3.1) anticipated this with a documented CSS grid fallback, which is what the fix implements.

### Why this fix
CSS grid with fixed column widths is simpler, more predictable, and gives the consumer full layout control. The dock workbench abstraction adds resizable splitters which are unnecessary for a dashboard with fixed dock panel widths.

### Alternatives considered
- Setting `minSize` to the desired width — doesn't work; `minSize` is a floor, not a default
- CSS `max-width` on dock panels — the `split()` component manages sizing internally; external CSS constraints fight the split layout engine
- Patching pages-ui to add `defaultSize` — correct long-term fix but requires upstream change
