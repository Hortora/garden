### Symptom
WebSocket connection established, server sends data, but the frontend receives nothing. No errors, no warnings, no events dispatched. The EventConnection appears connected and healthy.

### Context
Using `createEventConnection` from `@casehubio/pages-data` to receive push protocol messages. The server sends raw PushMessage dataset operations (e.g., `{"op":"snapshot","dataset":"channels","columns":[...],"rows":[...]}`).

### What was tried (didn't work)
Verified the WebSocket was connected, confirmed the server was sending data, checked for JSON parse errors. All looked correct — messages were received and parsed, but nothing was dispatched to the EventTarget.

### Root cause
EventConnection's `handleMessage` only dispatches messages where `op === "event"`. All other ops (`snapshot`, `append`, `replace`, `remove`, `ack`, `error`) are either handled specially (ack/error) or silently dropped. There is no catch-all, no warning, no fallback.

The pages-push protocol expects events to be wrapped in an event envelope: `{"op":"event","topic":"chat:messages","payload":{...},"seq":42}`. The actual dataset op goes inside `payload`. EventConnection extracts `payload` and dispatches it via `dispatchWireEvent`.

### Fix
Wrap all server-sent messages in `PushMessage.event(topic, payloadJson)` before sending to clients — including initial snapshots and replayed events. The `writeRawValue` in PushMessage.event embeds the payload as a nested JSON object, not a string.

```java
// Instead of:
sendText(connection, datasetBuilder.buildSnapshot(topic));
// Use:
sendText(connection, PushMessage.event(topic, datasetBuilder.buildSnapshot(topic)));
```

### Why this is non-obvious
The EventConnection receives and parses the messages correctly. The JSON is valid. The connection is healthy. There is zero indication that messages are being dropped — no warning log, no error callback, no rejected promise. The only symptom is silence.

### Alternatives considered
- Modifying EventConnection to handle raw dataset ops — rejected because EventConnection is a platform component and the event envelope is the correct protocol
- Adding a raw message handler callback to EventConnection — unnecessary; the fix is to use the protocol correctly on the server side
