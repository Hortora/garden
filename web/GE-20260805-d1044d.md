### Symptom

A YAML path walker that always prepends `/do/` to node IDs produces IDs like `/do/0/tryBlock/try/do/0/innerStep`. The SDK generates `/do/0/tryBlock/try/0/innerStep` — without the extra `/do/` after `try`. The integrity check reports "No YAML path for task node '/do/0/tryBlock/try/0/innerStep'" because the walker's ID doesn't match.

### Context

The SDK's `buildFlatGraph()` generates path-based node IDs. The format varies by context:

| Context | ID format | Example |
|---------|-----------|---------|
| Top-level `do:` array | `/do/{index}/{name}` | `/do/0/fetchData` |
| `try:` subtasks | `/{parent}/try/{index}/{name}` | `/do/0/tryBlock/try/0/innerStep` |
| `catch: do:` subtasks | `/{parent}/catch/do/{index}/{name}` | `/do/0/tryBlock/catch/do/0/handleError` |

### Root cause

The `/do/` segment in node IDs comes from the YAML key name. The top-level task list uses `do:` as the key, so its children get `/do/` in their path. Similarly, `catch:` contains a `do:` key, so catch subtasks get `/catch/do/`.

But `try:` directly contains the task list — there's no nested `do:` key. The YAML structure is:

```yaml
try:
  - innerStep:     # ← directly under try:, no do: wrapper
      call: http
```

Not:

```yaml
try:
  do:              # ← this does NOT exist in SWF
    - innerStep:
        call: http
```

So the SDK path is `/{parent}/try/{index}/{name}`, not `/{parent}/try/do/{index}/{name}`.

### Fix

The YAML walker must use the actual YAML key as the path segment. Don't hardcode `/do/` — pass the path prefix from each call site:

```typescript
// Root: prefix includes /do because the YAML key is 'do:'
walkTaskList(doNode, ['do'], '/do', paths);

// try: subtasks — prefix is just /try, no /do
if (key === 'try' && isSeq(prop.value)) {
  walkTaskList(prop.value, [...nodePath, 'try'], `${nodeId}/try`, paths);
}

// catch/do: subtasks — prefix includes /do because the YAML key IS 'do:'
if (key === 'catch') {
  // walk catch.do
  walkTaskList(catchDoValue, [...nodePath, 'catch', 'do'], `${nodeId}/catch/do`, paths);
}
```

Inside `walkTaskList`, the node ID is `${idPrefix}/${index}/${taskName}` — the caller determines the prefix, not the function.

### Why this is non-obvious

The SDK documentation doesn't specify the node ID format. The format must be discovered empirically by calling `buildFlatGraph()` and inspecting the output. The asymmetry between `try:` (direct task list) and `catch: do:` (nested under `do:` key) is a SWF spec detail that doesn't surface until you're correlating IDs.
