### Symptom
`head.speakAudio({audio, visemes, vtimes, vdurations})` returns without error, `isSpeaking` briefly becomes `true`, but morph target values never change and no lip movement occurs. The avatar stays idle during what should be speech animation.

### Context
Calling `speakAudio` from within an async WebSocket `onmessage` handler that has awaited `blob.arrayBuffer()` and `audioCtx.decodeAudioData()`. The call sits inside a microtask continuation of the original message event.

The same `speakAudio` call works perfectly when invoked directly from a `setTimeout`, a click handler, or the browser console.

### What was tried (didn't work)
- Verified `isSpeaking=true` immediately after call — appeared to work
- Checked morph target data in `mtAvatar` — data was populated but `value: 0, applied: 0`
- Tested with both pre-computed visemes and word-based lip-sync — same result
- Confirmed AudioContext state is `running`, not suspended
- Confirmed model has all 15 Oculus viseme blend shapes on 4 meshes
- Directly setting `morphTargetInfluences[idx] = 1.0` works — proving model is correct

### Root cause
TalkingHead's internal animation scheduling relies on `requestAnimationFrame` timing relative to the current event loop task. When `speakAudio` is called from a microtask continuation (after `await` in an async function triggered by a WebSocket message), the animation frame scheduling doesn't properly initialize. The morph target data is set internally but the animation loop doesn't pick it up.

### Fix
Wrap the `speakAudio` call in `setTimeout(fn, 0)` to break out of the microtask queue into the macrotask queue:

```javascript
var speakData = { audio: audioBuf, visemes: visemes, vtimes: vtimes, vdurations: vdurations };
setTimeout(function() {
  head.speakAudio(speakData);
}, 0);
```

### Why this is non-obvious
The call succeeds — no error, `isSpeaking` briefly becomes `true`, internal morph target data is populated. Every observable side effect suggests it worked. Only visual inspection (no lip movement) reveals the failure. The connection to microtask vs macrotask scheduling requires deep knowledge of both the browser event loop and TalkingHead's internal animation architecture.
