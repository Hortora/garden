## Context

A code generator (ts-morph script) needs to resolve types from sibling
workspace packages by reading their source `.ts` files directly — not
the `dist/` build output. But TypeScript's `paths` mappings that enable
this break the `tsc` build because resolved source files fall outside
the package's `rootDir`.

## Technique

Create two tsconfigs in the generator's package:

**`tsconfig.generator.json`** — used by the ts-morph script:
```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "dist",
    "rootDir": "src",
    "paths": {
      "@scope/pkg-*": ["../../components/*/src/index.ts"],
      "@scope/core": ["../core/src/index.ts"]
    }
  },
  "include": ["src"]
}
```

**`tsconfig.json`** — used by `tsc` for building the package:
```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "dist",
    "rootDir": "src"
  },
  "include": ["src"]
}
```

**`tsconfig.build.json`** — excludes generator-only files from the build:
```json
{
  "extends": "./tsconfig.json",
  "exclude": ["src/**/*.test.ts", "src/registry.ts"]
}
```

The generator script references `tsconfig.generator.json`:
```typescript
const project = new Project({
  tsConfigFilePath: resolve(__dirname, "../tsconfig.generator.json"),
});
```

The build script uses the standard config:
```json
{
  "scripts": {
    "generate": "tsx scripts/generate-schemas.ts",
    "build": "yarn generate && tsc -p tsconfig.build.json"
  }
}
```

## Why this is non-obvious

The natural instinct is one tsconfig per package. Adding `paths` to the
main tsconfig works for the generator but breaks the build with `rootDir`
violations. Removing `paths` from the main tsconfig makes the generator
unable to resolve source types (falls back to stale dist). The split
is the only configuration that satisfies both constraints without
requiring a full workspace build before generation.
