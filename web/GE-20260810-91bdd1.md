### Symptom
When calling `renderComponent(container, child)` in a loop over multiple children,
only the last child appears in the DOM. Previous children silently disappear.

### Context
The `renderComponent` function in `@casehubio/pages-component` calls
`target.innerHTML = ""` on line 28 before rendering the component tree.
This is by design — it replaces the target's content with the rendered tree.

### What was tried (didn't work)
```typescript
for (const child of centreComponents) {
  renderComponent(centreContainer, child, { permissions, onNode: callback });
}
```
Each call clears the previous render. Only the last child survives.

### Root cause
`renderComponent` is designed for rendering a single component tree into a
target — it owns the target's content exclusively. The `innerHTML = ""`
clear is intentional to prevent stale content from accumulating.

### Fix
Wrap multiple children in a layout component before calling `renderComponent` once:

```typescript
const centreRoot: Component = centreComponents.length === 1
  ? centreComponents[0]!
  : { type: "rows", slots: { default: [...centreComponents] } };
renderComponent(centreContainer, centreRoot, { permissions, onNode: callback });
```

### Why this is non-obvious
The existing `deferred` activation handler uses the same loop pattern and
appears to work — but only because deferred panels typically have a single
child. The pattern looks correct by analogy.
