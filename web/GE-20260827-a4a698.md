### Symptom
Setting `reconnectEdges={true}` on the `<ReactFlow>` component has no effect in v12 — edges cannot be reconnected by dragging. TypeScript may or may not flag it depending on the type definitions version, but even with `@ts-ignore` the prop is silently ignored at runtime.

### Context
Occurs when upgrading from React Flow v11 to v12, or when following older documentation/tutorials that reference the v11 prop name.

### Root cause
React Flow v12 renamed the `reconnectEdges` prop to `edgesReconnectable` as part of a broader prop naming convention change. The old prop name is silently ignored — no deprecation warning is emitted.

### Fix
Use the new prop name:

```tsx
// v11 (old)
<ReactFlow reconnectEdges />

// v12 (new)
<ReactFlow edgesReconnectable />
```

### Why this is non-obvious
The rename is not prominently documented in migration guides. The old prop name fails silently — no console warning, no TypeScript error in some type definition versions. The naming convention shift (`verbNoun` → `nounAdjective`) affects multiple props but isn't applied consistently across the API surface, making it hard to guess the new name.
