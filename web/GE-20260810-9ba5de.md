## Conditional vite aliases with `fs.existsSync()` for multi-environment compatibility

### Context
A project consumes packages from sibling repos via vite aliases (e.g. `@scope/pkg` → `../../sibling/src`). This works in the main development layout but breaks in alternative environments (CI, isolated slots, worktrees) where sibling repos aren't at the expected relative path.

### Technique
Make each alias conditional — only add it if the target directory exists. When absent, imports fall back to `node_modules` resolution (from npm-installed packages):

```typescript
import { defineConfig } from 'vite';
import path from 'path';
import fs from 'fs';

const SIBLING = path.resolve(__dirname, '../../../../sibling-repo/packages');

const siblingAlias = (find: string, replacement: string) =>
  fs.existsSync(replacement) ? { find, replacement } : null;

const aliases = [
  siblingAlias('@scope/pkg-a', path.resolve(SIBLING, 'pkg-a/src')),
  siblingAlias('@scope/pkg-b', path.resolve(SIBLING, 'pkg-b/src')),
].filter(Boolean) as { find: string; replacement: string }[];

export default defineConfig({
  resolve: { alias: aliases },
});
```

### Why this is non-obvious
The typical vite alias setup is static — aliases are always present and fail hard if the path doesn't exist (vite reports "Failed to resolve import"). The conditional pattern isn't documented in vite's alias documentation, and most monorepo setups assume a fixed directory structure. The key insight is that vite aliases are optional — when absent, normal node_modules resolution handles the import transparently.

### Alternatives considered
- Environment variables to switch alias sets — fragile, requires CI config changes
- Separate vite configs per environment — duplication, drift risk
- Always install to node_modules via npm — still needs the aliases for dev (live source editing)
