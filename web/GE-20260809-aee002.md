## Symptom

Panels docked to the "middle" or "bottom" positions within a side stripe (left/right column) appear in the wrong zone. A panel meant for the second zone in the left column ends up in the bottom bar instead, or vice versa.

## Stack

- TypeScript / React
- casehub-pages tool-window docking system
- `DockZone` enum and `resolveDockZone()` function

## Context

The dock stripe has three logical zone groups:
1. **Top** — top area of the side column
2. **Middle** — second area of the side column (below top, above bottom bar)
3. **Bottom** — full-width horizontal bar at the bottom of the viewport

These are mapped to zone IDs with a confusing naming pattern.

## Root Cause

Zone naming convention differs between side columns and the bottom bar:
- **Side columns** (left/right): zone IDs are `{side}-{position}` format
  - `left-top`, `left-bottom`, `right-top`, `right-bottom`
- **Bottom bar**: zone IDs are `{position}-{side}` format
  - `bottom-left`, `bottom-right`

The `resolveDockZone()` mapping is:
- `top` → `{side}-top` (e.g., `left-top`)
- `middle` or `top-second` → `{side}-bottom` (e.g., `left-bottom`) ⚠️
- `bottom` → `bottom-{side}` (e.g., `bottom-left`) ⚠️

**The confusion:** "left-bottom" is the second zone in the left column, NOT the bottom bar's left side. "bottom-left" is the bottom bar's left side. The word order reversal is deliberate but unintuitive.

## Fix

Always use the full zone ID explicitly instead of inferring from position names. Document the zone names prominently:

```typescript
enum DockZone {
  LEFT_TOP = "left-top",
  LEFT_MIDDLE = "left-bottom",    // Note: -bottom means 2nd zone in left column
  RIGHT_TOP = "right-top",
  RIGHT_MIDDLE = "right-bottom",  // Note: -bottom means 2nd zone in right column
  BOTTOM_LEFT = "bottom-left",    // This is the full-width bottom bar, left side
  BOTTOM_RIGHT = "bottom-right"   // This is the full-width bottom bar, right side
}
```

In code, avoid relying on `resolveDockZone(position)` — use the explicit zone ID:

```typescript
// ❌ Unclear mapping
const zone = resolveDockZone("middle"); // Which middle? Ambiguous

// ✅ Explicit
const zone = DockZone.LEFT_MIDDLE; // Clear that this is the 2nd zone in left column
```

## Why This is Non-Obvious

The naming pattern follows a grid-like logic (side + position), but reverses word order for the bottom bar to match its visual structure (a horizontal bar subdivided by side). This optimization for the bottom bar's semantics creates confusion elsewhere.

## Constraints

Applies to all dock zone assignments. The naming convention is fixed for backward compatibility.

## Alternatives Considered

- Renaming all zones to `{side}-{ordinal}` format (e.g., `left-1`, `left-2`, `bottom-1`, `bottom-2`) — more uniform but less semantic
- Always requiring explicit enum values (prevents shorthand inference, more verbose)

## Invalidation Triggers

Revisit if dock stripe refactored to support more than 3 zones per side or if bottom bar layout changes significantly.
