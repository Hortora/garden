### Symptom
Importing `EventStreamController` from `@casehubio/blocks-ui-core` and connecting to an SSE endpoint fails silently or connects via WebSocket instead of SSE.

### Context
When building a Lit component that needs to consume standard Server-Sent Events (SSE) from a backend, the natural discovery path leads to `EventStreamController` in `blocks-ui-core` — a Lit Reactive Controller with `hostConnected`/`hostDisconnected` lifecycle management. The name suggests SSE support.

### What was tried (didn't work)
Using `EventStreamController` with an SSE endpoint URL — the controller internally creates an `EventStream` → `EventStreamPool` → `EventConnection` chain that opens a **WebSocket** (`new WebSocket(url)`), not an `EventSource`. The connection either fails (if the backend doesn't support WebSocket) or connects to a different protocol than intended.

### Root cause
The naming hierarchy is misleading:
- `EventStreamController` (blocks-ui-core) wraps `EventStream` (pages-data)
- `EventStream` wraps `EventConnection` (pages-data)
- `EventConnection` creates a `new WebSocket(connectionUrl)` — WebSocket, not SSE

The "EventStream" name refers to a generic push-source abstraction, not the SSE specification. The WebSocket transport is intentional — it supports structured topic subscription, sequence tracking, and bidirectional communication that SSE can't provide.

### Fix
For standard SSE backends, use `SSEManager` from `@casehubio/pages-data`:

```typescript
import { SSEManager } from '@casehubio/pages-data/dist/sse/index.js';
import type { SSEEvent, SSEHandler } from '@casehubio/pages-data/dist/sse/index.js';

const manager = new SSEManager();

// In a Lit Reactive Controller:
hostConnected(): void {
  manager.subscribe('/events/stream', this._handler);
}

hostDisconnected(): void {
  manager.unsubscribe('/events/stream', this._handler);
}
```

`SSEManager` provides connection pooling (one `EventSource` per URL, multiple handlers), exponential backoff reconnection, and RAF-batched event dispatch.

### Why this is non-obvious
The `EventStreamController` name strongly implies SSE support. It's the first result when searching for "SSE" or "event stream" in blocks-ui. The actual SSE utility (`SSEManager`) is in a different package (`pages-data`) under a different name, and must be imported from a subpath (`/dist/sse/index.js`).
