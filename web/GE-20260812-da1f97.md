### Symptom
Running `vitest run` produces hundreds of unexpected test failures from packages you don't own. Test count jumps from ~30 to ~400. Failures reference files in `.casehub-packages/` or other vendored directories.

### Context
A project uses npm `optionalDependencies` with `file:` references to Maven-extracted packages in `.casehub-packages/packages/`. These packages contain their own test files (`*.test.ts`).

### What was tried (didn't work)
Assumed vitest would only discover tests in the project's own `src/` directory. The `root: 'src'` vite config was expected to limit discovery, but vitest's `include: ['**/*.test.ts']` glob operates from the package root, not the vite root.

### Root cause
npm `file:` references create symlinks in `node_modules/@scope/package → .casehub-packages/packages/package`. Vitest's default `include` pattern (`**/*.test.ts`) follows these symlinks and discovers test files in the symlink targets. The default `exclude` list includes `**/node_modules/**` but does NOT include `.casehub-packages/**` or other vendored directories.

The previous `resolutions` with `portal:` protocol (Yarn-only) did NOT create symlinks, so the same pattern worked without this problem.

### Fix
Add the vendored directory to vitest's `exclude` list:

```typescript
// vitest.config.ts
test: {
  environment: 'jsdom',
  globals: true,
  include: ['**/*.test.ts'],
  exclude: ['**/node_modules/**', '**/.casehub-packages/**'],
}
```

### Why this is non-obvious
The test pollution is silent — vitest doesn't warn that it's following symlinks into vendored packages. The failures appear to be in YOUR test suite, with confusing error messages from a different package's test context. The connection between `file:` references creating symlinks and vitest's glob pattern following them is not documented.
