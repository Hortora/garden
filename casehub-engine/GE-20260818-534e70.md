### Symptom
After migrating `GoapWorldState` from `Map<String, Boolean>` to `Map<String, Condition>` (TRUE/FALSE/UNKNOWN), existing dispatch-time planning tests fail — actions that required preconditions now execute without their dependencies being satisfied.

### Context
Adding ternary state (TRUE/FALSE/UNKNOWN) to GOAP world state with optimistic semantics (UNKNOWN satisfies hard preconditions). The change is needed for decomposition-time planning under partial observability.

### Root cause
Previously, absent keys in `GoapWorldState` returned `false` via `Boolean.TRUE.equals(conditions.get(key))`. After the ternary migration, absent keys return `Condition.UNKNOWN`. With optimistic semantics, UNKNOWN satisfies preconditions — so actions whose preconditions reference absent keys become applicable when they shouldn't be.

This silently changes planning semantics for all existing dispatch-time callers (`GoapPlanningStrategy`, `AdaptivePlanningStrategy`) without any compilation error.

### Fix
Provide two separate factory methods with different absent-key semantics:

- `closedWorld(Map<String, Boolean>)` — for dispatch-time callers. Only maps explicitly provided keys. Callers must also set all precondition keys from the action set to FALSE when they're not in the working layer:
  ```java
  for (GoapAction action : definition.getGoapActions()) {
    for (String key : action.preconditions().keySet()) {
      conditions.putIfAbsent(key, false);
    }
  }
  return GoapWorldState.closedWorld(conditions);
  ```

- `openWorld(JsonNode)` — for decomposition-time planning. Non-null JSON values → TRUE, absent keys → UNKNOWN. Used by `GoapDecompositionStrategy`, which additionally sets absent precondition keys to FALSE via `buildOpenWorldState()`.

### Why this is non-obvious
The migration compiles cleanly — `Map<String, Condition>` is a different type from `Map<String, Boolean>`, so the constructor change forces a migration. But the *semantic* change (absent = UNKNOWN instead of absent = FALSE) has no compile-time signal. Tests that use empty initial states (`GoapWorldState.closedWorld(Map.of())`) suddenly find shorter plans because the planner skips dependency chains.

### Why this fix
Two factories instead of a flag because the semantics are fundamentally different: dispatch-time callers know what's in the context (closed-world assumption), decomposition-time callers don't (open-world). Mixing both in one factory with a parameter would be error-prone.

### Alternatives considered
- Single factory with a `boolean closedWorld` parameter — rejected because the caller must also set precondition keys to FALSE, which the factory can't do without knowledge of the action set.
- Keep absent = FALSE globally — rejected because decomposition-time planning under partial observability requires UNKNOWN semantics.
