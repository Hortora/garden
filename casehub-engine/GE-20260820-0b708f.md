### Symptom
`PlanItem.markCompleted()` throws `IllegalStateException: Cannot transition to COMPLETED from PENDING` when called directly on a PENDING item.

### Context
In unit tests setting up compound completion scenarios, the natural setup is `item.markCompleted()` to simulate a completed step. This works for items that have been dispatched (RUNNING), but fails for items created via `PlanItem.create()` which start in PENDING.

### Root cause
`PlanItem` uses CAS-based state transitions with strict validation. The valid transition path is PENDING → RUNNING → COMPLETED. `markCompleted()` only accepts transitions from RUNNING or DELEGATED — not from PENDING. This is by design (a PlanItem shouldn't complete without being dispatched), but the error message doesn't suggest the fix.

### Fix
Call `tryMarkRunning()` before `markCompleted()` in test setup:

```java
item.tryMarkRunning();
item.markCompleted();
```

For faulted items, the same pattern applies:
```java
item.tryMarkRunning();
item.markFaulted();
```

`tryMarkRunning()` is a CAS operation returning boolean — it succeeds from PENDING or AVAILABLE.

### Why this is non-obvious
The error message says "Cannot transition to COMPLETED from PENDING" which is clear, but in test setup code where you're building a fixture (not simulating a real dispatch), the extra `tryMarkRunning()` call feels like unnecessary ceremony. The state machine constraints are correct for production but create friction in test setup.
