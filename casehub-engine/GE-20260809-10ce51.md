## casehubio/worker and casehubio/workers are separate repos

**Symptom:** Plan assumes worker-api source is at `slots/93/workers/api/` but the directory doesn't exist. Files like `WorkerFunction.java` are found only as JAR dependencies, not source.

**Context:** The casehub platform has two similarly-named repos:
- `casehubio/worker` — foundation tier types (`casehub-worker-api` at `api/`, `casehub-worker` runtime at `runtime/`). Contains `WorkerFunction`, `WorkerResult`, `WorkerOutcome`, `Worker`, `Capability`, `WorkerScope`, `Exchange`, `DataChannel`.
- `casehubio/workers` — worker implementation backends (`workers-camel`, `workers-http`, `workers-k8s`, `workers-mcp`, `workers-script`, `workers-github-actions`).

When a slot is created with `workers` as a repo, it clones `casehubio/workers` (the implementations). The foundation types in `casehubio/worker` must be branched and edited separately at its own location (e.g. `/Users/mdproctor/claude/casehub/worker`).

### Fix

When modifying foundation tier types (anything in `io.casehub.worker.api`):
1. Locate `casehubio/worker` at `/Users/mdproctor/claude/casehub/worker` (the main repo)
2. Create a matching branch there
3. Make changes, install SNAPSHOT to the slot's `.m2`
4. Then consume in the engine repo

### Why this is non-obvious

The names `worker` and `workers` are nearly identical. The slot system lists `workers` as a repo, and the CLAUDE.md `cross-repo-source-verification` protocol mentions the package (`io.casehub.worker.api`) but not the repo path. The error manifests as "file not found" when trying to edit what should be a source file.
