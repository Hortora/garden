## Symptom

Building a CDI observer for `WorkItemLifecycleEvent` that should only process events from a specific application scope (e.g. `"fsitrading"`). Two common mistakes:

1. Calling `event.scope()` — **does not exist**. The event has no `scope()` accessor.
2. Calling `event.type()` expecting a `WorkEventType` enum — **returns a CloudEvent type string** like `"io.casehub.work.workitem.created"`, not the enum.

## Context

`WorkItemLifecycleEvent` is a platform-wide CDI event fired for ALL work items across ALL case types. Unlike application-specific CDI events (e.g. `PositionUpdatedEvent`), it requires explicit scope filtering to avoid broadcasting events from other applications.

The scope is on `WorkItem`, not the event. And `workItem()` returns `null` for wire-deserialized events (`fromWire()`).

## Root cause

The `WorkItemLifecycleEvent` API has two confusingly similar accessor pairs:

| Method | Returns | What it actually is |
|--------|---------|-------------------|
| `type()` | `String` | CloudEvent type URI: `"io.casehub.work.workitem.created"` |
| `eventType()` | `WorkEventType` | Enum: `CREATED`, `ASSIGNED`, `ESCALATED`, etc. (parsed from `type()`) |
| `workItem()` | `WorkItem` or `null` | Full work item — null for `fromWire()` events |
| `workItemId()` | `UUID` | Always populated — safe to use for topic paths |

Scope lives on `WorkItem.scope()`, not on the event itself.

## Fix

```java
void onWorkItemLifecycle(@Observes WorkItemLifecycleEvent event) {
    WorkItem wi = event.workItem();
    if (wi == null || !"fsitrading".equals(wi.scope())) return;

    WorkItemPushPayload payload = switch (event.eventType()) {  // NOT event.type()
        case CREATED -> ...;
        case ASSIGNED -> ...;
        default -> null;
    };
    if (payload != null) {
        broadcaster.broadcast("work-items/" + event.workItemId(), payload);  // NOT wi.id()
    }
}
```

Three rules:
1. **Scope filter:** `event.workItem() != null && "yourScope".equals(event.workItem().scope())`
2. **Enum switch:** `event.eventType()` not `event.type()`
3. **ID access:** `event.workItemId()` not `event.workItem().id()` (null-safe)

## Why this is non-obvious

A developer writing a CDI observer would naturally try `event.scope()` (doesn't exist), then `event.type()` (wrong return type for switch), then `event.workItem().id()` (NPE for wire events). Each mistake compiles or fails silently — there's no compiler warning that guides you to the correct API.
