# Agent-Facing API Design — Don't Expose Plumbing

**Domain tags:** api-design, mcp, llm-agents, architecture, spi
**Last reviewed:** 2026-11-08

When building MCP tools or agent-facing APIs that wrap internal infrastructure,
the internal SPI patterns (cursor-based state, byte-level access, fine-grained
multi-step operations) become friction for agent consumers. Agents don't persist
state between sessions, don't decode raw bytes, and can't manage invisible
lifecycle dependencies.

## The pattern

Design the agent-facing API as a separate surface with its own types and
affordances. Let the infrastructure serve it internally — don't expose
infrastructure abstractions through the agent contract.

**Two consumers, two APIs, one truth.** The internal SPI stays optimized for
its original consumer (ingestion pipelines, backend services). The agent-facing
SPI provides fewer, richer operations that return everything the agent needs in
one call.

## Smell test — three questions

When wrapping an internal SPI as an MCP tool, ask:

1. **Does the return type require a follow-up call?** Raw bytes to decode, IDs
   to resolve, references to dereference — the agent should get usable content
   in one response.

2. **Does the caller need to manage state between calls?** Cursors, session
   tokens, pagination handles. Agents don't persist state between sessions.
   If the protocol requires state, the system manages it.

3. **Does the parameter require knowledge the caller can't have?** Opaque
   cursor strings, internal version numbers, implementation-specific
   identifiers. Use what the caller naturally has — timestamps, names, content.

If yes to any: you're exposing plumbing, not an API.

## Concrete example

Internal: `ChangeSource.changesSince(String cursor)` — opaque SHA cursor,
returns `ChangedEntry(path, type)` with no timestamp, no author, no content.
Designed for ingestion pipeline exactly-once processing.

Agent-facing: `CorpusEntryStore.recentChanges(CorpusRef, Instant since)` —
timestamp input (what agents naturally have), returns `ChangeRecord(path, type,
timestamp, author, preview)` with enriched metadata and content. System maps
Instant to internal cursor format per backend.

Same underlying data. Different surface for a different consumer.

## When this applies

- Designing MCP tools that wrap existing Java SPIs
- Building agent-facing query APIs over internal storage
- Exposing any stateful protocol to stateless consumers
- Any time an infrastructure pattern is being surfaced as a tool

## When this doesn't apply

- Internal SPI design for developer consumption — cursor patterns, byte-level
  access, and fine-grained operations are correct for that audience
- Agent-to-agent protocols where both sides manage state
